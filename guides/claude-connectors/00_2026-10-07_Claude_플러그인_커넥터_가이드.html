API와 MCP, 뭐가 다른가요?

“API”라는 말이 두 가지로 쓰여서 헷갈려요. 먼저 둘을 나누고, 그다음 MCP와 비교해요.

⚖️
먼저 “API”가 무엇을 가리키는지부터

대화 속 “API”는 보통 둘 중 하나예요.

  • ① 서비스의 API Notion API, Slack API, 사내 시스템 API처럼 그 서비스가 개발자에게 여는 문. 서비스마다 모양이 달라요.
  • ② Claude API 개발자가 자기 프로그램에서 Claude를 부르는 Anthropic의 API(Messages API). 채팅 앱·Claude Code 구독과는 다른 입구예요.

① 서비스의 API vs MCP

비교서비스의 APIMCP
정체서비스가 자기 기능을 여는 개별 인터페이스. 서비스마다 주소·인증·형식이 달라요 일반 설명AI 앱을 외부 시스템(데이터·도구·워크플로)과 잇는 공통 오픈소스 표준. 공식 소개의 비유는 “AI용 USB-C 포트” 공식확인
쓰는 쪽개발자가 코드로 호출 일반 설명AI가 도구 설명을 보고, 요청이 그 도구의 기능과 맞을 때 호출해요(질문이 일반 지식이면 호출하지 않음) 공식확인
제공하는 것엔드포인트(기능별 주소)서버가 Tools(실행 기능)·Resources(참고 데이터)·Prompts(템플릿)를 AI에게 알려 줘요 공식확인
한 번 만들면연결하는 쪽마다 따로 연동 코딩Claude·ChatGPT·VS Code·Cursor 등 MCP를 지원하는 여러 AI 앱에서 재사용(“build once and integrate everywhere”) 공식확인
둘의 관계대체 관계가 아니라 층이 달라요. MCP 서버가 뒤에서 서비스의 API를 호출해 AI가 쓰기 쉬운 형태로 내주는 구조가 흔해요. 일반 설명 공식 문서가 직접 비교한 표현은 못 찾음
비용·컨텍스트호출한 만큼 서비스 요금·한도도구 정의가 컨텍스트를 차지해요. Claude Code는 기본으로 지연 로드하고, gh·aws 같은 CLI가 있으면 CLI가 더 효율적이라고 안내해요 공식확인
비유 — 서비스의 API는 건물마다 다른 출입구, MCP는 AI가 어느 건물에서든 같은 방식으로 문을 여는 공통 규격의 출입증이에요. 건물(서비스)이 먼저 있어야 하고, 출입증이 있다고 건물 열쇠(권한)가 생기지는 않아요(각자 로그인·권한 상속).

MCP가 API를 대체하나요?
대체가 아니라 층이 달라요. 서비스의 API는 서비스가 여는 문이고, MCP는 AI가 그 문(또는 다른 기능)을 공통 방식으로 쓰게 하는 규격이에요. 공식 문서가 둘을 직접 비교하는 문장은 찾지 못했고, 위 설명은 일반적인 구조 설명이에요. 부분확인
MCP를 붙이면 토큰이 더 드나요?
도구 정의가 컨텍스트를 차지해서 더 들 수 있어요. Claude Code는 도구 정의를 기본 지연 로드해 이름·서버 지시문만 먼저 싣고, /context로 확인하며 안 쓰는 서버는 /mcp에서 꺼요. CLI가 있으면 CLI가 더 효율적이라고 공식 비용 문서가 안내해요. 공식확인
Claude API로 만든 앱에서 구독 한도를 쓸 수 있나요?
서비스를 만들 때는 API 키 방식이 원칙이고, 구독 로그인 중계는 허용되지 않는다고 공식 문서가 밝혀요. 개인이 자기 프로젝트에서 Agent SDK·claude -p를 쓰는 경우는 구독 한도에서 차감된다는 안내가 2026.6.15 기준으로 있어요(도움말, 지식카드). 부분확인

  • 정의 플러그인은 스킬·MCP 커넥터·명령·에이전트를 한 단위로 담아 클로드에 추가하는 패키지예요. 공식확인

설치하는 순서

Customize → Plugins 열기

claude.ai 또는 데스크톱 앱에서 왼쪽 Customize(사용자 지정) → Plugins를 열어요.

Discover에서 고르기

sales·finance·legal·marketing·HR·engineering·design·operations·data analysis 같은 역할별 플러그인이 있어요. 선택하고 Add(또는 Install)를 눌러요.

(선택) 마켓플레이스·ZIP으로 추가

Add → Add marketplace(Git 저장소 URL 또는 owner/repo) 또는 Add → Upload plugin(.zip·.plugin 파일).

번들된 커넥터는 따로 연결

플러그인을 추가해도 커넥터는 자동으로 연결·로그인되지 않아요. 플러그인의 Connectors 탭에서 각각 추가하고 연결해야 해요.

사용하기

대화창에서 /를 입력하거나 + 버튼으로 플러그인 스킬을 불러요. 관리는 같은 화면의 Disable plugin, Remove, Check for updates, Sync automatically로 해요.

입력창 + 메뉴 “플러그인 추가” — 2026.10.6 웹 화면에는 + 메뉴에 “플러그인 추가”가 보였어요(화면 관찰). 다만 Cowork·채팅용 공식 문서에서 이 메뉴 항목 자체를 설명한 곳은 못 찾았어요(미확인). 확실한 경로는 Customize → Plugins예요.

팀에 배포

프로젝트·조직 단위로 미리 깔아 두기

저장소 단위

저장소의 .claude/settings.json에 extraKnownMarketplaces와 enabledPlugins를 넣어요. 키 형식은 plugin-name@marketplace-name. 팀원이 폴더 신뢰(workspace trust) 창을 수락한 뒤에만 적용돼요.

조직 전체

관리 설정(서버 관리 설정·MDM·managed-settings.json)에 같은 키를 넣으면 다음 세션부터 자동 등록·설치되고, 사용자가 개인 범위에서 꺼도 관리 설정이 우선해요.

{
  "extraKnownMarketplaces": {
    "your-marketplace": {
      "source": { "source": "github", "repo": "your-org/your-marketplace" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": { "code-formatter@your-marketplace": true }
}
  • 제한: strictKnownMarketplaces(허용 목록; 빈 배열은 공식 포함 전부 차단), blockedMarketplaces(차단), disableSideloadFlags(--plugin-dir 등 거부). 허용 목록을 쓰면 공식 마켓플레이스도 명시적으로 허용해야 해요.
  • enabledPlugins를 false로 두면 모든 범위에서 차단하고 목록에서 숨겨요.

MCP — 외부 도구를 직접 연결하는 방법

커넥터의 바탕이 되는 표준(MCP)을 Claude Code에서 직접 다루는 법이에요. 비개발자는 개념과 보안 부분만 읽어도 충분해요.

🔧
이 탭에서는

MCP가 무엇인지, claude mcp add 명령, 저장 범위(scope), 인증, 컨텍스트 비용, 보안, 조직 통제, 2026-07-28 사양 변화를 순서대로 정리해요.

  • 정의 MCP는 AI 앱이 외부 시스템과 연결하는 오픈소스 표준이에요. “AI용 USB-C 포트”라는 비유가 공식 소개에 나와요. 공식확인
  • 서버가 주는 것 Tools(실행 기능) · Resources(참고 데이터) · Prompts(템플릿 메시지)

연결 방식 3가지

HTTP (원격)
권장

원격 서버에 연결하는 권장 방식. 대부분의 클라우드 서비스가 이 방식이에요.

SSE
더 이상 권장 안 함

deprecated. SSE만 지원하는 서비스도 --transport http로 추가하면 HTTP를 먼저 시도하고 안 되면 SSE로 전환해요.

stdio (로컬)
내 PC에서 실행

내 컴퓨터에서 프로세스로 도는 서버. 환경변수로 키를 넘기는 경우가 많아요.

명령

서버 추가·확인·삭제

# 원격(HTTP) 서버 추가 — 이름과 주소
claude mcp add --transport http notion https://mcp.notion.com/mcp

# 로컬(stdio) 서버 추가 — -- 뒤가 실행 명령
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable -- npx -y airtable-mcp-server

# 확인·삭제
claude mcp list
claude mcp get notion
claude mcp remove notion
  • --(대시 두 개)는 클로드 자신의 옵션과 서버를 실행하는 명령을 구분해요. --env 바로 뒤에 서버 이름을 두면 또 하나의 KEY=value로 읽혀 거부되니 사이에 --transport stdio 같은 옵션을 넣어요.
  • 세션 안에서는 /mcp로 서버 상태 확인·인증(authenticate)·Reconnect·Disable/Enable·Clear authentication을 해요. 끈 서버도 설정은 남아요.
  • 그 밖에: claude mcp add-json, claude mcp login <이름>(--no-browser 가능), claude mcp logout, claude mcp add-from-claude-desktop(이름에 공백 불가), claude mcp serve(Claude Code 자체를 MCP 서버로 실행).
확인 필요 — claude mcp add의 짧은 옵션 별칭(-t, -s 등)과 전체 옵션표는 열람한 요약본에서 확인하지 못했어요. 이 가이드는 문서에 예시로 나온 긴 옵션만 적었어요.
어디에 저장되나

범위(scope) 3가지와 .mcp.json

범위누구에게 보이나저장 위치추가 방법
local (기본)이 프로젝트에서, 나만~/.claude.json의 프로젝트 경로 아래기본값
project저장소를 쓰는 팀 전체프로젝트 루트의 .mcp.json (버전 관리)--scope project
user내 모든 프로젝트, 나만~/.claude.json--scope user
  • 우선순위(높음→낮음): local → project → user → 플러그인 제공 서버 → claude.ai 커넥터. 조직의 managedMcpServers가 모두 위예요.
  • 승인: 대화형 세션에서는 .mcp.json의 project 서버를 쓰기 전에 승인을 물어요. 단 claude -p·Agent SDK·클라우드 세션은 묻지 못하므로 묻지 않고 로드해요.
  • 환경변수 확장: ${VAR}, ${VAR:-기본값}을 command·args·env·url·headers에서 쓸 수 있어요. 원격 서버의 url·headers에서는 ANTHROPIC_API_KEY 같은 자격 증명 변수가 빈 값으로 읽혀요(프로젝트 파일이 내 자격 증명을 외부로 보내지 못하게 하는 장치).
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}

인증 — OAuth와 API 키

서버 추가

claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

/mcp에서 인증

세션에서 /mcp를 실행하고 안내에 따라 브라우저에서 로그인해요. 토큰은 안전하게 저장되고 자동 갱신돼요(정확한 저장 경로는 이 문서에서 확인하지 못했어요).

(선택) 브라우저가 없을 때·API 키

claude mcp login sentry --no-browser. 정적 헤더는 --header "Authorization: Bearer …", 미리 등록한 OAuth 정보는 --client-id·--client-secret·--callback-port.

원격 로그인 오류가 날 때 — SSH·컨테이너처럼 브라우저가 로컬 콜백 서버에 닿지 못하면 로그인 후 보이는 코드를 터미널의 “Paste code here if prompted”에 붙여 넣어요(Claude Code 인증 문서, 지식카드 2026.9.29).
비용·컨텍스트

연결할수록 매 요청이 무거워져요

  • MCP 도구 정의는 기본적으로 지연 로드돼요. 시작할 때는 도구 이름과 서버 지시문만 컨텍스트에 들어가고, 클로드가 특정 도구를 쓸 때 전체 내용이 로드돼요. 무엇이 자리를 차지하는지는 /context(전체는 /context all)로 봐요. 공식확인
  • 안 쓰는 서버는 끄기: /mcp에서 비활성화. /usage에서는 스킬·서브에이전트·플러그인·개별 MCP 서버별 사용 비중을 볼 수 있어요.
  • 출력 크기: 도구 출력이 10,000토큰을 넘으면 경고, 기본 최대는 25,000토큰이에요. 조정은 환경변수 MAX_MCP_OUTPUT_TOKENS. 시작 타임아웃은 MCP_TIMEOUT.
  • 공식 비용 문서의 팁: gh, aws, gcloud 같은 CLI 도구가 있으면 MCP보다 컨텍스트 효율이 좋아요(도구 목록이 붙지 않기 때문).
  • MCP 서버를 추가하면 프롬프트 캐시가 다시 만들어져 사용량이 늘 수 있어요(Claude Code 공식 캐시 문서, 지식카드 2026.9.29).
확인 필요 — 도구 검색(tool search) 세부 임계값과 OAuth 토큰 저장 위치는 문서 열람이 잘려 확인하지 못했어요(미확인).

DB
읽기 전용 계정

공식 예시는 연결 문자열에 read-only 사용자를 써서 조회만 가능하게 해요. 단 읽기 전용은 “변경 방지”일 뿐 데이터가 모델로 전송되는 것은 별개의 사내 정책 판단이에요.

디렉터리
감사가 아님

Anthropic은 디렉터리 등재 전에 기준을 검토하지만 MCP 서버를 보안 감사하거나 관리하지는 않는다고 밝혀요.

  • 권한 규칙 이름은 mcp__<서버>__<도구> 형식이에요. 서버 전체는 mcp__서버 또는 mcp__서버__*. allow 규칙의 와일드카드는 서버 접두어 뒤에서만 허용돼요. claude.ai 커넥터 도구는 mcp__claude_ai_<서버>__<도구>로 나타나요.
  • .mcp.json만 봐서는 세션이 실제로 로드하는 서버 전체를 알 수 없어요. 다른 범위·claude.ai 커넥터·플러그인이 서버를 더할 수 있기 때문이에요.

설치 전 점검표

출처가 믿을 만한가

claude plugin marketplace list로 소스를 확인하고, 홈페이지·GitHub에서 작성자와 유지 상태를 봐요. 공식·커뮤니티 이름은 github.com/anthropics/ 소스에서만 허용되고, 서드파티 마켓플레이스는 Anthropic이 검토하지 않아요.

무엇이 실행되는지 보기

/plugin 상세 화면의 Will install, 저장소의 hooks/hooks.json·.mcp.json·bin/을 읽어요. 설치 후에는 claude plugin details <이름>. 모드는 claude plugin validate 출력의 hooks:·calls: 줄을 확인.

권한은 최소로

커넥터는 도구별로 Needs approval/Blocked를 쓰고, Always allow는 믿는 서버에만. 쓰기 가능한 도구(발송·수정·삭제)는 특히 신중히.

자동 업데이트도 변경이에요

검토한 파일이 업데이트로 바뀔 수 있어요. 서드파티·커뮤니티 마켓플레이스는 자동 업데이트가 기본 꺼짐이니 그대로 두는 편이 안전해요.

테스트는 연습용 데이터로

DB는 개발·테스트 DB나 마스킹 데이터, 읽기 전용 계정으로. 읽기 전용은 “변경 방지”일 뿐 조회 결과가 모델로 전송되는 것은 사내 정책으로 따로 판단해야 해요.

계정 규칙도 확인 — Claude 구독 로그인(OAuth)은 공식 앱 전용이에요. 제3자 프록시·웹앱으로 구독을 우회 연결하거나 Free·Pro·Max 자격증명으로 사용자 요청을 중계하는 것은 약관상 허용되지 않고, 제품·서비스를 만들 때는 API 키 방식을 써야 해요(Claude Code 법률·컴플라이언스 문서, 지식카드 2026.9.29). 부분확인

Gmail·캘린더 커넥터가 Free 계정에서 안 돼요

용어 사전

이 가이드에 자주 나오는 말을 쉬운 풀이로 모았어요.

커넥터 (Connector)

클로드를 외부 앱·서비스에 잇는 연결. 사용자별로 로그인해 연결해요.

MCP

Model Context Protocol. AI 앱과 외부 도구를 잇는 오픈소스 표준 규격. “AI용 USB-C”로 비유돼요.

원격 / 로컬 MCP 서버

원격은 서비스가 운영하는 서버에 주소(URL)로 연결, 로컬은 내 컴퓨터에서 프로세스로 실행(stdio).

스킬 (Skill)

작업 절차와 기준을 적은 안내서 폴더(SKILL.md). 필요할 때만 본문이 로드돼요.

플러그인 (Plugin)

스킬·에이전트·훅·MCP 서버 등을 한 단위로 묶어 설치하는 꾸러미.

마켓플레이스 (Marketplace)

플러그인 목록을 담은 카탈로그. marketplace.json으로 정의하고, 여러 개를 등록할 수 있어요.

모드 (Mod)

Claude Code의 동작·화면을 바꾸는 JS/TS 코드가 든 플러그인. 샌드박스 없이 내 권한으로 실행돼요.

내장 모드 (@builtin)

Claude Code에 처음부터 들어 있는 모드. ID 끝에 @builtin이 붙고 Installed 탭의 Built-in에 보여요.

채널 (Channel)

메신저의 메시지를 실행 중인 Claude Code 세션에 전달하는 MCP 서버.

훅 (Hook)

특정 시점(도구 호출 전후 등)에 자동 실행되는 명령. 사용자 권한으로 돌아요.

서브에이전트 / side agent

메인 작업과 별도로 도는 보조 AI. You should know 모드는 side agent로 지켜봐요.

LSP

Language Server Protocol. 코드의 정의·오류 위치를 이해하게 해 주는 언어 서버.

범위 (scope)

설정이 적용되는 범위. user(내 모든 프로젝트)·project(팀 공유)·local(나만, 이 프로젝트).

OAuth

비밀번호를 넘기지 않고 서비스 로그인 화면에서 접근을 승인하는 방식.

MCP Apps / 인터랙티브 커넥터

대화 안에 대시보드·폼 같은 실시간 화면을 띄우는 확장.

데스크톱 확장 (.mcpb)

로컬 MCP 서버를 포장해 Claude Desktop에 설치하는 형식. MCP Bundles.

Customize (사용자 지정)

claude.ai·데스크톱 앱 사이드바의 메뉴. Skills·Connectors·Plugins를 관리해요.

Cowork

Claude Code의 에이전트 능력을 지식 업무로 확장한 모드. 2026.9.16 채팅과 통합 중.

프롬프트 인젝션

외부 문서·웹페이지·서버에 숨은 지시문으로 AI를 엉뚱하게 움직이려는 공격.

텔레메트리 (telemetry)

사용 현황·성능 정보를 서비스 제공자에게 보내는 것. You should know는 켜진 세션에서 제공.

ZDR

Zero Data Retention. 승인된 Enterprise 조직의 데이터 비보관 계약. 제3자 연동 데이터는 범위 밖.

컨텍스트 (context)

AI가 한 번에 보는 대화·지침·도구 설명의 총량. 연결·플러그인이 많을수록 차지하는 몫이 커져요.

항상 켜짐 토큰 (always-on)

플러그인을 켜 두면 사용 여부와 무관하게 매 턴 컨텍스트에 들어가는 토큰(이름·설명 등).

Claude API (Messages API)

개발자가 자기 프로그램에서 Claude를 부르는 Anthropic의 API. 채팅 앱·구독과는 다른 입구이고 API 키·토큰 과금이에요.

툴 유즈 (tool use)

Claude가 함수(도구)를 부르겠다고 요청하면 내 앱 또는 Anthropic이 실행해 결과를 돌려주는 방식. 함수 호출(function calling)이라고도 해요.

MCP 커넥터 (Claude API 기능)

Messages API에서 원격 MCP 서버에 바로 연결하는 베타 기능. 도구 호출만 지원하고 서버는 공개 HTTP여야 해요.

설치 수 vs GitHub 별

설치 수는 공식 마켓의 실제 설치 집계, 별은 관심도 표시. 둘 다 안전을 보증하지 않아요.

서브에이전트 (subagent)

메인 AI가 띄우는 보조 AI. 자기만의 컨텍스트에서 일하고 요약 결과만 돌려줘요. 토큰은 더 들어요.

Task tool → Agent tool

Claude Code에서 서브에이전트를 띄우는 도구. 2026.2.28(v2.1.63) 전에는 Task라는 이름이었어요.
