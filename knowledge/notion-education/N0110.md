### 확장자 — 파일 이름 끝의 꼬리표
- **확장자** = 파일 이름에서 마지막 점(.) 뒤 글자. 예: `AGENTS.md`의 `.md`, `round_01.xlsx`의 `.xlsx`
- 하는 일: 이 파일이 어떤 종류인지, 어떤 프로그램으로 열지 알려 줌
- 폴더 단위 작업에서 중요한 이유: 도구가 찾는 파일은 **이름과 확장자까지 정확히** 맞아야 함(`AGENTS.md` ⭕ / `AGENTS.md.txt` ✕)

### 파일 정리도 프롬프트의 일부
- AI가 보는 것은 파일 내용만이 아님
- **폴더 이름 · 파일 이름 · 위치 · 묶여 있는 관계**도 작업을 이해하는 단서가 됨
- 그래서 폴더를 잘 나누는 것은 단순한 정리 습관이 아니라 **업무 맥락을 설계하는 일**
예를 들어,
```plain text
교육기관_환불업무
├─ 01_규정
├─ 02_고객요청
├─ 03_작업중
└─ 04_최종
```
이렇게 되어 있으면 사람도 바로 이해합니다.
- `01_규정` → 무엇을 기준으로 판단하는가
- `02_고객요청` → 이번 업무의 입력 자료
- `03_작업중` → 아직 수정 중인 내용
- `04_최종` → 완성된 결과물

### 더 잘 쓰는 법
[원본 이미지 제외]
- 폴더 하나 = 업무 하나
- 입력·결과 폴더 분리 (`input/` · `output/`)
- 지침 파일은 짧게 — 규칙·사실·절차를 파일별로 나눔 (`rules.md` · `memory.md` · `SKILL.md`)
- 회차마다 새 작업(새 대화) + 결과 파일 이름에 회차 번호 + 회차마다 기록 남기기
- 자주 하는 업무는 템플릿 폴더(지침 파일만 든 빈 구조)를 만들어 복사해 재사용
### 편하다고 많이 열어 주는 것이 좋은 것은 아님
폴더 기반 작업의 장점은 여러 파일을 한 번에 다룰 수 있다는 것. 반대로 말하면 **허용한 폴더 안에 있는 불필요한 파일까지 함께 노출될 수 있음**.
그래서 기본 원칙은 단순합니다. **필요한 업무 폴더만 따로 만들고, 필요한 자료만 그 안에 넣는다.**
이 원칙은 정보보안에서 말하는 최소 권한 원칙(Principle of Least Privilege)과 연결됩니다.
### 세 가지만 지키면 됨
**1. 업무마다 폴더를 나누기**
```plain text
01_출장정산
02_환불업무
03_교육자료
```
→ 서로 다른 업무의 파일이 섞이지 않게 함
**2. 원본과 결과를 분리하기**
```plain text
00_원본
10_작업중
20_결과
```
→ 원본이 수정되거나 결과물과 섞이는 것을 방지
**3. 민감 자료는 필요한 만큼만 넣기**
- 개인정보
- 고객사 계약 조건
- 인사 자료
- 내부 기밀 자료
→ 업무에 꼭 필요한 자료가 아니라면 작업 폴더에 넣지 않음

⑥ 상담이력 파일이 입력에 있을 때만: 각 항목이 어느 접수번호에 해당하는지 표시하고, 원문 표현("확인 중", "~로 보임", "미기재" 등)을 그대로 인용한다. "귀책: ○○" 명시는 확정, "~로 보임"은 가능성, "확인 중"·"미기재"는 미확인으로 둔다. 상담이력에 없는 접수번호는 "08 미수록"으로 표시한다.
⑦ 미처리·누락 보고: 메일 번호가 연속되지 않으면 빠진 번호를 적는다. 앞선 메일을 가리키는데 그 원문이 없으면 "원 메일 자료에 없음"으로 표시하고 추정해 채우지 않는다. 클레임 내용이 "다른 자료 참조"뿐이면 판단 불가로 적는다.

### 핵심 문장
- 시작 전에 **실제로 열린 파일**부터 확인
- **폴더 이름은 권한이 아님.** 접근 범위·복사본·금지 문장·사후 확인으로 원본을 지킴
- 규칙은 `AGENTS.md`에 고정, 요청은 한 줄
- **이름만 같은 기록 ≠ 같은 사건.** 매핑 3분류로 표시
- **폴더 = 관리창이자 작업창.** 이름은 영어·공백 없이, 원본은 복사본으로
- 규칙·점검·반복이 한 폴더에 갖춰지면 에이전트 → 1일차 하네스·루프로 이어짐
- 자료가 추가되면 새 회차 폴더에 같은 `AGENTS.md`로 다시 실행하고 **영향받은 결론만 고침**
