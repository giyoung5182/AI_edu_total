### 📖 개념: 무엇을 보고 판정하는가
**답변이 아니라 결과물을 봅니다.**





나쁜 판정

좋은 판정




"빈칸으로 유지했다"는 답변을 읽고 통과

결과 파일을 열어 빈칸인지 확인




"기록을 남겼다"는 말을 믿음

기록 폴더에 파일이 실제로 있는지 확인




"원본은 수정하지 않았다"

원본 폴더의 수정 날짜를 확인




답변이 길고 그럴듯하면 통과

지시한 조건별로 하나씩 대조


> **주의** — **함정 케이스에서 특히 그렇습니다.** 답변에서는 "빈칸으로 두었다"고 하면서 실제 파일에는 0이 들어가 있는 경우가 있습니다. **1권 원리 하나가 검증 단계에서도 그대로 적용됩니다.** 말과 결과는 다를 수 있습니다.
**지시한 것과 지시하지 않은 것을 구분합니다**
```plain text
지시한 것        판정 대상. 다르면 실패
지시하지 않은 것   판정 대상 아님. 달라도 통과
```
예를 들어 **행 정렬 순서**를 지시하지 않았다면, 매체명 가나다순으로 나오든 기준표 목록 순으로 나오든 **둘 다 통과**입니다. 여기서 실패 판정을 내리면 지시문이 불필요하게 길어집니다.
**정말 필요한 항목이면 그때 지시문에 추가**하고, 다시 8건을 돌립니다.
**가점 항목**
지시하지 않았는데 해 주면 좋은 것들입니다. 필수는 아니지만 **잘 만들어진 지시문의 신호**입니다.
```plain text
원본에 합계 행이 있을 때 자기 계산과 교차 검증
원본 자체의 한계를 확인 필요 목록에 기록
   예) 반올림된 값이라 복원 불가
처리하지 않은 것을 명시적으로 목록화
   예) "빈칸을 채우지 않았다", "원본을 수정하지 않았다"
```

### 📌 6권 핵심 정리
① **구조가 규칙보다 강하다.** 원본·기준·결과·기록을 폴더로 분리하면 "수정 금지"가 저절로 지켜진다.
② **CLAUDE.md는 5권 지시문을 파일로 저장한 것이다.** 내용은 같고, 제목과 폴더 경로만 붙는다.
③ 규칙은 **검증 가능한 문장으로, 200줄 이내로, 충돌 없이** 쓴다. 길어질수록 안 지켜진다.
④ `/context`로 읽혔는지 확인하고, `/memory`로 무엇이 저장됐는지 보고, `/init`으로 초안을 만든다.
⑤ **CLAUDE.md는 지침이지 강제 장치가 아니다.** 반드시 막아야 하는 것은 폴더 구조로 막는다.
⑥ 테스트는 **전부 다시 돌린다.** 규칙 하나를 고치면 다른 규칙과 충돌할 수 있다.

```plain text
CLAUDE.md           동작하는 파일                     6권
테스트 결과          실제로 되는가                     6권
```
**일곱 개가 하나의 업무에서 나왔습니다.** 원 커리큘럼 2일 과정도 같은 구조입니다. 1일차 첫 시간에 고른 과제 하나가 2일차 마지막 Agent까지 이어집니다.
## 하나의 흐름으로 다시 보기
```plain text
AI의 성질 이해                    1권
      ↓
Input–Process–Output 분해         2권 활동 1
      ↓
자동화 과제 정의서                 2권 활동 2
      ↓
데이터 사전 · 지식 문서             3권 활동 1·3
      ↓
Agent 설계서                      4권 활동 2
      ↓
지시문 · 테스트 케이스              5권 활동 1·2
      ↓
CLAUDE.md · 실행 · 검증            6권 활동 2·3·4
```
**뒤 단계가 막히면 앞 단계로 돌아가야 합니다.** 지시문을 아무리 고쳐도 결과가 안 나오면 대개 2권 과제 선정이나 3권 데이터 정리에 문제가 있습니다. 그마저도 아니면 1권으로 돌아가 **AI에게 맡길 수 없는 일을 맡기고 있는 것은 아닌지** 확인해야 합니다.
## 자리로 돌아가서
```plain text

4  그 단계 하나만 정의서로 씁니다

```
