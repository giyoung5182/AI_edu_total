## 리눅스

### 개발자는 왜 리눅스를 사용할까
전 세계 서버의 대부분은 리눅스로 돌아갑니다. 우리가 매일 쓰는 웹 서비스의 뒤편도 대부분 리눅스입니다. 그래서 개발 도구의 상당수가 리눅스를 기준으로 만들어지고, 리눅스에서 가장 먼저, 가장 안정적으로 동작합니다.
개발자가 리눅스를 선택하는 더 현실적인 이유는 편의성입니다. Windows와 리눅스에서 같은 프로그램을 설치하는 과정을 비교해 봅니다.

Windows에서 프로그램 하나를 설치할 때
1. 브라우저를 열고 공식 사이트를 검색한다
2. 설치 파일(.exe)을 내려받는다
3. 설치 마법사를 실행하고 "다음"을 여러 번 누른다
4. 설치 경로를 정하고, 관리자 승인 창에 "예"를 누른다
5. 경우에 따라 환경 변수를 수동으로 등록한다
6. 재부팅이 필요할 때도 있다
리눅스(Ubuntu)에서 같은 일을 할 때
1. **sudo apt install** 프로그램명

한 줄이면 끝납니다. 내려받기, 설치, 경로 등록까지 시스템이 알아서 처리합니다. 프로그램 열 개를 설치해도 열 줄이고, 그 열 줄을 파일로 저장해 두면 다음 컴퓨터에서도 붙여넣기 한 번으로 같은 환경이 만들어집니다.
이 차이는 "따라 하기"에서 더 크게 벌어집니다. Windows의 설치 안내는 스크린샷 기반이라 프로그램 버전이 바뀌면 화면이 달라져 금방 낡습니다. 리눅스의 안내는 텍스트 명령이라 그대로 복사해 붙여넣으면 누구의 컴퓨터에서든 같은 결과가 나옵니다. 이 문서의 모든 절차가 명령 몇 줄로 정리될 수 있는 이유입니다.
### AI를 이용한 코딩도 리눅스가 편할까
리눅스가 훨씬 편합니다. 사람에게 편리했던 그 특성이, AI에게는 편리함을 넘어 필수 조건에 가깝습니다.
이번 과정에서 사용하는 Claude Code는 터미널 안에서 동작하는 AI 코딩 도구입니다. AI가 직접 파일을 만들고, 필요한 라이브러리를 설치하고, 코드를 실행하고, 오류를 확인해서 다시 고칩니다. 리눅스에서는 이 모든 일이 텍스트 명령과 텍스트 출력으로 이루어지므로, AI가 사람 손을 빌리지 않고 전 과정을 스스로 수행할 수 있습니다.
예를 들어 실습 중 파이썬 라이브러리가 하나 빠져 있으면, AI는 오류 메시지를 읽고 `pip install`을 직접 실행한 뒤 하던 작업을 이어갑니다. 우리는 그 과정을 지켜보며 승인만 하면 됩니다.
Windows에서는 이 자율성이 자주 끊깁니다. 설치 마법사 창, 관리자 승인 팝업, 마우스로 눌러야 하는 버튼이 나타나는 순간 AI는 멈추고 사람이 개입해야 합니다. AI가 일하다 말고 "이 창의 버튼을 대신 눌러 주세요"라고 요청하는 셈입니다. AI에게 가장 넓은 작업 권한과 자율성을 주는 환경이 리눅스이고, 그것이 우리가 리눅스에서 시작하는 이유입니다.
### 그래서 오늘 우리는
이번 과정의 모든 실습은 리눅스 환경에서 진행합니다. 다만 리눅스 컴퓨터를 따로 준비하지는 않습니다. 지금 쓰는 Windows 노트북 안에 리눅스를 넣어서 사용합니다. 그 방법이 바로 WSL입니다.
> 💡 이 과정의 모든 실습은 Windows 노트북 위의 WSL2(Ubuntu) 환경에서 진행합니다. 명령어는 전부 Ubuntu 터미널 기준입니다.

## WSL이란 무엇인가
[원본 이미지 제외]
WSL은 Windows Subsystem for Linux의 약자입니다. Windows 안에서 진짜 리눅스를 실행하는 기능이며, Microsoft가 Windows에 직접 내장해 제공합니다. 우리는 그중 최신 방식인 WSL2에, 가장 널리 쓰이는 리눅스 배포판인 Ubuntu를 올려 사용합니다.
Windows와 Ubuntu는 한 노트북 안에서 동시에 돌아갑니다. 브라우저로 자료를 찾는 일은 Windows에서, 실습은 Ubuntu에서 합니다. 두 세계는 탐색기로 파일을 서로 주고받을 수 있습니다.

## 1단계. WSL2와 Ubuntu 설치
PowerShell을 관리자 권한으로 열고 한 줄을 실행합니다.
```powershell
wsl --install
```
또는
```php
wsl --install -d Ubuntu-24.04
```
이 명령 하나가 WSL 기능 활성화, 리눅스 커널 설치, Ubuntu 배포판 설치를 모두 처리합니다.<br>설치가 끝나면 반드시 재부팅합니다.
**진행 순서**

1. 시작 메뉴 → "PowerShell" 검색 → 마우스 오른쪽 클릭 → 관리자 권한으로 실행
2. wsl --install 입력 후 Enter
3. 설치 완료 메시지 확인 후 컴퓨터 재부팅
4. 재부팅 후 자동으로 열리는 Ubuntu 창에서 사용자 이름 입력 (영문 소문자)
5. 비밀번호 입력 (화면에 표시되지 않는 것이 정상)
6. 비밀번호 재입력으로 확인

여기서 만드는 것은 Ubuntu 전용 계정입니다. 이 비밀번호는 Windows 로그인 비밀번호와 완전히 별개이며, 지금 새로 정하는 것입니다. 노트북에 Windows 비밀번호가 설정되어 있지 않아도 이 단계는 동일하게 진행됩니다.
> 🔐 **보안**: 여기서 만든 Ubuntu 비밀번호는 `sudo` 명령마다 필요합니다. 교육용 표준 계정명과 비밀번호는 운영 안내에 따라 통일합니다.
설치 상태는 PowerShell에서 다음으로 확인합니다.
```powershell
wsl --list --verbose
```
Ubuntu가 VERSION 2로 표시되면 정상입니다.
[원본 이미지 제외]

### WSL에서 비밀번호를 잊어버렸을 때
만약 비밀번호가 기억나지 않아 `sudo` 권한을 쓸 수 없는 상태라면, **윈도우 PowerShell에서 최고 관리자 권한(****`root`****)으로 접속하여 비밀번호를 강제로 재설정**해야 합니다.
**1.WSL 배포판 이름 확인:**
윈도우의 PowerShell을 열고 아래 명령어를 입력해 사용 중인 WSL 배포판 이름을 확인합니다. 앞서 설치하신 이름(예: `Ubuntu-24.04`)을 찾으시면 됩니다.
```plain text
wsl --list --verbose
```
**2.root(최고 관리자) 계정으로 WSL 접속:**
- `u root` 옵션을 붙여 비밀번호를 묻지 않는 최고 권한으로 WSL에 들어갑니다. (배포판 이름 부분에 자신의 배포판을 적어주세요.)
```plain text
wsl -d Ubuntu-24.04 -u root
```
**3.비밀번호 재설정:**
성공적으로 접속하면 프롬프트가 `root@...:#`으로 바뀝니다. 여기서 비밀번호를 바꿀 **일반 사용자 계정 아이디**를 지정해 명령어를 입력합니다.
```plain text
passwd 사용자아이디
```

## WSL과 친해지기
설치를 마쳤으니, 이 환경을 이루는 기본 개념을 하나씩 확인합니다. 여기 나오는 개념과 명령은 이번 과정 내내 사용합니다.
### 터미널이란 무엇인가
터미널은 컴퓨터에 텍스트로 명령을 내리는 창입니다. 마우스로 아이콘을 클릭하는 대신, 키보드로 명령을 입력하고 Enter를 누릅니다. 컴퓨터는 그 명령의 실행 결과를 다시 텍스트로 보여줍니다.
실제 모습은 이렇습니다. 사용자가 `ls`라고 입력하면, 컴퓨터가 현재 위치의 파일 목록을 출력합니다.
```plain text
username@laptop:~$ ls
hanbit-ai  memo.txt
username@laptop:~$
```
이번 과정에서 우리가 AI와 함께 일하는 공간이 바로 이 터미널입니다.
### 프롬프트란 무엇인가
터미널에서 입력을 기다리며 깜박이는 줄, 정확히는 그 줄 앞에 표시된 텍스트를 프롬프트라고 합니다. 위 예시의 `username@laptop:~$` 부분입니다. 프롬프트는 세 가지 정보를 담고 있습니다.
```plain text
username @ laptop : ~ $
──┬─── ──┬───  ─┬─
사용자명  컴퓨터명  현재 위치
```
프롬프트가 보인다는 것은 "명령을 받을 준비가 되었다"는 뜻입니다. 명령이 실행되는 동안에는 프롬프트가 사라졌다가, 끝나면 다시 나타납니다.
프롬프트 모양은 어느 세계에 있는지도 알려줍니다. `PS C:\...`로 시작하면 Windows의 PowerShell이고, `사용자명@컴퓨터명:~$` 형태면 Ubuntu입니다. 명령이 안 먹을 때 가장 먼저 확인할 것이 프롬프트 모양입니다.
### 루트와 홈: 리눅스의 폴더 구조
리눅스의 모든 폴더는 하나의 출발점 아래에 있습니다. 그 출발점이 루트(root)이고, 기호로는 `/`  하나로 씁니다. Windows에 `C:\`가 있다면 리눅스에는 `/`가 있습니다.
루트 아래에는 시스템이 쓰는 폴더들이 있고, 사용자마다 자기 전용 폴더가 하나씩 배정됩니다. 그 전용 폴더가 홈(home)이며, 기호로는 `~`로 씁니다.

/                        ← 루트: 모든 것의 출발점<br>├── bin/                 ← 시스템 명령어들<br>├── etc/                 ← 시스템 설정 파일들<br>├── mnt/<br>│   └── c/               ← Windows의 C 드라이브가 여기로 연결됨<br>└── home/<br>└── username/          ← 홈(\~): 사용자 "username"의 전용 공간<br>└── hanbit-ai/   ← 우리가 만들 프로젝트 폴더

터미널을 열면 항상 홈에서 시작합니다. 프롬프트의 `~`가 그 표시입니다. 이번 과정의 모든 작업물은 홈 아래에 둡니다.
### sudo란 무엇인가
리눅스에서 일반 사용자는 자기 홈 안에서는 무엇이든 할 수 있지만, 시스템 영역을 건드릴 수는 없습니다. 프로그램 설치처럼 시스템을 바꾸는 작업에는 관리자 권한이 필요합니다.
`sudo`는 명령 하나를 관리자 권한으로 실행하겠다는 선언입니다. 명령 맨 앞에 붙여 씁니다.
```bash
sudo apt update
```
`sudo`를 붙여 실행하면 비밀번호를 묻습니다. <br>1단계에서 만든 Ubuntu 계정 비밀번호입니다. Windows 로그인 비밀번호가 아니라는 점에 주의합니다. 비밀번호를 입력해도 화면에 아무것도 표시되지 않는 것이 정상이니, 그대로 입력하고 Enter를 누릅니다.
> ⚠️ **주의**: `sudo`는 시스템 전체를 바꿀 수 있는 권한입니다. 이 문서와 교육 자료에 나오는 명령에만 사용하고, 출처를 모르는 명령에는 붙이지 않습니다.
### 기본 명령어 다섯 가지
터미널 생활의 뼈대가 되는 다섯 명령입니다. "지금 어디에 있고(pwd), 무엇이 있는지 보고(ls), 이동하고(cd), 폴더를 만들고(mkdir), 파일을 복사한다(cp)" — 이 다섯 동작이면 파일 작업의 대부분을 해낼 수 있습니다. 지금 터미널에서 하나씩 직접 실행해 봅니다.
**`pwd`**** — 지금 내가 어디에 있는지 확인하기**
print working directory의 약자입니다. 현재 위치의 전체 경로를 출력합니다.
```bash
pwd
```
```plain text
/home/username
```
터미널 작업의 기본 습관은 "작업 전에 위치 확인"입니다. 명령이 이상하게 동작할 때 절반은 엉뚱한 위치에서 실행한 경우이고, `pwd` 한 번이면 확인됩니다.
**`ls`**** — 현재 위치의 파일 목록 보기**
list의 약자입니다.
```bash
ls
```
```plain text
hanbit-ai  memo.txt
```
뒤에 `-al`을 붙이면 마침표(`.`)로 시작하는 숨김 파일과 각 파일의 상세 정보까지 나옵니다.
```bash
ls -al
```
```plain text
drwxr-x--- 5 hanbit hanbit 4096 Jul 13 10:00 .
drwxr-xr-x 3 root   root   4096 Jul 13 09:00 ..
-rw-r--r-- 1 hanbit hanbit 3771 Jul 13 09:00 .bashrc
drwxr-xr-x 4 hanbit hanbit 4096 Jul 13 10:00 hanbit-ai
-rw-r--r-- 1 hanbit hanbit   52 Jul 13 10:00 memo.txt
```
`.bashrc`처럼 마침표로 시작하는 파일은 설정 파일입니다. 평소에는 숨겨져 있고, `ls -al`로만 보입니다.

**`cd`**** — 위치 이동하기**
change directory의 약자입니다.
```bash
cd hanbit-ai      # hanbit-ai 폴더 안으로 이동
cd ..             # 한 단계 위로 이동
cd ~              # 어디에 있든 홈으로 이동
```
이동하면 프롬프트의 위치 표시가 바뀝니다. `~`였던 부분이 `~/hanbit-ai`로 바뀌면 이동에 성공한 것입니다.
**`cp`**** — 파일 복사하기**
copy의 약자입니다. `cp 원본 대상` 순서로 씁니다.
```bash
cp memo.txt memo_backup.txt   # 같은 위치에 다른 이름으로 복사
cp memo.txt test/             # test 폴더 안으로 복사
ls test
```
```plain text
memo.txt
```

### 프로그램 설치 관리: apt update와 upgrade
`apt`는 Ubuntu의 프로그램 설치 관리자입니다. 프로그램의 검색, 설치, 업데이트를 모두 담당하며, 시스템을 바꾸는 작업이므로 항상 `sudo`와 함께 씁니다. 자주 쓰는 두 명령의 역할이 다릅니다.
**`sudo apt update`**** — 설치 가능한 프로그램 목록 갱신**
설치 가능한 프로그램들의 최신 목록을 받아옵니다. 프로그램 자체를 바꾸지는 않습니다.
```bash
sudo apt update
```
**`sudo apt upgrade`**** — 설치된 프로그램을 최신으로 갱신**
이미 설치된 프로그램들을 방금 받아온 목록 기준으로 실제 업데이트합니다. 그래서 순서는 항상 `update`가 먼저, `upgrade`가 나중입니다.
```bash
sudo apt upgrade -y
```
- `y`는 "계속하시겠습니까?" 질문에 모두 예로 답하겠다는 표시입니다.

## Windows와 WSL 사이에서 파일 주고받기
Windows와 Ubuntu는 서로의 파일에 접근할 수 있습니다. 방향별로 방법이 하나씩 있습니다. 둘 다 탐색기만으로 가능합니다.
### Windows 파일을 WSL로 가져오기 (탐색기 사용)
Windows 탐색기의 왼쪽 목록 맨 아래에 펭귄 아이콘의 **Linux** 항목이 있습니다. 이를 열면 Ubuntu의 폴더가 보입니다.
**진행 순서**
```plain text
1. Windows 탐색기 실행
2. 왼쪽 목록에서 Linux → Ubuntu → home → 사용자명 순서로 이동
   (또는 주소창에 \\wsl.localhost\Ubuntu\home\사용자명 입력)
3. 옮길 파일을 복사해서 이 위치에 붙여넣기
```
[원본 이미지 제외]
반대로 Ubuntu 터미널에서 현재 위치를 Windows 탐색기로 열 수도 있습니다.
```bash
explorer.exe .
```
마지막의 마침표는 "현재 폴더"라는 뜻입니다. 파일을 끌어다 놓을 때 편리합니다.
### WSL에서 Windows 파일에 접근하기
Ubuntu 쪽에서 보면 Windows의 C 드라이브는 `/mnt/c`에 연결되어 있습니다. 예를 들어 Windows의 다운로드 폴더는 다음 위치입니다.
```bash
ls /mnt/c[로컬 경로]
```
내려받은 파일을 프로젝트 폴더로 복사할 때 `cp`를 씁니다.
```bash
cp /mnt/c[로컬 경로] ~/hanbit-ai/
```
> 💡 **팁**: 접근은 양쪽 어디서든 되지만, 실습 작업은 반드시 `~/` 아래에서 합니다. `/mnt/c` 아래에서 작업하면 파일 처리 속도가 크게 떨어지고 권한 문제가 생길 수 있습니다. Windows 파일은 "복사해서 가져온다"가 원칙입니다.
### 복사하면 생기는 Zone.Identifier 파일
탐색기로 Windows 파일을 WSL에 복사하면, 파일 이름 뒤에 `:Zone.Identifier`가 붙은 정체불명의 파일이 함께 생기는 경우가 있습니다.
```plain text
hanbit@laptop:~/hanbit-ai$ ls
report.pdf  report.pdf:Zone.Identifier
```
이것은 Windows가 "이 파일은 인터넷에서 내려받은 것"이라고 표시해 두는 보안 꼬리표입니다. Windows 안에서는 파일 속에 숨겨져 있어 보이지 않지만, 리눅스로 넘어오면서 별도 파일로 드러난 것입니다.
실습에는 아무 영향이 없으며, 지워도 원본 파일은 그대로 남습니다.

## 복수 터미널 사용하기
터미널은 여러 개를 동시에 열 수 있습니다. Windows Terminal에서는 `Ctrl` + `Shift` + `T`를 누르거나 탭 옆의 `+` 버튼을 누르면 새 탭이 열립니다.

[원본 이미지 제외]
> 💡 **팁**: 탭은 서로 독립이므로, 현재 위치와 가상환경 활성화 상태도 탭마다 따로입니다. 새 탭을 열면 홈(`~`)에서 새로 시작한다는 점을 기억합니다.

## 2단계. Ubuntu 기본 도구 설치
Ubuntu 터미널에서 패키지 목록을 갱신하고 파이썬 관련 도구를 설치합니다. 앞에서 익힌 `update` → `upgrade` 순서 그대로입니다.
```bash
sudo apt update && sudo apt upgrade
```
```bash
sudo apt install -y python3-venv python3-pip unzip
```
설치 확인은 버전 출력으로 합니다.
```bash
python3 --version
```
Python 3.10 이상이 출력되면 정상입니다.

## 4단계. Claude Code 설치와 인증
Claude Code는 네이티브 인스톨러 한 줄로 설치합니다. Node.js 같은 사전 요구사항이 없고, 관리자 권한도 필요 없습니다. 반드시 Ubuntu 터미널 안에서 실행합니다.
```bash
curl -fsSL [개별 링크 제외] | bash
```
설치 후 터미널을 닫았다가 다시 열고 확인합니다.
```bash
claude --version
claude doctor
```
버전 번호가 나오고 doctor가 정상 보고를 하면 설치 완료입니다.
이전에 설치된 버전이 있어 Claude Code의 업데이트가 필요하다면 다음 명령어를 실행합니다.
```bash
claude update
```
**인증 (두 가지 방식 중 교육 운영 안내를 따릅니다)**
**방식 A** — 발급 API 키를 쓰는 경우:
```bash
[개별 인증정보 제외 — 본인 계정으로 준비하세요.]
source ~/.bashrc
```
**방식 B** — 계정 로그인을 쓰는 경우
프로젝트 폴더에서 `claude`를 실행하면 브라우저 인증 창이 열립니다. 안내된 계정으로 로그인하면 됩니다. 브라우저가 자동으로 열리지 않으면 터미널에 표시된 URL을 복사해 브라우저에 직접 붙여 넣습니다.
> 🔐 **보안**: 키 실값은 이 문서를 포함해 어떤 파일에도 적지 않습니다. 키는 `~/.bashrc`에만 존재하고, 코드에서는 환경 변수로만 읽습니다. 키가 노출되면 즉시 해당 대시보드에서 폐기하고 재발급합니다.
> ⚠️ **주의**: `claude` 명령을 찾지 못하면 PATH 문제입니다. 아래를 실행하고 다시 시도합니다.
```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

## 5단계. 프로젝트 폴더와 파이썬 환경
작업 폴더는 반드시 WSL 홈 디렉터리(`~/`) 아래에 만듭니다. <br>Windows 쪽 경로(`/mnt/c/...`)에서 작업하면 파일 처리 속도가 크게 떨어지고 권한 문제가 생길 수 있습니다.
```bash
mkdir -p ~/hanbit-ai
cd ~/hanbit-ai
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install pypdf chromadb voyageai google-genai tavily-python rank-bm25
```
설치 확인:
```bash
pip list | grep -E "pypdf|chromadb|voyageai|google-genai|tavily|rank-bm25"
```
여섯 패키지가 모두 목록에 보이면 완료입니다.
> 💡 **팁**: 터미널을 새로 열면 가상환경이 꺼져 있습니다. 프로젝트 작업 전에는 항상 `cd ~/hanbit-ai && source .venv/bin/activate`를 먼저 실행합니다. 프롬프트 앞에 `(.venv)`가 붙어 있으면 켜진 상태입니다.

## 6단계. 최종 점검
파이썬 환경을 한 번에 확인하는 점검 스크립트를 만듭니다.
```bash
cd ~/hanbit-ai && source .venv/bin/activate
cat > check_env.py << 'EOF'
for pkg in ["pypdf", "chromadb", "voyageai", "google.genai", "tavily", "rank_bm25"]:
    try:
        __import__(pkg)
        print(f"패키지 {pkg}: OK")
    except ImportError:
        print(f"패키지 {pkg}: 설치 필요")
EOF
python3 check_env.py
```
모든 항목이 OK면 준비 완료입니다. Claude Code는 `claude doctor`로 별도 확인합니다.

## 잘 안 될 때
**Q. ****`wsl --install`****이 인식되지 않음**
- **원인**: Windows 버전이 오래됨
- **해결**: Windows Update 후 재시도 (Windows 10은 2004 이상 필요)
**Q. 재부팅 후 Ubuntu 창이 안 뜸**
- **원인**: 자동 실행 실패
- **해결**: 시작 메뉴에서 "Ubuntu"를 직접 실행
**Q. WSL 설치 중 가상화 오류**
- **원인**: BIOS 가상화 꺼짐
- **해결**: BIOS에서 가상화(VT-x/SVM) 활성화 후 1단계 재수행
**Q. ****`sudo`**** 비밀번호가 계속 틀림**
- **원인**: Windows 비밀번호를 입력함
- **해결**: 1단계에서 만든 Ubuntu 계정 비밀번호를 입력
**Q. 명령이 전혀 안 먹음**
- **원인**: PowerShell에 입력 중
- **해결**: 프롬프트 확인. `PS C:\...`면 PowerShell이므로 Ubuntu 탭에서 재시도
**Q. 탐색기에 Linux 항목이 없음**
- **원인**: WSL 미실행 상태
- **해결**: Ubuntu 터미널을 한 번 실행한 뒤 탐색기 새로고침
**Q. ****`:Zone.Identifier`**** 파일이 생김**
- **원인**: Windows 보안 꼬리표 (무해함)
- **해결**: `find . -name "*:Zone.Identifier" -delete`로 정리
**Q. ****`claude: command not found`**
- **원인**: PATH 미반영
- **해결**: `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc` 후 `source ~/.bashrc` 실행
**Q. claude 실행 시 인증 오류**
- **원인**: 키 또는 로그인 문제
- **해결**: 4단계 인증 절차 재수행. `claude doctor`로 상태 확인
**Q. pip 설치가 매우 느리거나 실패**
- **원인**: 네트워크 불안정
- **해결**: 네트워크 확인 후 `pip install` 명령만 재실행 (이어서 진행됨)
**Q. ****`source .venv/bin/activate`**** 실패**
- **원인**: venv 미생성 또는 경로 다름
- **해결**: `cd ~/hanbit-ai` 확인 후 5단계 venv 생성부터 재수행
**Q. 한글 파일명이 ****`???`****로 보임**
- **원인**: 로케일 미설정
- **해결**: `sudo apt install -y language-pack-ko` 후 터미널 재시작

## 준비 완료 기준 (총괄 체크리스트)

- [ ] Claude Code 인증이 완료되어 있다 (발급 키 또는 계정 로그인)
- [ ] `~/hanbit-ai` 프로젝트 폴더와 `.venv` 가상환경이 준비되어 있다
- [ ] 파이썬 패키지 6종이 설치되어 있다
