# 우리 반 작업 규칙

## 대상
- 초등 3~4학년이 보는 화면이다.
- 학생들은 휴대폰으로 본다.

## 화면
- 글자 크기는 18px 이상. 기본값으로 두면 학생이 못 읽는다.
- 누르는 것은 최소 56px. 손가락으로 눌러야 한다.
- 표를 쓰지 않는다. 휴대폰에서 잘린다. 카드를 세로로 쌓는다.
- 가로 스크롤이 생기면 안 된다.

## 표현
- 어려운 낱말은 풀어쓴다. '실행' → '해 보기'
- 한 줄에 20자 이내로 끊는다.

## 금지
- 학생 화면에 외부 링크를 넣지 않는다.
- 학생 이름·사진·연락처를 넣지 않는다. 번호나 모둠명만 쓴다.

## 작업 방식
- 산출물은 항상 현재 프로젝트 폴더 안에만 만든다.
  임시 폴더에는 어떤 것도 만들지 않는다.
- 파일을 만든 뒤에는 저장 경로를 응답에 적는다.
- 새로 설치가 필요하면 먼저 무엇을 왜 설치하는지 말하고 허락을 구한다.
- 아이콘이나 이미지가 필요하면 이미 설치된 것만 써서 만든다.

## 확인
- 만든 결과를 네가 직접 열어서 테스트하지 않는다.
  항상 내가 직접 열어서 확인할 수 있게 안내한다.
- 확인이 필요해 보이면 실행하지 말고 "확인해볼까요?" 한 줄로만 물어본다.

# 2. 개인용 — 집에서 쓰는 것
수업이 끝나고 본인 작업에 쓰실 기본형입니다. 학년·과목만 바꾸시면 됩니다.
```plain text
# 작업 규칙

## 내 상황
- 나는 초등학교 SW 수업 강사다.
- 코드를 직접 읽거나 쓰지 않는다. 결과 화면으로 판단한다.
- 만드는 것은 대부분 학생이 보는 웹 화면이다.

## 결과물 기준
- 특별한 말이 없으면 파일 하나로 완결되게 만든다.
- 설치가 필요한 것은 쓰지 않는다. 필요하면 먼저 물어본다.
- 초등학생이 휴대폰으로 본다. 글자와 버튼을 크게.

## 작업 방식
- 산출물은 현재 프로젝트 폴더 안에만 만든다.
- 파일을 만들거나 고친 뒤에는 경로를 적는다.
- 내가 요청하지 않으면 결과를 직접 테스트하지 않는다.
- 한 번에 다 하지 말고, 큰 작업은 먼저 어떻게 할지 알려주고 시작한다.

## 설명 방식
- 전문 용어를 쓰지 않는다. 써야 하면 한 줄로 풀어준다.
- 코드를 길게 보여주지 않는다. 무엇을 했는지만 말한다.
- 내가 틀린 방향으로 가면 그냥 따르지 말고 짚어준다.

## 개인정보
- 학생 이름·사진·연락처·학번을 결과물에 넣지 않는다.
- 자료에 그런 것이 들어 있으면 먼저 알려준다.

## 자주 틀리는 것
(여기에 한 줄씩 추가해 나갈 것)
```

# 4. 남이 만든 규칙집 가져오기

```plain text

```
AI가 반복하는 실수를 네 가지 원칙으로 정리한 것입니다.
```plain text
· 애매한 지시를 마음대로 해석하는 것
· 100줄이면 될 걸 1000줄로 부풀리는 것
```
코딩 전에 **가정을 먼저 말하게** 하고 **최소한만 짜게** 만듭니다.<br>**파일 하나 붙여넣는 수준**이라 부담이 없습니다.
