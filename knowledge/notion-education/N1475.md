# 실습 2. 세 검색을 나란히 — 검색 페이지 증축

정리일: 2026-10-08 · 교육 에셋 N1475

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
검색 페이지를 키워드·의미·하이브리드 세 열 비교 화면으로 키우고, 단일 검색이 놓치는 질문을 직접 확인합니다.
## 진행 단계
1. **프롬프트 입력, 패키지 설치, 서버 재시작**
- 입력할 내용:
```plain text
검색 페이지를 업그레이드해 주세요. 요구사항입니다.

1. 질문을 입력하면 세 가지 검색을 모두 실행합니다.
   - 키워드 검색: BM25. 한국어 토큰화에 형태소 분석기
     kiwipiepy를 사용해 주세요. 대상은 벡터DB에 적재된
     청크 원문 전체입니다.
   - 의미 검색: 기존 벡터 유사도 검색 그대로입니다.
   - 하이브리드 검색: 두 검색의 순위를 RRF 방식으로 결합합니다.

2. 결과 화면은 세 열로 나란히 보여 주세요.
   [키워드 검색] [의미 검색] [하이브리드] 순서입니다.
   각 열에 상위 K개 청크 카드를 표시하고, 카드마다 순위,
   점수, 청크 번호, 원문 미리보기를 보여 주세요.

3. K값 입력칸은 기존 것을 세 열이 함께 쓰게 해 주세요.

4. 서버 로그에 검색 한 건마다 세 검색의 1위 청크 번호가
   한 줄로 출력되게 해 주세요.

5. 필요한 패키지 설치 명령을 알려 주세요.
```
1. **준비 질문 B 꺼내기** — Ch2의 정확한 용어·번호 질문
2. **\[예측\]** — 세 열 중 어느 검색이 정확한 조각을 1위에 올릴지 적기
3. **검색·비교** — 질문 B를 검색하고 세 열의 1위 카드를 펼쳐 예측과 실제 대조
4. **질문 A 검색** — 일상 말 질문에서 키워드 검색 열이 어떤 결과를 내는지 관찰
5. **하이브리드 확인** — 두 질문 모두에서 하이브리드 열이 정확한 조각을 상위에 올렸는지 확인
6. **자유 질문** — 두세 개 던지며 세 열의 차이를 관찰하고, 키워드 검색이 특히 강한 질문 유형을 하나 메모
## 막히는 지점
- 키워드 검색 열만 이상함: Claude Code에 "BM25 토큰화에 kiwipiepy가 쓰이는지 확인해 주세요"라고 요청
- 형태소 분석기 설치 실패: 오류 로그를 Claude Code에 붙여넣고 해결 요청. 늦어지면 강사 호출
- 점수 크기가 열마다 다름: 정상. BM25 점수와 유사도 점수는 범위가 달라 열 안의 순위만 비교
