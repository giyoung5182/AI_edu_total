# 실습 3. 결정문이 마음에 안 든다 — 직접 뜯어고친다

정리일: 2026-10-08 · 교육 에셋 N1173

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
방금 받은 결정문을 결정권자의 눈으로 다시 읽고, 아쉬운 점을 개선 지시로 바꿔 시스템을 고칩니다.
## 진행 단계
1. **아쉬운 점 고르기** — 결정문에서 아쉬운 점을 한 가지 고릅니다. 흠잡을 데 없으면 더 좋아질 수 있는 한 곳을 고릅니다.
2. **개선 지시** — 아쉬운 점을 내 언어로 Claude Code에 요청합니다.
- 입력할 내용: 예시 \[A\] 반대 측의 핵심 우려와 보완 조치를 결정문에 포함 / \[B\] 결정문 첫 문장에 결정 사항을 못 박고 실행 일정과 담당 명시 / \[C\] 되돌릴 조건을 한 줄 넣기. 그대로 쓰지 말고 내 아쉬움에 맞게 고칩니다.
3. **재실행** — \[본부장 회의 시작\]으로 회의를 다시 실행합니다. 같은 선택도, 다른 선택도 가능합니다.
4. **대조** — 새 결정문과 이전 결정문을 나란히 놓고 내가 지시한 부분이 실제로 달라졌는지 확인합니다.
5. **교환** — 옆자리와 결정문을 바꿔 읽습니다.
## 막히는 지점
- 결정문이 그대로: "결정문 생성 지시에 방금 요청이 반영되었는지 보여 주세요"라고 요청
- 무엇이 아쉬운지 모르겠음: 결정에서 진 쪽 팀장의 눈으로 다시 읽어 봄. 억울해할 지점이 대개 아쉬운 지점
