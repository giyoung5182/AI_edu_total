# Jev 가 뭔지 모르는 사람은 여기를 눌러주세요
# 1. Jev가 대체 뭐임?
Jev는 TypeSafe AI가 2026년 9월 15일 공개한 첫 번째 **System One Model**입니다.
ChatGPT처럼 긴 문장을 생성하거나 설명하는 AI가 아니라,
**주어진 상황을 보고 빠르게 판단하는 데 특화된 AI**입니다.
예를 들어 일반적인 AI에게 이렇게 묻는다고 해봅시다.
> "이 고객 문의를 읽고 어떤 상황인지 분석해줘."
일반 LLM이라면 문장을 생성합니다.
```plain text
이 고객은 결제 과정에서 문제가 발생했으며
상당히 긴급한 상황으로 보입니다.
결제 관련 부서에서 우선적으로...
```
Jev는 이런 식으로 답하는 모델이 아닙니다.
대신 미리 정해놓은 질문을 던집니다.
```plain text
긴급한 문의인가?
→ YES 확률 0.96
```
또는
```plain text
어느 부서가 처리해야 하나?

결제
기술지원
영업

→ 결제
```
즉,
> **LLM = 글을 생성하는 AI**<br>**Jev = 결정을 내리는 AI**
라고 생각하면 가장 쉽습니다.
TypeSafe는 이를 **"unstructured state in → typed probabilistic decisions out"**, 즉 상황을 넣으면 소프트웨어가 바로 사용할 수 있는 구조화된 확률 기반 판단을 반환하는 방식으로 설명합니다.

# 3. 왜 이렇게 빠르고 저렴함?
일반적인 LLM은 답변을 한 토큰씩 생성합니다.
예를 들어,
```plain text
이 이메일은 사기성 메일일 가능성이...
```
처럼 글자를 계속 생성해야 합니다.
반면 Jev는 애초에 긴 글을 만들지 않습니다.
```plain text
Fraud
```
또는
```plain text
YES → 0.97
```
같은 **결정 자체**만 반환합니다.
TypeSafe 공식 발표 기준 현재 Jev는:
- End-to-end latency: **70\~500ms**
- Input: **\$0.042 / 1M tokens**
- Output: **무료**
- 공식 System One workflow에서는 최대 **193.6× 빠르고 444.6× 저렴**한 결과를 발표
했습니다.
다만 여기서 중요한 점.
> **"Jev는 항상 모든 LLM보다 193배 빠르다"는 뜻은 아닙니다.**
193.6× / 444.6×는 TypeSafe가 구성한 특정 **System One workflow 평가 결과**입니다.
TypeSafe도 해당 숫자가 실제 환경에서 기대할 수 있는 성능 향상의 **높은 쪽에 해당할 가능성이 있다**고 직접 설명하고 있습니다.

# 4. Jev의 핵심 3가지 — Noul / Choice / Score
Jev를 처음 쓸 때는 복잡하게 생각할 필요 없습니다.
**Noul / Choice / Score**
이 3가지만 먼저 이해하면 됩니다.
## ① Noul
### "맞아? 아니야?"
YES / NO 성격의 판단입니다.
예를 들어 고객 문의가 있습니다.
```plain text
카드 결제가 두 번 됐습니다.
환불해주세요.
```
Jev에게 이렇게 물어봅니다.
```plain text
이 고객은 환불을 요청하고 있는가?
```
결과는 이런 개념입니다.
```plain text
YES 확률 → 0.98
```
즉 **0\~1 사이의 확률**로 판단합니다.
0에 가까우면 NO,
1에 가까우면 YES입니다.
### Noul 활용 예
```plain text
이 메일은 사기성인가?

이 댓글은 공격적인가?

이 문의는 긴급한가?

사용자가 환불을 요청했는가?
```
**YES / NO로 명확하게 질문할 수 있다면 → Noul**
## ② Choice
### "여러 개 중 뭐야?"
미리 정해놓은 여러 선택지 가운데 하나를 고르게 합니다.
예를 들어:
```plain text
고객 문의: "배송이 일주일째 안 오고 있어요."
```
질문: 어느 팀이 처리해야 할까?
선택지:
```plain text
배송
환불
결제
상품문의
```
Jev가 각 선택지에 대한 확률을 계산하고 하나를 선택합니다.
```plain text
배송     0.91
환불     0.05
결제     0.01
상품문의 0.03

→ 배송
```
Choice는 현재 **최대 255개 선택지**를 지원합니다.
**정답 후보를 미리 적을 수 있다면 → Choice**
## ③ Score
### "얼마나 심함?"
YES / NO로 자르기 어려운 연속적인 수준을 평가할 때 사용합니다.
예:
```plain text
고객의 불만 수준은?

1. 평온함
2. 약간 불만
3. 불만이 큼
4. 매우 화남
```
Score는 **단계가 존재하는 평가**에 적합합니다.
(왼쪽 화살표 토글을 열어 봐주세요)

## 4. 이제 State를 바꿔보기
Jev를 이해하는 가장 빠른 방법입니다.
기존 고객 문의를 지우고:
```plain text
The customer says:
"My password reset link doesn't work
and I can't log in."
```
처럼 바꿔봅니다. 질문은 그대로 둡니다.
```plain text
Which team should handle this customer request?
```
다시 **Run Jev** 를 누릅니다.
아까는 결제 문제였는데 이번에는 로그인/기술 문제이므로 판단이 달라지는 걸 볼 수 있습니다.
## 5. 여기서 Jev의 구조가 보임
Jev는 ChatGPT처럼
```plain text
안녕하세요
↓
무엇을 도와드릴까요?
↓
대화
↓
긴 답변
```
하는 AI가 아닙니다.
기본 구조는:
```plain text
STATE
↓
QUESTION
↓
DECISION
```
입니다.
**State** — Jev가 보고 판단해야 하는 상황
**Question** — 그 상황을 보고 어떤 판단을 내려야 하는지
**Decision** — 미리 정해놓은 형태의 결과

## 7. Jev는 정확히 뭐임?
Jev는 TypeSafe AI가 만든 첫 번째 System One Model입니다.
일반적인 LLM처럼 문장을 생성하는 모델이 아니라 **소프트웨어 안에서 빠르게 판단을 내리는 AI 모델**에 가깝습니다.
일반 LLM은:
```plain text
질문
↓
생각
↓
문장 생성
```
Jev는:
```plain text
상황
↓
정해진 질문
↓
판단
```
입니다.
Vercel 역시 Jev를 software를 위한 probabilistic decision model로 설명하고 있습니다.
## 8. "빠른 ChatGPT"라고 생각하면 안 됨
Jev에게 "오늘 서울 여행 계획 짜줘" 라고 해서 여행 계획을 작성하게 하는 모델이 아닙니다.
또 이메일 답장 작성, 블로그 글 작성, Python 코드 생성 같은 것도 Jev의 역할이 아닙니다.
Jev는 텍스트 생성 모델이 아니라 판단 모델입니다.

## 10. Jev의 핵심 판단 3가지
TypeSafe Direct API에서는 **Noul / Choice / Score** 세 가지 질문 타입을 사용합니다.
다만 Vercel과 Jev Playground에서는 Noul에 해당하는 인터페이스를 **Boolean**이라고 표시합니다. 두 provider의 API 표면이 완전히 같지는 않으니 개발할 때는 구분해야 합니다.
### ① Boolean / Noul — 맞아? 아니야?
```plain text
이 이메일은 사기성인가?

환불을 요청하고 있는가?

긴급한 문의인가?

사람 검토가 필요한가?
```
YES / NO 성격의 판단입니다. 결과는 단순한 YES가 아니라 probability까지 활용할 수 있습니다.
```plain text
YES → 0.97
```
### ② Choice — 여러 개 중 뭐야?
예:
```plain text
이 문의는 어느 팀?

Billing
Technical
Sales
Shipping

→ Billing
```
분류·라우팅·다음 행동 선택에 특히 잘 맞습니다.
### ③ Score — 어느 정도임?
예:
```plain text
이 문의의 긴급도는?

1. 낮음
2. 보통
3. 높음
```
또는:
```plain text
이 콘텐츠 후킹 강도는?

매우 약함
약함
보통
강함
매우 강함
```
처럼 단계가 있는 평가에 사용합니다.

## 12. Multiple Questions도 해보기
Playground 상단을 보면 **Single question** / **Multiple questions** 두 개가 있습니다.
Jev의 진짜 활용법은 사실 Multiple Questions 쪽에서 더 잘 보입니다.
하나의 State에 대해 여러 판단을 동시에 시킬 수 있습니다. Jev는 같은 State에 대한 여러 typed question을 병렬로 평가하도록 설계되어 있습니다.
예:
```plain text
STATE
"고객이 카드에서 두 번 결제됐고
오늘 해결되지 않으면 탈퇴하겠다고 함."
```
이 상황 하나에:
```plain text
결제 문제인가?
→ Boolean

어느 부서가 담당해야 하나?
→ Choice

긴급도는?
→ Score

사람 검토가 필요한가?
→ Boolean
```
를 동시에 묻는 겁니다.
## 13. 왜 이렇게 여러 개로 쪼갬?
일반적인 AI라면 "이 고객 문의를 분석해서 어떻게 처리해야 하는지 알려줘" 라고 한 번에 시키고 싶습니다.
하지만 Jev는 반대로 **큰 문제를 작은 판단으로 쪼개는 방식**이 잘 맞습니다.
```plain text
결제 문제?
+
긴급함?
+
고객 화남?
+
해지 위험 있음?
+
사람 필요?
```
↓ 코드에서:
```plain text
결제 문제
+
긴급도 높음
+
해지 위험 높음

↓

긴급 Billing Queue
```
처럼 사용할 수 있습니다.
## 14. 일반인은 어디에 써먹을 수 있음?
직접 코딩하지 않더라도 Jev를 이해할 때 가장 중요한 질문은 **"내가 매일 반복해서 하는 판단은 뭐지?"** 입니다.
### 이메일
- 중요한 메일인가? → Boolean
- 무슨 종류인가? → Choice
- 긴급도는? → Score
### 콘텐츠
- 훅이 강한가? → Boolean
- 어떤 유형인가? → Choice
- 정보성은? → Score
### 뉴스 큐레이션
- AI 관련인가?
- 내 팔로워가 관심 있어 할까?
- 최근 이슈인가?
- 어떤 카테고리인가?
- 콘텐츠 가치가 높은가?
### 고객 리뷰
- 긍정적인가?
- 배송 불만인가?
- 제품 문제인가?
- 재구매 의향이 있는가?
### 리서치
- 내 연구 주제와 관련 있는가?
- 실험 논문인가?
- 우선 읽을 가치가 있는가?
## 15. 이런 작업에서 특히 강함
Jev와 잘 맞는 작업에는 공통점이 있습니다.
### ① 답 후보를 미리 정할 수 있음
```plain text
YES / NO

A / B / C

낮음 / 보통 / 높음
```
### ② 같은 판단을 많이 반복함
```plain text
메일 100,000개

리뷰 1,000,000개

Agent action 수천 번
```
### ③ 속도가 중요함
```plain text
게임

브라우저 Agent

실시간 UI

모델 라우팅
```
## 16. 반대로 Jev 쓰면 안 되는 것
**글 작성** (메일 써줘, 블로그 써줘, 코드 만들어줘) → LLM
**깊은 추론** (이 논문 분석해줘, 복잡한 수학 문제 풀어줘) → Reasoning Model
**이미 코드로 정확히 판단 가능한 것** (`price >= 100000`?) → 그냥 코드
정리하면:
> **정확한 규칙 → Code**<br><br>**애매한 의미 판단 → Jev**<br><br>**생성 / 복잡한 추론 → LLM**
## 17. Probability가 중요한 이유
Jev는 답뿐만 아니라 얼마나 확신하는지 판단할 수 있는 정보도 제공합니다.
예:
```plain text
Billing      92%
Technical     6%
Sales         2%
```
라면 비교적 명확합니다.
반대로:
```plain text
Billing      51%
Technical    46%
Sales         3%
```
라면 애매합니다. 이 차이를 프로그램에서 이용할 수 있습니다.
## 18. 그래서 Jev + LLM 조합이 강함
예:
```plain text
이메일 10,000개
↓
Jev
확실한 것 → 자동 분류
애매한 것 → 더 강한 LLM
중요하거나 위험한 것 → 사람 검토
```
Jev를 "모든 AI를 대체하는 모델"로 보기보다 비싸고 느린 모델을 호출하기 전에 빠른 판단을 담당하는 층으로 보는 편이 훨씬 정확합니다. Vercel 역시 Agent loop에서 Jev가 decision point를 담당하고, 생성형 모델은 답변 작성, 코드는 권한과 실행을 담당하는 구조를 제안합니다.

## 19. TypeSafe 가입 막혔는데 개발자는 어떻게 씀?
현재 가장 쉬운 우회 경로는 **Vercel AI Gateway** 입니다.
[개별 링크 제외]
Vercel은 Jev를 AI Gateway에서 공식 지원하고 있습니다.
2026년 9월 21일부터는 Vercel AI SDK, TypeSafe client, 직접 HTTP API 세 방식으로 Jev를 호출할 수 있습니다.
중요한 점은: **Vercel AI Gateway를 사용할 때 TypeSafe 신규 가입이 필요하지 않습니다.**
Vercel 계정에서 발급받은 `AI_GATEWAY_API_KEY` 를 사용합니다.
따라서 TypeSafe Console의 신규 가입 중단과 별개의 경로입니다.
## 20. 개발자 사용 흐름
```plain text

↓

Jev 모델 선택
↓
typesafe-ai/jev
↓
API 호출
```
현재 Vercel 모델 페이지에서도 직접 API Key를 발급하고 Jev 예제 코드를 확인할 수 있습니다.
## 21. Vercel에서 모델 ID
```plain text
typesafe-ai/jev
```
를 사용합니다.
Vercel 예제는 이런 구조입니다.
```javascript
const result = await evaluate({
  model: 'typesafe-ai/jev',

  state:
    'The support agent issued a full refund to the customer.',

  questions: {
    refunded: {
      type: 'boolean',
      instructions: 'Was a refund issued?',
    },
  },
});
```
즉 개발자도 결국 똑같습니다. `STATE + QUESTION + DECISION TYPE` 를 코드로 보내는 겁니다.
## 22. HTTP로도 가능

따라서 특정 프레임워크에 묶이지 않고 여러 언어에서 호출할 수 있습니다.
구조는:
```plain text

↓
Vercel AI Gateway
↓
Jev
↓
typed decision
```
입니다.
## 23. 지금 무료임?
2026년 9월 24일 현재 Vercel은 Jev의 무료 프로모션을 진행 중이며, 공식 안내상 9월 25일 종료 예정입니다.
따라서 개발자가 이 가이드를 나중에 보는 경우에는 Vercel 모델 페이지에서 최신 가격을 다시 확인해야 합니다.
## 24. Jev가 얼마나 빠름?
TypeSafe 공식 발표 기준: **70\~500ms latency** 입니다.
TypeSafe의 특정 workflow 평가에서는 **최대 193.6× faster, 최대 444.6× cheaper** 라는 결과도 발표됐습니다.
다만 모든 작업에서 193배 빨라진다는 뜻은 아닙니다. 작업과 비교 대상에 따라 결과는 크게 달라집니다.
## 25. 실제 이용 속도도 엄청 빠르게 늘어남
Vercel에 따르면 Jev는 AI Gateway 출시 24시간 안에 유료 팀 약 13%가 사용했고, Vercel AI Gateway 역사상 가장 빠르게 채택된 모델이 됐습니다.
이런 빠른 확산과 함께 TypeSafe 공식 신규 가입도 9월 22일 일시 중단됐습니다.
## 26. 실제 사례 ① Doom
TypeSafe 공식 데모.
```plain text
게임 상태
↓
Jev
↓
다음 행동
↓
게임 상태 변경
↓
다시 판단
```
을 반복합니다.
핵심은 "AI가 Doom을 할 수 있다"보다 **AI 판단을 실시간 게임 루프 안에서 계속 돌릴 수 있을 정도로 빠르다**는 점입니다.
## 27. 실제 사례 ② 항공권 검색
Browser Agent에서 현재 브라우저 상태 → Jev → 다음 행동 결정을 반복합니다.
제작자 보고:
```plain text
전체 약 7초
비용 약 $0.0039
```
## 28. 실제 사례 ③ 이메일 분류
정상 이메일과 사기성 이메일 총 100개를 Jev로 1차 분류하고, 애매한 31개만 더 큰 모델로 넘겼습니다.
결과:
```plain text
Jev 1차 분류 1.42초
최종 96 / 100
```
이 사례가 Jev의 fallback 구조를 가장 이해하기 쉽게 보여줍니다.
## 29. 실제 사례 ④ Drape
사용자의 상황과 현재 착장 정보를 바탕으로 "옷장에서 다음 아이템은?"을 Jev가 판단합니다.
제작자 보고:
```plain text
약 620ms / decision
약 $0.0011 / decision
```
## 30. 실제 사례 ⑤ 로봇팔
MuJoCo 시뮬레이션에서도 현재 로봇 상태 → Jev → 다음 행동을 반복해 물체를 움직이는 실험이 등장했습니다.
## 31. 실제 사례 ⑥ 바이럴 예측
SuperX 프로젝트는 게시물 하나를 평가할 때 무려 61개의 작은 질문을 사용했습니다.
즉 "바이럴인가?"를 한 번 묻는 게 아니라, 후킹? 감정? 정보? 공감? 호기심? ...처럼 문제를 잘게 쪼개는 겁니다.
이게 Jev의 활용 방식을 굉장히 잘 보여줍니다.
## 32. 결국 모든 사례의 공통점
Doom: 다음 행동? · 항공권: 다음 클릭? · 이메일: 사기? · Drape: 다음 옷? · 로봇: 다음 움직임?
전부 **작고 명확한 판단을 매우 빠르게 반복**하고 있습니다.
## 33. Jev로 뭘 만들지 모르겠다면
이 질문부터 해보면 됩니다.
```plain text
내가 하루에 반복해서 내리는 판단이 뭐지?

YES / NO로 바꿀 수 있나?

몇 가지 후보 중 하나로 바꿀 수 있나?

점수로 바꿀 수 있나?

이 판단을 하루에 몇 번 하지?
```
예를 들어 AI 콘텐츠를 고른다면:
```plain text
최근 이슈인가?
→ Boolean

일반인이 이해할 수 있나?
→ Boolean

실용성은?
→ Score

콘텐츠 유형은?
→ Choice

캐러셀 가치가 있나?
→ Boolean
```
처럼 만들 수 있습니다.
