## 1-2. 저장 방식 4가지 — 전체 지도 (5분)
```plain text

   앱 → Lovable이 대신 관리해주는 데이터베이스

   구글시트가 데이터베이스 역할을 함.
```

### STEP 3. 테이블 생성 요청
**Lovable 채팅창에 붙여넣기:**
```plain text
연결된 내 Supabase에 데이터베이스 테이블을 만들고,
앱이 실제로 그 테이블에 저장하도록 연결해줘.

가장 중요:
데이터는 반드시 Supabase에 실제로 저장되어야 해.
React useState나 mock 데이터가 아니라 진짜 데이터베이스에
저장하고, 새로고침해도 데이터가 그대로 남아 있어야 해.

아래 두 테이블을 실제로 생성해줘:

1) vendors (업체)
   - id (자동 생성)
   - vendor_name (업체명, 텍스트)
   - vendor_group (구분: 야채/공장/정육, 텍스트)
   - initial_balance (초기 미수금, 숫자)

2) payments (결제)
   - id (자동 생성)
   - vendor_id (업체 연결)
   - requester (요청자, 텍스트)
   - request_amount (요청금액, 숫자)
   - scheduled_amount (예정금액, 숫자)
   - completed_amount (완료금액, 숫자)
   - status (상태: 요청/예정/완료, 텍스트)
   - request_date (요청일, 날짜)
   - completed_date (완료일, 날짜)
   - memo (메모, 텍스트)

기존 화면의 입력·조회 기능이 이 테이블을 실제로 읽고 쓰도록
연결해줘. 지금 브라우저에만 저장되는 부분을 전부 바꿔줘.
```
### STEP 4. 검증
```plain text
① 앱에서 업체 1건 입력 → 새로고침 → 남아있나?
② supabase.com → 내 프로젝트 → Table Editor
   → vendors 테이블에 행이 실제로 있나?
③ 스마트폰으로 접속 → 같은 데이터가 보이나?
```
> ⚠️ **오늘 목표는 vendors·payments 두 개까지입니다.** 6개 테이블을 다 하려다 시간을 다 쓰면 안 됩니다. 나머지 4개(companies·requests·adminList·prevSnapshot)는 이후에 이어서 하면 됩니다.
> ⚠️ **크레딧:** 이 작업은 크레딧을 꽤 씁니다. 부족하면 vendors 하나만 먼저 하세요.

## 프로님 — 스키마 복구
**준비물:** Lovable에서 받은 코드 압축파일
```plain text
① 압축 풀기 → supabase → migrations 폴더
② SQL 파일 17개 확인 (날짜순 정렬됨)
③ 1번 파일 더블클릭 → 메모장에서 열림
④ Ctrl+A → Ctrl+C
⑤ supabase.com → 프로젝트 → 왼쪽 [SQL Editor]
⑥ Ctrl+V → 오른쪽 아래 [Run]
⑦ "Success" 확인 → 다음 파일
⑧ 17번까지 반복
⑨ [Table Editor]에서 테이블 33개 확인
```
> 💡 **17개라고 부담 갖지 마세요.** 큰 것은 1번·3번 두 개뿐이고 나머지는 몇 줄짜리입니다. 가장 짧은 파일은 한 줄입니다.
> ⚠️ **반드시 순서대로.** 뒤 파일이 앞 파일에서 만든 표를 수정하므로 순서가 바뀌면 오류가 납니다.
**오류 시:** 몇 번째 파일인지, 오류 메시지가 뭔지 캡처 → 강사 호출
