# 1부. 먼저 알고 시작하면 시간이 반으로 줄어드는 것들

## 1️⃣ 안 될 때 — 원인은 셋뿐입니다
**전체 문제의 8할이 이 셋입니다.** 프롬프트를 다시 쓰기 전에 여기부터 확인하십시오.
### ① "파일을 첨부해 주세요"라고 할 때
**채팅만 모드입니다.** 열려 있는 시트를 못 읽습니다.
```plain text
Copilot 창 상단 모드 표시 클릭 → [편집] 선택
```
> ⚠️ **파일이 눈앞에 열려 있는데도 첨부하라고 합니다**
채팅만 모드는 일반 챗봇처럼 작동합니다. **프롬프트를 고치지 마시고 모드를 바꾸십시오.**
"데이터를 못 찾겠다", "시트 이름을 모르겠다"도 같은 원인입니다.
### ② "데이터를 찾을 수 없습니다"라고 할 때
**표 서식이 안 되어 있습니다.**
```plain text
데이터 안 셀 클릭 → Ctrl + T → 머리글 포함 체크 → 확인
```
### ③ Copilot 버튼이 회색일 때
**자동 저장이 꺼져 있습니다.** 파일이 OneDrive 폴더에 없다는 뜻입니다.
```plain text
파일을 바탕화면 또는 문서 폴더로 이동
(다운로드 폴더는 동기화 안 됨)
```

무엇

### 나쁜 예
```plain text
보고서 써줘
```
### 좋은 예
```plain text
[목표] 지점 실적 현황 보고서 초안을 작성해줘

[맥락] 다음 주 본부장 보고용이야.
       숫자보다 실행 방안에 관심이 많은 분이야.

[자료] 월별성과 시트의 2026년 데이터만 사용해줘

[기대] A4 한 장, 결론 먼저, 불릿 3개 이내
       추측성 표현은 쓰지 말 것
```
> 💡 **전부 채우기 부담스러우면 맥락(C)부터 넣으십시오**
"누가 볼 문서인지"만 알려줘도 톤이 확 달라집니다.

## 3️⃣ 반드시 지킬 다섯 가지
**오늘 실습에서 계속 나올 것들입니다.**
### ① 시트명·열 이름을 그대로 쓰십시오
```plain text
"규모별로"                        ✗
"지점마스터 시트의 지점규모 열"     ✓
```
Microsoft 공식 문서에도 명시돼 있습니다. **Copilot은 주로 영어 자료로 학습되어, 한국어에서는 정확도가 떨어질 수 있습니다.** 열 이름을 정확히 쓰는 게 이 문제를 줄이는 가장 효과적인 방법입니다.
### ② 시트를 연결할 때는 연결 열을 알려주십시오
```plain text
지점마스터의 지점규모와 지점장발령이력의 성별을
지점코드로 연결해서 교차표를 만들어줘
```
**"지점코드로 연결해줘"** 이 한 마디가 성공률을 크게 올립니다.
### ③ 계산은 결과 말고 수식으로 받으십시오
```plain text
합계 얼마야?              ✗  숫자만 받으면 검증 불가
합계 구하는 수식 알려줘     ✓  Excel이 계산하니 안 틀림
```
Microsoft 공식 문서도 같은 안내를 합니다. **정확도가 필요한 작업에는 SUM, AVERAGE, IF 같은 기본 수식을 쓰라**는 겁니다.
### ④ 원인은 절대 묻지 마십시오
```plain text
왜 이 지점 실적이 좋아?        ✗  지어냅니다
이걸 확인하려면 뭘 봐야 해?     ✓  이건 잘 알려줍니다
```
**데이터에는 원인이 없습니다.** 숫자의 차이만 있습니다. 그런데 물어보면 그럴듯한 이유를 만들어냅니다.
### ⑤ 수정할 때는 범위를 못박으십시오 → 부정 프롬프트 기법. (수정요청 할 때)
```plain text
③번 문단만 수정해줘. 전체를 다시 쓰지는 마.
```
이 말이 없으면 **전체를 다시 만들면서 멀쩡했던 부분이 바뀝니다.**

## 4️⃣ 안전장치 — 편집 모드는 시트를 바꿉니다
**시트를 읽으려면 편집 모드여야 하는데, 편집 모드는 시트를 바꿉니다.**
그래서 안전장치가 필요합니다.
```plain text
① 원본 시트 복사   ← 유일한 확실한 방법
   시트 탭 우클릭 → [이동/복사] → "복사본 만들기" 체크

② 프롬프트에 못박기
   "시트는 수정하지 마. 결과만 알려줘."

③ 중지 버튼 위치 익히기
   입력창 오른쪽 아래 모서리
```
> ⚠️ **프롬프트는 부탁이고, 원본 복사가 보험입니다**
편집 모드 작업은 `Ctrl + Z`가 안 될 수 있습니다. **30초 투자하십시오.**
---
## 5️⃣ 대화가 길어지면 품질이 떨어집니다
앞부분 지시가 흐려지고, 이전 작업 형식이 새 작업에 섞입니다.
```plain text
작업이 바뀌면              → 새 대화
결과가 이상해지기 시작하면   → 새 대화
```
> 💡 **"아까 그거 말고"라는 말이 나오면 이미 늦은 겁니다**
---
## 6️⃣ 검증 — 세 가지만 물어보십시오
답변을 받으면 습관처럼 물어보십시오. **10초면 됩니다.**
```plain text
방금 답변의 근거가 되는 부분을 표시해줘.
```
```plain text
이 답변 중 시트에서 직접 확인되지 않은 부분이 있으면
어느 부분인지 알려줘.
```
```plain text
이 숫자가 어떻게 계산됐는지 수식으로 보여줘.
```
> ⚠️ **근거를 못 대면 그 답변은 쓰지 마십시오**
Microsoft 공식 문서도 \*\*"유창하고 문법적으로 올바르게 생성하지만 부정확할 수 있다"\*\*고 명시합니다.
**문장이 매끄러운 것과 내용이 맞는 것은 별개입니다.**

## 🖥️ 실습 1 — 인사이트 자동 생성 (10분)
**가장 쉬운 시작점입니다.** 데이터를 주면 Copilot이 알아서 볼 만한 것을 찾아줍니다.
### 1단계. 기본 요청
`월별성과` 시트를 클릭하고 입력합니다.
```plain text
월별성과 시트의 데이터에서 눈에 띄는 패턴을 찾아줘.
차트나 요약 형태로 보여줘.
```
[원본 이미지 제외]
### 2단계. 결과 확인
```plain text
□ 추세를 짚어줬는가
□ 이상값을 지적했는가
□ 차트가 제안되었는가
```
### 3단계. 새 시트로 옮기기
답변 아래 버튼을 찾습니다.
```plain text
[그리드에 모든 인사이트를 추가하세요]
```
**클릭하면 새 시트가 생기면서** 발견된 인사이트가 정리됩니다.
> 💡 **버튼이 안 보이면**
```plain text
방금 인사이트를 새 시트에 정리해줘.
```
### 4단계. 시트를 연결한 요청 — 앞서 배운 것 적용
```plain text
지점규모별로 신계약건수 평균이 어떻게 다른지 알려줘.
지점마스터 시트의 지점규모 열과
월별성과 시트의 신계약건수 열을
지점코드로 연결해줘.
```
> 💡 **1부 ①②를 그대로 쓴 겁니다**
시트명·열 이름을 정확히 쓰고, 연결 열을 알려줬습니다. **이렇게 안 쓰면 헤맵니다.** 한번 짧게 물어보고 비교해 보셔도 좋습니다.
### 5단계. 검증
```plain text
방금 계산에 사용한 수식을 알려줘.
```
**수식이 나오면 Excel에서 직접 확인할 수 있습니다.**

## 🖥️ 실습 2 — 피벗과 교차 집계 (12분)
**두 가지 기준으로 동시에 보는 것**입니다. 실무에서 가장 자주 쓰는 형태입니다.
### 1단계. 기본 피벗
```plain text
지점장발령이력 시트로 피벗 테이블을 만들어줘.

행: 직전보직
열: 성별
값: 건수

새 시트에 만들어줘.
```
### 2단계. 결과 확인
```plain text
□ 직전보직 5가지가 행에 있는가
□ 남/여가 열에 있는가
□ 합계가 141인가
```
### 3단계. 두 시트를 연결한 교차표
[원본 이미지 제외]
```plain text
지점규모별 · 성별 지점장 배치 현황을 표로 만들어줘.

지점마스터의 지점규모와
지점장발령이력의 성별을 지점코드로 연결해줘.

각 칸에 건수를 표시해줘.
새 시트에 만들어줘.
```
### 4단계. 서식으로 보기 좋게
```plain text
방금 만든 표에서 가장 큰 값과 가장 작은 값을
각각 다른 색으로 강조해줘.
```
> 💡 **조건부 서식도 말로 시킵니다<br>**
[원본 이미지 제외]
```plain text
신계약건수가 100 이상인 행을 초록색으로 표시해줘
FC정착률이 낮은 순서로 정렬해줘
지역이 서울인 행만 필터링해줘
```
답변 아래 **\[적용\] 버튼을 눌러야** 시트에 반영됩니다.
### 5단계. 되돌리기
```plain text
방금 적용한 조건부 서식을 모두 지워줘.
```

## 🖥️ 실습 3 — 숫자는 맞는데 결론이 틀릴 때 (15분)
**마지막 실습입니다. 오늘 가장 중요한 부분입니다.**
### 1단계. 부서에서 나온 실제 질문
```plain text
지점장 성별에 따라 지점 성과가 다른지 확인하고 싶어.

지점장발령이력의 성별과
월별성과의 신계약건수를 지점코드로 연결해서
성별 평균 신계약건수를 비교해줘.

표로 보여줘.
```
[원본 이미지 제외]
### 2단계. 결과를 봅니다
**차이가 나올 겁니다.** 그럼 이렇게 보고해도 될까요?
> "여성 지점장 배치 지점의 평균 신계약건수가 남성 대비 높게 나타났습니다."
**잠깐 멈추고 생각해 보십시오.**
[원본 이미지 제외]
### 3단계. 한 가지만 더 확인합니다
실습 2에서 만든 교차표를 다시 보십시오.
```plain text
남성:  대형 22 / 중형 53 / 소형 47
여성:  대형 6  / 중형 11 / 소형 2
```
> ⚠️ **그림이 바뀝니다**
남성은 **소형 지점에 47건**이나 배치돼 있습니다. 여성은 2건뿐입니다.
소형 지점은 규모가 작아 신계약건수도 적습니다. 그렇다면 아까 나온 차이는 **성별 때문이 아니라 배치 때문**일 수 있습니다.
[원본 이미지 제외]
### 4단계. 물어보는 방식을 바꿉니다
```plain text
아래 결과만으로 "여성 지점장이 성과가 더 좋다"고 결론 내릴 수 있는지 검토해주고,
그러면 어떤 측면에서 더 분석을 하면 '지점장 성별'에 따른 객관적인 분석을 할 수 있지 고민해서 작업 계획 알려줘 (계획 모드로 실행하기)
```
### 5단계. 보고서로 정리
```plain text
아래 내용으로 보고용 요약을 만들어줘.

[확인된 수치]
- 월평균 신계약건수

[구성]
① 한 줄 결론
② 단순 비교가 오해를 부를 수 있는 이유
③ 추가 확인이 필요한 사항

[금지]
- 제시한 수치 외 새 숫자 생성 금지
- 원인 추측 금지
- 성별 능력 차이로 읽힐 표현 금지
```
[원본 이미지 제외]
### 6단계. 검증
```plain text
□ 시트에 없는 숫자가 등장하지 않았는가
□ 원인을 추측한 문장이 없는가
□ 성별 능력 차이로 읽힐 표현이 없는가
```
---
### 정리하면
```plain text
계산은 정확했습니다
   ↓
그런데 첫 해석은 틀렸습니다
   ↓
조건을 나눠보니 다른 그림이 나왔습니다
```
> **숫자가 틀리는 것보다 위험한 게 있습니다.**
**숫자는 맞는데 해석이 틀리는 것**입니다. 계산이 정확하니까 검산으로도 안 잡힙니다.
방법은 하나뿐입니다. **"두 그룹이 애초에 같은 조건이었나"를 한 번 물어보는 것.**

```plain text
프롬프트        →  목표·맥락·자료·기대 (GCSE)
시트 연결       →  연결 열을 반드시 명시
계산            →  결과 말고 수식으로
원인            →  묻지 말고 "확인할 항목"을 물어라
수정            →  범위를 못박아라
대화            →  주제 바뀌면 새로 시작
안전            →  원본 복사가 유일한 보험
```
> **기능은 계속 바뀝니다. 이 기준은 안 바뀝니다.**

## 시작하는 법
**전부 다 하려고 하지 마십시오.**
> 가장 시간을 많이 쓰는 업무 **하나**부터 적용해 보십시오.<br>하나가 익숙해지면 나머지는 자연스럽게 따라옵니다.
### 첫 주에 할 것
```plain text
□ 매주 반복하는 작업 하나를 고른다
□ 그 작업을 Copilot으로 해본다
□ 잘 된 프롬프트를 메모장에 저장한다
```
### 잘 쓰는 조직의 공통점
```plain text
① 해야 할 일을 분명하게 정리한다
② Copilot에게 초안을 만들게 한다
③ 사람이 결과를 다듬고 검토한다
```
**②만 하려고 하면 실패합니다.** ①과 ③이 있어야 도구가 힘을 발휘합니다.
