### AI가 코드를 잘하는 이유
똑똑해져서가 아니라 **코드는 규칙이 명확한 영역**이기 때문입니다. 시나 에세이는 다음에 올 말의 선택지가 아주 많아 매번 다르게 나오지만, 코드는 괄호가 반드시 닫히고 문법이 정해져 있어 비슷하게 나옵니다. 그래서 우리 할 일은 **AI가 헤매지 않도록 조건을 좁혀 주는 것**입니다. 오늘 PART04는 명세로, PART03은 자료 범위로, PART05·06은 검증 기준으로 이 조건을 좁혀갑니다.

### 오늘 이것을 쓰는 이유

**내 폴더의 자료를 직접 다루기 때문입니다.** 어제는 파일을 대화에 붙여서 쓰셨습니다(그 순간의 사본). 오늘은 **폴더를 가리키고 거기서 읽어 가게** 합니다(위치를 지정) - 파일이 바뀌어도 말은 그대로이고, 결과물이 화면 글이 아니라 파일로 폴더에 남습니다.

오늘 결과물은 **`.html`**** 파일 하나 (단일 파일 웹앱)** 입니다. 더블클릭하면 브라우저에서 열리고, 설치할 것이 없고, 파일 하나만 전달하면 되고, AI가 전체를 한 번에 봅니다.

**오늘 안 다루는 것** - 진짜 로그인, 여러 사람 동시 수정, 매체 광고 플랫폼 연동(서버·계정 권한이 필요). 다만 「관리자만 기준값을 고칠 수 있게」처럼 화면을 나누고 암호를 거는 정도는 만듭니다 - 파일을 열면 암호가 보이므로 진짜 보안은 아니고, 실수로 고치는 것을 막는 장치입니다. 데이터 저장은 PART05(결과물 만들기)에서 다룹니다.

### 첫 번째 벽 - 컨텍스트 붕괴
AI는 대화를 기억하지 않고 **매번 처음부터 다시 읽습니다.** 30번째 요청이면 앞의 29턴을 전부 다시 읽고 답합니다. 그 과정에서 처음 정한 규칙이 뒤에 쌓인 수십 턴에 **희석**되고, 긴 대화에서는 앞부분과 끝부분은 잘 참조하지만 **가운데는 덜 참조**합니다.
> 📎 출처: Liu et al., 「Lost in the Middle: How Language Models Use Long Contexts」 TACL 12:157–173, 2024 (arXiv:2307.03172) <br>- 실무 결론: **중요한 지시는 맨 앞이나 맨 뒤에 둡니다.**
**두 가지 규칙** - 30턴 규칙(약 서른 개 메시지를 넘으면 새 대화로 옮김), **2회 규칙**(같은 문제를 두 번 고쳐서 안 되면 세 번째를 시도하지 않고 멈춤). 2회 규칙은 PART05에서 실제로 씁니다 - 세 번째부터는 실패한 시도가 대화에 쌓여 고칠수록 나빠집니다.
**대응** - ①지금까지 확정된 것을 다섯 줄로 요약 ②새 대화를 엽니다 ③그 요약을 첫 줄에 붙여넣고 이어갑니다.
```javascript
이전 대화에서 하던 작업을 이어서 한다.
[ 지금까지 확정된 것 ]
- 만들 것: (한 줄로)
- 규칙: (핵심만)
- 제약: (하지 말 것)
- 여기까지는 동작을 확인했다
[ 지금 할 일 ]
(하나만) 이어서 만들어 달라. 나머지는 그대로 두어라.
```

### 같은 요청도 뒤로 갈수록 비싸집니다
매번 처음부터 다시 읽는다는 성질은 정확도뿐 아니라 **사용량**에도 그대로 나타납니다. 대화가 길수록 한 번의 수정 요청에서 읽어야 할 양이 늘어납니다.

이전 버전으로 되돌림

새로 만드는 것이 아니라 **소모가 거의 없습니다**. 꼬였을 때 되돌리기가 먼저인 이유입니다

### 두 번째 벽 - 회귀
수정을 요청하면 AI는 기존 코드를 다시 씁니다. 요청을 여러 개 몰아서 넣으면 그것을 동시에 만족시키려고 코드를 크게 건드려 **원래 잘 돌던 것이 깨집니다.**
**대응** - ①한 번에 하나만 요청 ②「나머지는 그대로 두세요」를 붙임 ③고칠 때마다 직접 눌러 확인. 관련 있는 것끼리는 묶어도 되지만(문구 여러 개 수정 등), **성격이 다른 것을 섞으면 안 됩니다**(문구 수정 + 기능 추가).

**새 기능만 확인하면 회귀를 놓칩니다.** 이전 기능도 반드시 다시 눌러 확인해야 합니다.

### 세 번째 벽 - 조용한 실패

**가장 위험한 벽입니다.** 화면이 뜨고 버튼도 눌리고 성공 메시지까지 나오는데, 실제로는 아무 일도 일어나지 않거나 값이 틀렸습니다.

광고 실무 예 - 값이 비어 있는 항목이 0으로 계산되어 평균이 낮아짐, 금액 단위가 섞여 합계가 왜곡됨, 결측 행이 표에서 조용히 사라짐. 넷 다 오류 메시지가 없습니다.
**대응** - ①「없는 값은 0으로 바꾸지 말고 제외하라」를 명세에 적음 ②「몇 건을 계산에 썼는지 함께 표시하라」를 붙임 ③결과를 받으면 한 건은 손으로 검산.
저장이 됐는지는 화면에 남아 있다(아직 아님) → 새로고침 후에도 있다(1차 통과) → 다른 기기에서도 보인다(진짜 저장) 순으로 확인합니다. **PART05에서 이 3단계 검증을 실제로 합니다.**

## Step 08 :: 다섯 가지 지시 유형

좋은 지시문을 외우면 그 상황에서만 씁니다. **유형을 익히면 처음 보는 상황에서도 스스로 만듭니다.**






유형

언제 쓰는가

특징




① 뼈대 세우기

처음부터 만들 때

길고 구조화됨. 제약이 명시됨




② 다듬기

작동은 하는데 손보고 싶을 때

③ 진단하기

④ 옮기기

일상어를 구체적 조건으로

금지를 미리 선언


**① 뼈대 세우기** - 네 층으로 묶습니다.
```javascript
[ 역할 ] 너는 광고 실무에서 쓰는 도구를 만드는 개발자다.
[ 할 일 ] ○○를 보여주는 단일 HTML 파일을 만들어라.
[ 하면 안 되는 것 ] 외부에서 불러오는 것을 사용하지 않는다 / 요청하지 않은 기능을 추가하지 않는다
[ 출력 ] 입력 영역과 결과 영역을 가진 한 화면. 파일명: 04_결과물.html
```
**② 다듬기** - 짧고 범위가 좁고 「나머지는 그대로」가 반드시 붙습니다. 예: 「색상 부분만 바꿔줘. 좀 더 차분한 색으로.」
**③ 진단하기** - 해결책을 지시하지 말고 증상만 설명합니다. 「「어느 화면」에서 「무엇」을 하면 「무슨 일」이 일어납니다. 원래는 「무엇」이 되어야 합니다」. 오류 메시지는 요약하지 말고 통째로 복사해 붙여넣습니다.
**④ 옮기기** - 일상어를 구체적 조건으로. 「보기 편하게」→「열 폭을 내용에 맞추고, 숫자는 오른쪽 정렬, 행 간격을 넓게」.
**⑤ 막아두기** - 건드리면 안 되는 것을 먼저 선언. 오늘 계속 걸어둘 것: 외부 불러오기 금지 / 다른 부분 수정 금지 / 클라이언트 실명·계약 금액 금지.

**부정 지시만으로는 약합니다.** 「코끼리를 생각하지 마세요」라고 하면 오히려 코끼리가 떠오릅니다. 「이모지를 쓰지 마」보다 **「텍스트만 사용해」**처럼 대체안을 먼저 주고 금지는 확인 사살로 붙입니다.

실습에서 쓰는 순서: **뼈대 세우기 → 다듬기 → 진단하기 → 막아두기**

## 실습 :: 지금 한 번 써봅니다. (15분)
**어디서** Claude 앱 → 채팅 탭 · 아티팩트 (오후에 쓸 `Code` 탭이 아닙니다. 폴더도 파일도 필요 없습니다.)
### 1) 무엇을 만들지 30초 안에 고릅니다.
게임(테트리스·숫자 맞히기·가위바위보) · 가계부(지출 입력하고 합계 보기) · 여행 계획(갈 곳 목록) 중에서, 또는 떠오르는 것으로. 조건: 넣는 값이 세 개 이하 / 화면 하나로 끝남 / 설명 없이도 무엇인지 아는 것.
### 2) 뼈대 세우기 - 화면만
```javascript
[ 할 일 ] (고른 것)을 단일 html 파일로 만들어줘.
[ 화면 ] 입력하는 곳과 결과가 보이는 곳, 두 영역만.
[ 하면 안 되는 것 ] 요청하지 않은 기능을 추가하지 않는다 / 외부에서 불러오는 것을 쓰지 않는다
아직 기능은 넣지 마. 화면만 먼저 보고 싶어.
```
### 3) 다듬기 - 기능 하나만, 「나머지는 그대로」
예: 「숫자를 입력하면 정답인지 알려주는 기능을 넣어줘. 다른 부분은 그대로 두고.」 되면 다른 기능으로 한 번 더.

새 기능은 됐는데 아까 되던 것이 안 되면 그게 **회귀**입니다. 「방금 추가하기 전 상태로 되돌리고, 이번엔 ○○ 부분만 건드려줘」라고 하세요. 아티팩트는 버전이 남아 이전 버전으로 돌아갈 수 있습니다.

### 4) 진단하기 - 증상만 설명
❌「코드를 다시 짜줘」 / ✅「합계가 3만원이어야 하는데 30만원으로 나옵니다. 0이 하나 더 붙은 것 같습니다.」
### 5) 되짚어봅니다 - 무엇을 안 적었나
**여기가 이 실습의 목적입니다.** 만들면서 AI가 알아서 정한 것이 있습니다 - 넣는 값의 범위, 끝나는 조건, 결과 형태, 잘못된 값·빈 값 처리. 대부분 말한 적이 없는데 화면에는 다 들어가 있습니다.

지금은 혼자 쓰는 작은 화면이라 문제가 없지만, **오후에 만들 것은 업무에 쓸 도구입니다.** 거기서 AI가 알아서 정하면 조용한 실패가 그대로 일어납니다. 그래서 오후에는 먼저 명세를 적고 시작합니다(PART04).
