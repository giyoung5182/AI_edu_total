# 왜 시스템 프롬프트가 더 강하게 듣나
[원본 이미지 제외]
`원리 2`와 바로 이어집니다. 시스템 프롬프트는 **매 요청마다 작업 책상 맨 위에 다시 올라갑니다.** 대화가 길어져 앞의 말들이 밀려나도 이것만은 밀려나지 않습니다.
그래서 **"매번 말했는데 자꾸 안 지키네"** 싶은 조건일수록 시스템 프롬프트로 올려야 합니다. 사람이 부지런해서 해결되는 문제가 아니라, 구조가 그렇게 되어 있기 때문입니다.





매번 프롬프트로 처리할 때

시스템 프롬프트로 올렸을 때




새 대화마다 회사·부서·톤을 다시 설명

설명 없이 바로 본론부터 요청




대화가 길어지면 규칙이 흐려짐

끝까지 같은 규칙이 유지됨




사람마다 결과 품질이 제각각

누가 써도 같은 품질로 나옴




잘 나온 지시문을 메모장에서 찾아야 함

이름만 부르면 바로 실행




실수하면 그 문서만 잘못됨

실수하면 **모든 문서가 잘못됨**



마지막 줄이 중요합니다. 시스템 프롬프트는 **힘이 센 만큼 실수도 증폭됩니다.** 잘못된 규칙을 넣으면 그 Gem으로 만든 모든 문서가 같은 방향으로 틀립니다. 그래서 모듈 06에서 테스트를 따로 하는 것입니다.

`필요한 정보가 빠졌으면 추측하지 말고 반드시 먼저 질문합니다.`

# 실무자만 아는 요령 다섯 가지
써 본 사람과 안 써 본 사람이 갈리는 지점입니다.
### 1. 금지는 "하지 마라"보다 "대신 이렇게 해라"
"금액을 만들지 마세요"라고만 하면 AI가 그 자리를 어떻게 처리할지 몰라 문장을 어색하게 비틉니다. **대체 행동까지 주면** 깔끔해집니다.
```plain text
나쁨   알려주지 않은 금액은 쓰지 마세요.
좋음   알려주지 않은 금액은 쓰지 말고, 그 자리를 [금액]으로 비워 두세요.
```
### 2. 규칙은 다섯 줄을 넘기지 않습니다
길수록 좋아 보이지만 반대입니다. 규칙이 많아지면 **AI가 우선순위를 스스로 정하다가 중요한 것을 놓칩니다.** 그리고 책상 자리를 규칙이 다 차지해 정작 처리할 자료가 들어갈 공간이 줄어듭니다(`원리 2`).

**지킬 것만 남기는 법** — 규칙을 다 쓴 뒤 한 줄씩 지워 보세요. 지워도 결과가 그대로면 그 줄은 원래 없어도 되는 줄입니다.

### 3. 순서를 시키면 정확도가 올라갑니다
시스템 프롬프트의 진행 방식 칸에 **단계를 번호로** 적으면, AI가 바로 답하지 않고 순서를 밟습니다. 특히 1단계를 "확인"으로 두는 것이 핵심입니다.
```plain text
1단계  필요한 정보를 확인합니다. 빠진 것이 있으면 먼저 질문합니다.
2단계  초안을 작성합니다.
3단계  "수정할 부분이 있으신가요?"라고 묻습니다.
```
### 4. 예시 한 개가 설명 열 줄보다 강합니다
톤을 말로 설명하려 하면 끝이 없습니다. **잘 쓴 문서 하나를 통째로 넣는 편**이 훨씬 정확합니다. 모듈 05의 역설계가 이 원리를 극단까지 쓴 방법입니다.
### 5. Gem은 하나로 만들지 않습니다
용도가 다르면 나누세요. 하나에 다 넣으면 규칙이 서로 충돌해 품질이 떨어집니다.
```plain text
좋음   거래처 안내문 도우미 / 사내 보고 정리반 / 고객 회신 초안반
나쁨   내 업무 도우미 (모든 걸 다 하는 하나)
```

# 넣지 말아야 할 것

**시스템 프롬프트에 넣으면 안 되는 것**
고객 실명, 계좌·계약 번호, 내부 심사 기준, 미공개 금리표, 대외비 규정 원문
한 번 넣으면 그 Gem을 쓰는 **모든 대화에 계속 따라다닙니다.** 한 번의 실수가 영구적인 노출이 됩니다.
넣어도 되는 것은 **공개된 양식과 문체 수준**입니다.
