```plain text
9회차에 한 것
  Lovable 최종 점검 · 데이터 연동 점검
  → GitHub 계정 생성 + Lovable → GitHub 연동   (코드가 내 소유가 됨)
  → Cursor 설치 + Clone                        (코드를 내 컴퓨터로 가져옴)
  → npm install                                (부품 설치)
  → npm run dev                                (앱이 내 컴퓨터에서 켜짐 = localhost)

9회차에 못 한 것 = 오늘 오전에 할 것
  → Cursor로 각자 앱 수정
  → GitHub에 올리기 (Commit + Push)
  → Vercel 배포 (인터넷에 공개)
```
즉 코드는 이미 내 컴퓨터에 와 있고, **앱을 인터넷에 공개하는 마지막 구간만 남아 있는 상태**입니다.

## 1-1. 먼저 알아둘 것 — 지난주 그 주소는 사라져 있습니다
Cursor를 열고 지난주에 보던 `localhost:8080`에 접속하면 아마 이렇게 나올 것입니다.
```plain text
이 사이트에 연결할 수 없음
```
**고장이 아닙니다. 정상입니다.** 이유를 알면 앞으로 당황하지 않습니다.
### localhost의 정체
```plain text
localhost:8080 은 인터넷 주소가 아닙니다.

  localhost = 내 컴퓨터
  8080      = 내 컴퓨터 안의 8080번 창구

즉 "내 컴퓨터 안에서만 열리는 임시 주소"입니다.
```
이 주소는 `npm run dev`로 **서버가 켜져 있는 동안에만** 존재합니다. 지난주 수업이 끝나고 Cursor를 닫거나 컴퓨터를 껐다면, 그 순간 서버도 함께 꺼졌습니다. **주소가 사라진 것이 아니라, 주소를 열어주던 프로그램이 꺼진 것**입니다.
가게에 비유하면 문을 닫은 것과 같습니다. 가게(코드)는 그대로 있고 셔터만 내려간 상태입니다. 다시 올리면 됩니다.
### 내 코드는 사라졌나 — 아닙니다
```plain text
지난주에 Clone(내려받기)한 프로젝트 폴더는 그대로 남아 있습니다.

  위치  [로컬 경로]

npm install로 받은 부품(node_modules)도 그대로 있습니다.
→ 그래서 오늘은 npm install을 다시 하지 않습니다.
```
**오늘 다시 켜는 데 필요한 것은 명령어 딱 한 줄입니다.** 아래 순서대로 진행합니다.

**AI가 작업하는 동안 화면에서 일어나는 일 — 순서대로**

### 6-4. ★★ \[Keep\]으로 확정하기 — 가장 많이 빠뜨리는 단계
```plain text
AI 패널 위쪽에 이렇게 뜹니다:  > 1 File            [Undo]  [Keep]  [Review]    ↑ 고친 파일 수      ↑되돌리기 ↑확정  ↑자세히보기→ 가운데 [Keep]을 누르세요.
```
**Keep이 정확히 무슨 일을 하나요?**
```plain text
파일 저장    → 이미 끝났음 (AI가 고칠 때 바로 저장됨) Keep이 하는 일 → "이 변경을 검토 완료로 표시하고,                  되돌리기 대기 상태를 해제한다"
```
즉 Keep은 **저장 버튼이 아니라 "확인했습니다" 도장**에 가깝습니다.
**Keep을 누르면 화면이 이렇게 바뀝니다**
```plain text
· 코드 편집기의 초록·빨강 강조 표시가 사라집니다· 버튼에서 [Undo]와 [Keep]이 없어지고 [Review]만 남습니다  ★ 이게 정상 처리된 증거입니다
```
> ⚠️ **Keep을 안 누르면 어떻게 되나요?**<br>파일은 그대로 유지되고 화면도 바뀌어 있습니다. 그래서 **"됐다"고 생각하고 넘어가기 쉽습니다.** 하지만 내부적으로는 "검토 대기" 상태가 남습니다.
· 다음 요청을 하면 이전 변경과 새 변경이 섞여서 뭐가 뭔지 알 수 없게 됩니다<br>· 나중에 실수로 \[Undo\]를 누르면 **작업이 통째로 날아갑니다**
**다음 요청 전에 반드시 Keep으로 정리하는 습관**을 들이세요.

### 7-3. ★ Git 사용자 정보 설정 — 지금 안 하면 오후에 막힙니다
> 💡 **이게 뭔가요?**<br>Git에게 **"이 컴퓨터에서 코드를 수정하는 사람이 누구인지"** 알려주는 설정입니다.
> 💡 **왜 필요한가요?**<br>Git은 커밋(택배 상자에 송장 붙이기)을 만들 때 **"누가 · 언제 · 무엇을 바꿨는지"를 반드시 함께 기록**합니다. 송장에 보내는 사람 이름이 없으면 접수가 안 되는 것과 같습니다.
이름과 이메일이 등록되어 있지 않으면 **기록을 만들 수 없어서 커밋 자체가 거부됩니다.**
```plain text
Make sure you configure your "user.name" and "user.email" in git.(git에 사용자 이름과 이메일을 설정하세요)
```
**원인:** Git은 모든 기록에 **"누가 이 변경을 했는지"** 서명을 남깁니다. 그런데 이 컴퓨터에 이름/이메일이 등록된 적이 없어서 서명을 못 하는 겁니다. **커밋이 실패한 상태**입니다.
**왜 지금까지 안 났나:** Clone(가져오기)은 읽기만 하니 서명이 필요 없었습니다. **처음 커밋할 때 딱 한 번** 터집니다. 한 번 설정하면 그 컴퓨터에서는 다시 안 뜹니다.

**설정을 안 하면 오후에 만나게 될 오류**


```plain text
[Commit] 버튼을 누르는 순간:  Make sure you configure your "user.name" and "user.email" in git.

  (git에 user.name과 user.email을 설정했는지 확인하세요)→ 커밋이 안 되고 여기서 진도가 멈춥니다.→ 처음 Git을 쓰는 사람은 예외 없이 이 오류를 만납니다.
```
