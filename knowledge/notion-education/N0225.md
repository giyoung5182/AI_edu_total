# 부록 A. 바로 쓰는 프롬프트 모음

정리일: 2026-10-08 · 교육 에셋 N0225

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

대괄호 안만 바꿔서 그대로 복사해 쓰시면 됩니다.
교육 끝나고도 이 페이지만 따로 저장해두세요.


모든 프롬프트에 공통 적용 — 고객 실명, 계약번호, 실제 금액·금리는 입력하지 않습니다.
`A딜러사`, `B기계`, `[금액]`처럼 바꿔서 씁니다.

---
# 1 · 기본 양식 (RCTCK)
한 번짜리 요청을 제대로 할 때 씁니다.
```plain text
[역할]
당신은 [업무 영역] 담당자입니다. 다음을 잘합니다.
① [잘하는 것 1]
② [잘하는 것 2]
③ [잘하는 것 3]

[맥락]
- 받는 사람 : [누구에게]
- 상황     : [왜 이 글이 필요한지]
- 목적     : [상대가 읽고 무엇을 하길 바라는지]
- 분위기   : [공식적 / 사무적 / 편안하게]

[할 일]
1. [첫 번째 할 일]
2. [두 번째 할 일]
3. [세 번째 할 일]

[조건]
- 분량 : [본문 10줄 이내 등]
- 형식 : [항목 정리 / 표 / 본문만]
- 톤   : [거래처 발송 문체 / 사내 보고 문체]
- 알려주지 않은 날짜·금액·조항 번호는 만들지 마세요.
- 제가 채워야 할 자리는 [ ]로 비워 두세요.

[지식]
(참고할 지난 문서 붙여넣기 — 고객 실명·계약번호 삭제하고)
```
---
# 2 · 업무별 즉시 사용
### 거래처·딜러사 안내 메일
```plain text
[받는 사람]에게 [안내할 내용]을 알리는 안내 메일을 써 주세요.

- 본문 10줄 이내, 정중하되 사무적으로
- 필요 사항과 기한은 항목으로 정리
- 마지막에 문의처 한 줄
- 제목은 3개 제안해 주세요
- 알려주지 않은 날짜·금액은 [ ]로 비워 두세요
```
### 고객 문의 회신문
```plain text
아래 문의에 대한 회신문 초안을 써 주세요.

- 정중하고 차분하게, 고객이 불안하지 않게
- 절차는 순서대로 번호를 매겨 정리
- 고객이 준비해야 할 것은 따로 항목으로
- 어려운 용어는 괄호로 쉽게 풀어서
- 금리·수수료 등 수치는 절대 임의로 쓰지 말고 [ ]로 비워 두세요
- 조건을 단정적으로 약속하는 표현은 쓰지 마세요
---
(문의 내용 붙여넣기)
---
```
### 주간 업무 보고
```plain text
답을 쓰기 전에, 먼저 아래 메모를 완료 / 진행 중 / 지연으로
분류해 주세요. 그 다음 분류 결과로 보고문을 작성해 주세요.

1. 이번 주 완료 사항
2. 진행 중 사항과 현재 단계
3. 지연 사항과 사유
4. 다음 주 예정 사항

- 각 항목은 한 줄씩, 개조식(~함, ~예정)으로
- 메모에 없는 내용은 추가하지 마세요
- 수치가 불명확하면 [확인 필요]로 표시하세요
---
(이번 주 메모 붙여넣기)
---
```
### 회의록 정리
```plain text
아래 회의 메모를 정리해 주세요.

1. 결정된 사항
2. 논의만 하고 미결인 사항
3. 담당자별 후속 조치와 기한

- 확정되지 않은 것은 [미정]으로 표시하고 임의로 채우지 마세요
- 판단이나 평가는 덧붙이지 마세요
---
(메모 붙여넣기)
---
```
### 긴 자료 요약
```plain text
아래 자료를 읽고 핵심만 5줄로 요약해 주세요.

- 원문에 없는 내용은 절대 추가하지 마세요
- 숫자는 원문에 있는 것만 그대로 인용하세요
- 어려운 용어는 괄호로 쉽게 풀어 주세요
---
(자료 붙여넣기)
---
```
### 문서 검토
```plain text
아래 글을 검토해 주세요.

1. 빠진 정보가 있는지
2. 오해를 살 수 있는 표현이 있는지
3. 더 간결하게 쓸 수 있는 문장이 있는지

고쳐 쓰지 말고, 지적만 항목으로 정리해 주세요.
---
(글 붙여넣기)
---
```

# 3 · Gem 설정문 양식 (ROPE+K)
```plain text
[역할]
당신은 [업무] 담당자입니다. 다음을 잘합니다.
① [잘하는 것 1]  ② [잘하는 것 2]  ③ [잘하는 것 3]

[목적]
사용자가 [무엇]을 빠르고 일관되게 할 수 있도록 돕습니다.

[진행 방식]
1단계  필요한 정보를 확인합니다.
        빠진 것이 있으면 추측하지 말고 먼저 질문합니다.
2단계  [두 번째 단계]
3단계  [세 번째 단계]
4단계  "수정할 부분이 있으신가요?"라고 묻습니다.

[예시]
결과물은 항상 아래 순서를 따릅니다.
  [항목 1]  [항목 2]  [항목 3]

[지식·원칙]
- 알려주지 않은 날짜·금액·금리·조항 번호는 만들지 않으며,
  사용자가 채울 자리는 [ ]로 비웁니다.
- 조건을 단정적으로 약속하는 표현은 쓰지 않습니다.
- 과장된 표현과 불필요한 인사말은 넣지 않습니다.
```

# 4 · 역설계 프롬프트
내가 잘 쓴 문서로 Gem 설정문을 만들 때 씁니다.
```plain text
당신은 AI 설정문을 설계하는 전문가입니다.
아래는 제가 실제 업무에서 작성한 문서입니다.
앞으로 이와 같은 문서를 만들어줄 AI를 만들려고 합니다.

먼저 이 문서를 분석해 주세요.
1. 어떤 사람이 쓴 글인가 (역할과 강점)
2. 문서의 구조는 어떻게 되어 있는가
3. 문체와 톤의 특징은 무엇인가
4. 의도적으로 피한 것은 무엇인가

그 분석을 바탕으로 [역할] [목적] [진행 방식] [예시]
[지식·원칙] 다섯 항목의 설정문을 작성해 주세요.

반드시 포함해 주세요.
- 알려주지 않은 날짜·금액·조항 번호는 만들지 않고 [ ]로 비울 것
- 필요한 정보가 빠졌으면 추측하지 말고 먼저 질문할 것

바로 복사해 쓸 수 있게 한 덩어리로 정리해 주세요.
---
(내 문서 붙여넣기)
---
```

# 5 · 이미지와 발표자료
### 이미지
```plain text
[용도]에 넣을 이미지를 만들어 주세요.

- 대상 : [무엇을 그릴지]
- 분위기 : [차분한 / 밝은 / 신뢰감 있는]
- 형식 : [플랫 일러스트 / 사진 / 수채화]
- 색감 : [흰 배경에 파랑 계열 등]
- 구도 : [가로형 / 세로형, 여백 위치]
- 글자는 넣지 마세요.
```
### 발표자료 구성
```plain text
[주제]로 [시간]짜리 사내 발표를 준비합니다.
듣는 사람 : [팀장 / 부서원 / 타 부서]

답을 쓰기 전에, 먼저 이 발표가 끝났을 때 듣는 사람이
무엇을 알고 있어야 하는지 세 가지를 정리해 주세요.
그 다음 슬라이드 구성을 짜 주세요.

- 슬라이드 6장 이내
- 각 장마다 제목과 핵심 내용 3줄
- 제가 알려주지 않은 수치는 [ ]로 비워 두세요
```

# 6 · 결과물 고치기
마음에 안 들 때 처음부터 다시 쓰지 말고 이렇게 말하세요.
```plain text
더 짧게 줄여줘. 핵심만 남기고.
3번 항목만 다시 써줘. 나머지는 그대로 두고.
표 형식으로 정리해줘.
좀 더 사무적인 톤으로 바꿔줘.
확인이 필요한 내용만 따로 표시해줘.
이 내용으로 세 가지 버전을 만들어줘. 간결한 것 / 상세한 것 / 정중한 것.
```
