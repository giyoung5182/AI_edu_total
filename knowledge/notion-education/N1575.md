# Codex(Antigravity) 로 코딩하기

이제부터는 Codex(Antigravity)를 이용해서 실제로 프로그램을 만들어보겠습니다.
앞에서는 설치하고 실행하는 방법을 익혔다면,
이제는 Codex(Antigravity)에게 원하는 프로그램을 설명하고,
그 결과로 나온 코드를 실행하고 수정하는 흐름을 연습하게 됩니다.

중요한 점은, 우리가 처음부터 모든 코드를 직접 작성하는 것이 아니라
"무엇을 만들고 싶은지"를 Codex(Antigravity)에게 설명하고
그 결과를 확인하면서 조금씩 다듬어가는 방식으로 진행한다는 것입니다.
즉, 직접 코드를 한 줄씩 쓰는 방식보다
요구사항을 설명하고 → 코드를 받고 → 실행하고 → 수정하는 방식에 더 가깝습니다.
[원본 이미지 제외]

Codex(Antigravity)를 사용할 때의 기본 흐름은 아래와 같습니다.
1. 만들고 싶은 프로그램을 설명합니다
2. Codex(Antigravity)가 코드를 작성합니다
3. 생성된 코드를 실행합니다
4. 실행 결과를 보고 다시 수정 요청합니다
이 흐름에 익숙해지면
복잡한 프로그램도 한 번에 완성하려고 하기보다
작게 만들고, 실행해보고, 계속 개선하는 방식으로 개발할 수 있습니다.

# 중요: Codex(Antigravity) Skills 와 Codex(Antigravity) 로 코딩하기의 차이점
[원본 이미지 제외]

여기서 한 가지 중요한 개념을 구분하고 넘어가면 좋습니다.
이번 실습에서 하는 것은
Codex(Antigravity)를 이용해서 "하나의 프로그램(코드)"을 만드는 것입니다.
예를 들면
- 엑셀 파일 전처리 프로그램 만들기
- 파일 정리 자동화 코드 만들기
- 웹 자동 입력 코드 만들기
처럼 특정 작업을 해결하는 코드를 생성하고,
그 코드를 직접 실행하는 방식입니다.
---
반면, Codex(Antigravity)의 skill을 만든다는 것은
단순히 코드 파일 하나를 만드는 것이 아니라
- 어떤 방식으로 문제를 해결할지
- 어떤 절차로 작업을 수행할지
- 어떤 흐름으로 반복 실행할지
👉 "작업 방식 자체"를 정의하는 것에 가깝습니다.


---
### 💡 중요한 차이 (실무 관점)
### 1. 토큰 비용 관점
Codex(Antigravity)에게 매번 작업을 직접 시키는 경우
- 매 요청마다 전체 맥락을 다시 설명해야 하고
- 데이터나 조건을 계속 전달해야 합니다
👉 그만큼 토큰 사용량이 계속 증가합니다
반면, 한 번 코드를 만들어두면
- 이후에는 Codex(Antigravity)를 다시 호출하지 않고
- 로컬에서 코드만 실행하면 됩니다
👉 즉, 반복 작업일수록 비용이 훨씬 줄어듭니다
---
### 2. 보안 관점
Codex(Antigravity)에게 직접 작업을 맡기는 경우
- 데이터가 AI를 거쳐 처리됩니다
반면, 코드를 한 번 생성한 뒤에는
- 그 코드를 내 컴퓨터에서 직접 실행하게 됩니다
- 데이터가 외부로 전달되지 않습니다
👉 즉, 민감한 데이터일수록
코드로 만들어서 로컬에서 실행하는 것이 더 안전합니다
---
### 👉 정리
- 코딩하기
= 작업을 코드로 만들어두고 반복 실행 (비용 ↓, 보안 안전 ↑)
- skill 만들기
= Codex(Antigravity)가 일하는 방식 자체를 설계 (비용 ↑, 자율성 ↑)

### 📁 step1 : 실습데이터 구조 파악하기
먼저 원천 엑셀 파일들을 열어보고 구조를 확인합니다.
실무에서는 같은 데이터를 받더라도 파일마다 양식이 조금씩 다릅니다.
이번 실습 데이터에도 다음과 같은 문제가 들어 있습니다.
- 파일마다 컬럼명이 다름
- 실제 헤더가 1행이 아닌 곳에 있음
- 제목행, 메모행, 합계행, END 행이 섞여 있음
- 일부 값이 비어 있음
- 날짜 형식이 제각각임
- 금액에 `₩`, `,` 같은 문자가 섞여 있음
- 수량이 숫자가 아니라 `2개`, `3`처럼 텍스트로 들어 있음
- 상품코드가 비어 있거나 상품명이 다르게 적혀 있음
- 취소, 반품, 입금대기 데이터가 섞여 있음
- 같은 주문번호가 여러 파일에 중복으로 들어 있음
- 숨김 시트나 참고용 코드표가 들어 있음
즉, 바로 합치면 안 되는 데이터입니다.<br>

### Step2 : 전처리 규칙 정의하기
이 단계가 가장 중요합니다.
Codex(Antigravity)에게 정확하게 요청하려면
전처리 기준을 먼저 정해야 합니다.

## 1. 표준 컬럼 정의
최종 취합 파일은 아래 컬럼 구조로 만듭니다.
```plain text
원천파일, 주문번호, 주문일자, 지점, 채널, 고객식별값, 상품코드, 상품명, 수량, 단가, 상품금액, 할인금액, 배송비, 순매출, 주문상태
```
[원본 이미지 제외]
---
## 2. 컬럼명 통일
파일마다 다른 컬럼명을 하나의 표준 컬럼명으로 바꿉니다.
예시:
```plain text
주문번호 / Sale No / 거래ID / 주문ID / 승인번호 → 주문번호
주문일 / 판매일자 / 거래일 / 일자 / 승인일시 → 주문일자
지점 / 매장 / 파트너사 → 지점
채널 / 배송구분 / 원천 시스템 구분 → 채널
고객ID / 고객전화 / 구매자 → 고객식별값
상품코드 / SKU / 품목코드 / 바코드 → 상품코드
상품명 / 품목명 / 품명 / 제품명 / 상품 → 상품명
수량 / Qty / 판매수량 / 총수량 → 수량
단가 / Unit Price → 단가
공급가액 / 매출액 / 판매금액 / 카드매출+현금매출 → 상품금액 또는 순매출
할인금액 / Discount Amount / 할인쿠폰 → 할인금액
배송비 / 배송료 → 배송비
결제상태 / 주문상태 / 처리결과 / 취소여부 → 주문상태
```
---
## 3. 날짜 형식 통일
모든 날짜는 `YYYYMMDD` 형식으로 변환합니다.
예시:
```plain text
2026-01-03 → 20260103
01/03/2026 → 20260103
2026.01.03 → 20260103
2026년 1월 3일 → 20260103
```
날짜가 비어 있거나 변환할 수 없는 경우에는 `예외로그` 시트에 기록합니다.
---
## 4. 금액 데이터 정리
금액 컬럼은 숫자로 변환합니다.
다음 문자는 제거하고 숫자로 처리합니다.
```plain text
₩
,
공백
```
예시:
```plain text
₩18,500 → 18500
18,500 → 18500
무료 → 0
- → 0
빈 값 → 0
```
---
## 5. 수량 데이터 정리
수량은 숫자로 변환합니다.
예시:
```plain text
2개 → 2
 3  → 3
-1 → -1
```
반품 데이터는 수량이 음수로 들어올 수 있습니다.
---
## 6. 결측치 처리
비어 있는 값은 컬럼 성격에 따라 처리합니다.
```plain text
문자 컬럼 → "미입력"
금액 컬럼 → 0
수량 컬럼 → 0
날짜 컬럼 → 변환 실패로 기록
상품코드 → 상품명으로 마스터 매핑 시도
```
상품코드가 비어 있는 경우 `06_상품마스터_불완전.xlsx`의 `상품명_별칭` 시트를 이용해 매핑합니다.
---
## 7. 상품명 및 상품코드 정규화
원천 파일의 상품명은 표기가 다를 수 있습니다.
예시:
```plain text
원두_아메리카노 1KG
AM 원두 1kg
아메리카노 원두 1kg
```
위 값들은 모두 같은 상품으로 처리해야 합니다.
상품명 매핑 기준은 `06_상품마스터_불완전.xlsx` 파일을 사용합니다.
상품코드나 상품명을 매핑할 수 없는 경우에는 삭제하지 말고 `예외로그` 시트에 기록합니다.
---
## 8. 주문상태 표준화
파일마다 주문상태 표현이 다릅니다.
아래 기준으로 통일합니다.
```plain text
정상 / Paid / N → 정상
취소 / VOID / Y → 취소
반품 / Return → 반품
입금대기 / Pending / 보류 → 입금대기
```
매출 집계 시에는 기본적으로 `정상` 상태만 포함합니다.
단, 취소/반품/입금대기 행은 삭제하지 않고 취합 파일에는 남깁니다.
---
## 9. 중복 데이터 처리
같은 `주문번호`가 여러 번 나타나면 중복으로 판단합니다.
처리 기준:
```plain text
1. 완전히 같은 주문이면 1건만 유지
2. 서로 다른 파일에 같은 주문번호가 있으면 예외로그에 "중복주문번호" 기록
3. 어떤 행을 유지할지 애매하면 삭제하지 말고 예외로그에 남김
```

## Step3: 바이브코딩하기
이제 Codex 또는 Antigravity에게 프로그램 작성을 요청합니다.
요청할 때는 다음 내용을 반드시 포함합니다.
- 어떤 파일을 읽을지
- 어떤 전처리 규칙을 적용할지
- 어떤 컬럼 구조로 만들지
- 결과 파일을 어디에 저장할지
- 예외 데이터를 어떻게 남길지
---
## Codex 요청 예시
```plain text
처음에 사용자가 파일탐색기에서 엑셀 파일들을 여러 개 선택하고,
저장 경로를 선택한 후 작업 버튼을 누르면 전처리된 엑셀이 저장되게 하는
Python 프로그램을 작성해줘.

합치려는 엑셀 예시는 현재 폴더의 "현장형_취합실습_데이터" 폴더에 있어.

대상 파일은 아래 5개야.
- 01_서울본사_온라인몰_주문내역_2026-01.xlsx
- 02_부산지점_POS매출_2026-01.xlsx
- 03_대구_파트너정산_2026_Q1.xlsx
- 04_광주지점_월마감자료.xlsx
- 05_제주_팝업스토어_카드매출.xlsx

상품명과 상품코드 매핑은 아래 파일을 참고해줘.
- 06_상품마스터_불완전.xlsx

전처리 규칙은 아래와 같아.

1. 최종 컬럼은 아래 순서로 통일
원천파일, 주문번호, 주문일자, 지점, 채널, 고객식별값,
상품코드, 상품명, 수량, 단가, 상품금액,
할인금액, 배송비, 순매출, 주문상태

2. 파일별로 헤더 위치가 다르므로 실제 헤더 행을 찾아서 읽기
- 서울본사 파일은 4행이 헤더
- 부산 POS 파일은 2행이 헤더
- 대구 정산 파일은 5행이 헤더이고 B열부터 데이터 시작
- 광주 월마감 파일은 4행이 헤더이고 END 행 이후는 제외
- 제주 카드매출 파일은 5행이 헤더이고 중간 공백/메모행 제외

3. 날짜 형식 통일
모든 날짜는 YYYYMMDD 형식으로 변환
예: 2026-01-01, 01/01/2026, 2026.01.01, 2026년 1월 1일 모두 20260101로 변환

4. 금액 정리
₩, 쉼표, 공백을 제거하고 숫자로 변환
"무료", "-", 빈 값은 0으로 처리

5. 수량 정리
"2개", " 3 " 같은 값은 숫자로 변환
변환 불가능하면 0으로 처리하고 예외로그에 기록

6. 상품코드 정규화
상품코드가 없으면 상품명_별칭 시트로 매핑
상품명 표기가 달라도 표준상품명과 표준상품코드로 통일
매핑 실패 시 예외로그에 "상품매핑실패" 기록

7. 주문상태 통일
정상, Paid, N은 정상
취소, VOID, Y는 취소
반품, Return은 반품
입금대기, Pending, 보류는 입금대기

8. 중복 주문번호 확인
중복 주문번호가 있으면 예외로그에 "중복주문번호" 기록
완전히 동일한 중복 행은 1개만 유지

9. 결과 파일 생성
처음에 지정한 저장 경로에 저장
파일명은 output_data_YYYYMMDD_HHMM.xlsx 형식으로 저장
예: output_data_20260416_1659.xlsx

10. 결과 엑셀에는 시트를 3개 만들어줘
- 취합_RAW: 원천에서 읽은 데이터를 최대한 보존한 데이터
- 취합_CLEAN: 전처리 완료된 표준 데이터
- 예외로그: 변환 실패, 상품매핑실패, 중복주문번호 등 확인이 필요한 데이터
```

## Step4: 프로그램 실행 후 결과 확인하기
프로그램 실행 후 저장된 엑셀 파일을 열어 확인합니다.
확인할 내용:
- `취합_RAW` 시트가 생성되었는가
- `취합_CLEAN` 시트가 생성되었는가
- `예외로그` 시트가 생성되었는가
- 날짜가 모두 `YYYYMMDD` 형식인가
- 금액 컬럼이 숫자인가
- 수량 컬럼이 숫자인가
- 상품코드가 표준화되었는가
- 중복 주문번호가 표시되었는가
- 취소/반품/입금대기 데이터가 삭제되지 않고 남아 있는가

## 이 프로그램을 다른 사람도 쓰게 하려면?
여기서 중요한 포인트가 하나 있습니다.
이번 실습에서는 Codex(Antigravity)를 이용해
Python 으로 엑셀 전처리 및 취합 코드를 만들었습니다.
그런데 한 번 코드가 완성되면,
같은 규칙으로 처리하는 작업은 매번 AI에게 다시 요청할 필요가 없습니다.
예를 들어,
- 컬럼명 통일
- 결측치 처리
- 날짜 형식 통일
- 여러 파일 취합
같은 규칙이 정해져 있다면
이후에는 이미 만들어진 코드를 그대로 실행하면 됩니다.
즉, 처음 한 번은 AI의 도움을 받아 만들고,
그 이후에는 AI 없이도 반복 실행할 수 있습니다.

[원본 이미지 제외]


이 방식의 장점은 분명합니다.
### 1. 반복 작업 시 비용이 줄어듭니다
매번 Codex(Antigravity)에게 같은 작업을 다시 요청하면
그때마다 설명과 데이터 맥락이 필요하고,
그만큼 토큰도 계속 사용됩니다.
하지만 한 번 코드를 만들어두면
이후에는 AI를 다시 부르지 않고
코드만 실행하면 되므로 반복 비용이 크게 줄어듭니다.
### 2. 내부망이나 오프라인 환경에서도 사용할 수 있습니다
코드가 이미 완성되어 있다면
인터넷이 없는 환경이나 내부망 환경에서도 실행할 수 있습니다.
즉,
- AI 접속 없이
- 외부 전송 없이
- 로컬 환경에서
정해진 규칙대로 데이터를 처리할 수 있습니다.
### 3. 보안 측면에서도 더 유리합니다
민감한 데이터를 매번 AI에 전달하는 대신,
처음 만든 코드를 내부 컴퓨터에서 직접 실행하면
데이터가 외부로 나가지 않습니다.
그래서 반복적으로 처리해야 하는 업무일수록
"AI로 코드 생성 → 내부에서 반복 실행" 방식이 더 안전하고 효율적입니다.

