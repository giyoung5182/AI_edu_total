## 1. 스킬은 폴더입니다
"스킬은 그냥 .md 파일 아닌가요?" — 가장 흔한 오해입니다.
스킬은 **폴더**입니다.<br>마크다운 하나가 아니라, 그 안에 스크립트, 예제 코드, 데이터 파일, 템플릿을 전부 담을 수 있는 구조입니다.
Claude에게 "이 폴더 안에 이런 파일들이 있어"라고 알려주면, 필요한 시점에 알아서 꺼내 읽습니다.

**스킬 폴더 구조**

```plain text
my-skill/
  SKILL.md           <- 핵심 지침
  references/api.md  <- 상세 API 문서
  assets/template.md <- 출력 템플릿
  examples/          <- 예제 코드
  scripts/fetch.py   <- 자동화 스크립트
```
Anthropic이 "가장 흥미로운 스킬들"이라고 꼽은 것들의 공통점은 설정 옵션과 폴더 구조를 창의적으로 활용하고 있었다는 겁니다.

## 2. 스킬의 유형
Anthropic이 사내 스킬을 전수 조사했더니 9개 카테고리로 나뉘었습니다.<br>잘 만든 스킬은 하나에 딱 속하고, 애매한 스킬은 여러 개에 걸쳐 있었다고 합니다.

"엔지니어 한 명이 일주일을 투자해서 검증 스킬 하나를 만드는 것도 충분히 가치가 있다." — Anthropic

### 라이브러리/API 레퍼런스
사내 빌링 라이브러리처럼, 메서드 호출 순서를 잘못하면 에러가 나는 함정이 있는데 Claude는 이걸 모릅니다.<br>이런 엣지 케이스와 "이렇게 하면 안 돼" 목록을 스킬에 담는 겁니다.

`billing-lib` — 사내 빌링 라이브러리의 엣지 케이스, 함정 모음<br>`frontend-design` — Claude가 디자인 시스템을 쓸 때 틀리는 부분 교정

### 제품 검증
Playwright나 tmux 같은 도구와 짝을 이뤄서, Claude가 직접 테스트를 돌리고 결과를 검증하게 만듭니다.

`signup-flow-driver` — 회원가입 → 이메일 인증 → 온보딩을 헤드리스 브라우저에서 실행, 각 단계마다 상태 검증

### 데이터 패칭/분석
접속 정보, 대시보드 ID, 분석 워크플로우를 스킬에 담아두면<br>Claude가 매번 "그 테이블 이름이 뭐였죠?"라고 물을 필요가 없습니다.

`funnel-query` — "가입 → 결제 퍼널을 보려면 어떤 테이블을 조인해야 하는지" + 캐노니컬 user_id 테이블

### 팀 자동화
티켓 트래커 + GitHub + Slack을 긁어서 스탠드업을 만들어주는데,<br>이전 기록을 로그로 남겨두면 "어제 대비 뭐가 바뀌었는지"만 delta로 보여줍니다.

`standup-post` — 티켓 + GitHub + Slack 집계 → 포맷된 스탠드업 (변경분만 표시)

### 코드 스캐폴딩
"새 API 엔드포인트 만들어줘"라고 하면,<br>인증, 로깅, 배포 구성이 미리 연결된 상태로 파일 구조를 잡아줍니다.

`create-app` — 인증, 로깅, 배포 설정이 미리 연결된 새 내부 앱 스캐폴딩

## 3. 잘 만드는 팁
### 당연한 걸 적지 마세요
Claude는 코딩을 이미 잘 압니다. 일반 상식을 적으면 토큰만 낭비됩니다.<br>Claude가 틀리는 것만 적어야 합니다.

**frontend-design 스킬<br>**~~"좋은 디자인 원칙을 따르세요"~~ ← 쓸모없습니다<br>"Inter 폰트 쓰지 마", "보라색 그라데이션 쓰지 마" ← Claude가 구체적으로 틀리는 습관을 잡아줍니다

### Gotchas 섹션
"Claude가 이 스킬을 쓸 때 자주 빠지는 함정" 목록입니다.<br>완벽하게 만들어서 배포하는 게 아니라, 실패할 때마다 한 줄 추가하는 게 성장 방식입니다.

**Gotchas 섹션 예시<br>**• 비례 배분 계산 시 반올림이 아니라 **내림**을 써야 한다<br>• create_invoice() 호출 전에 반드시 validate_line_items()를 먼저 호출할 것<br>• 테스트 환경에서는 USD만 지원됨, 다른 통화로 테스트하면 silent fail

### 점진적 공개를 활용하세요
SKILL.md에는 핵심 지침만 넣고, 상세 API는 references/에, 템플릿은 assets/에 분리합니다.<br>마크다운 하나에 전부 넣으면 매번 전체를 읽어야 해서 토큰이 낭비됩니다.
### Claude를 너무 가두지 마세요

"반드시 A를 호출하고, 그 다음 B를 호출하고, 결과를 C 형식으로 저장하라"


"이런 함수들이 있고, 각각의 용도는 이렇다. 상황에 맞게 조합해서 써라"

### 스크립트를 넣으세요
데이터 분석 스킬에 데이터 페칭 함수 라이브러리를 넣어두면, Claude는 매번 코드를 처음부터 쓰는 대신 이 함수들을 조합해서 분석에 집중할 수 있습니다.

"화요일에 무슨 일이 있었어?"라고 물으면<br>Claude가 미리 준비된 함수를 조합해서 스크립트를 즉석으로 짜고 실행합니다.<br>보일러플레이트에 턴을 쓰지 않으니까 토큰이 줄어듭니다.

## 4. Gotchas 성장 패턴
사내 빌링 라이브러리 스킬을 예로 들면:

**1일차<br>**"내부 빌링 라이브러리 사용법. API 문서 참조." — 이게 끝.


**2주차<br>**내부 빌링 라이브러리 사용법. API 문서 참조<br>**<br>\*\***Gotchas**\*\*<br>**Claude가 비례 배분 계산에서 반올림을 했는데 실제로는 내림. `→ Gotchas에 한 줄 추가.`

Claude가 실수할 때마다 한 줄씩 늘어납니다.<br>Anthropic은 "스킬 본문보다 Gotchas 한 줄이 실수를 더 잘 막는다"고 합니다.

"대부분의 스킬은 몇 줄과 Gotcha 하나로 시작했다.<br>사람들이 계속 추가하면서 좋아진 거다."<br>— Thariq
