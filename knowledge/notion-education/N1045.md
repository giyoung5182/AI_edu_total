# 활동 2 — 검증 에이전트 만들기 (result-verifier)

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
같은 폴더에 읽기 도구만 가진 검증 에이전트를 추가해, 작업자와 검증자를 분리함.
## 진행 단계
1. **요청문 입력** — Claude Code에 아래를 입력.
- 입력할 내용:
```javascript
같은 폴더에 result-verifier 라는 서브에이전트를 하나 더 만들어줘.

역할
- 03_결과와 04_기록의 산출물을 CLAUDE.md 기준으로 점검한다
- 완료 판정 4개 항목이 실제로 충족됐는지 확인한다
- 금지 사항을 어긴 흔적이 있는지 찾는다

점검할 것
- 통합 표의 행 수가 원본 합계와 맞는가
- 컬럼이 기준표와 일치하는가
- 빈칸이 0이나 평균으로 채워진 흔적이 있는가
- 변경 내역에 없는 값 변경이 있는가
- 01_원본과 02_기준의 파일이 수정되지 않았는가

중요
- 이 에이전트는 아무것도 고치지 않는다. 읽기 도구만 준다.
- 문제를 발견하면 어느 파일 어느 항목인지 지목해서 보고한다
- 문제가 없으면 없다고 명확히 말한다. 억지로 찾지 않는다
```
2. **tools 확인** — 생성된 파일의 tools 줄이 Read, Grep, Glob이고 Write와 Edit이 없는지 확인.
- 정상 결과: 수정 도구가 없어 고칠 수 없는 result-verifier.md가 생성됨.
## 막히는 지점
- 검증 역할을 주면 AI가 뭐라도 지적하려 해 없는 문제를 만들어 냄 — "억지로 찾지 않는다", "추측으로 지적하지 않는다"를 본문에 넣음.
