지난 시간에는 Claude Code를 실행하고, 폴더 안 파일을 읽게 해봤습니다. 거기까지는 "내 파일을 읽는다"는 점만 빼면 챗봇과 크게 다르지 않았습니다. 이번 시간에 진짜 차이가 드러납니다.
이번에 만들 것은 Subagent입니다. **메인 에이전트가 모든 일을 직접 하지 않고, 특정 업무를 전담하는 부하 직원(Subagent)에게 일을 맡기는 구조**입니다. 오늘은 사고 접수 건들을 보상 검토하는 Subagent를 직접 만들어, 폴더에 쌓인 사고 10건을 한 번에 검토하게 만들어 보겠습니다.
## **이번에 만들 Subagent**
보상 검토 Subagent가 할 일은 이렇습니다.
```plain text
data 폴더에 사고 접수 건 10개가 쌓여 있습니다.
"이 사고 건들을 보상 검토해줘" 하면
→ Subagent가 10개 파일을 모두 읽고
→ 운전자보험 약관의 보상 기준(보장 항목, 면책 등)과 대조해서
→ 건별로 [보상가능 / 추가확인 / 면책 / 심사보류] 판정과 사유를 표로 만들어 줍니다.
```
지난 시간 챗봇은 "이 사고 건 하나 요약해줘"에 답했습니다. 이번 Subagent는 10건을 한꺼번에 조사하고, 정해진 기준으로 판단해서, 보상 검토 결과 문서를 만들어 냅니다. 사람이 직접 하면 10건을 하나하나 열어 약관과 대조하며 판정해야 하는 일입니다.

### 2. Claude에게 짧게 브리핑합니다
입력창에 아래 정도만 붙여넣고 엔터를 누릅니다. 스펙을 처음부터 다 적지 않아도 됩니다. 판정 4종의 대략 기준과 역할, 출력 형태, 모델만 알려주면, 나머지(호출 조건, 표 구성 등)는 Claude가 초안으로 채워 줍니다.
```plain text
data 폴더의 사고 접수 건을 보상 검토하는 서브에이전트를 .claude/agents/ 폴더에 만들어줘.
사고 건을 운전자보험 약관의 보상 기준과 대조해서, 건별로 아래 4개 중 하나로 판정하고
사유와 함께 표로 정리하는 역할이야.

- 보상가능: 보장 항목에 해당하며 보상 가능
- 추가확인: 서류 미비나 금액 미확정 등으로 추가 정보가 필요할 때
- 면책: 음주, 무면허 등 보상하지 않는 손해에 해당할 때
- 심사보류: 사고 경위 불명확 등으로 조사 후 판단이 필요할 때

'보상 검토', '사고 건 검토', '보상 심사', '사고 접수 검토' 요청이 오면
반드시 이 에이전트가 쓰이도록 description을 써줘.
에이전트 이름(name)은 영어 소문자와 하이픈으로 지어줘.
도구는 모두 허용해줘. 모델은 Sonnet으로 해줘.
```

### 3. Claude가 초안을 만듭니다
Claude가 브리핑을 정리해서 서브에이전트 정의 파일을 `.claude/agents/` 폴더에 만들어 줍니다. 파일을 만들거나 쓰는 작업 진행 여부를 물어보면, 허용(1번 또는 엔터)을 선택합니다.
- C**laude가 에이전트 이름(예: ****`claim-compensation-assessor`****), 호출 조건(description), 사용할 도구(tools), 모델(model), 판정 표, 시스템 프롬프트(본문)를 알아서 채워 저장**합니다.
- 중간에 이름이나 도구 범위를 되물으면 편하게 답하면 됩니다. 잘 모르겠으면 "네가 적당히 정해줘"라고 해도 됩니다.
>

### 6. 새로 만든 에이전트는 Claude Code를 재시작해야 잡힙니다
**우리는 처음 Agent를 만들었기 때문에 현재 대화에선 ****`.claude`**** 폴더가 인식 안 될 가능성이 높습니다.**
이 상태에서 바로 실행하면 "Agent type ... not found"처럼 에이전트를 못 찾는다는 메시지가 뜰 수 있습니다.
한 번만 재시작하면 됩니다.** 입력창에서 ****`/exit`****로 Claude Code를 끄고(또는 Ctrl+C를 두 번), 같은 폴더에서 다시 ****`claude`****를 실행**하세요. 재시작하면 새 에이전트가 목록에 등록됩니다.

## Step 3. 메인에 연결하고 실행하기 (라우팅)
이제 만든 Subagent에게 실제로 일을 시켜 봅니다. 여기서 "라우팅"이라는 개념이 함께 나옵니다.
### 라우팅이란
우리가 어떤 요청을 하면, 메인 Claude가 그 일을 어느 담당자에게 넘길지 정합니다.
요청을 맞는 에이전트에게 이어 주는 이 과정을 **라우팅**이라고 합니다. 조직에 비유하면, 팀장이 들어온 일을 보고 담당자를 정해 배정하는 것과 같습니다.
[원본 이미지 제외]
라우팅에는 두 가지 방식이 있습니다.
- 이름을 불러 배정: 우리가 담당자를 직접 지정합니다. "보상검토 에이전트한테 맡겨줘"처럼 부르면 그 담당자로 확실히 넘어갑니다.
- 자동 배정: 이름을 안 부르면, 메인 Claude가 요청과 각 에이전트의 description을 보고 스스로 넘길지 정합니다. 편하지만, 넘길지 말지는 Claude의 판단이라 항상 걸린다고 보장하기 어렵습니다.
### 실행: 담당자를 이름으로 불러 맡깁니다
터미널 입력창에 아래를 입력하고 엔터를 누릅니다. 담당자에게 일을 맡기듯, 방금 만든 에이전트 이름을 불러 배정합니다.
```markdown
보상검토 에이전트한테 data 폴더의 사고 건들을 보상 검토 맡겨줘.
운전자보험 약관의 보상 기준을 기준으로, 건별로 판정과 사유를 표로 정리해줘.
```
이름을 부르면 Claude가 그 담당자(보상검토)에게 배정해 실행하고, 폴더 안 사고 건들을 하나씩 읽으며 검토하기 시작합니다.
Step 2에서 description에 적어 둔 호출 조건("보상 검토, 사고 건 검토, 보상 심사 요청이 오면...")이, 이 에이전트가 보상 검토 담당이라는 것을 Claude가 알게 해 줍니다.
>
[원본 이미지 제외]
### 주의: 이름을 빼면 메인이 직접 해버릴 수 있습니다
이 부분이 실습에서 가장 많이 헷갈리는 지점입니다.
**이름을 빼고 "data 폴더의 청약 건들을 1차 심사해줘"라고만 하면, 메인 Claude가 "이 정도는 내가 하면 되겠다"고 판단해 에이전트를 부르지 않고 직접 처리해 버리는 경우**가 있습니다.
이때 화면에는 에이전트 이름 없이, 메인이 폴더를 읽고 10건을 읽고 PDF를 확인하는 흐름만 보입니다.
이건 고장이 아니라 **자동 라우팅의 원래 성질**입니다. 결과 표 자체는 나오지만, 우리가 만든 에이전트가 도는 모습은 보이지 않습니다. 그래서 데모에서는 위처럼 반드시 이름을 불러 배정하세요.
이름을 불렀는데도 메인이 직접 해버린다면 두 가지를 확인합니다.
- 첫째, 요청에 에이전트를 가리키는 말("보상검토")을 넣었는지.
- 둘째, `.claude/agents/claim-review.md`의 description에 "보상 검토, 사고 건 검토, 보상 심사" 같은 호출 문구가 들어 있는지. 이 문구가 약하면 이름을 불러도 잘 안 걸립니다.
### 그래도 메인이 하면 되는데 왜 에이전트를 쓰나
결과가 달라서가 아닙니다. 메인도 심사는 합니다. 에이전트로 넘기는 이유는 두 가지입니다.
첫째, 에이전트는 자기만의 공간에서 10건을 처리하고 깔끔한 결과 표만 돌려줍니다. 파일 더미가 메인 대화를 어지럽히지 않습니다.
둘째, 판정 기준과 페르소나, 출력 형식이 에이전트에 박혀 있어, 매번 다시 브리핑하지 않고 한마디로 같은 기준을 적용합니다. 이 이점은 이름을 불러 배정해도 그대로 남습니다.
> **팁 (자동 배정):** description을 강하게 써 두면, 이름을 부르지 않고 "보상 검토해줘"라고만 해도 이 에이전트로 넘어가는 경우가 많습니다. 다만 자동은 판단이라 보장은 아니니, 확실히 보여줘야 하는 데모에서는 이름을 부르세요.
> **팁 (반드시 고정하고 싶다면):** 특정 에이전트로 무조건 돌려야 하는 상황이라면, 입력창에서 `@`를 눌러 에이전트를 태그하면 그 작업은 해당 에이전트 실행이 보장됩니다. 슬랙에서 담당자를 태그하는 것과 같습니다.

## ※참고 서브에이전트 자가 복제 오류 사전 대응 방법
[원본 이미지 제외]

**요약 가이드**
최근 클로드 코드(Claude Code)의 시스템 업데이트로 인해, 서브에이전트가 복잡한 분석을 하다가 막히면 스스로를 똑같이 카피(자가 복제)해서 무한으로 호출하는 현상(재귀 호출)이 발생할 수 있습니다. 이 경우 시간과 비용(토큰)이 낭비되므로, 아래 설정을 통해 에이전트의 다른 에이전트 호출 권한을 확실하게 잠가주어야 합니다.

### 1️⃣ 현상 및 원인
- **어떤 현상이 일어나나요?**
- 대시보드 생성이나 대량 파일 분석 명령을 내렸을 때, 화면에 `Waiting for background agents` 메시지가 뜨며 특정 에이전트(예: 면책 사유 점검, 리스크 점검 등)가 일을 끝내지 않고 뱅글뱅글 도는 현상이 발생합니다.
- **왜 이런 일이 생기나요?**
- 기존에는 에이전트가 다른 에이전트를 부르는 기능이 제한되어 있었으나, 최신 업데이트로 제한이 해제되었습니다. 이로 인해 서브에이전트가 판단하기 모호한 상황을 마주하면, 자기 자신을 또 하나의 서브에이전트로 중첩 호출(재귀 호출)하여 일을 떠넘기는 구조적 버그가 발생하게 된 것입니다.
### 2️⃣ 해결 방법: `disallowedTools` 옵션으로 락(Lock) 걸기
에이전트를 생성할 때 설정 창(YAML 영역)에 "너는 다른 에이전트를 소환하는 도구를 절대 쓸 수 없다"는 강력한 제한 규칙을 한 줄 추가해 주면 해결됩니다.
#### 📌 \[방법 A\] 처음 에이전트를 만들 때 (프롬프트 추가)
에이전트 생성 프롬프트 맨 마지막에 아래 문구를 함께 적어줍니다.
Plaintext
```plain text
"추가로, 이 에이전트가 스스로를 무한 호출하거나 다른 에이전트에게 업무를 토스하지 못하도록 설정(disallowedTools)에 'Agent'를 반드시 추가해줘."
```
#### 📌 \[방법 B\] 이미 만든 에이전트 파일을 수정할 때 (YAML 직접 수정)
1. 실습 폴더 내의 `.claude/agents/` 폴더로 이동합니다.
2. 문제가 발생하는 에이전트 파일(예: `claim-review.md`)을 메모장이나 에디터로 엽니다.
3. 파일 맨 위 `--` 와 `--` 사이(YAML 설정 영역)에 **`disallowedTools: [Agent]`** 문구를 삽입하고 저장합니다.
- **수정 전 예시:**
YAML
```plain text
---
name: insurance-risk-screener
description: 청약 건들 중 위험 신호가 있는 건을 가려내는 에이전트
model: sonnet
---
```
- **🟢 수정 후 예시 (참고)**
YAML
```plain text
---
name: insurance-risk-screener
description: 청약 건들 중 위험 신호가 있는 건을 가려내는 에이전트
model: sonnet
disallowedTools: [Agent]
---
```
> **⚠️ 주의:** `disallowedTools: [Agent]`에서 **Agent의 'A'는 반드시 대문자**로 적어주어야 시스템이 정확하게 인식합니다.
### 3️⃣ 반드시 기억할 마무리: 세션 새로고침
에이전트 설정을 말로 수정했거나 파일을 직접 고쳤다면, 클로드 코드가 바뀐 규칙(자물쇠)을 새로고침하여 인식할 수 있도록 **반드시 프로그램을 재시작**해야 합니다.
1. 대화창에 `/exit`를 입력하거나 `Ctrl + C`를 두 번 눌러 클로드 코드를 완전히 종료합니다.
2. 터미널 창에 다시 `claude`를 입력하여 실행하면, 이제 비서가 딴짓을 하지 않고 한 방에서 자기 혼자 깔끔하게 업무를 완수합니다.

### 검증 체크포인트 3가지
>
