# 1️⃣ AI 입력 = 외부 전송이라는 관점
## 왜 필요한가요?
바이브 코딩에서는 업무 문제를 설명하고, 예시 데이터를 넣고, 결과 화면을 빠르게 확인합니다.
이때 가장 많이 생기는 실수가 `실제 회사 데이터`를 그대로 AI나 생성형 AI에 붙여넣는 것입니다.
AI 입력창은 개인 메모장이 아닙니다. 입력하는 순간 데이터는 외부 서비스로 전송될 수 있다고 보고 다뤄야 합니다.
> TIP: 오늘의 기준은 간단합니다. `이 내용을 외부 사람에게 메일로 보내도 되는가?`라고 물었을 때 망설여진다면 AI에도 그대로 넣지 않습니다.
## 사례
2023년 국내 대기업에서도 생성형 AI 사용 과정에서 소스코드, 회의 내용, 업무 데이터가 외부 AI 서비스에 입력된 사례가 알려졌습니다.
문제는 한번 입력된 내용은 회수하기 어렵다는 점입니다.

❓ AI에 붙여넣기 전, 이 데이터가 우리 회사·고객·임직원을 특정하게 만들 수 있나요?

---

# 2️⃣ 절대 넣으면 안 되는 데이터
## 입력 금지 데이터
아래 데이터는 AI, ChatGPT, Claude 같은 외부 AI 도구에 그대로 넣지 않습니다.
1. 개인정보: 임직원 이름, 연락처, 이메일, 사번, 주민등록번호, 고객 개인정보
2. 고객·거래처 정보: 고객사명, 계약 조건, 담당자명, 거래 내역
3. 재무·영업 정보: 매출, 원가, 계약 금액, 견적, 수익률, 투자 정보
4. 내부 전략 문서: 회의록, 사업 계획, 조직 개편, M&A, 평가 자료
5. 소스코드와 시스템 정보: 내부 코드, API 키, DB 구조, 계정 정보
6. 프로젝트 정보: 실제 프로젝트명, 내부 코드명, 출시 전 서비스명
7. 연구·생산 정보: 특허, 실험 결과, 제조 조건, 품질 데이터
## 바이브 코딩 실습에서 특히 조심할 부분
PRD를 작성할 때 실제 프로젝트명, 고객사명, 내부 코드명을 그대로 쓰기 쉽습니다.
하지만 AI가 앱을 만들기 위해 꼭 알아야 하는 것은 `실제 이름`이 아니라 `데이터의 구조`와 `처리 규칙`입니다.
나쁜 예
```plain text
한솔OO 고객사의 실제 납품 일정과 담당자별 이슈를 넣으면 위험도를 계산하는 앱을 만들어줘.
```
좋은 예
```plain text
고객사 A, 고객사 B처럼 익명화된 더미 데이터를 사용해 납품 일정과 이슈 위험도를 계산하는 앱을 만들어줘.
실제 고객명, 담당자명, 계약 정보 입력을 유도하지 않도록 안내 문구를 넣어줘.
```
> TIP: AI에게 필요한 것은 `누구의 데이터인지`가 아니라 `어떤 형식의 데이터인지`입니다.

# 3️⃣ 바이브 코딩 실습에서 안전하게 데이터 쓰는 법
## 방법 1️⃣ 헤더만 넣기
엑셀이나 표 전체를 붙여넣지 않고, 열 이름과 데이터 타입만 설명합니다.
```plain text
내 데이터에는 아래 열이 있어.
- 부서명
- 업무명
- 마감일
- 진행 상태
- 이슈 여부

이 구조를 기준으로 마감 임박 업무를 표시하는 HTML 단일 파일 도구를 만들어줘.
실제 업무 데이터는 넣지 않고 더미 데이터 버튼으로 테스트할 수 있게 해줘.
```
## 방법 2️⃣ 더미 데이터를 AI에게 만들게 하기
실제 데이터를 숨기고, 형식만 알려준 뒤 AI가 테스트 데이터를 생성하게 합니다.
```plain text
아래 구조에 맞는 더미 데이터 10행을 만들어줘.
실제 회사명, 임직원명, 고객명은 쓰지 말고 모두 가상의 값으로 작성해줘.

열 구조:
- 부서: 구매, 영업, 생산, 재무 중 하나
- 업무명: 짧은 업무 제목
- 마감일: 2026-05-01 ~ 2026-05-31 사이 날짜
- 상태: 예정, 진행중, 완료, 지연 중 하나
- 이슈: 한 문장 설명
```
## 방법 3️⃣ 고유명사를 바꾸기
업무 구조를 유지하되 식별 가능한 이름을 바꿉니다.
1. 실제 고객사명 → 고객사 A, 고객사 B
2. 실제 임직원명 → 담당자 1, 담당자 2
3. 실제 프로젝트명 → 프로젝트 A, 프로젝트 B
4. 실제 내부 코드명 → 코드명 A, 코드명 B
5. 실제 이메일·전화번호 → 삭제
## 방법 4️⃣ ID만 남기고 원본은 내 PC에 보관하기
AI에는 `ID`와 분석에 필요한 비식별 값만 넣습니다.
원본 매칭표는 내 PC나 사내 승인된 저장소에만 둡니다.
```plain text
AI에 넣는 버전
ID | 업무유형 | 마감일 | 상태 | 이슈수
1  | 보고    | 2026-05-12 | 진행중 | 2
2  | 승인    | 2026-05-15 | 지연   | 1

내가 보관하는 원본
ID 1 = 실제 프로젝트명 / 실제 담당자 / 실제 고객사
ID 2 = 실제 프로젝트명 / 실제 담당자 / 실제 고객사
```
> TIP: `AI는 모르지만 나는 알 수 있게` 만드는 것이 핵심입니다.

# 4️⃣ AI에 붙여넣기 전 5초 체크리스트
## 붙여넣기 전 확인 질문
AI에 내용을 넣기 전 아래 질문을 빠르게 확인합니다.
1. 사람 이름이 들어 있나요?
2. 고객사명이나 거래처명이 들어 있나요?
3. 실제 프로젝트명이나 내부 코드명이 들어 있나요?
4. 이메일, 전화번호, 사번 같은 개인정보가 들어 있나요?
5. 계약 금액, 매출, 원가, 평가 정보가 특정 대상과 연결되어 있나요?
6. 회의록이나 전략 문서처럼 외부에 나가면 안 되는 내용인가요?
하나라도 `예`라면 그대로 넣지 않고, 삭제·익명화·더미 데이터로 바꿉니다.
## 안전한 변환 예시
```plain text
Before
김OO 부장이 한솔OO 고객사 재계약 건을 5월 20일까지 검토해야 함. 계약금액은 실제 금액 기준으로 계산.

After
담당자 1이 고객사 A 관련 업무를 5월 20일까지 검토해야 함. 금액은 더미 값 기준으로 계산.
```
## 최종 정리
1. AI에 넣는 것은 실제 데이터가 아니라 `구조`, `규칙`, `더미 예시`입니다.
2. PRD에는 데이터 보안 조건을 기본 항목으로 넣습니다.
3. 단일 HTML 앱에는 더미 데이터 자동 입력 버튼과 결과 복사 버튼을 넣습니다.
4. 제출 전에는 화면 문구와 예시 데이터까지 보안 기준을 확인합니다.
> TIP: `쓰지 마라`가 아니라 `안전하게 바꿔서 쓰자`가 오늘의 핵심입니다.
