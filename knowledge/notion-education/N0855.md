## Claude로 GAS 코드 만들기 (50분)

### Claude에게 코드 요청하는 방법
2권에서는 완성된 코드를 받아서 설치했습니다.<br>3권에서는 처음부터 직접 요청하는 방법을 배웁니다.
---
### 좋은 코드 요청 vs 나쁜 코드 요청
**나쁜 요청 (자주 하는 실수):**
```plain text
"GAS로 지출결의서 자동화해줘"
→ 어떤 파일인지, 어떤 셀인지, 어디에 저장하는지 모름
→ Claude가 추측으로 코드를 짜고
→ 실제 파일과 맞지 않아서 오류 발생
```
**좋은 요청 (4가지를 반드시 포함):**
```plain text
① 파일 구조 (시트 이름과 역할)
② 셀 위치 (어느 셀에서 무엇을 읽는지)
③ 동작 순서 (버튼 클릭 시 무슨 일이 일어나야 하는지)
④ 완료 후 메시지 (사용자에게 뭐라고 알려줄지)
```
**요청 템플릿:**
```plain text
Google Apps Script 코드를 만들어줘.

[파일 구조]
구글 스프레드시트에 아래 시트들이 있어:
- '___' 시트: [이 시트의 역할 설명]
- '___' 시트: [이 시트의 역할 설명]

[셀 위치]
- ___셀: [이 셀에 뭐가 있는지]
- ___셀: [이 셀에 뭐가 있는지]
내역 데이터: ___행 ~ ___행
각 행의 열 구성: A=내용, B=거래처, C=금액 (예시)

[동작 순서]
버튼 클릭 시:
1. [___셀]에서 [무엇]을 읽어서
2. [조건] 확인
3. [어떤 시트]에 [어떤 순서]로 저장
4. 완료 후 "[메시지]" 팝업

[메뉴]
스프레드시트 열릴 때 '[메뉴명]' 메뉴 생성:
- [버튼명] → [함수명]
- [버튼명] → [함수명]

[주의사항]
- [특이한 조건이 있으면 명시]
- [예외 처리 필요한 경우 명시]
```

### 강사 시연 — 지출결의서 자동화 (10분)
수강생은 따라 하지 않고 흐름만 확인합니다.
**시연 포인트:**
```plain text
① 지출결의서 폼에 매장명·내역·금액 입력
② [📋 지출결의서] → [☑ 제출] 클릭
③ 확인 팝업 → [예]
④ 제출이력 시트 열기 → 데이터 자동 저장 확인
⑤ [📊 월별집계 갱신] → 월별지출집계 시트 자동 생성 확인
```
**핵심:**
```plain text
코드가 하는 일은 딱 하나입니다. 제가 방금 집계 파일 열고 → 탭 찾고 → 셀 찾고 → 숫자 입력하던 것을 버튼 하나로 대신 해준 것입니다. 이게 자동화입니다.
```

### 왜 이렇게 프롬프트를 작성해야 하는가 — 항목별 원리 분석
단순히 "이렇게 쓰면 됩니다"가 아닙니다. 각 항목이 왜 필요한지, 없으면 어떤 일이 생기는지를 이해하면 어떤 업무에도 적용할 수 있습니다.
---
**\[내 업무 상황\] — Claude가 맥락을 이해하게 하는 섹션**
```plain text
나쁜 예:
"비즈머니 알림 코드 만들어줘"

좋은 예:
"매일 수동으로 확인하고 있는데 소진 후에야 알게 돼서
 광고가 중단되는 문제가 반복돼"
```
**왜 필요한가:**<br>Claude는 코드를 짤 때 "왜 이 기능이 필요한가"를 알수록 더 정확한 설계를 합니다.<br>예를 들어 "소진 후에야 알게 된다"는 맥락이 있어야 "기준보다 이하일 때 미리 알림"이라는 로직이 나옵니다.<br>맥락 없이 "알림 만들어줘"만 하면 언제, 어떤 조건으로 알릴지 Claude가 추측으로 채웁니다.
---
**\[파일 구조\] — Claude가 실제 파일을 알 수 있는 유일한 방법**
```plain text
나쁜 예:
"비즈머니 잔액 시트가 있어"

좋은 예:
"- '비즈머니_잔액' 시트: 잔액 현황이 있는 시트
   C4셀: 누적 충전액 (숫자)
   F4셀: 현재까지 소진액 (숫자)"
```
**왜 필요한가:**<br>Claude는 내 파일을 볼 수 없습니다. 내가 설명하는 것이 전부입니다.<br>시트 이름이 '비즈머니_잔액'인지, 잔액이 어느 셀에 있는지, 숫자인지 텍스트인지 알아야 정확한 코드가 나옵니다.<br>특히 **시트 이름은 탭 이름과 한 글자도 다르면 안 됩니다.** 코드가 `getSheetByName('비즈머니잔액')`으로 나왔는데 실제 탭이 '비즈머니_잔액'이면 오류가 납니다.
---
**\[동작 순서\] — 코드의 설계도**
```plain text
나쁜 예:
"잔액이 적으면 이메일 보내줘"

좋은 예:
"1. C4 - F4 으로 현재 잔액 계산
 2. 잔액이 500,000원 이하이면 이메일 발송
 3. 잔액이 500,000원 초과이면 아무것도 하지 않음"
```
**왜 필요한가:**<br>"이메일 보내줘"만 하면 Claude가 조건·내용·발송 시점을 전부 추측으로 채웁니다.<br>번호를 매겨서 순서대로 쓰면 Claude가 이 순서 그대로 함수를 작성합니다.<br>특히 **"초과이면 아무것도 안 함"을 명시**하는 것이 중요합니다.<br>쓰지 않으면 조건이 충족되지 않아도 뭔가를 하는 코드가 나올 수 있습니다.
---
**이메일 본문 내용 명시 — 받는 사람 관점으로 설계**
```plain text
나쁜 예:
"이메일 본문에 잔액 정보 넣어줘"

좋은 예:
"본문: 현재 잔액 / 일 평균 소진 / 광고 중단 예상일 포함"
```
**왜 필요한가:**<br>결제팀이 이메일을 받았을 때 즉시 판단할 수 있는 정보가 있어야 합니다.<br>"잔액이 부족합니다" 한 줄짜리 이메일은 받는 사람이 다시 확인해야 합니다.<br>"현재 잔액 500,000원 / 일 평균 소진 336,832원 / 중단 예상일 6월 21일"이면 즉시 판단 가능합니다.<br>**이메일을 받는 사람 입장에서 필요한 정보를 역으로 설계하는 것이 핵심입니다.**
---
**\[트리거\] — 자동화의 완성**
```plain text
나쁜 예:
(트리거 언급 없음)

좋은 예:
"매일 오전 9시에 자동 실행되게 트리거 설정 방법도 알려줘"
```
**왜 필요한가:**<br>트리거 없이는 버튼을 직접 눌러야 합니다. 그러면 자동화가 아닙니다.<br>"매일 오전 9시"로 지정하면 Claude가 트리거 설정 방법을 코드와 함께 안내해줍니다.<br>시간을 9시로 잡은 이유: 업무 시작 전에 알아야 오전 중 충전 요청이 가능하기 때문입니다.
---
**\[메뉴\] — 사람이 쓰는 인터페이스 설계**
```plain text
나쁜 예:
(메뉴 언급 없음)

좋은 예:
"'📊 광고 관리' 메뉴:
 - '비즈머니 잔액 확인' → check비즈머니잔액
```
