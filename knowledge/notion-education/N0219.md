```plain text
R — Role         역할     어떤 담당자처럼 답할지
C — Context      맥락     상황, 받는 사람, 목적
T — Task         할 일    무엇을 만들지, 몇 단계로
C — Constraints  조건     분량, 형식, 금지사항
K — Knowledge    지식     참고할 자료, 예시
```

## K — 붙여준 것만 근거가 됩니다
지난번에 잘 쓴 메일, 사내 양식, 담아야 할 정보 목록을 함께 붙입니다. 잘 쓴 지난 문서 하나만 넣어도 톤이 우리 회사 문서처럼 바뀜니다.

붙여넣기 전에 **고객 실명과 계약번호는 지우고** 넣으세요.

# 완성 예시
### 예시 1 — 딜러사 서류 제출 안내 메일
```plain text
[R] 당신은 캐피탈사 영업지원 담당자입니다. 다음을 잘합니다.
    ① 필요한 정보만 남기고 군더더기를 걷어냅니다.
    ② 상대가 무엇을 언제까지 해야 하는지 명확히 드러냅니다.
    ③ 거래처에 보내기 적절한 사무적이고 정중한 문체를 씁니다.

[C] 받는 사람 : A딜러사 담당자, 오래 거래한 곳입니다
    상황     : 리스 실행에 필요한 서류 일부가 아직 접수되지 않았습니다
    목적     : 미비 서류를 기한 내 제출하도록 안내하는 것
    분위기   : 재촉으로 느껴지지 않게, 사무적으로

[T] 1. 위 상황에 맞는 안내 메일 초안을 작성해 주세요.
    2. 제목을 3개 제안하고, 각각 어떤 인상을 주는지 한 줄로 설명해 주세요.
    3. 필요한 서류와 제출 기한은 본문 안에 항목으로 정리해 주세요.
    4. 마지막 문단에 문의처 안내 한 줄을 넣어 주세요.

[C] - 본문은 10줄 이내로 합니다.
    - 과장된 표현과 불필요한 인사말은 넣지 않습니다.
    - 제가 알려주지 않은 날짜·금액·조항 번호는 만들지 마세요.
    - 제가 채워야 할 자리는 [ ]로 비워 두세요.

[K] 아래는 지난달 발송한 안내 메일입니다. 이 톤과 형식을 참고해 주세요.
    (지난 메일 본문 붙여넣기 — 고객 실명과 계약번호는 삭제하고)
```
### 예시 2 — 주간 업무 보고 정리
```plain text
[R] 당신은 팀 주간 보고를 정리하는 실무자입니다.
    사실만 간결하게 쓰고, 추측이나 평가를 덧붙이지 않습니다.

[C] 받는 사람 : 팀장
    상황     : 한 주 동안 처리한 업무 메모를 보고 형식으로 정리해야 합니다
    목적     : 진행 상황과 다음 주 예정을 한눈에 보이게 하는 것

[T] 답을 쓰기 전에, 먼저 아래 메모를 완료 / 진행 중 / 지연 세 가지로
    분류해 주세요. 그 다음 분류 결과를 바탕으로 보고문을 작성해 주세요.
    1. 이번 주 완료 사항
    2. 진행 중 사항과 현재 단계
    3. 지연 사항과 사유
    4. 다음 주 예정 사항

[C] - 각 항목은 한 줄씩, 개조식(~함, ~예정)으로 씁니다.
    - 메모에 없는 내용은 추가하지 마세요.
    - 수치가 불명확하면 임의로 쓰지 말고 [확인 필요]로 표시하세요.

[K] (이번 주 업무 메모 붙여넣기)
```

**한 줄 기법 — 생각의 순서를 시키기**
예시 2의 "답을 쓰기 전에 먼저 분류해 주세요"가 핵심입니다. 바로 답하게 하지 않고 **정리 → 작성 순서를 밟게** 하면 누락이 줄어듭니다. 이것을 **CoT(생각의 사슬)**라고 하며, 복잡한 요청일수록 효과가 큽니다.

### 5단계. 지어내는지 직접 확인해봅니다
알려준 적 없는 정보를 물어보세요.
```plain text

```

**여기서 무엇을 보나** — 대괄호로 비워두면 조건이 제대로 작동한 것이고, 그럴듯한 날짜와 번호를 만들어냈다면 그게 할루시네이션입니다. 실제 업무에서 이 차이가 사고를 가릅니다.
