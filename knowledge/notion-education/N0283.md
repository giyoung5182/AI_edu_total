```plain text

```

### 크롤링 확장프로그램은 어떤가요
페이지 목록을 표로 긁어오는 확장프로그램도 많습니다. 다만 레퍼런스 수집 목적이라면 **대부분의 경우 위 두 가지로 충분**하고, 크롤링 도구는 성격이 다릅니다.

**긁어오기 전에 확인할 것**
**사이트 이용약관을 봅니다.** 자동 수집을 금지한 사이트가 많습니다. 로그인해야 보이는 화면은 특히 그렇습니다.
**모은 자료는 참고용입니다.** 레퍼런스는 구조와 방향을 보기 위한 것이고, **문구나 이미지를 그대로 가져다 쓰면 저작권 문제**가 됩니다. 「이 사이트처럼 만들어줘」가 아니라 **「이 구성 순서를 참고해서 우리 내용으로」**가 맞는 요청입니다.
**사내 반입 기준은 그대로 적용됩니다.** 외부에서 모은 자료라도 어디에 올리느냐는 별개 문제입니다.


- **레퍼런스에서 설계도로 - 실제 순서**
```plain text
1  참고할 페이지를 탭으로 열어둡니다
   3~5개가 적당합니다. 너무 많으면 공통점이 흐려집니다

2  구성을 먼저 뽑습니다
   "각 페이지가 무엇을 어떤 순서로 보여주는지 표로 정리해줘"
   → 이게 [2 장별 설계도]의 재료가 됩니다

3  그다음 색과 크기를 뽑습니다
   "가장 마음에 드는 쪽의 색상 코드와 글자 크기 비율을 정리해줘"
   → 이게 [3 디자인 규격]에 그대로 들어갑니다

4  우리 것으로 바꿉니다
   "이 구성 순서를 참고하되, 내용은 아래 자료로 바꿔줘"
   → 여기서부터는 레퍼런스가 아니라 우리 자료입니다

5  설계도에 옮겨 적습니다
   대화 안에 두면 사라집니다. 설계도 파일에 적어야 남습니다
```

**레퍼런스를 모으는 목적은 베끼기가 아니라 「말로 바꾸기」입니다.**
머릿속의 「이런 느낌」이 색상 코드와 구성 순서로 바뀌는 순간, 그건 AI에게 넘길 수 있는 지시가 됩니다. **설계도를 못 쓰는 이유는 대개 안목이 없어서가 아니라, 안목을 문장으로 옮겨본 적이 없어서입니다.**

## 심화 A · 보고서 논리 구조 — 결론 선행과 피라미드 〔원칙①〕
**왜 구조가 먼저인가**
- 구조를 사람이 먼저 정해 두면 결론과 근거의 **위아래 관계**로 논리 점검 가능
**피라미드 구조 — 세 층**
```plain text
               [결론 1문장]  ← 독자가 결정할 것
                    │
    ┌───────────────┼───────────────┐
[근거 묶음 1]    [근거 묶음 2]    [근거 묶음 3]   ← 결론을 받치는 이유 2~4개
    │               │               │
[사실 E#·E#]    [사실 E#·E#]    [사실 E#·E#]    ← 근거표의 사실
```

판별 질문




1. 위는 아래의 요약

결론은 근거 묶음을 합친 말, 근거 묶음은 그 아래 사실을 합친 말

아래 칸을 모두 읽은 사람이 위 칸 문장에 동의할 수밖에 없는가




2. 같은 층은 같은 종류

근거 묶음끼리는 같은 기준으로 나눔(예: 규정 조항별 / 자료 영역별)

묶음 이름을 나란히 놓았을 때 기준이 하나인가




3. 빠짐·겹침 점검

같은 사실이 두 묶음에 들어가지 않고, 결론에 필요한 영역이 빠지지 않음

한 사실을 두 번 세지 않았는가 / 결정에 필요한 영역이 비어 있지 않은가




4. 지우기 시험

근거 묶음 하나를 지웠을 때 결론이 약해져야 함

지워도 결론이 그대로면, 그 묶음은 이 보고서에 필요 없는 내용

### B-1. 평균·중앙값 — n과 포함·제외 기준





❌

"정산팀 정산작업 시간이 가장 김"

값·n·단위

"정산팀 정산작업_시간 평균 ○○(n=○, 부서 표기 통일 후, 단위 미정의 \[확인 필요\])"

극단값 포함 여부

"예약운영팀 평균 ○○(n=○, 극단값 포함) / 극단값 1건 제외 시 ○○(n=○) / 중앙값 ○○"




"전체 평균 ○○(n=58)" — 빈칸이 있는 지표에도 58 사용

지표별 유효 n

"회의_시간 평균 ○○(n=○, 빈칸 행 제외)" — 빈칸이 있는 지표는 n이 58보다 작아짐


- 평균만 쓰면 되는 경우: 값이 고르게 모여 있고 극단값이 없음
- 평균과 중앙값을 **같이** 써야 하는 경우: 평균과 중앙값 차이가 큼 → 소수의 큰 값이 평균을 끌어올렸을 가능성
- n이 작을 때: 숫자를 지우지 않음. 해석 층에 "n이 작아 부서 전체 경향으로 일반화 주의" 추가
- 부서 순위를 말할 때: 순위 기준(평균/중앙값/극단값 제외 평균)을 문장에 포함. 기준이 바뀌면 순위가 바뀔 수 있음
### B-2. 비율 — 분자/분모와 분모 정의





❌

빠진 것

⭕ 예




"AI 사용 경험자는 소수임"

분자·분모

"AI사용경험 '있음' 20/58명(34.5%, 업무시간실태조사 58행 기준)"




"영수증 미첨부 비율 ○%"

분모가 무엇인지

"개인카드 후정산 87행 중 영수증 미첨부 ○행(○/87)" 또는 "출장정산 321행 중 ○행(○/321)" — 분모가 다르면 다른 문장




"위반 의심이 ○% 증가"

비교 기준·분모

"○월 ○/○행 → ○월 ○/○행(같은 판정 명세 기준)"


- 같은 분자라도 분모에 따라 의미가 달라짐
- 분모 321(출장정산 전체 행) → "전체 정산 중 얼마나"
- 분모 87(결제방법 '개인카드 후정산' 행) → "영수증 제출 대상 중 얼마나"
- 결제방법 분포: 법인카드 234행 · 개인카드 후정산 87행(합계 321행)
- 비율 표기 규칙
- 분모가 작으면 %보다 **분수 그대로**(예: ○/5). %로 바꾸면 규모가 커 보임
- % 옆에 분수 병기 — "34.5%(20/58)"
- 반올림 자리 통일(소수 첫째 자리 등)을 보고서 첫머리나 조사 개요에 한 번 명시
- 증가·감소는 **%p(퍼센트포인트)** 와 **%** 구분 — 비율 30%→40%는 "10%p 증가", "33% 증가"와 다른 말
