앞에서는 프로그램을 만들 때<br>프론트엔드와 백엔드로 나눠서 생각할 수 있다고 했습니다.<br><br>그럼 여기서 한 가지 생각해볼 수 있습니다.<br><br>이 작업을 AI 하나가 처음부터 끝까지 순서대로 하면 어떨까요?<br>그리고 역할을 나눠서 동시에 진행하면 어떨까요?<br><br>이번 페이지에서는 이 차이를 보겠습니다.

```plain text
3. 마지막으로 둘을 연결하고 실행합니다.
```

## 역할을 나누면 더 빠르게 진행할 수 있습니다
그럼 이렇게 생각해볼 수 있습니다.

그런데 역할을 나누면<br>각자 자기 일을 진행하고,<br>마지막에 합치면 됩니다.
Claude도 비슷하게 작업을 나눠서 진행할 수 있습니다.
이때 사용하는 방식이 Sub Agent입니다.

## Sub Agent란?
Sub Agent는<br>메인 Claude가 모든 일을 혼자 처리하지 않고,<br>일부 작업을 따로 맡기는 방식입니다.
예를 들어 웹앱을 만든다고 하면<br>이렇게 나눌 수 있습니다.
### 역할 분리 예시
```plain text
Main Agent
→ 전체 요청을 이해하고 작업을 나눕니다.

Frontend Sub Agent
→ 화면, 버튼, 표, 차트 같은 프론트엔드 작업을 맡습니다.

Backend Sub Agent
→ API, 데이터 처리, 서버 실행 같은 백엔드 작업을 맡습니다.
```

쉽게 말하면<br>Claude 혼자 모든 걸 붙잡고 있는 게 아니라,<br>작업 일부를 담당자에게 나눠 맡기는 방식입니다.

---
## 앞에서 만든 프로그램 구조에 적용해보겠습니다
우리가 앞에서 봤던 구조를 다시 떠올려보겠습니다.
```plain text
frontend/
backend/
run.bat
```
이렇게 나눠진 프로젝트라면<br>작업도 나눠서 생각하기 좋습니다.
### Sub Agent 적용 구조
```plain text
Frontend Sub Agent
- React + Vite 화면 구현
- 업로드 버튼
- 표와 차트
- UI 배치

Backend Sub Agent
- FastAPI 서버 구현
- API 구조 설계
- 데이터 처리 로직
- 실행 환경 정리

Main Agent
- 전체 구조 확인
- 두 작업 결과 통합
- 실행 방법 정리
```
여기서 중요한 건<br>Sub Agent를 쓴다고 해서<br>우리가 갑자기 어려운 개발을 하는 게 아니라는 점입니다.
그냥 작업을 역할별로 나눠서<br>더 정리된 방식으로 맡긴다고 보면 됩니다.
---
## 프롬프트는 이렇게 바꿔볼 수 있습니다
앞에서 프로그램 개발 요청을 이렇게 했다고 해보겠습니다.
### 기존 요청
```plain text
프론트엔드는 frontend/ 폴더에 React + Vite로 작성해주고,
백엔드는 backend/ 폴더에 FastAPI를 사용해서 만들어줘.

작업이 완료되면 두 서버를 동시에 실행하는 run.bat 파일을 만들어줘.
```
여기에 한 줄을 추가해볼 수 있습니다.
### Sub Agent 적용 요청
```plain text
프론트엔드는 frontend/ 폴더에 React + Vite로 작성해주고,
백엔드는 backend/ 폴더에 FastAPI를 사용해서 만들어줘.

작업이 완료되면 두 서버를 동시에 실행하는 run.bat 파일을 만들어줘.

Sub Agent를 활용해서
frontend 작업과 backend 작업을 나누어 진행해줘.
```
이렇게 요청하면<br>Claude가 작업을 더 나눠서 생각할 수 있습니다.

## Sub Agent를 쓸 때 확인할 점
Sub Agent를 쓰면 편하지만<br>무조건 좋아지는 건 아닙니다.
작업을 나누려면<br>나눌 기준이 있어야 합니다.
### 확인할 것
```plain text
1. 작업을 역할별로 나눌 수 있는가?
2. 각 역할의 결과물이 분명한가?
3. 마지막에 합쳐야 할 기준이 있는가?
4. 서로 충돌할 수 있는 파일은 없는가?
5. 실행 방법을 마지막에 정리하게 했는가?
```

Sub Agent는 마법처럼 알아서 완성도를 높여주는 기능이라기보다,<br>작업을 나누기 좋은 상황에서 더 효과적인 방식입니다.
