## 1-4. 작업 폴더 만들기
커넥터로 드라이브를 읽더라도, **결과물을 저장할 폴더**는 있어야 합니다.
바탕화면이 아닌 곳에 폴더를 만듭니다. 사용자 폴더 아래에 `교육기관_정리` 라는 이름으로 만드세요. 그 안에 `자료` 하위 폴더를 하나 더 만듭니다.

**바탕화면과 문서 폴더는 피하세요.** OneDrive 동기화 때문에 문제가 생길 수 있습니다. 9회차와 같은 이유입니다.

### 자료 모으기 — 폴더째 ZIP으로 받기
커넥터로 드라이브를 훑어봤으니, 이제 **깊게 읽힐 자료를 폴더로 가져옵니다.**

**왜 둘 다 하나**
커넥터는 드라이브를 훑어보며 **무엇이 있는지**를 파악하는 데 좋습니다. 반면 문서를 만들려면 **내용까지 깊게** 읽어야 하고, 그럴 때는 폴더에 있는 편이 빠르고 안정적입니다.

**파일을 하나씩 받지 마세요.** 구글 드라이브는 폴더를 통째로 받으면 자동으로 압축해줍니다.
**받는 순서**
1. 구글 드라이브에서 교육기관 심화교육 폴더를 엽니다
2. **내 이름으로 된 폴더를 오른쪽 클릭**합니다
3. **다운로드**를 선택합니다
4. 잠시 기다리면 압축 파일이 받아집니다
5. 받은 파일을 오른쪽 클릭 → **압축 풀기**
6. 풀린 내용을 `교육기관_정리` 안의 `자료` 폴더로 옮깁니다

**폴더가 크면 시간이 걸립니다.** 내 폴더만 받으세요. 전체 교육 폴더를 받으면 다른 분 자료까지 따라옵니다.

**이외에 내 노트북에만 있는 것도 넣습니다**
- 복습 워크시트 (오늘 오전에 채운 것)
- 에이전트 파일 (`.claude/agents` 폴더)
- 앱 화면 캡처 (있으면)

**넣지 말아야 할 것** — 개인정보가 든 파일(연락처, 주민번호, 급여)와 계정 비밀번호가 적힐 파일. 꼭 필요하면 해당 부분을 지우고 넣으세요.

- 앱 고도화 워크시트 (11회차)

# 2부. 하네스 만들기 (15분)
## 2-1. 하네스가 무엇인가
**하네스(harness)는 원래 말에 채우는 마구를 뜻합니다.** 힘센 말이 아무 데나 가지 않고 목적지까지 달리게 잡아주는 장치입니다.
AI도 같습니다. 능력은 있는데 규칙이 없으면 제멋대로 갑니다.
**AI가 일할 환경과 규칙을 만들어주는 것**을 하네스 엔지니어링이라고 부릅니다.

# 월간 클레임 보고서 만드는 절차

## 1. 자료 확인
- data 폴더에서 해당 월 CSV를 찾는다
- 매장명, 클레임유형, 접수건수, 처리완료건수 열이 있는지 확인한다

## 2. 집계
- 총 접수 건수와 총 처리완료 건수를 계산한다
- 매장별로 접수 건수를 합산한다
- 처리율은 처리완료를 접수로 나눈 값이다

## 3. 보고서 작성
- 아래 여섯 항목을 반드시 포함한다
  총 접수 / 처리율 / 매장별 건수 / 전월 대비 / 최다 매장 / 데이터 출처

데모의 모든 구조에는 이유가 있습니다. **내 업무로 바꿀 때 같은 이유로 설계하시면 됩니다.**
**왜 만드기·검사하기·고치기를 파일로 나눠놓았나**
한 파일에 다 넣으면 "검사 기준만 바꾸고 싶은데" 할 때 전체를 건드려야 합니다. 나눠놓으면 **고칠 곳만 고칠 수 있고, 어디서 틀렸는지도 바로 보입니다.**
**왜 초안이 일부러 불완전한가**
교육용이기 때문입니다. 1회차에 전부 통과하면 루프가 도는 것을 볼 수 없습니다. 실무에서는 일부러 만들지 않아도 자연스럽게 실패가 나옵니다.
**왜 실패한 항목만 고치나**
전체를 다시 만들면 **이미 맞던 부분까지 바뀌어** 어제 맞던 것이 오늘 틀리는 일이 생깁니다. 시간과 비용도 더 듭니다.
**왜 최대 3회인가**
무한 반복을 막기 위해서입니다. 그리고 **3회 안에 안 고쳐지면 기준이나 설계가 잘못된 것**이므로 사람이 봐야 합니다. 계속 돌려봐야 답이 안 나옵니다.
**왜 검사 기록을 남기나**
어느 회차에 무엇이 실패했는지 남아야 **"이 기준은 항상 실패하네"를 발견**할 수 있습니다. 그러면 기준을 고치거나 생성 부분을 고쳐야 합니다.
**왜 규칙과 목표를 따로 둔는가**
CLAUDE.md는 어떤 일을 하든 항상 지킬 규칙이고, plan.md는 이번 작업의 목표입니다. **다른 업무로 바꿀 때 plan만 고치면 됩니다.**
**왜 평가 기준을 문서로 뺀냈나**
기준을 코드 안에 박아두면 개발자가 아닌 사람은 고칠 수 없습니다. 문서로 빼두면 **업무 담당자가 직접 기준을 바꿀 수 있습니다.**

# 5부. 검토와 정리 (10분)
## 5-1. 만들어진 파일 확인
작업 폴더에 아래 파일들이 생겼는지 봅니다.
- 지침서 파일
- 인수인계 문서
- 오류해결 모음
- 노하우 모음
## 5-2. 반드시 확인할 세 가지
**첫째, 비밀번호와 개인정보가 들어가 있지 않은가.** 여러 사람이 볼 문서입니다. 이것부터 확인하세요.
**둘째, 자료에 없는 내용이 그럴듯하게 채워져 있지 않은가.** '확인 필요'로 표시됐는지 봅니다.
**셋째, 앱 주소와 이름이 정확한가.** 틀리면 다음 사람이 못 찾습니다.

**AI가 만든 문서를 그대로 올리지 마세요.** 12주 내내 강조한 것입니다. **초안은 AI가, 확인은 사람이.**

## 5-3. 드라이브에 올리기
1. 구글 드라이브에서 교육기관 심화교육 폴더의 12회차 폴더를 엽니다
2. 인수인계 문서, 오류해결 모음, 노하우 모음 세 파일을 올립니다
3. 에이전트 파일 폴더도 함께 올립니다
**문서 파일은 구글 문서로 변환해서 올려도 됩니다.** 여러 사람이 보기 편합니다.
