## 왜 설치를 "수업 중에 함께" 하는가
```plain text
설치를 미리 각자 해오지 않는 이유:

컴퓨터마다 환경이 전부 다릅니다.
  · 운영체제 (Windows 10/11, Mac Intel/Apple Silicon)
  · 백신 프로그램의 차단
  · 회사 PC의 관리자 권한 제한
  · 기존에 깔린 프로그램과의 충돌

이런 변수 때문에 혼자 설치하면 막히는 지점에서
아무도 도와줄 수 없습니다.
강사 화면을 함께 보면서, 막히면 바로 해결하며 진행합니다.
```
> ⚠️ 이 문서는 "혼자 미리 하세요"가 아니라 "강사와 함께 볼 때 참고하세요"용입니다. 순서대로 강사를 따라오시면 됩니다.

# 수업 전 안내
아래 두 가지만 수업 전에 확인·준비해 오시면 됩니다. 프로그램 설치는 수업 중에 함께 합니다.
## 사전 준비 1 — 컴퓨터 저장 공간 비우기
```plain text
필요 공간: 최소 5GB 이상 여유 (넉넉하게 10GB 권장)

이유:
  Node.js, Git, Cursor 세 프로그램 + 각자 앱 코드 +
  실습 중 생성되는 파일들을 저장할 공간이 필요합니다.

확인 방법:
  [Windows] 파일 탐색기 → '내 PC' → C: 드라이브 확인
            → 남은 공간이 5GB 미만이면 정리 필요
  [Mac]     화면 왼쪽 위 애플 로고 → '이 Mac에 관하여'
            → '저장 공간' 탭 → 사용 가능 공간 확인

공간이 부족하면:
  · 다운로드 폴더의 큰 파일 정리
  · 휴지통 비우기
  · 안 쓰는 프로그램 삭제
```
## 사전 준비 2 — 내 컴퓨터 사양 확인
```plain text
확인해서 수업 전 강사에게 알려주시면, 미리 대비할 수 있습니다.

최소 사양 (2026년 기준):
  · 운영체제: Windows 10 이상 / macOS 12(몬터레이) 이상
  · 메모리(RAM): 4GB 이상 (8GB 이상 권장)
  · 저장 공간: 5GB 이상 여유

확인 방법:
  [Windows]
    키보드에서 [윈도우키] + [Pause/Break]
    또는 설정 → 시스템 → 정보
    → "설치된 RAM"과 "시스템 종류(64비트)" 확인
    → Windows 버전은 설정 → 시스템 → 정보 → "Windows 사양"

  [Mac]
    화면 왼쪽 위 애플 로고 → '이 Mac에 관하여'
    → macOS 버전(예: Sonoma 14.x)
    → 메모리(RAM)
    → 칩(Apple M1/M2/M3 또는 Intel) 확인
    ★ 칩 정보가 중요합니다 — 설치 파일 종류가 갈립니다
```
**수업 전 강사에게 알려줄 것 (한 줄이면 충분):**
```plain text
예시:
  "Windows 11, RAM 16GB, 64비트입니다"
  "Mac인데 Apple M2 칩, macOS Sonoma입니다"
  "Mac인데 Intel이에요, macOS Ventura입니다"
```
> 💡 사양이 최소 기준에 약간 못 미쳐도 오늘 실습은 대부분 가능합니다. 다만 미리 알면 강사가 그 자리에서 더 빠르게 대응할 수 있습니다.

# 오늘 설치할 3가지 — 미리 그림 그리기
```plain text
설치 순서와 각각의 역할:

① Node.js (+npm)   — 앱을 내 컴퓨터에서 실행시키는 엔진
                     (Lovable 앱은 이게 있어야 로컬에서 돌아감)
② Git              — 코드 버전 관리 도구
                     (Cursor가 GitHub와 대화할 때 뒤에서 사용)
③ Cursor           — AI 코드 편집기
                     (실제로 우리가 손으로 다루는 메인 도구)

왜 이 순서인가:
  Cursor 안에서 npm과 git 명령어를 쓰기 때문에,
  Cursor를 켜기 전에 Node.js와 Git이 먼저 깔려 있어야
  나중에 "명령어를 못 찾겠다"는 오류가 안 납니다.
```
> 💡 세 가지 모두 **무료**입니다. 결제 정보 입력이 필요 없습니다.

# STEP 1 — Node.js 설치 (앱 실행 엔진)
> 💡 **Node.js가 뭔가요?**<br>Lovable이 만든 앱은 웹 기술(JavaScript)로 되어 있습니다. 이 앱을 내 컴퓨터에서 미리보기로 띄우려면<br>JavaScript를 실행해주는 엔진이 필요한데, 그것이 Node.js입니다.<br>npm(앱에 필요한 부품을 설치하는 도구)이 함께 딸려옵니다.

## Windows — Node.js 설치


```plain text
STEP 1-1. 브라우저에서 nodejs.org 접속

STEP 1-2. 첫 화면 왼쪽의 [Get Node.js®] 버튼 클릭
  → 예전의 "초록색 LTS 버튼"은 이제 없습니다.
  → 큰 [Get Node.js®] 버튼을 누르면 다운로드 페이지로 넘어갑니다.
  → (그 아래 'Get security support'는 다른 버튼이니 누르지 마세요)


STEP 1-3. 다운로드 페이지에서 — 위쪽 복잡한 부분은 전부 무시
  → 페이지 맨 위에 이런 문장이 있습니다:
    "Node.js [v24.x LTS] 를 [Windows] 환경에서 [Docker] 방식으로..."
  → ⚠️ 방식이 'Docker' 등으로 잡혀 있으면 아래에
    'docker pull node...' 같은 무서운 명령어 코드가 보입니다.
    → 이건 우리가 쓸 게 아닙니다. 전부 무시하세요.
  → 위쪽 드롭다운(방식 선택)은 절대 건드리지 마세요.
  → 버전이 [LTS]로 표시돼 있는지만 확인 (기본값이 LTS라 보통 그대로 둠)

STEP 1-4. 페이지 맨 아래로 스크롤 → 초록색 버튼 클릭
  → "또는 [x64] 아키텍처... 미리 빌드된 Node.js를 다운로드하세요" 아래
  → 초록색 [Windows 설치 프로그램 (.msi)] 버튼 클릭
  → ⚠️ 옆의 [Standalone Binary (.zip)]는 아닙니다. 반드시 .msi

STEP 1-5. 다운로드된 .msi 파일 더블클릭 → 설치 마법사 진행
  → ① Welcome 화면 → [Next]
  → ② License Agreement → "I accept..." 체크박스 체크 → [Next]
       (체크 안 하면 Next가 회색으로 안 눌립니다)
  → ③ Destination Folder(설치 위치) → 기본값 그대로 → [Next]
  → ④ Custom Setup(설치 구성) → 기본값 그대로 → [Next]
       ★ 'Add to PATH'가 포함돼 있는지만 확인 (기본으로 켜져 있음)
         이게 있어야 나중에 명령어가 인식됩니다. 아무것도 끄지 마세요.
  → ⑤ Tools for Native Modules 화면
       → ⚠️ "Automatically install the necessary tools..." 체크박스는
         비워둡니다 (체크하지 않음) → [Next]
         체크하면 Python·빌드도구까지 대량 추가설치되어 오래 걸리고
         오늘 실습에는 전혀 쓰지 않습니다.
  → ⑥ Ready to Install → [Install]
       → "이 앱이 기기를 변경하도록 허용?" 팝업(UAC) → [예]
  → ⑦ 설치 진행 → 완료되면 [Finish]

STEP 1-6. 설치 확인 (가장 중요 — 여기서 성공/실패 판정)
  → 키보드 [윈도우키] 누르고 "cmd" 입력 → Enter → 명령 프롬프트 실행
  → 아래를 입력하고 Enter:
      node -v
  → v24.x.x (예: v24.18.0) 같은 버전 숫자가 나오면 성공
  → 이어서:
      npm -v
  → 11.x.x (예: 11.16.0) 같은 숫자가 나오면 npm도 정상
```

## Mac — Node.js 설치
> ⚠️ 아래 Mac 절차는 개편된 새 다운로드 페이지 구조를 반영한 것이지만<br>실습 당일 현장 검증 전 버전입니다. Mac 수강생이 있으면 화면을 함께 보며 확정합니다.

```plain text
STEP 1-3. 다운로드 페이지에서 운영체제가 [macOS]로 잡혔는지 확인
  → 위쪽 방식 드롭다운(Docker/nvm 등)의 복잡한 코드는 전부 무시

```

# STEP 2 — Git 설치 (버전 관리 도구)

## Windows — Git 설치


```plain text
STEP 2-1. 브라우저에서 git-scm.com 접속

STEP 2-3. Install 페이지로 이동 → 상단 [Windows] 탭 확인
  → 탭이 Windows / macOS / Linux / Build from Source 로 나뉘어 있습니다.
  → Windows 탭이 선택된 상태에서 진행합니다.

STEP 2-4. 맨 위 주황색 문장의 [Click here to download] 클릭
  → "Click here to download the latest (2.55.0...) x64 version of
     Git for Windows" 라는 문장의 링크입니다.
  → 아래 "Other Git for Windows downloads" 목록은 볼 필요 없습니다.
  → .exe 파일이 다운로드됩니다.

  💡 대부분의 윈도우 PC는 x64입니다. 이 링크가 정답입니다.
     (드물게 ARM64 노트북을 쓰는 수강생만 아래 목록의
      'Git for Windows/ARM64 Setup'을 받습니다.)

STEP 2-5. 다운로드된 .exe 파일 더블클릭 → 설치 마법사 진행

  ⚠️ Git 설치 마법사는 화면이 10개 이상으로 많습니다.
     겁먹지 마세요. 거의 전부 기본값 그대로 [Next]이고,
     딱 한 군데(에디터 선택)만 바꿉니다.

  → ① Information (GNU 라이선스 안내) → [Next]
       (읽을 필요 없음, 동의 체크박스도 없음)
  → ② Select Destination (설치 위치) → 기본값 → [Next]
  → ③ Select Components (구성 요소) → 기본값 그대로 → [Next]
  → ④ Start Menu Folder → 기본값 → [Next]
  → ⑤ ★ Choosing the default editor (에디터 선택) → 아래 설명 참고
       → 드롭다운을 [Use Notepad as Git's default editor]로 변경 → [Next]
  → ⑥ Initial Branch Name → 기본값(Let Git decide) → [Next]
  → ⑦ Adjusting your PATH environment → 아래 설명 참고
       → 가운데 옵션(기본 선택)을 그대로 두고 → [Next]
  → ⑧ 이후 여러 화면(줄바꿈, 터미널, 기타 옵션 등) → 전부 기본값 [Next]
  → ⑨ [Install] 클릭 → 설치 진행 → 완료되면 [Finish]

  ⚠️ Finish 화면의 [View Release Notes] 체크를 풀고 Finish하세요.
     켜져 있으면 Finish 직후 브라우저로 "릴리스 노트" 웹페이지가
     자동으로 열립니다. 이건 버전 변경 안내문일 뿐이니,
     떠도 그냥 닫으면 됩니다. 설치와 무관합니다.

STEP 2-6. 설치 확인 (성공/실패 판정)
  → cmd를 새로 엽니다. ([윈도우키] → "cmd" → Enter)
     ★ 이미 열어둔 cmd가 있어도 반드시 새 창으로 여세요 (아래 PATH 설명)
  → 아래를 입력하고 Enter:
      git --version
  → git version 2.55.x 같은 숫자가 나오면 성공
```

## 💡 개념 설명
### ① PATH란 무엇인가 (제일 중요)
PATH는 쉽게 말해 "컴퓨터가 프로그램을 찾아다니는 주소록"입니다.
```plain text
node -v 또는 git --version 을 쳤을 때,
컴퓨터는 "node가 어디 있지?" 하고 이 주소록을 뒤집니다.

  주소록에 위치가 등록돼 있으면 → 찾아서 실행 (버전 숫자 출력)
  등록돼 있지 않으면       → "내부 또는 외부 명령이 아닙니다" 오류
```
- 설치할 때 **'Add to PATH'가 켜져 있어야** 이 주소록에 자동 등록됩니다. Node·Git 모두 기본으로 켜져 있어 우리가 손댈 필요는 없습니다.
- 방금 프로그램을 깔았는데 **이미 열려 있던 cmd 창**은 옛 주소록을 기억합니다. 그래서 설치 후에는 **cmd를 새로 열어야** 갱신된 주소록으로 프로그램을 찾습니다.
- ⚠️ 실습날 "분명 설치했는데 명령어가 안 먹혀요"의 90%는 **cmd를 새로 안 열어서**입니다. 첫 대응: **cmd 새로 열기.** 그래도 안 되면 컴퓨터 재시작.
### ② 왜 에디터를 Notepad로 바꾸는가
에디터 선택 화면의 \*\*기본값은 `Use Vim`\*\*입니다.
```plain text
Git은 가끔 글자를 입력받아야 할 때(예: 커밋 메시지) 에디터를 자동으로 엽니다.
그 에디터가 Vim이면:
  · 검은 화면에 안내가 없고
  · 마우스가 안 먹고
  · 끄는 법조차 특이함 (:q! 같은 명령어를 알아야 나옴)
→ 처음 보는 사람은 "화면이 멈췄다"며 패닉합니다.
```
- Notepad(윈도우 기본 메모장)로 바꾸면, 우리가 아는 메모장이 열립니다. 쓰고 저장하고 닫으면 끝 — **못 빠져나오는 사고가 원천 차단**됩니다.
- ⚠️ **VS Code를 고르면 \[Next\]가 회색으로 죽습니다.** 그 에디터가 이 PC에 설치돼 있어야만 선택 가능한데, 우리는 VS Code 대신 Cursor를 쓰므로 없습니다. 그래서 **어떤 윈도우 PC에도 있는 Notepad**를 고르는 것입니다.
- 💡 사실 오늘 실습에선 Git 에디터가 열릴 일이 거의 없어, Vim 그대로 둬도 당장 문제는 없습니다. 이건 **사고 예방(안전벨트)** 차원입니다. 수강생 전원 Notepad로 통일하면 지도하기도 쉽습니다.

# STEP 1 — Node.js 설치 (앱 실행 엔진)
> 💡 **Node.js가 뭔가요?**<br>Lovable이 만든 앱은 웹 기술(JavaScript)로 되어 있습니다.<br>이 앱을 내 컴퓨터에서 미리보기로 띄우려면<br>JavaScript를 실행해주는 엔진이 필요한데, 그것이 Node.js입니다.<br>npm(앱에 필요한 부품을 설치하는 도구)이 함께 딸려옵니다.
> ⚠️ **2026년 7월 기준 nodejs.org 화면이 개편되었습니다.**<br>예전처럼 첫 화면에 초록색 \[LTS\] 버튼이 바로 있지 않습니다.<br>\[Get Node.js®\] → 다음 페이지 맨 아래 초록 버튼, 이렇게 **두 단계**로 바뀌었습니다.<br>아래 절차는 개편된 실제 화면 기준입니다.

## Windows — Node.js 설치
```plain text
STEP 1-1. 브라우저에서 nodejs.org 접속

STEP 1-2. 첫 화면 왼쪽의 [Get Node.js®] 버튼 클릭
  → 예전의 "초록색 LTS 버튼"은 이제 없습니다.
  → 큰 [Get Node.js®] 버튼을 누르면 다운로드 페이지로 넘어갑니다.
  → (그 아래 'Get security support'는 다른 버튼이니 누르지 마세요)

STEP 1-3. 다운로드 페이지에서 — 위쪽 복잡한 부분은 전부 무시
  → 페이지 맨 위에 이런 문장이 있습니다:
    "Node.js [v24.x LTS] 를 [Windows] 환경에서 [Docker] 방식으로..."
  → ⚠️ 방식이 'Docker' 등으로 잡혀 있으면 아래에
    'docker pull node...' 같은 무서운 명령어 코드가 보입니다.
    → 이건 우리가 쓸 게 아닙니다. 전부 무시하세요.
  → 위쪽 드롭다운(방식 선택)은 절대 건드리지 마세요.
  → 버전이 [LTS]로 표시돼 있는지만 확인 (기본값이 LTS라 보통 그대로 둠)

STEP 1-4. 페이지 맨 아래로 스크롤 → 초록색 버튼 클릭
  → "또는 [x64] 아키텍처... 미리 빌드된 Node.js를 다운로드하세요" 아래
  → 초록색 [Windows 설치 프로그램 (.msi)] 버튼 클릭
  → ⚠️ 옆의 [Standalone Binary (.zip)]는 아닙니다. 반드시 .msi

STEP 1-5. 다운로드된 .msi 파일 더블클릭 → 설치 마법사 진행
  → ① Welcome 화면 → [Next]
  → ② License Agreement → "I accept..." 체크박스 체크 → [Next]
       (체크 안 하면 Next가 회색으로 안 눌립니다)
  → ③ Destination Folder(설치 위치) → 기본값 그대로 → [Next]
  → ④ Custom Setup(설치 구성) → 기본값 그대로 → [Next]
       ★ 'Add to PATH'가 포함돼 있는지만 확인 (기본으로 켜져 있음)
         이게 있어야 나중에 명령어가 인식됩니다. 아무것도 끄지 마세요.
  → ⑤ Tools for Native Modules 화면
       → ⚠️ "Automatically install the necessary tools..." 체크박스는
         비워둡니다 (체크하지 않음) → [Next]
         체크하면 Python·빌드도구까지 대량 추가설치되어 오래 걸리고
         오늘 실습에는 전혀 쓰지 않습니다.
  → ⑥ Ready to Install → [Install]
       → "이 앱이 기기를 변경하도록 허용?" 팝업(UAC) → [예]
  → ⑦ 설치 진행 → 완료되면 [Finish]

STEP 1-6. 설치 확인 (가장 중요 — 여기서 성공/실패 판정)
  → 키보드 [윈도우키] 누르고 "cmd" 입력 → Enter → 명령 프롬프트 실행
  → 아래를 입력하고 Enter:
      node -v
  → v24.x.x (예: v24.18.0) 같은 버전 숫자가 나오면 성공
  → 이어서:
      npm -v
  → 11.x.x (예: 11.16.0) 같은 숫자가 나오면 npm도 정상
```
