# [사례 연구] 프로님 광고지표 자동화 — 완결형 GAS 시스템과 "어디까지 가야 하나"

정리일: 2026-10-08 · 교육 에셋 N0891

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

> 이 자료는 실제 수강생(프로님)이 만든 GAS 자동화 시스템을 뜯어보며,<br>"드라이브 → GAS 정리 → 저장 → (앱)"이라는 데이터 파이프라인의 전체 구조와,<br>\*\*"굳이 Supabase·앱까지 가야 하는가"\*\*라는 판단 기준을 함께 배우는 사례 연구입니다.<br>GAS 자동화의 정석이 담긴 실물 코드라, 하나의 완결된 교보재로 사용합니다.
---
## 1. 이 사례가 중요한 이유
수강생들이 자주 묻는 질문이 있습니다.
> "단순한 데이터 말고, **매일 드라이브에 쌓이는 로우데이터를 GAS가 정리하고,<br>버튼 하나 누르면 자동으로 처리해서 저장·연동하는** 그런 시스템도 되나요?"
**답은 '된다'이고, 프로님 광고지표 시스템이 바로 그 실물입니다.**<br>심지어 이 시스템은 이미 그 대부분이 완성되어 있어서, "복잡한 자동화가 실제로<br>어떻게 생겼는지"를 보여주는 가장 좋은 사례입니다.
---
## 2. 데이터 파이프라인을 4개 조각으로 나누기
복잡해 보이는 자동화 시스템도 4개 조각으로 쪼개면 명확해집니다.
```plain text
[조각 1] 로우데이터 불러오기   (구글드라이브의 원본 파일을 GAS가 읽음)
[조각 2] 정리·가공            (버튼 하나로 필요한 형태로 정리)
[조각 3] 저장/전송            (구글시트 또는 Supabase에 저장)
[조각 4] 표시                (구글시트에서 보거나, 앱 대시보드로 표시)
```
> 💡 핵심: 이 4조각은 **독립적**입니다. 조각 3(Supabase 전송)을 뚫었다고<br>조각 1·2가 저절로 되는 게 아니고, 반대로 조각 1·2가 있으면 조각 3만<br>이어붙이면 됩니다. "어디까지 완성됐고, 무엇이 남았는지"를 조각으로 보면<br>시스템 전체가 한눈에 들어옵니다.
---
## 3. 프로님 시스템을 조각별로 해부
### 업무 배경
매일 네이버 광고센터에서 \*\*플레이스 광고지표(캠페인별 노출·클릭·비용)\*\*를<br>xlsx로 다운로드받아, 매장별로 정리하고 비즈머니(광고비) 잔액을 관리하는 업무.
### 조각 1 — 드라이브에서 로우데이터 불러오기 ✅ 완성
```plain text
importFromDrive() 함수가 담당:
  · DriveApp.getFolderById(FOLDER_ID) 로 지정 폴더 접근
  · 폴더 안 .xlsx 파일들을 파일명 내림차순 정렬 → 최신 파일 자동 선택
  · 파일명에서 날짜 추출
    (플레이스_캠페인_20260624_1137.xlsx → 2026-06-24)
  · Drive.Files.copy 로 xlsx를 임시 구글시트로 변환해 읽음
    ⚠️ 이 변환은 "Drive API 고급 서비스" 활성화가 필요 (함정 포인트)
```
> 💡 배울 점: **DriveApp**은 GAS가 구글드라이브의 파일을 코드로 다루는 도구입니다.<br>"폴더에서 가장 최신 파일을 자동으로 집는다"는 것이 자동화의 출발점입니다.<br>사람이 매번 어떤 파일인지 고를 필요가 없어집니다.
### 조각 2 — 버튼 하나로 정리·가공 ✅ 완성
```plain text
onOpen() 이 시트 상단에 커스텀 메뉴 "📊 광고 자동화" 를 자동 생성:
  · [① 데이터 입력]  → importFromDrive 실행
  · [② 시트 매핑]    → mapToStoreSheets 실행

버튼 ①의 정리 로직:
  · 캠페인 ID가 'cmp-'로 시작하는 행만 추출 (쓰레기 행 걸러냄)
  · 총비용·노출수·클릭수·클릭률·CPC 파싱
  · '원본데이터' 시트 9~12행에 4개 캠페인 정리 입력
  · 8행에 합계(총비용·노출·클릭 합, 평균 클릭률) 자동 계산

버튼 ②의 매핑 로직:
  · 캠페인명 → 매장 시트명 매핑 (CAMPAIGN_MAP)
    바베큐광장_100000 → '부화', 솥뚜껑구이 → '부솥' ...
  · 각 매장 시트의 A열에서 "기준 날짜와 일치하는 행"을 찾아 그 행에 입력
    (dateToSerial 로 날짜를 시트 시리얼 번호로 변환해 정확히 매칭)
  · 비즈머니 잔액 체크 → 기준 이하면 Gmail 자동 발송
```
> 💡 배울 점: 이 조각이 GAS의 진짜 힘입니다.<br>· **커스텀 메뉴(onOpen)**: 코드를 모르는 사람도 버튼만 누르면 실행.<br>· **파싱·필터링**: 'cmp-'로 시작하는 행만 뽑는 등, 사람이 하던 눈대중을 규칙으로.<br>· **날짜 매칭**: 날짜를 시리얼 번호로 바꿔 정확히 그 날짜 행에 꽂아넣음.<br>· **조건부 Gmail 알림**: 잔액이 (일평균 소진 × 2) 이하면 자동 메일.<br>→ "사람이 매일 확인하던 것"을 시스템이 대신 감시.
### 조각 3 — 저장 ✅ (단, 지금은 "구글시트"까지만)
```plain text
현재: 정리된 데이터가 '매장별 시트(부화/부솥/부돌/풍납)'에 저장됨.
     즉 구글시트 안에서 완결. Supabase는 아직 붙지 않은 상태.
```
### 조각 4 — 표시
```plain text
현재: 구글시트에서 직접 조회·그래프. (별도 앱 없음)
```

## 4. 그래서 — "복잡한 시스템도 Supabase 연동되나?" 의 답
**됩니다. 그리고 프로님 케이스가 가장 쉽습니다.** 이유는:
- 조각 1·2(드라이브 읽기 + 정리·가공)가 **이미 완성**되어 있음
- 앞선 리허설에서 뚫은 \*\*조각 3(GAS → Supabase 전송)\*\*만 끝에 이어붙이면 됨
지금 흐름:
```plain text
드라이브 xlsx → 원본데이터 시트 → 매장별 시트  (여기서 끝)
```
Supabase를 붙이면:
```plain text
드라이브 xlsx → 원본데이터 시트 → 매장별 시트
                                    ↓ (아래 코드만 추가)
                              Supabase 광고지표 테이블 → 앱 대시보드
```
`mapToStoreSheets()`에서 매장별 시트에 입력하는 그 지점에, 앞선 리허설의<br>`UrlFetchApp.fetch(Supabase...)` 를 함께 호출하면 됩니다. (개념 예시)
```javascript
// 매장별 시트에 입력하면서 Supabase에도 전송
const record = {
  store: sheetName,     // 부화/부솥/부돌/풍납
  date: dateStr,        // 2026-06-24
  impressions: imp,     // 노출수
  clicks: click,        // 클릭수
  ctr: ctr,             // 클릭률
  cost: cost            // 총비용
};
UrlFetchApp.fetch(SUPABASE_URL + '/rest/v1/ad_metrics', {
  method: 'post',
  contentType: 'application/json',
  headers: {
    'apikey': SERVICE_ROLE_KEY,               // Legacy service_role key
    'Authorization': 'Bearer ' + SERVICE_ROLE_KEY
  },
  payload: JSON.stringify(record),
  muteHttpExceptions: true
});
```
> 💡 즉 **파이프(연결 방식)는 이미 리허설로 검증됐고, 흐르는 데이터만<br>"휴무"에서 "광고지표"로 바뀔 뿐**입니다. 복잡한 로우데이터 파이프라인도<br>조각 3만 이어붙이면 앱까지 연결된다는 것을 보여주는 증명 사례입니다.

## 5. ★ 가장 중요한 질문 — "굳이 Supabase·앱까지 가야 하나?"
여기서 반드시 멈춰 생각해야 합니다. **기술적으로 가능하다 ≠ 반드시 해야 한다.**
프로님 시스템은 지금 **구글시트 안에서 이미 완결**되어 잘 돌아갑니다:
```plain text
✅ 매일 드라이브 파일 → 버튼 → 매장별 시트에 자동 정리
✅ 비즈머니 잔액 부족 시 Gmail 자동 알림
✅ 구글시트에서 바로 조회·그래프 확인 가능
```
그렇다면 **굳이 Supabase와 앱까지 만들 이유가 있을까요?** 판단 기준:





상황

권장




구글시트에서 보는 것으로 충분하다

**Supabase·앱 불필요.** 지금 그대로 유지




시트를 열지 않고, 웹/모바일 앱의 예쁜 대시보드로 보고 싶다

Supabase + 앱 추가




여러 사람이 각자 권한대로 접근해야 한다

Supabase + 앱 (권한 관리 필요)




외부(임원 등)에게 URL로 공유해야 한다

Supabase + 앱 (배포 필요)


> ⚠️ **핵심 원칙: 도구는 목적에 맞춰 고른다.**<br>"Supabase를 붙일 수 있다"는 것과 "붙여야 한다"는 것은 다릅니다.<br>구글시트로 충분한 업무에 무리하게 앱을 얹으면, 관리할 것만 늘고<br>실익이 없을 수 있습니다. **프로님 케이스는 "지금 시스템으로 충분할 수도<br>있다"가 정직한 답**이며, 앱 대시보드로 볼 뚜렷한 이유가 생겼을 때<br>비로소 조각 3·4를 추가하는 것이 맞습니다.
> 💡 이 판단은 다른 수강생에게도 그대로 적용됩니다.
- 프로님(발주·렌탈): 시트로 충분하면 유지. 다중 사용자·규모 커지면 그때 Supabase.
- 프로님(매장점검): 앱으로 이미 감. 휴무는 조회를 앱으로 통합할 이유가 있어 연동 검토.
- 프로님(결제): 부서 간 공유가 필수라 처음부터 앱+DB가 맞음.<br>→ **"업무의 성격"이 도구를 결정하지, "기술이 되니까"가 결정하지 않습니다.**

## 6. 이 사례에서 배우는 GAS 자동화 정석 (요약)
```plain text
· onOpen()으로 커스텀 메뉴 만들기 → 비개발자도 버튼으로 실행
· DriveApp으로 드라이브 파일 자동 선택 (최신 파일 집기)
· Drive API 고급 서비스로 xlsx → 구글시트 변환해 읽기
· 파일명에서 날짜 추출 (정규식 매칭)
· 'cmp-' 접두어로 유효 행만 필터링
· dateToSerial로 날짜를 시리얼 번호화해 정확한 행 매칭
· parseNumber로 "95,133원" → 숫자 변환
· 조건부 GmailApp.sendEmail 자동 알림 (임계값 = 일평균 × 2)
· (선택) UrlFetchApp로 Supabase 전송 = 조각 3 이어붙이기
```

## 붙여넣을 위치 안내
이 자료는 **독립된 사례 연구**로, 아래 위치를 권장합니다.
1. **8회차 교재 또는 심화 자료의 "GAS 자동화 심화" 섹션** — 가장 적합.<br>1권/2권은 "설치\~배포 파이프라인"이 주제라, 이 완결형 자동화 사례는<br>그 다음 단계(심화)에 두는 것이 흐름상 자연스럽습니다.
2. **개념 질문 로그의 "데이터 연동 방식 ③(구글시트+GAS)" 하단 심화 사례**로 첨부 —<br>방식 ③을 설명한 뒤 "실제로 이렇게 정교하게 만들 수 있다"는 실물 예시로 연결.
3. **프로님 개별 미션 카드의 참고 자료**로 링크 — 미션 카드의<br>"GAS 전환 완전성 검증" 항목 옆에, 본인 시스템 구조 해설로 붙이면<br>본인이 자기 시스템을 조각으로 이해하는 데 도움.
> 💡 권장: **1번(8회차 심화 자료)** 위치에 본문으로 넣고, 프로님 미션 카드에는<br>"→ 본인 광고지표 시스템 상세 분석은 \[GAS 자동화 심화 사례\] 참고" 한 줄만 링크.
