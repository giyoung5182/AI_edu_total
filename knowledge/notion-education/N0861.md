## PART 4. 강의 1 — 공통과정 1회차 심화 (35분)
> 지난 1회차에서 다룬 1.3\~1.6 내용을 **강사의 언어로 한 단계 더 깊이** 들어가는 시간입니다. 읽고 이해하는 것과 청중 앞에서 설명하는 것은 완전히 다릅니다. 각 개념마다 원리를 더 깊이 이해하고, 강의에서 어떻게 활용할지에 집중합니다.
---
### 4-1. 머신러닝 학습 방식 3가지 — 지도·비지도·강화학습
교재 1.3에서 AI → ML → 딥러닝 → 생성형 AI 계층을 배웠습니다. <br>한 단계 더 들어가면, <br>머신러닝이 "어떻게 스스로 배우는가"에는 세 가지 방식이 있습니다. 이 구분을 알아야 LLM이 왜 이렇게 작동하는지 설명할 수 있습니다.
**① 지도학습 (Supervised Learning) — 정답이 있는 데이터로 학습**
```plain text
학습 방식: [입력 데이터] + [정답 라벨] → 패턴 학습
예시:
  고양이 사진 100만 장 + "고양이" 라벨 → 고양이 인식 모델
  스팸 메일 수백만 건 + "스팸/정상" 라벨 → 스팸 필터

대표 활용: 이미지 인식, 스팸 분류, 번역, 음성 인식
LLM과의 연결: LLM 사전 학습(Pre-training)의 핵심 기반.
  "다음 단어 예측"이라는 문제 자체가 지도학습의 일종.
  인터넷의 텍스트가 입력, 다음 단어가 정답 라벨.
```
**② 비지도학습 (Unsupervised Learning) — 정답 없이 패턴 스스로 발견**
```plain text
학습 방식: [입력 데이터만] → 숨겨진 구조·군집 발견
예시:
  구매 이력 데이터만으로 → 유사한 고객 그룹 자동 분류
  뉴스 기사만으로 → 주제별 자동 군집화

대표 활용: 추천 알고리즘, 고객 세분화, 이상 탐지
LLM과의 연결: LLM이 텍스트의 의미 구조를 파악할 때 활용.
  "사과"와 "과일"이 의미적으로 가깝다는 걸 아는 것은
  비지도 방식으로 학습한 결과.
```
**③ 강화학습 (Reinforcement Learning) — 보상과 벌점으로 최적 전략 학습**
```plain text
학습 방식: [행동] → [보상/벌점] → 반복 → 최적 전략 발견
예시:
  알파고: 바둑 수 → 승리(보상)/패배(벌점) → 최강 전략 학습
  게임 AI: 점수 획득(보상)/죽음(벌점) → 최고 점수 전략

LLM과의 연결: RLHF (Reinforcement Learning from Human Feedback)
  = 인간 피드백 강화학습
  → 사람이 AI 답변에 "좋다/나쁘다" 평가
  → 이 평가를 강화학습으로 반영
  → 더 자연스럽고 안전한 답변 생성
  ChatGPT가 "그럴듯하게" 말하는 게 아니라
  "사람이 원하는 방식으로" 말하게 된 핵심 기술이 RLHF
```
> 💡 **강사 포인트 — 세 가지를 한 문장으로 연결하는 법**<br>"AI는 처음에 엄청난 양의 글을 보며 패턴을 익히고(지도학습), 그 안에서 의미 구조를 스스로 파악하고(비지도학습), 사람이 '이게 더 좋아'라고 피드백하면서 더 자연스러운 답을 내도록 다듬어진 거예요(강화학습)." — 세 단계가 합쳐진 게 오늘날의 LLM입니다.

### 4-2. 딥러닝 — 신경망 구조 (뉴런·레이어·가중치)
머신러닝 중에서도 딥러닝이 왜 특별한지, 그 구조를 이해해야 LLM이 "어떻게 복잡한 언어를 처리하는가"를 설명할 수 있습니다.
**인공 신경망의 구조**
```plain text
[입력층 Input Layer]
  → 데이터를 받아들이는 입구
  → 예: 텍스트의 각 토큰

        ↓

[은닉층 Hidden Layers] ← "딥(Deep)"의 정체
  → 데이터를 변환·추상화하는 여러 층
  → 층이 깊을수록 더 복잡한 패턴 학습 가능
  → 각 층은 수백~수천 개의 뉴런으로 구성

        ↓

[출력층 Output Layer]
  → 최종 결과를 내보내는 출구
  → 예: 다음에 올 토큰의 확률 분포
```
**뉴런 (Neuron) — 정보를 처리하는 최소 단위**
```plain text
입력값들을 받아서 → 가중치를 곱하고 → 합산 → 활성화 함수 통과 → 출력

예: 사람 뇌의 뉴런이 여러 신호를 받아 "충분히 강하면 반응"하는 것과 유사
    인공 뉴런도 입력 신호의 합이 임계값 이상이면 다음 층으로 신호 전달
```
**가중치 (Weight) — 학습의 실체**
```plain text
가중치 = 각 연결의 "중요도"를 나타내는 숫자
학습 = 가중치를 반복 조정하는 과정

예: "오늘 날씨가 __" 다음에 "맑다"가 올 확률이 높다는 걸
    AI가 아는 건, 그 연결의 가중치가 높게 조정돼 있기 때문

오차역전파(Backpropagation): 틀린 답이 나왔을 때
  → 얼마나 틀렸는지 계산
  → 뒤에서 앞으로 가중치를 조금씩 수정
  → 이 과정을 수억 번 반복 = 학습
```
> 💡 **강사 포인트 — 가중치를 비유로 설명하는 법**<br>"AI가 '공부'한다는 게 뭔지 아세요? 수조 개의 숫자(가중치)를 조금씩 조정하는 거예요. 처음엔 엉뚱한 답을 내다가, 틀릴 때마다 '아, 이 연결은 약하게, 저 연결은 강하게'를 수십억 번 반복한 결과가 지금의 AI입니다."

### (★과제/다음 시간) 4-3. 트랜스포머 아키텍처 — LLM이 문맥을 파악하는 원리
2017년 구글이 발표한 "Attention is All You Need" 논문에서 시작된 트랜스포머 구조는 오늘날 모든 LLM(ChatGPT·Claude·Gemini·교육기관 20)의 핵심입니다. 강사가 이 원리를 알면 "왜 AI가 긴 문장도 맥락을 잘 잡는가"를 설명할 수 있습니다.
**트랜스포머 이전의 문제**
```plain text
기존 방식 (RNN·LSTM):
  문장을 왼쪽에서 오른쪽으로 순서대로 처리
  → 문장이 길어지면 앞부분을 잊어버림
  → "나는 어제 친구와 함께 오랫동안 기다리던 그 카페에 ___"
     → 문장 끝에서 "나는"을 기억하기 어려움
```
**Attention 메커니즘 — 트랜스포머의 핵심**
```plain text
Attention = "지금 이 단어를 처리할 때
             문장의 어느 부분에 집중(Attention)해야 하는가"를
             동시에 계산하는 방식

예: "그 은행은 강가에 있다"
    → "은행"을 처리할 때
       "강가"에 높은 Attention → 금융 기관이 아닌 강둑으로 해석

예: "나는 어제 친구와 함께 카페에 갔다. 거기서 ___"
    → "거기서"를 처리할 때
       "카페"에 높은 Attention → 카페에서 일어난 일로 이어짐
```
**Self-Attention — 문장 안에서 단어끼리 서로 참조**
[원본 이미지 제외]
```plain text
모든 단어가 동시에 다른 모든 단어와의 관련성을 계산
→ 순서대로 처리하지 않아도 됨
→ 병렬 처리 가능 → 학습 속도 혁신적 향상
→ 긴 문맥도 잃어버리지 않음

[Query] 지금 처리 중인 단어가 "무엇을 찾는가"
[Key]   각 단어가 "나는 이런 정보를 갖고 있다"
[Value] 실제로 가져올 정보의 내용
→ Q·K가 매칭되면 V를 가져와서 합산
```
> 💡 **강사 포인트 — Attention을 비유로 설명하는 법**<br>"사람도 긴 글을 읽을 때 모든 단어에 똑같이 집중하지 않죠. '중요한 부분'에 더 집중하잖아요. AI도 똑같이 합니다. '지금 이 단어를 이해하려면 앞의 어느 단어를 참고해야 하나'를 매 순간 계산하는 게 Attention이에요. 그래서 문장이 길어도 앞부분을 잊지 않고 맥락을 잡을 수 있는 겁니다."

### (★과제/다음 시간) 4-4. LLM 원리 심화 — 사전학습·파인튜닝·Temperature·RLHF
**사전학습 (Pre-training) vs. 파인튜닝 (Fine-tuning)**
```plain text
사전학습 (Pre-training):
  인터넷·책·논문 등 수조 개 텍스트 학습
  → 언어의 일반적 패턴·지식 습득
  → 엄청난 컴퓨팅 자원 필요 (수백억 원 수준)
  → 이 단계에서 만들어진 게 "기반 모델(Base Model)"

파인튜닝 (Fine-tuning):
  기반 모델 위에 특정 목적에 맞는 추가 학습
  → 훨씬 적은 데이터·비용으로 가능
  → ChatGPT: 대화에 특화
  → 교육기관 20: 일상 관리·라이프스타일에 특화
  → Claude: 긴 문서 처리·안전성에 특화

강사 포인트: "루미가 일상 관리를 잘하는 이유"를
  파인튜닝 개념으로 설명할 수 있습니다.
```
**Temperature — 답변의 창의성·일관성 조절**
```plain text
Temperature = AI 답변의 "다양성" 조절 파라미터 (0~2 사이)

낮은 Temperature (0에 가까울수록):
  → 가장 확률 높은 토큰만 선택
  → 일관되고 예측 가능한 답변
  → 팩트 확인, 번역, 코딩에 적합

높은 Temperature (1~2):
  → 낮은 확률의 토큰도 선택 가능
  → 창의적이지만 일관성 낮음
  → 브레인스토밍, 창작, 아이디어 발산에 적합

"왜 같은 질문에 답이 매번 다른가?" 의 기술적 이유:
  Temperature가 0이 아닌 이상,
  매번 확률 분포에서 조금씩 다른 토큰이 선택됨
```
**RLHF — ChatGPT가 자연스러운 이유**
```plain text
RLHF = Reinforcement Learning from Human Feedback
      = 인간 피드백 기반 강화학습

과정:
  1. 기반 모델이 여러 답변 생성
  2. 사람이 "이 답변이 더 좋다" 평가
  3. 이 선호도를 보상 모델(Reward Model)로 학습
  4. 강화학습으로 "사람이 선호하는 답변" 방향으로 모델 조정
  5. 반복

결과:
  → 단순히 "그럴듯한 텍스트"가 아니라
  → "사람이 원하는 방식으로 도움이 되는 답변"을 생성
  → 위험하거나 해로운 내용을 피하는 것도 RLHF의 결과
```
> 💡 **강사 포인트 — RLHF를 비유로 설명하는 법**<br>"AI를 훈련시키는 건 강아지 훈련이랑 비슷해요. 잘했을 때 칭찬(보상), 잘못했을 때 교정(벌점)을 반복하면서 '사람이 좋아하는 행동'을 익히게 되는 거예요. ChatGPT가 공손하고 안전하게 답하는 이유가 이겁니다."

### 4-5. 환각 심화 — 원인·종류·**RAG**
**환각의 기술적 원인 — Softmax 확률 분포**
```plain text
LLM이 다음 토큰을 선택하는 과정:
  1. 수만 개 후보 토큰 각각에 점수 계산
  2. Softmax 함수로 확률 분포로 변환
  3. 가장 높은 확률의 토큰 선택

문제:
  → LLM은 "이게 사실인가"를 확인하지 않음
  → "이 맥락에서 가장 자연스러운 토큰"을 선택할 뿐
  → 낮은 확률의 토큰도 선택될 수 있음 (Temperature)
  → 모르는 주제에서도 "그럴듯한 문장"은 생성 가능
  → 결과: 사실이 아닌 내용을 자신 있게 생성
```
**환각의 종류 3가지**
```plain text
① 사실 오류 (Factual Hallucination)
   → 틀린 날짜, 없는 통계, 가짜 인용
   → 예: "세종대왕이 1446년에 스마트폰을 발명했습니다" --> 퍼블렉시티.

② 출처 조작 (Citation Hallucination)
   → 실제로 없는 논문·책·기사를 있는 것처럼 인용
   → 제목·저자·연도까지 그럴듯하게 만들어냄
   → 학술·법률 분야에서 특히 위험

③ 맥락 이탈 (Context Drift)
   → 대화가 길어질수록 앞의 조건·제약을 잊고 벗어남
   → 예: "한국어로만 답해줘"라고 했는데
          대화가 길어지면 영어로 답변 시작
```
**RAG — 환각을 줄이는 핵심 기술**
```plain text
RAG = Retrieval-Augmented Generation
    = 검색 증강 생성

작동 방식:
  질문 입력 → 관련 문서·데이터 검색 → 검색 결과를 맥락으로 제공
  → LLM이 검색된 실제 자료를 바탕으로 답변 생성

효과:
  → AI가 "지어내는" 대신 "실제 자료에서 찾아서" 답변
  → 환각 대폭 감소, 출처 제공 가능

루미와의 연결:
  루미가 "내 일정을 기억한다"는 것도 RAG 개념의 적용.
  내가 등록한 데이터를 참조해서 답하기 때문에
  범용 AI보다 개인화된 정확한 답변이 가능.
```
> 💡 **강사 포인트 — 환각 3종류를 강의에서 쓰는 법**<br>환각을 하나로 뭉뚱그려 설명하면 수강생이 "AI는 다 거짓말한다"고 오해합니다. "이럴 때는 틀리고, 이럴 때는 맞는다"를 구체적으로 설명할수록 신뢰가 올라갑니다. 특히 출처 조작 사례를 하나 보여주면 수강생이 강렬하게 기억합니다.

### (2회차/06.25) 4-6. 토큰 심화 — 임베딩·BPE·한국어 이슈
**임베딩 (Embedding) — AI가 의미를 이해하는 방법**
```plain text
임베딩 = 토큰을 수백~수천 차원의 숫자 벡터로 변환하는 과정

예:
  "사과"  → [0.2, 0.8, 0.1, 0.9, ...]  (수백 개 숫자)
  "과일"  → [0.3, 0.7, 0.2, 0.8, ...]  (비슷한 숫자들)
  "자동차" → [0.9, 0.1, 0.8, 0.2, ...]  (전혀 다른 숫자들)

핵심:
  의미가 비슷한 단어 → 벡터 공간에서 가까운 위치
  의미가 다른 단어 → 벡터 공간에서 먼 위치

AI가 "사과"와 "과일"이 관련 있다는 걸 아는 이유:
  두 벡터의 수학적 거리가 가깝기 때문

유명한 예:
  king - man + woman ≈ queen
  (왕의 벡터 - 남자 벡터 + 여자 벡터 = 여왕 벡터)
  → 의미 관계가 수학으로 표현됨
```
**BPE (Byte Pair Encoding) — 토큰을 나누는 실제 알고리즘**
```plain text
BPE = 자주 함께 나타나는 글자 조합을 하나의 토큰으로 묶는 방식

작동 원리:
  1. 처음엔 모든 글자를 개별 토큰으로 시작
  2. 가장 자주 붙어 나타나는 쌍을 하나의 토큰으로 합침
  3. 이 과정을 원하는 어휘 크기가 될 때까지 반복

결과:
  자주 쓰이는 단어 → 하나의 토큰
  희귀한 단어 → 여러 토큰 조각으로 분리
  → 어휘 효율 최대화

예:
  "인공지능" (자주 쓰임) → [인공지능] 1토큰
  "할루시네이션" (덜 쓰임) → [할루] [시네] [이션] 3토큰
```
**한국어 토큰 비효율 이슈**
```plain text
문제:
  주요 LLM(GPT·Claude·Gemini)은 영어 중심으로 훈련
  → 한국어를 영어보다 많은 토큰으로 처리

실제 비교:
  영어: "I love artificial intelligence" → 약 5토큰
  한국어: "나는 인공지능을 사랑합니다" → 약 8~12토큰
  → 같은 내용을 한국어로 쓰면 1.5~2배 토큰 소비

실무 영향:
  → 무료 플랜 한도가 더 빨리 소진됨
  → 긴 한국어 문서를 넣으면 컨텍스트 윈도우를 빨리 채움
  → 요약·번역 등 한국어 작업 시 비용 고려 필요
```
> 💡 **강사 포인트 — 임베딩을 강의에서 쓰는 법**<br>"AI가 뜻을 이해한다"는 말이 정확히 뭔지 궁금하셨죠? 사실 AI는 모든 단어를 숫자로 바꾸고, 비슷한 뜻의 단어들이 수학적으로 가까운 위치에 오도록 훈련받은 거예요. "사과"와 "과일"이 가깝고, "자동차"와는 멀게요. 이게 AI가 '의미를 안다'는 것의 실제 정체입니다.

### 4-7. LLM 강의 비유 3가지 — 청중별 선택
교재에서 배운 핵심을 수강생에게 어떻게 전달하느냐에 따라 반응이 완전히 달라집니다.
**비유 ① 책을 엄청 많이 읽은 사람 (시니어·초보자 대상)**
> "AI는 세상에 있는 글을 상상도 못할 만큼 많이 읽은 사람이에요. 우리가 뭔가 물어보면, 그 사람이 읽어온 것들 중에서 '이 다음엔 이 말이 오는 게 가장 자연스럽다'를 골라서 대답해요. 정답을 외운 게 아니라 패턴을 익힌 거라서, 가끔 그럴듯하게 틀리기도 해요."
**비유 ② 자동완성의 진화 버전 (40\~50대 대상)**
> "스마트폰에서 문자 칠 때 다음 단어 추천해주는 기능 아세요? AI가 그걸 수십억 문장으로 훈련해서 엄청 정교하게 만든 거예요. '오늘 점심은 김치...' 다음에 '찌개'가 올 확률이 높다는 걸 아는 거죠. 이게 문장 전체로 확장된 게 지금 우리가 쓰는 AI예요."
**비유 ③ 확률 기반 텍스트 생성 (젊은 층·AI 경험자 대상)**
> "LLM은 정답을 검색하는 게 아니에요. 트랜스포머 구조로 문맥 전체를 한 번에 보면서, Attention 메커니즘으로 어느 단어에 집중할지 계산하고, 다음 토큰이 뭐가 올 확률이 가장 높은지를 Softmax로 뽑아내는 거예요. 그래서 같은 질문에도 답이 매번 조금씩 달라요."

### 4-8. 환각 — 강의 현장 시나리오별 대응
**시나리오 1 — 강의 중 AI가 틀린 답을 냈을 때**
❌ 흔한 대응
> "어, 이상하네요. 보통은 잘 되는데..."
✅ 프로다운 대응
> "보세요, 지금 AI가 틀린 답을 했어요. 이게 바로 환각이에요. 이렇게 실제로 나옵니다. 그래서 AI 답변은 항상 사람이 한 번 확인해야 해요."
**시나리오 2 — "AI가 틀린다고요? 그럼 못 쓰는 거 아닌가요?"**
❌ 흔한 대응
> "그래도 대부분은 맞아요, 걱정 마세요."
✅ 프로다운 대응
> "AI가 80%를 빠르게 만들어주면, 사람이 나머지 20%를 책임지는 거예요. 네이버 지도도 가끔 길을 잘못 안내하죠? 그래도 쓰잖아요. 최종 판단은 항상 사람이 하는 겁니다."
**시나리오 3 — 수강생이 AI 답변을 그대로 믿으려 할 때**
> "잠깐, 이 내용은 한 번 확인해볼게요. 건강·법률·금융 관련 내용은 AI 답변만 믿지 마시고, 꼭 전문가나 공식 출처에서 다시 확인하세요. AI는 초안입니다."

## PART 5. 강의 2 — 기존 강의 자료 피드백 (30분)
> 이사님이 만드신 87장 자료를 함께 보면서 구체적인 피드백을 드리는 시간입니다. 잘 만든 부분은 살리고, 개선이 필요한 부분은 방향을 함께 잡습니다.

### 5-1. 전체 구조 진단
**현재 자료의 전체 흐름**
```plain text
입장 방법 안내 → 강사 소개 → 타이밍·기회 → 블록체인 →
AI란? → LLM·토큰 → 프롬프트 → Tips → 교육기관 20 UI 설명 → 실습
```
**진단**
흐름 자체는 있지만, 수강생 입장에서 "왜 이 순서인가"가 보이지 않습니다. 특히 블록체인이 AI 개념 앞에 오는 구조는 "오늘이 AI 강의인가, 투자 설명회인가"라는 혼란을 줄 수 있습니다.
**개선 방향 — 수강생 여정 중심으로 재구성**
```plain text
❌ 현재: 강사가 말하고 싶은 순서
✅ 개선: 수강생의 이해가 쌓이는 순서

[도입] 오늘 뭘 배울 건지 + 수강생 현황 파악 (1.1 자기진단 활용)
   ↓
[공감] "AI 어렵지 않으세요?" — 수강생 고민 먼저 꺼내기 (1.2 공감 대화 활용)
   ↓
[개념] AI란 무엇인가 (LLM · 생성형 AI · 환각)
   ↓
[실전] 루미로 어떻게 쓰는가 (프롬프트 · 실습)
   ↓
[마무리] 오늘 배운 것 정리 + 다음 단계
```

### 5-2. 섹션별 구체적 피드백
**① 도입부 — 블록체인·토큰 노출**
- 현재: 블록체인 개념, BscScan 거래 화면, 교육기관 20 코인 시세 화면이 강의 앞부분에 등장
- 문제: 수강생 첫인상이 "AI 강의"가 아니라 "코인·투자 강의"로 형성될 수 있음. AI에 관심 있어서 온 일반 수강생에게 이탈 원인이 됨
- 개선: 도입부에서 완전히 분리. AI 라이프스타일 기능 강의와 자산·토큰 관련 내용은 목적과 대상이 다른 강의
**② "타이밍·기회·일상=대중화=시장=돈" 섹션**
- 현재: 카카오톡 → 루미로 이어지는 시장 흐름 설명, "기회는 다음 시대의 흐름을 먼저 읽는 곳에서 시작" 강조
- 문제: 동기부여 메시지로는 좋지만, AI 교육 도입부로 오면 "루미에 올라타야 돈을 번다"는 인상을 줄 수 있음
- 개선: "AI가 일상에 들어오고 있다"는 맥락 중심으로 편집. 수익·기회 강조는 줄이고 "생활이 편해진다"로 메시지 전환
**③ AI 개념 설명 (AI란?·LLM·토큰)**
- 현재: "데이터를 배웁니다 / 판단합니다 / 생성합니다" 세 줄로 설명
- 문제: AI를 이미 써본 수강생이 오면 즉시 "그래서요?"가 나옴. 전문성이 느껴지지 않음
- 개선: 오늘 심화한 LLM 작동 원리 + 청중별 비유를 자료에 반영. "AI는 다음 단어를 예측하는 모델"이라는 핵심 원리를 명확하게 전달하는 슬라이드로 교체
**④ 프롬프트 6요소 섹션**
- 현재: 구성 명확하고 디자인도 깔끔. 각 요소별 Before/After 예시 포함
- 잘 된 점: 수강생이 바로 써먹을 수 있는 구조. Before/After 비교가 직관적
- 보완점: 6요소를 한꺼번에 보여주면 수강생이 압도될 수 있음. "일단 목적 하나만 명확하게 → 익숙해지면 하나씩 추가"로 진입 장벽 낮추는 멘트 추가 필요
**⑤ 할루시네이션 섹션**
- 현재: 원인 → 예시 → 줄이는 법 3단 구성. 내용 탄탄함
- 잘 된 점: 실제 예시가 수강생 기억에 남음
- 보완점: "AI가 틀릴 수 있다"로 끝나면 수강생이 불안해짐. "그래서 사람이 필요하다"는 긍정적 전환 멘트로 마무리하면 강의 신뢰도 올라감
**⑥ 교육기관 20 UI 설명 (화면 설명 1\~4)**
- 현재: 실제 화면 캡처 4장으로 기능 안내
- 잘 된 점: 실제 앱 화면을 보여주는 것 자체는 효과적
- 문제: 설명 없이 화면만 나열된 느낌. 수강생이 "이게 뭘 하는 건지"를 스스로 파악해야 함
- 개선: 각 화면마다 "이 기능으로 뭘 할 수 있는가"를 한 줄 자막으로 추가. "이런 상황에서 이렇게 쓴다"는 시나리오 중심으로 재편
**⑦ 실습 섹션 (1\~5)**
- 현재: 이미지 생성 실습 위주 ("배를 그려줘" 동음이의어 활용, 메타프롬프트 등)
- 잘 된 점: 수강생이 직접 해볼 수 있고 재미 요소 있음
- 보완점: 루미의 핵심 가치인 "일상 관리" 실습이 없고 이미지 생성에 집중됨. 일정 등록, 메모, 가계부 기록 등 생활 밀착형 실습을 최소 하나 이상 추가하면 루미의 차별점이 살아남
