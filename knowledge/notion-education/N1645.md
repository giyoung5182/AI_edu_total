## 02. 파워쿼리란 무엇인가요?
> ⏱ 예상 소요: 약 35분
💡 **파워쿼리는 "데이터 준비 작업을 레시피로 기록해서, 다음부터는 버튼 하나로 반복하는 도구"입니다.**
**☑️ 먼저, 비유로 시작해 볼게요**
요리사가 매일 같은 요리를 만든다고 상상해 보세요. <br>처음에는 재료 손질부터 간 맞추기까지 하나하나 직접 합니다.<br>그런데 매일 똑같은 과정을 처음부터 반복한다면… 너무 비효율적이죠.<br>
그래서 요리사는 **레시피**를 만듭니다.<br>"양파 깍둑썰기 → 소금 한 꼬집 → 중불 5분" — 이렇게 적어두면<br>다음부터는 레시피대로만 하면 항상 같은 결과가 나옵니다.<br>**파워쿼리는 데이터 정리의 레시피 노트입니다.<br>**<br>"빈 행 삭제 → 공백 제거 → 날짜 타입 변환" → 여러분의 클릭이 그대로<br>**적용된 단계(Applied Steps)** 라는 레시피로 기록되고,<br>다음 달 새 파일이 오면 **새로고침 한 번**으로 같은 레시피가 자동 실행됩니다.

<br>- 감사에서 "이 보고서 수치의 근거를 제시하라"는 요청이 오면 <br> → 적용된 단계를 그대로 보여주면 됨
- 담당자가 바뀌어도 → 적용된 단계가 곧 인수인계 문서- 담당자 퇴사 후 감사 대응 실패 <br> → 파워쿼리를 쓰면 원천적으로 발생하지 않음

**☑️ M 언어 **
파워쿼리의 모든 클릭은 내부적으로 **M**이라는 언어의 코드로 기록됩니다.
- 우리가 M을 배울 필요는 없습니다 — 99%는 클릭으로 됩니다.
- 나머지 1% (클릭 메뉴에 없는 특수한 변환)가 필요할 때, **AI에게 M코드를 요청**하면 됩니다.
- 이것이 오늘 배울 "AI 활용" 파트의 핵심입니다.

**☑️ ⭕❌ 미니 퀴즈**
1. 파워쿼리로 정제하면 원본 파일이 수정된다
2. 새 파일이 폴더에 추가되면 쿼리를 처음부터 다시 만들어야 한다
3. 파워쿼리를 쓰려면 M 언어 문법을 외워야 한다
4. Power BI의 데이터 준비 기능은 파워쿼리와 같다

```sql
-- 어제: 개인정보 포함 컬럼 조회 (두 테이블 연결)
SELECT t.table_name, c.col_name, t.owner_dept
```

- 어제 카탈로그에 "갱신 주기: 월 1회"라고 적었다면, 오늘은 그 갱신 작업 자체를 자동화했습니다.
- 파워쿼리는 데이터 준비(ETL: 추출-변환-적재)를 '적용된 단계'라는 레시피로 기록해, 새로고침 한 번으로 반복하는 도구입니다.
- 적용된 단계는 내 작업의 데이터 계보(Lineage) 기록이며, 감사 대응·인수인계 문서를 겸합니다.
- 어제 본 `Gcal`/`gcal`/`GCal` 표기 혼용 같은 표준 미준수가 데이터에 남긴 흔적이 5대 오염(날짜 혼용·텍스트 숫자·공백·대소문자·중복)입니다.
- 진단은 AI에게 목적·출력 형식·항목 요구사항을 명시해 요청하고, 불완전한 답변은 추가 질문(핑퐁)으로 보완합니다.
- AI 직접 정제는 일회성·비민감 데이터에, 파워쿼리는 반복·사내 데이터에 적합합니다. 최강 조합은 "진단·코드는 AI, 실행은 내 파워쿼리".
- 어제 `is_pii = 'Y'`로 찾던 개인정보 컬럼이 든 파일은 AI에 업로드하지 않습니다. 구조와 가짜 예시만으로 충분합니다.
- 정제 순서: 행 단위 오염(빈 행·중복) 먼저 → 값 정리(공백·대소문자·쉼표) → 타입 변환은 맨 나중.
- 폴더 병합은 새 파일 추가 시 새로고침만으로 반영되고, 연결 속성으로 파일 열 때 자동 새로고침도 설정할 수 있습니다.
- 쿼리 병합은 어제 배운 JOIN의 클릭 버전이며, 왼쪽 외부(왼쪽 전체 유지)가 실무 기본값입니다.
- 왼쪽 앤티 조인은 "마스터에 없는 코드 찾기"로, 0행 확인 자체가 품질 점검 업무입니다.
- 피벗 해제는 보고서형 가로 표를 분석형 세로 데이터로 되돌리는 실무 필수 기능입니다.
- 그룹화로 쿼리 안에서 집계할 수 있고, 만든 단계는 ⚙️로 언제든 수정합니다.
- 클릭 메뉴에 없는 변환(상위 10% 등)은 고급 편집기 M코드를 AI에게 요청해 해결하며, 오류는 메시지를 그대로 복사해 물어봅니다.
