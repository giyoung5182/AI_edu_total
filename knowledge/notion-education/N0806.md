0교시에서 우리는 게임을 직접 하나씩 만들어 봤습니다. 말로 던지니 화면이 뚝딱 나오긴 했는데, 막상 보면 내가 머릿속에 그린 모습 그대로는 아니었을 겁니다. 게임은 대충 시켜도 됐지만, 내 업무에 쓸 도구는 내가 그린 그대로 나와야 합니다. 그래서 오늘은 원하는 것을 정확히 시키고, 마음에 안 드는 곳을 고쳐 내 것으로 만드는 법을 익힙니다. 따로 배워야 할 문법은 없고, 코드를 읽거나 외울 일도 없습니다. 우리가 할 일은 원하는 것을 말로 또박또박 설명하는 것입니다.
갓 들어온 후배에게 "알아서 잘 정리해 주세요"라고만 하면 엉뚱한 게 돌아오기 쉽습니다. 무엇을, 어떤 형식으로, 언제까지 원하는지를 후배가 알 수 없기 때문입니다. "이 자료를 표로 정리해서 날짜순으로, 내일 오전까지 주세요"라고 하면 원하는 것이 나옵니다. AI도 똑같습니다. 우리가 적은 만큼만 알고, 적은 그대로 만듭니다. 그래서 오늘 연습하는 건 사실상 '설명하는 법'입니다.

## 01. 바이브 코딩이란
2023년, AI 연구자 안드레이 카파시가 이런 말을 했습니다. "요즘 가장 인기 있는 프로그래밍 언어는 영어다." 컴퓨터 언어를 따로 배우지 않아도 사람이 쓰는 말로 컴퓨터에 일을 시킬 수 있게 됐다는 뜻입니다. 2025년에 그는 이 방식에 이름을 붙였습니다. 코드를 직접 쓰지 않고 AI에게 말로 지시해 만드는 방식, 이게 '바이브 코딩'입니다.
> "나는 그저 보고, 말하고, 실행하고, 복사해서 붙여넣을 뿐인데 대부분 작동한다. 이건 사실 코딩이라고 할 수 없다." — 안드레이 카파시
'바이브(vibe)'는 감각이나 분위기를 뜻합니다. 코드 문법을 한 줄씩 다룰 필요 없이, 내가 원하는 결과물의 느낌과 방향만 넘기면 AI가 만들어 줍니다. 그래서 오늘 배우는 건 '코딩'보다 'AI에게 무엇을 만들지 설명하는 법'에 가깝습니다.
이건 이미 일하는 방식으로 자리 잡았습니다.

**바이브 코딩, 이미 일하는 방식으로 자리 잡았습니다**
- **콜린스 사전** 2025년 올해의 단어: 'Vibe Coding'
- **와이콤비네이터** 2025년 초 선정 기업 네 곳 중 한 곳: 프로그램의 95% 이상을 AI로 제작
- **실리콘밸리**: 이미 일상적인 개발 방식

우리가 오늘 해 보는 게 지금 가장 빠르게 퍼지는 방식입니다.
## 02. 작업 흐름: 보기 · 말하기 · 실행하기 · 고치기
바이브 코딩은 네 단계로 돕니다. 화면을 보고, 원하는 것을 말로 시키고, 결과를 받아 보고, 마음에 안 드는 곳을 다시 말합니다. 이 네 단계를 계속 반복합니다. 코드를 직접 읽거나 쓰는 단계는 없습니다.

## 03. Gemini Canvas
우리가 쓸 도구는 구글 Gemini의 캔버스(Canvas)입니다. 캔버스는 Gemini 안에서 문서나 코드를 만들고 다듬고 공유하도록 만들어진 작업 공간으로, 고친 내용이 실시간으로 화면에 반영됩니다. HTML로 만든 웹 화면은 따로 실행할 필요 없이 캔버스 안에서 바로 미리 볼 수 있습니다.
보통 채팅창은 우리가 글로 물으면 AI도 글로 답하는 공간입니다. 캔버스를 켜면 화면이 둘로 나뉩니다. 왼쪽은 지시를 적는 채팅창, 오른쪽은 그 지시대로 만들어진 결과물이 실제로 보이는 화면입니다. 왼쪽에 "이렇게 만들어줘"라고 적으면 오른쪽에 화면이 생기고, "이 부분을 이렇게 바꿔줘"라고 적으면 오른쪽이 그 자리에서 바뀝니다. 만들어지는 걸 눈으로 보면서 고칠 수 있어, 코드를 모르는 우리에게 편한 도구입니다.

## 04. 구체적으로 지시하기
AI는 우리가 적은 그대로 만듭니다. '예쁘게 만들어줘'라고 하면 무엇이 예쁜지 AI가 알아서 짐작합니다. 그 짐작이 내가 그린 그림과 맞을 확률은 낮습니다. '연한 파란 배경에 가운데 둥근 버튼을 놓아줘'라고 하면, 적힌 대로 연한 파란 배경에 둥근 버튼이 가운데 놓입니다. 같은 AI인데 결과가 갈리는 건, 내가 본 화면을 얼마나 그대로 적었느냐에 달렸습니다.

그러니 지시는 떠오른 화면을 눈에 보이듯 적습니다. 무엇이 어디에 있고, 색은 어떻고, 누르면 무슨 일이 일어나는지를 적습니다. 처음부터 완벽할 필요는 없습니다. 일단 시켜 보고, 화면을 본 다음 마음에 안 드는 곳을 고치면 됩니다.
## 05. 실습: D-day 계산기
캔버스를 열고, 먼저 대충 한 줄 던져 봅니다.
```plain text
날짜 계산기 만들어줘
```
엔터를 누르면 날짜와 관련된 화면이 나오긴 합니다. 그런데 마감일 계산기인지, 두 날짜 사이를 세는 도구인지, 결과가 어떤 모양인지는 AI가 알아서 정해 버립니다. 내가 원한 것과는 다릅니다. 이번엔 본 그대로 구체적으로 말합니다.
```plain text
마감일을 고르면 오늘부터 며칠 남았는지 큰 숫자로 보여주는 페이지를 만들어줘
```
잠깐 사이에 오른쪽 화면이 채워집니다. 날짜를 고르는 칸이 있고, 그 아래에 '며칠 남았다'는 숫자가 큼지막하게 뜹니다. 아무 날짜나 하나 넣어 보세요. 며칠 남았는지 숫자가 딱 바뀝니다. 방금 우리가 만들었습니다. 코드는 한 줄도 보지 않았습니다.
같은 AI에게 시켰는데 두 결과가 갈렸습니다. 차이를 만든 건 내 지시의 구체성입니다. 오늘 이 차이만 익혀도 절반은 한 셈입니다.
## 06. 실습: 화면 하나씩 수정하기
이제 고쳐 봅니다. 한 번에 여러 개를 바꾸려 하지 말고 하나씩 보냅니다. 하나 보내고 화면이 어떻게 바뀌는지 확인한 다음, 그다음 것을 보냅니다. 그래야 무엇 때문에 화면이 바뀌었는지 알 수 있습니다.
숫자가 좀 작다 싶으면 이렇게 보냅니다.
```plain text
남은 날짜 숫자를 더 크게 해줘
```
가운데 숫자가 한층 커집니다. 다음으로 제목을 손봅니다.
```plain text
제목을 '납기까지 D-'로 바꿔줘
```
화면 위쪽 제목이 우리가 적은 문구로 바뀝니다. 마지막으로 지난 날짜를 눈에 띄게 합니다.
```plain text
기한이 지났으면 숫자를 빨간색으로 바꿔줘
```
지나간 날짜를 골라 보면 숫자가 빨갛게 표시됩니다. 세 번 고치는 동안 매번 같은 일을 했습니다. 한 가지를 말하고, 화면을 보고, 다음으로 넘어갔습니다. 고치기도 만들기와 같은 흐름입니다.

**한 번에 하나씩**
고칠 게 다섯 개 떠올라도 한 줄에 다 적지 말고 하나씩 보내세요. 무엇이 화면을 바꿨는지 보여야 다음에 더 잘 시킬 수 있습니다.

## 07. 실습: AI에게 기능 제안받기
지금까지는 내가 원하는 걸 알고 시켰습니다. 그런데 만들다 보면 뭘 더 붙이면 좋을지 막막할 때가 있습니다. 이럴 때는 바로 고치게 시키지 말고 AI에게 먼저 물어봅니다. 코드는 건드리지 말고 설명만 해달라고 하면, 화면은 그대로 둔 채 선택지를 알려 줍니다.
```plain text
코드는 고치지 말고, 이 도구에 뭘 더하면 좋을지 설명만 해줘
```
더하면 좋을 기능 몇 가지를 글로 설명해 줍니다. 한꺼번에 다 시키지 말고, 그중 마음에 드는 하나만 골라 시킵니다.
```plain text
그럼 그걸 추가해줘
```
고른 기능이 화면에 더해집니다. 다시 물어보고, 또 하나 골라 추가합니다. 이렇게 두세 번 반복해 보세요. 내가 방향을 쥔 채로 기능을 하나씩 늘려 가게 됩니다.

## 08. 실습: 기한 관리표로 확장하기
지금까지 만든 D-day 계산기는 날짜 하나가 며칠 남았는지 보여 줍니다. 여기에 실제 업무에서 쓸 법한 기능을 얹으면 기한 관리표가 됩니다. 한 줄씩 시켜 봅니다.
```plain text
마감일을 여러 개 등록해 임박한 순서로 목록을 보여줘
```
날짜 하나만 보던 화면이 여러 마감일을 줄지어 보여 주는 목록으로 바뀝니다. 임박한 순서로 정렬되니 맨 위가 가장 급한 일입니다. 다음으로 각 날짜에 이름표를 붙입니다.
```plain text
각 기한에 계약명이나 품목 이름을 붙이게 해줘
```
날짜마다 이름을 적을 수 있어, 무슨 건의 기한인지 한눈에 보입니다. 마지막으로 급한 정도를 색으로 구분합니다.
```plain text
3일 이내는 빨강, 일주일 이내는 노랑으로 표시해줘
```
임박한 항목이 빨강, 그다음이 노랑으로 칠해집니다. 처음에 날짜 하나 세던 화면이 기한을 관리하는 표가 됐습니다. 말로 시키고, 화면을 보고, 한 줄씩 고쳤습니다. 코드는 끝까지 한 줄도 읽지 않았습니다.

**회사 자료는 그대로 넣지 마세요**
실제 계약명이나 품목을 시험 삼아 적어 보고 싶어도, 진짜 회사 정보는 빼거나 가짜 이름으로 바꿔 넣습니다. 입력창에 친 자료는 외부 서버로 넘어갑니다.

## 09. 정리
오늘 우리는 빈 화면에서 시작해 기한 관리표까지 만들었습니다. 그 사이에 한 일은 같은 동작의 반복입니다. 원하는 것을 말로 시키고, 나온 화면을 보고, 마음에 안 드는 곳을 다시 말로 고쳤습니다. 잘 시키려면 떠오른 화면을 본 그대로, 구체적으로 적으면 됩니다. 다음 시간에는 이 도구를 잠깐 내려놓고 '나는 무엇을 만들지'부터 정해 봅니다. 시키기 전에, 무엇을 시킬지를 먼저 또렷하게 만드는 시간입니다.
