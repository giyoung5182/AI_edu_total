# 스킬(SKILL) 이 뭔가요?

스킬(Skills)은 AI가 특정 작업을 수행할 때 참고할 수 있는 "전문 지식 패키지"입니다. 마치 사람이 업무 매뉴얼이나 가이드를 참고하듯이, AI도 스킬을 통해 일관된 방식으로 작업을 처리할 수 있어요.
간단히 말하면: 스킬은 "지시사항 + 참고자료 + 스크립트"를 담은 폴더입니다.


이러한 지시사항이 필요할 때만 로드되는 방식으로 사용되므로
다른 기능과 달리 Skills는 "이런 스킬이 있어요."라는 메타데이터 정보만 토큰을 차지하고 있으며 필요할 때만 사용됩니다. 결국 토큰을 절약해줍니다.

[원본 이미지 제외]


💡 실무 예시
내 회사에서 이런 상황을 생각해볼까요?
- 광고 카피를 작성할 때마다 "내 회사 브랜드 가이드라인"을 따라야 함
- 전략 문서를 작성할 때마다 "1페이지 전략 메모 템플릿"을 사용해야 함
- 고객 응대 메시지를 작성할 때마다 "고객 응대 톤앤매너 가이드"를 지켜야 함
매번 Claude에게 "이 가이드라인을 따라줘"라고 설명하는 건 번거롭죠. 스킬을 만들어두면, AI가 알아서 "아, 광고 카피 작성이네? 브랜드 가이드 스킬을 참고해야지!"라고 판단하고 적용합니다.

## 📦 스킬의 파일 구조
스킬은 단순한 폴더지만, 그 안에 특정 규칙을 따라 파일을 배치해야 합니다:

 Skills 는 3단계에 나누어 필요한 정보만 로드하여 토큰을 효율적으로 사용할 수 있습니다.
[원본 이미지 제외]


## 필수 요소
- **SKILL.md 파일**: 모든 Skill은 반드시 **SKILL.md** 파일을 포함해야 합니다. 이는 Skill의 핵심 파일로 YAML 프론트매터와 마크다운 본문으로 구성됩니다.
- **YAML 프론트매터의 필수 필드**
- **name**: Skill의 고유 식별자입니다. 소문자, 숫자, 하이픈을 사용하며 디렉터리 이름과 일치해야 합니다.
- **description**: Skill이 무엇을 하는지, 언제 사용해야 하는지를 포함해야 합니다. AI는 이 정보를 기반으로 Skill 실행 여부를 결정합니다.

- **마크다운 본문**: Claude가 작업을 수행하는 구체적인 단계와 지침을 안내합니다.
---
## 선택 요소
- **번들 리소스**: Skill 실행에 필요한 보조 자료를 제공하며, 다음과 같은 폴더 구조를 따릅니다.
- **scripts/**: Python이나 Bash로 작성된 실행 가능한 코드 파일입니다. 반복적으로 재작성되는 코드나 결정론적 실행이 필요한 작업에 사용합니다.
- **references/**: 필요 시 컨텍스트에 로드할 문서나 참고 자료입니다. 데이터베이스 스키마, API 문서, 도메인 지식, 회사 정책 등에 활용합니다.
- **assets/**: 컨텍스트에 로드하지 않고 출력에 사용할 파일입니다. 템플릿, 이미지, 아이콘, 보일러플레이트 코드 등이 포함됩니다.

# 역할
너는 경영진 보고용 보고서를 작성하는 전문 비즈니스 문서 작성자이다.
사용자가 제공한 자료, 링크, 문서, 메모, 초안 내용을 바탕으로 핵심 정보를 신속하게 파악하고, 이를 경영진의 의사결정에 도움이 되는 보고서 형태로 재구성한다.

# 목적
이 스킬은 단순 요약이 아니라, 산재된 정보를 경영진 보고에 적합한 구조와 문체로 정리하는 데 목적이 있다.
특히 핵심 메시지, 시장 및 현황, 주요 이슈, 리스크, 시사점, 실행 방향이 명확히 드러나는 문서를 작성해야 한다.


# 작성 원칙
보고서는 아래 원칙에 따라 작성한다.

1. 핵심 내용을 먼저 파악한다.
   자료 전체를 그대로 옮기지 말고, 중요한 사실, 변화, 의미, 대응 포인트를 우선 추린다.

2. 경영진 관점으로 재구성한다.
   실무 단위의 세부 설명보다는, 경영 판단에 필요한 영향, 우선순위, 리스크, 기회 요소를 중심으로 정리한다.

3. 구조를 분명하게 작성한다.
   문서는 목적, 현황, 주요 이슈, 시사점, 실행 방향이 자연스럽게 이어지도록 구성한다.

4. 문장은 간결하고 전문적으로 작성한다.
   불필요하게 장황한 표현은 줄이고, 명확하고 단정한 비즈니스 문장으로 작성한다.

5. 근거 없는 단정은 피한다.
   자료에 없는 내용을 과도하게 추론하지 말고, 불확실한 내용은 불확실하다고 분명히 밝힌다.

6. 필요 시 표와 항목화를 활용한다.
   시장 현황, 비교 내용, 리스크 요인, 대응 방향 등은 표나 항목으로 정리해 가독성을 높인다.

# 문체 가이드
다음 기준을 따른다.

- 문체는 비즈니스 문체로 작성한다.
- 지나치게 감정적인 표현은 사용하지 않는다.
- “~인 것으로 보인다”, “~가 필요하다”, “~를 검토할 필요가 있다”와 같은 보고형 표현을 적절히 사용한다.
- 경영진 보고용 문서답게 핵심 위주로 작성한다.
- 애매한 수식어보다는 의미가 분명한 표현을 사용한다.

# 출력 방식
사용자 요청이 없으면 아래 방식으로 결과를 제공한다.

- 제목 포함
- 본문은 보고서 형식으로 정리
- 필요 시 표 포함
- 항목 간 논리 흐름이 자연스럽게 이어지도록 작성
- 자료가 부족하면 추가로 필요한 정보도 함께 명시

# 추가 처리 원칙
- 사용자가 기사, 링크, 자료 요약을 주면 단순 요약이 아니라 보고용 문서로 다시 쓴다.
- 사용자가 러프한 메모를 주면 표현을 정제하고 구조를 보완한다.
- 사용자가 특정 목차를 주면 해당 목차를 우선 따른다.
- 사용자가 “경영진 보고용”, “임원 보고용”, “비즈니스 문체”를 요구하면 그 수준에 맞게 어휘와 구조를 강화한다.

# 금지 사항
- 자료의 문장을 그대로 길게 복붙하지 않는다.
- 근거 없는 수치, 사실, 전망을 임의로 추가하지 않는다.
- 실무 메모 수준의 산만한 구조로 작성하지 않는다.
- 지나치게 구어체이거나 가벼운 표현은 사용하지 않는다.

# 최종 목표
최종 결과물은 사용자가 별도의 수정 없이도 경영진 보고 초안으로 활용할 수 있을 정도로,
핵심이 명확하고, 구조가 정돈되어 있으며, 의사결정 관점이 살아 있는 문서여야 한다.

## 🔄 Progressive Disclosure: 효율적인 컨텍스트 관리
스킬의 가장 큰 장점은 "필요한 만큼만 불러온다"는 것입니다. 이를 Progressive Disclosure라고 해요.

👉 Level 1: 항상 로드 (\~100 토큰)
skill.md의 Front Matter만 항상 컨텍스트에 포함됩니다. 즉, AI는 "이런 스킬이 있구나"라는 정보만 항상 알고 있어요.

👉 Level 2: 트리거 되면 로드 (\~5000 토큰)
사용자가 "기획서 작성해줘"라고 말하면, AI가 이 키워드를 감지하고 skill.md의 본문을 불러옵니다.

👉 Level 3: 필요할 때만 로드 (가변)
skill.md에서 참조하는 파일(예: resources/strategy-memo.md)은 정말 필요할 때만 불러옵니다.

💡 왜 좋은가요?
프로젝트는 모든 파일을 한번에 로드하지만, 스킬은 단계별로 로드하기 때문에 컨텍스트 윈도우를 훨씬 효율적으로 사용합니다! 스킬 10개를 만들어도, 사용되는 스킬만 로드되니까 빠르고 효율적이죠.

### AI 를 잘 관리하는 방법 : 워크플로우 명시
AI에게 복잡한 업무를 맡길 때는, 작업을 한 번에 길게 설명하기보다
작은 단계로 나누어 순서대로 안내하는 것이 좋습니다.
단계가 분명할수록 AI는 지금 해야 할 일을 더 정확하게 이해할 수 있고,
사용자도 진행 상황을 쉽게 확인할 수 있습니다.
특히 자료 조사, 내용 정리, 분석, 초안 작성처럼 여러 과정이 이어지는 작업에서는
단계별 체크리스트를 함께 주면 훨씬 안정적으로 결과를 만들 수 있습니다.
이 방식은 작업 누락을 줄이고, 결과물의 흐름을 더 자연스럽게 정리하는 데에도 도움이 됩니다.
필요한 경우에는 각 단계에서 무엇을 확인해야 하는지까지 함께 적어주면 더욱 효과적입니다.

- 예시
```markdown
## 연구 종합 워크플로우

이 체크리스트를 복사하고 진행 상황을 추적하세요:

```
연구 진행:
- [ ] 단계 1: 모든 소스 문서 읽기
- [ ] 단계 2: 주요 테마 식별
- [ ] 단계 3: 주장 교차 참조
- [ ] 단계 4: 구조화된 요약 생성
- [ ] 단계 5: 인용 확인
```

**단계 1: 모든 소스 문서 읽기**

`sources/` 디렉토리의 각 문서를 검토하세요. 주요 주장과 뒷받침하는 증거를 기록하세요.

**단계 2: 주요 테마 식별**

소스 전체에서 패턴을 찾으세요. 어떤 테마가 반복적으로 나타나나요? 소스가 동의하거나 불일치하는 곳은 어디인가요?

**단계 3: 주장 교차 참조**

각 주요 주장에 대해 소스 자료에 나타나는지 확인하세요. 각 포인트를 지원하는 소스를 기록하세요.

**단계 4: 구조화된 요약 생성**

테마별로 결과를 구성하세요. 다음을 포함하세요:
- 주요 주장
- 소스의 뒷받침하는 증거
- 상충하는 관점 (있는 경우)

**단계 5: 인용 확인**

모든 주장이 올바른 소스 문서를 참조하는지 확인하세요. 인용이 불완전하면 단계 3으로 돌아가세요.
```

### AI 를 잘 관리하는 방법 : 피드백 루프 구현
**일반적인 패턴:** 검증자 실행 → 오류 수정 → 반복
이 패턴은 출력 품질을 크게 향상시킵니다.

AI를 활용할 때는 한 번에 완벽한 결과를 기대하기보다,
결과를 확인하고 수정하는 과정을 반복하는 방식으로 접근하는 것이 좋습니다.
초안을 먼저 만들고, 정해둔 기준에 따라 검토한 뒤,
부족한 부분을 수정하고 다시 확인하는 과정을 거치면
결과물의 정확성과 완성도를 높일 수 있습니다.
이러한 피드백 루프는 특히 문서 작성, 콘텐츠 제작, 보고서 정리처럼
품질 기준이 중요한 작업에서 더욱 효과적입니다.
중간 점검 없이 한 번에 끝내려 하면 작은 오류나 누락이 그대로 남기 쉽지만,
검토와 수정 단계를 반복하면 점차 더 안정적인 결과를 만들 수 있습니다.

따라서 AI에게 작업을 맡길 때는
‘초안 작성 → 기준에 따라 검토 → 수정 → 재검토’의 흐름을
하나의 작업 방식으로 설계해두는 것이 중요합니다.

```markdown
## 콘텐츠 검토 프로세스

1. 문체가이드.md의 지침에 따라 콘텐츠 초안 작성
2. 체크리스트에 대해 검토:
   - 용어 일관성 확인
   - 예가 표준 형식을 따르는지 확인
   - 모든 필수 섹션이 있는지 확인
3. 문제가 발견된 경우:
   - 각 문제를 특정 섹션 참조와 함께 기록
   - 콘텐츠 수정
   - 체크리스트 다시 검토
4. 모든 요구사항이 충족될 때만 진행
5. 문서 최종화 및 저장
```
