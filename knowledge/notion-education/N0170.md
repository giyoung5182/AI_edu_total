# 1. Skill의 구조 — 3단계로 열립니다
공식 문서에서는 이걸 **점진적 공개**라고 부릅니다. Skill을 이해하는 열쇠입니다.





단계

무엇이

언제 읽히나




**1단계**

맨 위 정보 (이름 + 설명)

**항상** — 다만 아주 짧음




**2단계**

SKILL.md 본문

이 작업과 관련 있다고 판단될 때




**3단계**

딸린 참고 파일

본문을 읽다가 필요해질 때


```plain text
평소        이름표만 보고 있음
   ↓ 내가 요청
2단계       이름표가 맞으니 본문을 펼침
   ↓ 본문에 "자세한 건 references/학년별표현.md 참고"
3단계       그 파일도 읽음
```
> 💡 **그래서 Skill은 여러 개 가지고 있어도 부담이 없습니다.**<br>그리고 **본문은 짧게, 상세한 건 딸린 파일로** 빼는 게 정석입니다.
## 폴더 구조
```plain text
class-page-maker/
  ├── SKILL.md          ← 필수. 핵심 지침만
  ├── references/       ← 필요할 때 읽는 상세 문서
  ├── assets/           ← 결과물에 쓰는 템플릿·서식
  └── scripts/          ← 실행할 코드
```
## ⚠️ 이름 규칙 — 안 지키면 아예 안 올라갑니다
```plain text
파일 이름   SKILL.md      정확히 이것만 (대소문자 포함)
폴더 이름   영문 소문자 + 붙임표만

✅ class-page-maker
❌ Class Page Maker   (공백·대문자)
❌ class_page_maker   (밑줄)
❌ 학습페이지-만들기    (한글)
```
**그 외**
```plain text
· 폴더 안에 README.md 를 넣지 않습니다 (설명은 SKILL.md나 references/)
· 이름에 claude 나 anthropic 을 넣지 않습니다 (예약어)
· 설명은 1024자 미만
```

# 2. 설명(description)이 전부입니다
Claude는 평소에 **설명만 보고 있습니다.** 여기가 부실하면 아무리 본문이 좋아도 안 꺼냅니다.
## 좋은 설명의 구조
```plain text
[무엇을 하는가] + [언제 쓰는가] + [어떤 말이 나오면]
```
**✅ 좋은 예**
```plain text
수업 자료 내용을 학생용 안내 웹 페이지로 만듭니다.
차시 안내, 활동 순서, 준비물 안내를 만들 때 사용.
"학습 페이지", "활동 안내 만들어줘" 요청 시 사용.
```
**❌ 나쁜 예**
```plain text
프로젝트에 도움을 줍니다.            ← 너무 막연
웹 페이지를 생성합니다.              ← 언제 쓰는지 없음
계층적 컴포넌트 구조를 구현합니다.     ← 사용자가 쓸 말이 아님
```
## 제대로 꺼내지는지 확인하는 법
공식 문서에 나오는 **가장 쉬운 진단**입니다. 그냥 물어보면 됩니다.
```plain text
방금 만든 Skill, 언제 쓰는 거야?
```
Claude가 **설명에 적힌 내용을 그대로 읊어줍니다.** 대답을 들어보면 뭐가 빠졌는지 바로 보입니다.
## 안 꺼내질 때 / 아무 때나 꺼내질 때





증상

원인

해결




필요한데 안 나옴

설명이 막연함

엉뚱한 데서 나옴

범위가 넓음

**"\~할 때는 쓰지 않는다"** 를 추가




나오는데 안 따름

본문이 장황함

짧게. 중요한 걸 위로


**부정 트리거 예시**
```plain text
설명에 이 내용도 넣어줘.
'단순히 글을 정리하거나 문서를 만들 때는 쓰지 않는다'
```
> 💡 **"\~할 때는 쓰지 마세요" 한 줄**이 의외로 효과가 큽니다.

# 3. 잘 만드는 원칙 여섯
## ① 당연한 걸 적지 마세요
Claude가 이미 잘하는 걸 적으면 분량만 늘어납니다. **틀리는 것만** 적습니다.
```plain text
❌ "보기 좋은 화면을 만드세요"
✅ "글자는 18px 이상. 기본값이면 초등학생이 못 읽음"
```
## ② 「자주 틀리는 것」 목록을 만드세요
아래쪽에 이 항목을 하나 두고 **실패할 때마다 한 줄씩** 추가합니다.
```markdown
## 자주 틀리는 것
- 글자 크기를 안 적으면 항상 작게 만듦. 반드시 명시
- 표를 만들면 휴대폰에서 잘림. 세로 배치로 유도
- '실행'처럼 어려운 낱말을 그대로 씀. 3학년 기준으로 풀어쓸 것
```
> 💡 **본문을 잘 쓰는 것보다 이 목록 한 줄이 실수를 더 잘 막습니다.**
## ③ 실제로 이렇게 자랍니다
```plain text
1일차    "우리 반 안내 페이지 만드는 방법. 기본틀 참조." — 이게 전부

2주차    + 주의: 글자 크기를 안 적으면 항상 작게 만듦

두 달 뒤  주의 항목이 6개로 늘어남 → 이제 거의 실수하지 않음
```
**처음부터 완벽하게 만들려고 하지 마세요.**
## ④ 너무 가두지 마세요
```plain text
❌ "반드시 A → B → C 순서로 하고 결과를 D 형식으로 저장하라"
✅ "이런 것들이 있고 각각 이럴 때 쓴다. 상황에 맞게 조합하라"
```
순서를 못 박으면 상황이 조금만 달라져도 이상해집니다.
## ⑤ 길어지면 나누세요
본문에는 핵심만. 상세한 건 `references/`로 빼고 링크로 연결합니다.
## ⑥ 성공했을 때 뽑으세요
공식 문서의 권고입니다.
> **"하나의 어려운 작업에서 성공할 때까지 반복한 다음,<br>그 성공한 방식을 Skill로 추출하라."**
**Skill을 먼저 만들려고 하면 잘 안 됩니다.** 성공한 경험이 있어야 뽑을 게 생깁니다.<br>오늘 4교시에 만들고 5교시에 뽑은 것이 바로 이 순서입니다.

# 4. Skill이 잘 되는 세 가지 갈래
공식 문서에서 실제로 잘 쓰이는 유형을 세 가지로 정리했습니다.
## ① 문서·결과물 만들기
일관된 품질의 산출물을 반복 생산합니다.
```plain text
· 학습 안내 페이지 만들기      ← 오늘 만든 것
· 활동지 만들기
· 지도안 정리하기
· 학부모 안내문 쓰기
```
**핵심 기법**: 기준을 내장, 템플릿 구조, 마무리 전 점검 목록
## ② 반복 절차 자동화
여러 단계를 정해진 방법으로 진행합니다.
```plain text
· 학기말 자료 폴더 정리
· 평가 기록 정리
· 차시 자료를 한 형식으로 통일
```
**핵심 기법**: 단계마다 확인 지점, 중간 검토, 반복 개선
## ③ 외부 도구 사용법 담기
연결된 도구를 잘 쓰는 방법을 담습니다.
```plain text
· 구글 드라이브 자료를 가져와 정리하는 방법
· 웹에서 자료를 모아오는 순서
```
> 💡 초등 강사 업무는 대부분 **①과 ②**입니다.

# 8. 만들기 전후 점검표
공식 문서의 체크리스트를 초등 강사용으로 줄인 것입니다.
**만들기 전**
```plain text
□ 이 Skill을 쓸 상황을 두세 개 떠올렸다
□ 그 상황에서 내가 어떻게 말할지 안다
```
**만든 뒤**
```plain text
□ 폴더 이름이 영문 소문자다
□ SKILL.md 철자가 정확하다
□ 설명에 "무엇을"과 "언제"가 다 있다
□ 지시가 구체적이다
□ 작업 후 확인할 것이 있다
```
**쓰기 전**
```plain text
□ 다르게 말해도 꺼내지는가
□ 관계없는 요청에는 안 꺼내지는가
□ 실제로 원하는 결과가 나오는가
```
**쓰면서**
```plain text
□ 실수할 때마다 「자주 틀리는 것」에 한 줄 추가
□ 안 쓰는 내용은 지우기
```

# 9. Skill이 왜 중요해졌나
한 문장으로 말하면 이렇습니다.
> **"매번 좋은 프롬프트를 쓰는 것"에서<br>"좋은 Skill을 고르는 것"으로 바뀌었습니다.**
매번 처음부터 상세한 지시문을 작성하는 대신, Skill을 불러오면 Claude가 그 분야에 맞는 방식과 기준, 하지 말아야 할 것을 즉시 알게 됩니다.
## 우리에게 이게 의미하는 것
```plain text
지금까지     매번 긴 지시문을 잘 쓰려고 애씀
                        ↓
앞으로       내가 반복하는 일을 Skill로 쌓아둠
             → 지시는 짧아지고 결과는 일정해짐
```
**오늘 만드신 Skill 하나가 그 시작입니다.**
한 학기 동안 대여섯 개만 쌓아도, 매번 처음부터 설명하던 시간이 크게 줄어듭니다.<br>그리고 그 Skill은 **다른 선생님께 그대로 넘겨드릴 수도 있습니다.**
> 💡 이게 오늘 배운 것 중 **가장 오래 남을 부분**입니다.<br>도구는 계속 바뀌지만, **"반복하는 일을 정리해두는 습관"** 은 어디서든 통합니다.

# 10. 정리
```plain text
① Skill은 이름표만 보이다가 필요할 때 펼쳐진다
② 그래서 설명(무엇을 + 언제)이 가장 중요하다
③ 당연한 건 적지 말고, 틀리는 것만 적는다
④ 실패할 때마다 한 줄씩 늘린다
⑤ 성공한 작업에서 뽑는다. 먼저 만들지 않는다
⑥ 많이 설치하는 게 목표가 아니다
```
> 💡 **오늘 만드신 Skill 하나 + 필요할 때 하나씩.** 이 속도가 맞습니다.
