# 3️⃣ 생산설비 대시보드 만들기
> 목표: 2번 실습에서 만든 `조치우선순위_설비.csv`와 원본 `실습파일/교육기관생산설비데이터_실습.xlsx`를 활용해, 설비 리스크를 한 화면에서 파악할 수 있는 HTML 대시보드를 만듭니다.

## 3-1. 2번 실습 산출물 확인
> 먼저 앞 실습에서 생성한 `조치우선순위_설비.csv`가 어떤 조건으로 만들어졌는지 확인합니다. 대시보드는 원본 전체 현황과 조치 우선순위 목록을 함께 보여주는 구조로 만듭니다.
```plain text
현재 폴더에서 조치우선순위_설비.csv 파일이 있는지 확인해줘.

있으면 아래 내용을 요약해줘.
- 전체 행 수
- 공장별 건수
- 담당팀별 건수
- 이상유형 Top 5
- 정지시간(h)이 가장 긴 설비 5개

파일이 없으면 실습파일/교육기관생산설비데이터_실습.xlsx를 읽어서 아래 조건으로 다시 만들어줘.
- 조치필요여부가 Y
- 그리고 가동률 85% 미만, 수율 98% 미만, 정지시간(h) 3시간 이상 중 하나 이상에 해당
- 결과 파일명은 조치우선순위_설비.csv
```
## 3-2. 대시보드에 넣을 KPI 정하기
> 업무 대시보드는 숫자가 많을수록 좋은 것이 아니라, 판단에 필요한 핵심 지표가 먼저 보여야 합니다.
```plain text
실습파일/교육기관생산설비데이터_실습.xlsx와 조치우선순위_설비.csv를 함께 사용해서 생산설비 대시보드 KPI를 계산해줘.

KPI 카드는 아래 4개로 구성해줘.
1. 전체 설비 로그 수
2. 조치필요 건수
3. 총 정지시간(h)
4. 평균 가동률

추가로 보조 지표로 평균 수율, 가동률 85% 미만 건수, 수율 98% 미만 건수도 계산해줘.
결과는 표로 보여주고, 대시보드에서 어떤 지표를 크게 보여주면 좋을지 3줄로 설명해줘.
```
## 3-3. HTML 대시보드 만들기
> 원본 엑셀은 전체 운영 현황을 보여주고, `조치우선순위_설비.csv`는 바로 봐야 할 대상을 보여줍니다. 두 데이터를 한 화면에 연결합니다.
```plain text
실습파일/교육기관생산설비데이터_실습.xlsx와 조치우선순위_설비.csv를 참고해서 생산설비 리스크 대시보드를 HTML로 만들어줘.

파일명은 hansol_equipment_dashboard.html로 저장해줘.
대시보드에는 아래 요소를 넣어줘.
- KPI 카드 4개: 전체 로그 수, 조치필요 건수, 총 정지시간, 평균 가동률
- 공장별 총 정지시간 막대그래프
- 공장-라인별 총 정지시간 Top 5 막대그래프
- 이상유형 비중 도넛 차트
- 담당팀별 조치필요 건수 표
- 조치 우선순위 설비 Top 10 표

디자인은 한솔 CI에 어울리는 녹색 계열을 기본으로 쓰고, 위험 강조는 빨간색보다 주황/적색 계열을 제한적으로 사용해줘.
```

## 3-5. 가독성과 강조 기준 다듬기
> 대시보드는 “예쁜 화면”보다 “어디를 먼저 봐야 하는지”가 명확해야 합니다. 조건부 강조와 메모 영역을 추가합니다.
```plain text
hansol_equipment_dashboard.html을 업무 판단에 맞게 다듬어줘.

수정 기준은 다음과 같아.
- 조치필요 건수와 총 정지시간은 강조 색상으로 표시
- 공장별 총 정지시간에서 가장 큰 공장은 강조
- 조치 우선순위 설비 Top 10 표에서 가동률 80% 미만 또는 정지시간 4시간 이상인 행은 눈에 띄게 표시
- 제목 아래에는 데이터 기준과 `교육용 샘플 데이터` 문구를 작게 넣기
- 하단에는 `오늘 확인할 포인트` 박스를 넣고 확인 액션 2개를 작성
```

## 3-6. Excel·CSV와 대시보드 비교
> 웹 대시보드는 보기 좋게 만드는 것보다 숫자가 원본과 맞는지 확인하는 단계가 더 중요합니다.
```plain text
실습파일/교육기관생산설비데이터_실습.xlsx와 조치우선순위_설비.csv에서 계산한 값이 hansol_equipment_dashboard.html의 KPI와 같은지 확인해줘.

확인할 값은 다음과 같아.
- 전체 로그 수
- 조치필요 건수
- 총 정지시간(h)
- 평균 가동률
- 공장별 총 정지시간
- 조치 우선순위 설비 Top 10

다르면 어떤 값이 다른지, 원인이 데이터 필터 문제인지 반올림 문제인지 구분해서 알려줘.
```

## 3-7. 실습: 대시보드를 현장 업무 도구로 바꾸기
> 지금까지 만든 HTML 대시보드는 출발점입니다. 여기서 한 단계 더 나아가면, 현장에서 반복적으로 확인하고 정리하는 일을 작은 웹앱이나 업무 도구로 바꿀 수 있습니다.





실습

현장 시나리오

도구로 바꿀 기능

확인할 결과




1. 조건을 직접 바꾸는 필터 도구 만들기

회의마다 위험 기준이 조금씩 달라집니다. 어떤 날은 가동률 85% 미만을 보고, 긴급 회의에서는 80% 미만만 봐야 합니다.

가동률 기준, 수율 기준, 정지시간 기준을 입력하면 조치 우선순위 목록과 KPI가 다시 계산되도록 수정합니다.

기준을 바꿨을 때 설비 목록, 조치필요 건수, 강조 행이 함께 바뀌는지 확인합니다.




2. 공장·라인·담당팀 선택 도구 만들기

공장장, 라인장, 정비팀장이 각자 자기 범위만 빠르게 보고 싶어 하는 상황입니다.

공장, 라인, 담당팀을 선택할 수 있는 필터를 추가하고 선택한 범위의 KPI, 차트, Top 10 표만 보여주게 만듭니다.

사용자가 선택한 조직 단위에 맞게 화면이 좁혀지고, 불필요한 데이터가 숨겨지는지 확인합니다.




3. 점검 체크리스트 도구 만들기

정비팀이 대시보드를 본 뒤 바로 점검 대상 목록을 들고 현장으로 나가야 하는 상황입니다.

조치 우선순위 설비 Top 10을 체크리스트 형태로 바꾸고, 설비별 `점검 전 / 점검 중 / 완료` 상태를 표시할 수 있게 만듭니다.

대시보드가 단순 조회 화면을 넘어 당일 점검 실행 목록으로 이어지는지 확인합니다.




## 3-8. 이런 도구를 만들 때 먼저 정할 것
> 앱이나 웹 도구를 만들 때 중요한 것은 기술 이름이 아니라, 사용자가 실제로 어떤 행동을 더 쉽게 하게 만들 것인지입니다. 화면을 만들기 전에 아래 질문을 먼저 정리합니다.





설계 질문

확인할 내용

예시




누가 쓰는 도구인가?

사용자의 역할과 관심 범위를 정합니다.

공장장, 라인장, 정비팀장, 품질 담당자




언제 쓰는 도구인가?

사용 시점과 긴급도를 정합니다.

아침 회의 전, 주간 정비계획 전, 품질 이슈 발생 직후




무엇을 선택하거나 입력해야 하는가?

필터, 기준값, 조회 범위를 정합니다.

공장, 라인, 담당팀, 가동률 기준, 수율 기준




무엇을 자동으로 계산해야 하는가?

도구가 대신 처리할 반복 계산을 정합니다.

KPI, Top 10, 총 정지시간, 에너지 효율, 점검 우선순위

점검 지시, 회의 보고, 지원 요청, 개선 과제 선정
