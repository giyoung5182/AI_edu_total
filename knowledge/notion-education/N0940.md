본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

# 0. 왜 이 업무를 골랐나
## 지금 어떻게 하고 있나
```plain text
① 각 부서에서 지출결의서를 작성해 총무팀으로 보냄
② 총무팀 담당자가 하나씩 열어서 확인
     · 규정 한도를 넘지 않았는지
     · 증빙이 첨부됐는지
     · 계정과목이 맞는지
③ 문제가 있으면 해당 부서에 연락해 보완 요청
④ 이상 없으면 결재 상신
⑤ 월말에 부서별·항목별로 집계해 보고
```
## 무엇이 번거로운가
```plain text
· 매주 20~30건을 하나씩 열어봐야 함
· 규정집을 다시 확인하는 일이 반복됨
· 같은 부서가 같은 실수를 반복하는데, 그걸 알아채려면 기억에 의존
· 월말 집계를 또 처음부터 함
```
**"열어서 → 기준과 대조 → 분류"의 반복입니다.** 에이전트가 잘하는 일의 전형적인 형태입니다.

# 1. 폴더 준비
## 폴더 구조
```plain text
총무팀_지출검토\
   ├─ data\
   │    ├─ 지출결의서_01_영업관리부_출장비.txt
   │    ├─ 지출결의서_02_구매팀_소모품.txt
   │    ├─ ... (총 12건)
   │    └─ 지출결의서_12_사무국_경조사비.txt
   ├─ 지출규정.txt          ← 판단 기준이 되는 문서
   └─ 부서목록.txt          ← 참조용
```
**두 가지가 필요합니다.**
```plain text
① 검토할 자료 (data 폴더)      — 여러 건이 쌓인 곳
② 판단 기준 문서               — 규정·매뉴얼·가이드
```
> **기준 문서가 없으면 에이전트가 판단할 근거가 없습니다.** 규정집이 종이로만 있다면, 핵심 조항만 텍스트로 정리해서 넣어도 충분합니다.

# 2. 에이전트 3개 설계 — 4축으로
**한 업무를 세 각도로 나눴습니다.**





에이전트

보는 각도

하는 일




**지출검토**

건별 판정

각 건이 규정에 맞는지 판정




**반복부서 점검**

패턴

같은 실수가 반복되는 부서 추출




**집계**

분포

부서별·항목별 금액 집계


## 왜 셋으로 나눴나
```plain text
하나로 다 시키면
  "규정 대조도 하고, 반복도 찾고, 집계도 해줘"
  → 한 에이전트가 12개 파일을 세 번 다르게 읽어야 함
  → 결과가 길어지고 정확도가 떨어짐

셋으로 나누면
  각자 자기 관점으로만 봄 → 결과가 깔끔하고 정확
  메인이 셋을 불러 합침
```
## 각 에이전트의 4축
**① 지출검토 에이전트**
```plain text
역할       지출결의서를 지출규정과 대조해 처리 구분을 판정
정보 범위   data 폴더의 지출결의서, 지출규정.txt
출력 형식   건별로 [승인가능 / 보완필요 / 규정초과 / 확인필요] 판정과 사유를 표로
페르소나   신중한 검토 담당자. 반려를 단정하지 않고 확인이 필요한 것은 확인필요로 둠
```
**② 반복부서 점검 에이전트**
```plain text
역할       같은 부서에서 반복되는 문제를 가려냄
정보 범위   data 폴더의 지출결의서
출력 형식   부서명 / 건수 / 반복 유형 / 주의 정도를 표로, 주의 정도가 높은 순
페르소나   책임을 묻지 않고 패턴만 짚는 관찰자
```
**③ 집계 에이전트**
```plain text
역할       부서별·항목별로 금액과 건수를 집계
정보 범위   data 폴더의 지출결의서
출력 형식   부서별 표 + 항목별 표, 금액 큰 순
페르소나   숫자만 다루는 정리 담당자. 계산 근거를 함께 표시
```

# 3. 에이전트 제작 — 실제로 넣은 프롬프트
## 3-1. 지출검토 에이전트
**폴더에서 ****`claude`**** 실행 후 아래를 붙여넣습니다.**
```plain text
지출검토 에이전트를 .claude/agents/ 폴더에 만들어줘.

[역할]
이 에이전트는 data 폴더의 지출결의서를 지출규정.txt와 대조해
건별로 처리 구분을 판정하는 역할을 담당한다.

[정보 범위]
작업 폴더 안의 data 폴더 지출결의서 파일들과 지출규정.txt를 읽고 참고한다.

[출력 형식]
결과는 표로 작성한다.
열은 문서번호 / 부서 / 항목 / 금액 / 판정 / 사유 로 한다.
판정은 아래 4개 중 하나로 한다.
- 승인가능: 규정 한도 내이며 증빙이 갖춰진 경우
- 보완필요: 증빙 누락이나 기재 미비로 추가 자료가 필요한 경우
- 규정초과: 규정 한도를 넘은 경우
- 확인필요: 기재 내용이 불충분해 판정이 어려운 경우

[페르소나 및 판단 기준]
- 신중한 검토 담당자. 단정 대신 근거로 판단한다.
- 자료에 없는 내용은 추측하지 말고 '확인 필요'로 표시한다.
- 최종 승인이나 반려를 확정하지 않고 1차 검토 의견으로 제시한다.
- 판정 근거가 되는 규정 조항을 사유에 함께 밝힌다.

'지출 검토', '지출결의서 검토', '지출 판정', '결의서 확인'과 같거나
비슷한 요청이 오면 반드시 이 에이전트가 쓰이도록 description을 작성해줘.
에이전트 이름(name)은 영어 소문자와 하이픈으로 만들어줘.
도구와 모델은 현재 실습 환경에 맞게 적절히 설정해줘.
disallowedTools에 'Agent'를 추가해줘.
```
**화면에서 일어난 일**
```plain text
① "파일을 만들어도 될까요?" → 1번(허용)
② expense-reviewer.md 파일이 .claude/agents/ 에 생성됨
③ 완료 메시지와 함께 파일 경로 표시
```
**초안이 나온 뒤 규칙 보정**
```plain text
좋아. 세 가지만 반영해줘.
금액이 애매하면 규정초과로 단정하지 말고 확인필요로 둬.
증빙 첨부 여부가 문서에 적혀 있지 않으면 '확인 필요'로 표시해.
최종 승인 여부는 판단하지 말고 1차 검토 의견만 내.
```
**→ ****`/exit`**** 후 ****`claude`**** 재실행**

## 3-2. 반복부서 점검 에이전트
```plain text
반복부서 점검 에이전트를 .claude/agents/ 폴더에 만들어줘.

[역할]
data 폴더의 지출결의서들 중에서 같은 부서에서 반복되는 문제를
가려내는 역할을 담당한다.

[정보 범위]
작업 폴더 안의 data 폴더 지출결의서 파일들을 읽는다.

[출력 형식]
결과는 표로 작성한다.
열은 부서 / 건수 / 반복 유형 / 해당 문서번호 / 주의 정도(높음·중간) 로 한다.
주의 정도가 높은 순으로 정렬한다.
반복이 없는 부서는 표에 넣지 않는다.
반복 유형 예: 증빙 누락 반복, 한도 초과 반복, 기재 미비 반복

[페르소나 및 판단 기준]
- 책임을 묻지 않고 패턴만 짚는 관찰자.
- 자료에 없는 내용은 추측하지 말고 '확인 필요'로 표시한다.
- 특정 부서를 비판하는 표현을 쓰지 않는다.
- 최종 조치를 결정하지 않고 점검 관점의 주의 신호만 제시한다.

'반복부서 점검', '반복 문제 확인', '주의 부서 정리'와 같거나
비슷한 요청이 오면 반드시 이 에이전트가 쓰이도록 description을 작성해줘.
에이전트 이름(name)은 영어 소문자와 하이픈으로 만들어줘.
도구는 모두 허용해줘. 모델은 Sonnet으로 해줘.
disallowedTools에 'Agent'를 추가해줘.
```
**→ ****`/exit`**** 후 ****`claude`**** 재실행**

## 3-3. 집계 에이전트
```plain text

[역할]
data 폴더의 지출결의서들을 부서별·항목별로 집계하는 역할을 담당한다.

[정보 범위]
작업 폴더 안의 data 폴더 지출결의서 파일들을 읽는다.

[출력 형식]
표 두 개를 만든다.
표 1 — 부서별: 부서 / 건수 / 합계 금액, 금액 큰 순
표 2 — 항목별: 항목 / 건수 / 합계 금액, 금액 큰 순
각 표 아래에 총 건수와 총 금액을 표시한다.

- 자료에 없는 금액을 추정하지 않는다.

에이전트 이름(name)은 영어 소문자와 하이픈으로 만들어줘.
도구는 모두 허용해줘. 모델은 Sonnet으로 해줘.
disallowedTools에 'Agent'를 추가해줘.
```

# 4. 하나씩 실행해보기 — 합치기 전에
**대시보드로 합치기 전에 각각을 따로 돌려봅니다.** 하나라도 이상하면 대시보드도 이상하게 나오기 때문입니다.
## 4-1. 지출검토만 실행
```plain text
지출검토 에이전트한테 data 폴더의 지출결의서들을 검토 맡겨줘.
지출규정.txt 기준으로, 건별로 판정과 사유를 표로 정리해줘.
```
**확인할 것**
```plain text
□ 12건이 모두 표에 들어왔는가
□ 판정이 4종 안에서만 쓰였는가
□ 사유에 규정 조항이 언급되는가
□ 금액이 애매한 건이 '확인필요'로 갔는가
```
## 4-2. 반복부서 점검만 실행
```plain text
반복부서 점검 에이전트한테 data 폴더의 지출결의서들을 점검 맡겨줘.
같은 부서에서 반복되는 문제를 표로 정리해줘.
```
**확인할 것**
```plain text
□ 반복이 있는 부서만 나왔는가 (반복 없는 부서가 섞이면 기준이 느슨한 것)
□ 어떤 유형이 반복인지 명시됐는가
□ 특정 부서를 비판하는 표현이 없는가
```
## 4-3. 집계만 실행
```plain text
지출집계 에이전트한테 data 폴더의 지출결의서들을 집계 맡겨줘.
부서별·항목별로 표를 만들어줘.
```
**확인할 것**
```plain text
□ 총 건수가 실제와 맞는가        ← 반드시 직접 세어 검산
□ 부서별 합계와 총합이 일치하는가
□ 금액이 불명확한 건이 따로 표시됐는가
```
> **여기서 문제가 나오면 지금 고치세요.** 대시보드는 세 결과를 합치는 것이라, 하나가 틀리면 전체가 틀립니다.

# 5. 종합 대시보드 만들기
## 5-1. 넣은 프롬프트
```plain text
이번 주 지출결의서 검토 현황을 종합 보고 대시보드로 만들어줘.

먼저 지출검토 에이전트로 data 폴더의 지출결의서들을 건별 검토하고,
다음 반복부서 점검 에이전트로 반복 문제가 있는 부서를 정리하고,
마지막으로 지출집계 에이전트로 부서별·항목별 금액을 집계해줘.

세 결과를 합쳐서, 한눈에 보는 HTML 대시보드 파일로 만들어줘.
- 맨 위에 총 건수와 총 금액을 큰 숫자로 보여줘
- 판정별 건수(승인가능·보완필요·규정초과·확인필요)를 요약해서 보여줘
- 건별 검토 결과를 표로 정리해줘
- 반복 문제가 있는 부서는 눈에 띄게 표시해줘
- 부서별·항목별 집계 표를 함께 넣어줘
- 맨 위에 생성 시각을 표시해줘
- 결과는 dashboard.html 파일로 저장해줘

원본 자료는 수정하지 말고 새 결과물 파일만 만들어줘.
자료에 없는 내용은 임의로 만들지 말고 '확인 필요'로 표시해줘.
금액 계산에 포함한 건수를 함께 표시해서 검산이 가능하게 해줘.
```

## 5-3. 실행하면 일어나는 일
```plain text
① 메인이 작업 계획을 세움
② 지출검토 에이전트 호출 → 12개 파일 읽음 → 판정 표 반환
③ 반복부서 점검 에이전트 호출 → 같은 파일 다른 각도 → 주의 목록 반환
④ 지출집계 에이전트 호출 → 금액 집계 → 집계 표 반환
⑤ 메인이 세 결과를 합쳐 HTML 작성
⑥ 파일 저장 여부 확인 → 1번(허용)
⑦ dashboard.html 생성 완료
```
**3\~5분 걸립니다.** 멈춘 것 같으면 `Ctrl + O`로 진행 상황을 확인하세요.

## 5-5. 검증 — 반드시 하세요
```plain text
□ 총 건수 12건이 맞는가          ← 폴더 파일 수와 대조
□ 판정별 건수 합이 12인가        ← 7+3+1+1 = 12
□ 부서별 합계의 총합이 총 금액과 같은가
□ 반복 부서로 표시된 곳이 실제로 반복인가  ← 원본 2건 열어서 확인
□ 한글이 깨지지 않았는가
□ 생성 시각이 표시됐는가
```
> **판정별 건수 합이 총 건수와 다르면** 어딘가 빠진 것입니다. "판정별 건수 합이 총 건수와 맞지 않아. 다시 확인해서 고쳐줘"라고 요청하세요.

## 세 관점을 고르는 요령
```plain text
관점 1 — 건별로 무엇을 판정할 것인가     (가장 기본)
관점 2 — 무엇이 반복되는지 보고 싶은가   (패턴)
관점 3 — 무엇을 세거나 합하고 싶은가     (분포·금액)

셋 다 필요 없으면 둘만 만들어도 됩니다.
```
## 판정 구분을 정하는 요령
```plain text
· 3~4개가 적당합니다. 너무 많으면 기준이 흐려집니다
· 반드시 "확인필요"에 해당하는 구분을 하나 넣으세요
  → 자료가 부족할 때 억지로 판정하는 것을 막습니다
· 각 구분이 무엇인지 한 줄로 쓸 수 있어야 합니다
  → 못 쓰면 에이전트도 판단하지 못합니다
```

# 8. 이 예시에서 얻을 교훈 세 가지
```plain text
① 합치기 전에 하나씩 돌려봐라
   대시보드는 결과를 합치는 것이라, 하나가 틀리면 전체가 틀립니다

② 숫자는 반드시 검산해라
   화면이 그럴듯해 보여도 집계가 틀릴 수 있습니다.
   "계산에 포함한 건수를 표시해줘"를 프롬프트에 넣으면 검산이 쉬워집니다

③ "이건 1차 검토 의견"이라는 문구를 넣어라
   다른 사람이 이 화면을 볼 때 AI 결과를 최종 결정으로
   오해하지 않게 하는 장치입니다
```
