## 이번 세션에서 할 일
지금까지 우리는 이 자료의 지시대로 만들었습니다.<br>대화하는 챗봇, 문서를 읽고 근거를 다는 검색,<br>여럿이 협업하는 에이전트 팀까지 전부 손에 있습니다.<br>이제 지시가 끝나고, 선택이 시작됩니다.
이번 세션은 세 개의 트랙 중 하나를 골라 진행합니다.
1. 트랙 1 — 자유주제: 만들고 싶은 것을 스스로 정해 만듭니다.
2. 트랙 2 — AI 게시판: AI 주민들이 스스로 글과 댓글을 쓰는 게시판을 만들고 관전합니다.
3. 트랙 3 — 함정 질문 챌린지: 출제된 문제 5문항을 풀도록 내 시스템을 개선합니다.

트랙은 하나만 고릅니다. 고르는 기준은 이렇습니다.<br>아이디어가 이미 있다 → 트랙 1.<br>멀티 에이전트가 제일 재미있었다 → 트랙 2.<br>검색과 근거의 정확도를 끝까지 밀어붙이고 싶다 → 트랙 3.<br>5분 안에 못 고르겠으면 트랙 2나 3을 권합니다.<br>정해진 절차가 있어 출발이 빠릅니다.

💡 세 트랙 공통의 시간 규칙은 하나입니다.<br>남은 시간의 절반이 지나면 기능 더하기를 멈추고,<br>지금까지 만든 것의 완주 확인으로 전환합니다.<br>미완성 기능 셋보다 완주하는 기능 하나가 강합니다.

### 막혔을 때의 기술 — 세 트랙 공통
구축 중 막히는 것은 사고가 아니라 기본값입니다.<br>대처 순서를 정해 두면 막힘이 짧아집니다.
1. 창①의 오류 로그를 복사해 창②에 붙여넣고 "이 오류를 해결해 주세요"라고 요청합니다.
2. 수정 요청이 엉키기 시작하면 `/clear` 후 현재 상태와 목표를 새로 설명합니다.
3. 같은 오류가 세 번 반복되면 그 기능을 빼거나 단순한 형태로 바꿉니다. 기능을 빼는 결정은 후퇴가 아니라 설계입니다.
4. 10분 이상 혼자 막혀 있지 않습니다. 손을 들어 강사를 부릅니다.

## 트랙 1. 자유주제
만들 것을 스스로 정하는 트랙입니다.<br>정하는 데에도 절차가 있습니다. 다섯 칸이면 설계가 끝납니다.
```plain text
① 해결할 일:   한 문장으로. "○○을 넣으면 ○○이 나온다"
② 입력 자료:   지금 이 자리에서 확보 가능한 것만
③ 원하는 출력: 이번 시간 안에 나올 크기로
④ 필요한 부품: 지금까지 만든 것 중에서 고릅니다
⑤ 팀 명단:    도구 하나에 담당 하나. 이름은 기능으로
              ("검색 담당" 좋음, "팀장" 나쁨)
```
다섯 칸을 채웠으면 강사에게 보여 확인을 받습니다.<br>확인 포인트는 ②의 확보 가능성과 ③의 크기, 두 가지입니다.<br>확인 후 아래 틀에 칸을 옮겨 담아 창②에 입력합니다.
**Claude Code 프롬프트**
```plain text
새 기능을 만듭니다. 기존에 만든 것을 재조합해 주세요.

[목표] (①을 씁니다)
[입력 자료] (②를 씁니다)
[결과물] (③을 씁니다)
[구성] (⑤를 씁니다)

[작업 방식]
전체를 한 번에 만들지 말고, 다음 순서로 하나씩 만들어
각 단계가 동작하는 것을 저와 확인한 뒤 넘어가 주세요.
1단계: 입력 화면과 뼈대
2단계: 기능을 하나씩 합류
3단계: 최종 결과물 화면
무료 한도 보호용 호출 간 대기도 유지해 주세요.
```
🔐 새 문서를 재료로 쓸 때는 공개된 소형 문서(수십 페이지 이내)만 사용합니다.<br>회사 자료, 개인정보가 담긴 문서는 쓰지 않습니다.<br>문서 내용이 처리 과정에서 외부로 전송된다는 사실을 기억하면 판단이 쉽습니다.

## 트랙 2. AI 게시판 — 풀어놓으면 무슨 일이 벌어지는가
지금까지의 에이전트들은 우리가 시킨 일을 했습니다.<br>이번에는 일을 시키지 않습니다.<br>성격이 다른 AI 주민들을 게시판에 입주시키고,<br>스스로 글을 쓰고 댓글을 달게 풀어놓은 뒤 관전합니다.
같은 모델이 세 줄짜리 성격 규칙 하나로<br>전혀 다른 인격처럼 행동하는 것,<br>그리고 지시받지 않은 AI들 사이에서<br>예상 못 한 대화가 태어나는 것을 눈으로 봅니다.
### 게시판의 규칙
```plain text
주민의 한 턴:
  게시판의 글 제목들을 읽는다
   → 글이 하나도 없으면 그 사실을 인식하고 첫 글을 쓴다
   → 관심 가는 글이 있으면 열어 읽고 댓글을 단다
   → 댓글에 답하고 싶으면 대댓글을 단다
   → 내키지 않으면 이번 턴은 지나간다

제한:
  글은 1,000자, 댓글은 100자 이내
  글과 댓글의 합계가 100건이 되면 프로그램 종료
```
⚠️ 종료 조건이 없는 자율 시스템은 정의상 영원히 돕니다.<br>100건 상한과 \[정지\] 단추가 이 게시판의 멈춤 장치입니다.
### 주민 카드 10종
각 카드는 이름, 말투 규칙, 자주 쓰는 표현, 행동 성향으로 구성됩니다.<br>이 중 5명을 골라 입주시킵니다. 어떤 5명을 뽑느냐가 게시판의 분위기를 정합니다.
```plain text
① 출처장인   말투: 주장마다 근거나 출처를 함께 답니다.
             확인 안 된 정보에는 꼭 짚고 넘어갑니다.
             표현: "출처 있을까요?" "제가 찾아보니" "정확히는 이렇습니다"
             성향: 댓글 위주. 정보성 글에 우선 반응.

② 반박러     말투: 어떤 글이든 반대 논거부터 찾습니다.
             첫마디가 거의 항상 "근데"로 시작합니다.
             표현: "근데 그건 좀" "반대로 생각하면" "꼭 그럴까요?"
             성향: 댓글·대댓글 위주. 동의 여론이 형성된 글에 뛰어듦.

③ 사연러     말투: 무슨 주제든 자기 경험담으로 시작해 길게 씁니다.
             결론보다 과정이 깁니다.
             표현: "제가 예전에" "저만 그런가요" "얘기하자면 긴데"
             성향: 새 글 작성 위주.

④ 눈팅러     말투: 거의 나타나지 않다가 한 줄만 남깁니다.
             짧지만 핵심을 찌릅니다.
             표현: "그래서 결론은?" "둘 다 맞는 말" "지나가다 한마디"
             성향: 지나가기가 기본값. 열 턴에 한두 번만 활동.

⑤ 화제전환러 말투: 대화가 뜨거워지면 슬쩍 딴 얘기를 꺼냅니다.
             본인은 자연스럽다고 생각합니다.
             표현: "그건 그렇고" "갑자기 생각났는데" "딴 얘기지만"
             성향: 댓글 많은 글에 새 화제 댓글, 또는 새 글.

⑥ 질문러     말투: 답 대신 질문만 남깁니다. 질문이 꼬리를 뭅니다.
             표현: "왜 그런 걸까요?" "다들 어떻게 생각하세요?" "그럼 이건요?"
             성향: 댓글 위주. 모든 글에 고르게 반응.

⑦ 중재러     말투: 의견이 갈리면 양쪽 다 일리 있다고 정리합니다.
             갈등을 못 견딥니다.
             표현: "둘 다 일리 있는 게" "정리하자면" "싸우지 마시고"
             성향: 대댓글 위주. 반박러가 활동한 자리에 나타남.

⑧ 옛날사람   말투: 뭐든 과거와 비교하며 시작합니다.
             요즘 것에 대한 애정 어린 잔소리가 섞입니다.
             표현: "예전에는 말이야" "요즘 친구들은" "그때가 좋았지"
             성향: 새 글과 댓글 반반.

⑨ 신기술맹신러 말투: 모든 문제의 답이 AI와 최신 기술이라고 믿습니다.
             안 물어봐도 도구를 추천합니다.
             표현: "그거 AI로 되는데" "요즘 누가 그걸 손으로" "신기술 하나 소개하자면"
             성향: 새 글 작성 위주. 고민 글에는 해결책 댓글.

⑩ 팩폭러     말투: 감정 배려 없이 숫자와 사실만 말합니다.
             짧고 건조합니다.
             표현: "팩트만 말하면" "숫자로 보면" "냉정하게"
             성향: 댓글 위주. 사연러와 옛날사람의 글에 자주 나타남.
```
### 실습 1. 게시판 구축과 입주
작업 시작 전에 창②에서 `/clear`를 실행합니다.
**Claude Code 프롬프트**
```plain text
AI 주민들이 스스로 활동하는 게시판을 만들어 주세요. 요구사항입니다.

1. /board 경로에 게시판 페이지를 만들어 주세요.
   글 목록, 글 본문, 댓글, 대댓글이 트리로 보이는 구조입니다.
   글마다 작성자 이름과 시각이 붙습니다.

2. AI 주민 5명이 순번을 돌며 활동합니다. 각 주민의 성격은
   제가 다음 메시지로 드리는 주민 카드를 따릅니다.
   [주민 5명 선정]

3. 주민 한 명의 턴은 호출 한 번으로 처리해 주세요.
   Gemini(gemini-2.5-flash)에 현재 게시판 상태(글 제목 목록과
   최근 글·댓글 내용)와 그 주민의 카드를 주고, JSON 하나로
   행동을 받습니다: {행동: 새글|댓글|대댓글|패스,
   대상 글/댓글 번호, 내용}.
   게시판에 글이 하나도 없으면 그 사실을 알려 주어,
   주민이 첫 글을 쓸 수 있게 해 주세요.

4. 제한 규칙입니다.
   - 글은 1,000자, 댓글과 대댓글은 100자 이내로 지시하고,
     넘으면 서버에서 잘라 주세요.
   - 글과 댓글의 합계가 100건이 되면 활동을 종료하고
     "게시판 활동 종료" 안내를 표시해 주세요.
   - 호출 사이에 3초 대기를 넣어주세요.

5. 화면 하단에 [활동 시작]과 [정지] 단추를 두고,
   정지는 진행 중에도 즉시 동작해야 합니다.
   새 글과 댓글이 몇 초 안에 화면에 반영되게 해 주세요.

6. 서버 로그에 턴마다 한 줄(주민 이름, 행동, 대상)이 남게 해 주세요.
```
프롬프트 입력 후, 주민 카드 10종에서 5명을 골라<br>카드 내용을 그대로 복사해 창②에 전달합니다.
**진행 순서**

1. 서버를 재시작하고 /board 페이지를 엽니다.<br>2. \[활동 시작\]을 누르고 화면에서 손을 뗍니다.<br>3. 첫 장면을 확인합니다. 빈 게시판을 인식한 주민이 첫 글을 씁니다. 누가 먼저 썼고 어떤 주제를 골랐는지 봅니다.<br>4. \[예측\] 다음 턴의 주민이 이 글에 댓글을 달지, 새 글을 팔지 예측해 적습니다.<br>5. 관전합니다. 반박러가 시비를 걸고 중재러가 말리는 순간, 화제전환러가 흐름을 끊는 순간을 찾아 메모합니다.<br>6. 흥미로운 대화 하나를 골라, 창①의 로그에서 그 턴의 기록을 찾아 화면과 짝지어 봅니다.<br>7. 100건 종료 또는 \[정지\]로 마칩니다.

### 실습 2. 개입과 교체
**Claude Code 프롬프트 (개입 기능)**
```plain text
게시판에 제가 직접 참여하는 기능을 추가해 주세요.
글 작성칸과 댓글 입력칸을 두고, 제가 쓴 글과 댓글도
주민들의 다음 턴에서 게시판 상태로 전달되어
주민들이 반응할 수 있게 해 주세요.

```
내가 단 댓글에 반박러가 시비를 걸어오는 순간이<br>이 트랙의 정점입니다. 우리도 이 시스템의 참여자입니다.
**페르소나 공장 (주민 교체·증원용 프롬프트)**
```plain text
다음 형식으로 게시판 주민 카드 3개를 새로 만들어 주세요.
형식: 이름 / 말투 규칙 2줄 / 자주 쓰는 표현 3개 / 행동 성향 1줄
조건: ___
```
조건 칸에 자기 아이디어를 넣습니다.<br>"우리 회사에 있을 법한 유형으로", "정반대 성격 셋으로" 같은 식입니다.
**FAQ.**
- **증상: 429 에러**
- **원인:** 호출 간격 부족
- **해결:** 창②에 "호출 사이 대기를 늘려 주세요"라고 요청합니다.
- **증상: 주민들이 새 글만 쓰고 댓글을 안 닮**
- **원인:** 게시판 상태 전달 누락
- **해결:** 창②에 "턴마다 기존 글과 댓글 내용이 프롬프트에 들어가는지 확인해 주세요"라고 요청합니다.
- **증상: 같은 주민만 계속 활동**
- **원인:** 순번 로직 오류
- **해결:** 창②에 "주민 순번이 공평하게 도는지 점검해 주세요"라고 요청합니다.
- **증상: 글자 수 초과**
- **원인:** 지시 미준수
- **해결:** 정상 범위입니다. 서버 측 잘라내기가 동작하는지 확인합니다.
- **증상: 정지가 안 먹힘**
- **원인:** 중단 처리 누락
- **해결:** 창①에서 Ctrl+C로 서버를 끄고, 창②에 정지 단추 수리를 요청합니다.

## 트랙 3. 함정 질문 챌린지 — 출제된 문제를 푼다
실제로 상금 1,000만 원이 걸렸던 AI 경진대회가 있습니다.<br>문서를 근거로 질문에 정확히 답하는 시스템을 겨루는 대회였고,<br>참가자들을 괴롭힌 것은 표 속에 숨은 정답,<br>비슷해서 헷갈리는 항목, 조각 사이에 걸친 답이었습니다.
그 문제 유형을 새 문서 한 부에 옮겨 다섯 문항을 출제했습니다.<br>문서는 「2026년 6월 소비자물가동향」(국가데이터처)입니다.<br>비슷한 지수가 밀집하고, 큰 표가 이어지고,<br>모든 숫자가 두 가지 비교 기준을 갖는 —<br>함정 출제에 이상적인 문서입니다.
정답은 문제지에 공개되어 있습니다.<br>정답을 아는 것은 아무 도움이 되지 않기 때문입니다.<br>정답을 말해야 하는 것은 내가 아니라 내 시스템입니다.
### 미션 정의
**목표**: 문제지 5문항 중 4문항 이상에서 \[답 정합\]과 \[근거 정합\]을 동시에 만족시켜라.
- 답 정합: 챗봇의 답이 정답 카드와 맞습니다. 핵심 요소가 빠짐없이 담기고, 틀린 값이 없어야 합니다.
- 근거 정합: 답변에 표시된 근거 청크를 펼쳤을 때, 그 안에 정답의 내용이 실제로 들어 있어야 합니다. 답은 맞는데 엉뚱한 청크가 근거면 실패입니다.
**특별 판정**
- 환각 유도 문항: "문서에서 확인되지 않습니다" 계열의 답이 통과입니다.
- 이중 기준 문항: 두 기준의 존재를 구분해 답하면 통과입니다. 한 값만 단정하면, 어느 기준의 값인지 명시한 경우에만 통과입니다.
**허용 수단** — 전부 이미 배운 것들입니다.<br>청킹 전략 교체와 재적재, K값 조정, 답변 프롬프트 강화(근거 제한·인용·표 처리 지시), 파싱 보강 요청, 검색 방식 점검·조정.
**반칙** — 아래 세 가지는 통과로 인정하지 않습니다.
1. 질문 문구를 바꾸는 것. 문제지의 질문을 토씨 하나 바꾸지 않고 그대로 입력합니다. 고칠 대상은 질문이 아니라 시스템입니다.
2. 정답을 심는 것. 정답 문장을 프롬프트, 문서, 코드 어디에도 넣지 않습니다.
3. 문항 전용 장치를 만드는 것. "이 질문이 오면 이렇게 답하라"는 분기는 반칙입니다. 비슷한 다른 질문에도 통할 일반적인 개선만 인정합니다.
### 사전 준비 — 문서 교체 적재

[첨부 원본 제외: 파일 권리·개인정보 확인 전입니다.]


1. 배부받은 「2026년 6월 소비자물가동향」 PDF를 docs 폴더에 넣습니다.<br>2. 문서 처리 페이지에서 기존 적재를 비우고 이 문서를 적재합니다.<br>3. 적재 현황에서 청크 수가 0이 아닌 것을 확인합니다.<br>4. 채팅방에서 가벼운 질문 하나("6월 소비자물가지수는 몇 % 상승했나요?")를 던져 근거 청크가 달린 답이 오는지 확인합니다.

### 문제지
질문은 그대로 복사해 입력합니다.
**문항 1. \[표 속 정답\]**
- 질문: 6월 석유류의 전년동월대비 상승률은 몇 %인가요?
- 정답: 24.7%.
- 근거 위치: \<품목성질별 등락률 및 기여도\> 표의 (석유류) 행
- 노리는 약점: 이 값은 표 안에만 있습니다. 본문에는 휘발유(23.1), 경유(33.7), 등유(23.1)가 노출되어 있어, 표가 파싱에서 무너지면 이웃 숫자가 답으로 올라옵니다.
**문항 2. \[유사 항목 혼동\]**
- 질문: 6월 농산물및석유류제외지수는 전년동월대비 몇 % 상승했나요?
- 정답: 2.4%.
- 근거 위치: 요약 또는 본문 1절 \<월별 농산물및석유류제외지수 동향\>
- 노리는 약점: 식료품및에너지제외지수(2.5%)가 문서 전체에서 항상 바로 옆에 붙어 다닙니다. 검색과 생성 모두 2.5%를 집어 오기 쉽습니다.
**문항 3. \[조각 경계\]**
- 질문: 지출목적별 12개 부문 중 6월 전월대비 하락한 부문 세 곳과 각각의 하락률은 무엇인가요?
- 정답: 교통 -0.6%, 오락·문화 -0.2%, 통신 -0.1%. 세 부문과 수치가 모두 담겨야 답 정합입니다.
- 근거 위치: 본문 2절 지출목적별 동향
- 노리는 약점: 상승 부문 나열이 길어 하락 3개가 문단 끝자락에 몰려 있습니다. 청크 경계가 문장을 자르면 반쪽 답이 나옵니다.
**문항 4. \[이중 기준\]**
- 질문: 이 문서에서 소비자물가지수의 기준연도는 몇 년인가요?
- 정답: 이 문서에는 기준이 둘로 실려 있습니다. 지수의 기준연도는 2020년, 가중치의 기준연도는 2022년입니다. 두 기준을 구분해 답하면 통과입니다.
- 근거 위치: 문서 앞부분 일러두기
- 노리는 약점: 부록에는 "기준연도 2020년=100"만 다시 등장합니다. 부록 청크가 상위에 잡히면 시스템이 2020년을 단정합니다.
**문항 5. \[환각 유도\]**
- 질문: 이 문서 기준, 6월의 체감물가상승률은 몇 %인가요?
- 정답: 문서에서 확인되지 않습니다. (체감물가가 총지수와 다른 이유는 설명되어 있으나, 체감물가상승률이라는 수치는 없습니다.)
- 노리는 약점: "체감물가"라는 단어가 문서에 실재하고, 보조지표로 생활물가지수(3.4%)가 소개됩니다. 근거 제한이 약하면 3.4%를 체감물가상승률로 둔갑시킵니다.
### 실패의 진단 — 세 갈래
틀린 문항을 고치기 전에, 왜 틀렸는지부터 가립니다.<br>방법은 하나뿐입니다. 답변에 달린 근거 청크를 펼쳐 읽는 것.
```plain text
증상 A. 엉뚱한 청크가 근거로 잡혔다
        → 찾기의 문제. 처방: 검색 방식 점검, K값 조정, 청킹 교체
증상 B. 맞는 자리의 청크인데 내용이 깨져 있다
        → 조각의 문제. 처방: 청킹 교체, 파싱 보강 요청
증상 C. 근거가 빈약한데 답은 그럴듯하다
        → 지시의 문제. 처방: 답변 프롬프트의 근거 제한·인용 강화
```
증상이 겹치면 A → B → C 순서로 하나씩 처방합니다.<br>찾기가 안 되면 조각을 고쳐도 소용없고,<br>조각이 깨졌으면 지시를 조여도 소용없기 때문입니다.
### 진행 순서

1. \[기준선\] 지식 기반 답변 모드를 켜고 5문항을 순서대로, 문구 그대로 입력합니다. 문항마다 기록합니다: 통과/실패, 실패면 증상 A/B/C. 판정은 반드시 근거 청크를 펼쳐서 합니다.<br>2. \[예측\] 실패 문항마다 처방을 하나 고르고, "이 처방이면 몇 번이 살아난다"를 예측해 적습니다.<br>3. \[처방은 한 번에 하나\] 처방 하나를 적용합니다. 청킹·파싱을 건드렸으면 재적재까지 합니다.<br>4. \[재측정\] 실패했던 문항만 다시 입력해 판정하고 예측과 비교합니다. 통과였던 문항이 무너지지 않았는지도 봅니다.<br>5. 3\~4를 반복합니다. 4문항에 도달하면 5문항 전체를 처음부터 한 번 더 돌려 최종 점수를 확정합니다.<br>6. \[기록 마감\] 최종 점수와 가장 효과가 컸던 처방 하나를 한 줄로 남깁니다.

기록은 라운드마다 한 줄이면 충분합니다.
```plain text
라운드 0 (기준선): ①실패B ②실패A ③통과 ④실패A ⑤실패C → 1/5
라운드 1 (처방: 표 보존 파싱 재적재): ①통과 ②실패A ④실패A ⑤실패C → 2/5
라운드 2 (처방: ...): ...
```
💡 "한 번에 하나"가 이 챌린지의 핵심 기술입니다.<br>처방 여럿을 섞으면 무엇이 통했는지 알 수 없게 됩니다.<br>수정과 측정을 짝지어야 개선과 개악을 가릴 수 있습니다.
**FAQ.**
- **증상: 검색 결과가 세 열 모두 비어 있음**
- **원인:** 벡터DB가 비어 있음
- **해결:** 문서 처리 페이지의 적재 현황을 확인합니다. 0개면 문서를 다시 적재합니다.
- **증상: 키워드 검색 열만 결과 이상**
- **원인:** 형태소 분석기 미적용
- **해결:** 창②에 "BM25 토큰화에 kiwipiepy가 쓰이고 있는지 확인해 주세요"라고 요청합니다.
- **증상: 형태소 분석기 설치 실패**
- **원인:** 환경 문제
- **해결:** 창②에 오류 로그를 붙여넣고 해결을 요청합니다. 해결이 늦어지면 강사에게 알립니다.
- **증상: 점수가 열마다 자릿수가 다름**
- **원인:** 정상
- **해결:** BM25 점수와 유사도 점수는 계산법이 달라 범위도 다릅니다. 열 안에서의 순위만 비교하면 됩니다.
