# 7️⃣ 세션 7 · 고도화 & 시연 준비 — 발표까지 완성

정리일: 2026-10-08 · 교육 에셋 N1595

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

**세션 목표:** 앞에서 만든 도우미를 조금 더 똑똑하게 다듬고, 짧고 인상적인 시연 시나리오를 만들어 **발표를 준비**합니다. (발표는 각자 자기 프로젝트로, 세션 4\~7에서 만든 조각을 이어 붙이면 됩니다.)

**쉽게:** "고도화" = **더 좋게 다듬기**, "데모/시연" = **그 자리에서 직접 돌려 보여주기**. 새 기능을 크게 붙이는 게 아니라, 규칙 한두 개를 더해 결과를 한 단계 매끄럽게 만드는 정도면 충분합니다.

### 📖 개념: 좋은 시연은 스토리가 있다
**데모의 구조 (짧고 굵게)**
- 상황 — "저는 이런 문제가 있었습니다"
- 입력 — "이런 데이터를 넣으면"
- 결과 — "이런 결과가 나옵니다"
- 액션 — "이제 이렇게 활용할 수 있습니다"
[원본 이미지 제외]

**대사 예시**: "저는 매주 협력사 10곳 견적을 일일이 비교하는데 4시간이 걸렸습니다. (입력) 이 엑셀 파일을 넣으면 → (결과) 30초 만에 자동 비교표가 나옵니다. 이제 이 시간을 협상에 쓸 수 있습니다."


**Padlet에 올리기** (`세션7 · 발표 준비`) — "내 솔루션이 도입되면 바뀌는 점 + 숫자로 표현한 절감 효과"를 올려주세요. 이게 **발표의 ④ 활용·기대효과**이자 마지막 슬라이드 문구가 됩니다.

<summary>옵션 A: 기준값 룰 적용</summary>
```plain text
분석 결과에 다음 기준값 룰을 추가해줘:
- [예: 지연일이 3일 이상이면 "긴급" 표시]
- [예: 비용 초과율이 10% 이상이면 "검토 필요" 태그]
- [예: 같은 사유로 이번 달 3회 이상 발생하면 "반복 이슈" 경고]
```
</details>
<details>
<summary>옵션 B: 우선순위 정렬 추가</summary>
```plain text
결과 테이블에 우선순위 정렬을 추가해줘.
기준: 1순위 영향도↑+긴급도↑ / 2순위 영향도↑+긴급도↓ / 3순위 영향도↓+긴급도↑ / 4순위 영향도↓+긴급도↓
각 항목의 우선순위를 "P1/P2/P3/P4"로 표시하고 정렬해줘.
```
</details>
<details>
<summary>옵션 C: 자동 질문 리스트 생성</summary>
```plain text
분석 결과를 바탕으로 논의해야 할 핵심 질문 리스트를 자동 생성해줘.
형식: [즉시 확인] 질문 3개 / [이번 주 내] 검토 3개 / [이번 달 내] 개선 검토 2개
```
</details>
<details>
<summary>옵션 D: 비교 인사이트 추가</summary>
```plain text
지난 번 분석 결과와 이번 분석 결과를 비교해줘.
[지난 번 분석 요약 또는 수치를 여기에 붙여넣기]
- 개선된 부분: / - 악화된 부분: / - 주목해야 할 변화:
표와 한 줄 코멘트 형식으로 정리해줘.
```
비교할 지난 데이터가 없다면, 세션 6 활동 2에서 테스트했던 결과를 "지난 번 결과"로 활용하세요.

**🔥 활동 3 — 발표 이미지 만들기**
```javascript
내가 만든 AI 솔루션을 짧고 임팩트 있게 발표할 수 있도록 소개하는 이미지를 만들어줘.
발표 내용: [이름·직무 / 해결한 문제 / 만든 솔루션 / 주요 기능 / 기대 효과]
요구사항: 문제→솔루션→기대효과 순서, 큰 글씨·넉넉한 여백
```
**🔥 활동 3-1 — 발표 슬라이드 HTML 만들기**
라이브 데모 전후에 핵심을 한 장으로 보여주고 싶다면, 아래 프롬프트로 슬라이드 1장을 HTML로 만들어 브라우저 탭에 열어두세요.
```javascript
아래 발표 시나리오 내용을 바탕으로, 발표용 슬라이드 1장을 HTML 파일로 만들어줘.
발표 내용: [이름·직무 / 해결한 문제 / 만든 솔루션 / 주요 기능 / 기대 효과]
요구사항: CSS 포함 단일 HTML 파일, 문제→솔루션→기대효과 순서, 큰 글씨·넉넉한 여백,
스크린샷/표 대신 핵심 메시지와 숫자만 크게. 파일명은 "발표슬라이드_[이름].html".
```
**📌 세션 7 핵심 정리**
① 고도화는 "기준값 룰"과 "우선순위 정렬"만 추가해도 실용성이 크게 높아진다.
② 발표는 기능 설명이 아니라 "문제 → 해결" 스토리로 구성한다.
③ 짧은 데모일수록 입력부터 결과까지 한 번에 보여주는 것이 핵심이다.

## 📊 발표 — 추첨으로, 시간 되는 만큼
발표는 **각자 자기 프로젝트**를 보여주는 자리입니다. 세션 4\~7에서 만든 네 조각을 그대로 이어 붙이면 되므로, 따로 준비할 게 없습니다.
**발표 = 세션에서 만든 조각 이어 붙이기**
- ① 상황·문제 (세션 4) → ② 데모 입력 (세션 5) → ③ 결과 (세션 6) → ④ 활용·기대효과 (세션 7)
- 여기에 활동 3의 발표 대본과 활동 3-1의 슬라이드 1장을 더하면, 그 자리에서 에이전트를 돌려 보이는 **라이브 데모**가 완성됩니다.
**진행 방식**
- 전원이 순서대로 발표하면 시간이 오래 걸리므로, **추첨으로 뽑아 시간이 허락하는 만큼만** 시연합니다.
- 뽑힌 사람은 슬라이드 → 라이브 데모(입력 → 결과) → 기대효과 순으로 짧게 보여줍니다. 혼자가 부담되면 팀원이 옆에서 거들어도 됩니다.
- 발표에 걸리지 않아도 모든 결과물이 이미 Padlet에 올라와 있어 **그 자체로 공유·제출이 끝난 상태**입니다.

**리허설**: 추첨 전에 팀 안에서 각자 한 번씩 짧게 데모를 돌려보면, 실제로 뽑혔을 때 훨씬 매끄럽습니다.
