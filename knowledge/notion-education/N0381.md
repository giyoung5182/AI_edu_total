# 실습 2 — 담당 업무 발표자료 설계서 1종 쓰기

정리일: 2026-10-08 · 교육 에셋 N0381

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
담당 업무 자료로 발표자료 설계서(4블록) 1종을 완성한다.
## 진행 단계
1. **자료 준비 (2분)** — 최근 작성한 사업 계획, 실적 정리, 회의 결과 등 담당 업무 자료 1건. 외부 공개가 안 되는 정보는 미리 제거
2. **초안 생성 (4분)** — 4-9의 초안 생성 프롬프트에 자료를 붙여 넣고 실행
- 입력할 내용:
```plain text
아래 자료를 읽고, 발표자료 설계서 초안을 작성해 줘.
아직 슬라이드는 만들지 말고 설계서 텍스트만 줘.

설계서는 네 블록으로 구성해 줘.
블록 1 맥락: 개요, 유의사항 3개 이상, 최종 목적, 전체 흐름
블록 2 슬라이드 설계도: 각 장마다 분류 / 헤드메시지 / 내용 설명 / 시각 요소.
       표가 아니라 줄글로 서술해 줘
블록 3 디자인 규격: 색상 코드, 글꼴, 크기, 레이아웃 규칙
블록 4 산출 규칙: 말투, 사실 관계, 구성, 재량

조건
- 슬라이드는 총 [○]장
- 헤드메시지는 주제어가 아니라 결론이 담긴 완성 문장으로
- 자료에 없는 수치는 절대 추가하지 말고 [확인 필요]로 표시
- 유의사항 항목은 이 자료의 특성을 근거로 직접 판단해서 써 줘

[자료]
(사업 공고문, 실적 데이터, 회의 메모 등을 붙여넣으세요)
```
3. **검토·수정 (6분)** — 유의사항(청중 특성을 사람이 직접 채우기) / 헤드메시지(순서대로 읽어 논리가 이어지는지) / ［확인 필요］(어디에 구멍이 있는지 파악)
4. **디자인 규격 (1분)** — 블록 3에 기관 색상 코드 입력
5. **저장 (2분)** — 완성된 설계서 저장 (오늘의 진짜 산출물은 슬라이드가 아니라 설계서)
- 정상 결과(완료 기준): 네 블록이 모두 채워짐 / 유의사항 3개 이상 / 모든 헤드메시지가 결론 문장 / 헤드메시지만 읽어도 논리가 이어짐 / 자료에 없던 수치가 새로 생기지 않음 / 색상 코드 포함 / 파일로 저장
## 막히는 지점
- 설계서 쓰는 데 시간이 더 걸리면: 매번 처음부터 작성하지 말고 4-9로 초안 생성, 3권 부록 B Gem 활용
