**이번 PART에서는**, 어제 고른 과제를 오늘 만들 수 있는 크기로 좁히고, 네 칸짜리 명세로 확정합니다. 완성 기준도 미리 정합니다. 오늘 오후 만들 것의 설계도를 완성하는 시간입니다.

## 시작하기 전에

만들고 나서 설명을 붙이면 "왜 이렇게 만들었더라"가 됩니다. 그리고 무엇보다 끝나는 지점이 없어집니다. 결과물을 보면 늘 고칠 곳이 보이고, "조금만 더 다듬으면…"이 반복되면서 시간이 통째로 사라집니다. 그래서 순서를 뒤집습니다. **무엇이 되면 끝인지를 먼저 적고, 그다음에 만듭니다.** 앞에서 "AI가 헤매지 않도록 조건을 좁혀 주는 것이 우리 몫"이라고 했습니다. 이 PART가 그 작업입니다.

### 이 PART에서 하는 것
- 만들 값어치가 있는지 **판단**하기
- 오늘 안에 끝낼 수 있게 **범위 좁히기**
- **명세 네 칸** 채우기 - 목적 · 입력 · 출력 · 제약
- **완성 기준 다섯 개** 미리 정하기

**오전에는 명세 없이 15분 만에 화면을 만들었는데, 왜 지금은 번거롭게 명세를 쓸까요.** 오전 것은 감을 잡는 것이 목적이었고 만들고 끝났습니다. 지금 만드는 것은 회사에 가져가서 다음 주에도 쓸 도구입니다. 그러려면 명세 · 데이터 · 결과물 · 백업이 한 폴더에 남아야 이어집니다. 그리고 명세를 쓰면 왕복 횟수가 줄어듭니다 - 명세 없이 만들면 「만들고 → 보고 → 고치고」를 여러 번 반복하고, 명세를 쓰면 그 왕복을 앞으로 당겨와 한 번에 끝납니다.

**오늘 쓰는 것은 PRD를 한 장으로 줄인 것입니다.** 혼자 쓸 도구를 만드는 데 정식 PRD는 과합니다. 대상 사용자는 나 혼자이고, 일정은 지금이고, 배경은 이미 알고 있습니다. 그래서 빠지면 결과가 틀리는 네 칸만 남겼습니다.

**줄글로 적으면 무엇이 빠졌는지 스스로 알 수 없습니다.** 네 칸으로 나눠 적으면 비어 있는 칸이 바로 눈에 띕니다. 그리고 빈 칸을 채우는 과정에서 "그러면 값이 없을 땐 어떻게 하지"를 스스로 묻게 됩니다.

### 칸 ① 목적
이 도구가 어떤 업무를 대신하는지 한 문장으로 적습니다. "캠페인 관리를 편하게"가 아니라 "**캠페인별 진행 단계를 넣으면 전체 진척률과 지연 건이 나온다**"처럼 씁니다. 두 문장이 되면 도구를 둘로 나눠야 합니다. "\~를 넣으면 \~가 나온다" 구조가 쓰기 쉽습니다.
### 칸 ② 입력
무엇을 넣는지 적습니다. 형식과 범위까지 적어야 합니다. "조건들"이 아니라 실제 항목명으로, 값의 범위와 단위까지 함께 적어야 확인 조건이 나옵니다.
```javascript
항목 6개
코드명 / 매체 / 예산(원) / 담당 / 마감일 / 진행단계
진행단계는 5종 - 기획 · 제작 · 검수 · 승인 · 집행
```
### 칸 ③ 출력
무엇이 나와야 하는지, 어떤 순서로 보이는지, 표라면 열 이름과 순서까지 적습니다. 값의 자릿수와 단위 표기도 여기서 정합니다.
```javascript
① 전체 요약 - 전체 건수 / 진행중 / 완료 / 지연
② 캠페인 표 - 코드명 · 매체 · 예산 · 담당 · 단계 · 상태
③ 확인 필요 목록 - 값이 비어 있는 항목만
금액은 천 단위 쉼표, 숫자는 오른쪽 정렬
```
### 칸 ④ 제약

**네 칸 중 결과의 신뢰도를 결정하는 칸이면서, 가장 자주 비는 칸입니다.** 만들고 싶은 것은 머릿속에 있지만 안 되는 경우는 생각해 본 적이 없습니다. 그런데 실제 자료에는 안 되는 경우가 반드시 섞여 있습니다. 제약이 비면 그 부분을 AI가 알아서 처리하고, 문제가 화면에 드러나지 않습니다 - 앞에서 배운 조용한 실패입니다.

제약 칸에 넣을 것: 빈 값 처리 방법 · 잘못된 값 처리 방법 · 계산 불가 상황 · 화면 표시 방식.
여기에 **두 줄을 더 붙이면 결과가 눈에 띄게 달라집니다.**





추가할 줄

없으면 생기는 일




내가 준 사실만 쓰고, 전달하지 않은 것은 만들지 않는다

빈 칸을 그럴듯한 값으로 채우고, 그렇게 했다고 말해주지 않습니다




참고할 것과 참고하지 않을 것을 적는다

어디서 가져왔는지 모를 문구·이미지가 섞입니다



참고 범위는 이런 식으로 씁니다 - 「○○ 페이지는 **배치와 여백의 분위기만** 참고하고 문구나 이미지는 복제하지 마. 열 수 없으면 앞서 정한 설명을 따라줘.」 무엇을 참고할지만 적으면 어디까지 참고할지는 AI가 정합니다.

```javascript
- 예산이 비어 있으면 0으로 채우지 말고 「미입력」으로 둔다.
- 마감일이 오늘보다 이르면서 완료가 아니면 지연으로 표시한다.
- 클라이언트 실명과 계약 금액은 화면에 넣지 않는다.
```
### 얼마나 구체적으로 적어야 하나





흐린 명세

계산식과 기준까지 적은 명세




「진행 상황 보여주는 화면」 - 무엇을 어떻게 세는지 없음, 지연 기준이 없음, 예외 처리가 없음

**진척률 = 완료 단계 수 ÷ 전체 단계 수 / 지연 = 마감일 경과 + 완료 아님 / 예산 빈 값은 미입력으로 표시**  • 그대로 지시문이 됨, 확인 기준이 명확, 예외 동작이 정의됨

## Step 04 :: 명세를 AI가 되묻게 합니다.

**네 칸이 잘 채워지지 않을 때 쓰는 방법입니다.** 혼자 채우는 것보다 훨씬 빠릅니다.

```javascript
나는 아래 도구를 만들려고 한다.
요구사항 명세를 함께 완성해 달라.

[ 만들고 싶은 것 ]
(두세 문장으로 자유롭게)

요청이야.
1) 목적 · 입력 · 출력 · 제약 네 요소 중 빠진 것을 물어라.
2) 특히 제약에서 아래를 반드시 확인하라.
   - 값이 비었을 때 어떻게 하는가
   - 잘못된 값이 들어왔을 때 어떻게 하는가
3) 한 번에 하나씩만 물어라.
4) 내가 답하면 네 칸을 채운 표로 정리하라.
5) 내가 말하지 않은 조건을 넣지 마라.

## Step 06 :: 완성 기준 다섯 개를 정합니다.

**완성 기준이 없으면 계속 다듬게 되고 언제 멈춰야 할지 모릅니다.** 다섯 개 조건으로 적어두면 그것만 통과하면 완성입니다.

> 🤔 **일단 만들어보고 나중에 정하면 안 되나요?**
>
> 훨씬 자연스러운 순서인데 거의 항상 실패합니다. 첫째, 결과를 먼저 보면 기준이 결과 쪽으로 끌려갑니다 - 나온 것을 보고 기준을 정하면 무의식적으로 "지금 나온 것이 합격"이 되는 기준을 쓰게 됩니다. 둘째, 기준이 없으면 끝나는 지점이 없습니다. 완성 기준은 "여기까지 됐으면 끝"을 미리 못 박아 두는 문장입니다.

```

## Step 07 :: 명세는 한 번에 완성되지 않습니다.

**만들다 보면 빠뜨린 제약이 드러납니다. 그때 채우면 됩니다.** 첫 명세로 만들어 보면 생각하지 못한 상황이 나옵니다. 그때마다 명세의 제약 칸에 한 줄씩 추가합니다. 명세와 결과물을 함께 키워 가는 것이 정상적인 진행입니다.
