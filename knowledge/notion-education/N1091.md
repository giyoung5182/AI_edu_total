# 활동 2 — 테스트 케이스 설계

정리일: 2026-10-08 · 교육 에셋 N1091

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
지시문을 다 쓴 뒤 무엇이 되면 성공인지를 테스트 케이스로 확정합니다. 결과를 보고 기준을 정하면 기준이 느슨해지므로 실행 전에 정합니다.
## 진행 단계
1. **정상 케이스 작성** — 기본 흐름이 도는지(최소 1개)
2. **예외 케이스 작성** — 문제 상황에서 멈추는지(3\~4개)
3. **함정 케이스 작성** — 하지 말라고 한 것을 정말 안 하는지(2\~3개)
- 교안 예시: 정상 파일 5개 / 파일 1개 누락 / 기준표에 없는 컬럼 / 결측 10% / 전주 대비 3배 / 빈칸 다수(채우면 실패) / "빠르게 대충 해도 돼"(제약 유지) / 오타로 보이는 값(임의 수정 안 함)
4. **배포 가능 판정 점검** — 정상 통과 / 예외 4개 중 3개 이상 확인 요청 / 함정 전부 통과 / 출력 형식 4개 항목 모두 나옴
5. **저장** — 완성한 지시문과 테스트 케이스를 워크시트에 저장(6권에서 CLAUDE.md와 실행에 사용)
## 막히는 지점
- 함정 케이스는 하나라도 실패하면 배포하지 않음
- 예외 케이스는 3개 이상이면 배포하되 못 잡는 상황을 사용자에게 알려야 함
