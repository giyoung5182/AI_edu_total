# Step 4. 결과 확인과 검증

정리일: 2026-10-08 · 교육 에셋 N0606

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
사고 10건의 판정 결과를 확인하고, 말로 에이전트를 다듬은 뒤 세 가지 체크포인트로 검증합니다.
## 진행 단계
1. **결과 확인** — 사고 10건의 판정 결과가 표로 나옵니다.
2. **말로 튜닝** — 메뉴가 아니라 말로 합니다. 예: "보상검토 에이전트가 사유를 더 구체적으로 쓰도록 에이전트를 수정해줘". Claude가 `.claude/agents/[에이전트이름].md` 파일을 수정합니다. 튜닝은 새 세션(/new)에서 하면 더 좋습니다.
- 판정 기준이 느슨하거나 빡빡하면 "이 건은 이렇게 판정되어야 해"라고 예시를 줍니다.
- 사유가 짧으면 "사유를 더 구체적으로 적어줘"라고 요청합니다.
- 표 형식을 바꾸려면 원하는 열 구성을 다시 알려줍니다.
3. **검증 체크포인트 3가지** — 세 가지가 모두 충족되어야 신뢰할 수 있는 Subagent입니다.
- 호출 정확도: 맞는 상황에 호출되는가 / 다른 Subagent와 헷갈리지 않는가 / 필요한 정보가 함께 전달되는가
- 판정 품질: 기준과 정확히 대조했는가 / 판정 라벨이 기준에 맞는가 / 사유가 명확하고 근거가 구체적인가
- 태도 일관성: 정중하고 전문적인 톤인가 / 불확실한 내용을 단정하지 않는가 / 모르는 내용은 '추가확인'으로 처리하는가
## 막히는 지점
- 엉뚱한 요청에 에이전트가 호출됨: 호출 조건 수정
- 판정이나 사유가 어색함: 출력 형식과 판단 기준 수정
- 검토 태도가 들쭉날쭉함: 페르소나(신중한 보상 심사자)를 다시 강조
