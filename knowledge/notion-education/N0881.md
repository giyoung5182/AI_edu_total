## 3.0 다시 시작하기 — 2주차에서 여기까지
지난주 우리는 RCTC+K로 좋은 질문을 만들고, 그걸 저장해두는 에이전트를 만들었습니다. 그리고 시스템 프롬프트 워크시트를 채워 왔죠. 이번 주는 세 가지 흐름입니다.
```plain text
① 만들어온 에이전트 발표 + 피드백  (3.1~3.2)
   → 내가 설계한 게 맞는지 함께 점검

② 에이전트 고도화  (3.3~3.5)
   → CoT(단계적 사고) + 메타 프롬프팅으로 시스템 프롬프트를 더 정교하게
   → "한 번에 완성"이 아니라 "AI와 대화하며 정교화"

③ 콘텐츠 제작 + 워크플로우  (3.6~3.11)
   → 이미지 생성 심화 (모델 비교 · 6요소 · 체이닝)
   → 5단계 워크플로우 실습 (카드뉴스 한 세트 완성)
```

## 3.1 워크시트 발표 — 발표 개요
지난주 과제로 채워온 시스템 프롬프트 워크시트를 발표합니다. 발표의 목적은 "얼마나 잘 만들었나"를 평가하는 게 아닙니다. **내가 설계한 것을 말로 설명해보면서, 빠진 것과 더 구체화할 것을 스스로 발견**하는 과정입니다.
### 발표에 포함할 내용 (1인 3\~5분)
발표할 때 아래 순서로 이야기하면 됩니다. 외우지 않아도 되고, 워크시트를 보면서 자연스럽게 설명합니다.
**① 어떤 업무를 골랐나? (STEP 1)**
- 어떤 반복 업무를 에이전트로 만들기로 했는지
- 왜 그 업무를 골랐는지 (가장 자주 하거나 가장 귀찮아서)
**② 지금 무엇이 불편한가? (STEP 2)**
- 현재 그 업무에서 가장 번거로운 점
- AI로 해결되면 가장 좋겠는 것 한 가지
**③ 내가 설계한 시스템 프롬프트 읽기 (STEP 3\~4)**
- RCTC+K 각 요소를 직접 읽는다
- "역할은 이렇게 잡았고, 규칙은 이런 것들을 넣었어요" 식으로
- K(정보)에 무엇을 넣었는지 — 특히 보안 이슈 없는지
**④ 테스트 계획 (STEP 5)**
- 이 에이전트를 어떤 한 줄로 테스트할 계획인지
- 실제로 테스트해봤다면 그 결과 공유 (화면 캡처 환영)
**⑤ 스스로 느낀 한계 (자유 의견)**
- 채우다가 막혔던 부분이 있으면 솔직하게
- "규칙을 뭘 넣어야 할지 몰랐어요", "K에 어디까지 넣어야 하나 모르겠어요" — 이런 고민이 다음 섹션(고도화)에서 바로 해결됩니다
> 강사 포인트: 발표 분위기는 "평가"가 아니라 "공유"여야 합니다. 첫 발표자가 떨지 않게, 강사가 먼저 "저도 처음에 이런 고민이 있었어요"로 공감대를 만들어주세요. 잘 만든 것을 칭찬하되, 모두가 비슷한 고민을 가졌다는 걸 자연스럽게 꺼내주면 다음 발표자가 훨씬 편하게 발표합니다.

## 3.2 피드백 구조 — 강사와 동료가 함께 체크하는 법
발표가 끝나면 피드백을 줍니다. 아래 체크리스트를 기준으로, 동료가 먼저 "잘된 점 하나 + 보완할 점 하나"를 말하고, 강사가 마무리합니다.
### 발표 피드백 체크리스트





요소

체크 포인트

잘됨

보완 필요




R (역할)

역할이 충분히 구체적인가? "비서야" vs "10년 차 고객 상담 전문가야"








C (맥락)

내 상황이 포함됐는가? AI가 혼자 읽어도 이해할 수 있는가?








T (과업)

무엇을 해달라는지 명확한가? 단계로 쪼개져 있는가?








C (규칙)

규칙이 3개 이상인가? 형식·내용·톤이 모두 포함됐는가?








K (정보)

AI가 모를 핵심 정보가 담겼는가? 보안 문제는 없는가?








전체

이 프롬프트 하나면 매번 설명 없이 작동할 것 같은가?






### 자주 나오는 패턴과 처방
**패턴 1 — "역할은 있는데 규칙이 너무 적다"**
가장 흔한 케이스입니다. 역할(R)은 잘 썼는데 규칙(C)이 1\~2개인 경우. 처방: "지금 그 업무를 직접 할 때 매번 신경 쓰는 게 뭐예요?"를 물어보면 규칙이 바로 나옵니다.
**패턴 2 — "규칙이 너무 추상적이다"**
"친근하게 써줘" → "친근한 반말, 이모지 2개 이내, 문장은 3줄 이내"처럼 구체화해야 합니다. AI는 "친근하게"라는 말을 사람마다 다르게 해석합니다.
**패턴 3 — "K(정보)가 비어 있다"**
정보를 안 주면 AI가 지어냅니다(환각). "내 제품·서비스 정보", "자주 쓰는 용어", "해서는 안 되는 표현"을 넣어야 합니다.
**패턴 4 — "과업이 너무 넓다"**
"이메일 써줘" → "고객 문의 이메일의 답장 초안을 써줘. 인사→공감→해결방안→마무리 인사 순서로."

## 3.3 에이전트 고도화 — "한 번에" 말고 "AI와 함께"
### 지금까지 만들어온 방식의 한계
워크시트로 RCTC+K를 채우는 방식은 "사람이 재료를 생각해서 AI에게 준다"는 구조였습니다. 이게 기본이자 핵심이지만, 한 가지 한계가 있습니다.
> "내가 어떤 규칙을 넣어야 할지 모르겠다."
이 고민, 발표에서도 많이 나왔을 겁니다. 사실 **AI한테 시스템 프롬프트를 만들어달라고 시키면 됩니다.** 이게 **메타 프롬프팅**입니다.
### 메타 프롬프팅이란
> **메타 프롬프팅(Meta Prompting) = AI에게 "AI를 위한 지시문(프롬프트)"을 만들어달라고 하는 것**
프롬프트를 사람이 혼자 짜는 게 아니라, AI와 대화하면서 같이 설계하는 방식입니다. 그리고 여기에 \*\*CoT(단계적 사고)\*\*를 결합하면 훨씬 정교한 결과가 나옵니다.
```plain text
[기존 방식]
사람이 워크시트 채움 → 완성된 시스템 프롬프트 입력 → AI 작동

[메타 프롬프팅 방식]
사람: "내 업무를 설명할게. 좋은 시스템 프롬프트를 만들어줘"
AI: 질문으로 재료를 뽑아냄
사람: 답변
AI: 초안 생성
사람: "이 부분 더 구체화해줘"
AI: 개선판 생성
→ 반복할수록 정교해짐
```

## 3.4 CoT × 메타 프롬프팅 실전 — 3단계 정교화 흐름
### 전체 흐름
```plain text
STEP 1 · 상황 투입
   내 반복 업무를 AI에게 설명한다
          ↓
STEP 2 · AI가 CoT로 재료를 추출
   AI가 단계별로 질문하며 RCTC+K 재료를 뽑는다
          ↓
STEP 3 · 시스템 프롬프트 초안 생성
   AI가 모은 재료로 초안을 만든다
          ↓
STEP 4 · 약점 진단 + 개선
   AI가 스스로 약점을 찾고 개선안을 제시한다
          ↓
STEP 5 · 테스트 + 최종 확정
   한 줄 입력으로 작동 확인
```
### STEP 1 · 상황 투입 — 시작 프롬프트
```plain text
[메타 프롬프팅 시작 프롬프트]

나는 AI 에이전트를 만들려고 해.
아래 업무를 자동화하고 싶어.

[내 업무 설명]
업무: _______________________
자주 반복되는 이유: _______________________
지금 번거로운 점: _______________________

이 업무를 위한 최적의 시스템 프롬프트를 만들어줘.
단, 바로 만들지 말고 먼저 단계별로 나에게 필요한 정보를 물어봐줘.
한 번에 하나씩 질문해줘.
```
> ⚠️ 핵심: "바로 만들지 말고 먼저 질문해줘 / 한 번에 하나씩" — 이 두 줄이 CoT의 시작입니다. 이 없으면 AI가 불완전한 정보로 성급하게 만들어냅니다.
### STEP 2 · AI의 CoT 질문 예시
AI는 보통 이런 순서로 질문합니다.
```plain text
AI: "좋아요. 몇 가지 물어볼게요.
    첫 번째: 이 에이전트가 처리할 내용은 주로 어떤 형태인가요?
    (예: 고객 문자, 이메일, 메신저 내용, 회의 메모 등)"

사람: "고객 인스타 DM이요."

AI: "감사해요. 두 번째:
    결과물로 원하는 게 정확히 무엇인가요?
    (예: 바로 발송할 수 있는 완성 답장, 아니면 참고할 초안)"

사람: "바로 복붙해서 보낼 수 있는 답장이요."

AI: "세 번째:
    답장의 말투나 브랜드 톤은 어떤가요?
    (예: 친근한 반말, 공손한 존댓말, 전문적인 격식체)"
```
이렇게 AI가 질문을 단계적으로 던지면서 RCTC+K 재료를 자연스럽게 추출합니다.
### STEP 3 · 시스템 프롬프트 초안 생성
질문이 끝나면 AI에게 생성을 요청합니다.
```plain text
[초안 생성 요청]
좋아. 지금까지 내가 답한 내용을 바탕으로
RCTC+K 구조로 시스템 프롬프트를 만들어줘.
각 요소(R·C·T·C·K)가 무엇을 담당하는지
한 줄씩 레이블을 달아서 보여줘.
```
AI가 RCTC+K 구조로 정리된 초안을 냅니다.
### STEP 4 · AI 자가 진단 + 개선 (핵심)
초안을 받은 뒤, 바로 확정하지 말고 AI에게 약점을 물어봅니다.
```plain text
[자가 진단 요청]
방금 만든 시스템 프롬프트의 약점을 스스로 찾아줘.
다음 기준으로 단계별로 평가해줘.

1단계: RCTC+K 각 요소가 충분히 구체적인가? (모호한 표현이 있으면 지적)
2단계: 이 프롬프트만 보고 AI가 매번 일관된 결과를 낼 수 있는가?
3단계: 환각(잘못된 정보 생성) 위험이 있는 부분은?
4단계: 빠진 제약 조건이 있을 것 같은 부분은?

평가가 끝나면 개선된 버전을 보여줘.
```
> 💡 이게 CoT의 핵심입니다. AI가 스스로 "1단계: ... 2단계: ... 3단계: ..."로 생각하면서 약점을 찾기 때문에, 사람이 미처 몰랐던 구멍이 드러납니다.
### STEP 5 · 반복 정교화 — 원하는 만큼
개선판을 받은 뒤 추가 수정이 필요하면:
```plain text
[특정 부분 심화 요청]
규칙(Constraints) 부분이 아직 부족한 것 같아.
내가 이 업무에서 절대 해서는 안 되는 것들을 물어봐줘.
그 답변을 반영해서 규칙을 더 구체적으로 다시 만들어줘.
```
```plain text
[실전 테스트 요청]
완성된 시스템 프롬프트를 기준으로,
아래 샘플 입력이 들어왔다고 가정하고 실제로 작동해봐줘.
[샘플 입력: 고객 메시지 예시]
```

## 3.5 메타 프롬프팅 전후 비교
### ❌ 워크시트로만 만든 버전 (초기)
```plain text
너는 고객 상담 비서야.
고객 DM에 답장해줘.
친근하게 써줘.
우리 가게는 카페야.
```
→ 결과: 그럭저럭 작동하지만, 말투가 들쑥날쑥하고 가게 정보를 지어내는 경우가 있음.
### ✅ CoT 메타 프롬프팅으로 정교화한 버전
```plain text
[R] 너는 성수동 미루 카페의 10년 차 단골 손님처럼
    가게를 잘 아는 친근한 상담 담당자야.

[C] 인스타그램 DM으로 들어오는 고객 문의를 처리하고 있어.
    고객은 주로 20~30대 여성이고, 감성적이고 친근한 소통을 좋아해.

[T] 고객 DM을 주면, 아래 순서로 답장을 써줘.
    1단계: 고객의 문의 의도 파악
    2단계: 의도에 맞는 답장 초안 작성 (바로 발송 가능한 수준)

[C] 규칙:
    1. 친근한 반말 존댓말 혼용 (예: "안녕하세요! ...이에요 :)")
```

## 3.6 이미지 생성 AI 심화 — 작동 원리
### 확산 모델(Diffusion Model)이란
모든 이미지 생성 AI의 핵심 기술은 **확산 모델**입니다. 작동 원리는 하나입니다.
```plain text
랜덤 노이즈(점묘화처럼 흐릿한 상태)에서 시작
        ↓
텍스트 프롬프트가 "이 노이즈를 어떤 방향으로 정제할지" 안내
        ↓
수십~수백 단계를 거쳐 노이즈 → 이미지로 수렴
        ↓
최종 이미지 완성
```
모델마다 결과가 다른 이유:
1. 학습 데이터의 종류와 양 (어떤 이미지를 얼마나 봤는가)
2. 프롬프트 해석 방식 (언어 이해 모델의 성능)
3. 학습 목표 (예술적 감성 vs 사실적 정확도 vs 텍스트 정확도)
> **결론: "최고의 모델"은 없습니다. "내 작업에 가장 맞는 모델"을 고르는 것이 핵심입니다.**

## 3.8 이미지 프롬프트 6요소 — 결과를 결정하는 구조
좋은 이미지 프롬프트도 텍스트 프롬프트처럼 구성 요소가 있습니다.
```plain text
① 주제(Subject)   : 무엇을 — 따뜻한 커피 한 잔
② 배경(Setting)   : 어디서 — 나무 테이블 위, 창가
③ 스타일(Style)   : 어떻게 — 미니멀, 클린, 인테리어 매거진
④ 조명(Lighting)  : 빛은 — 부드러운 자연광, 아침 햇살
⑤ 구도(Angle)     : 각도 — 위에서 내려다본 구도 (플랫레이)
⑥ 화질(Quality)   : 수준 — 4K, 포토리얼리스틱, 광고 사진 수준
```
### 전후 비교
**❌ 6요소 없이:**
```plain text
커피 사진 만들어줘
```
결과: 평범하고 어떤 느낌인지 알 수 없는 이미지.
**✅ 6요소 완성:**
```plain text
[주제] 따뜻한 아메리카노 한 잔, 하얀 세라믹 컵, 20대 긴생머리 여자가 깔끔한 하늘색 톤의 잠옷을 입고 커피를 음미하고 있는 사진
[배경] 원목 테이블 위, 창가에서 들어오는 빛
[스타일] 미니멀, 북유럽 감성, 인테리어 매거진
[조명] 부드러운 아침 자연광, 따뜻한 톤
[구도] 45도 각도에서 내려다본 뷰
[화질] 4K 포토리얼리스틱, 광고 사진 수준
```

## 3.9 체이닝(Chaining) — 60%를 90%로 올리는 법
### 왜 한 번에 완성이 안 되나
이미지 생성 AI는 첫 번째 결과가 60\~70% 수준인 경우가 대부분입니다. 이건 AI의 한계가 아니라 **방향이 아직 정해지지 않은 것**입니다. 체이닝은 방향을 점점 좁혀가는 대화입니다.
```plain text
첫 이미지 생성 (60%)
        ↓
"스타일은 유지하되, 이 부분만 바꿔줘" (75%)
        ↓
"조명만 조정해줘" (85%)
        ↓
"배경 색감을 더 따뜻하게" (90%+)
```
### 체이닝 핵심 원칙 3가지
**① 한 번에 하나만 바꾼다**
```plain text
❌ "조명 바꾸고, 배경도 바꾸고, 구도도 수정해줘"
   → AI가 방향을 잃음. 전혀 다른 이미지가 나올 수 있음

✅ "조명만 따뜻하게 바꿔줘. 나머지는 그대로."
   → 원하는 요소만 정교화됨
```
**② "유지" 지시를 명확하게 건다**
```plain text
✅ 체이닝 지시 템플릿:
"스타일·구도·색감은 그대로 유지해줘.
 [바꿀 요소]만 [원하는 방향]으로 수정해줘."
```
**③ 같은 채팅창에서 이어서 한다**<br>새 채팅창을 열면 이전 맥락이 사라집니다. 반드시 같은 대화 안에서 이어가야 합니다.
### 체이닝 실습 예시 (카드뉴스 배경 이미지)
```plain text
[1차 생성]
여름 건강 관리 관련 카드뉴스 배경 이미지.
밝고 산뜻한 느낌. 초록색 계열. 4K.

[2차 체이닝]
분위기와 색감은 그대로 유지해줘.
구도만 세로 비율(9:16)로 바꿔줘.
아래쪽 1/3은 텍스트 넣을 공간으로 비워줘.

[3차 체이닝]
구도는 그대로. 색감을 좀 더 따뜻하게.
초록 + 따뜻한 베이지 톤으로.
```

## 3.9.1 (향후 해보기) 카드뉴스 한 세트 완성 (단계별)
예시 주제: **"여름철 건강 관리 팁"** 카드뉴스 5장.

```plain text
"여름철 건강 관리를 주제로 일반인 대상 카드뉴스를 만들 거야.

 각각 한 줄로."
```
### STEP 2 · 리서치 (15분)
```plain text
"위 5개 주제 각각의 핵심 정보를 2~3줄로 정리해줘.
 출처가 불확실한 정보는 (확인 필요)로 표시해줘."
```
> ⚠️ 건강·수치 정보는 반드시 사람이 검수. 환각 가장 많이 나오는 영역.
### STEP 3 · 본문 작성 (15분)
```plain text
"위 정보로 카드뉴스 5장을 만들어줘.
 각 장: 제목 한 줄 + 설명 두 줄.
```


## (과제) 3.10 AI 교수법 — 비전공 청중을 가르치는 기술
> 이 섹션이 3주차의 진짜 핵심입니다. 도구를 아는 것과, 모르는 사람에게 가르치는 것은 완전히 다른 능력입니다. 강사는 그 두 번째를 갖춰야 합니다.
### AI 교육이 일반 강의와 다른 이유
일반 강의는 "모르는 것을 알게" 합니다. AI 교육은 여기에 두 가지가 더 붙습니다.
```plain text
일반 강의: 모름 → 앎
AI 교육:   두려움 → 안심
           불신   → 신뢰
           앎     → 직접 해봄
```
청중은 AI를 배우러 오지만, 실제로는 **세 가지 감정** 중 하나를 품고 옵니다.





감정

유형

표현 방식




두려움

"AI가 내 일자리를 뺏지 않을까?"

질문을 안 하고 팔짱을 낀다




불신

"AI가 틀린 말도 한다던데, 믿을 수 있나?"

날카로운 반박 질문




과한 기대

"AI가 다 해주겠지?"

나중에 실망하고 떠남


이 세 가지를 다루지 않으면, 아무리 좋은 기능을 가르쳐도 수강생이 집에 가서 쓰지 않습니다.
### 세 가지 감정을 다루는 법
**① 두려움 → "AI는 대체제가 아니라 도구"**
```plain text
❌ 하면 안 되는 말:
"AI가 이 정도를 할 수 있게 됐으니, 앞으로 많은 일이 자동화됩니다."
→ 두려움이 커짐.

✅ 이렇게 말하세요:
"AI가 반복 작업의 80%를 가져가면, 여러분은 나머지 20%의
 판단·창의·책임에 더 집중하게 됩니다. 그게 AI를 잘 쓰는 사람과
 못 쓰는 사람의 차이입니다."
```
**② 불신 → "한계를 먼저 솔직하게"**
```plain text
❌ 하면 안 되는 말:
"AI는 정말 놀라운 기술이에요! 못 하는 게 없어요."
→ 나중에 틀린 답이 나오면 강사 신뢰가 무너짐.

✅ 이렇게 말하세요:
"AI는 가끔 틀린 내용을 자신 있게 말합니다. 환각이라고 해요.
 그래서 사람이 마지막에 꼭 확인해야 합니다. AI는 초안 작성자,
 사람은 최종 판단자 — 이 역할 분담이 AI를 안전하게 쓰는 법입니다."
→ 한계를 먼저 말하면 오히려 신뢰가 올라갑니다.
```
**③ 과한 기대 → "Quick Win으로 현실 조율"**
```plain text
❌ 하면 안 되는 말:
"AI 쓰면 업무가 다 자동화됩니다."
→ 기대치가 너무 높아짐. 나중에 "생각보다 별로네"로 이탈.

✅ 이렇게 말하세요:
"오늘 끝나면 이 하나만 가져가세요 — 지금 30분 걸리는 이 작업,
 3분으로 줄이는 것. 그것 하나면 충분합니다."
→ 작은 성공(Quick Win)이 습관을 만들고, 습관이 AI 활용 문화를 만듭니다.
```

## 3.11 교수법 원칙 7가지 — 강사 필수 암기
### 원칙 1 · 용어를 일상어로 바꾼다





AI 용어

강의에서 쓸 말




프롬프트

"AI에게 하는 말", "부탁하는 방법"




환각(Hallucination)

"AI가 가끔 지어내는 것"




토큰

"AI가 읽는 글자 단위" (숫자 외우게 하지 말 것)




컨텍스트 윈도우

"AI의 작업 기억 한계"




에이전트

"맞춤 전용 비서"




RCTC+K

약자를 외우게 하지 말고 "5가지로 구체적으로"로




시스템 프롬프트

"비서한테 미리 교육해두는 것"




메타 프롬프팅

"AI한테 AI 지시문을 만들어달라고 하는 것"


> 규칙: **용어는 강사가 알고, 청중에게는 비유를 준다.**
### 원칙 2 · 비유를 먼저, 개념을 나중에
설명 순서가 거꾸로 되면 청중이 닫힙니다.
```plain text
❌ 잘못된 순서:
"LLM은 대규모 언어 모델로, 확률 기반 토큰 예측을 통해..."
→ 첫 문장에서 청중의 절반이 포기.

✅ 올바른 순서:
"AI는 세상의 책을 엄청 많이 읽은 사람이, 다음에 올 말을 잘 맞히게
 된 거예요. 정답을 외운 게 아니라 패턴을 익힌 거죠."
→ 비유로 직관을 준 뒤 개념을 설명.
```
### 원칙 3 · 개념 → 시연 → 체험의 3단 구조
강의의 모든 파트를 이 순서로 진행합니다.
```plain text
① 개념 (5분): 왜 이게 중요한지, 비유로
② 시연 (5분): 강사가 화면에서 직접 보여주기
③ 체험 (10분): 수강생이 손으로 직접 해보기

→ ③이 없으면 기억에 남지 않습니다.
   "들었다"와 "해봤다"는 전혀 다른 기억입니다.
```
### 원칙 4 · "왜"를 먼저, "어떻게"는 나중에
청중이 "왜 이걸 배우지?"를 느끼면 집중이 끊깁니다.
```plain text
❌ "오늘은 RCTC+K를 배우겠습니다."
→ "그게 뭔데?"

✅ "AI한테 뭔가 시켰는데 결과가 별로였던 적 있으시죠?
   그 이유가 오늘 3분 안에 풀립니다."
→ 이유가 생기면 집중이 생깁니다.
```
### 원칙 5 · 라이브 시연은 "실패"도 교육이다
시연 중 AI가 엉뚱한 답을 내는 경우가 반드시 생깁니다. 이걸 두려워하지 마세요.
```plain text
❌ 실패했을 때 당황하거나 서두르면
→ 청중이 "강사도 모르는 거 아닌가?" 불신

✅ 실패했을 때 이렇게 말하면
"오, 이렇게 나왔네요. 이게 바로 환각입니다.
 실제 강의에서도 이런 일이 생기고, 이럴 때 이렇게 대응하면 됩니다."
→ 실패가 가장 생생한 교육 자료가 됩니다.
```
### 원칙 6 · 청중이 직접 입력하게 만든다
듣기만 하면 3일 뒤 잊습니다. 손이 기억해야 합니다.
```plain text
"자 이제 여러분도 해보세요. 지금 ChatGPT(또는 교육기관 20) 열고,
 아까 제가 보여드린 프롬프트에서 【 】 부분만 본인 상황으로 바꿔서
 넣어보세요. 3분 드릴게요."
```
> 손 한 번 움직인 경험이, 1시간 강의보다 강합니다.
### 원칙 7 · 마무리는 항상 "다음 한 걸음"으로
강의 끝에 "오늘 배운 걸 정리하면..." 대신, 집에 가서 바로 할 수 있는 것 하나를 줍니다.
```plain text
❌ "오늘 RCTC+K, 에이전트, 이미지 생성, 워크플로우를 배웠습니다."
→ 많이 배웠는데 정작 뭘 해야 할지 모름.

✅ "오늘 집 가시면 딱 이것 하나만 해보세요.
   지금 제일 귀찮은 반복 업무 하나에 RCTC+K 써서 AI에게 시켜보기.
   15분이면 됩니다."
→ 구체적인 다음 행동이 습관의 씨앗이 됩니다.
```

## 3.13 결과물 검수 & 저작권
**검수 3원칙**
- 정보(수치·사실)는 원본과 대조 — 특히 건강·법·가격 정보
- 맞춤법·브랜드 톤·금지 표현 최종 확인

- AI 생성 이미지의 상업 사용 조건은 도구마다 다름 → 약관 확인 필수
- 가장 안전: Adobe Firefly (Adobe가 상업 면책 보장)
- 실존 인물·로고·저작물을 따라 만든 이미지는 위험
- **"이 내용이 외부에 노출되어도 괜찮은가?"** — AI에 뭔가를 넣기 전 이 질문 한 번

### 과제 내용 — "5분 수업 시연 + PPT"

### A-1. 메타 프롬프팅 시작 템플릿
```plain text

업무: _______________
자주 반복되는 이유: _______________
지금 번거로운 점: _______________

이 업무를 위한 최적의 시스템 프롬프트를 만들어줘.
단, 바로 만들지 말고 먼저 단계별로 나에게 필요한 정보를 물어봐줘.

```
