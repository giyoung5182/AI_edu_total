# 1️⃣ 세션 설명
## 이번 세션의 목적
1. 결과물을 제출 가능한 형태로 정리합니다.
2. 동료 결과물을 체험하며 다른 업무 아이디어를 확인합니다.
3. 지금 만든 결과물을 어디까지 확장할 수 있을지 떠올립니다.

## 진행 순서
1. 작품 제목 정리
2. Pain Point / 해결 방식 / 더미 데이터 설명 작성
3. HTML 파일 최종 점검
4. 보안 체크
5. 콘테스트 플랫폼 제출
6. 동료 결과물 체험
7. 추천 또는 피드백
8. 적용 아이디어 짧게 공유

> TIP: 콘테스트에서 중요한 것은 기술 용어가 아니라 `왜 만들었고, 무엇이 편해졌는지`를 분명히 말하는 것입니다.

# 2️⃣ 제출 전에 반드시 정리할 것
## 1️⃣ 작품 제목
제목은 한눈에 기능이 보이게 적습니다.
좋은 예
1. `주간보고 3줄 요약기`
2. `회의 Action Item 추출기`
3. `팀 일정 시각화 보드`

## 2️⃣ Pain Point
해결하고 싶었던 실제 병목을 한두 문장으로 적습니다.
예
1. `부서별 주간 보고가 제각각 들어와서 핵심만 빠르게 보기 어려웠다.`
2. `회의 후 누가 무엇을 언제까지 해야 하는지 다시 정리하는 데 시간이 많이 들었다.`

## 3️⃣ 해결 방식 및 기획 의도
도구가 어떤 식으로 문제를 해결하는지 설명합니다.
예
1. `텍스트를 붙여넣으면 핵심 내용만 3줄로 압축하고 상태별 카드로 정리한다.`
2. `회의 메모를 넣으면 담당자·일정·할 일을 표 형태로 분리해 보여준다.`

## 4️⃣ (필요시) 더미 데이터
테스트 사용자를 위한 데이터가 필요하다면 플랫폼에서 테스트할 수 있도록 더미 데이터를 준비합니다.
1. 실제 회사 데이터는 넣지 않습니다.
2. 형식만 유사한 가상 예시를 사용합니다.
3. 입력 형태를 빠르게 이해할 수 있도록 2\~3줄 정도면 충분합니다.

# 4️⃣ 동료 결과물 체험 포인트
## 갤러리에서 무엇을 볼까요?
1. 문제 정의가 명확한가?
2. 입력과 출력이 직관적인가?
3. 바로 써보고 싶은 흐름인가?
4. 다른 업무에도 확장 가능성이 있는가?
## 피드백은 어떻게 주나요?
좋은 피드백은 `멋있다`보다 구체적입니다.
1. `입력 형식이 단순해서 바로 써보고 싶었습니다.`
2. `결과를 카드로 보여줘서 회의 후 공유에 유용해 보였습니다.`
3. `더미 데이터 예시가 있어 사용법을 이해하기 쉬웠습니다.`
4. `복사 버튼이 있으면 더 실무적일 것 같습니다.`

2. 추가하면 좋을 기능 하나
3. 다른 업무에 확장 가능한 아이디어 하나
