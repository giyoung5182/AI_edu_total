# PART 1. SIMJI 트러블슈팅
---
## 🔴 S-01. SIMJI가 너무 많이 물어봐요
**증상**: 질문이 끝없이 이어지고 PRD가 안 나옴
**원인**: SIMJI는 대화형으로 설계되어 있어 기본적으로 단계별 질문을 함
**해결**:
```plain text
지금까지 나눈 대화를 바탕으로
Lovable에 바로 붙여넣기 가능한 PRD를 지금 바로 출력해줘.
영문으로, 코드 블록 형식으로.
```
**예방**: 4교시 결과물(페르소나·기능·스케치)을 SIMJI 첫 대화에 한꺼번에 붙여넣으면 질문 횟수가 줄어듦
---
## 🔴 S-02. PRD가 한국어로 나왔어요
**증상**: PRD 전체가 한국어로 출력됨
**원인**: 대화를 한국어로 진행하면 결과물도 한국어로 나오는 경우 있음
**해결**:
```plain text
방금 출력한 PRD를 영문으로 다시 출력해줘.
Lovable이 영어 PRD를 더 정확하게 처리해.
코드 블록 형식으로.
```
**참고**: Lovable은 영어 PRD를 더 잘 이해함. 한국어 텍스트(서비스 이름, 카피 등)는 PRD 안에 Korean string으로 포함시키면 됨
---
## 🔴 S-03. PRD가 너무 짧아요 (핵심 내용이 빠짐)
**증상**: PRD가 10줄 이내로 너무 단순하게 나옴
**해결**:
```plain text
PRD가 너무 짧아요. 아래 항목들을 모두 포함해서 다시 작성해줘:

1. Project Overview (앱명, 타깃, WHY 선언문 핵심)
2. Design System (Primary/Secondary 컬러 Hex, 분위기 3가지 형용사)
3. Screen Structure (각 화면별 구성 요소 상세하게)
4. Core Features (각 기능별 작동 방식 설명)
5. CRITICAL INSTRUCTIONS FOR LOVABLE
   (React useState 필수, 모바일 반응형, 인터랙션 명세)

영문으로, 코드 블록 형식으로.
```

## 🔴 S-04. PRD에 CRITICAL 섹션이 없어요
**증상**: PRD 마지막에 기술 지시사항이 없어서 Lovable이 정적 페이지만 만듦
**해결**: PRD 끝에 직접 추가하거나 SIMJI에게 요청:
```plain text
PRD 마지막에 아래 내용을 추가해줘:

## CRITICAL INSTRUCTIONS FOR LOVABLE AI

DO NOT build a static UI. Every feature MUST be
fully interactive using React useState.

Mandatory requirements:
1. All buttons must be clickable and trigger state changes
2. All forms must be submittable with success messages
3. Navigation between screens must work without page reload
4. Like/bookmark buttons must toggle and update counters
5. Mobile responsive at 375px minimum width
6. No dead-end screens — all navigation paths must work
```
---

**원인**: Claude.ai 계정 없거나 링크 만료
**해결**:
1. Claude.ai 직접 접속 → 새 대화 시작
2. 아래 내용을 대화 시작에 직접 붙여넣기:
```plain text
당신은 AI MVP 워크숍의 비즈니스 PM 파트너입니다.
예비창업가의 WHY 선언문과 비즈니스 캔버스를 바탕으로
Lovable에 붙여넣기 가능한 PRD를 대화로 설계해주세요.

먼저 제 WHY와 아이템을 설명할게요:
WHY: "[WHY 선언문]"
아이템: [아이템]
핵심 고객: [타깃]
Must Have 기능: 1.[기능1] 2.[기능2] 3.[기능3]
화면 구성: [화면1]→[화면2]→[화면3]

이 내용으로 Lovable PRD를 영문으로 만들어주세요.
```

## 🔴 L-01. 화면이 완전히 다르게 나왔어요
**증상**: PRD와 전혀 다른 레이아웃·색상·구조로 생성됨
**원인 1**: PRD 설명이 Lovable이 다르게 해석한 경우<br>**원인 2**: PRD의 핵심 구조 설명이 불명확
**해결**:
```plain text
Please rebuild the [섹션명/화면명] completely.
The current result doesn't match my requirements.

Here is what I need:
- Layout: [원하는 레이아웃 설명]
- Content: [원하는 내용]
- Style: [원하는 스타일]
- Color: Primary #[Hex], Secondary #[Hex]

Keep all other sections as they are.
Only rebuild [섹션명].
```
---
## 🔴 L-02. 버튼을 눌러도 아무 반응이 없어요
**증상**: 생성된 화면에서 버튼 클릭 시 아무것도 안 됨
**원인**: Lovable이 정적 UI만 만들고 인터랙션 구현을 빠뜨린 경우
**해결**:
```plain text
Please make ALL buttons interactive at once:

1. [버튼명1] button: clicking must [동작 설명]
   Use React useState to manage the state change.
   Show [결과/변화] immediately after click.

2. [버튼명2] button: clicking must [동작 설명]
   Update the UI without page reload.

3. [버튼명3] button: clicking must [동작 설명]

For every button, add a visible hover effect (opacity or color change).
All state changes must be immediate and visible.
```
---
## 🔴 L-03. 폼 제출 후 아무것도 안 나타나요
**증상**: 이름·이메일 입력 후 버튼 클릭해도 성공 메시지 없음
**해결**:
```plain text
Please make the [폼명] form fully functional:

1. User fills in: [필드 1], [필드 2], [필드 3]
2. User clicks submit button
3. Immediately show success message: "[성공 메시지 텍스트]"
   (display as a green banner or modal)
4. Clear all form fields after successful submission
5. Do NOT reload the page

Use React useState:
- formData state for field values
- isSubmitted state for success message display
- All managed without page reload
```
---
## 🔴 L-04. 모바일에서 화면이 깨져요
**증상**: PC에서는 정상이지만 스마트폰에서 레이아웃 이상
**확인 방법**: 브라우저 F12(개발자도구) → 좌상단 모바일 아이콘 클릭 → iPhone SE (375px) 선택
**해결**:
```plain text
Please fix all mobile layout issues at once for 375px width:

1. Prevent horizontal scrolling — all content must fit within 375px
2. All text: minimum 16px font size, no overflow
3. All buttons: minimum 48px height, full width on mobile
4. All images: max-width 100%, maintain aspect ratio
5. Navigation: if more than 4 menu items, convert to hamburger menu
6. Form inputs: 44px minimum height, 16px font (prevents iOS zoom)
7. Cards/columns: stack vertically on mobile (single column layout)

Test result at exactly 375px viewport width.
```
---
## 🔴 L-05. 화면 간 이동이 안 돼요 (Dead End)
**증상**: 버튼을 눌러도 다음 화면으로 넘어가지 않거나 뒤로 가기가 없음
**해결**:
```plain text
Please fix all navigation issues at once:

Current broken navigation:
- [화면A]에서 [버튼명] 클릭 → [화면B]로 이동 안 됨
- [화면B]에서 뒤로 가기 버튼 없음

Required navigation flow:
[화면1] → clicking [버튼/요소] → show [화면2]
[화면2] → clicking [버튼/요소] → show [화면3]
[화면2, 3] → clicking back/닫기 button → return to previous screen

Use React useState with a 'currentScreen' variable to manage navigation.
All transitions must be smooth, no page reload.
Every sub-screen must have a visible back button (top-left or top-right).
```
