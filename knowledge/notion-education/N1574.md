## 이번 세션에서 할 일
지금 우리 앞에는 빈 작업 폴더 하나가 있습니다.<br>아직 파일도, 프로그램도, AI도 없습니다.<br>이번 세션이 끝나면 이 폴더는 동작하는 웹 서비스가 됩니다.<br>브라우저에서 질문을 입력하면 AI가 답하는 채팅방입니다.<br>그리고 그 채팅방의 이름, 말투, 생김새는 각자 다릅니다.<br>오른쪽 자리와 내 화면이 다른 것이 정상입니다.

## Claude Code — 자연어로 개발을 지시하는 도구
[원본 이미지 제외]
Claude Code는 터미널에서 실행하는 AI 개발 도구입니다.<br>우리가 한국어로 요청하면 Claude Code가 코드를 작성합니다.<br>파일 생성, 수정, 프로그램 실행까지 해냅니다.<br>우리는 코드를 직접 타이핑하지 않습니다.
실제로 주고받는 대화는 이런 모습입니다.

우리: 지금 폴더에 hello.txt 파일을 만들고 "안녕하세요"라고 적어 주세요.
Claude Code: hello.txt 파일을 생성하겠습니다.<br>\[Write 도구 사용 승인 요청: hello.txt\]
**우리: (y를 눌러 승인)**
Claude Code: hello.txt 파일을 만들었습니다.

**중간에 승인 요청이 등장합니다.**
[원본 이미지 제외]
Claude Code는 파일 생성, 명령 실행 같은 작업 전에 우리에게 허락을 구합니다.<br>무엇을 하려는지 읽어 보고 승인하는 습관이 안전한 사용의 기본입니다.<br>내용을 모르는 채 무조건 승인하는 방식은 피합니다.
Claude Code 입력창에서 `/`를 누르면 명령어 목록이 나타납니다.<br>이번 세션에서 사용하는 명령어입니다.
- `/init` — 현재 폴더를 분석해 프로젝트 안내 파일(CLAUDE.md)을 만듭니다
- `/clear` — 대화 기록을 전부 지우고 새로 시작합니다
- `/compact` — 대화 기록을 요약해 압축합니다. 작업 흐름은 유지됩니다
- `/context` — 대화 기록의 현재 사용량을 확인합니다
- `/cost` — 지금까지 사용한 토큰과 비용을 보여줍니다
- `/help` — 사용 가능한 전체 명령어를 보여줍니다
`/clear`와 `/compact`의 차이가 중요합니다.<br>`/clear`는 대화를 완전히 비웁니다. 새 작업을 시작할 때 사용합니다.<br>`/compact`는 요약본만 남기고 줄입니다. 같은 작업을 이어갈 때 사용합니다.<br>두 명령 모두 이미 만든 파일은 지우지 않습니다.
> 💡 대화가 길어지면 Claude Code의 응답 품질이 서서히 떨어집니다.<br>작업 주제가 바뀔 때마다 `/clear`로 새로 시작하는 습관이 좋습니다.

### 호출은 비용이다 — /cost 읽는 법
Claude Code는 대화할 때마다 지금까지의 대화 전체를 다시 읽습니다.<br>대화가 길수록 읽는 양이 늘고, 비용과 시간이 함께 늘어납니다.<br>`/cost`를 실행하면 실제 숫자를 확인할 수 있습니다.
```plain text
Total cost:  $0.42
Usage:       8,100 tokens input (fresh)   ← 새로 읽은 양 (정가)
           125,300 tokens cache read      ← 저장본을 다시 읽은 양 (저렴)
```
cache read는 프롬프트 캐싱의 흔적입니다.<br>이미 읽은 앞부분을 저장해 두고, 다시 읽을 때 싸게 처리하는 기능입니다.<br>캐싱을 직접 조작할 일은 없습니다.<br>비용 화면에서 두 숫자의 의미를 읽을 수 있으면 충분합니다.
이 과정에서 사용하는 AI 호출은 전부 유료입니다.<br>호출 한 번은 돈 한 번입니다.<br>그래서 무엇을 지시하기 전에 요구사항을 정리해 한 번에 보내는 습관이,<br>같은 지시를 여러 번 고쳐 보내는 습관보다 쌉니다.

## 로컬 서버 — 내 컴퓨터가 요청을 받고 응답한다
[원본 이미지 제외]
**서버는 요청을 받아 응답을 돌려주는 프로그램입니다.<br>서버가 내 컴퓨터에서 실행되면 로컬 서버라고 부릅니다.**
브라우저 주소창의 `localhost:8000`은 내 컴퓨터의 8000번 창구라는 뜻입니다.<br>인터넷 어딘가가 아니라, 지금 이 노트북 안입니다.
요청과 응답은 이렇게 왕복합니다.
[원본 이미지 제외]
서버가 꺼지면 응답할 프로그램이 없어집니다.<br>브라우저를 새로고침해도 "연결할 수 없음"만 나타납니다.<br>서버가 살아 있어야 서비스가 삽니다.<br>이번 실습에서 서버를 직접 껐다 켜며 이 사실을 확인합니다.

## 두 개의 AI — 만드는 AI와 서비스 속 AI
이번 세션에는 AI가 두 개 등장합니다.<br>두 AI의 역할 구분이 이번 세션에서 가장 중요한 부분입니다.
[원본 이미지 제외]
구분이 헷갈릴 때는 완성된 서비스에서 확인하면 됩니다.<br>채팅방에 "안녕"이라고 입력했을 때 답을 만드는 쪽은 Gemini입니다.<br>이때 Claude Code는 아무 일도 하지 않습니다.<br>Claude Code의 일은 채팅방 프로그램을 만드는 시점에 이미 끝났습니다.
서버 코드가 Gemini를 부르는 실제 요청은 이런 형태입니다.
```json
POST [개별 링크 제외]

{
  "contents": [
    { "parts": [ { "text": "점심 메뉴 추천해 주세요" } ] }
  ]
}
```
사용자가 채팅방에 입력한 문장이 `text` 자리에 들어갑니다.<br>Gemini가 돌려준 답변을 서버가 받아 브라우저에 전달합니다.<br>이 왕복이 채팅 한 번의 전부입니다.

### API 키 — 서비스 속 AI를 부르는 열쇠
Gemini를 호출하려면 API 키가 필요합니다.<br>API 키는 "이 요청은 내 계정의 요청이다"를 증명하는 문자열입니다.<br>이번 과정에서는 각자 배부받은 개별 키를 사용합니다.


**배부받은 키는 결제 수단에 연결된 유료 키입니다.**<br>키가 유출되면 사용량 초과가 아니라 과금 사고로 이어집니다.<br>다음 세 가지를 지킵니다.
- 키를 코드 파일 안에 직접 적지 않습니다. `.env` 파일에만 보관합니다.
- 키를 화면 공유, 채팅, 공유 문서에 노출하지 않습니다.
- 이 자료의 모든 예시에는 실제 키 대신 `YOUR_API_KEY`라고만 적혀 있습니다.<br>각자 배부받은 키를 이 자리에 넣습니다.

- **Q. claude: command not found**

- **Q. /init이 오래 걸립니다**
- 정상 동작입니다.
- 빈 폴더 기준 1분 내외면 정상입니다. 그대로 기다립니다.

진행 순서

5. 키를 메모장 등에 임시 보관합니다.

[원본 이미지 제외]
<br>

**.env(Environment) 파일**은 API 키, 데이터베이스 비밀번호, 포트 번호 등 외부에 노출되면 안 되는 **민감한 설정값**이나 **로컬 환경 설정**을 저장해 두는 파일입니다. 코드 내부에 직접 비밀번호를 적어두는(하드 코딩) 대신, `.env` 파일에 안전하게 보관하고 코드에서 이를 불러와 사용하는 방식을 표준으로 삼고 있습니다.

> 🔐 키를 다루는 지금이 유출 위험이 가장 큰 순간입니다.<br>키를 Claude Code 대화창이나 공유 문서에 붙여넣지 않습니다.<br>`.env` 파일 안에만 존재하게 합니다.

### 실습 3. 나만의 채팅방 만들기 — 프롬프트 조립

## FAQ
- **Q. 페이지는 열리는데 답변이 안 옵니다**
- `.env`의 키 값에 오타나 공백이 있는 경우가 대부분입니다.
- 키 앞뒤 공백과 따옴표를 제거하고, 서버를 껐다 다시 켭니다.
- **Q. 401 또는 403 에러 로그가 보입니다**
- 키가 유효하지 않은 상태입니다.
- `.env`의 키를 배부받은 키와 다시 대조합니다. 계속 실패하면 진행요원을 호출합니다.
- **Q. Address already in use**
- 8000번 창구를 다른 프로그램이 사용 중입니다.
- 터미널 B에서 `Ctrl+C` 후 재실행합니다. 안 되면 Claude Code에 "8001 포트로 실행하는 명령을 알려 주세요"라고 요청합니다.
- **Q. 답변이 안 오고 멈춘 듯합니다**
- 정상 범위의 지연입니다.
- 첫 응답은 수 초 걸릴 수 있습니다. 터미널 B에 "호출 시작" 로그가 있다면 기다립니다.
- **Q. 스타일이 고른 블록과 다르게 나왔습니다**
- AI 생성 결과의 정상적인 편차입니다.
- Claude Code에 다른 부분을 구체적으로 알려 주면 고쳐 줍니다. (예: "말풍선 색을 노란색으로 바꿔 주세요")
- **Q. 서버 실행 명령을 잊었습니다**
- Claude Code에 "서버 실행 명령을 다시 알려 주세요"라고 요청합니다.
⚠️ 에러가 나면 터미널 B의 로그부터 읽습니다.<br>로그에는 무엇이 실패했는지가 거의 항상 적혀 있습니다.<br>로그를 복사해 Claude Code에 붙여넣고 "이 에러를 해결해 주세요"라고<br>요청하는 방법도 좋습니다.

## 실습 확장 (선택)
기본 실습을 마친 분은 아래를 자유롭게 시도합니다.<br>순서는 없으며, 하나만 해도 됩니다.
- **말투 갈아입히기**: Claude Code에 이렇게 요청합니다.<br>"Gemini 말투 지시를 ○○로 바꿔 주세요."<br>같은 질문에 대한 답변이 어떻게 달라지는지 비교합니다.
- **스타일 블록 교체**: 고르지 않은 블록 중 하나로 바꿔 달라고<br>요청합니다. 화면이 통째로 갈아입는 과정을 지켜봅니다.
- **로그 꾸미기**: "서버 로그에 답변 글자 수도 함께 출력해 주세요"라고<br>요청합니다. 서버를 재시작하고 로그 변화를 확인합니다.
- **코드 열어 보기**: "Gemini를 호출하는 함수를 보여 주고,<br>한 줄씩 설명해 주세요"라고 요청합니다.<br>내 채팅방의 심장을 직접 들여다봅니다.
- **비용 확인**: 터미널 A에서 `/cost`를 실행합니다.<br>cache read 항목에서 캐싱이 동작한 흔적을 확인합니다.

## 이번 실습 결과물
이번 세션을 마친 우리 손에는 다음이 있습니다.
- 내가 지은 이름과 내가 고른 스타일로 동작하는 AI 채팅방
- 서버의 생사와 서비스의 생사가 같다는 사실을 확인한 경험
- 요청 한 건이 로그 몇 줄로 나타나는지 아는 눈
- `.env` 안에만 존재하는 나의 유료 API 키
지금 프로젝트 폴더의 구조입니다.
```plain text
~/my-chat/
├── CLAUDE.md          ← /init이 만든 프로젝트 안내 파일
├── .env               ← API 키 보관 (외부 공유 금지)
├── server.py          ← 로컬 서버 (요청 수신, Gemini 호출, 로그 출력)
├── static/
│   └── index.html     ← 채팅 화면 (각자 고른 스타일)
└── requirements.txt   ← 설치한 패키지 목록
```
파일 이름은 Claude Code의 작업에 따라 조금 다를 수 있습니다.<br>구조가 다르더라도 채팅방이 동작하면 문제없습니다.<br>정확한 구조가 궁금하면 Claude Code에 이렇게 요청합니다.<br>"지금 프로젝트의 파일 구조를 보여 주세요."
**지금 우리가 가진 부품**
```plain text
부품 A. 나만의 AI 채팅방 (로컬 서버 + Gemini 연결 + 내 스타일)
```
