# 1️⃣ 생성형 AI는 어떻게 답변을 만드는가?
### 🧠 언어모델(LLM)이란? - 사용자 관점에서 이해하기

**한 줄 정의**: 언어모델(LLM)은 **"엄청나게 많은 글을 읽고, 다음에 올 말을 예측하는 AI"**입니다.

**쉬운 비유로 이해하기**
- 📱 스마트폰 키보드의 "다음 단어 추천" 기능을 아시나요?
- "이번 달 집행"까지 치면 "금액은", "현황은" 같은 단어가 자동 추천됩니다
- 언어모델은 이것의 **초거대 버전**입니다
- 인터넷의 수십억 개 문서를 학습해서, 어떤 질문에도 "그럴듯한 다음 문장"을 만들어냅니다

**핵심: AI는 "이해"하는 것이 아니라 "계산"하는 것입니다**
AI는 여러분의 질문을 진짜로 이해하지 않습니다. 학습한 패턴을 바탕으로 **"가장 그럴듯한 다음 단어"를 확률적으로 계산**하여 이어 붙이는 것입니다. 그래서 때때로 사실이 아닌 내용도 자신 있게 말하는 것입니다 (환각 현상).

---
### AI의 응답 메커니즘 — "예측 기계"

**생성형 AI의 작동 원리를 한 문장으로 요약하면:**
"앞에 나온 단어들을 보고, 다음에 올 **가장 그럴듯한 단어**를 예측하여 이어 붙인다"
즉, AI는 **"이해"하는 것이 아니라 "예측"하는 것**입니다.

**왜 이걸 알아야 할까요?**
AI가 예측 기계라는 사실을 이해하면, 다음 두 가지가 명확해집니다:
- **맥락을 잘 주면** → 예측 정확도가 올라가고 → 좋은 결과물이 나온다
- **맥락이 부족하면** → 예측이 빗나가고 → 일반적이고 뻔한 결과가 나온다
**결론: AI 활용의 핵심은 "프롬프트를 어떻게 쓰느냐"에 달려 있습니다.**

**환각 (Hallucination)**

없는 정보를 그럴듯하게 만들어냄. 존재하지 않는 기준, 잘못된 비용 항목, 가짜 수치를 생성할 수 있음

없는 원가 기준이나 임의의 집행률을 보고서에 넣으면 월마감·본부 보고에서 즉시 문제가 됨




**논리적 허점**

앞뒤 맥락이 맞지 않는 답변 생성. 모순된 내용을 자연스럽게 서술

원가 초과 원인과 후속 조치가 서로 맞지 않거나, 현금흐름 리스크와 승인 요청 금액이 불일치할 수 있음




**지식 단절**

학습 데이터 이후의 최신 정보를 모름. 최신 공시·법규·시장가격 변동을 반영하지 못할 수 있음

최근 자재 단가, 노무비, 금융비용, 세무·회계 기준 변경을 놓칠 위험

### 실제로 위험한 사례

**사례 1: 환각으로 인한 잘못된 기준 인용**
AI에게 "공동주택 현장 간접비 초과분을 어느 계정으로 처리해야 하는지 알려줘"라고 질문했더니, 존재하지 않는 내부 원가 기준과 계정 코드를 만들어 답변. 이를 그대로 월간 원가 보고서에 반영했다면 검토 과정에서 즉시 문제가 됩니다.
**사례 2: 논리적 허점**
"이번 달 집행률 보고서 정리해줘"라고 했더니, 데이터 없이 **원가 초과 항목 5건과 후속 조치 7건이 서로 매칭되지 않게** 정리됨. 원인, 담당 부서, 예상 영향 금액이 서로 어긋납니다.

### 그래서 어떻게 해야 하나?

**AI 활용의 황금 법칙 3가지**
1. **AI 결과물은 "초안"이다** → 반드시 본인 전문성과 원본 자료로 검증
2. **수치/기준은 반드시 교차 검증** → 예산서, 실행예산, ERP/회계 시스템, 계약서, 내부 기준 원문 확인
3. **맥락을 구체적으로 줄수록 환각이 줄어든다** → 프롬프트 엔지니어링이 핵심

### 3 요소 적용 전 vs 후 비교
**❌ 3 요소 없이 질문한 경우:**
```markdown
이번 달 원가 보고서 정리해줘
```
→ 결과: 어떤 프로젝트인지, 어떤 기준의 원가인지, 어떤 형식인지 모르니 **일반적이고 뻔한 내용**만 나옴
**✅ 3요소를 적용한 경우:**
```markdown
## 역할
당신은 교육기관 현장 원가관리 담당자입니다.

## 맥락
- 프로젝트: ○○아파트 신축공사
- 기준월: 2026년 5월 월마감
- 검토 대상: 실행예산 대비 누계 집행률
- 주요 공종: 토공, 골조, 마감, 기계, 전기
- 특이사항: 골조 공종 집행률이 계획 대비 8%p 높고, 마감 공종은 기성 청구가 지연됨
- 결정사항 5건, 액션아이템 7건 발생

## 출력 형식
1. 보고 개요 (기준월/대상/작성자, 표 형태)
2. 공종별 예산 대비 집행 현황
3. 주요 차이 원인 (표: 번호 / 공종 / 차이 / 원인)
4. 액션아이템 (표: 번호 / 할 일 / 담당자 / 기한)
```
→ 결과: **실제 발송 가능한 수준**의 월간 비용·집행 보고서가 구체적으로 생성됨

형식을 바꾸고 싶을 때

"이걸 \[ \] 형식으로 정리해줘"

"이걸 공종별 표 형식으로 정리해줘"

**고도화 핵심: "다시 해줘" ❌ → "2번 항목을 더 구체적으로, 표 형식으로" ✅**
구체적으로 뭐가 문제인지, 어떻게 바꿔달라는지 말해야 AI가 제대로 수정합니다.
보통 **3번 정도 수정 요청**을 거치면 바로 쓸 수 있는 수준의 결과물이 나옵니다.

### 리라이팅 실습 1: 월간 원가 회의록

**미션: 아래 "Before" 프롬프트를 3요소를 적용한 "After"로 리라이팅하세요.**
**Before (개선 전):**
```markdown
오늘 월간 원가 회의록 써야 하는데 도와줘.
골조비 초과랑 마감 기성 지연, 현금 집행 일정 이야기했고
결정사항 5건 액션아이템 7건 나왔어.
```
**After (개선 후) — 아래를 참고하여 본인의 업무에 맞게 수정해보세요:**
```markdown
## 역할
당신은 교육기관 현장 원가관리 담당자입니다.

## 맥락
- 프로젝트: ○○아파트 신축공사
- 회의명: 5월 월간 원가 점검 회의
- 일시: 2026년 5월 6일 (화) 14:00~16:00 / 본사 회의실 A
- 참석자: 사업본부 3명, 현장 원가 담당 4명, 공무·공사 담당 5명
- 주요 논의: 골조 공종 집행률 초과 / 마감 기성 청구 지연 / 6월 현금 유출 집중
- 결정사항 5건, 액션아이템 7건 발생

## 출력 형식
다음 구조의 회의록을 작성해줘:
1. 회의록 헤더 (회의명, 일시/장소, 작성자)
2. 참석자 (표: 소속/직위/성명)
3. 안건별 논의 내용 요약 (3개 안건)
4. 결정사항 (표: 번호 / 내용 / 근거)
5. 액션아이템 (표: 번호 / 할 일 / 담당자 / 기한)
6. 다음 회의 일정 및 준비 사항
```
**진행 방법:**
1. 위 "After" 프롬프트를 ChatGPT에 입력
2. 생성된 회의록을 확인
3. 본인의 실제 회의 상황으로 맥락을 수정하여 다시 시도

### 리라이팅 실습 2: 예산 초과 검토 요청 메모

골조비가 예산보다 많이 나와서 검토 요청 메모 좀 써줘.

## 역할

- 회신 기한: 2026.05.13 (목)
- 목적: 예산 초과 원인 검토 및 후속 조치 요청

## 출력 형식
1. 메모 제목
