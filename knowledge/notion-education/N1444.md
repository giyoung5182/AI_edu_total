# 3.1 워크시트 발표 — 에이전트 설계 공유·피드백

정리일: 2026-10-08 · 교육 에셋 N1444

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
지난주 과제로 채워 온 시스템 프롬프트 워크시트를 발표하고 피드백 체크리스트로 동료와 강사가 점검한다. 평가가 아니라 빠진 것을 스스로 발견하는 공유의 자리다.
## 진행 단계
1. **어떤 업무를 골랐나** — 어떤 반복 업무를 에이전트로 만들기로 했는지, 왜 골랐는지 말한다.
2. **불편한 점** — 그 업무에서 가장 번거로운 점, AI로 해결되면 가장 좋을 것 한 가지.
3. **시스템 프롬프트 읽기** — RCTC+K 각 요소를 직접 읽는다. K에 무엇을 넣었는지, 특히 보안 이슈가 없는지.
4. **테스트 계획** — 어떤 한 줄로 테스트할 계획인지, 테스트했다면 결과 공유.
5. **한계 공유·피드백** — 막혔던 부분을 솔직하게 말하고, 동료가 잘된 점 하나 + 보완할 점 하나를 말한 뒤 강사가 마무리한다.
- 정상 결과: 체크리스트의 R(구체적 역할) / C(내 상황 포함) / T(단계로 쪼개짐) / C(규칙 3개 이상) / K(핵심 정보·보안 문제 없음)
## 막히는 지점
- 역할은 있는데 규칙이 너무 적음 → "지금 그 업무를 직접 할 때 매번 신경 쓰는 게 뭐예요?"
- 규칙이 너무 추상적 → "친근하게"를 구체적 숫자·형식으로
- K(정보)가 비어 있음 → AI가 지어냄(환각)
- 과업이 너무 넓음 → 더 구체적인 단계로
