# 이어 붙이기

**소요 20분** · 3교시에 만드신 Gems가 만드는 **바로 그 문서**를 완성합니다.


**무엇을 만드는지는 사람마다 다릅니다**
3교시에 규격 검토 Gems를 만드셨으면 **검토표**가 나오고,
API 명세 정리 Gems를 만드셨으면 **명세 정리 문서**가 나옵니다.
**Gems가 만들도록 설계한 것을 실제로 한 번 만들어 보는 시간**입니다.

## Step 01 :: Notebook에서 근거를 뽑습니다 (5분)
4교시에서 만든 노트북에서 필요한 항목을 **출처와 함께** 메모장에 옮깁니다.
## Step 02 :: 사람이 대조합니다 (5분)
숫자가 들어간 것만 원문과 맞춰 봅니다.

**\[확인 필요\]가 남은 항목은 Gems로 넘기지 마십시오.**
그대로 넘기면 Gems가 **그 칸을 채워버립니다.**

## Step 03 :: Gems로 문서를 만듭니다 (5분)
3교시에서 만든 Gems에 확인된 근거를 붙여넣습니다.
## Step 04 :: 숫자만 다시 보고 마감합니다 (5분)

**마감 전 30초 점검**
- \[확인 필요\] 표시가 남아있지 않은가
- 수치가 전부 원문과 같은가 (단위 포함)
- 문서에 없는 조항 번호가 붙지 않았는가
- 근거 없는 단정 문장이 들어가지 않았는가


**서로 봐 주세요** · 5분
옆 분과 바꿔 보고 **하나만** 확인해 주시면 됩니다. 「이 숫자는 어디서 나왔나요?」
제조사나 발주처가 묻는 질문도 결국 이겁니다.

**하네스와 루프를 구분하시면 됩니다**
검증 절차를 만들어 둔 것까지는 **하네스**입니다.
검증이 실패했을 때 **사람이 보고 판단한다면 아직 하네스**입니다.
**AI가 스스로 고쳐서 다시 돌리고, 기준을 통과할 때까지 반복**해야 루프입니다.


**루프가 실패하는 이유는 성능이 아니라 출구입니다**
잘 설계된 루프는 이 세 가지를 스스로 판단해 멈춥니다.
기준을 통과했다 · 더 이상 의미 있는 변화가 없다 · 여기부터는 사람의 판단이 필요하다

그래프는 여러 루프를 엮는 것입니다. 루프는 AI 하나가 혼자 반복하며 일하고, 그래프는 여러 AI가 서로 일을 넘기며 일합니다.
`변경 분류 → 영향 범위 분석 → 문서 갱신 → 검증 → 통과한 것만 커밋`
다만 **AI 하나를 제대로 돌리는 것부터** 되어야 합니다.

**오늘 여러분은 2단계까지 오셨습니다**
관심 있으시면 **Claude Code**나 **Cursor**를 찾아보시면 됩니다.
설치와 개발 환경이 필요해 오늘 실습에는 넣지 않았습니다.
다만 **지시문을 쓰는 법은 똑같습니다.** 오늘 만든 R.O.P.E.+K가 그대로 들어갑니다.
