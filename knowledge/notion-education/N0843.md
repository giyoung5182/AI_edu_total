### 발표 방식
1인당 2분. 아래 3가지를 공유합니다.
```plain text
① 어떤 파일을 골랐는가 (파일 종류 + 이유)

② DSRF를 어떻게 작성했는가
   [D] 어떻게 설명했는지
   [S] 무엇을 분석하려 했는지
   [R] 어떤 형식으로 요청했는지
   [F] 무엇을 제외했는지

③ 결과가 어떻게 나왔는가
   잘 됐으면: 어떤 점이 좋았는가
   막혔으면: 어디서 막혔는가 (이게 더 중요합니다)
```
> **과제를 못 하신 분:** 발표 안 하셔도 됩니다. Ch 4에서 직접 해봅니다.

### 강사 피드백 — 잘 쓴 프롬프트 라이브 분해
발표를 들으면서 강사가 **잘 쓴 프롬프트 1개**를 골라 왜 잘 썼는지 실시간으로 분해합니다.
**분해 기준:**





요소

확인 포인트




**\[D\]**

파일명·시트명·열 구조까지 구체적으로 명시했는가




**\[S\]**

"분석해줘"가 아니라 원하는 결과를 역방향으로 생각해서 질문을 설계했는가




**\[R\]**

표·글·파일 등 형식이 명시됐는가. 정렬·개수 등 세부 조건이 있는가




**\[F\]**

합계 행·오류값·코드 제거 등 필터가 명시됐는가


**강사가 자주 보완해주는 것들:**
```plain text
[D] 추가 포인트:
   "파일은 알려줬는데 어떤 시트인지 명시가 없으면
    AI가 임의로 시트를 선택합니다."

[S] 추가 포인트:
   "분석 목적이 없으면 AI가 결과를 어디에 쓸지 모릅니다.
    '이 정보로 ___에 활용할 예정이야'를 추가하면
    결과의 깊이가 달라집니다."

[F] 추가 포인트:
   "2회차에서 겪은 오류를 [F]에 미리 명시하면
    같은 오류가 반복되지 않습니다.
    예: '합계 행 제외 / 소수점 발생 시 정수로 표시'"
```

## 0-2. 2회차 Q&A (10분)
2회차 이후 실제 업무에서 써보다가 생긴 질문을 공유합니다. 아래는 자주 나오는 질문 미리 정리입니다.
---
**Q1. 새 채팅을 열면 앞에서 한 분석 내용이 사라져요.**
AI는 새 채팅에서 이전 대화를 기억하지 않습니다. 연속된 분석을 할 때는 같은 채팅을 이어서 씁니다. 오늘 Ch 1\~2 실습이 같은 채팅을 이어서 쓰는 방식으로 설계돼 있습니다. 직접 경험해보세요.
단, 채팅이 너무 길어지면 AI가 앞 내용을 잊는 경우가 생깁니다. 이럴 때는 핵심 데이터만 다시 붙여넣는 방식으로 대처합니다.
---
**Q2. 같은 프롬프트인데 결과가 매번 달라요.**
AI는 매번 동일한 결과를 보장하지 않습니다. 이것은 버그가 아니라 AI의 특성입니다. 결과가 달라서 문제가 생길 때의 대처법:
```plain text
① [F]에 조건을 더 구체적으로 추가
   "수량은 반드시 정수로 표시. 소수점 금지."
   "품목 수는 반드시 10개. 더 많거나 적으면 안 됨."

② 결과 검증 질문 추가
   "분석에 사용된 품목 수가 몇 개야?" → 기대값과 대조

③ 중요한 결과는 항상 원본 파일과 샘플 대조
```
---
**Q3. 파일이 너무 커서 Claude가 못 읽는다고 해요.**
Claude Pro는 파일당 최대 30MB까지 가능합니다. 실제 원자재입고양식처럼 5,000행 이상 파일은 해당 날짜 시트만 별도로 저장해서 올립니다.
오늘 실습 파일은 미리 최적화해서 드립니다. 실제 업무에서 큰 파일을 다룰 때의 팁:
```plain text
① 해당 날짜 시트만 별도 파일로 저장
   (파일 → 다른 이름으로 저장 → 해당 시트만 선택)

② 필요한 열만 남기고 나머지 삭제 후 업로드

③ CSV로 변환 후 업로드 (용량 대폭 감소)
```
---
**Q4. AI 결과를 그냥 써도 되나요?**
2회차에서 다룬 Human-in-the-Loop 개념입니다. AI 결과는 항상 초안입니다. 오늘 보고서 실습에서 검증 3단계를 다시 연습합니다.
```plain text
검증 1: "분석에 사용된 품목 수가 몇 개야?" → 기대값 대조
검증 2: 임의 항목 2~3개를 원본 파일에서 직접 확인
검증 3: AI가 모르는 현장 맥락을 담당자가 추가
```

## 0-3. 오늘 교육의 위치
3회차가 전체 12회차 중 어디에 있는지 파악하면 오늘 배우는 것의 의미가 달라집니다.
```plain text
1회차: 비정형 → 정형 (변환)
   사진·메신저 → 표

2회차: 정형 → 대조·집계 (분석)
   엑셀 → 현황·이상값

3회차: 결과 → 보고서 (시각화·전달)  ← 오늘
   분석 결과 → 차트·인포그래픽·보고서

4회차: 반복 → 자동화 (Make.com)
   알림 자동 발송

5회차: 연결 → GAS (자동화 심화)
   두 파일 자동 연결
```
**오늘 만드는 것들이 4·5회차의 재료가 됩니다.**
오늘 만드는 보고서 템플릿 → 4회차 자동 생성 시스템의 설계도<br>오늘 정리하는 프롬프트 → 라이브러리에 저장 후 전 회차 재사용

## 0-4. 오늘 쓰는 새 도구 — NotebookLM 소개
Ch 0에서 오늘 처음 쓰는 NotebookLM을 간단히 소개합니다.
### NotebookLM이란
Google이 만든 AI 기반 노트 도구입니다. Claude가 **프롬프트 중심**이라면 NotebookLM은 **소스(문서·데이터) 중심**입니다.
내가 올린 소스 안에서만 답합니다. 즉 "내 데이터를 기반으로 분석해줘"가 NotebookLM의 핵심입니다.

## 과제 ③ 잘 된 사례 vs 아쉬운 사례 — 강사 준비 메모
과제 발표를 들으면서 강사가 피드백을 줄 때 참고하는 기준입니다. 수강생도 이 기준으로 본인 프롬프트를 평가해볼 수 있습니다.
**잘 된 DSRF의 기준:**
```plain text
[D] ✅ 파일명·시트명이 명시됨
    ✅ 열 구조가 설명됨 ("A열: 날짜 / B열: 품목명 / C열: 수량")
    ✅ 데이터의 맥락이 설명됨 ("이 파일은 매일 오전 업데이트됨")

[S] ✅ "분분석해줘"가 아닌 구체적 질문
    ✅ 활용 목적이 명시됨 ("발주 계획 수립에 활용")
    ✅ 분분석 범위가 명확함 ("5월 한 달치 기준")

[R] ✅ 출력 형식이 구체적 (표/글/파일 등)
    ✅ 정렬 기준 명시 (내림차순/오름차순)
    ✅ 개수·분량 명시 (TOP 10 / A4 1페이지)

[F] ✅ 제외할 행·열 명시 (합계 행 제외)
    ✅ 오류값 처리 방법 명시 (#N/A 제외)
    ✅ 출력 형식 주의사항 (소수점 없이 정수로)
```
**자주 보이는 아쉬운 패턴:**





패턴

문제

개선 방법




\[D\]에 "엑셀 파일이야"만 씀

어떤 시트인지 AI가 모름

시트명·열 구조 추가




\[S\]에 "분분석해줘"

무엇을 분분석할지 AI가 임의로 결정

구체적 질문으로 변경




\[F\]가 없음

합계 행 포함, 소수점 발생 등 예상 오류 발생

2회차에서 겪은 오류를 \[F\]에 추가




결과 검증을 하지 않음

AI 결과를 그대로 사용

## 오늘 교육에서 처음 나오는 개념들
오늘 처음 다루는 개념들을 미리 알아두면 실습 중 덜 헷갈립니다.
**1. 피벗 테이블**<br>대량 데이터를 원하는 관점으로 즉시 재구성하는 엑셀 도구. "어떤 기준으로 볼 것인가"를 먼저 결정해야 합니다.
**2. 시각화 (Visualization)**<br>데이터를 차트·그래프·인포그래픽으로 표현하는 것. 목적은 "더 빠르게, 더 정확하게 전달"입니다.
**3. 인포그래픽**<br>숫자에 의미와 스토리를 담은 시각 자료. 단순 차트보다 한 단계 높은 커뮤니케이션 도구입니다.
**4. NotebookLM**<br>Google의 AI 노트 도구. 내가 올린 소스(문서·데이터) 안에서만 답하므로 할루시네이션(없는 내용을 지어내는 것) 위험이 낮습니다.
**5. Claude for PowerPoint**<br>PowerPoint 안에서 Claude를 사용하는 추가 기능. Claude Pro 구독자는 추가 비용 없이 설치 가능합니다.

### G.I.G.O — 오늘도 적용됩니다
> **G.I.G.O: Garbage In, Garbage Out**<br>잘못된 데이터를 넣으면 잘못된 결과가 나온다.
2회차에서 원자재입고양식에 'o' 문자 오입력이 있었습니다. 오늘 재고파악 실습 파일에도 비슷한 상황이 생길 수 있습니다.
**오늘 실습에서 G.I.G.O 방지 체크:**
```plain text
① 파일 업로드 후 가장 먼저:
   "이 파일에 숫자가 아닌 값이 있어? 있으면 알려줘."

② 결과가 나왔을 때:
   "이 결과에 소수점이 포함됐어? 있으면 어떤 값이야?"

③ 보고서 작성 전:
   "핵심 수치 3개를 원본 파일에서 다시 확인해줘."
```

## 오늘 새로 배우는 개념 — 미리 읽어두기
**시각화의 3단계:**
```plain text
1단계: 숫자를 표로 정리 (Ch 1 — 피벗)
2단계: 표를 차트·인포그래픽으로 변환 (Ch 2 — 시각화)
3단계: 차트+텍스트를 보고서·슬라이드로 통합 (Ch 3 — 보고서)
```
각 단계가 다음 단계의 입력이 됩니다. Ch 1을 잘 해야 Ch 2·3이 수월합니다.
**NotebookLM과 Claude Pro의 작동 방식 차이:**
```plain text
Claude Pro:
사용자 → 프롬프트 입력 → Claude가 답변 생성
(AI의 학습 데이터 전체를 활용)

NotebookLM:
사용자 → 소스 업로드 → 소스 기반으로만 답변 생성
(내가 올린 문서·데이터 안에서만 답함)

오늘 사용 전략:
분분석·차트·파일 생성 → Claude Pro
소스 기반 요약·인포그래픽·브리핑 → NotebookLM
```

## 자주 묻는 질문 (FAQ) — 오늘 실습 관련
**Q. 같은 채팅을 계속 이어 쓰면 Claude가 앞 내용을 잊지 않나요?**
Claude Pro는 하나의 채팅에서 약 200,000 토큰(약 15만 단어)까지 기억합니다. 오늘 하루 실습 분량으로는 충분합니다. 다만 채팅이 매우 길어지면 앞 내용의 세부 사항을 놓칠 수 있으므로 중요한 수치는 필요할 때 다시 언급하는 것이 좋습니다.
**Q. NotebookLM은 무료인가요?**
기본 기능은 무료입니다. Google 계정만 있으면 사용할 수 있습니다. 소스 업로드 용량 제한이 있지만 오늘 실습 분량으로는 충분합니다.
**Q. Claude for PowerPoint는 무료인가요?**
Claude Pro 구독자(\$20/월)는 추가 비용 없이 사용 가능합니다. 설치는 PowerPoint 추가 기능에서 "Claude by Anthropic"을 검색해서 추가합니다.
**Q. 오늘 만든 파일들을 어디에 저장해야 하나요?**
구글 드라이브 → 교육기관 AI 교육 → 3회차 (2026.06.12) 폴더를 만들어서 저장합니다. 다음 회차에서 오늘 만든 파일을 활용합니다.
**Q. 보고서 초안을 그대로 제출해도 되나요?**
아닙니다. 반드시 아래 3단계 검증을 거쳐야 합니다:
1. 핵심 수치 3개를 원본과 대조

3. 보고 대상에 맞는 언어인지 확인
AI 초안은 80%입니다. 나머지 20%는 담당자가 채웁니다.

## 2회차에서 발견된 오류 — 3회차에서 반복하지 않기
