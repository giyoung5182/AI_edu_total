# 2. 레퍼런스를 프롬프트로 바꾸는 법
이번 실습의 진짜 기법입니다. 실무에서 가장 많이 쓰게 됩니다.
## 2-1. 왜 필요한가
프롬프트를 아무리 잘 써도 **머릿속에 원하는 그림이 없으면** 좋은 결과가 나오지 않습니다. "세련되게"라고 쓰는 이유는 세련됨의 구체적 형태를 스스로도 모르기 때문입니다. `원리 셋`
레퍼런스를 먼저 찾으면 이 문제가 사라집니다.
## 2-2. 4단계 절차
```plain text
1단계  레퍼런스 수집
       핀터레스트, 비핸스, 노트폴리오에서 검색
       검색어 예: "poster design gradient", "행사 포스터", "IT 세미나 포스터"
       마음에 드는 것 3~5장 저장

2단계  시각 언어로 분해
       AI에게 이미지를 보여주고 요청
       "이 포스터의 시각적 특징을 분석해 줘.
        색상, 도형, 배치, 타이포그래피, 질감으로 나눠서 설명해 줘."

3단계  번역 요청 (여기가 핵심)
       "이 분석 결과를 참고하되 그대로 따라 하지 말고,
        [우리 주제]에 맞는 새로운 포스터 프롬프트를 만들어 줘.
        구조와 에너지는 참고하고 색과 형태는 다르게 가져가 줘."

4단계  생성 및 검수
       나온 프롬프트로 이미지 생성 → 한글 검수 → 부분 수정
```
## 2-3. 3단계를 빠뜨리면 생기는 일
레퍼런스를 그대로 보여 주고 "이렇게 만들어 줘"라고 하면 원본에 근접한 결과가 나옵니다. 남의 디자인을 복제하는 셈입니다. 공공기관 홍보물에서는 문제가 될 수 있습니다. `2권 5-3`
**"그대로 따라 하지 말고 구조만 참고해 달라"는 문장이 반드시 들어가야 합니다.**

# 10. 강사용 메모
## 10-1. 이 실습에서 강조할 것
**첫째, 2번 절차(레퍼런스 → 시각 언어 → 프롬프트)가 오늘의 진짜 기법입니다.** 프롬프트 A·B·C는 결과물일 뿐입니다. 다음에 다른 스타일이 필요할 때 스스로 만들 수 있어야 합니다.
**둘째, "그대로 따라 하지 말고"라는 문장을 반드시 짚으세요.** 저작권 이슈이기도 하고, 실무에서 남의 홍보물과 비슷한 결과물이 나오면 곤란해집니다.
**셋째, 대상에 따라 톤이 달라진다는 점.** 1번 표를 실습 시작 전에 보여 주세요. 그렇지 않으면 "공공기관인데 이래도 되나요" 질문이 나옵니다.
## 10-2. 실습 2와의 연결
같은 사업입니다. 실습 1에서 대외 홍보물을, 실습 2에서 내부 보고자료를 만듭니다.
```plain text
[오픈이노베이션 협업 지원사업]
        │
        ├─→  실습 1  스타트업 모집 포스터      (대외, 이미지)
        │
        └─→  실습 2  상반기 실적 보고 발표자료  (내부, 설계서)
```
마무리에서 이 그림을 한 번 보여 주면 2권 5-1 통합 워크플로우가 자연스럽게 이해됩니다.
## 10-3. 예상 질문
**Q. 핀터레스트 이미지를 그대로 업로드해도 되나요.**<br>분석 목적의 참고는 가능하지만, 결과물이 원본과 유사해지지 않도록 "구조만 참고하고 색과 형태는 다르게" 지시를 반드시 넣으라고 안내하세요.
**Q. 색상 코드는 어디서 얻나요.**<br>기관 CI 매뉴얼에 있습니다. 없으면 기존 홍보물을 캡처해 "이 이미지의 주요 색상 코드를 알려 줘"로 추출할 수 있습니다.
**Q. 이렇게 만든 포스터를 바로 인쇄해도 되나요.**<br>2권 5-3 용도별 기준을 확인하세요. 인쇄물은 해상도와 라이선스를 별도로 검토해야 합니다.
