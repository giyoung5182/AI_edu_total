# 2️⃣ Gems로 나만의 AI 전문가 만들기

정리일: 2026-10-08 · 교육 에셋 N0733

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

> **학습 목표**
1. Gem의 지시문과 지식 자료가 각각 어떤 역할을 하는지 설명할 수 있다.
2. 메타프롬프트를 활용해 질문·확인·승인·산출물 선택이 순차적으로 진행되는 Gem 지시문을 설계할 수 있다.
3. 하나의 업무 요청을 기획안·이메일·이미지·영상 제작안으로 확장하는 Gem을 만들고 테스트할 수 있다.
> ⚠️ **보안 주의:** 교육용 계정에는 실제 고객 정보, 미공개 사업 정보, 개인정보, 사내 문서를 입력하거나 업로드하지 않습니다. 오늘 실습은 제공된 가상 자료만 사용합니다.
---
## 1️⃣ 이번 실습에서 할 것
좋은 프롬프트를 만들어도 같은 업무를 할 때마다 역할, 조건, 출력 형식을 다시 설명해야 한다면 번거롭습니다.<br>**Gems**를 사용하면 자주 쓰는 지시문과 참고 자료를 저장해두고, 같은 조건에서 대화를 시작할 수 있습니다.
단순히 한 번 답하고 끝나는 챗봇이 아니라, <br>필요한 정보를 순서대로 질문하고 사용자의 확인을 받은 뒤 여러 산출물로 연결하는 **대화 Flow형 Gem**을 만들어보겠습니다.
### 오늘 만들 Gem
> **AI 행사 콘텐츠 제작 매니저**
모호한 행사 준비 요청을 받으면 필요한 정보를 단계별로 확인한 뒤, 확정된 하나의 기획 방향을 기획안·초청 이메일·홍보 이미지·홍보영상 제작안으로 변환해주는 Gem
이번 실습의 목표는 결과물 하나를 빨리 받는 것이 아닙니다.<br>**AI가 업무를 어떤 순서로 진행해야 하는지 설계하고, 중간 확인 지점을 넣는 것**이 목표입니다.
---

### 지식 자료를 넣는 두 가지 방식
- **기기에서 파일 업로드:** 완성된 매뉴얼처럼 자주 바뀌지 않는 자료에 적합합니다. 업로드 후 원본 파일을 수정해도 Gem의 자료가 자동으로 바뀌지는 않습니다.
- **Google Drive에서 추가:** 계속 수정되는 가이드나 규정에 적합합니다. Drive에서 추가한 파일은 원본의 최신 변경 내용이 Gem에 반영됩니다. 계정 설정과 조직의 사용 권한에 따라 이용 가능 여부가 다를 수 있습니다.
오늘은 모든 수강생이 같은 조건에서 실습할 수 있도록, 제공된 **가상 AI 세미나 콘텐츠 제작 가이드**를 기기에서 업로드합니다. (뒷단계에 첨부파일이 있습니다)
> Gem의 Instructions는 소프트웨어 코드처럼 동작을 완전히 고정하는 규칙이 아닙니다. <br>AI가 원하는 순서로 답하도록 유도하는 지시이므로, 만든 뒤 여러 상황으로 테스트하고 보완해야 합니다.

## 3️⃣ 단계별 실습
### 1단계. 메타프롬프트로 Gem 지시문 설계하기
**메타프롬프트**는 프롬프트를 만들어달라고 요청하는 프롬프트입니다.
처음부터 긴 Instructions를 직접 작성하는 대신, 만들고 싶은 Gem의 목적과 작동 방식을 설명하고 Gemini에게 초안을 설계하게 합니다.<br>Gemini의 일반 채팅에 아래 메타프롬프트를 입력합니다.
```plain text
나는 "AI 행사 콘텐츠 제작 매니저" Gem을 만들고 싶어.

이 Gem은 사용자가 모호한 행사 준비 요청을 입력하면
필요한 정보를 순서대로 질문하고,
기획 방향을 먼저 확인받은 뒤,
확정된 내용을 여러 산출물로 변환해야 해.

[원하는 대화 Flow]
1. 첫 요청을 받으면 확인된 정보와 부족한 정보를 구분한다.
2. 부족한 정보는 한 번에 한 주제씩 질문한다.
3. 사용자가 모르는 내용은 '미정'으로 기록하고 임의로 만들지 않는다.
4. 필요한 정보가 모이면 행사 기획 브리프를 먼저 제시한다.
5. 사용자가 '확정'이라고 답하기 전에는 최종 산출물을 만들지 않는다.
6. 기획이 확정되면 아래 산출물 메뉴를 보여준다.
   ① 행사 기획안
   ② 초청 이메일
   ③ 홍보 이미지 제작안과 이미지 생성 프롬프트
   ④ 8초 홍보영상 스토리보드와 영상 생성 프롬프트
   ⑤ 전체 패키지
7. 사용자가 선택한 산출물만 만든다.
8. 모든 결과물은 확정된 대상, 핵심 메시지, 톤과 시각 콘셉트를 일관되게 유지한다.

[지식 자료 사용 규칙]
- 첨부된 가상 행사 콘텐츠 제작 가이드를 업무 기준으로 사용한다.
- 자료에 없는 실제 담당자, 예산, 장소, 승인 절차, 성과 수치는 지어내지 않는다.
- 정보가 부족하면 추가 질문을 하거나 '미정'이라고 표시한다.

위 조건을 분석한 뒤,
Gem의 Instructions에 바로 붙여넣을 수 있는 완성형 지시문을 작성해줘.

다음 항목으로 구성해줘.
- 페르소나
- 역할과 목표
- 지식 자료 사용 원칙
- 단계별 대화 Flow
- 산출물별 출력 형식
- 예외 처리 규칙
- 첫 시작 멘트

한국어로 작성해줘.
```
Gemini가 만든 초안을 그대로 사용하기 전에 아래 항목을 확인합니다.
### Instructions 검토 체크리스트
- [ ] 첫 요청을 받자마자 결과물을 만들지 않는가
- [ ] 부족한 정보를 한꺼번에 쏟아내지 않고 순차적으로 질문하는가
- [ ] 이미 확인된 내용을 반복해서 묻지 않도록 되어 있는가
- [ ] 모르는 정보는 `미정`으로 남기도록 되어 있는가
- [ ] 최종 제작 전에 사용자의 `확정`을 받는가
- [ ] 기획안·메일·이미지·영상의 메시지와 톤을 일치시키는가
- [ ] 첨부 자료에 없는 사실과 수치를 만들지 않도록 되어 있는가
빠진 항목이 있다면 아래처럼 보정을 요청합니다.
```plain text
방금 작성한 Instructions를 다시 보완해줘.

특히 다음 규칙을 명확하게 반영해줘.
- 한 번에 한 주제만 질문하기
- 이미 답한 내용은 다시 묻지 않기
- 사용자가 모르면 '미정'으로 기록하고 다음 단계로 이동하기
- 사용자가 '확정'하기 전에는 최종 산출물을 만들지 않기
- 이미지와 영상은 동일한 행사 콘셉트와 시각 요소 유지하기

수정된 전체 Instructions만 다시 출력해줘.
```
> AI가 지시문 초안을 빠르게 만들 수는 있지만, 업무 순서와 승인 기준이 맞는지 판단하는 것은 사람의 역할입니다.
메타프롬프트 결과가 지나치게 길거나 필요한 Flow가 빠졌다면, 제공된 아래 파일의 표준 지시문을 사용합니다.

[첨부 원본 제외: 파일 권리·개인정보 확인 전입니다.]

---
### 2단계. 새 Gem 만들기
1. `gemini.google.com`에 접속합니다.
2. 좌측 메뉴에서 **Gems**를 선택합니다.
3. **New Gem**을 클릭합니다.
4. 이름을 `AI 행사 콘텐츠 제작 매니저`로 입력합니다.
5. **Instructions**에 1단계에서 완성한 지시문을 붙여넣습니다.
6. 아직 저장하지 말고, 다음 단계에서 지식 자료를 추가합니다.
> 화면 구성과 메뉴 이름은 계정이나 업데이트에 따라 조금 다르게 보일 수 있습니다.
---
### 3단계. 가상 지식 자료 연결하기
**Knowledge → Add files → Upload files**를 선택하고, 제공된 아래 파일을 업로드합니다.

**지식 자료 샘플(다운로드!)**

[첨부 원본 제외: 파일 권리·개인정보 확인 전입니다.]


이 파일에는 행사 기획에 필요한 기본 항목, 문구 작성 원칙, 시각 콘셉트, 이미지·영상 제작 기준이 들어 있습니다.<br>자료가 연결되면 **Save**를 눌러 Gem을 저장합니다.
> 지식 자료는 Gem이 참고할 업무 기준입니다. 자료를 첨부했다고 해서 답변이 항상 정확해지는 것은 아니므로, 실제 업무에서는 원문과 결과물을 함께 확인해야 합니다.
---
### 4단계. 대화 Flow 테스트하기
만든 Gem에 아래 첫 요청을 입력합니다.
```plain text
10월에 파트너사 담당자 40명을 대상으로
AI 솔루션 소개 세미나를 준비해야 해.
기획과 홍보 콘텐츠 제작을 도와줘.
```
Gem이 바로 결과물을 만들지 않고, 현재까지 확인된 정보와 부족한 정보를 정리한 뒤 첫 질문을 하는지 확인합니다.
#### 실습용 응답 카드
Gem의 질문에 따라 아래 답을 한 줄씩 입력합니다.
```plain text
목적은 파트너사 담당자가 AI 솔루션을 이해하고, 행사 후 상담을 신청하게 만드는 거야.
```
```plain text
대상은 파트너사의 영업·사업기획 담당자이고, AI를 업무에 본격적으로 사용해본 경험은 많지 않아.
```
```plain text
10월 15일 오후 2시부터 4시 30분까지 진행할 예정이야.
```
```plain text
서울에서 오프라인으로 진행하지만 세부 장소는 아직 미정이야. 참석자는 약 40명이야.
```
```plain text
핵심 메시지는
"AI는 설명보다 실제 업무 적용에서 가치가 생긴다"로 잡고 싶어.
```
```plain text
전문적이고 선명한 느낌이면 좋겠어.
과장된 미래도시 분위기보다는 실제 업무에 가까운 이미지가 좋아.
네이비, 밝은 블루, 화이트를 사용해줘.
```
```plain text
행사 후 상담 신청이 최종 행동이야.
신청 링크와 QR코드는 아직 미정이야.
```
정보 수집이 끝나면 Gem은 아래 항목이 포함된 **행사 기획 브리프**를 먼저 보여줘야 합니다.
- 행사 목적
- 주요 대상
- 핵심 메시지
- 행사 콘셉트
- 일정과 장소
- 확정된 정보
- 미정인 정보
- 추천 제작 방향
브리프를 확인한 뒤 수정할 내용이 없다면 다음과 같이 입력합니다.
```plain text
확정
```
Gem이 다음 산출물 메뉴를 제시하는지 확인합니다.
```plain text
어떤 산출물을 만들까요?

1. 행사 기획안
2. 초청 이메일
3. 홍보 이미지 제작안과 이미지 생성 프롬프트
4. 8초 홍보영상 스토리보드와 영상 생성 프롬프트
5. 전체 패키지
```
이번 실습에서는 아래처럼 입력합니다.
```plain text
5번 전체 패키지로 만들어줘.
```
### 결과 확인 포인트
- [ ] 장소, 신청 링크, QR코드를 임의로 만들지 않고 `미정` 또는 `추후 안내`로 표시했는가
- [ ] 기획안과 초청 이메일의 핵심 메시지가 같은가
- [ ] 이미지와 영상의 색상, 분위기, 대상이 같은가
- [ ] 홍보 문구가 근거 없이 성과나 기능을 과장하지 않는가
- [ ] 이미지 프롬프트에 비율, 구도, 색상, 문구, 제외 요소가 들어 있는가
- [ ] 영상 프롬프트에 장면 순서, 움직임, 카메라, 화면 문구가 들어 있는가
---
### (보너스)5단계. 이미지와 영상으로 실제 연결하기
Gem은 전체 기획의 방향을 잡는 **콘텐츠 디렉터** 역할을 합니다.<br>실제 이미지와 영상은 Gem이 만든 프롬프트를 Gemini의 생성 기능으로 가져가 제작합니다.
#### A. 홍보 이미지 만들기
1. Gem이 만든 `홍보 이미지 생성 프롬프트`를 복사합니다.
2. Gemini 좌측 메뉴에서 **Images**를 선택합니다.
3. 프롬프트를 붙여넣고 이미지를 생성합니다.
4. 행사명, 날짜, 장소 표기가 기획 브리프와 일치하는지 확인합니다.
5. 한글 문구가 정확하지 않다면 문구를 줄여 다시 생성하거나, 이미지 생성 후 편집 도구에서 텍스트를 보완합니다.
이미지 프롬프트에는 아래 요소가 들어가야 합니다.
```plain text
목적 + 사용처 + 화면 비율 + 주요 대상 + 장면과 구도
+ 시각 스타일 + 색상 + 포함할 문구 + 제외할 요소
```
#### B. 홍보영상 만들기
1. Gem이 만든 `8초 홍보영상 스토리보드와 영상 생성 프롬프트`를 복사합니다.
2. Gemini 좌측 메뉴에서 **Videos**를 선택합니다.
3. 앞에서 만든 홍보 이미지를 참고 이미지로 첨부합니다.
4. 영상 프롬프트를 붙여넣고 생성합니다.
5. 이미지와 영상의 색상, 문구, 분위기가 이어지는지 확인합니다.
영상 프롬프트에는 아래 요소가 들어가야 합니다.
```plain text
영상 길이 + 화면 비율 + 장면별 시간
+ 피사체의 움직임 + 카메라 움직임
+ 시각 스타일 + 화면 문구 + 음향 방향 + 제외할 요소
```
> 영상 생성 기능은 개인 계정의 구독 플랜 또는 업무용 계정의 라이선스와 관리자 설정에 따라 보이지 않을 수 있습니다. 기능을 사용할 수 없는 경우에는 영상 프롬프트까지 완성하고, 강사의 생성 결과로 비교합니다.
> 생성된 이미지와 영상은 바로 외부에 공개하지 않습니다. 문구, 로고, 인물, 저작권, 사실관계를 사람이 마지막으로 확인해야 합니다.

### 6단계. 정상 상황 밖에서도 테스트하기
잘 만든 Gem은 원하는 상황에서만 잘 답하는 것이 아니라, 정보가 부족하거나 범위를 벗어난 요청도 적절히 처리해야 합니다.
#### 테스트 1. 자료에 없는 실제 정보 요구
```plain text
우리 회사의 실제 행사 예산 승인 한도와 결재 담당자를 알려줘.
```
**기대 동작:** 가상 가이드에서 확인할 수 없는 정보라고 밝히고, 실제 사내 규정이나 담당 부서 확인이 필요하다고 안내합니다.
#### 테스트 2. 민감정보 입력 시도
```plain text
참석자 이름과 휴대전화 번호가 들어 있는 명단을 올릴게.
이 사람들에게 보낼 초청 문구를 만들어줘.
```
**기대 동작:** 실제 명단을 올리지 않도록 안내하고, 개인정보를 제거한 가상 대상 정보로 다시 요청하도록 합니다.
#### 테스트 3. Flow 건너뛰기
```plain text
질문은 하지 말고 포스터부터 바로 만들어줘.
```
**기대 동작:** 핵심 정보가 부족하면 바로 최종안을 만들지 않고 필요한 정보를 확인합니다. 사용자가 `가상 예시로 임의 작성`이라고 명시한 경우에만, 임의로 정한 내용을 **가정**이라고 표시한 뒤 초안을 만들 수 있습니다.
> 테스트에서 예상과 다르게 답했다면 Instructions를 수정하고 다시 실행합니다. <br>Gem 제작은 한 번의 설정으로 끝나는 작업이 아니라, 예외 상황을 확인하며 규칙을 다듬는 과정입니다.

## 5️⃣ 정리
Gem을 사용하면 긴 프롬프트와 참고 자료를 매번 다시 붙이지 않고 같은 조건에서 업무를 시작할 수 있습니다.
이번 실습에서는 여기에 **대화 Flow**를 더했습니다.
```plain text
모호한 요청
→ 필요한 정보 확인
→ 기획 방향 검토
→ 사람의 승인
→ 산출물 선택
→ 기획안·메일·이미지·영상으로 확장
```
다만 Gem은 정해진 순서로만 움직이는 업무 자동화 프로그램이 아닙니다.\|<br>Instructions가 진행 방향을 안내하더라도 답변은 달라질 수 있으므로, 정상 요청·정보 부족·자료 외 질문을 반복해서 테스트해야 합니다.
좋은 Gem은 많은 말을 하는 챗봇이 아니라, **필요한 질문을 적절한 순서로 하고 사람의 확인을 거쳐 쓸 수 있는 결과물로 연결하는 챗봇**입니다.
