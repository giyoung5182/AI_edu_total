Skill은 메인 Claude가 조리법을 보고 **직접** 만드는 것입니다.<br>서브에이전트는 **다른 Claude에게 일을 떼어주는 것**입니다.
## 결정적 차이 — 기억을 공유하지 않습니다
서브에이전트는 **메인 대화를 물려받지 않습니다.** 깨끗한 상태로 시작합니다.
```plain text
메인 Claude
  │  (지금까지의 대화, 실패한 시도, 온갖 이야기가 쌓여 있음)
  │
  ├─→ 서브에이전트 A   ← 이 일만 알고 시작. 깨끗함
  ├─→ 서브에이전트 B   ← 이 일만 알고 시작. 깨끗함
  └─→ 서브에이전트 C   ← 이 일만 알고 시작. 깨끗함
              ↓
        결과만 메인으로 돌아옴
```
2교시에서 배운 것을 떠올려보세요. **대화가 길어질수록 결과가 나빠집니다.**<br>서브에이전트는 그 문제를 피하는 방법입니다. 긴 작업을 떼어내서 메인 대화를 깨끗하게 유지합니다.

# 3. 언제 쓰면 좋은가
아래 중 **두 개 이상**이면 써볼 만합니다.
```plain text
□ 같은 검토를 여러 번 반복해야 한다
□ 비교할 대상이 많다
□ 한 가지 관점만으로는 놓치는 게 있을 것 같다
□ 중간 결과가 너무 많아 대화가 복잡해진다
□ 결과를 서로 대조해서 확인하고 싶다
```
## 반대로, 쓰면 과한 경우
```plain text
□ 질문 하나에 답만 받으면 되는 경우
□ 단순 요약이나 정리
□ 한 번만 하면 끝나는 작은 작업
□ 기준이 아직 명확하지 않은 작업
```
> ⚠️ **오늘 만든 웹 화면 하나**는 여기에 해당합니다. 서브에이전트를 쓰면 오히려 느려집니다.

# 4. 실습 — 폴더를 세 사람이 동시에 살펴보기
> 💡 **2교시에 쓴 ****`sw-practice`**** 폴더를 그대로 씁니다.**<br>이미 정리하셨다면 압축을 다시 풀어 새 폴더로 만드세요.
## 4-1. 왜 이 폴더인가
2교시에는 한 번에 **하나의 기준**으로만 정리했습니다. 차시별로, 또는 종류별로요.
그런데 실제 폴더에는 **여러 문제가 섞여 있습니다.**
```plain text
· 이름 규칙이 제각각이다
· '최종', '진짜최종', '복사본'이 뒤섞여 있다
· 사진이 정리가 안 되어 있다
· 지난 학기 자료가 섞여 있다
· 그리고 — 여기 있으면 안 될 파일도 있다   ← 2교시에는 못 봤을 겁니다
```
**한 명에게 다 시키면 놓칩니다.** 정리에 집중하다 보면 위험한 파일을 그냥 옮겨버립니다.
그래서 **세 사람에게 각각 다른 눈으로** 보게 합니다.
## 4-2. 해보기
새 세션을 열고 `sw-practice` 폴더를 선택한 뒤 아래를 넣으세요.
```plain text
이 폴더를 세 가지 관점에서 각각 따로 살펴봐줘.
서브에이전트를 활용해서 나눠서 진행해줘.

1) 구조 담당
   어떤 폴더 구조로 나누면 좋을지 제안해줘.
   기준을 두세 가지 제시하고 각각의 장단점도 알려줘.

2) 중복 담당
   같은 내용인데 이름만 다른 파일,
   버전이 여러 개인 파일을 전부 찾아줘.
   어떤 걸 남기고 어떤 걸 지울지도 제안해줘.

3) 위험 담당
   이 폴더에 있으면 안 될 것 같은 파일을 찾아줘.
   개인적인 내용이거나, 다른 사람과 공유하면 곤란한 것.
   왜 그렇게 판단했는지도 알려줘.

세 가지 결과를 각각 보여준 다음,
마지막에 종합해서 정리 계획을 제안해줘.
아직 파일은 옮기지 마.
```
> 💡 마지막 줄을 꼭 넣으세요. 1교시에서 배운 **"하지 말아야 할 것"** 입니다.
## 4-3. 무엇을 보게 되나요
**구조 담당**은 2교시와 비슷한 답을 냅니다. 차시별, 종류별, 시기별 같은 기준들이요.
**중복 담당**은 이런 것들을 찾아냅니다.
```plain text
· 4차시 활동지(최종).docx  vs  4차시 활동지(진짜최종).docx
· 발표자료.pptx  vs  발표자료_final.pptx
· 2차시_수정.docx  vs  복사본_2차시_수정.docx
· 수업계획.xlsx  vs  수업계획_수정본.xlsx
```
**위험 담당**이 가장 흥미롭습니다. 아마 이 둘을 짚어낼 겁니다.
```plain text
· 개인_건강검진결과_2026.docx
· 연락처.txt
```
> 💡 **2교시에 이 파일들을 눈여겨보셨나요?**<br>대부분 그냥 지나쳤을 겁니다. **정리에 집중하면 위험이 안 보입니다.**
이게 관점을 나누는 이유입니다. 한 사람이 여러 눈을 동시에 갖기는 어렵습니다.
## 4-4. 이어서 해볼 것
세 결과를 받은 뒤, 종합 계획이 마음에 들면 이렇게 진행합니다.
```plain text
좋아. 그 계획대로 진행하되,
위험 담당이 짚은 파일들은 옮기지 말고 그대로 둬.
대신 '따로_확인.md' 파일에 목록만 적어줘.
```
> 💡 **자동으로 지우게 하지 마세요.** 사람이 판단할 것은 사람에게 남깁니다.

# 6. 주의할 것
## ① 비용이 큽니다
서브에이전트를 여러 개 띄우면 각각이 따로 일합니다. **그만큼 사용량이 늘어납니다.**
```plain text
· 작은 작업으로 먼저 시험해보기
· 한 번에 3~5개를 넘기지 않기
· 결과 형식을 미리 정해주기 ("표로 정리해줘")
```
## ② 나눌 기준이 있어야 합니다
```plain text
❌ "여러 명이 나눠서 잘 해줘"
   → 뭘 어떻게 나눌지 모름

✅ "구조 / 중복 / 위험 세 관점으로 나눠서"
   → 각자 볼 것이 분명함
```
**많이 돌리는 것보다 어떤 기준으로 나눌지가 훨씬 중요합니다.**
## ③ 합칠 기준도 정해야 합니다
세 결과가 서로 다른 말을 할 수 있습니다. 그때 어떻게 할지를 미리 정해줘야 합니다.
```plain text
세 결과가 서로 다르면, 어느 쪽을 따를지 이유와 함께 알려줘.
내가 판단할 부분은 질문으로 남겨줘.
```
## ④ 최종 판단은 사람이 합니다
파일을 옮기거나 지우는 것 같은 되돌리기 어려운 일은 **반드시 사람이 확인하고 결정**합니다.

# 7. 정리
```plain text
① 서브에이전트는 "다른 Claude에게 일을 떼어주는 것"이다
② 메인 대화를 물려받지 않아서 깨끗하게 시작한다
③ 여러 관점으로 동시에 봐야 할 때 쓴다
④ 나눌 기준과 합칠 기준을 내가 정해줘야 한다
⑤ 오늘 만든 정도에는 필요 없다
```
> 💡 **급하게 배우실 필요 없습니다.**<br>지금 단계에서 불편한 게 생겼을 때 다음으로 가는 게 맞습니다.<br>필요 없는데 미리 올라가면 복잡하기만 합니다.

## 강사 참고 — 시연할 때
> 🔒 아래는 강사용 메모입니다.
**시연 순서 (5분)**
```plain text
1. "오늘은 안 하실 겁니다"를 먼저 말한다        ← 부담 차단
2. 2교시 폴더를 다시 열어둔다
3. 4-2의 프롬프트를 넣는다
4. 세 결과가 각각 나오는 걸 보여준다
5. 위험 담당이 개인 파일을 짚어내는 순간을 강조   ← 하이라이트
```
💬 **대사 예시**
> "아까 오전에 이 폴더 정리하셨죠.<br>그때 이 파일 보셨어요? (개인_건강검진결과 가리키며)
아마 대부분 그냥 지나치셨을 거예요.<br>**정리에 집중하면 위험한 건 안 보입니다.**
그래서 눈을 나눠보는 겁니다. 정리하는 눈, 중복 찾는 눈, 위험 보는 눈.<br>오늘 만든 정도에는 필요 없지만, 한 학기 자료를 통째로 볼 때는 이게 훨씬 낫습니다."
**실패 대비**: 세 개로 안 나뉘고 한 번에 답하면, 그냥 "결과를 세 관점으로 정리해준 것"으로 설명하고 넘어갑니다. 개념 전달이 목적이지 기능 시연이 목적이 아닙니다.
**⚠️ 사전 확인 필요**: 이 프롬프트로 실제로 나뉘어 진행되는지, 아니면 한 번에 답하는지 리허설에서 확인하세요. 결과에 따라 대사를 조정해야 합니다.
