# 실습 1. 데이터 활용 As-Is / To-Be 분석

정리일: 2026-10-08 · 교육 에셋 N1166

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
공사 DB의 현재 상태를 쿼리로 확인하고, 5개 영역(거버넌스, 품질, 표준화, AI 활용, 플랫폼) 중 2개 이상에 대해 As-Is → To-Be 분석표를 작성합니다.
## 진행 단계
1. **테이블별 데이터 규모·최근 갱신 확인** — information_schema.TABLES 조회
- 입력할 내용:
```sql
SELECT TABLE_NAME AS 테이블명, TABLE_ROWS AS 추정_레코드수, DATA_LENGTH / 1024 AS 데이터크기_KB, CREATE_TIME AS 생성일시, UPDATE_TIME AS 최근_갱신일시
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'kdhc_db'   -- 실습 DB명으로 변경
ORDER BY TABLE_ROWS DESC;
```
- 정상 결과: heat_usage, customers, complaints, facilities, inspection_log 테이블별 레코드 수·갱신일시 표
1. **핵심 테이블 NULL 비율 확인** — heat_usage의 사용량·요금 컬럼 NULL 건수·비율 집계 (UNION ALL 쿼리, 교안 참고)
- 정상 결과: 요금 NULL 5.0%, 사용량 NULL 1.0%
2. **월별 데이터 누적 현황** — DATE_FORMAT으로 연월별 등록 건수 집계
- 정상 결과: 연월별 등록건수 표(예시 월 1284건)
3. **As-Is / To-Be 분석표 작성** — 영역·As-Is·To-Be·주요 과제 4열 표를 2개 영역 이상 작성
## 막히는 지점
- UPDATE_TIME이 수개월 전에 멈춰 있는 테이블은 데이터가 제대로 수집되고 있는지 담당 부서에 확인이 필요
