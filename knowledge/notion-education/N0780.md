# 프롬프트 엔지니어링이란?


## 프롬프트
**= 지시, 질문**
AI에게 보내는 입력 메시지를 뜻합니다. "이 글을 요약해줘"처럼 AI에게 던지는 모든 말이 프롬프트입니다.


## 엔지니어링
**= 깎고 광내는 것**
프롬프트를 더 정교하게 다듬어서 원하는 결과를 얻는 기술입니다.



같은 질문이라도 **어떻게 물어보느냐**에 따라 AI의 답변 품질이 크게 달라집니다. 프롬프트 엔지니어링은 AI를 잘 활용하기 위한 가장 기본적이고 중요한 스킬입니다.

# 프롬프트 엔지니어링 3가지 기법
---

**개괄식으로 정돈해서 설명한다**
장황하게 설명하지 말고, 핵심을 간결하게 정리해서 전달합니다. AI는 구조화된 입력을 더 잘 이해합니다.<br><br>예시)<br>1. 역할 : 개발<br>2. 목표: 대시보드 웹앱 제작<br>3. 기술: react+vite

**예시 비교:**
- ❌ "저는 경영관리 팀에서 일하는데요, 매달 예산 집행 현황을 정리해야 해요. 부서별로 엉킨 데이터를 모아서 보고서를 만드는데..."
- ✅ "역할: 경영관리팀 예산 담당자 / 목표: 매월 부서별 예산 집행 현황 자동 요약 보고서 / 조건: 표 형식, 한국어, 전월 대비 증감률 포함"
---

**프롬프트를 단계별로 하나씩 전달한다 (CoT)**
Chain of Thought — 한 번에 모든 것을 요청하지 말고, 단계별로 나누어 전달합니다. AI가 각 단계를 충실히 수행할 수 있습니다.

**예시:**
- 1단계: "내 업무를 분석해줘"
- 2단계: "분석 결과 중 자동화할 수 있는 부분을 찾아줘"
- 3단계: "자동화 방안을 구체적으로 설계해줘"
---

**역질문기법 : "나를 인터뷰해줘"**
내가 설명하는 대신, AI에게 먼저 질문을 하도록 시킵니다. AI가 필요한 정보를 스스로 물어보면서, 더 정확한 맥락을 파악하게 됩니다.

**예시:**
- "내 업무를 자동화하고 싶어. 먼저 나를 인터뷰해서 어떤 업무인지 파악해줘."
- → AI가 "어떤 부서에서 일하시나요?", "매일 반복하는 작업은 무엇인가요?" 등을 질문
---

# BRD와 PRD — AI에게 정확히 지시하는 방법
AI에게 복잡한 작업을 시킬 때, 그냥 "만들어줘"라고 하면 원하는 결과가 나오지 않습니다. **BRD와 PRD를 먼저 작성하면**, AI가 맥락을 이해하고 정확하게 만들어줍니다.



**BRD** (Business Requirements Document)<br>= **"뭘 만들지?"**<br><br>목표, 배경, 이해관계자, 예산, 제약사항 등<br>비즈니스 관점의 요구사항




**PRD** (Product Requirements Document)<br>= **"어떻게 만들지?"**<br><br>핵심기능, UI 설계, 기술사양, 구현계획 등<br>기술 관점의 요구사항




**활용 흐름**: BRD 작성(뭘 만들지) → PRD 작성(어떻게 만들지) → AI에게 구현 요청하기 위한 계획 생성(plan) → AI에게 구현 요청하기<br>BRD와 PRD도 AI에게 작성을 시킬 수 있습니다! "이런 목적의 BRD를 작성해줘. 내가 결정해야 할 부분은 질문으로 남겨줘."

</details>
<details>
<summary>이해관계자 — 누가 관여하는가?</summary>
프로젝트에 관련된 사람들과 각자의 역할을 정리합니다. 예: "영업팀(주문 관리), 구매팀(재고 등록), IT팀(시스템 유지보수), 고객사(주문 사용자)"
</details>
<details>
<summary>타임라인 — 언제까지 만드는가?</summary>
단계별 마일스톤과 일정을 정합니다. "기획 2주 → 개발 4주 → 테스트 2주 → 배포" 처럼 구체적인 날짜를 잡습니다.
</details>
<details>
<summary>예산 — 얼마나 드는가?</summary>
프로젝트 비용과 기대 효과를 함께 정리합니다. "개발비 3,000만원 vs 영업팀 인건비 절감 연 5,000만원" 처럼 ROI를 보여줍니다.
</details>
<details>
<summary>제약 사항 — 무엇이 발목을 잡을 수 있는가?</summary>
기술적 한계, 보안 규정, 인력 부족 등 예상되는 장애물을 미리 파악합니다. 예: "사내 보안 정책으로 외부 클라우드 사용 불가"
</details>
> BRD에 들어가는 대표적인 분석: **SWOT 분석** (강점·약점·기회·위협), **이해관계자 맵**, **비용 대비 효과 분석**

# 컨텍스트 엔지니어링

바이브코딩에서는 프롬프트 엔지니어링을 기반으로 한 **컨텍스트 엔지니어링**이 가장 중요합니다.

**컨텍스트(Context) = 맥락**. AI에게 단순히 질문을 잘 하는 것(프롬프트 엔지니어링)을 넘어서, AI가 작업에 필요한 **모든 맥락 정보**를 체계적으로 제공하는 것이 컨텍스트 엔지니어링입니다.
### LLM에게 넘겨줘야 하는 정보
- **시스템 지침** : "친절한 튜터처럼 행동해" 또는 "JSON만 출력해"와 같은 규칙
- **사용자 프롬프트** : "이 기사를 요약해 줘"와 같은 특정 질문 또는 작업
- **대화 기록** : 일관성을 유지하기 위한 이전 상호작용
- **외부 데이터** : 모델에 제공되는 **문서**, 데이터베이스 또는 API 결과
- **도구** : 웹 검색이나 파일 조작 같은 **도구**에 대한 접근

사실 LLM을 잘 사용하고 있었던 유저는 이미 어느정도 컨텍스트 엔지니어링을 하고 있었던 것입니다.<br>요청 → 응답 받은 것 직접 실행 → 실행 결과를 LLM에게 공유 → 다시 요청... 이 과정 자체가 맥락을 쌓아가는 것이니까요.
