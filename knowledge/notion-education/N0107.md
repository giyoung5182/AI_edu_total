## Step 01 :: 사람 A와 사람 B — 문서를 넣은 AI는 어떻게 답하는가
### 1-1. 기억으로 답하는 사람 vs 규정집을 펼쳐 보는 사람
- 왜 알아야 하나: 규정집을 넣은 AI의 답도 틀릴 수 있음. 어디를 보고 답했는지 확인하는 습관이 필요





구분

사람 A — 기억으로 답함

사람 B — 규정집을 펼쳐 보고 답함




근거

예전에 들은 것, 다른 회사 경험, 일반 상식

지금 책상 위에 펼친 페이지




약점

우리 회사 규정과 다를 수 있음. 틀려도 자신 있게 말함

**펼친 페이지만큼만 앎.** 엉뚱한 페이지를 펼치면 엉뚱하게 답함




확인 방법

"그거 어디서 봤어요?" → 대답 못 함

"몇 쪽 몇 조예요?" → 페이지를 보여 줌


- 문서를 넣지 않은 AI = 사람 A / 문서를 넣은 AI = 사람 B
- ❌ "자료를 넣었으니 이제 정확함" → ⭕ "어느 근거를 짚었는지 확인해야 맞는지 알 수 있음"
### 1-2. 자료를 찾아 읽고 답하는 방식(RAG: 자료 검색 기반 증강 기술) — 두 단계
- 문서를 넣은 AI는 **자료에서 관련 부분을 찾아 읽고 답함**. 이 방식을 RAG라고 부름
- 쉽게 보려고 **준비 단계**와 **질문 단계**로 나눔
```plain text
[준비 단계] — 질문이 오기 전
  ① 문서 읽기   : 파일에서 글자·표를 꺼냄
  ② 조각 나누기 : 긴 문서를 여러 조각으로 자름
  ③ 찾기 준비   : 관련 조각을 빨리 찾도록 정리

[질문 단계] — 질문이 들어올 때마다
  ④ 질문        : 사용자가 묻는 말
  ⑤ 근거 고르기 : 질문과 관련 있어 보이는 조각을 고름
  ⑥ 답 만들기   : 고른 조각 + 질문 + 지침을 보고 답을 씀
```

5

**근거는 찾았는데 답만 틀림** (⑥ 답 만들기)

칸

**지침** (프로젝트 설정의 **지침** 칸, Instructions)

처리 규칙 — 작업 순서, 확인 방법, 금지, 멈출 때, 응답 양식

**지식** (프로젝트 파일)

근거 자료 — 규정 원문, 문서번호, 시행일·개정일

개인 메모, 버전을 모르는 요약본




**개별 요청** (입력창)

이번 건의 사실 — 고객사·일정·지역·질문

매번 반복하는 규칙

        적용 문서를 단정하지 않는다. 판단에 필요한 정보가 없으면 "확인 필요"와 확인 대상을 쓴다.

## 정리
### 핵심 문장
- 문서를 넣은 AI는 **펼친 페이지만큼만 아는 사람 B** — 어느 근거를 봤는지 확인
- 답이 틀리면 **자료 있나 → 읽혔나 → 찾았나 → 맞게 해석했나 → 결론이 맞나** 순서로 찾고, 틀린 곳만 고침
- 같은 주제를 다르게 정한 문서가 있으면 **둘 다 보여 주고 확인 대상을 적음**
- 지침에는 **처리 규칙**, 지식에는 **근거와 버전**, 요청에는 **이번 건의 사실**
