## 오프닝 공감 대화
교육기관 27은 2004년부터 580개 이상 현장을 수행한 입주관리 종합대행 전문회사입니다. <br>삼성물산·현대건설·대우건설·교육기관 등 1군 건설사를 포함해 전국 3,600명의 매니저 풀을 운영하고 있습니다. 오늘 교육은 이 규모와 이 업무 복잡도에 딱 맞는 AI 활용법을 배웁니다.
---
**프로님:** "입주 후 하자 보고서를 건설사에 제출해야 하는데, 하자 유형별로 분류하고 처리 현황 정리하고 공문 형식 맞추는 게 매번 시간이 오래 걸려요. 이걸 AI가 도와줄 수 있을까요?"
오늘 해결: 할 수 있습니다. 오늘 만들 Gem A는 타일·가구·도배·목창호·PVC창호·도장·전기·설비 등 실제 공종 분류 체계를 내장하고, 하자 현황 데이터를 붙여넣으면 건설사 제출용 보고서를 즉시 초안으로 만들어줍니다. R.C.T.C 공식으로 맥락을 명확히 주는 법도 배웁니다.
---
**프로님:** "건설사 금액 청구 서류 작성이나, 아파트 관리 서비스 수주를 위한 제안서 자료 찾는 게 시간이 많이 걸려요. 시장 조사 자료도 빠르게 만들 수 있으면 좋겠고요."
오늘 해결: Gemini의 실시간 검색 연동으로 시장분석 보고서를 10분 안에 초안으로 잡을 수 있습니다. 기성청구서 작성에는 Gem B를 세팅해두면 항목과 금액만 입력하면 표 형식으로 자동 정리됩니다. 오늘 딥리서치 변환 기법도 같이 해봅니다.
---
**프로님:** "저는 CS교육과 업무기획을 담당하고 있어요. AI한테 물어볼 때마다 매번 우리 회사 상황을 처음부터 설명해야 하는 게 불편해서요. 한 번 세팅해두면 계속 쓸 수 있는 방법이 있나요?"
오늘 해결: 정확히 그게 오늘의 핵심입니다. Gem(시스템 프롬프트)을 세팅하면 "너는 교육기관 27 CS교육 담당자야, 우리는 입주관리 종합대행 회사고..." 같은 설명을 한 번만 해두면 됩니다. 이후에는 "이번 분기 CS교육 계획 초안 짜줘"라고만 해도 맥락을 알고 답합니다.
---
**프로님:** "기성청구 관련 엑셀 데이터 정리하고, 기존 PPT 자료를 다른 양식으로 바꾸는 작업이 반복적으로 생겨요. 스마트폰으로 참여하는데 많이 불편할까요?"
오늘 해결: Gemini 앱으로 대부분 가능합니다. 문서 내용을 복사해서 붙여넣고 "이 형식으로 바꿔줘"라고 하면 됩니다. 데이터 정리 프롬프트도 오늘 직접 써보겠습니다. NotebookLM 파일 업로드는 PC가 더 편하지만, 기본 실습은 스마트폰으로 충분합니다.
---
**프로님:** "AI를 거의 안 써봤어요. 현장 관리하면서 매니저 수급, 보고서 정리, 채용 공고 작성 같은 게 반복적으로 생기는데, 어디서 시작해야 할지 모르겠습니다."
오늘 해결: 오늘 배울 건 딱 3가지입니다. Gemini 켜기, 프롬프트 붙여넣기, 결과 확인하기. 매니저 JD(직무기술서) 작성, 현장 일지 요약, 카카오톡 공지용 짧은 버전 자동 변환까지 오늘 직접 해봅니다. Gem C를 한 번 세팅해두면 이후 반복 업무가 크게 줄어듭니다.

### 1-3. LLM은 어떻게 작동하는가
핵심 한 문장:
> LLM은 엄청난 양의 문장을 학습하고, 다음에 어떤 단어가 오면 가장 자연스러운지를 확률로 예측하는 모델입니다.
"오늘 점심은 김치..."까지 입력하면, LLM은 학습한 패턴에서 "찌개(40%) / 볶음밥(25%) / 전(10%)..." 처럼 다음 후보의 확률을 계산하고 가장 그럴듯한 것을 고릅니다. 이 과정을 토큰 하나하나마다 반복해 문장을 완성합니다.
강사가 알아야 할 두 가지 통찰:
첫째, AI는 "이해"가 아니라 "예측"합니다. 의미를 아는 것처럼 보여도 근본은 통계적 패턴 매칭입니다.
둘째, 그래서 같은 질문에도 답이 매번 조금씩 다릅니다. "왜 어제랑 답이 달라요?"라는 질문의 답이 여기 있습니다.

### 1-4. 할루시네이션 — AI가 틀리는 이유와 대처법
> \[다이어그램\] 할루시네이션 SVG — 발생 원리 + 위험 상황 + 대응 원칙<br>
[원본 이미지 제외]
할루시네이션이란: AI가 사실이 아닌 내용을 사실처럼 자신 있게 생성하는 현상입니다. 없는 통계 수치, 틀린 날짜, 존재하지 않는 법 조항을 진짜처럼 말합니다.
왜 생기는가:
LLM은 "정답 검색"이 아니라 "가장 자연스러운 다음 단어 예측"을 합니다. 모를 때도 예측을 멈추지 않습니다. 빈칸으로 두는 대신 그럴듯한 말로 채웁니다. AI에겐 "모른다"보다 "그럴듯한 문장"이 더 자연스러운 출력이기 때문입니다.
할루시네이션이 특히 잘 나오는 상황:
- 최신 정보 (AI 학습 시점 이후 사건)
- 구체적 숫자·통계·인용·출처
- 아주 전문적이거나 희귀한 주제
- 존재 여부가 불확실한 것 ("○○라는 규정 알려줘")
핵심 원칙:
```plain text
AI = 빠른 초안 작성자
사람 = 최종 판단자

수치·날짜·고유명사·법규정은 반드시 원본으로 교차 검증
```
환각을 결함으로만 보면 AI를 불신하게 됩니다. 올바른 시각: "그래서 사람의 검수가 가치 있습니다. AI가 80%를 빠르게 만들고, 사람이 20%를 책임집니다." 할루시네이션은 사람의 역할이 사라지지 않는 이유입니다.

### 1-5. 토큰 — AI가 텍스트를 처리하는 단위
AI는 글자가 아니라 토큰(단어 또는 단어 조각) 단위로 처리합니다.
```plain text
"안녕하세요"      →  [안녕] [하세요]               약 2토큰
"인공지능"        →  [인공] [지능]                 약 2토큰
"하자처리율"      →  [하자] [처리] [율]             약 3토큰
이미지 (사진 1장) →                               수백~수천 토큰
```
한국어는 영어보다 토큰을 더 많이 소비하는 경향이 있습니다.
실무에서 토큰이 중요한 이유:
무료 플랜 사용 한도는 보통 토큰 기준입니다. "오늘 사용량을 다 썼어요"의 정체가 바로 이것입니다.
사진·파일은 텍스트보다 훨씬 많은 토큰을 소비합니다.
대화가 길어질수록 누적 토큰이 쌓여 앞부분을 잊게 됩니다.

```plain text
컨텍스트 윈도우 = AI가 한 번에 볼 수 있는 최대 분량 (입력 + 출력 합산)
```

### 1-7. AI 도구 지형 — 도구별 차이와 Gemini를 선택하는 이유
> \[다이어그램\] 주요 AI 도구 비교 SVG — ChatGPT · Claude · Gemini · 뤼튼
[원본 이미지 제외]
같은 "AI 챗봇"처럼 보여도 만든 회사, 강점, 철학이 다릅니다. <br>한 줄로 특징을 잡아보면:
**ChatGPT — 가장 유명하고 생태계가 넓은 범용 AI**
OpenAI가 만든 GPT-5 계열 모델입니다. 이미지 생성(DALL-E 연동), 음성 대화, 코드 작성 등 다양한 기능을 갖춰 "AI하면 ChatGPT"라는 인식이 강합니다. 다만 Gem에 해당하는 GPTs 기능은 유료 플랜(Plus 이상)이어야 제대로 쓸 수 있고, 무료 사용자는 GPT-5의 고성능 모드 사용이 제한됩니다.
**Claude — 긴 문서와 규칙 준수에 가장 강한 AI**
Anthropic이 만든 Opus/Sonnet 계열입니다. 안전성과 윤리를 중시하는 철학으로 설계되었고, 긴 문서를 통째로 읽고 분석하는 능력이 뛰어납니다. 계약서·보고서·매뉴얼처럼 분량이 많은 자료를 다룰 때 강점을 보입니다. "시스템 프롬프트 규칙을 잘 지킨다"는 평이 많아 Gem 세팅의 기반 개념은 Claude 방식에서 온 것이기도 합니다.
**Gemini — 구글 생태계에 녹아드는 AI (오늘의 주인공)**
Google이 만든 Gemini 3 계열입니다. 구글 드라이브, Gmail, 구글 문서와 연동되어 업무 환경에서 바로 쓸 수 있고, 실시간 웹 검색이 기본 내장되어 있습니다. Gem(나만의 비서) 기능을 무료로 사용할 수 있다는 점이 오늘 교육에서 가장 중요한 이유입니다. NotebookLM도 구글 계정으로 연동됩니다.
**뤼튼 — 비용 없이 시작하고 싶을 때**
국내 기업 뤼튼테크놀로지스가 만들었으며, ChatGPT·Claude 등 타사 AI 모델을 무료로 연결해 쓸 수 있는 플랫폼입니다. 완전 무료로 고성능 AI를 체험할 수 있는 입문 도구입니다. 다만 기반 모델이 타사 AI이므로 정책 변동에 영향을 받을 수 있고, 자체 비서 기능(Gem 수준)은 제한적입니다.
같은 회사 안에도 모델이 여러 개인 이유:
보통 고성능(느림·비쌈) / 균형형 / 고속(빠름·저렴) 3단 구조로 나뉩니다.
```plain text
Claude 계열
    Opus   — 가장 강력, 복잡한 분석 작업 (최신: Opus 4.8)
    Sonnet — 균형형, 일반 업무 (최신: Sonnet 4.6)
    Haiku  — 가장 빠름, 간단한 작업 (최신: Haiku 4.5)

Gemini 계열
    Pro    — 고성능, 복잡한 작업
    Flash  — 고속 응답, 일상적 사용

ChatGPT 계열
    GPT-5  — 현재 자동으로 응답 깊이를 전환
```
주의: 모델명·버전은 수주 단위로 바뀝니다. 교재의 버전명보다 "지금 시점의 최신 모델"이라고 말하고, 강의 직전 확인하는 것이 맞습니다. 틀린 정보를 자신 있게 말하지 않는 것이 AI 강사의 신뢰입니다. 이것은 1-4에서 배운 할루시네이션 원칙과 동일합니다. 사람도 모르면 확인합니다.

### 1-8. GIGO 원칙 — 질문의 질이 답변의 질을 결정한다
GIGO: Garbage In, Garbage Out
```plain text

"보고서 써줘"

→ AI는 어떤 목적의 보고서인지, 누가 읽는지, 어떤 형식인지 알 수 없어
  일반적인 보고서 형식을 추측해서 작성합니다.

명확한 질문:
"교육기관 27 입주관리팀 이사로서,

 하자 유형 3가지로 분류하고 처리 현황을 표 형식으로,
 A4 1장, 격식체로 작성해줘"

→ 목적·대상·형식이 명확하여 원하는 결과물이 즉시 생성됩니다.
```

## Part 2. 지휘 공식 & AI 비서 구축 — 1시간

### 2-1. 지휘 공식 R.C.T.C — AI를 제대로 부리는 4계명
이 공식 하나면 오늘부터 AI 활용 수준이 완전히 달라집니다.<br>
[원본 이미지 제외]
```plain text
R — Role        역할 부여   어떤 전문가처럼 행동할지
C — Context     맥락 설명   배경·대상·목적
T — Task        구체적 과업  동사 중심의 명확한 지시
C — Constraints 형식과 제약  형식·톤·길이·포함/제외
```
### R — 역할 부여의 힘
AI에게 전문가 페르소나를 입히면 답변의 품질이 달라집니다.
```plain text
나쁜 예시:
"너는 아파트 전문가다"
→ 일반적이고 피상적인 답변

좋은 예시:
"당신은 아파트 입주관리 및 건설사 하자협의 경험이 10년 이상인
 전문 담당자입니다. 공공기관 격식체를 사용하며, 수치 근거를
 반드시 제시합니다."
→ 전문적이고 심층적인 결과물
```
팁 1: "\~처럼 행동해"라고 쓰면 AI가 역할 수행에 더 집중합니다.<br>팁 2: 전문 용어, 경력 연차, 전문 분야를 구체적으로 쓸수록 좋습니다.<br>팁 3: 나의 배경도 함께 알려주면 수준에 맞는 맞춤 응답을 받습니다.
### C — 맥락 제공의 힘
```plain text
맥락 없는 질문:
"제안서 써줘"
→ 어떤 목적인지, 누구에게 보내는지 알 수 없어 일반적인 답변 생성

맥락 있는 질문:
"우리는 교육기관 27이야. 아파트 입주 관리 및 하자 처리를 담당해.
 신규 아파트 단지 관리사무소를 대상으로 하는 서비스 제안서야.
 상대방은 관리소장이고, 우리 강점인 하자처리 신속성을 강조해야 해."
```
팁: 5W1H(누가, 언제, 어디서, 무엇을, 왜, 어떻게)로 상황을 설명하세요. 더 많이 알려줄수록 더 정확한 결과가 나옵니다.
### T — 명확한 지시의 기술
효과적인 액션 동사:
```plain text
작성하다   이메일, 보고서, 기획안 등 문서 생성
분석하다   데이터 해석, 패턴 발견, 인사이트 도출
요약하다   긴 내용을 핵심만 간결하게 정리
추출하다   텍스트·데이터에서 특정 정보만 선별
비교하다   두 가지 이상 항목 간 차이점/유사점 분석
```
단계별 지시: —\> COT
```plain text
"먼저 하자 유형을 3가지로 분류하고,
 다음으로 각 유형별 처리 현황을 표로 정리하고,
 마지막으로 건설사에 청구할 총 비용을 계산해줘."
```
### C — 제약조건의 힘
```plain text
출력 형식 및 분량:  "A4 1장 이내로" / "표 형식으로" / "5가지 목록으로"
                   지금부터 보고서를 작성할거야.
                   보고서의 양식은 다음과 같아.
                   1. 개요 2. 행사 일정 3. 행사 참여자 4. 만족도조사
어조/톤:           "격식체(합니다체)로" / "건설사 제출용 공문 형식으로"
금지사항:          "전문 용어는 쉽게 풀어서" / "추측성 답변 금지"
```
제약조건이 명확할수록 AI는 더 정확하고 유용한 결과물을 생성합니다.

의미

직업뿐만 아니라 태도와 시각을 정의했는가? 경력 연차나 전문 분야를 설정했는가?




O (Objective)

Gem의 존재 이유

Agent의 존재 이유를 한 문장으로 요약할 수 있는가? 단일 목표로 집중되어 있는가?




P (Process)

일하는 순서

일하는 순서(Step-by-Step)를 단계별로 명시했는가? 지켜야 할 제약 조건과 금지 사항이 있는가?




E (Example)

원하는 결과물 예시

입력(Input)과 출력(Output) 예시를 제공했는가? 예시가 톤앤매너와 형식을 반영하고 있는가?




K (Knowledge)

내부 문서 학습

우리 회사만의 내부 문서(PDF 등)를 업로드했는가? 지식 파일을 우선 참고하라고 지시했는가?

### 2-6. Agent 디자인 5가지 기법
단순한 Gem을 넘어 정교한 전문가를 만드는 실전 기술입니다.
### 기법 1. 정석 — R.O.P.E.+K 빈칸 채우기
```plain text
가장 기초적이고 탄탄한 방법론.
R.O.P.E.+K 5가지 항목을 논리적으로 채웁니다.

언제 쓰는가:
- 내가 업무 프로세스를 명확히 알고 있을 때
- 오차가 적고 정확한 결과물이 필요할 때
→ 예시: 하자 보고서, 기성청구서, 현장 일지
```
### 기법 2. 복제 — 검증된 구조를 내 업무에 맞게 변형
```plain text
검증된 시스템 프롬프트를 가져와서 내 업무에 맞게 변형하는 방식.
핵심 원칙: 구체성과 체계는 유지하되, 용어만 치환합니다.

변형 명령 예시:
"지금 주는 시스템 프롬프트를
 '교육기관 27 하자관리 업무'에 맞게 변형해줘.
 원본의 구체성과 체계는 유지하되, 용어만 치환하는 정도로만 바꿔."
```
### 기법 3. 딥리서치 변환 — AI에게 먼저 공부시키기
```plain text
내가 모르는 영역의 Gem을 만들 때:
AI에게 먼저 웹 검색을 시켜 정보를 수집하게 한 뒤,
그 지식으로 스스로 매뉴얼을 짜게 하는 2단계 기법.

언제 쓰는가:
- 최신 정보가 필요할 때
- 내가 전문가가 아닌 영역의 Gem을 만들 때

Step 1: "최근 3년간 아파트 하자 관련 건설사-관리사 분쟁 사례와
         하자 처리 모범 사례를 심층 분석하고 싶어. Gem 만들 거야."
Step 2: "딥리서치 내용을 바탕으로 Gem 시스템 프롬프트를 R.O.P.E.+K 형식으로 짜줘."
```
### 기법 4. 역설계 — 황금알에서 거꾸로 (추천)
```plain text
완벽한 결과물을 AI에게 던져주고,
"이거랑 똑같이 쓰는 기계를 만들어줘"라고 명령하는 가장 쉽고 강력한 방법.

언제 쓰는가:
- 우리 회사만의 고유한 양식이나 보고서 포맷이 있을 때
- 나만의 문체나 스타일을 복제하고 싶을 때

마법의 주문:
"이건 내가 쓴 최고의 보고서야.
[보고서 붙여넣기]
이 보고서를 분석해서
1) 톤앤매너,
2) 글의 구조(개요→현황→결론),
3) 문장 호흡을 추출해줘.
그리고, 앞으로 내가 어떤 현황을 던지든 무조건
이 보고서랑 똑같은 스타일로 새 보고서를 작성해주는
시스템 프롬프트를 네가 직접 짜줘."
```
역설계 실전 워크시트:
```plain text
Step 1. 가장 잘 썼다고 칭찬받은 하자 보고서 또는 건설사 청구 공문 1건 준비

Step 2. 마법의 주문 입력
        "위 문서의 톤앤매너, 구조, 핵심 전략을 분석하여
         동일한 스타일로 문서를 작성할 수 있는 System Prompt를 만들어줘.
         Role, Objective, Process, Example 형식으로."

Step 3. AI가 생성한 System Prompt 확인 → Gem 요청사항 칸에 붙여넣기

Step 4. 다른 상황에 테스트 → 톤앤매너 일치 여부 점검 → 미세 조정
```
### 기법 5. 메타 프롬프트 — AI가 AI를 돕는 방식
```plain text
AI에게 좋은 프롬프트를 만들어달라고 요청하여,
AI가 스스로의 프롬프트를 개선하게 하는 고급 기법.
```

## 자주 나오는 질문 & 해결법
**Q1. AI 결과가 왜 매번 달라요?**
프롬프트가 조금씩 달라서 그렇습니다. Part 2에서 만든 Gem을 사용하면 일관성이 유지됩니다. 또는 "이 스타일 유지해서 써줘"라고 추가 입력하세요.
**Q2. AI가 틀린 정보를 쓰는 경우가 있어요.**
AI는 없는 정보를 만들어내기도 합니다. 이건 모든 AI의 구조적 한계입니다.<br>대응법: 수치·날짜·고유명사는 반드시 직접 확인. 중요한 문서는 AI 초안 → 사람 검토 → 최종 확인 순서로. NotebookLM은 우리 문서 기반이라 이 문제가 훨씬 적음. 제약 조건에 "추측성 답변 금지"를 명시하면 줄어듦.
**Q3. 회사 기밀 정보를 AI에 넣어도 되나요?**
해도 되는 것: 공개 가능한 일반 업무 정보, 비식별화한 데이터(이름·주소 제거).<br>조심해야 하는 것: 개인정보가 포함된 문서, 계약 금액·거래처 정보 등 기밀 내용.<br>팁: 민감한 내용은 지우고 넣거나, 구조만 참고하세요.
**Q4. 스마트폰으로도 다 되나요? (프로님)**
