# 실습 3. 카드 3 — 고객 회신 초안: 좋은 예시 vs 오염된 예시

정리일: 2026-10-08 · 교육 에셋 N0438

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
예시 속 사실이 새 회신에 섞이는지(오염)를 실행 A·B로 비교하고, 수정 요청 3원칙으로 한 문장만 고친다.
## 진행 단계
1. **실행 A — 오염된 예시** — 새 채팅에 프롬프트 붙여넣기 → Enter (\[예시\]에 가상 고객사·금액·원인 확정 문장 포함, \[대상 자료\]에 메일·클레임이력·안내서 6.1)
2. **P2-4 기록** — 점검 질문 3개 + 자료에 없는 금액·원인·보상 여부를 예/아니오 + 해당 문장으로 A 열에 기록
3. **실행 B — 좋은 예시** — 새 채팅에서 A 프롬프트의 \[예시\] 블록만 '형식 예시(교육용 가상 사례, 구조만 참고, 사실은 \[대상 자료\]에서만)' 블록으로 교체
- 정상 결과: (1) 확인된 내용 (2) 확인 중 (3) 요청 정보 (4) 다음 안내 네 문단, 예시 이름·표현 없음, 날짜는 \[회신 예정일 확인 필요\]
4. **P2-4 B 열 기록**
5. **수정 요청 1회** — 같은 채팅에 \[유지할 것\] \[바꿀 것\] \[근거\] 문형으로 요청 → P2-5 기록
## 막히는 지점
- 실행 A 결과가 예시 고객사명으로 시작 → 오염으로 그대로 기록
- \[대상 자료\]를 같이 지워 '대상 메일이 없다'는 답 → A 프롬프트를 다시 복사해 \[예시\] 블록만 교체
- 수정 요청 후 초안 전체가 바뀜 → '지정한 문장 외에는 직전 초안과 글자 하나 다르지 않게 다시 보여줘.'
