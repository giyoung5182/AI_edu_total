# 1. 저장이 왜 따로 필요한가
지금까지 만든 화면은 **열려 있는 동안만** 살아 있습니다.
```plain text
학생이 입력  →  화면에 보임  →  새로고침하면 사라짐
```
웹 화면은 원래 그렇습니다. **기억하는 기능이 없습니다.**
기록을 남기려면 **내용을 어딘가에 보내서 보관**해야 합니다. 그 "어딘가"를 무엇으로 할지가 이 문서의 주제입니다.

# 3. ⚠️ 학생 개인정보 — 건너뛰지 마세요
기능보다 중요합니다.
## 회원가입은 만들지 마세요
만 14세 미만 학생의 개인정보를 수집하려면 **법정대리인 동의**가 필요합니다.<br>학생이 이름·아이디·비밀번호를 입력하는 순간 개인정보 수집이 됩니다.
**교사가 개인적으로 만든 도구로 이걸 하시면 안 됩니다.**
## 대신 이렇게

[계정 정보가 포함된 표 제외]

> 💡 선생님은 누가 몇 번인지 아시니까 확인에 문제가 없고,<br>다른 사람이 기록을 봐도 누구인지 알 수 없습니다.
## 관리자 화면 — 정직하게
화면 코드에 적은 비밀번호는 **누구나 볼 수 있습니다.** 보안이 아닙니다.
```plain text
❌ "비밀번호 1234를 넣으면 관리자 화면"
   → 초등학생도 5분이면 찾아냅니다

✅ 주소를 나눈다
   학생용   .../index.html
   관리용   .../teacher-x7k2.html
```
> 📌 **좋은 수업 소재이기도 합니다.** 실제로 열어서 보여주면 학생들이 놀랍니다.

# 5. B안 · 내 기기에만 저장 — 가장 쉬움
## 이런 경우
```plain text
· 학생이 하다가 새로고침해도 자기 것은 남았으면 좋겠다
· 선생님이 모아 볼 필요는 없다
· 여러 차시에 걸쳐 자기 진행 상황을 보게 하고 싶다
```
## 어떻게
서버가 전혀 필요 없습니다. **브라우저 자체에 저장**합니다.
```plain text
학생이 만든 규칙을 저장해서
새로고침하거나 나중에 다시 들어와도 남아있게 해줘.

서버는 쓰지 말고 브라우저에 저장하는 방식으로.
'처음부터 다시' 버튼도 만들어줘.
```
## 알아둘 것
```plain text
· 같은 기기, 같은 브라우저에서만 남습니다
· 학생이 다른 폰으로 들어오면 안 보입니다
· 선생님은 볼 수 없습니다
· 브라우저 기록을 지우면 사라집니다
```
> ⚠️ **학교 공용 태블릿에서는 주의하세요.** 다음 시간 학생에게 앞 학생 기록이 보입니다.<br>'처음부터 다시' 버튼을 꼭 만들어두세요.

# 6. C안 · 구글 시트 — 대부분 여기서 해결
## 왜 이걸 권하나
```plain text
✅ 이미 쓰고 계신 도구입니다 (새로 가입할 것 없음)
✅ 결과가 표로 쌓여서 그대로 확인·정리·인쇄가 됩니다
✅ 무료입니다
✅ 데이터베이스 개념을 몰라도 됩니다
```
> 💡 **가장 큰 장점은 "결과를 아는 형태로 본다"는 것**입니다.<br>데이터베이스에 쌓이면 따로 화면을 만들어야 보이지만, 시트는 열면 바로 보입니다.
## 흐름
```plain text
학생이 '제출' 누름
      ↓
Apps Script (시트에 딸린 작은 프로그램)
      ↓
구글 시트에 한 줄 추가
      ↓
선생님이 시트를 열어서 확인
```
**Apps Script**는 구글 시트에 딸린 기능입니다. 별도 설치나 가입이 없습니다.
## STEP 1 · 시트 만들기
```plain text
1. 구글 드라이브에서 새 스프레드시트를 만듭니다
2. 이름을 정합니다 (예: 3학년_활동기록)
3. 첫 줄에 항목 이름을 적습니다
   시각 | 번호 | 답 | 결과
```
## STEP 2 · 스크립트 넣기
```plain text
1. 시트 메뉴에서  확장 프로그램 → Apps Script
2. 새 탭이 열립니다
3. 기존 내용을 다 지웁니다
```
**코드는 Claude가 만들어줍니다.**
```plain text
구글 시트에 웹 화면에서 보낸 내용을 한 줄씩 기록하는
Apps Script 코드를 만들어줘.

받을 항목은 번호, 답, 결과 세 가지야.
기록할 때 시각도 같이 남겨줘.

웹 화면에서 보낼 때 오류가 나지 않게
CORS 문제를 피하는 방식으로 만들어줘.

코드만 주고, 어디에 붙여넣는지도 알려줘.
```
> 💡 **CORS 줄을 꼭 넣으세요.** 안 넣으면 거의 반드시 오류가 납니다. (8장 참고)
## STEP 3 · 배포하기
```plain text
1. Apps Script 오른쪽 위  배포 → 새 배포
2. 유형 선택 →  웹 앱
3. 실행 사용자:  나
4. 액세스 권한:  모든 사용자        ← 이게 핵심입니다
5. 배포 클릭
```
**처음 배포하면 경고 화면이 나옵니다.** 정상입니다.
```plain text
"이 앱은 확인되지 않았습니다" 화면
→ 고급 (Advanced) 클릭
→ "안전하지 않은 페이지로 이동" 클릭
→ 권한 허용
```
> ⚠️ 겁나 보이지만 **내가 내 시트에 접근하는 것을 내가 허락하는 절차**입니다.
배포가 끝나면 **웹 앱 URL**이 나옵니다. 복사해두세요.
```plain text
[개별 링크 제외]
```
## STEP 4 · 화면에 연결
```plain text
index.html에 저장 기능을 붙여줘.

학생이 '제출하기'를 누르면 아래 주소로 내용을 보내줘.
[여기에 복사한 URL 붙여넣기]

보낼 항목은 번호, 답, 결과 세 가지야.

주의할 점이야.
- 학생 이름은 받지 않아. 번호만 입력받아
- 보내는 중에는 버튼을 못 누르게 해줘
- 보내고 나면 "저장했어요" 안내를 보여줘
- 인터넷이 안 되면 "잠시 후 다시 해보세요"라고 알려줘
- CORS 오류가 나지 않는 방식으로 보내줘
```
## 확인
```plain text
□ 화면에서 제출해봅니다
□ 구글 시트에 줄이 생기는지 봅니다
□ 휴대폰에서도 되는지 봅니다        ← 꼭
□ 두세 번 연속으로 눌러봅니다        ← 중복 저장 확인
```

# 8. 반드시 만나게 될 오류 — CORS
구글 시트든 Supabase든 **처음 연결하면 거의 100% 만납니다.**
## 증상
```plain text
화면에서는 "저장했어요"가 나오는데 시트에 아무것도 없다
또는
빨간 글씨로 CORS 어쩌고 하는 오류가 나온다
```
## 왜 나나요
브라우저가 \*\*"다른 주소로 함부로 정보를 보내지 마"\*\*라고 막는 안전장치입니다.<br>내 화면과 저장소가 다른 주소라서 걸립니다.
## 해결
```plain text
저장이 안 되고 CORS 오류가 나.
[오류 메시지 그대로 붙여넣기]

보내는 방식을 바꿔서 이 오류를 피하게 해줘.
```
> 💡 **2회 규칙을 여기서도 지키세요.**<br>두 번 고쳐서 안 되면 새 세션으로 시작하고, 이 오류를 미리 알려주며 처음부터 다시 만드세요.

# 10. 정리
## 결정 순서
```plain text
① 정말 저장이 필요한가?           → 아니면 여기서 끝
② 제출만 받으면 되나?             → 구글 폼 (만들지 않음)
③ 내 기기에만 남으면 되나?         → 브라우저 저장
④ 선생님이 모아 봐야 하나?         → 구글 시트        ← 대부분 여기
⑤ 실시간·대량·로그인이 필요한가?    → Supabase / Firebase
```
## 그리고 순서
```plain text
① 저장 없이 완성하고 배포한다      ← 오늘 여기까지
② 실제로 수업에 써본다
③ "기록이 남았으면 좋겠다" 싶으면
④ 그때 위 결정 순서를 따라간다
```
**②번을 건너뛰지 마세요.** 써보기 전에는 무엇을 저장해야 할지 모릅니다.
