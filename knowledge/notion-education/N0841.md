## 왜 이 챕터를 하는가
2회차에서 27일 하루치 재고 데이터를 분석했습니다. <br>오늘은 한 단계 더 나아가 **월간 전체 흐름**을 구조화합니다.
```plain text
2회차 (완료):
27일 하루 → 재고 부족 탐지 → 긴급·위험 목록 → 알림 문구

3회차 오늘:
월간 전체 → 피벗으로 구조화 → 차트·인포그래픽 → 보고서 완성
```
**왜 월간 데이터가 중요한가:**
2회차에서 직접 확인했습니다. 27일 하루치 기준으로는 된장육수가 TOP 10에 없었지만, 월간 누계 기준으로는 10위에 진입했습니다. 하루만 보면 놓치는 패턴이 월간 데이터에서 드러납니다.
```plain text
하루치 분석: "오늘 뭐가 부족한가?" → 당일 발주·알림
월간 분석:  "이번 달 전체 패턴이 어떤가?" → 발주 계획·공급업체 협상
```
두 관점을 함께 쓰는 것이 구매부 업무의 실력입니다.

## 실습 전 개념 — 질문이 먼저, 피벗은 그다음
피벗 테이블을 열면 "행에 뭘 넣지? 값에 뭘 넣지?"부터 막힙니다. 이유는 하나입니다. <br>**질문을 먼저 정하지 않아서**입니다.
**잘못된 순서:**
```plain text
엑셀 열기 → 피벗 삽입 → "어디에 뭘 넣지?" → 막힘
```
**올바른 순서:**
```plain text
① "이번 달 어떤 품목이 가장 많이 나갔는가?" ← 질문 먼저
② 행: 품목명 / 값: 월총출고 합계 / 정렬: 내림차순 ← 피벗 설계
③ 피벗 생성 + 결과 검증 ← 분석
```
질문이 먼저 있으면 피벗 설계가 자연스럽게 따라옵니다.

### 결과 나오면 — 이런 상황이 생길 수 있습니다
**질문 1에서 27일 하루치로 분석 결과가 나왔다면?**
AI가 월총합 시트 대신 27 시트를 선택했을 때 발생합니다. DSRF에서 \[D\]를 충분히 명시했어도 AI가 더 구체적 데이터가 있는 시트를 선택하는 경우가 있습니다.
**왜 이렇게 나오는가:**
AI는 두 시트를 모두 인식하지만 "이번 달 전체"가 어느 시트인지 확신이 없으면 데이터가 더 명확한 시트를 선택합니다. 이것이 \[D\]에 시트명·열 구조를 구체적으로 명시해야 하는 이유입니다.
**대처법 — 수정 요청:**
```plain text
질문 1을 다시 해줘.
월총합 시트의 '월총출고' 열을 기준으로
이번 달 전체 출고량 TOP 10을 뽑아줘.
27일 하루치가 아닌 월간 누계 기준이야.
```
> 이것이 반복 정제(Iteration)입니다. 첫 결과가 틀렸다고 처음부터 다시 시작하지 않습니다. 틀린 부분만 구체적으로 짚어서 수정 요청합니다.

### 방법 A. 엑셀에서 직접 만들기
Claude가 알려준 구조대로 엑셀에서 직접 피벗 테이블을 생성합니다.
**실습 순서:**
```plain text
① [3회차] 재고파악_실습용.xlsx 열기
② 월총합 시트 클릭
③ 데이터 범위 전체 선택
④ 삽입 → 피벗 테이블 → 새 시트에 생성
⑤ 오른쪽 필드 목록에서:
   - 품목 → 행(Rows)에 드래그
   - 월총출고 → 값(Values)에 드래그
⑥ 값 셀 우클릭 → 정렬 → 내림차순
⑦ 행 레이블 우클릭 → 필터 → 상위 10개
```
**막히는 경우 Claude에 물어보기:**
```plain text
"피벗 테이블 만드는데 삽입 탭에 피벗 테이블이 안 보여.
 어디에 있어? Excel 2021 버전이야."
```

### 방법 B. Claude Pro에 결과 파일 만들어달라고 하기 (추천)
같은 채팅에서 이어서 요청합니다.
```plain text
[질문 1] 결과를 엑셀 파일로 만들어줘.

월총합 시트 기준 월총출고 TOP 10 결과를
아래 형식으로 정리해줘:

| 순위 | 품목명 | 월총출고 | 구성비(%) |

구성비는 소수점 1자리 %로.
(예: 46.9%)

엑셀 파일로 다운로드할 수 있게.
파일명: 5월_월간출고_TOP10.xlsx
```
**결과 파일 받으면 반드시 확인:**
구성비가 소수점 17자리로 나오는 경우가 있습니다.
```plain text
구성비가 0.468645...처럼 소수점이 너무 길어.
소수점 1자리 %로 다시 만들어줘. 예: 46.9%
```
> **왜 이 오류가 나오는가:** Claude가 파일을 만들 때 구성비 계산에 부동소수점 처리를 그대로 두기 때문입니다. 오류가 아니라 형식 설정 누락입니다. \[F\]에 "소수점 1자리 %"를 명시하면 처음부터 방지할 수 있습니다.
