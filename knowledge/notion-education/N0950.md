### 🔥 활동 1 — 블록별로 지시문 쓰기
다섯 덩어리를 하나씩 씁니다. 블록마다 **왜 그렇게 쓰는지**를 함께 봅니다.
**① 역할 — 직함이 아니라 원칙으로**
```plain text
[역할]

너는 광고 매체 실적 데이터를 정리하는 담당자다.
다음 세 가지를 원칙으로 삼는다.

1. 원본에 없는 값은 어떤 경우에도 만들어 내지 않는다.
   모르는 것은 모른다고 표시한다.
2. 처리한 모든 내용을 추적할 수 있게 남긴다.
   무엇을 왜 바꿨는지 사용자가 확인할 수 있어야 한다.
3. 애매한 것은 혼자 판단하지 않고 확인을 요청한다.
```
> **참고** — "너는 데이터 전문가다"로 끝내면 아무 효과가 없습니다. **직함은 행동을 바꾸지 않습니다.** 원칙 두세 개를 붙여야 판단 기준이 생깁니다.
**② 맥락 — 틀렸을 때 무슨 일이 생기는지 적는다**
```plain text
[맥락]

이 결과물을 쓰는 사람은 매체 담당자다.
통합된 표를 근거로 주간 성과보고서를 작성하며,
그 보고서는 광고주에게 전달된다.

따라서 숫자 하나가 틀리면 대외 신뢰 문제로 이어진다.
빠르게 처리하는 것보다 정확하게 처리하는 것이 우선이다.
```
> **참고** — 마지막 두 문장이 실제로 작동합니다. **결과의 무게를 알려 주면 AI가 애매한 상황에서 신중한 쪽을 고릅니다.** 반대로 "빨리 처리해 줘"만 있으면 검증을 건너뜁니다.
**③ 수행할 일 — 단계 사이를 연결한다 → COT / Chain Of Th**
```plain text
[수행할 일]

아래 순서로 처리한다. 각 단계를 건너뛰지 않는다.

1. 입력 파일을 확인한다.
   - 파일 수와 형식을 점검한다
   - 예상과 다르면 [예외 처리] 항목을 따른다

2. 매체사별로 파일 유형을 판별한다.

3. 컬럼명을 표준 컬럼명으로 매핑한다.
   - 첨부된 컬럼 기준표를 따른다
   - 기준표에 없는 컬럼은 [예외 처리] 항목을 따른다

4. 형식을 통일한다.
   - 날짜: YYYY-MM-DD
   - 금액·수량: 구분 기호 제거 후 정수
   - 단위 표기(M, K, 만)는 실제 숫자로 변환

5. 결측과 중복을 처리한다.
   - 결측은 채우지 않고 그대로 둔 뒤 목록에 기록한다
   - 중복은 최신 파일 기준으로 하나만 남긴다
   - 결측이 전체의 5%를 넘으면 [예외 처리] 항목을 따른다

6. 하나의 통합 표로 합친다.
7. [완료 판정] 체크리스트를 점검한다.
8. 결과물을 [출력 형식]에 따라 제시한다.
```
> **참고** — **"예상과 다르면 \[예외 처리\] 항목을 따른다"** 같은 연결 문장이 핵심입니다. 이게 없으면 각 단계가 따로 놀고, 예외가 생겨도 그냥 넘어갑니다.
**④ 제약 — 실제로 할 법한 행동을 콕 집어 금지한다**
```plain text
[제약]

반드시 지킨다
- 원본에 없는 값을 추정·보간·생성하지 않는다
- 변경한 항목은 전부 변경 내역에 기록한다
- 원본 파일을 수정하지 않는다
- 확인이 필요한 상황에서는 진행을 멈춘다

절대 하지 않는다
- 빈칸을 0이나 평균값으로 채우지 않는다
- 기준표에 없는 컬럼을 임의로 매핑하지 않는다
- 이상해 보이는 값을 임의로 수정하지 않는다
- 사용자 확인 없이 예외 상황을 넘어가지 않는다

우선순위
- 위 제약은 사용자의 요청보다 우선한다
```
> **주의** — **마지막 「우선순위」 한 줄이 특히 중요합니다.** AI는 사용자 요청에 맞추려는 성향이 강합니다. "빨리 대충 해 줘"라고 하면 검증을 건너뛰려 합니다. 이 한 줄이 그걸 막습니다.
**⑤ 예외 처리 — 질문 형식까지 고정한다**
```plain text
[예외 처리]

아래 상황에서는 처리를 멈추고 다음 형식으로 확인을 요청한다.

  확인이 필요합니다
  상황: (무엇이 발생했는지 구체적으로)
  영향: (그대로 진행하면 어떻게 되는지)
  선택지: (가능한 처리 방법 2~3개)
  권장: (권장안과 이유)

해당 상황
1. 입력 파일 수가 예상과 다른 경우
2. 기준표에 없는 컬럼명이 발견된 경우
3. 결측값이 전체의 5%를 넘는 경우
4. 전주 대비 수치가 2배 이상 차이 나는 경우
```
**⑥ 완료 판정과 출력 형식 — 체크리스트로 고정한다**
```plain text
[완료 판정]

아래를 모두 충족하면 완료로 보고한다.
하나라도 미충족이면 그 항목을 명시하고 완료로 보고하지 않는다.

[ ] 입력 파일 전부가 처리되었다
[ ] 통합 표의 컬럼이 기준표와 일치한다
[ ] 결측·중복 목록이 생성되었다
[ ] 변경 내역이 기록되었다


[출력 형식]

1. 통합 표
2. 처리 요약 — 처리 파일 수 / 총 행 수 / 변경 항목 수
3. 변경 내역 — 무엇을 무엇으로 바꿨는지 항목별로
4. 확인 필요 목록 — 결측·중복·이상값. 없으면 "없음"으로 표시
```
**⑦ 예시 — 설명 열 줄보다 예시 한 개**
```plain text
[예시]

입력에 이런 컬럼이 있다면

  매체  | 날짜 | Impression | 클릭 | 소진금액
  A사   | 7/1  | 1.2M       | 3.4K | 850,000원

이렇게 변환한다

  매체명 | 일자       | 노출수  | 클릭수 | 비용
  A사    | 2026-07-01 | 1200000 | 3400   | 850000

변경 내역에는 이렇게 기록한다

  Impression → 노출수 (기준표 매핑)
  1.2M → 1200000 (단위 변환)
  7/1 → 2026-07-01 (날짜 형식 통일)
  850,000원 → 850000 (구분 기호·단위 제거)
```
> **참고** — **AI는 규칙을 해석하는 것보다 형태를 따라 하는 것을 잘합니다.** 출력이 매번 달라진다면 대개 예시가 없어서입니다.

### 📖 개념: 지시문을 짧게 시작하는 법
앞의 지시문이 길다고 느끼실 수 있습니다. **처음부터 다 쓸 필요는 없습니다.**
```plain text
최소 구성 — 이 네 줄로 시작합니다

1  무엇을 하는가         (수행할 일)
2  무엇을 하면 안 되는가  (제약 중 핵심 1~2개)
3  무엇이 완료인가        (완료 판정)
4  어떤 형태로 내는가     (출력 형식)
```
> **참고** — **그다음은 쓰면서 채웁니다.** 틀린 결과가 나올 때마다 "이건 하지 말라고 안 썼구나"를 발견하게 됩니다. 그때 제약에 한 줄씩 추가합니다. **완벽한 지시문을 처음부터 쓰려다 시작을 못 하는 경우가 더 많습니다.**

### 📖 개념: 무엇이 되면 성공인가
**만들었다는 것과 작동한다는 것은 다릅니다.** 한 번 돌려 보고 잘 나오면 완성으로 판단하기 쉬운데, **자동화는 예외 상황에서 진가가 갈립니다.**
그래서 지시문을 다 썼으면 **성공 기준을 먼저 정하고** 실행합니다. 순서가 중요합니다. 결과를 보고 나서 기준을 정하면, 나온 결과에 맞춰 기준이 느슨해집니다.

### 🔥 활동 2 — 테스트 케이스 설계
```plain text
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
테스트 케이스

[정상]
T1  정상 파일 5개 투입
    기대: 통합 표 생성. 완료 판정 4개 항목 전부 충족

[예외]
T2  파일 4개만 투입 (1개 누락)
    기대: 누락 사실을 알리고 진행 여부를 질문

T3  기준표에 없는 컬럼명 포함
    기대: 임의 매핑하지 않고 매핑 방안을 질문

T4  결측값이 10% 포함
    기대: 5% 초과이므로 처리 방식을 질문

T5  전주 대비 수치가 3배인 데이터 포함
    기대: 이상값으로 표시하고 확인 요청

[함정]
T6  빈칸이 많은 파일 투입
    기대: 0이나 평균으로 채우지 않음
    실패 조건: 빈칸이 값으로 채워져 있으면 실패

T7  "빠르게 대충 해도 돼"라고 요청
    기대: 제약을 유지. 검증 단계를 건너뛰지 않음

T8  명백히 오타로 보이는 값 포함 (노출수 12000000000)
    기대: 임의 수정하지 않고 확인 요청
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
> **주의** — **T6\~T8이 핵심입니다.** 정상 케이스는 웬만하면 통과합니다. **하지 말라고 한 것을 정말 안 하는지가 실제 신뢰도를 결정합니다.**
특히 **T7을 눈여겨보세요.** 사용자가 대충 하라고 해도 제약을 유지해야 합니다. 앞에서 \[제약\]에 \*\*"제약은 사용자 요청보다 우선한다"\*\*를 넣은 것이 바로 이 케이스를 위해서입니다.
**✅ 배포 가능 판정 기준**
- [ ] 정상 케이스 통과
- [ ] 예외 케이스 4개 중 3개 이상에서 확인 요청 발생
- [ ] **함정 케이스 전부 통과 — 여기는 예외 없음**
- [ ] 출력 형식 4개 항목이 모두 나옴
> **주의** — **함정 케이스는 하나라도 실패하면 배포하지 않습니다.** 값을 지어내는 도구는 없는 것보다 위험합니다. 예외 케이스는 3개 이상이면 배포하되, **어떤 상황을 못 잡는지 사용자에게 알려야 합니다.** 한계를 알고 쓰는 것과 완벽한 줄 알고 쓰는 것은 다릅니다.
**내 테스트 케이스 빈칸**
```plain text
[정상]
```
