**이번 PART에서는**, 명세와 데이터로 실제 동작하는 화면을 만들고, 만든 것이 내가 세운 기준을 실제로 만족하는지 점검합니다. 오늘 배운 세 개의 벽을 실제로 만나고 대응합니다. 오늘 가장 긴 PART입니다.

## 시작하기 전에

**한 번에 다 시키면 어디가 틀렸는지 못 찾습니다.** 그래서 뼈대부터 세우고 하나씩 쌓으면서 매번 확인합니다. 느려 보이지만 다시 만드는 것보다 빠릅니다. 그리고 저장을 나중에 붙이지 않습니다 - 화면을 다 만든 뒤에 저장을 넣으면 데이터를 다루는 부분을 통째로 다시 쓰게 됩니다. 브라우저 저장소 연결을 화면 만들기 초반에 넣습니다.

## Step 01 :: 먼저 "한 번에 다" 시켜봅니다.

**사람한테는 "보고서 하나 만들어줘"로 시키는데, AI는 왜 안 될까요.** 사람에게 그 말이 통하는 이유는 사람이 모르면 물어보기 때문입니다 - 애매하면 중간에 확인하고 일단 멈춥니다. AI는 묻지 않습니다. 애매한 것을 만나면 그 자리에서 스스로 정하고 계속 갑니다. 요청이 클수록 혼자 정해야 할 것이 많아지고, 그 결정들이 전부 물어봤어야 할 것들입니다. 더 곤란한 것은 고칠 때입니다 - "지연 기준만 바꿔줘"라고 하면 처음부터 통째로 다시 만듭니다. 그래서 작게 나눠 시킵니다.

새 세션을 열고 그대로 넣어봅니다.
```javascript
coding 폴더의 02_명세서.md 와 03_데이터.csv 을 읽고,
화면을 하나 만들어줘. 명세서에 적힌 대로 다 넣고 보기 좋게 만들어줘.

coding 폴더에 임시.html 로 저장해줘.
```
파일 탐색기에서 `임시.html`을 더블클릭해 열어봅니다.

**저장이 두 번째입니다.** 표를 만든 뒤에 저장을 붙이면 표를 다시 만들게 됩니다. 데이터를 어떻게 남길지 먼저 정해두고 그 위에 화면을 올립니다.


**핵심은 말투입니다.** "여기에 \~를 추가해줘"라고 하면 AI는 지금 화면을 재료로 받아 한 조각을 얹습니다. "\~하게 만들어줘"라고 하면 백지에서 다시 만듭니다. 앞의 것이 사라지면 "지금 있는 내용은 그대로 두고 아래에 추가만 해줘"를 명시적으로 붙입니다.

### ① 뼈대만
```javascript
[ 역할 ]
너는 광고 실무에서 쓰는 도구를 만드는 개발자다.

[ 할 일 ]
coding 폴더의 02_명세서.md 를 읽고 화면 틀만 만들어라.
지금은 제목과 기간만 넣고, 내용 자리는 비워 둔다.

[ 하면 안 되는 것 ]
- 외부에서 불러오는 것을 사용하지 않는다
- 요청하지 않은 기능을 추가하지 않는다

[ 출력 ]
coding 폴더에 04_결과물.html 파일 하나
```

**"요청하지 않은 기능을 추가하지 않는다"가 중요합니다.** 없으면 뼈대만 시켰는데 표와 계산까지 다 만들어버립니다.

### ② 저장소를 연결합니다.
```javascript
여기에 브라우저 저장소를 연결해줘.

사용자가 값을 바꾸거나 입력하면 저장소에 저장되고,
새로고침해도 그 내용이 그대로 남아야 해.
처음 열었을 때는 03_데이터.csv 의 내용으로 시작하고,
그 다음부터는 저장소에 있는 걸 우선해서 보여줘.

지금 있는 내용은 그대로 두고 추가만 해줘.
```

**"지금 있는 내용은 그대로 두고"를 빼지 마세요.** 없으면 앞에서 만든 뼈대가 사라지고 새로 만들어질 수 있습니다. 한 번 값을 바꾸고 나면 03_데이터.csv 은 더 이상 안 쓰입니다 - 저장소에 있는 것이 진짜 데이터가 됩니다.

### ③\~⑥ 기능을 하나씩 쌓습니다.
```javascript
③ 여기에 데이터를 표로 보여주는 부분을 추가해줘.
지금 있는 내용은 그대로 두고 아래에 추가만 해줘.
금액은 천 단위 쉼표, 숫자는 오른쪽 정렬로.
값이 비어 있으면 「미입력」으로 표시해줘.
```
```javascript
④ 그 위에 전체 요약을 추가해줘.
전체 건수와 단계별 개수를 숫자로.
계산에 쓴 건수와 제외한 건수도 함께 표시해줘.
```
```javascript
⑤ 표의 단계 칸을 색으로 구분해줘.
한눈에 구분되게, 다만 색은 세 종류를 넘지 않게.
```
```javascript
⑥ 맨 아래에 '확인 필요' 목록을 추가해줘.
값이 비어 있는 항목만 모으고, 왜 확인이 필요한지 사유를 한 줄씩 적어줘.
```

**④의 마지막 줄이 조용한 실패를 막는 장치입니다.** 15건 중 13건으로 계산했다고 화면에 나오면 2건이 빠진 것을 바로 압니다. 그리고 **매번 브라우저를 새로고침해서 확인하세요.** 이상한 것이 나오면 직전 한 걸음 안에 원인이 있습니다.

**화면이 멈추거나 아무 반응이 없으면 그것이 문제입니다.** 잘못된 값이 들어왔을 때 무엇이 일어나는지 알려주지 않는 것이 가장 나쁩니다. 그리고 화면에 나온 숫자 하나를 골라 원본 데이터와 직접 대조하세요 - 요약의 전체 건수가 데이터 개수와 같은가, 계산에 쓴 건수 + 제외한 건수 = 전체인가. 이걸 안 하면 틀린 것을 모른 채 넘어갑니다.

## Step 05 :: 세 개의 벽을 실제로 만납니다.

오전에 이름을 붙여둔 것들을 지금부터 실제로 만나게 됩니다. 증상이 나타나면 무슨 벽인지 먼저 판정하고 대응하세요 - **30초 판정법**을 다시 씁니다 (컨텍스트 붕괴 → 새 대화, 회귀 → 백업으로 되돌리기, 무한 왕복 → 즉시 멈추고 범위 축소, 조용한 실패 → 손으로 검산).

오류 메시지가 나오면 **빨간 글씨를 전부 드래그 → 복사 → 붙여넣기** 하면 됩니다. 무슨 뜻인지 몰라도 됩니다 - 원문을 그대로 주는 것이 핵심입니다.
안 될 때는 해결책을 지시하지 말고 증상만 설명합니다 - ❌「계산 부분을 다시 짜줘」 / ✅「요약에 전체 15건으로 나오는데 표에는 13건만 보입니다. 빈 값 두 건이 표에서 빠진 것 같습니다.」
수정할 때는 범위를 명시합니다.
```javascript
합계 계산을 고쳐줘.
다른 기능은 그대로 두고, 계산 부분만 수정해줘.
```

**새 기능만 확인하고 넘어가면 회귀를 놓칩니다.** 고친 뒤에는 이전 기능도 다시 눌러 보세요.

### 2회 규칙
**같은 것을 두 번 고쳐서 안 되면 그만 고칩니다.** 세 번째부터는 시간만 갑니다 - 실패한 시도가 대화에 쌓여서 고칠수록 나빠지기 때문입니다. 대신 둘 중 하나를 합니다: **A. 요구를 바꿉니다**("이 기능은 빼자. 대신 단순하게 목록으로만 보여줘") 또는 **B. 새로 시작합니다**(확정된 것 다섯 줄 요약 후 새 대화).


브라우저를 새로고침합니다. **그 칸만 비어 보입니다** - 화면은 '매체'라는 열을 찾는데 파일에는 '매체명'만 있기 때문입니다. 이름이 하나만 달라도 못 찾습니다. 사람은 같은 뜻으로 읽지만 기계는 글자 그대로 봅니다. 되돌립니다: `'매체명' 을 다시 '매체' 로 되돌려줘.`

**이게 실무에서 자주 나는 사고입니다.** 담당자마다 열 이름을 다르게 쓰면 - '매체' · '매체명' · '채널' - 합칠 때 다른 항목으로 잡힙니다. 그리고 이건 오류 메시지 없이 벌어집니다. 조용한 실패의 한 종류입니다.

### 사내 톤에 맞추기
화면을 팀에 돌릴 것이라면 **우리 회사에서 쓰는 표기**로 맞춰두는 편이 낫습니다. 색을 고르는 문제가 아니라 읽는 사람이 헷갈리지 않게 하는 문제입니다.
```javascript
아래 표기를 우리 팀 기준으로 맞춰줘. 다른 부분은 그대로 두고.
- 날짜는 YYYY-MM-DD
- 금액은 천 단위 쉼표, 단위는 원
- 단계 이름은 기획·제작·검수·승인·집행 다섯 가지만 사용
- 강조색은 한 화면에 한 종류만
```
### 처음 보는 사람 관점
만든 사람에게는 다 보입니다. 안 본 사람에게 보이는가가 문제입니다. 스스로 확인: 이 화면만 보고 무슨 자료인지 알 수 있나 / 숫자가 무엇의 숫자인지 알 수 있나 / "미입력"이 왜 미입력인지 알 수 있나.
옆 분의 화면을 3분간 보고, "이건 무슨 뜻이지?" 싶은 곳 한 군데만 말해줍니다. 서로 한 번씩 합니다.

**고쳐주지 마세요.** 어디가 안 읽히는지만 알려주면 됩니다. 업무가 서로 다르니 내용은 몰라도 됩니다 - 모르는 사람 눈이 필요한 것이라 오히려 낫습니다. 만든 사람은 자기 결과물을 제대로 못 봅니다 - 화면에 "진행률 82%"라고만 적혀 있어도, 만든 사람은 그것이 무엇의 82%인지 이미 알고 있어서 읽는 순간 머릿속에서 자동으로 채워 읽습니다.

지적받은 것을 그 부분만 고칩니다: `[지적받은 내용]을 고쳐줘. 다른 부분은 그대로 두고.`
