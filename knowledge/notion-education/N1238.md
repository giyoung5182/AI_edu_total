# STEP 2 : 응용 - 세부 요구사항 추출 및 유형 분류

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
실제 RFQ 문서를 분석해 견적 대응에 필요한 필수 정보와 기술 요구사항의 유형별 대응 전략을 수립합니다.
## 진행 단계
1. **2-1 견적 대응을 위한 필수 정보 추출** — 견적서 작성 시 반드시 확인할 핵심 입력 항목을 기술/상업/가격 항목으로 분류하고 요구 형식, 예상 난이도, 담당 부서를 정리합니다.
- 입력할 내용:
```javascript
당신은 CS 영업팀 견적 담당자입니다. 제Ⅲ편 견적서 양식을 분석하여 다음 정보를 테이블 형태로 정리해주세요.

[문서 내용 첨부]

| 구분 | 필수 입력 항목 | 요구 형식 | 예상 난이도 | 담당 부서 |
|------|----------------|-----------|-------------|-----------|
| 기술사항 | | | | |
| 상업사항 | | | | |
| 가격사항 | | | | |

난이도: 상(복잡한 계산/설계 필요), 중(기존 데이터 활용), 하(단순 입력)
담당부서: 영업팀, 기술팀, SCM팀, 품질팀 등
```
1. **2-2 기술 요구사항 상세 분석** — 제Ⅳ편 기술규격서에서 CS가 직접 대응 가능한 부분과 외부 협력이 필요한 부분을 구분합니다.
- 입력할 내용: 풍력발전 타워 전문 제조업체 CS의 기술팀장 관점에서 요구사항을 '직접 대응 가능 / 파트너 협력 필요 / 고위험 요구사항'으로 분류(각 항목별 요구사항·인증·품질 기준·위험 요소·대응 방안) (이하 교안 참고)
2. **2-3 납기 및 조건 분석** — 프로젝트 관리자 관점에서 일정 관련 요구사항을 분석합니다.
- 입력할 내용: 주요 마일스톤(계약 체결 후 → 설계 승인 / 설계 승인 후 → 제조 완료 / 제조 완료 후 → 현장 인도), Critical Path(가장 긴 작업·병목 구간·리스크 요소), 조건부 요구사항(날씨·운송·기타 제약) (이하 교안 참고)
- 정상 결과: 각 단계에 '결과예시' 토글의 이미지가 있습니다.
