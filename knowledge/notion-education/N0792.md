# 1️⃣ 아이디어를 3단계로 분해하기
## 1. 개발 사고방식의 기본: 입력(input) → 처리(Logic) → 출력(output)
- 대부분의 프로그램은 `무언가를 입력받고`, `규칙에 따라 처리한 뒤`, `결과를 출력`합니다.
- 이 틀을 이해하면 앱 구조가 갑자기 단순해집니다.
```mermaid
flowchart LR
A["입력"] --> B["처리"] --> C["출력"]
```
## 2. 각 단계는 무엇을 뜻하는가?
### 입력
- 사용자가 입력하는 값 또는 시스템이 받아오는 데이터
- 예: 이름, 날짜, 버튼 클릭, 파일 업로드, 설문 응답
### 처리
- 입력값을 검사, 계산, 저장, 분류하는 단계
- 예: 빈칸 확인, 중복 검사, 합계 계산, 카테고리 분류
### 출력
- 처리 결과를 보여주거나 전달하는 단계
- 예: 완료 메시지, 목록 화면, 이메일 전송, 보고서 생성

# 2️⃣ 업무 예시를 I-L-O로 바꿔보기
## 예시 1️⃣ 주간보고 3줄 요약기
1. Input: 부서별 주간 보고 텍스트
2. Logic: 핵심 내용을 압축하고 완료/진행중/이슈로 분류
3. Output: 3줄 요약 + 상태 카드
## 예시 2️⃣ 회의록 Action Item 추출기
1. Input: 회의 메모 또는 녹취 정리 텍스트
2. Logic: 담당자, 일정, 할 일을 찾아 분리
3. Output: Action Item 표와 할 일 목록
## 예시 3️⃣ 예산/KPI 시각화 대시보드
1. Input: 항목별 실적 숫자
2. Logic: 합계/달성률 계산, 항목별 비교
3. Output: KPI 카드 + 막대 차트
## 예시 4️⃣ 1on1 피드백 가이드
1. Input: 상황, 피드백 목적, 팀원 상태
2. Logic: 상황에 맞는 표현 톤과 질문 문장 생성
3. Output: 면담 질문 목록 + 피드백 스크립트 초안
## 예시 5️⃣ 팀 일정 시각화
1. Input: 팀원명, 일정 종류, 기간
2. Logic: 날짜 범위 정렬, 겹치는 일정 표시
3. Output: 팀 일정 보드 또는 간트형 레이아웃

# 3️⃣ AI가 알아듣는 PRD 작성법
## PRD는 AI에게 보내는 지시서입니다
이번 과정에서 PRD는 개발 문서라기보다 `AI에게 전달하는 설계 문서`입니다.
적지 않은 것은 AI가 임의로 해석합니다. 그래서 짧더라도 핵심이 들어간 PRD가 필요합니다.
## PRD에 꼭 들어갈 항목
1. 해결하려는 문제
2. 활용 상황
3. 입력값
4. 처리 규칙
5. 출력 형식
6. 예외 상황
7. 디자인/톤 가이드
8. 구현 제약 조건
9. 데이터 보안 조건
## 예시 데이터의 중요성
텍스트만 설명하는 것보다 예시 데이터를 2\~3줄 함께 주면 AI가 훨씬 정확하게 이해합니다.
예를 들어 KPI 대시보드라면 아래처럼 적습니다.
```plain text
예시 데이터
부서: 구매 / 목표: 120 / 실적: 98
부서: 영업 / 목표: 150 / 실적: 162
부서: 생산 / 목표: 200 / 실적: 187
```
> TIP: 예시 데이터는 실제 회사 데이터가 아니라 더미 값으로 작성합니다.
> 보안 기준: 실제 고객명, 임직원 개인정보, 계약·매출·인사 등 민감 정보는 그대로 입력하지 않습니다. 필요한 경우 형식만 유지한 더미 데이터 또는 익명화된 예시 데이터로 바꿔서 사용합니다.

# 4️⃣ 실습: 나만의 업무 병목을 PRD로 쓰기
## 실습 목표
1. 반복되는 문제를 하나 고릅니다.
2. I-L-O로 분해합니다.
3. AI에 바로 붙여넣을 수 있는 PRD 초안을 만듭니다.

## 진행 순서
### 1️⃣ 주제 고르기: 3가지 트랙 중 하나 선택
참여자의 AI 경험과 업무 상황이 다르기 때문에, 아래 3가지 방향 중 하나를 선택합니다. 중요한 것은 멋진 앱을 고르는 것이 아니라, 오늘 내가 끝까지 설명하고 검증할 수 있는 문제를 고르는 것입니다.
1. A 트랙: 내가 매주 반복하는 일 중 줄이고 싶은 것
2. B 트랙: 우리 팀원이 자주 막히는 일 중 도구로 풀어주고 싶은 것
3. C 트랙: 내가 한 번도 시도해본 적 없는 영역 중 오늘 처음 건드려보고 싶은 것

### 2️⃣ I-L-O 작성하기
아래 형식으로 작성합니다.
```plain text
선택 트랙(A/B/C):
문제:
활용 상황:
Input:
Logic:
Output:
예외 상황:
데이터 보안 조건:
```

### 3️⃣ PRD로 확장하기
아래 템플릿에 맞춰 문장을 채웁니다.
### PRD 작성 흐름
```plain text
[주제 선택]
   ↓
[I-L-O]
   ↓
[예외 상황 정리]
   ↓
[데이터 보안 조건 확인]
   ↓
[PRD 완성]
```
### AI에 붙여넣기 전 PRD 템플릿
```plain text
1. 사용 상황
-

2. 입력값(Input)
-

3. 처리 규칙(Logic)
-

4. 출력 형식(Output)
-

5. 디자인 가이드
-

6. 구현 제약
- HTML, CSS, JavaScript만 사용
- 하나의 HTML 파일로 완성
- 브라우저에서 바로 실행 가능해야 함

7. 데이터 보안 조건
- 실제 고객명, 임직원 개인정보, 계약·매출·인사 등 민감 정보는 입력하지 않음
- 필요한 경우 더미 데이터 또는 익명화된 예시 데이터만 사용
- 제출용 예시 데이터도 실제 회사 데이터가 아닌 테스트용 데이터로 작성
```


# 5️⃣ 실습: PRD로 단일 HTML 웹앱 구현하기
PRD를 작성했다면 바로 AI에 붙여넣어 실행 화면으로 연결합니다. 이 단계의 목표는 완벽한 앱이 아니라, 더미 데이터로 검증 가능한 단일 HTML MVP 초안을 만드는 것입니다.
## 구현 흐름
1. 작성한 PRD를 복사합니다.
2. AI에 붙여넣습니다.
3. AI가 만든 화면을 직접 조작합니다.
4. 더미 데이터로 입력, 처리, 출력이 맞는지 확인합니다.
5. 어색한 부분을 다시 자연어로 수정 요청합니다.

## 왜 단일 HTML인가요?
이번 교육에서는 `배포 환경`, `서버 연동`을 기본 실습 범위로 다루지 않습니다. 지금의 목표는 현업에서 바로 실행해볼 수 있는 프로토타입을 빠르게 만드는 것입니다.
HTML 단일 파일의 장점은 다음과 같습니다.
1. 더블클릭만으로 실행 가능합니다.
2. 사내 PC에서도 테스트가 쉽습니다.
3. 결과물 제출과 공유가 간단합니다.
4. 에러 포인트를 빠르게 잡을 수 있습니다.
> TIP: 이번 단계에서 중요한 것은 기술적 멋이 아니라 `실제 업무에 바로 써볼 수 있느냐`입니다.

# 6️⃣ 실습: PRD를 MVP로 구현하기
## 실습 목표
1. PRD를 그대로 붙여넣어 초안을 만듭니다.
2. 기본 동작을 직접 테스트합니다.
3. 더미 데이터로 결과물의 방향성을 검증합니다.
## 진행 순서
### 1️⃣ 마스터 프롬프트 준비하기
다음 프롬프트 뒤에 방금 작성한 PRD를 붙여넣습니다.
### AI에 붙여넣을 마스터 프롬프트
```plain text
아래 PRD를 바탕으로 브라우저에서 바로 실행 가능한 업무용 웹앱을 만들어줘.

반드시 HTML, CSS, JavaScript만 사용해서 하나의 HTML 파일로 완성해줘.
외부 프레임워크는 사용하지 말고, 복사해서 저장한 뒤 바로 실행할 수 있어야 해.

필수 조건
1. 입력 영역이 명확해야 함
2. 실행 버튼이 명확해야 함
3. 결과 영역이 명확해야 함
4. 버튼 클릭 시 즉시 반응해야 함
5. 오류 또는 빈 입력 시 안내 문구가 보여야 함
6. 더미 데이터 자동 입력 버튼이 있어야 함
7. 결과 복사 버튼이 있어야 함
8. 복잡하지 않은 비즈니스 스타일이어야 함
9. 실제 회사 데이터 입력을 유도하지 않아야 함

아래는 PRD야.
[여기에 작성한 PRD 붙여넣기]
```

### 2️⃣ 기본 완성 기준 확인하기
초안이 생성되면 아래 기준을 먼저 확인합니다. 이 기준을 만족하면 공통 필수 산출물인 단일 HTML MVP로 인정합니다.
1. 입력창이 있는가?
2. 실행 버튼이 실제로 눌리는가?
3. 결과 영역이 보이는가?
4. 입력을 바꾸면 출력도 바뀌는가?
5. 빈 입력이나 잘못된 입력에 안내 문구가 나오는가?
6. 더미 데이터 자동 입력 버튼이 있는가?
7. 결과 복사 버튼이 있는가?

### 3️⃣ 더미 데이터로 검증하기
실제 회사 데이터 대신 더미 데이터를 넣어 테스트합니다. 고객명, 임직원 개인정보, 계약·매출·인사 정보처럼 민감할 수 있는 값은 AI에 그대로 입력하지 않습니다.
예를 들어 KPI 도구라면 아래처럼 테스트할 수 있습니다.
```plain text
구매팀 목표 120 실적 98
영업팀 목표 150 실적 162
생산팀 목표 200 실적 187
```

### 4️⃣ 첫 번째 수정 요청 넣기
다음과 같은 방식으로 수정 요청을 보냅니다.
1. `결과를 표 말고 카드 형태로 보여줘.`
2. `빈 값이 있으면 빨간 안내 문구를 보여줘.`
3. `복사 버튼을 추가해줘.`
4. `제목을 더 직관적으로 바꿔줘.`
