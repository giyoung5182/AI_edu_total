# 만들기 전에 자리부터 정합니다
이미지를 만들기 전에 **어떤 정보가 어디 들어가는지**부터 정해요. 이게 정해져야 여백을 어디에 확보할지 결정됩니다.
```plain text
[위쪽 1/3]   행사명 (가장 큰 글씨)
             한 줄 설명
                 ↓
[가운데]     그래픽 영역  ← AI가 만드는 부분
                 ↓
[아래쪽 1/3] 일시 / 장소 / 신청 방법
                 ↓
[맨 아래]    센터명
```

**여기서 나온 결론이 프롬프트의 마지막 문장이 됩니다**
`위쪽 3분의 1과 아래쪽 3분의 1은 단색 여백으로 비워 두고, 그래픽은 가운데 영역에만 배치해 줘.`
`원리 넷`의 긍정형 전환이기도 해요. 여백을 안 잡아두면 나중에 문구 얹을 자리가 없어서 결국 다시 만들게 됩니다.

한 가지만 더. **정보가 많은 게시물일수록 배경은 단순해야 해요.** 배경이 복잡하면 글자가 안 읽힙니다. 센터 정책 안내 카드뉴스가 잘 읽히는 이유가 이거예요. 배경이 거의 단색이고 캐릭터 하나만 있죠.

# 안 되는 문장과 되는 문장
## 사례 1 · 연합 운동회 모집
```plain text
안 되는 문장

"청년 운동회 홍보 포스터 만들어 줘. 활기차고 재밌게."
```

**뭐가 문제냐면**
형용사만 있고 `원리 셋`, 규격과 여백 지정이 없어요. 그리고 "운동회"는 시각적 형태가 너무 넓어서 AI가 알아서 정해버립니다.

```plain text
되는 문장

굵은 외곽선의 플랫 일러스트 스타일로 만들어 줘.
화면 가운데에 둥근 캐릭터 세 명이
각각 노랑, 분홍, 파랑 옷을 입고 나란히 서서
한쪽 팔을 위로 들어올린 모습으로 그려 줘.
얼굴은 점 두 개로 된 눈과 작은 곡선 입만 있고,
머리와 몸의 비율은 1대 1로 해 줘.
정면에서 눈높이로 본 수평 구도,
모든 면을 단색으로 채우고 경계선은 뚜렷하게.
배경은 연한 크림색 단색이야.
위쪽 3분의 1과 아래쪽 3분의 1은 연한 크림색 단색으로 비워 두고
캐릭터는 가운데 영역에만 배치해 줘.
정사각형 1대 1 비율, 고해상도.

[금지]
- 그림자와 그라데이션
- 사진 같은 사실적 표현
- 이미지 안의 설명 문구
```
**차이를 만든 문장** — "머리와 몸의 비율은 1대 1", "눈은 점 두 개". 이게 `원리 셋`의 형용사 제거예요. 그리고 금지 블록을 본문 밖으로 뺀 게 `원리 넷`이고요.

## 사례 2 · 정책 안내 카드뉴스
```plain text
안 되는 문장

"청년 교통비 지원 카드뉴스. 깔끔하고 눈에 띄게. 글씨 없이."
```

**뭐가 문제냐면**
"글씨 없이"가 `원리 넷` 정면 위반이고요. "깔끔하고 눈에 띄게"는 서로 충돌하는 요구예요. 무엇을 그릴지도 없고요.

```plain text
되는 문장

플랫 벡터 일러스트 스타일로 만들어 줘.
화면 가운데에 파란 시내버스 한 대를 정측면에서 본 모습으로,
바퀴와 창문만 단순한 도형으로 표현해 줘.
버스만 화면에 두고 다른 사물은 비워 줘.
정면 수평 구도, 균일한 조명,
색은 흰 배경에 하늘색과 연두색 두 가지만 사용하고
모든 면은 단색으로 채워 줘.
위쪽 40퍼센트와 아래쪽 30퍼센트는 흰색 단색으로 비워 두고
버스는 가운데에만 배치해 줘.
정사각형 1대 1 비율, 고해상도.

[금지]
- 이미지 안의 설명 문구
- 금액이나 날짜 표기
- 실제 존재하는 로고나 기관 마크
```

**금액을 왜 금지하냐면**
정책 홍보에서 제일 위험한 게 숫자예요. AI가 50퍼센트를 70퍼센트로 그려놔도 그럴듯해 보입니다.
**숫자는 사람이 넣습니다.** 예외 없어요.

# STYLE LOCK · 수정할 때 제일 중요한 한 줄
`원리 하나`
수정이 실패하는 가장 흔한 이유는 **고쳐달란 것 말고 딴 것까지 바뀌기 때문**이에요.
AI는 이미지를 부분적으로 고치는 게 아니라 **원본을 참고해서 새로 그립니다.** 지키라고 말 안 한 건 안 지켜져요.

**원칙 — 바꿀 것보다 "바꾸지 말 것"을 더 길게 씁니다**

수정 프롬프트 맨 앞에 이걸 붙이세요.
```plain text
STYLE LOCK — 아래는 그대로 유지할 것:
- 구도와 시선 높이
- 캐릭터의 생김새와 비율
- 색상 규칙과 선 굵기
- 배경 처리 방식
- 상하단 여백의 크기

내가 명시적으로 요청한 것만 바꿀 것. 나머지는 전부 동일하게.

[바꿀 것]
- (여기에 하나만)
```

**한 번에 하나만 고치세요**
두 가지를 동시에 요청하면 AI가 방향을 잃어요. 여백도 넓히고 색도 바꾸고 싶으면 두 번에 나눠서.
서포터즈 활동에서 이게 결정적인 이유는 **행사 하나에 이미지가 여러 장 필요하기 때문**이에요. 첫 장이 잘 나왔는데 "이거랑 비슷하게 하나 더"라고만 하면 전혀 다른 그림이 나옵니다.

# 시연 · 처음부터 완성까지
강사가 화면으로 진행합니다. 지금 따라 하지 않으셔도 돼요. **순서만 눈에 익히시면 됩니다.**
**소재** 2026 충북청년축제 연합 운동회 (9월 19일, 맹동혁신국민체육센터)

**핵심은 이미지를 만들기 전에 텍스트로 방향을 끝내는 겁니다**
1·2단계를 건너뛰고 바로 생성하면, 마음에 안 들 때마다 재생성하게 돼요. 무료 한도를 태워먹는 제일 흔한 패턴입니다.
그리고 더 중요한 게 있어요. **1권에서 본 조기 수렴을 막는 게 바로 이 1·2단계입니다.** 바로 생성하면 첫 결과물에 갇히고, 방향을 먼저 세 개 보면 그게 안 생깁니다.
**세 번에 끝낼 일을 열다섯 번 쓰면 그날 활동이 거기서 끝나요.**






단계

무엇을 하나

같이 보실 것




**1. 발산**

"배경 컨셉 3가지 방향으로 제안해 줘. 이미지는 아직 만들지 마"

세 방향이 왜 그렇게 다른지. 하나만 보면 괜찮아 보이는 것도 셋을 놓고 보면 금방 판단돼요




**2. 설계**

"2번 방향으로 6요소 프롬프트 작성해 줘. 아직 만들지 마"

내가 빠뜨린 요소를 AI가 채워주는 지점




**3. 생성**

완성된 프롬프트로 1회 생성

결과가 프롬프트와 어디가 다른지 `원리 다섯`




**4. 수정**

**STYLE LOCK 빼고 한 번, 넣고 한 번**

**요청 안 한 것까지 바뀌는 걸 직접 보셔야 이 원칙이 와닿습니다**




**5. 문구**

캔바로 옮겨서 행사명·일시·장소·링크 올리기

여백을 미리 잡아둔 게 얼마나 편한지




**6. 규격**

정사각형 저장 → 같은 배경으로 스토리 하나 더

배경 하나로 두 규격이 나오는 것



**언제 멈추나**
같은 시도를 **3번** 했는데 나아지지 않으면 중단하세요. 20분 넘게 붙들고 있으면 손을 떼는 게 맞아요.
이건 포기하라는 뜻이 아니에요. **수정을 멈추고 1단계로 돌아가서 방향을 다시 받으라는 신호**입니다. 조기 수렴에 빠졌다는 증거니까요.
