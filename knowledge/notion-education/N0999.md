## 02. 데이터 기반 행정 및 의사결정 구조 이해

** “감”이나 “경험”만으로 판단하지 않고, 데이터를 근거로 합리적인 의사결정을 하는 방식입니다.**

<details>
<summary>**☑️ 데이터 기반 행정이란 무엇인가요?**</summary>
**데이터 기반 행정은 공공기관이 보유한 데이터를 수집·분석·활용하여 정책과 행정 업무의 품질을 높이**
**는 방식입니다. **기존에는 담당자의 경험, 관행, 직관에 따라 의사결정이 이루어지는 경우가 많았습니
다. 하지만 데이터 기반 행정에서는 실제 업무 데이터를 바탕으로 문제를 확인하고, 원인을 분석하고,
개선 방안을 결정합니다. 예를 들어 다음과 같은 질문들이 데이터 기반 행정의 출발점이 될 수 있어요.

- 어느 지역에서 열 사용량이 빠르게 증가하고 있는가?
- 여름/겨울철 피크 수요는 어떤 조건에서 발생하는가?
- 설비 고장은 특정 설비나 특정 시기에 반복되는가?
- 고객 민원은 어떤 유형이 가장 많은가?
- 안전사고나 아차사고는 어떤 작업에서 자주 발생하는가?
- 예산과 인력을 어느 업무에 우선 배치해야 하는가?

**즉, 데이터 기반 행정은 단순히 데이터를 많이 모으는 것이 아니라, 업무 문제를 데이터로 설명하고,**
**더 나은 의사결정으로 연결하는 과정입니다.**

</details>
<details>
<summary>**☑️ 경험 기반 의사결정과 데이터 기반 의사결정의 차이**</summary>
**경험은 여전히 중요합니다. 다만,  경험만으로 판단하면 개인의 기억, 익숙한 방식, 부서별 관행에 따라**
**판단이 달라질 수 있습니다. 데이터 기반 의사결정은 경험을 배제하는 것이 아니라, 경험과 데이터를**
**함께 사용하여 판단의 정확도를 높이는 방식입니다.**

<summary>**☑️ 데이터 기반 의사결정에서 주의할 점**</summary>
**데이터가 있다고 해서 항상 올바른 의사결정이 가능한 것은 아닙니다. **데이터를 잘못 해석하면 오히려
잘못된 결론을 낼 수도 있습니다. 주의해야 할 점은 다음과 같습니다.

- **데이터가 최신인지 확인해야 합니다.**
- **데이터가 누락되거나 잘못 입력된 것은 아닌지 확인해야 합니다.**
- **단위가 통일되어 있는지 확인해야 합니다.**
- **평균만 보지 말고 예외 상황도 함께 봐야 합니다.**
- **숫자만 보고 현장 맥락을 무시하면 안 됩니다.**
- **상관관계를 원인관계로 착각하면 안 됩니다.**
- **분석 결과가 실제 업무에서 실행 가능한지 검토해야 합니다.**

고객 수가 증가했거나, 신고 채널이 확대되었거나, 특정 계절적 요인이 있었을 수도 있습니다.
**따라서 데이터 분석 결과는 항상 업무 맥락과 함께 해석해야 합니다.**

## 03. 데이터 거버넌스란?

**조직이 데이터를 정확하고 안전하며 일관되게 관리하기 위한 원칙과 체계입니다.**

<details>
<summary>**☑️ 데이터 거버넌스의 의미**</summary>
데이터를 많이 보유하고 있어도, 데이터의 기준이 부서마다 다르거나 품질이 낮거나 보안 관리가 되지 않으면 제대로 활용하기 어렵습니다. **데이터 거버넌스는 데이터를 조직의 중요한 자산으로 보고, 누가, 어떤 기준으로, 어떻게 관리하고 활용할지 정하는 체계입니다. **데이터를 활용하려면 다음 질문에 답할 수 있어야 합니다.
[원본 이미지 제외]
- 이 데이터는 어디에서 생성되었나요?
- 누가 관리하나요?
- 어떤 기준으로 입력되나요?
- 같은 용어를 부서마다 다르게 쓰고 있지는 않나요?
- 데이터가 정확한가요?
- 누가 접근할 수 있나요?
- 외부에 공개해도 되는 데이터인가요?
- 개인정보나 민감정보가 포함되어 있나요?
- 문제가 생기면 누가 책임지고 수정하나요?

</details>
<details>
<summary>**☑️ 왜 데이터 거버넌스가 필요한가요?**</summary>
**데이터 분석과 AI 활용이 잘 되려면 데이터 자체가 신뢰할 수 있어야 합니다. 하지만 실제 조직에서는 다음과 같은 문제가 자주 발생합니다.**
- 같은 의미의 데이터가 부서마다 다른 이름으로 관리됨
- 같은 지표인데 계산 방식이 다름
- 데이터 입력 기준이 명확하지 않음
- 오래된 데이터와 최신 데이터가 섞여 있음
- 데이터 오류를 발견해도 수정 책임자가 불명확함
- 개인정보와 내부자료의 접근 권한이 명확하지 않음
- 데이터가 시스템별로 흩어져 있어 연결하기 어려움
- 보고서마다 수치가 달라 신뢰도가 떨어짐

이런 문제가 있으면 분석 결과도 신뢰하기 어렵습니다. 예를 들어 “열 판매량”이라는 지표가 있다고 했을 때, 어떤 부서는 월 기준으로 보고, 어떤 부서는 일 기준으로 보고, 어떤 부서는 특정 지역만 포함하고, 어떤 부서는 전체 지역을 포함한다면 같은 용어를 쓰더라도 결과가 달라질 수 있습니다.
**데이터 거버넌스는 이런 혼란을 줄이고, 조직 전체가 같은 기준으로 데이터를 이해하고 활용할 수 있게 합니다.**

</details>

## 04. 사례로 살펴공보는 공공기관 데이터 관리

**공공기관 데이터 관리는 공공서비스의 품질과 행정의 신뢰도를 높이는 일입니다.**

<details>
<summary>**☑️ 사례 1. 열 수요 데이터 관리**</summary>
교육기관 10와 같은 에너지 기관에서는 열 수요 데이터가 매우 중요합니다.
열 수요 데이터는 공급 계획, 설비 운영, 피크 대응, 에너지 효율 관리에 활용될 수 있습니다.
### **👤 상황**
겨울철 특정 지역에서 열 사용량이 급격히 증가했습니다. 담당자는 해당 지역의 수요 증가 원인을 파악
하고, 다음 겨울철 공급 계획에 반영해야 합니다.
### ⭕ **활용 가능한 데이터**
- 지역별 열 사용량
- 시간대별 열 공급량
- 외부 기온
- 요일 및 공휴일 여부
- 세대 수 변화
- 건물 유형
- 과거 피크 수요
- 설비 가동 현황
### 🔐 데이터 관리 포인트
- 지역명이 표준화되어 있어야 합니다.
- 열 사용량 단위가 통일되어 있어야 합니다.
- 시간 기준이 일별, 월별, 시간대별로 명확해야 합니다.
- 기상 데이터와 연결할 수 있어야 합니다.
- 과거 데이터와 현재 데이터를 비교할 수 있어야 합니다.
### ⚠️ 잘 관리되지 않았을 때의 문제
- 지역명이 다르게 입력되어 지역별 비교가 어려움
- 일부 기간의 데이터가 누락되어 수요 증가 원인을 잘못 해석함
- 단위가 섞여 있어 사용량 계산이 틀어짐
- 기상 데이터와 연결되지 않아 날씨 영향을 분석하기 어려움
### 🔑 데이터 기반 개선 방향
- 지역코드와 지역명을 표준화합니다.
- 열 사용량 단위를 통일합니다.
- 기상 데이터와 연계 가능한 기준일자를 관리합니다.
- 피크 수요 발생 조건을 지속적으로 모니터링합니다.
- 수요 예측 모델에 활용할 수 있도록 데이터를 정리합니다.

</details>
<details>
<summary>**☑️ 사례 2. 설비 운영 및 정비 데이터 관리**</summary>
설비 데이터는 안정적인 열 공급과 안전한 운영을 위해 매우 중요합니다.
설비 고장 이력과 운전 데이터를 잘 관리하면 예방 정비와 이상 징후 탐지에 활용할 수 있습니다.
### **👤 상황**
특정 설비에서 반복적으로 알람이 발생하고 있습니다.
하지만 알람 원인과 정비 이력이 여러 시스템에 흩어져 있어 정확한 원인 파악이 어렵습니다.
### ⭕ **활용 가능한 데이터**
- 설비 마스터 정보
- 설비 위치
- 온도, 압력, 유량 등 센서 데이터
- 알람 발생 이력
- 고장 이력
- 정비 이력
- 부품 교체 이력
- 점검 결과
### 🔐 데이터 관리 포인트
- 설비 코드가 일관되게 관리되어야 합니다.
- 설비별 운전 데이터와 정비 이력이 연결되어야 합니다.
- 알람 유형이 표준화되어야 합니다.
- 정비 결과가 자유 문장으로만 남지 않도록 주요 항목을 구조화해야 합니다.
- 설비의 변경, 교체, 폐기 이력이 관리되어야 합니다.
### ⚠️ 잘 관리되지 않았을 때의 문제
- 같은 설비가 시스템마다 다른 이름으로 저장됨
- 고장 이력과 정비 이력을 연결하기 어려움
- 알람 유형이 제각각 입력되어 반복 패턴 분석이 어려움
- 예방 정비보다 사후 대응 중심으로 업무가 진행됨
### 🔑 데이터 기반 개선 방향
- 설비 마스터 데이터를 정비합니다.
- 설비 코드, 위치, 유형, 관리부서를 표준화합니다.
- 알람 유형과 고장 유형을 코드화합니다.
- 정비 이력을 구조화된 항목으로 입력합니다.
- 고장 발생 전 센서값 변화를 분석하여 이상 징후를 조기에 파악합니다.

</details>
<details>
<summary>**☑️ 사례 3. 안전관리 데이터 관리**</summary>
공공기관의 안전관리는 사고 발생 후 대응보다 예방이 중요합니다.
안전 관련 데이터를 체계적으로 관리하면 위험 작업을 사전에 파악하고, 반복되는 사고 요인을 줄일 수 있습니다.
### **👤 상황**
작업허가서와 위험성평가서는 작성되고 있지만,
문서가 개별 파일로 흩어져 있어 반복되는 위험 요인을 분석하기 어렵습니다.
### ⭕ **활용 가능한 데이터**
- 작업허가서
- 위험성평가서

- 작업 유형
- 작업 시간

- 안전교육 이수 정보
### 🔐 데이터 관리 포인트

- 사고와 아차사고를 같은 기준으로 관리해야 합니다.
- 문서형 데이터도 검색과 분석이 가능하도록 구조화해야 합니다.
- 개인정보와 민감정보는 적절히 보호해야 합니다.
### ⚠️ 잘 관리되지 않았을 때의 문제
- 위험성평가 문서가 많아도 반복 위험 요인을 찾기 어려움
- 사고사례가 축적되어도 교육 자료로 활용하기 어려움
- 작업 유형별 위험 수준을 비교하기 어려움
- 유사 사고가 반복될 가능성이 높아짐
### 🔑 데이터 기반 개선 방향
- 작업 유형, 위험 요인, 사고 유형을 표준화합니다.
- 사고사례와 아차사고를 함께 관리합니다.
- 자주 발생하는 위험 요인을 대시보드로 모니터링합니다.
- 안전교육 자료와 연결합니다.
- 생성형 AI를 활용할 경우, 민감정보를 제거한 뒤 문서 요약이나 위험 요인 분류에 활용합니다.

## 05. 요약

**금일 수업내용을 복기해 보겠습니다. **

- 데이터는 업무 과정에서 만들어지는 기록이며, 의사결정의 중요한 근거가 됩니다.
- 데이터 분석은 숫자를 정리하는 일이 아니라, 업무 문제의 원인과 패턴을 찾는 과정입니다.
- 데이터 매니저와 데이터 분석가는 데이터를 통해 조직의 더 나은 판단을 돕는 역할을 합니다.
- 좋은 데이터 분석은 도구 사용보다 문제를 정확히 정의하는 것에서 시작됩니다.
- 데이터 기반 행정은 경험을 버리는 것이 아니라, 경험에 데이터를 더해 더 객관적으로 판단하는 방식입니다.
- 공공기관에서는 의사결정의 객관성, 설명 가능성, 책임성이 특히 중요합니다.
- 데이터 거버넌스는 조직이 데이터를 믿고 사용할 수 있도록 기준, 책임, 품질, 보안을 관리하는 체계입니다.
- 데이터 품질이 낮으면 분석 결과도 왜곡되고, 잘못된 의사결정으로 이어질 수 있습니다.
- 공공기관 데이터 관리는 데이터를 저장하는 일이 아니라, 업무와 공공서비스에 활용 가능한 상태로 만드는 일입니다.
- AI와 데이터 분석을 잘 활용하려면 먼저 데이터가 정확하고 안전하며 일관되게 관리되어야 합니다.
