## 이 시간의 구조
```plain text
13:05~13:35   2주 실행계획 수립 (전원)      ← 컨설팅 전에 먼저 합니다
13:35~14:45   1:1 컨설팅 (순번) + 고도화 작업
14:45~15:00   마무리 · 12회차 안내
```
**실행계획을 먼저 세우는 이유**는, 컨설팅에서 "무엇을 만들까"만 이야기하면 2주 뒤에 또 "만들었는데 아무도 안 쓴다"가 되기 때문입니다. **누구에게 어떻게 쓰게 할지를 먼저 정해놓고**, 그것을 전제로 무엇을 만들지 상의합니다.

# 1부. 2주 실행계획 수립 (30분)
---
## 이번 과제는 "만들기"가 아닙니다
```plain text
지금까지의 과제      "이런 기능을 만들어 오세요"
이번 과제           "만든 것을 실제로 남이 쓰게 해보고, 관찰해 오세요"
```
**12회차 발표의 중심이 여기입니다.** "기능을 추가했습니다"가 아니라 \*\*"누구에게 일주일간 쓰게 했더니 이런 일이 있었습니다"\*\*가 발표 내용이 됩니다.
---
## 과제 요건 다섯 가지
```plain text
① 개선한 앱을 최소 1주일 이상 실제로 운영할 것
② 나 말고 최소 1명 이상이 쓰게 할 것
③ 그 사람이 볼 설명서를 만들 것
④ 쓰는 동안 관찰한 것을 기록할 것        (워크시트 시트 5)
⑤ 관찰 결과로 개선안을 정리할 것         (워크시트 시트 6)
```
> **②가 이번 과제의 핵심입니다.** 한 명이라도 실제로 써보면, 혼자 두 달 고민해도 안 나올 것이 하루 만에 나옵니다.
---
## 왜 남에게 쓰게 하는가
```plain text
만든 사람이 보는 것        쓰는 사람이 보는 것
─────────────────────────────────────────
"여기 누르면 되는데"       "이게 버튼인지 몰랐어요"
"당연히 이 순서지"         "뭐부터 해야 하죠?"
"그건 그냥 넘어가면 돼"    "오류가 떠서 멈췄어요"
"이 정도면 편하지"         "그냥 카톡이 빠른데요"
```
**만든 사람 눈에 잘 보이는 것이 쓰는 사람에게는 전혀 아닌 경우가 많습니다.** 이걸 확인하는 유일한 방법은 실제로 시켜보는 것입니다.
### 1권에서 본 세 가지가 여기서 만납니다
```plain text
MIT 조사      성공한 5%의 공통점 = "실제로 쓸 사람들과 협업한 것"
JPMorgan     확산은 지시가 아니라 "쓸 수 있으니까" 일어났다
Klarna       사람을 다 빼려다 되돌렸다. 역할을 나누는 것이 답이었다
```
**세 사례가 같은 것을 말합니다.** 만드는 사람의 머릿속이 아니라 **쓰는 사람의 현실에서 검증되어야** 살아남습니다. 2주간의 실행이 그 검증입니다.
---
## 실행계획 작성 — 워크시트 시트 4
여섯 항목을 채웁니다.
### ① 누구에게 쓰게 할 것인가
```plain text
이름과 부서를 구체적으로 적습니다.

  못 씀   "총무팀 사람들"
  잘 씀   "총무팀 김○○ 대리"

한 명이면 충분합니다. 여러 명이면 더 좋지만,
한 명도 확실히 못 정하면 2주가 그냥 갑니다.
```
**누구를 고를까**
```plain text
좋은 후보
  · 이 업무를 실제로 자주 하는 사람
  · 평소 소통이 되는 사람
  · 새 도구에 거부감이 적은 사람

피할 후보
  · 이 업무와 무관한 사람 (형식적으로만 써봄)
  · 지금 극도로 바쁜 사람
```
### ② 어떤 목적으로 쓰게 할 것인가
```plain text
그 사람이 앱으로 무엇을 하게 되는지 적습니다.

  예) 결제 요청을 카톡 대신 앱으로 등록하게 하고,
      나는 앱에서 등록 여부를 확인한다

★ "무엇을 안 하게 되는지"도 함께 적으세요
  예) 그 사람은 더 이상 나에게 카톡을 보내지 않는다
```
### ③ 언제부터 언제까지
```plain text
최소 7일 이상. 날짜를 못 박으세요.

  예) ○월 ○일(월) ~ ○월 ○일(일)

기간이 짧으면 관찰할 것이 안 나옵니다.
2주 중 최소 1주는 확보하세요.
```
### ④ 쓰게 하기 전에 준비할 것
```plain text
□ 계정 발급 (또는 접속 방법 안내)
□ 설명서 전달
□ 5분 시연 (직접 보여주기)
□ "시범 기간"이라고 알리기
```
> **④를 안 하면 대부분 안 씁니다.** 링크만 던져주고 "써보세요"라고 하면 한 번 열어보고 끝납니다. **5분 시연이 가장 효과적입니다.**
### ⑤ 설명서는 어떤 형태로
```plain text
형태 후보
  · A4 한 장 (인쇄해서 책상에)
  · 카톡으로 보낼 이미지 한 장
  · 앱 안에 안내 문구로 넣기
  · 짧은 화면 녹화 (2~3분)

→ 그 사람이 실제로 볼 만한 형태로 고르세요.
  긴 문서는 안 읽습니다.
```
### ⑥ 협조를 어떻게 구할 것인가
```plain text
예) 부서 회의 때 5분 설명 후 시범 기간이라고 안내
    점심 때 옆자리에서 직접 보여주기
    부서장에게 먼저 알리고 진행
```
**"시범 기간"이라고 말하는 것이 중요합니다.** 완성품이라고 하면 문제가 생겼을 때 말을 안 해줍니다. 시범이라고 하면 오히려 적극적으로 알려줍니다.

[계정 정보가 포함된 표 제외]

```plain text
분류    계정 / 기능 / 입력 / 사용법 / 속도 / 기타
```

### 특히 놓치기 쉬운 기록 두 가지
```plain text
① "아무 일도 없었던 날"
   문제가 없으면 안 적게 되는데, 그것도 기록입니다.
   "3/8 — 김 대리 2건 등록, 문제 없음"
   → 잘 돌아간 날이 며칠인지가 성과의 근거가 됩니다

② "안 쓴 날"
   그 사람이 안 쓴 날이 있으면 반드시 적으세요.
   왜 안 썼는지가 가장 값진 정보입니다.
   "3/9 — 바빠서 그냥 카톡으로 보냈다고 함"
   → 앱이 아직 기존 방식보다 편하지 않다는 신호
```
**1권에서 본 조용한 실패가 여기서도 적용됩니다.** 아무 소식이 없는 것과 잘 돌아가는 것은 다릅니다. **주 1회는 직접 물어보세요.** "그거 쓰고 계세요?" 한마디면 됩니다.


```plain text
강사가 한 명씩 순서대로 만납니다.
```

# 3부. 컨설팅 대기 중 작업
---
**기다리는 동안 각자 작업합니다.** 아래 세 갈래 중 자기 항목에 맞는 것으로 가세요.
```plain text
갈래 A   앱 밖과 잇는 것 (알림·내보내기)      → 3-1
갈래 B   앱 안을 고치는 것 (화면·계정·표시)    → 3-2
갈래 C   설명서·안내 만들기                   → 3-3
```
> **오늘 다 못 끝내도 됩니다.** 2주가 있습니다. 오늘은 **시작하는 것**이 목표입니다.
---
## 3-1. \[갈래 A\] 앱 밖과 잇기
**Cursor를 거의 쓰지 않는 작업입니다.** 크레딧 걱정 없이 진행할 수 있습니다.
### 자동 알림 붙이기 (GAS)
앱 데이터가 구글시트에 있거나 시트로 내보낼 수 있는 경우입니다.
```plain text
Claude에게 요청할 내용

구글 앱스크립트 코드를 만들어줘.
[시트 이름] 시트에서 [조건]에 해당하는 행을 골라
[주기]마다 [받는 사람 메일]로 요약 메일을 보내줘.

메일에 포함할 것
- 해당 건수
- 건별 목록 (표 형태)
- 생성 시각
- 해당 건이 0건이어도 "0건입니다"로 메일을 보내줘
```
**마지막 줄이 중요합니다.** 0건이어도 메일이 와야 안 오는 것으로 고장을 알 수 있습니다.
```plain text
설치 순서
① 구글시트 → 확장 프로그램 → Apps Script
② 코드 붙여넣기 → 저장 → 실행 (첫 실행 시 권한 승인)
③ 왼쪽 [트리거] → 트리거 추가 → 시간 기반 → 주기 설정
```
### 서비스 연결 (Make)
```plain text
시나리오 구성
① 트리거   구글시트 새 행 추가 감지 (또는 Webhook)
② 필터     조건에 맞는 건만 통과
③ 액션     이메일 또는 메신저 발송

설정 후 확인
□ 시나리오가 ON(활성) 상태인가
□ 실행 기록(History)에서 성공했는가
□ 실패한 실행의 사유는 무엇인가
```
### 기존 양식으로 내보내기
병행을 없애거나 잇는 데 가장 효과적인 방법입니다.
```plain text
Cursor에 요청

현재 목록을 엑셀 파일로 다운로드하는 버튼을 추가해줘.
열 순서는 [기존 양식의 열 순서]로 맞춰줘.
파일명은 [양식명]_날짜 형태로 해줘.
```
**기존에 쓰던 엑셀 양식과 열 순서를 맞추는 것이 핵심입니다.** 그래야 그대로 붙여넣거나 업로드할 수 있습니다.

## 3-2. \[갈래 B\] 앱 안 고치기

## 12회차 안내
```plain text
12회차에 하는 것
  ① 개인 발표 (1인 15분)
  ② 사내 지식베이스 정리 — 구글 드라이브에 자산으로 남기기
```
**발표에 들어갈 다섯 가지**
```plain text
① 무엇을 개선했나
② 누구에게 어떻게 쓰게 했나        ← 이번 회차의 핵심
③ 실제로 돌아가는 화면 (시연)
④ 관찰된 것과 숫자
⑤ 다음 개선 계획
```
**②와 ④가 이번 발표의 중심입니다.** 기능 설명이 아니라 "써보게 했더니 이런 일이 있었다"가 내용입니다.
**미리 준비해둘 것**
```plain text
□ 오늘 적은 현재 상태 숫자 (사용 횟수, 사용자 수)
□ 개선 전 화면 캡처
□ 만든 설명서
□ 관찰 기록 (워크시트 시트 5)
□ 만든 에이전트 파일 (.claude/agents 폴더)
```
> **오늘 만든 설명서가 12회차 인수인계 문서의 초안이 됩니다.** 따로 만들 필요 없이, 2주간 쓰면서 보완한 것이 그대로 회사 자산이 됩니다.
### 이번 2주가 12회차와 이어지는 방식
```plain text
2주간 하는 일              12회차에 쓰이는 곳
────────────────────────────────────────────
개선 작업              →   발표 ① 무엇을 개선했나
설명서 만들기          →   지식베이스 인수인계 문서
남에게 쓰게 하기       →   발표 ② 누구에게 어떻게
관찰 기록              →   발표 ④ 관찰된 것과 숫자
겪은 오류와 해결        →   지식베이스 노하우 시트
```
**따로 준비할 것이 거의 없습니다.** 2주간 제대로 하면 12회차 자료가 자동으로 쌓입니다.
