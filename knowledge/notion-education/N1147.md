# 실습 1. 복원 안내서와 백업 만들기

정리일: 2026-10-08 · 교육 에셋 N1147

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
프로젝트를 다른 컴퓨터에서 되살릴 수 있도록 복원 안내서(RESTORE.md)를 만들어 백업하고 개인 저장 공간으로 옮깁니다.
## 진행 단계
1. **Claude Code에 요청** — 창②에 아래 프롬프트를 입력합니다.
- 입력할 내용:
```javascript
프로젝트를 마무리하고 백업하려 합니다. 도와주세요.

1. RESTORE.md 파일을 만들어 주세요. 이 프로젝트를 처음 보는
   사람이 다른 컴퓨터에서 되살릴 수 있도록 다음을 담습니다.
   - 프로젝트 소개 한 문단과 주요 기능 목록
   - 필요한 준비물 (WSL, Claude Code, 파이썬 패키지 설치)
   - 새 API 키를 발급받아 .env를 만드는 방법
     (.env에 어떤 항목이 필요한지 이름만 적고, 값은 적지 마세요)
   - 문서(docs)와 대피소 데이터(data)를 다시 구해
     적재하는 방법
   - 서버 실행 명령과 처음 확인해 볼 페이지

2. 백업 압축 파일을 만들어 주세요.
   - 파일명: backup-disaster-bot.zip
   - 제외할 것: .env, chroma_db 폴더, docs 폴더, data 폴더
   - 만든 뒤 압축 파일 안의 목록을 보여 주세요.
```
1. **압축 파일 목록 확인** — RESTORE.md와 server.py가 들어 있고 .env가 들어 있지 않은지 봅니다.
2. **탐색기에서 찾기** — 윈도우 파일 탐색기 주소창에 \\wsl\$ 입력 → Ubuntu → home → 계정 폴더 → disaster-bot에서 backup-disaster-bot.zip을 찾습니다.
3. **검증** — 압축 파일을 바탕화면으로 복사한 뒤 열어서 RESTORE.md가 읽히는지 직접 확인합니다.
4. **개인 공간으로 이동** — 개인 이메일로 자신에게 보내기, 개인 클라우드, USB 중 편한 방법을 씁니다.
5. **이동 확인** — 옮긴 곳에서 파일이 열리는 것까지 확인해야 백업 완료입니다.
## 막히는 지점
- `\\wsl$` 가 안 열림: 원인 WSL 미실행. 해결 WSL 터미널을 하나 열어 둔 상태에서 다시 시도
- zip 명령이 없다는 오류: 원인 압축 도구 미설치. 해결 창②에 오류를 붙여넣으면 설치부터 진행
- 압축 파일이 너무 큼: 원인 제외 목록 미적용. 해결 "chroma_db와 docs가 제외되었는지 확인해 주세요"라고 요청
- 개인 메일 첨부 용량 초과: 개인 클라우드나 USB 사용
- 백업을 옮기는 곳은 반드시 개인 소유 공간이어야 합니다(교육용 계정 드라이브는 반납 대상이라 백업도 함께 잃음).
