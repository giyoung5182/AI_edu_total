## Claude 모델 선택 가이드
---
입력창 오른쪽에 모델 이름이 떠 있습니다. 그걸 누르면 목록이 나오고, 목록 아래에는 "노력"과 "사고"라는 낯선 설정이 또 있습니다.
**여기서 뭘 고르느냐가 오늘 실습의 성패를 가릅니다.** 결과물 품질 때문이 아니라 **한도** 때문입니다. 더 좋아 보이는 모델을 골랐다가 수업 중간에 막히면 그 자리에서 실습이 끝납니다. 되돌릴 방법이 없습니다.
그래서 이 부록은 "Sonnet 5를 고르세요"에서 끝내지 않고, **왜 그게 맞는 선택인지, 다른 걸 고르면 무슨 일이 생기는지**까지 정리합니다.
---
## 1. 먼저 잡을 개념 — 모델은 "성능 순위표"가 아니다
처음 보면 목록이 성능 순위처럼 보입니다. 위에 있는 게 좋고 아래가 나쁜 것 같습니다. **그렇지 않습니다.**
모델 선택은 **세 가지를 맞바꾸는 일**입니다.
```plain text
        능력          속도          한도 소모
        ────────────────────────────────────
Haiku    낮음    ←    빠름     ←    적음
Sonnet   중간         중간          중간
Opus     높음    →    느림     →    많음
Mythos   최상        가장 느림      가장 많음
```
큰 모델은 **더 똑똑한 대신 더 느리고 더 많이 먹습니다.** 작은 모델은 그 반대입니다.
> 💡 **비유로 설명하실 때**<br>편의점 갈 때 트럭을 몰고 가지 않습니다.<br>트럭이 승용차보다 성능이 좋지만, 편의점 가는 데는 승용차가 낫습니다.<br>기름도 덜 먹고 주차도 쉽습니다.
**오늘 우리가 갈 곳은 편의점입니다.** HTML 퀴즈 앱 하나를 만드는 일이고,<br>이건 중간 모델이 여유 있게 처리하는 수준의 작업입니다.
---

### ⚠️ 가장 흔한 실수 — "4.8이 최신이니까 Sonnet 4.8"
**Sonnet 4.8은 존재하지 않습니다. 4.8은 Opus에 붙은 숫자입니다.**
Sonnet 계열은 **5와 4.6 두 개뿐**입니다. 그런데 목록에서 Opus 4.8이 Sonnet 5보다 **위에** 있고 숫자도 커 보여서, "Sonnet 쓰라고 했으니 4.8" 하고 Opus를 켜는 일이 자주 생깁니다.
```plain text
❌  Sonnet 4.8   ← 이런 건 없습니다
✅  Sonnet 5     ← 목록 세 번째 줄, 체크 표시가 붙어 있는 것
```
> 📌 **안내할 때는 숫자 말고 위치로**<br>"Sonnet 5요"라고만 하면 위에서부터 훑다가 Opus를 누릅니다.<br>\*\*"위에서 세 번째, 파란 체크 붙어 있는 거요"\*\*라고 하세요.
### 📖 Fable 5는 뭔가요
목록 맨 위에 설명도 없이 놓여 있어서 제일 궁금해지는 이름입니다.
2026년 6월 9일에 공개된 모델로, Anthropic이 Opus보다 위에 두는 "Mythos 등급"의 첫 공개 모델입니다. Anthropic은 이 모델을 자사가 일반에 공개한 모델 중 가장 능력이 뛰어나다고 설명하며, 길고 복잡한 여러 단계 작업에서 격차가 가장 크게 벌어진다고 밝히고 있습니다.
**그래서 오늘 쓰면 안 됩니다. (어차피 PRO 버전은 따로 사용 불가능! 0722 기준)** <br>능력이 높다는 건 한도를 그만큼 빨리 쓴다는 뜻이고, 우리가 만들 퀴즈 앱은 그 능력이 전혀 필요 없는 작업입니다.
> 📖 **알아두면 좋은 것 — 같은 모델을 골라도 다른 모델이 답할 때가 있습니다**<br>Fable 5는 능력이 높은 만큼 오용 위험도 커서, 특정 주제의 질문은<br>**자동으로 다른 모델에게 넘겨 답하도록** 안전장치가 걸려 있습니다.<br>"분명 이 모델을 골랐는데 답이 좀 다른데?" 싶은 상황이 생길 수 있는 이유입니다.
AI 도구를 가르칠 때 "내가 고른 것과 실제로 답하는 것이 항상 같지는 않다"는 사례로 쓸 만합니다.

## 3. 📖 "노력" 설정
모델 목록 아래에 있습니다. 클릭하면 다섯 단계가 나옵니다.
```plain text
낮음
중간   기본값   ✓
높음
엑스트라
최대
```
**화면에 뜨는 설명**
> 더 높은 노력은 더 철저한 응답을 의미하지만, 시간이 더 오래 걸리고 **한도를 더 빨리 사용합니다.**
같은 모델이라도 **얼마나 공들여 답할지**를 조절하는 다이얼입니다. 모델을 바꾸지 않고도 소모량이 달라진다는 점이 중요합니다.
**오늘은 기본값 "중간" 그대로 둡니다.** 이유는 두 가지입니다.
첫째, **낮추면 오히려 더 쓸 수 있습니다.** 첫 결과물이 부실하면 고치는 횟수가 늘어납니다. 그런데 **수정 한 번이 처음 만들 때보다 비싼 경우가 많습니다.** 대화가 길어질수록 앞의 코드 전체를 매번 다시 읽어야 하기 때문입니다. 아끼려다 더 쓰는 구조입니다.
둘째, **설정을 바꾸라고 하면 그 자체가 시간입니다.** 여러 명이 동시에 하위 메뉴를 뒤지면 못 찾는 사람, 엉뚱한 걸 누르는 사람이 반드시 나옵니다.

## 4. 📖 "사고" 토글
노력 설정 옆에 별도 스위치가 있습니다.
> **사고** — 더 복잡한 작업에 대해 깊이 사고합니다
답을 바로 내놓지 않고 **먼저 생각을 정리한 다음** 답하게 하는 기능입니다. 사람이 어려운 문제를 풀 때 연습장에 먼저 끄적이는 것과 비슷합니다. 그만큼 시간과 한도를 더 씁니다.
**오늘은 기본값(켜짐) 그대로 둡니다.** 끄면 조금 아낄 수 있지만, 결과물 품질이 어떻게 달라지는지 실측하지 않았습니다. 확인되지 않은 것을 31명에게 시키지 않습니다.
> 📌 **확인 필요**<br>"사고"를 껐을 때 아티팩트 품질이 실제로 떨어지는지는 검증하지 못했습니다.<br>한도가 빠듯한 상황에서 쓸 수 있는 카드이긴 하나, 현재로서는 권장하지 않습니다.

## 5. 🎓 한도 — 이것 때문에 모델을 고르는 겁니다
### Pro 계정 기준
Anthropic 공식 안내에 따르면, Pro는 대화가 비교적 짧고 연산 부담이 적은 모델을 쓸 경우 **5시간마다 최소 45개 메시지**를 보낼 수 있고, 이 한도는 **5시간마다 리셋**됩니다. 실제 횟수는 메시지 길이, 첨부 파일, 대화 길이, 사용하는 모델에 따라 달라집니다.
**여기서 놓치면 안 되는 단서가 "짧은 대화 기준"입니다.**
```plain text
짧은 대화        "이거 뭐야?" → 세 줄 답변           → 소모 적음
아티팩트 작업     프롬프트 20줄 → 코드 400줄 생성      → 소모 큼
                수정 요청 → 코드 400줄 다시 읽고 다시 쓰기 → 더 큼
                수정 10번째 → 그동안 쌓인 것 전부 다시 읽기 → 훨씬 큼
```
아티팩트 작업은 짧은 대화가 아닙니다. 그리고 **뒤로 갈수록 한 번의 소모가 계속 커집니다.**
### 오늘 수업의 시간 구조
```plain text
09:00  첫 메시지 → 5시간 창 시작
12:00  수업 종료
14:00  리셋 (수업 끝나고 두 시간 뒤)
```
**3시간 수업이 한 창 안에 통째로 들어갑니다.** 중간에 채워지는 일이 없다는 뜻이고, 곧 처음부터 아껴 써야 한다는 뜻입니다.

### 한도가 끊겼을 때 — 강등 사다리
```plain text
1단계   Sonnet 5로 계속               (정상)
```

## 7. 자주 나오는 질문
**Q. 더 좋은 모델 쓰면 결과물이 더 좋지 않나요?**<br>오늘 만들 수준에서는 **차이가 잘 안 납니다.** HTML 퀴즈 앱은 Sonnet 5가 여유 있게 처리하는 작업입니다. 상위 모델의 강점은 길고 복잡한 여러 단계 작업에서 나오는데, 오늘 실습은 거기에 해당하지 않습니다. 차이는 안 나고 한도만 빨리 닳습니다.
**Q. 대화 중간에 모델을 바꿔도 되나요?**<br>바꿀 수 있습니다. 다만 **한도가 끊긴 뒤에 내려가는 용도**로만 쓰세요. 중간에 올렸다 내렸다 하면 결과물 스타일이 흔들려서 오히려 수정 횟수가 늘어납니다.
**Q. Sonnet 4.6으로 내리면 아낄 수 있나요?확인되지 않았습니다.** 한도 소모는 등급(Haiku \< Sonnet \< Opus \< Mythos)을 따라가는 것으로 알려져 있으나, 같은 Sonnet 안에서 버전을 내렸을 때 소모가 줄어드는지는 확인하지 못했습니다. 아낄 목적이라면 **Haiku 4.5**가 확실한 카드입니다.
**Q. 무료 계정에서도 되나요?**<br>모델 선택 폭과 한도가 다릅니다. 오늘은 기관에서 준비한 Pro 계정으로 진행하므로 해당 사항이 없습니다.
**Q. 한도가 끊기면 대화 내용이 날아가나요?**<br>아닙니다. 대화와 만든 결과물은 그대로 남습니다. 새 요청만 막힙니다. 시간이 지나면 다시 보낼 수 있습니다.

## STEP 2 — 생성 (10:20\~10:32)
### A파트. 아티팩트를 만드는 세 가지 경로
같은 아티팩트를 만드는 길이 하나가 아닙니다. 실습 중에 사이드바를 눌러보고 "이건 뭐예요?" 하는 질문이 나오니 미리 정리합니다.
### 경로 1 — 채팅창 (오늘 실습)
```plain text
새 대화 → 프롬프트 입력 → 오른쪽 패널에 결과물
```
가장 기본입니다. **오늘 실습은 전부 이 경로로 진행합니다.**
이 경로를 쓰는 이유는 기능이 더 좋아서가 아닙니다. 오늘 배우는 핵심이 "만든 다음 대화로 고쳐나간다"인데, 채팅창에서 시작하면 그 흐름이 화면에 그대로 보이기 때문입니다.
### 경로 2 — 사이드바 \[아티팩트\] 📖
```plain text
왼쪽 사이드바 [아티팩트] → 카테고리 선택 → 만들기
```
카테고리 7개가 나옵니다.
```plain text
앱 및 웹사이트    문서 및 템플릿    게임    생산성 도구
창작 프로젝트     퀴즈 또는 설문조사    처음부터 시작하기
```
**만들기·수정·게시 모두 채팅 경로와 똑같이 됩니다.** 실습에 필요한 기능은 전부 있습니다.
### 경로 3 — 게시된 아티팩트 커스터마이즈 📖
게시된 아티팩트 페이지 **오른쪽 위 \[사용자 지정\]** 버튼입니다. 누르면 이런 안내가 뜹니다.
```plain text
┌────────────────────────────────────────┐
│  ⤫  Artifact 커스터마이즈               │
│                                        │
│  이 아티팩트를 새로운 Claude 대화로       │
│  가져가서 자신만의 독특한 방식으로        │
│  발전시켜 보세요.                        │
│                                        │
│  Artifact를 커스터마이즈하려면           │
│  Claude.ai 계정이 필요합니다.            │
│                                        │
│      [ 취소 ]  [ 이 Artifact 커스터마이즈하기 ]│
└────────────────────────────────────────┘
```
누르면 "Remixed artifact"라는 새 대화가 열리고, 남이 만든 아티팩트가 **내 대화 안으로 들어온 상태**에서 시작합니다. 처음부터 만들 필요 없이 바로 고치기부터 할 수 있습니다.
> 💡 **이게 강사님들께 가장 실용적인 경로입니다**<br>오늘 만든 퀴즈 앱 링크를 동료 강사에게 보내면, 그분은 **\[사용자 지정\] 한 번으로 자기 과목용으로 바꿔** 쓸 수 있습니다. 프롬프트를 다시 쓸 필요도, 처음부터 만들 필요도 없습니다.
학교 안에서 수업 자료를 돌려쓰는 방식으로 그대로 쓸 수 있습니다.
> ⚠️ **단, 학생은 여전히 안 됩니다**<br>안내창에 "Claude.ai 계정이 필요합니다"라고 명시돼 있습니다.<br>Claude는 만 18세 이상만 가입할 수 있으므로 학생은 커스터마이즈를 할 수 없습니다.

## STEP 3 — 수정 (10:32\~10:47)
> **바이브코딩의 실력은 처음 만드는 데서 갈리지 않고 고치는 데서 갈립니다.**
### 왜 한 번에 하나씩인가 — 회귀 (2분)
```plain text
수정을 요청하면 Claude는 기존 코드를 다시 씁니다.

요청을 다섯 개 몰아서 넣으면:
  → 다섯 개를 동시에 만족시키려고 코드를 크게 건드립니다
  → 그 과정에서 원래 잘 돌던 게 깨집니다
  → 개발에서는 이걸 회귀(regression)라고 부릅니다

하나씩 고치면 건드리는 범위가 작아서 깨질 확률이 낮습니다.
```
### 수강생 실습 — 하나씩 (10분)


### 검증 체크포인트 3가지

> ⚠️ **점수 계산은 반드시 검산하세요.**<br>다 틀려서 0점, 다 맞혀서 만점이 나오는지 확인합니다.<br>**채점 오류는 겉보기에 멀쩡해서 수업 중에 발견됩니다.**
**② 내용 품질 — 이건 AI에게 맡길 수 없습니다**

> ⚠️ **앞에서 배운 할루시네이션이 여기서 나옵니다.**<br>동작은 눈으로 확인되지만 **문제 내용의 사실관계는 확인되지 않습니다.**<br>반드시 선생님이 읽어보셔야 합니다. 이게 \*\*"70%의 문제"에서 남는 30%\*\*입니다.
**③ 사용 환경**
```plain text

□ 버튼이 손가락으로 누를 만한 크기인가
```
