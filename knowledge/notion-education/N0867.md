# 1장 — 업무 자동화의 생태계
> Make.com 화면을 열기 전에 반드시 읽어야 합니다.<br>"도구를 쓰기 전에 왜 이 도구인가"를 알아야 제대로 쓸 수 있습니다.

## 업무 자동화란 무엇인가
```plain text
자동화의 정의:
사람이 매번 직접 해야 했던 규칙 기반의 반복 동작을 시스템이 대신 실행하도록 만드는 것
```
핵심은 두 가지입니다.
```plain text
① 규칙 기반:  "항상 같은 방식으로 처리되는 것"만 자동화 가능
              판단이 필요한 것은 여전히 사람이 해야 함

② 반복:       한 번만 하는 일은 자동화할 필요 없음
              반복될수록 자동화의 가치가 높아짐
```

## 업무 자동화 도구의 세 가지 종류
---
### 1. iPaaS — 오늘 배우는 것
```plain text
Integration Platform as a Service
"다양한 앱들을 노코드로 연결해주는 플랫폼"

코드 없이 드래그앤드롭으로 앱 사이를 연결

대표 도구:
  Make.com  ← 오늘 실습 (입문용, 직관적)
  n8n       ← 장기적으로 더 강력
  Zapier    ← 가장 많이 알려짐, 비용 높음
```
---
### 2. AI 자동화 — 가장 빠르게 성장 중
```plain text
AI가 판단까지 포함해서 작업을 처리
단순 규칙이 아닌 상황에 따라 유연하게 대응

우리가 1~4회차에서 한 것이 바로 AI 자동화
(Claude Pro를 사람이 직접 조작하는 방식)

다음 단계:
Claude를 n8n·Make.com과 연결하면
→ 사람이 조작하지 않아도 AI가 자동으로 처리
```
---
### 3. RPA — 참고로만 알아두기
```plain text
Robotic Process Automation
로봇이 사람처럼 화면을 보고 마우스·키보드로 작업

이지포스 같은 외부 시스템에 이론상 가능하지만
구축 비용이 매우 높고 (수백만~수천만 원)
화면 UI가 조금만 바뀌어도 자동화가 깨짐

→ 알아두되, 지금 당장 쓸 도구는 아님
```

## n8n — 장기적으로 더 중요한 도구
Make.com이 오늘의 실습 도구라면, n8n은 장기적으로 더 강력한 도구입니다.
---
### n8n이란
```plain text
오픈소스 워크플로우 자동화 플랫폼

오픈소스 = 소스코드가 공개되어 누구나 무료 사용·수정 가능

2가지 사용 방법:
① n8n Cloud: 웹에서 바로 사용 (월 $20~)
② Self-hosted: 내 서버·PC에 설치 (서버 비용만, 실행 무제한)
```

### n8n의 핵심 강점 4가지
**강점 1: Claude와의 연동성이 가장 좋다**
```plain text
n8n에는 Claude 전용 AI Agent 노드가 있습니다.

일반 자동화:
  규칙대로 데이터를 전달할 뿐, 판단 불가

n8n + Claude:
  데이터가 들어오면 → Claude가 내용 판단·분석 →
  판단 결과에 따라 다음 동작 결정

실제 예시:
  이메일 수신 → Claude가 "긴급 여부" 판단 →
  긴급이면 슬랙 즉시 알림 / 일반이면 구글 시트에 저장

→ 이것이 단순 자동화와 AI 자동화의 차이
```
**강점 2: 비용 구조가 유리하다**
```plain text
Make.com:  모듈 실행 횟수(Operations)마다 비용 발생
Zapier:    작업(Task) 횟수마다 비용 발생
n8n:       워크플로우 실행 횟수만 카운트

예시: 100개 데이터를 처리하는 워크플로우 (모듈 5개)
Make.com → 100 × 5 = 500 operations 소비
n8n      → 100번 실행 = 100 executions만 카운트

→ 복잡한 워크플로우일수록 n8n이 압도적으로 유리
   Self-hosted 시 서버 비용만 내면 무제한 실행
```
**강점 3: 데이터가 내 것이다**
```plain text
Make.com·Zapier:
  데이터가 해외 서버를 통과
  서비스 종료 시 설정·데이터 사라짐

n8n Self-hosted:
  내 서버에서 실행 → 데이터가 외부로 안 나감
  보안·개인정보 민감한 업무에 적합
```
**강점 4: Claude가 n8n 워크플로우를 직접 만들어준다**
```plain text
2025년 현재:
  Claude에게 "이런 자동화 워크플로우 만들어줘"라고 하면
  → n8n 워크플로우 JSON 파일을 직접 생성
  → 이걸 n8n에 붙여넣으면 바로 작동

Make.com은 이 방식이 불가능
n8n은 오픈소스라 Claude가 구조를 완전히 이해하고 생성 가능

→ 4회차에서 배운 "Claude에게 코드 요청" 방식이
  n8n에서도 동일하게 적용
```
---
### n8n vs Make.com  — 비교
**학습 전략:**
```plain text
오늘 → Make.com으로 자동화 개념과 흐름 먼저 익히기
이후 → n8n으로 Claude와 연결된 AI 자동화로 발전

일반적으로 Make → n8n으로 넘어가는 경우가 많음
두 툴은 개념이 비슷해서 Make를 먼저 익히면 n8n도 빠르게 배울 수 있음
```

## MCP — 알아두면 좋은 최신 개념
[원본 이미지 제외]
```plain text
Model Context Protocol (모델 컨텍스트 프로토콜)

Anthropic(Claude 만든 곳)이 2024년 11월 발표한 표준 프로토콜

개념:
  AI 모델과 외부 도구를 연결하는 표준 규격
  비유: USB-C 처럼 어떤 앱이든 같은 방식으로 AI와 연결

기존 방식의 문제:
  각 앱마다 다른 API를 직접 개발해야 함 → 복잡·번거로움

MCP의 해결:
  슬랙·Gmail·구글 캘린더 등이 MCP 표준에 맞춰 개발되면
  → AI가 이 도구들을 코드 없이 바로 사용 가능

Make.com·n8n과의 차이:
  Make.com/n8n: 앱과 앱 사이를 "시나리오"로 연결
  MCP:          AI가 직접 앱을 "도구"로 사용

→ 지금은 개념만 알아두고, 나중에 n8n + Claude 연동 시 다시 등장
```

## 주의해야 할 것 3가지
[원본 이미지 제외]
**주의 1: 자동화는 실수도 자동화한다**
```plain text
자동화 전: 실수 → 사람이 즉시 인지 → 수정
자동화 후: 잘못된 로직 → 수백 건에 자동 적용 → 대량 오류

대처:
```

```plain text

```

```plain text
Make.com 가격 인상 또는 서비스 변경 시를 대비해
핵심 업무를 외부 서비스에 100% 의존하지 않기
```

```plain text
비유: 업무 처리 규정서

  화면에서 시각적으로 만든 것
```

```plain text
모듈이 5개 있는 시나리오가 3번 실행되면
```

```plain text

시나리오에 모듈 5개 × 1회 실행 = 5 operations 소비

무료 플랜:  월 1,000 operations
```

## 즉시 실행 vs 예약 실행 — 가장 많이 헷갈리는 부분
```plain text
즉시 실행 (Instant Trigger):
  조건 발생 순간 바로 실행
  → 웹훅(Webhook)을 지원하는 앱만 가능
  → 슬랙·노션·Tally 등 일부 앱
  → 모듈에 "instant" 태그가 붙어있음

예약 실행 (Scheduled):
  Make.com이 주기적으로 확인 후 실행
  → 15분·1시간·매일 등 설정한 주기
  → 구글 폼·구글 시트 등 대부분의 앱
  → "15분 안에 처리된다" = 정상

오늘 실습 소재 (구글 폼):
  예약 실행 방식 → 최대 15분 후 이메일 발송
  실시간이 아닌 것이 정상
```

```plain text
웹훅이란:
```

## 라우터 + 필터 — 조건 분기의 핵심
**라우터 (Router):**
```plain text
시나리오를 여러 경로로 나누는 기능

[트리거] → [라우터] → [경로 A: 긴급 처리]
                   → [경로 B: 일반 처리]
                   → [경로 C: 보류]
```
**필터 (Filter):**
```plain text
각 경로에 통과 조건을 설정

경로 A 필터: "긴급도" = "긴급" 일 때만 통과
경로 B 필터: "긴급도" = "일반" 일 때만 통과

조건 연산자:
  AND: 모든 조건 충족 시 통과
  OR:  하나라도 충족 시 통과
```
**실제 활용 예:**
```plain text
구글 폼 → 라우터
         → [긴급] 경로: 슬랙 즉시 알림 + 이메일
         → [일반] 경로: 구글 시트 저장만
```

## 에러 핸들러 — 실무에서 반드시 설정해야 함
```plain text
자동화가 외부 서비스와 연동될 때
→ 서버 오류·인증 만료·네트워크 문제 등으로 실패 가능
→ 에러 핸들러 없으면 데이터 유실

가장 중요한 에러 핸들러: Break (브레이크)
  오류 발생 시 자동으로 재실행 시도
  재시도 횟수·간격 설정 가능
  → 중요한 API 호출 모듈에는 모두 Break 설정 권장

오류 확인:
  왼쪽 메뉴 [History] → 빨간색 항목 클릭
  → 어느 모듈에서 오류? 어떤 메시지?
  → 메시지 복사 → Claude에 "이 오류 해결법 알려줘"
```

```plain text
별도 Claude·ChatGPT API 키 없이
Make.com 오퍼레이션만으로 AI 기능 사용 가능
```

## Make.com 화면 구성
**왼쪽 사이드바:**
```plain text
🏠 Home:         대시보드
⚡ Scenarios:    내 시나리오 목록 ← 여기서 시작
🔗 Connections:  연결된 앱 계정 관리
📋 Templates:    미리 만들어진 시나리오 예시
📊 History:      실행 기록 (오류 확인 시 여기)
```
[원본 이미지 제외]

**시나리오 편집 캔버스:**
```plain text
⊕ 버튼:    새 모듈 추가
→ 화살표:  실행 방향 (왼쪽 → 오른쪽)
모듈 클릭: 오른쪽에 설정 패널 열림
```
**하단 컨트롤 바:**
```plain text
[Run once]:   테스트 실행 (한 번만)
[▶ Schedule]: 실행 주기 설정
[ON/OFF]:     시나리오 켜기/끄기
[Save]:       저장 ← 자주 눌러주세요
```

## 연결(Connection) 설정
```plain text
앱 모듈 추가 시 해당 앱 계정을 연결해야 함

과정:
[Add a connection] 클릭 → 앱 로그인 창 열림
→ 로그인 + 권한 허용
→ 연결 완료 (이후 재사용)

연결이 안 될 때:
① 팝업 차단 → 브라우저 팝업 허용 후 재시도
② 계정 선택을 건너뜀 → [Add] 다시 클릭
③ 권한을 [취소] → 다시 시도해서 [허용]
```
