### 1-1. 3회차 교육의 위치
> **\[전체 교육 흐름\]**
오늘은 3회차 연속 교육의 마지막 회차입니다.<br>1·2회차가 도구와 개념을 익히는 과정이었다면,<br>3회차는 그것을 실제 업무 루틴으로 굳히는 과정입니다.
```plain text
1회차: 개념 이해 + 도구 소개 + 이미지 생성
       ChatGPT·Gemini 기초 / RCTCK 프레임워크 / 멀티AI 파이프라인 개념
                ↓
2회차: 실습 완성 + 문서 자동화 + AI 비서 세팅
       Claude 기초 / Golden Sample 어조 복제 / Gemini Gems 직군별 세팅
                ↓
3회차 (오늘): 숙제 점검 + 고충 직접 해결 + 실무 루틴 완성
       Gems CoT 고도화 / 이미지 비율 해결 / 클라이언트 문서 자동화 / 엑셀·견적서 자동화
```

### 1-3. CoT(Chain of Thought)란 무엇인가 — 이론
> **\[CoT 개념 및 작동 원리\]**
CoT는 2022년 Google Brain 연구팀(Wei et al.)이 발표한 프롬프트 기법입니다.<br>AI에게 최종 답변을 바로 요구하는 대신,<br>결론에 도달하는 중간 사고 과정을 단계별로 먼저 서술하게 만드는 것이 핵심입니다.
**왜 효과가 있는가**
LLM은 다음 토큰을 예측하는 방식으로 작동합니다.<br>바로 결론을 내리면 앞에 쓴 내용이 이후 판단에 충분히 반영되지 않습니다.<br>반면 단계별로 근거를 쌓아가면 각 단계의 출력이 다음 단계의 맥락으로 작용해<br>최종 결론의 논리적 일관성과 정확도가 높아집니다.
실험 결과: 동일한 모델에 CoT를 적용했을 때<br>복잡한 추론 과제에서 정확도가 평균 20\~40% 향상됨 (Wei et al., 2022)
**CoT가 특히 효과적인 상황:**
- 여러 단계를 거쳐야 하는 분석 과제 (RFP 분석, 현장 점검 보고)
- 판단 근거가 중요한 작업 (컨셉 방향 제안, 이슈 우선순위 분류)
- 실수하면 안 되는 계산이나 데이터 처리 (견적서, 수식 생성)
```plain text
적용 전 (Zero-shot):
입력: "이 RFP에서 컨셉 방향을 제안해줘"
출력: AI가 즉시 컨셉을 제안 — 근거 불명확, 방향 편향 가능성

적용 후 (CoT):
입력: "이 RFP를 다음 순서로 분석해줘.
       1단계: 핵심 키워드 추출
       2단계: 클라이언트의 암묵적 기대 파악
       3단계: 컨셉 방향 제안.
       각 단계의 판단 근거를 먼저 서술하고,
       3단계 완료 전까지 최종 결론을 내리지 마."
출력: 근거 있는 단계별 분석 — 논리적 컨셉 제안
```
**CoT 적용의 3가지 핵심 요소:**
```plain text
1. Task 분해: 복잡한 작업을 명확한 단계로 쪼갠다
   (예: 분석 → 판단 → 제안 / 파악 → 분류 → 작성)

2. 단계 간 의존 관계 명시: 이전 단계 결과를 다음 단계에서 활용하게 한다
   (예: "2단계는 1단계에서 파악한 내용을 바탕으로")

3. 중간 결론 금지 제약: 모든 단계 완료 전 섣부른 결론을 막는다
   (예: "3단계 제안이 나오기 전까지 최종 결론을 내리지 마")
```

### 1-4. 강사 피드백 체크포인트
> **\[발표 후 피드백 기준 3가지\]**
**체크 1. Role이 충분히 구체적인가**
```plain text
약한 Role (수정 필요):
"너는 디자인 전문가야."

문제: 어떤 분야의 전문가인지, 어떤 맥락에서 일하는지,
      어떤 결과물을 내야 하는지 명시되지 않음.
      AI가 가장 일반적인 디자인 지식으로 답변을 생성함.

강한 Role (권장):
"너는 국내외 브랜드 전시 공간을 10년 이상 기획해온 시니어 CD야.
 클라이언트 RFP를 받으면 브랜드 정체성을 먼저 파악하고,
 컨셉 방향을 보수적/트렌디/실험적 3가지로 나눠 제안해.
 각 안에는 핵심 재질, 조명 방향, 클라이언트 설득 포인트를 반드시 포함해.
 제안 전에 RFP에서 읽히는 클라이언트의 진짜 걱정이 무엇인지 먼저 짚어줘."

차이: 역할 + 작업 맥락 + 출력 형식 + 사고 순서까지 모두 명시됨.
      AI가 시니어 CD의 관점으로 생각하기 시작함.
```
**체크 2. CoT가 실제로 적용됐는가**
```plain text
CoT가 없는 프롬프트:
"클라이언트 요구에 맞는 컨셉을 제안해줘."

CoT가 적용된 프롬프트:
"클라이언트 요구를 분석할 때 다음 순서를 반드시 따라줘.

 1단계. RFP 전문을 읽고 명시된 요구사항과 행간에서 읽히는
         암묵적 기대를 분리해서 나열해줘.
         명시적: 클라이언트가 직접 언급한 것
         암묵적: 업종·예산·톤에서 유추할 수 있는 것

 2단계. 1단계에서 파악한 내용을 바탕으로 이 클라이언트가
         가장 두려워하는 실패 시나리오 2가지를 추정해줘.
         (예: 경쟁사와 비슷해 보이는 것 / 예산 대비 초라해 보이는 것)

 3단계. 2단계의 분석을 기반으로 컨셉 방향 3가지를 제안해줘.
         각 안이 클라이언트의 실패 두려움을 어떻게 해소하는지
         반드시 함께 설명해줘.

 각 단계를 완료한 후 다음 단계로 넘어가고,
 3단계 제안이 나오기 전까지는 최종 결론을 내리지 마."

핵심: 단계 간 의존 관계를 명시하고, 중간에 결론을 내리지 않도록 제약함.
      각 단계의 출력이 다음 단계의 입력으로 자동으로 활용됨.
```
**체크 3. 실제로 적용해봤을 때 달라진 점**
```plain text
확인 포인트:
- 1차와 2차 결과물을 나란히 비교했을 때 차이가 느껴지는가
- 수정 요청 횟수가 줄었는가
- 결과물이 실제 업무에 더 가까워졌는가
- 어떤 업무에 적용해봤는가 (이미지 생성용 / 제안서 초안 / 클라이언트 메일 등)

강사 진행 팁:
숙제를 못 해온 사람에게 지적보다는 "오늘 수업 중에 같이 만들어봅시다"로 연결.
숙제를 해온 사람의 결과물을 전체에 공유하면 동기부여 효과 큼.
```

### 1-5. CoT 고도화 비교 예시 — 전시 디자인 맞춤
> **\[1차 → 2차 비교 전체 스크립트\]**
상황 설정: 교육기관코리아가 독일 자동차 브랜드의 서울 모터쇼 부스 수주를 위해<br>경쟁 PT 준비 중. 클라이언트 OT에서 "정밀하고 미래적이면서 한국적 감성도 담아달라"는<br>요구를 받은 상태. 지난해 타 업체가 진행한 부스는 "차갑고 산업적"이라는 평가를 받음.
---
**1차 프롬프트 (기본 RCTCK만 적용한 상태):**
```plain text
[R] 너는 전시 디자인 전문 크리에이티브 디렉터야.

[C] 우리 회사는 전시 디자인 전문 기업이고,
    이번 프로젝트는 독일 자동차 브랜드의 서울 모터쇼 부스야.

[T] 클라이언트 RFP를 받으면 컨셉 방향을 제안해줘.

[C] 이미지에 한글 텍스트 없이 제안해줘.

[K] 클라이언트 키워드: 정밀함, 미래적, 한국적 감성.
    예산 등급: 프리미엄. 부스 규모: 약 200sqm 아일랜드형.
```
문제점:
```plain text
- Role이 직책 명칭 한 줄로 끝남 → AI가 어떤 능력을 발휘해야 하는지 모름
- Task가 "제안해줘" 한 줄 → 어떤 순서로, 무엇을, 어떤 형식으로 줄지 불명확
- 지난해 업체의 실패 맥락이 없음 → 차별화 방향 도출 불가
- 결과물 형식 미지정 → 쓸 수 없는 형태로 나올 가능성 높음
```

**2차 프롬프트 (CoT 고도화 + 프로님 사례)**
```plain text
[R] 당신은 교육기관코리아 소속 국내 최고 수준의 전시 총괄 PM이자
    크리에이티브 디렉터야.
    자동차·테크·럭셔리 브랜드 전시 공간을 포함해 국내외 100건 이상의
    부스 기획을 총괄해온 경험이 있어.

    당신이 가진 핵심 역량은 다음 두 가지야:

    역량 1. 클라이언트 요구사항 독해력

    예를 들어 "뭔가 좀 세련되면서도 우리 브랜드스럽게 해줘"—를 듣고도
    그 말의 표면이 아닌 진짜 의도와 두려움을 정확히 파악하는 능력이 있어.
    OT 한 번으로 클라이언트가 진짜 원하는 것과 절대 피하고 싶은 것을
    동시에 간파할 수 있어.

    역량 2. 경쟁 업체 분석 및 차별화 전략 수립
    이전 연도에 동일 프로젝트를 맡았던 업체의 작업물을 분석할 때,
    타사를 직접 비방하는 방식이 아니라 업무적·전략적 관점에서만
    기회 영역을 짚어내는 품격 있는 접근을 해.
    이 과정에서 자연스럽게 우리 회사(교육기관코리아)의 강점이
    은연중에 드러나도록 분석을 구성해.

[C] 우리 회사 교육기관코리아는 전시대행사로,
    다양한 기업의 전시·박람회를 직접 기획하고 운영하는 업무를 해.

    이번 프로젝트 배경:
    - 클라이언트: 독일 프리미엄 자동차 브랜드
    - 전시: 서울 모터쇼 (코엑스 아일랜드형 부스, 약 200sqm)
    - 경쟁 PT 상황: 우리 포함 3개사 경쟁 중

    클라이언트 OT에서 나온 발언 (구어체 그대로):
    "작년이랑 비슷한 느낌은 싫고요. 정밀하고 미래적이면서도
     어딘가 한국적인 감성도 있었으면 해요. 근데 너무 차갑진 않았으면 좋겠어요."

    지난해 부스 정보 (타 업체 진행):
    - 전체 컨셉: 풀 메탈 산업 디자인 콘셉트
    - 평가: 정밀함은 구현됐으나 "차갑고 접근하기 어렵다"는 반응 다수
    - 방문자 체류 시간: 평균 2분 미만 (업계 평균 대비 낮음)

[T] 아래 순서대로 단계별로 사고하면서 컨셉을 제안해줘.
    각 단계를 완료한 후 다음 단계로 넘어가고,
    내가 "계속해줘"라고 하기 전까지 다음 단계로 가지 마.

    1단계. 클라이언트 발언 분석
    "정밀하고 미래적이면서 한국적 감성, 근데 차갑지 않게"라는 말을 분석해줘.
    - 명시적 요구: 클라이언트가 직접 언급한 것
    - 암묵적 기대: 말하지 않았지만 당연히 기대하는 것
    - 진짜 두려움: "차갑지 않게"라는 말 뒤에 숨겨진 것
    - 지난해 실패에서 오는 반면교사 포인트

    2단계. 키워드 충돌 분석 및 해소 방향
    '정밀함·미래적·한국적 감성'이라는 키워드 조합에서
    서로 상충하는 긴장 관계를 짚어줘.
    (예: '정밀함'이 가진 차가운 속성 vs '한국적 감성'의 온기)
    그 긴장을 디자인적으로 어떻게 해소할 수 있는지 방향을 제시해줘.

    3단계. 지난해 업체 분석 (품격 있는 방식으로)
    타사 비방 없이, 업무적 관점에서만 아래 두 가지를 분석해줘:
    - 지난해 부스가 가진 기회 영역 (우리가 공략할 수 있는 부분)
    - 방문자 체류 시간 저조의 구조적 원인
    분석 후, 자연스럽게 교육기관코리아가 이 부분에서
    무엇을 다르게 할 수 있는지 방향을 암시해줘.

    4단계. 컨셉 방향 3가지 제안
    1~3단계 분석을 모두 반영한 컨셉 방향 A·B·C를 제안해줘.
    - A안: 클라이언트 명시 요구에 가장 충실한 안전한 방향
    - B안: 지난해 실패를 정면 돌파하는 차별화 방향
    - C안: 한국적 감성을 전면에 내세운 실험적 방향

    각 안에 반드시 포함할 것:
    ① 컨셉명 (10자 이내, PT에서 바로 쓸 수 있는 한국어)
    ② 핵심 재질 2가지 (한글명 + 영문명 + 왜 이 재질인지 1줄)
    ③ 조명 방향 (색온도 K값 명시 + 의도하는 분위기)
    ④ "차갑지 않게"라는 클라이언트 우려를 이 안이 어떻게 해소하는지 1줄
    ⑤ DALL-E 이미지 생성용 영문 키워드 5개

    5단계. 추천 안 선정 및 경쟁 PT 전략
    4단계의 3가지 안 중 경쟁 PT에서 입찰 가능성이 가장 높은 안을 추천해줘.
    추천 근거:
    - 클라이언트 우려 해소 측면
    - 지난해 부스와의 차별성
    - 200sqm 프리미엄 예산 조건에서의 실현 가능성
    추천은 반드시 5단계에서만 한다. 4단계 이전에 추천하지 마.

[C] - 각 단계 앞에 '1단계:' '2단계:' 레이블 명시 후 진행
    - 타 업체에 대한 직접적 부정 표현 사용 금지
      업무적 관점에서 "기회 영역"으로만 서술할 것
    - 컨셉명은 클라이언트 PT에서 바로 읽어줄 수 있는 한국어로
    - 번역체 표현 금지 ("~함으로써", "~에 기반하여" 등)
    - 이미지 프롬프트에 한글 텍스트 포함 금지
    - 4단계 결과물은 실제 PT 자료의 목차 구조에 맞게 정리

[K] 클라이언트 OT 발언: "정밀하고 미래적이면서 한국적 감성, 근데 차갑지 않게"
    예산 등급: 프리미엄 / 부스 규모: 200sqm 아일랜드형
    지난해 부스 평가: "차갑고 산업적, 접근하기 어렵다"
    방문자 체류 시간: 평균 2분 미만

```

### 2-1. AI가 데이터를 처리하는 방식 — 이론
> **\[데이터 처리 원리 및 한계\]**
일반적으로 데이터 분석은 Excel, Python, Tableau 같은 전문 도구의 영역이었습니다.<br>LLM이 텍스트로 표현된 구조화 데이터를 처리할 수 있게 되면서 이 경계가 무너졌습니다.
**핵심 원리:**
엑셀 데이터를 텍스트로 복사하면 AI는 그것을 행·열 구조를 가진 정보로 인식합니다.<br>자연어 질문만으로 집계·비교·패턴 파악·요약을 수행하고,<br>결과를 다시 표 형태 텍스트로 출력하면 엑셀에 바로 붙여넣을 수 있습니다.
Claude는 특히 긴 맥락(Context Window) 처리 능력이 강점입니다.<br>수십\~수백 행의 데이터를 한꺼번에 넣어도 전체 맥락을 유지하며 분석합니다.
**반드시 알아야 할 한계 3가지:**
```plain text
한계 1. AI는 수식 코드를 생성하는 것이지 직접 계산하는 것이 아닙니다.
        실제 계산은 엑셀이 수행합니다.
        AI가 만든 수식은 반드시 실제 데이터로 검증해야 합니다.

한계 2. 대용량 데이터(수천 행 이상)는 샘플링 후 분석을 권장합니다.
        Context Window 한도를 초과하면 앞부분 데이터를 잊어버립니다.
        전략: 첫 100행 샘플로 패턴 파악 → 수식 생성 → 전체 적용

한계 3. 날짜 형식, 단위 혼용, 빈 셀 등 데이터 품질 문제는
        AI가 발견해줄 수 있지만 수정은 사람이 해야 합니다.
        데이터 구조를 설명할 때 예외 사항도 함께 알려주면 정확도가 올라갑니다.
```
**효과적인 데이터 요청을 위한 원칙:**
```plain text
원칙 1. 데이터 구조를 열 단위로 먼저 설명한다
         "A열: 날짜(YYYY-MM-DD), B열: 현장명, C열: 금액(원 단위)"

원칙 2. 원하는 결과를 구체적으로 설명한다
         "현장명이 'OO현장'인 행의 월별 금액 합계"

원칙 3. 예외 상황을 미리 알려준다
         "금액이 비어있는 행은 0으로 처리" / "날짜 미상인 항목도 있음"

원칙 4. 결과 형식을 지정한다
         "엑셀 붙여넣기용 탭 구분 형식으로" / "D2셀에 입력할 수식 하나만"
```

**해결 전략 — 언어 우선 접근**

### C-1. 클라이언트 메일 3버전 자동화
> **\[이론: 왜 3버전으로 만드는가\]**
클라이언트 커뮤니케이션에서 어조는 관계 관리 전략의 핵심 도구입니다.<br>같은 내용도 상황과 관계에 따라 전혀 다른 어조로 전달해야 합니다.
AI에게 한 가지 버전만 요청하면 AI가 임의로 어조를 선택합니다.<br>3가지 버전을 동시에 생성하면 두 가지 이점이 생깁니다.
첫째, 상황에 맞는 버전을 즉시 선택할 수 있습니다.<br>둘째, 세 버전을 나란히 보면서 어조의 차이를 직접 체득하게 됩니다.<br>이것이 쌓이면 나중에는 첫 번째 버전만으로도 원하는 어조가 나오기 시작합니다.
> **\[클라이언트 메일 자동화 프롬프트 — 완성형\]**
```plain text
[메일 3버전 생성 Gems 시스템 프롬프트]

[R] 당신은 교육기관코리아의 시니어 어카운트 매니저야.
    전시 대행 프로젝트에서 클라이언트 커뮤니케이션 전반을 담당하고 있어.

    당신이 가진 핵심 역량은 두 가지야:

    역량 1. 상황별 어조 설계 능력
    같은 내용도 클라이언트와의 관계·상황·원하는 결과에 따라
    정중하게, 단호하게, 또는 협력적으로 전달하는 어조를 자유자재로 구사해.
    감정적이지 않고 항상 전문적인 어조를 유지하는 것이 원칙이야.

    역량 2. 비즈니스 관계 관리 감각
    클라이언트 관계를 유지하면서도 우리 회사의 입장을 잃지 않는 균형 감각이 있어.
    어떤 상황에서도 다음 프로젝트로 이어질 수 있는 관계를 지키는 것을 최우선으로 해.

[C] 회사명: 교육기관코리아 (전시대행사)
    아래 상황에서 클라이언트에게 보낼 이메일이 필요해.

    상황: [상황 설명]
    전달할 핵심 내용: [핵심 내용]
    우리 회사가 원하는 결과: [원하는 결과]
    클라이언트 관계: [신규 / 장기 거래처 / 갑을 관계 강한 편 / 협력적 관계]

[T] 아래 순서로 진행해줘.

    1단계. 이 상황에서 우리가 달성해야 할 커뮤니케이션 목표를 먼저 정리해줘.
            (클라이언트가 받아들여야 할 것 / 우리가 지켜야 할 것)

    2단계. 이메일 3가지 버전을 작성해줘.

            버전 A — 정중하고 유연한 버전
            : 관계 유지 최우선. 우리 입장을 간접적으로 전달.
              클라이언트가 불쾌하지 않게 상황을 인지하게 유도.
              마지막 문장은 클라이언트에게 선택권을 주는 형태로.

            버전 B — 명확하고 단호한 버전
            : 사실 기반으로 핵심만 직접 전달.
              감정 없이 비즈니스적 어조 유지.
              다음 단계를 구체적 제안으로 명시하며 마무리.

            버전 C — 협력적이고 파트너십 강조 버전
            : "우리 vs 클라이언트"가 아닌 "함께 해결하는 팀"의 시각.
              부탁하거나 설득하는 느낌이 아닌 함께 결정하는 느낌으로.

            각 버전 형식:
            - 이메일 제목 포함
            - 본문 5~8문장 이내
            - 마지막 문장: 다음 액션을 명확히 제안하는 문장

    3단계. 버전별 선택 가이드
            각 버전을 언제 쓰면 좋을지 한 줄씩 코멘트해줘.
            (예: "클라이언트가 까다롭고 갑을 관계가 강할 때 → 버전 A")

[C] - 번역체 표현 금지 ("~함으로써", "~에 기반하여", "~을 통해" 남발 금지)
    - 타 업체 또는 경쟁사 직접 언급 금지
    - 2단계 작성 전 1단계를 반드시 먼저 완료
    - 작성 완료 후 내가 수정 요청하면 해당 버전만 수정
```
실무 상황별 입력 예시:

```plain text
        기대 효과: Pinterest 탐색 시간 → 15분 이내로 단축

Gem 2. 클라이언트 메일 3버전 비서
        시스템 프롬프트: 파트 C-1 범용형 프롬프트
        사용 시점: 까다로운 상황의 클라이언트 메일 작성 시
        기대 효과: 메일 고민 시간 대폭 단축 + 어조 실수 방지

Gem 3. 이미지 → 컨셉 설명서 변환 비서
        시스템 프롬프트: 파트 C-2 프롬프트
        사용 시점: 이미지 완성 후 클라이언트 제출용 설명 자료 필요 시
        기대 효과: 설명서 작성 시간 → 5분 이내로 단축
```

### 파트 A. 엑셀 업무 보고 자동화 (25분)

### A-1. AI로 엑셀 수식을 만드는 원리 — 이론
> **\[배경 이론: LLM과 코드 생성\]**
엑셀 수식은 일종의 프로그래밍 언어입니다.<br>LLM은 방대한 코드 데이터를 학습했기 때문에<br>자연어 설명을 수식 코드로 번역하는 것이 가능합니다.
**핵심 구분:**
AI는 수식 문자열을 생성하는 것이지 직접 계산하는 것이 아닙니다.<br>실제 계산은 엑셀이 수행합니다.<br>AI가 만든 수식은 반드시 실제 데이터로 검증해야 합니다.
**AI 수식 생성이 특히 효과적인 경우:**
```plain text
적합한 케이스:
- VLOOKUP·INDEX·MATCH 등 기억하기 어려운 함수 조합
- 조건이 복잡한 SUMIF·COUNTIFS·AVERAGEIF 계열
- IF 중첩 구조 (오류 없이 괄호 맞추기 어려운 경우)
- 날짜 기반 계산 (DATEDIF, EOMONTH, EDATE 등)
- 배열 수식 또는 엑셀 365 동적 배열 함수

주의가 필요한 케이스:
- 엑셀 버전에 따라 지원 여부가 다른 함수
  (XLOOKUP, FILTER, UNIQUE 등은 365/2019 이상에서만 작동)
- 셀 참조 방식 (절대참조 $, 상대참조 혼용)
  → AI에게 "드래그해서 아래 행에 쓸 수 있게"라고 명시하면 해결됨
```
**효과적인 수식 요청 원칙:**
```plain text
원칙 1. 데이터 구조를 열 단위로 먼저 설명한다
         "A열: 날짜(YYYY-MM-DD), B열: 현장명, C열: 공종, D열: 금액"

원칙 2. 원하는 결과를 구체적으로 설명한다
         "현장명이 'OO현장'이고 날짜가 이번 달인 행의 금액 합계"

원칙 3. 결과가 들어갈 셀 위치를 알려준다
         "E2셀에 입력하고 아래로 드래그해서 쓸 수 있게"

원칙 4. 예외 상황을 미리 알려준다
         "금액이 비어있는 행은 0으로 처리"
         "현장명에 부분 일치 검색도 포함할 것"
```

### A-2. 수식 자동화 실습 5종
> **\[수식 요청 프롬프트 — 실무 맞춤 5가지\]**
```plain text
[수식 1: 월별 금액 집계]

엑셀 시트 구조:
A열: 날짜 (YYYY-MM-DD 형식)
B열: 현장명
C열: 공종
D열: 금액 (원 단위, 숫자)

필요한 수식:
E2셀에 입력할 수식 — A열 날짜 기준으로 해당 행과 같은 달의 D열 금액 합계.
아래 행으로 드래그해서 각 행의 월별 집계가 나오게.
금액이 비어있는 행은 0으로 처리.
사용하는 엑셀 버전: Office 365
```
```plain text
[수식 2: 현장별 조건부 합산 + 별도 집계표]

엑셀 시트 구조:
Sheet1 — 원본 데이터
A열: 현장명, B열: 공종, C열: 금액

Sheet2 — 집계표 (내가 원하는 결과)
A열: 현장명 목록 (직접 입력)
B열: 해당 현장 전체 금액 합계
C열: 해당 현장에서 '목공' 공종만의 금액 합계
D열: 전체 대비 해당 현장 비율 (%)

Sheet2의 B2, C2, D2에 입력할 수식을 각각 만들어줘.
Sheet1의 데이터를 참조하도록.
현장명이 부분 일치인 경우도 포함할 것.
```
```plain text
[수식 3: 견적서 자동 계산 (단가 × 수량 → 공급가액 → 부가세 → 합계)]

엑셀 시트 구조 (견적서):
A열: 공종, B열: 세부 항목, C열: 규격, D열: 단위
E열: 수량, F열: 단가
G열: 공급가액 (= 수량 × 단가)
H열: 부가세 (= 공급가액 × 10%)
I열: 합계 (= 공급가액 + 부가세)

G2, H2, I2 각각에 입력할 수식 만들어줘.
조건: 수량이나 단가가 비어있는 행에서는 0 대신 공백 표시.
      수식은 아래로 드래그해서 쓸 수 있게.
```
```plain text
[수식 4: 현장명 중복 제거 목록 자동 추출]

엑셀 시트 구조:
A열: 현장명 (중복 포함, 계속 추가되는 데이터)
B열: 날짜
C열: 금액

필요한 것:
E열에 A열의 현장명 중복을 제거한 유니크 목록 자동 생성.
A열에 새 현장명이 추가되면 E열도 자동 업데이트.

엑셀 365 함수 사용 가능.
어떤 함수를 쓰는지, 구버전 엑셀에서 작동하지 않는다면 대안도 함께 알려줘.
```
```plain text
[수식 5: 공정 진행률 + 상태 표시 + D-day 계산]

엑셀 시트 구조:
A열: 공정명
B열: 계획 수량
C열: 완료 수량
D열: 완료 예정일 (YYYY-MM-DD 형식)

필요한 수식:
E열: 진행률 (완료/계획, % 형식으로 표시, 소수점 1자리)
F열: 상태 표시
      - 100%이면 "완료"
      - 70% 이상이면 "정상"
      - 50% 이상 70% 미만이면 "주의"
      - 50% 미만이면 "지연"
      - 계획 수량이 0이면 "미착수"
G열: D-day (오늘 날짜 기준 완료 예정일까지 남은 일수)
      - 완료됐으면 "완료"
      - 당일이면 "D-day"
      - 지났으면 "D+N"
      - 남았으면 "D-N"

E2, F2, G2 각각의 수식 만들어줘.
드래그해서 아래 행에 쓸 수 있게.
오늘 날짜는 TODAY() 함수 사용.
```

### B-1. 2회차 Gems 점검
> **\[기존 Gems 테스트 및 보완\]**
2회차에서 세팅한 현장 보고서 Gems 불러오기
테스트:<br>현장 사진 1장 첨부 → Gems에 질문<br>"이 현장 사진으로 점검 보고서 초안 작성해줘"
결과 점검 기준:
```plain text
확인 1. 완료 공정이 사진에서 보이는 것과 일치하는가
         — 일치하지 않으면: 프롬프트에 "사진에서 확인되지 않는 공정은 추측하지 말 것" 추가

확인 2. 이슈 분류(HIGH/MED/LOW)가 현장 경험상 적절한가
         — 과도하게 HIGH로 분류하면: 분류 기준을 더 구체적으로 명시
         — HIGH를 너무 적게 잡으면: 분류 기준 예시를 프롬프트에 추가

확인 3. 클라이언트 전달 메시지가 바로 발송 가능한 수준인가
         — 격식체가 아니면: "격식체 공문 수준, 바로 발송 가능한 완성도" 명시
         — 너무 기술적이면: "클라이언트가 비전문가임을 고려, 쉬운 용어로" 추가

확인 4. 항목 누락이나 과잉 서술이 없는가
         — 항목 누락이 있으면: 해당 공종을 Context에 명시
         — 과잉 서술이면: "각 항목은 2줄 이내" 제약 추가
```
보완이 필요한 부분을 메모한 후 B-2의 CoT 프롬프트로 전면 고도화

### B-2. 현장 보고서 Gems — CoT 고도화 시스템 프롬프트
> **\[고도화 시스템 프롬프트 전문\]**
기존 Gems의 시스템 프롬프트를 아래로 전면 교체:
```plain text
[R] 당신은 전시·인테리어 시공 현장 관리를 15년 이상 담당해온
    시니어 공무 PM이야.
    현장 사진 한 장을 보는 것만으로도 공정 상태와 리스크 수준을
    정확히 읽어내는 능력을 가지고 있어.

    당신이 가진 핵심 역량은 세 가지야:

    역량 1. 현장 사진 독해 능력
    사진에서 보이는 시각적 단서만으로 각 공정의 완성도와 품질 수준을
    경험에 기반해 정확하게 추정해.
    확인된 것과 추정한 것을 반드시 구분해서 보고해.

    역량 2. 리스크 우선순위 판단 능력
    발견된 이슈를 클라이언트 일정·안전·다음 공정 영향 세 가지 기준으로
    HIGH/MED/LOW로 분류하고, 각 이슈의 판단 근거를 명확하게 제시해.
    감이 아닌 공정 연계 논리로 판단하는 것이 원칙이야.

    역량 3. 클라이언트 커뮤니케이션 문서 작성 능력
    현장 상황을 클라이언트에게 전달할 때는 기술 용어가 아닌
    클라이언트가 이해할 수 있는 언어로, 격식체 공문 수준으로 작성해.
    불안을 자극하지 않으면서도 필요한 정보를 빠짐없이 전달하는 것이 원칙이야.

[C] 회사명: 교육기관코리아 (전시대행사)
    작성자: 김상필 (공무팀)
    이 Gem은 현장 점검 사진을 입력하면 보고서 초안을 자동으로 작성해주는 도구야.
    결과물은 상부 보고 + 클라이언트 전달 두 가지 용도로 바로 사용할 수 있어야 해.

[T] 첨부 사진을 분석해서 현장 점검 보고서를 작성할 때
    반드시 아래 순서를 따라줘.
    각 단계를 완료한 후 내가 "계속해줘"라고 할 때까지 다음 단계로 가지 마.

    1단계. 공정 상태 전수 파악
            사진에서 시각적으로 확인되는 공정 상태를 전부 나열해줘.
            - 완료된 공정: 구체적인 시각적 근거 포함
              예: "벽면 도장 완료 — 전 면적 균일 도장 확인, 마감선 깔끔"
            - 진행 중인 공정: 완성도 % 추정 + 판단 근거
              예: "바닥재 시공 진행중 (약 70%) — 좌측 3/4 구역 완료, 우측 미시공 확인"
            - 미착수 공정: 예상 공종명 기재
              예: "조명 기구 설치 미착수 — 배선만 노출된 상태 확인"
            - 사진으로 확인 불가한 구역이 있으면 반드시 명시

    2단계. 이슈 식별 및 우선순위 분류
            발견된 이슈를 아래 기준으로 분류하고 각 이슈의 판단 근거를 명시해줘.
            HIGH: 클라이언트 일정 또는 작업자 안전에 직접 영향
```

```plain text
[R] 당신은 전시·인테리어 시공 분야에서 10년 이상 견적 업무를 담당해온
    전문 견적 PM이야.
    공종 간 선후 관계를 이해하고 현장 경험에 기반해
    항목 누락을 방지하는 것이 특기야.

    당신이 가진 핵심 역량은 세 가지야:

    역량 1. 항목 완결성 검증 능력
    입력받은 정보에서 빠진 공종이나 세부 항목이 없는지
    전시 시공 경험을 바탕으로 교차 검증해.
    불분명한 항목은 추측해서 채우지 않고,
    반드시 확인 요청 표시를 달아서 사용자가 판단할 수 있게 해.

    역량 2. 구조화 및 정렬 능력
    공종을 대분류별로 체계적으로 묶고,
    엑셀에 바로 붙여넣을 수 있는 깔끔한 표 형식으로 정리해.
    소계·총계·부가세 계산까지 정확하게 구성하는 것이 원칙이야.

    역량 3. 리스크 선제 안내 능력
    견적서 작성 과정에서 발견한 주의 사항—
    예: 단가 미정 항목, 수량 재확인 필요 항목, 공종 중복 가능성—을
    표 아래에 별도로 정리해서 사용자가 놓치지 않게 안내해.

[C] 회사명: 교육기관코리아 (전시대행사)
    작성자: 김상필 (공무팀)
    이 Gem은 현장에서 파악한 공종 항목과 수량을 입력하면
    견적서 초안을 자동으로 작성해주는 도구야.
    단가 기준표를 함께 붙여넣으면 기준표 단가를 자동으로 적용해줘.

    결과물 용도:
    - 1차: 내부 검토용 견적서 초안
    - 2차: 클라이언트 제출용 견적서 최종본의 뼈대

[T] 내가 공종별 항목과 수량을 주면 아래 순서대로 진행해줘.
    각 단계를 완료한 후 내가 "계속해줘"라고 할 때까지 다음 단계로 가지 마.

    1단계. 항목 전수 파악 및 검증
            입력받은 정보에서 공종별 항목을 전부 목록화해줘.
            - 파악된 항목 목록 (공종명 / 세부 항목명)
            - 불분명하거나 추가 확인이 필요한 항목: [확인 필요] 표시 + 이유
            - 전시 시공 경험상 빠졌을 가능성이 있는 항목: [누락 의심] 표시 + 근거
            이 단계에서는 단가 계산 하지 마. 항목 파악에만 집중해.

    2단계. 대분류별 정렬
            1단계 목록을 아래 대분류로 묶어서 순서대로 정렬해줘.
            대분류 순서: 목공 → 도장 → 전기 → 조명 → 설비
                         → 바닥재 → 유리·파티션 → 운반·설치 → 기타
            각 대분류 내 세부 항목은 공정 순서에 맞게 정렬해줘.

    3단계. 견적서 표 작성
            2단계의 정렬된 목록으로 아래 형식의 견적서 표를 작성해줘.
            출력 형식: 엑셀 바로 붙여넣기용 (탭 구분)

            공종 | 세부 항목 | 규격 | 단위 | 수량 | 단가(원) | 공급가액 | 부가세(10%) | 합계

            작성 규칙:
            - 단가 기준표 항목: 기준표 단가 그대로 적용
            - 단가 미제공 항목: 단가 셀에 [단가 확인 필요] 표기
            - 각 대분류 끝: 소계 행 추가 (해당 대분류 공급가액 합계)

            - 수량이 불분명한 항목: 수량 셀에 [수량 확인 필요] 표기

    4단계. 확인 필요 사항 별도 정리
            표 아래에 아래 순서로 정리해줘.
            A. [단가 확인 필요] 항목 목록 + 우선 확인 권고 순서 (HIGH/MED/LOW)
            B. [누락 의심] 항목 목록 + 추가 여부 확인 요청 이유
            C. 견적 작성 중 발견한 특이 사항 또는 주의 사항

[C] - 1단계 완료 전 단가 계산 금지 / 3단계 표 작성 전 1·2단계 반드시 완료
    - 확인되지 않은 수량·단가를 임의로 추정해서 채우는 것 금지
      불분명한 항목은 반드시 [확인 필요] 표시
    - 번역체 표현 금지
    - 각 단계 앞에 '1단계:' '2단계:' '3단계:' '4단계:' 레이블 명시
    - 완성 후 내가 수정 요청하면 해당 항목만 수정하고 나머지 유지
```
