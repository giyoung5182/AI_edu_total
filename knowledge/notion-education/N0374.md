# 6. 실습 — 나만의 Gem 처음부터 직접 만들기

정리일: 2026-10-08 · 교육 에셋 N0374

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
완성된 지시문을 복붙하지 않고, 내 업무를 분석해 ROPE+K를 직접 채워 Gem을 만들고 실제로 돌려 봅니다. (25분)
## 진행 단계
1. **STEP 1 내 업무 발굴 (5분)** — 가장 자주 반복하는 문서 업무 고르기, 현재 비효율 적기, Gem을 쓸 상황과 이름 정하기.
2. **STEP 2 ROPE+K 워크시트 (10분)** — 칸마다 가이드라인과 작성 전 체크를 보며 채웁니다.
- R: 기관·부서, 경력, 어조, "확인 안 된 내용은 작성 안 한다" 원칙
- O: "내가 ***를 주면 Gem이 ***를 출력" 구조, 버전 수
- P: "결과물은 항상 이 순서로" + 번호 목록, 형식과 분량
- E: 좋은 출력 예시 1건(없어도 작동)
- K: 기관 기본 정보, Golden Sample, 절대 금지 사항
3. **STEP 3 지시문 합치기 (3분)** — R·O·P·E·K를 하나의 틀에 붙이고 자가 점검 체크리스트를 확인합니다.
4. **STEP 4 Gem 등록 (3분)** — gemini.google.com → 왼쪽 사이드바 Gem 탐색 → 새 Gem 만들기 → 이름·지시문 입력 → 저장 → 내 Gem 목록에서 확인.
5. **STEP 5 첫 테스트 (4분)** — 실제 업무 내용을 입력해 돌려 봅니다.
- 정상 결과: P에서 정한 순서·형식·분량이 지켜짐 / 입력하지 않은 수치·날짜를 만들지 않음 / \[미기재\] 항목이 표시됨 / Golden Sample과 문체가 비슷함
6. **6-3 결과 공유 & 피드백 (7분)** — 자원자 2\~3명이 화면을 공유하며 어떤 업무를 만들었는지, 가장 어려웠던 칸, 기대와 다른 점, 개선점을 발표합니다.
## 막히는 지점
- 결과가 너무 길다 → P에 분량 제한 추가
- 문체가 어색하다 → K의 Golden Sample을 더 구체적인 문서로 교체
- 빠진 항목이 생긴다 → P의 출력 항목에 추가
- AI가 임의로 수치를 만든다 → C와 K의 금지 사항에 "확인되지 않은 수치는 작성 금지" 추가
