# 1. 11회차는 무엇을 하는 시간인가
---
## 지금까지와 다른 점
```plain text
1~10회차   도구를 배우는 시간
             데이터 자동화 → GAS → Make → 앱 만들기 → 배포
             → 이미지·콘텐츠 → AI 에이전트

11~12회차  배운 것으로 실제 문제를 푸는 시간
             팀이 하나의 업무를 골라, 진단하고, 해결책을 만들어 발표
```
지금까지는 **강사가 정한 주제로 도구를 익혔습니다.** 11회차부터는 **여러분이 고른 실제 업무**를 다룹니다. 어떤 도구를 쓸지도 정해져 있지 않습니다. 업무의 성격을 보고 팀이 판단합니다.
---
## 11회차의 성격 — 강의가 아니라 함께 설계하는 시간
**11회차는 앉아서 듣는 시간이 아닙니다.** 여러분이 가져온 업무와 자료를 **실제로 펼쳐놓고, 강사와 함께 해결책을 설계하는 시간**입니다.
```plain text
그날 함께 하는 일

  · 이 업무의 어느 단계가 진짜 문제인지 같이 짚어보고
  · 그 단계를 어떤 도구로 바꿀 수 있는지 같이 따져보고
  · 실제 자료를 놓고 "이렇게 만들면 되겠다"까지 같이 그려봅니다
```
지금까지 강사가 여러분의 업무를 보며 해온 작업을, **이번에는 여러분의 업무를 놓고 같이 하는 것**입니다. 그래서 **가져오는 재료가 그날의 결과를 좌우합니다.** 현황과 자료가 준비되어 있으면 그날 설계까지 끝나고, 없으면 현황 파악만 하다 끝납니다.
---
## AX가 무엇인가 (11회차에 자세히 다룹니다)
```plain text
AX = AI Transformation, 즉 AI를 통한 업무 전환

"AI 도구를 쓴다"와 "AX를 한다"는 다릅니다.

  AI 도구를 쓴다   기존 방식은 그대로 두고, 중간에 AI를 하나 끼워 넣는 것
  AX를 한다        업무의 흐름 자체를 다시 짜는 것
                   → 없어도 되는 단계는 없애고
                   → 사람이 꼭 해야 하는 일만 남기고
                   → 나머지를 AI와 자동화에 맡기는 것
```
11회차에는 **"어떻게 비효율을 찾아내고, 어떻게 다시 설계하는가"** 를 다룹니다.
---
## 11회차 진행 순서
```plain text
1부   AX 사고란 무엇인가
        · 비효율을 진단하는 관점
        · 사람이 할 일과 맡길 일을 나누는 기준
        · 어떤 도구를 언제 쓰는가 (자동화 / 앱 / 에이전트)

2부   우리 팀 업무 진단
        · 가져온 워크시트를 놓고 팀별 진단
        · 어느 단계가 진짜 병목인지 함께 확인

3부   해결책 함께 설계하기          ← 이 시간이 핵심입니다
        · 실제 가져온 자료를 펼쳐놓고
        · 어느 단계를 어떤 도구로 바꿀지 강사와 함께 결정
        · 만들 것의 모양을 구체적으로 그려보기

4부   계획서 작성 + 착수
        · 설계한 내용을 계획서로 정리
        · 역할 나누기 · 다음 2주 계획 세우기
```
**11회차 이후 약 2주간 팀별로 실제 결과물을 만들고, 12회차에 발표합니다.**
---
# 2. 왜 과제가 필요한가
---
11회차 2·3부는 **여러분이 가져온 자료를 놓고 시작합니다.** 그 자료가 없으면 그날 처음부터 "그 업무가 어떻게 돌아가는지" 파악해야 하고, 정작 중요한 **설계에 쓸 시간이 사라집니다.**
```plain text
현황 + 자료를 가져온 팀    11회차에 진단 → 설계 → 계획서까지
현황만 가져온 팀           설계는 하되 구체적인 모양을 잡기 어려움
아무것도 없는 팀           그날 내내 현황 파악만 하다 끝남
                          → 2주 프로젝트 기간이 그만큼 줄어듦
```
**어려운 과제가 아닙니다.** 새로 조사하라는 것이 아니라, 9회차에 이미 찾아온 후보 중 하나를 골라 **조금 더 자세히 물어보고, 쓰고 있는 자료를 받아오는 것**입니다.
---
# 3. 과제 — 네 가지
---
## 과제 1. 프로젝트 주제 확정하기
9회차 워크시트에 적은 프로젝트 후보 중 **하나를 골라 확정**합니다.
```plain text
고르는 기준
  · 자주 반복되는 업무인가          (한 번뿐인 일은 개선 효과가 작습니다)
  · 데이터가 어디 있는지 명확한가    (파악이 안 되면 만들 수가 없습니다)
  · 2주 안에 뭐라도 만들어볼 수 있는 크기인가
```
**후보가 없거나 마음에 들지 않으면 새로 골라도 됩니다.** 다만 그 경우 해당 부서에 한 번 더 물어보셔야 합니다.
---
## 과제 2. 그 업무가 지금 어떻게 돌아가는지 파악하기
고른 업무의 담당자에게 아래를 물어봅니다.
```plain text
① 이 일을 어떤 순서로 하시나요? (단계별로)
② 각 단계는 누가, 어떤 도구로, 얼마나 걸려서 하나요?
③ 그 기록은 어디에 남나요? (엑셀 / 종이 / 메신저 / 사내 시스템)
④ 이 중에서 가장 손이 많이 가는 단계는 어디인가요?
⑤ 규정상 반드시 지금 방식대로 해야 하는 부분이 있나요?
```
**한 번에 다 알아내지 않아도 됩니다.** 아는 만큼만 적고, 모르는 칸은 비워두면 11회차에 함께 채웁니다.
> 9회차 인터뷰가 "무엇이 불편한가"를 묻는 것이었다면, 이번은 **"그 일이 실제로 어떻게 흘러가는가"** 를 묻는 것입니다. 개선안을 만들려면 흐름을 알아야 합니다.
---
## 과제 3. 실제 자료 받아오기 ★
**이번 과제에서 새로 추가된 부분입니다.** 인터뷰를 하면서, **그 업무에 실제로 쓰이는 자료를 함께 받아오세요.**
### 왜 받아와야 하나
```plain text
설명만 들으면    "매장별로 확인서를 받아 정리한다" → 막연함
실물을 보면      양식에 어떤 칸이 있고, 매장이 몇 개고,
                 제출 현황을 어떻게 적고 있는지가 한눈에 보임
                 → 무엇을 만들어야 하는지가 구체적으로 잡힘
```
11회차 3부에서 **실제 자료를 펼쳐놓고 설계합니다.** 자료가 있으면 "이 엑셀을 이렇게 바꾸면 되겠네"까지 그날 나오고, 없으면 말로만 그리다 끝납니다.
### 어떤 자료를 받아오면 되나
```plain text
· 지금 쓰고 있는 양식·서식        (한글, 엑셀, PDF)
· 목록성 자료                     (매장 목록, 품목 목록, 담당자 목록)
· 실제 기록 몇 건                 (전체가 아니라 3~10건 샘플이면 충분)
· 종이로만 있는 자료              (사진 몇 장으로 대체)
```
**전체 데이터를 다 받아올 필요 없습니다.** 양식 하나와 샘플 몇 건이면 설계에는 충분합니다.
### 개인정보 주의 — 반드시 지켜주세요
```plain text
· 주민번호·연락처·계좌번호·급여액은 지우거나 가린 뒤 가져오세요
· 사람 이름은 'A매장', '직원1'처럼 바꿔도 됩니다
· 판단이 애매하면 가져오지 말고 양식만 가져오세요
  → 양식(빈 서식)만으로도 설계는 충분히 가능합니다
· 자료를 받기 전에 담당자에게 사용 목적(사내 교육)을 알리고 동의를 받으세요
```
### 못 받아와도 괜찮습니다
자료를 못 받았다고 과제 미완성이 아닙니다. **"무엇을 받으려 했고 왜 못 받았는지"** 를 워크시트에 적어 오면 11회차에 함께 방법을 찾습니다. 자료가 없으면 비슷한 형태의 예시 자료를 만들어 설계를 진행합니다.

## 시트 3 — 비효율 진단
시트 2에 적은 단계를 놓고 **네 가지 관점**으로 봅니다.
```plain text
① 병목      가장 오래 걸리는 단계는 몇 번인가
② 반복      같은 일을 되풀이하는 지점은 어디인가
③ 실수·누락  빠지거나 틀리기 쉬운 지점은 어디인가
④ 구분      사람이 꼭 해야 하는 일 vs 아니어도 되는 일
```
**④번이 가장 중요합니다.** AI로 바꿀 수 있는 것은 대부분 "사람이 꼭 하지 않아도 되는 일"이기 때문입니다.
```plain text
위 예시로 나눠보면

  꼭 사람이 해야 함    매장과의 소통, 최종 확인, 원본 보관
  아니어도 됨          누가 안 냈는지 집계, 안내문 작성·발송, 누락 알림
```
**구분이 애매하면 "판단이 필요한가?"를 기준으로 나눠보세요.** 판단이 필요하면 사람, 정해진 규칙대로 처리하면 되는 일이면 자동화 후보입니다.

## 시트 4 — 데이터·제약
**이 시트가 도구 선택을 좌우합니다.**
```plain text
데이터가 구글시트에 있다      → 자동화(GAS·Make)로 바로 연결 가능
데이터가 개인 엑셀에 있다      → 공유 위치로 옮기는 것부터
데이터가 종이에만 있다        → 입력받는 화면(앱)부터 필요
데이터가 사내 시스템에 있다    → 내려받기가 되는지가 관건
```
**"바꿀 수 없는 것"을 적는 칸을 꼭 채워주세요.** 법적 보관 의무나 결재 규정처럼 손댈 수 없는 부분이 있으면, 그것을 피해서 설계해야 합니다. 이걸 모르고 만들면 다 만든 뒤에 못 쓰게 됩니다.

# 5. 자주 나오는 질문
---
**Q. 우리 팀이 그 업무를 잘 모르는데 괜찮나요?**
괜찮습니다. **오히려 그게 정상입니다.** 남의 부서 업무를 처음부터 잘 아는 경우는 없습니다. 모르니까 물어보는 것이고, 물어보는 과정 자체가 컨설팅의 첫 단계입니다. 모르는 칸은 비워두고 오세요.
**Q. 회사 자료를 받아와도 되나요?**
사내 교육 목적이므로 문제되지 않지만, **개인정보가 든 자료는 반드시 가리거나 지운 뒤** 가져오세요. 판단이 애매하면 실제 데이터 대신 **빈 양식만** 가져오시면 됩니다. 양식만으로도 설계는 충분히 가능합니다. 자료를 받기 전 담당자에게 용도를 알리고 동의를 받는 것도 잊지 마세요.
**Q. 자료를 못 받으면 어떻게 하나요?**
**못 받은 이유를 적어오시면 됩니다.** 그것도 진단의 일부입니다. "시스템에서 다운로드가 안 된다"는 사실 자체가 해결책 설계에 중요한 정보입니다. 자료가 없으면 11회차에 비슷한 형태의 예시 자료를 만들어 설계를 진행합니다.
**Q. 어디까지 만들어야 하나요?**
11회차에 정합니다. 지금은 **현황 파악과 자료 확보까지가 과제**입니다. 2주 안에 만들 수 있는 범위로 함께 조정할 예정이니, 지금 크기를 걱정하지 마세요.
**Q. 담당자가 바쁘다고 하면요?**
15분이면 충분합니다. 위 다섯 질문만 물어보고, 쓰고 있는 양식 파일 하나만 받아오세요. 어렵다면 팀에서 아는 만큼 적고 11회차에 알려주세요. 강사가 함께 방법을 찾겠습니다.
**Q. 우리 부서 업무를 하면 안 되나요?**
권장하지 않습니다. 이미 자기 업무는 각자 앱으로 다뤄봤습니다. **다른 부서 업무를 다루는 이유는 "내가 잘 모르는 일을 진단하는 법"을 익히기 위해서**입니다. 그것이 실제 컨설팅에 가까운 경험입니다.
**Q. 도구는 뭘 써야 하나요?**
11회차 3부에서 함께 정합니다. 지금까지 배운 것(GAS·Make·Lovable 앱·Claude Code 에이전트·이미지 도구) 중 무엇을 쓸지는 **업무의 성격과 데이터 위치**를 보고 결정합니다. 먼저 도구를 정하고 업무를 끼워 맞추면 실패합니다.
