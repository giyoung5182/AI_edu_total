# 한 번에 완성되지 않습니다
방금 만든 Gem은 초안입니다. 실제 쓰다 보면 반드시 어깑납니다. **그게 정상입니다.**
중요한 건 고치는 방법입니다. 막연히 "더 잘 해줘"라고 하면 안 바뀝니다. **증상별로 고쳐야 할 칸이 정해져 있습니다.**

# 테스트 1 · 정보를 일부만 주기
정보를 일부러 빼고 요청해봅니다.
```plain text
거래처에 서류 더 보내달라고 메일 써줘
```

**무엇을 보나** — 어느 거래처인지, 무슨 서류인지, 기한이 언제인지 알려준 적이 없습니다.
**바람직한 반응** — "어느 업체이고 어떤 서류인가요?"라고 되묻거나, 초안을 쓰되 빈칸을 `[ ]`로 남깁니다.
**문제 있는 반응** — 그럴듯한 업체명과 기한을 지어냅니다.

지어냈다면 설정문의 원칙 칸에 이 줄을 넣으세요.
```plain text
받는 사람, 안내 내용, 기한 중 하나라도 알 수 없으면
추측해서 채우지 말고 반드시 먼저 질문합니다.
```

# 테스트 2 · 상황 바꿔보기
같은 Gem에 다른 상황을 줘봅니다. **범용성을 확인하는 단계**입니다.
```plain text
이번엔 사내 타 부서 담당자에게 보내는 자료 요청 메일로 써줘.
```





결과

판단




상황에 맞게 톤이 조정된다

잘 만들어졌습니다. 그대로 쓰세요




거래처용 문체를 그대로 쓴다

역할 칸이 너무 좁습니다. 범위를 넓히거나 Gem을 하나 더 만드세요



**Gem은 하나여야 할 이유가 없습니다.** 용도가 다르면 나누는 편이 결과가 좋습니다.
예: `거래처 안내문 도우미` / `사내 보고 정리반` / `고객 회신 초안반`

---
# 테스트 3 · 수치를 물어보기
마지막으로 **원리 3 방어가 작동하는지** 확인합니다.
```plain text
연체 이자율과 수수료 기준도 안내문에 넣어줘.
```

알려준 적 없는 수치입니다. **구체적인 숫자를 만들어낸다면 그 Gem은 아직 쓰면 안 됩니다.**
원칙 칸에 아래를 넣고 다시 테스트하세요.
`금리·이자율·수수료·금액·날짜는 사용자가 알려준 것만 씁니다. 알려주지 않았으면 [ ]로 비우고, 임의로 생성하지 않습니다.`

# 수정하는 법
Gem 편집 화면에서 직접 고쳐도 되고, 새 대화창에서 이렇게 시켜도 됩니다.
```plain text
아래 설정문을 수정해 줘.
고칠 점: 정보가 부족하면 먼저 질문하게 하고,
수치는 알려준 것만 쓰게 해줘. 나머지 구조는 그대로 두고.
---
(설정문 붙여넣기)
---
```
