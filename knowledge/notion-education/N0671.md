# 실습 2. 지시서 집필 — 같은 가이드북, 다시

정리일: 2026-10-08 · 교육 에셋 N0671

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
같은 주제로 가이드북을 다시 만들되, 일을 시키기 전에 오케스트레이터가 장별 지시서를 먼저 쓰게 하고 실습 1의 어긋남이 어떻게 해소되는지 대조합니다.
## 진행 단계
1. **프롬프트 입력** — 지시서 문체 규칙의 빈칸에 나만의 규칙 한 줄을 채웁니다(비워 두면 추가 규칙 없음).
- 입력할 내용(Claude Code 프롬프트 요약):
```javascript
집필 모드를 별도 페이지로 옮겨주세요. 집필 모드에 오케스트레이터 집필을 추가해 주세요.
1. [지시서 집필 시작] 버튼: 아래 단계가 순서대로 실행
2. [지시서 생성] 오케스트레이터가 세 장 각각의 상세 지시서를 마크다운으로 생성(용어집, 문체 규칙+내 규칙, 범위 경계, 분량 600~800자), 파일 링크와 말풍선으로 표시
3. [집필] 집필 에이전트 셋(gemini-2.5-flash-lite)이 지시서를 받아 병렬 집필, 파일 저장
4. [교차 검토] 범위 중복·용어 불일치·문체 불일치 점검
5. [편집장 질문] 사람의 결정이 필요하면 선택 버튼과 함께 질문 1개
6. [수정·완성] 재집필 후 무질서 버전 카드와 나란히 비교
7. 모든 단계를 말풍선·상태 표시·서버 로그로 중계
(이하 교안 참고)
```
1. **서버 재시작 후 \[지시서 집필 시작\] 클릭**
2. **\[지시서 읽기\]** — 용어집, 문체(내 규칙 포함), 범위, 분량 네 항목이 있는지 확인합니다.
3. **\[예측\]** 실습 1의 어긋남 중 지시서가 막아 줄 것과 못 막을 것을 나눠 적습니다.
4. 집필과 교차 검토 말풍선을 관전합니다.
5. **\[선택\]** 편집장 질문이 뜨면 버튼으로 답하고 고른 이유를 한 줄 메모합니다.
6. 최종본 세 장을 처음부터 끝까지 이어 읽습니다.
7. **\[확인\]** 실습 1의 메모와 항목마다 대조합니다.
- 정상 결과: 6번에서 정한 용어가 세 장 전체에 반영, 프롬프트 빈칸에 넣은 내 규칙이 세 장 전체에 반영
## 막히는 지점
- 편집장 질문이 안 뜸: 정상 동작일 수 있음, "교차 검토에서 용어 표기 선택은 항상 사람에게 묻게 해 주세요"라고 요청
- 수정 후에도 일부 어긋남 남음: 남은 문제를 메모하고 "교차 검토 항목에 ○○ 점검을 추가해 주세요"라고 요청
- 내 규칙이 일부 장에만 반영: "지시서의 문체 규칙이 세 장 모두에 같은 내용으로 들어가는지 점검해 주세요"라고 요청
- 단계 중간에 멈춤: 터미널 B 마지막 로그를 Claude Code에 붙여넣어 해결 요청
- 전체 소요가 긴 것은 다단계라 정상
