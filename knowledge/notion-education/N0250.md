## 블록 1 · 맥락
4권에서 적은 세 줄이 여기 들어갑니다.
```plain text
1) 개요
- 자료명: [제안서 제목]
- 종류: [나를 제안 / 신사업 제안 / 아이디어 제안 / 공모 신청]
- 용도: [메일로 보낼 / 직접 설명할 / 신청서로 제출할]
- 대상: [받는 사람 한 명 또는 한 팀]
- 분량: 9장

2) 유의사항
- (세 개 이상 쓰세요)

3) 최종 목적
- 컨셉: [한 줄]
- 이 자료를 본 뒤 상대가 하게 될 행동: [구체적 행동]

4) 전체 흐름
- 도입 (1장) / 배경·문제 (2장) / 제안 (2장) / 근거 (1장) / 실행·효과 (2장) / 마무리 (1장)
```
### 유의사항이 자료의 성격을 결정합니다
같은 제안이라도 이렇게 달라져요.

**기업에 보낼 때**<br>"담당자가 5분 안에 판단한다. 배경 설명은 최소화하고 결론과 근거를 앞세울 것.<br>출처가 없는 항목은 슬라이드에서 제외할 것.<br>이 조직이 이미 하고 있는 일을 모르는 것처럼 쓰지 말 것."


**공모전에 낼 때**<br>"심사위원이 여러 건을 연속으로 본다. 첫 장에서 차별점이 드러나야 한다.<br>심사 기준 항목을 슬라이드 순서에 반영할 것.<br>예산이나 자원이 필요한 부분은 현실적 규모로 쓸 것."


**함께할 사람에게 보낼 때**<br>"이 사람이 시간을 내야 하는 일이다. 부담이 얼마나 되는지 먼저 밝힐 것.<br>혼자서도 시작할 수 있다는 걸 보여 줄 것.<br>거창하게 쓰지 말 것."


**유의사항은 세 개 이상 쓰세요.** 하나만 쓰면 AI가 그것만 과하게 반영합니다.

  "그거 이미 있는데요"라는 반응을 미리 차단하는 것이 목적임.

## 블록 3 · 디자인 규격
```plain text
- 배경색: #FFFFFF (기본) / #F4F5F7 (섹션 구분용)
- 주색상: #(하나만 정하세요)
- 강조색: #(포인트 색 하나만)
- 글꼴: 프리텐다드 또는 본고딕(Noto Sans KR)
- 글자 크기: 제목 40pt 이상, 본문 24pt 이상
- 비율: 16:9 고정
- 레이아웃 규칙
  · 하단에 빈 공간이 남지 않도록 화면 전체를 채울 것
  · 요소 간 겹침과 잘림이 없도록 배치할 것
  · 수치는 표 또는 그래프로 제시하고 줄글로 나열하지 말 것
  · 출처가 있는 항목은 각주로 출처를 표기할 것
  · 한 장의 요소는 5개 이하로 제한할 것
- 이미지: 미니멀 벡터 아이콘과 평면 그래픽만 사용. 사진과 3D 렌더는 쓰지 말 것
- 요소가 깨지거나 겹치지 않도록 작업 후 다섯 번 이상 확인할 것
```

**"파란색"이라고 쓰면 AI가 파란색의 평균을 씁니다.**
`#0C3C6E`라고 쓰면 정확히 그 색이 나와요. 색은 세 개까지만 쓰세요.<br>번거로우면 메인색 하나만 주고 **"어울리는 색 2개를 알아서 골라 줘"**라고 해도 됩니다.


**제안 대상의 색을 쓰면 효과가 큽니다**
그 회사 로고 색을 찾아 주색상으로 넣어 보세요. **"우리 회사를 알아봤구나"**가 첫 장에서 전달됩니다.

## 블록 4 · 산출 규칙
여기가 **AI 티를 없애는 블록**입니다.
```plain text
1) 말투
   - 구어체 사용 금지. 개조식으로 작성할 것
   - 예: "많은 도움이 될 것으로 기대됩니다" (X) / "예상 효과: 문의 유형 변화" (O)

2) 사실 관계
   - 내가 제공하지 않은 수치·기관명·사례는 절대 추가하지 말 것
   - 자료에 없는데 필요한 항목은 [확인 필요]로 표시할 것
   - 출처가 있는 수치는 각주로 출처를 유지할 것
   - 조사에서 "추측"으로 표기한 항목은 슬라이드에서도 그 표기를 유지할 것

3) 구성
   - 한 장에 두 가지 이상의 주제를 섞지 말 것
   - 내용이 넘치면 억지로 넣지 말고 장을 분리할 것
   - 분리했을 경우 어느 부분을 추가·수정했는지 보고할 것

4) 재량
   - 설계도는 가이드이며, 맥락상 필요한 내용은 추가해도 됨
   - 지시대로만 따르지 말고 빠진 부분이 있으면 보완할 것
```

**2번의 세 번째·네 번째 줄이 오늘 특히 중요합니다**
3부 조사에서 "출처 없음"이나 "추측"으로 표시한 항목이 있습니다.<br>이 지시가 없으면 그것들이 **확정된 사실처럼** 슬라이드에 올라갑니다.

# 설계서를 AI에게 대신 쓰게 하기 ✍️
2부 클로드 대화창에 이어서 넣으세요. 딜레마 답변과 조사 결과가 거기 있습니다.
```plain text
아래 자료를 읽고, 제안서 설계서 초안을 작성해 줘.
아직 슬라이드는 만들지 말고 설계서 텍스트만 줘.

설계서는 네 블록으로 구성해 줘.
블록 1 맥락: 개요, 유의사항 3개 이상, 최종 목적, 전체 흐름
블록 2 슬라이드 설계도: 각 장마다 분류 / 헤드메시지 / 내용 설명 / 시각 요소.
       표가 아니라 줄글로 서술해 줘
블록 3 디자인 규격: 색상 코드, 글꼴, 크기, 레이아웃 규칙
블록 4 산출 규칙: 말투, 사실 관계, 구성, 재량

조건
- 슬라이드는 총 9장
- 헤드메시지는 주제어가 아니라 결론이 담긴 완성 문장으로
- 6장은 위에서 제가 답한 딜레마 내용과 가치 키워드를 근거로 쓸 것
- 제가 주지 않은 수치·기관명·사례는 절대 추가하지 말고 [확인 필요]로 표시
- 출처가 있는 항목은 출처를 유지할 것
- 조사에서 "추측"으로 표기한 항목은 그 표기를 유지할 것
- 유의사항은 아래 제안서 종류와 대상의 특성을 근거로 직접 판단해서 써 줘

[제안서 종류]
[받는 사람]
[상대가 할 행동]
[3부 조사 정리표 — 출처 포함]
[3부 조직이 지키는 것 세 가지]
```

**AI가 쓴 설계서에서 사람이 반드시 볼 세 항목**
**① 유의사항** — AI는 그 조직을 모릅니다. 여기는 사람이 채워야 해요<br>**② 헤드메시지** — 순서대로 읽어 논리가 이어지는지 확인<br>**③ \[확인 필요\] 표시** — 어디에 자료 구멍이 있는지 파악
