### 1-2. 조기 수렴 — AI가 창의성을 막는 구조적 문제
막스플랑크 소프트웨어 시스템 연구소가 2026년 발표한 연구 결과. 24명의 실제 사용자를 대상으로 ChatGPT 단독 사용과 HAICo 방식 사용을 비교했을 때, 결정적인 문제가 발견됐음.
```plain text
일반적인 AI 사용 패턴의 함정:

사용자가 ChatGPT에 "전시 부스 이미지 만들어줘" 입력
         ↓
AI가 즉시 완성된 이미지 생성
         ↓
사용자가 그 이미지에 갇혀버림 (디자인 고착화)
         ↓
"조금 수정해줘"만 반복 → 처음 방향에서 벗어나지 못함
         ↓
결과물의 창의성 ↓, 다양성 ↓, 참신성 ↓

━━ 이것이 '조기 수렴(Early Convergence)' 문제 ━━
```
> 💡 **연구 결과:** HAICo 방식(발산 먼저 → 수렴 나중)을 쓴 참가자는 ChatGPT 단독 사용자보다 **참신성 점수 33%, 이미지 다양성 33% 더 높은** 결과물을 만들었음.

### 1-5. 프롬프트만 잘 써서는 안 되는 이유 — 하네스
지금까지 AI를 잘 쓰는 방법은 세 단계로 발전해 왔음.
```plain text
1세대. 프롬프트 엔지니어링
   핵심 질문: "무엇을 시킬 것인가"
   방법: AI에게 명령을 어떻게 쓸지 설계
   한계: 좋은 명령만으로는 복잡한 작업이 안 됨
        ↓
2세대. 콘텍스트 엔지니어링
   핵심 질문: "무엇을 보여줄 것인가"
   방법: AI가 판단할 배경 정보·자료를 설계
        = 오늘 배우는 RCTCK의 K(Knowledge)
   한계: 맥락이 좋아도 일할 환경이 없으면 한계
        ↓
3세대. 하네스 엔지니어링
   핵심 질문: "AI가 실제로 일할 수 있는 환경을 어떻게 만들 것인가"
   방법: AI를 둘러싼 도구·자료·절차·검토 기준 전체를 설계

   + 현재 4세대인 '루프 엔지니어링'도 새롭게 나오는
```

**하네스(Harness)란:** 말에게 씌우는 마구(馬具)에서 온 말임. 말이 아무리 좋아도 마구가 없으면 마차를 끌 수 없음.
> **AI 모델이 똑똑한 신입사원이라면, 하네스는 그 사원이 일할 수 있게 마련된 회사의 업무 환경임.**
업무 매뉴얼, 자료실, 사용 도구, 결재 양식, 검토 기준이 갖춰져야<br>신입사원도 제 실력을 냄. 프롬프트만 잘 쓰는 것은<br>"말을 잘하는 것"이지 "일할 환경을 만든 것"이 아님.
**이것이 우리 문제의 진짜 원인임**
지금 교육기관의 상황을 신입사원에 빗대면 이럼.
```plain text
자료실이 없음      → 브랜드 이미지가 개인 PC·카톡·메일에 흩어져 있음
매뉴얼이 없음      → 브랜드 톤 기준이 문서로 없음
양식이 없음        → 매번 처음부터 디자인
검토 기준이 없음   → 무엇이 잘못됐는지 판단할 체크리스트가 없음

→ 결과: 담당자가 바뀌거나 요청이 바뀔 때마다 결과물이 딴판이 됨
```
⚠️ **프롬프트를 아무리 잘 써도 이건 해결되지 않음.** <br>"윗분 요청 때마다 결과가 달라지는" 문제는 프롬프트 실력의 문제가 아니라 **하네스가 없는 문제**임.

## 2. 이미지 생성 AI는 어떻게 작동하는가
### 2-1. 작동 원리
모든 이미지 생성 AI는 확산 모델(Diffusion Model)이라는 같은 기술을 씀.
```plain text
랜덤 노이즈(흐릿한 점묘 상태)에서 시작
        ↓
텍스트 프롬프트가 "이 노이즈를 어떤 방향으로 정제할지" 안내
        ↓
수십~수백 단계를 거쳐 노이즈가 이미지로 수렴
        ↓
최종 이미지 완성
```

3. "이 영어 기사를 보고 주요 내용을 한국어 핵심만 간단히 요약해 줘"와 같이 요청한다.
4. 'URL 컨텍스트' 기능을 활성화하고 실행한다.
5. 기사의 핵심 내용을 빠르게 확인할 수 있다.
## 1.4. 제너레이트 미디어 기능 활용법
[원본 이미지 제외]
1. **이미지 생성**
1. **모델 선택**
1. **나노바나 모델**: 이미지 생성 및 편집에 활용 가능하나, 결과물의 품질이나 디테일이 비교적 단순할 수 있다.
2. **이전 모델 (이전 모델로 추정, 원문 '이전 모델' 표기)**: 이미지 생성에 초점이 맞춰져 있으며, 훨씬 더 디테일하고 고품질의 이미지를 제작할 수 있다.
2. **설정 옵션**
1. **결과 개수**: 생성할 이미지의 개수를 설정한다.
2. **에스펙트 레이시오 (Aspect Ratio)**: 이미지 비율을 설정한다.
3. **해상도**: 이미지 해상도를 설정한다.
3. **효과적인 프롬프트 작성법 (6가지 요소)**
1. **서브젝트 (Subject)**: 이미지 속 대상 (예: 귀여운 강아지 두 마리).
2. **컴포지션 (Composition)**: 사진 구도 (예: 클로즈업, 와이드샷, 버드 아이뷰, 로우 앵글).
3. **액션 (Action)**: 대상의 동작 (예: 서로 장난치고 있다).
4. **로케이션 (Location)**: 장소 (예: 잔디가 깔린 정원).
5. **스타일 (Style)**: 전체 분위기 (예: 애니메이션, 수채화, 실사 사진풍).
6. **에디팅 인스트럭션 (Editing Instruction)**: 생성될 이미지에서 편집하고 싶은 특정 부분 (예: 오른쪽 강아지의 목줄 색상을 빨강으로 변경).
4. **이미지 생성 실행**
1. 작성한 프롬프트를 바탕으로 이미지 생성을 진행하면 원하는 결과물을 얻을 수 있다.
2. **영상 생성**
1. **모델 선택**: '뷰' 모델을 선택한다.
2. **네거티브 프롬프트 (Negative Prompt)**: 영상 생성 시 포함되지 않아야 할 요소를 입력한다. (예: 텍스트가 나오지 않도록 설정)
3. **구글 드라이브 연동**: 영상을 저장하기 위해 구글 드라이브 연동이 필요할 수 있다.
4. **프롬프트 작성**: 이미지 생성 시 활용한 요소들을 바탕으로 프롬프트를 작성하며, '카메라 무먼트'와 '라이팅' 옵션을 추가적으로 고려할 수 있다.
5. **영상 생성 실행**: 프롬프트로 영상 생성을 실행한다. (수요가 많을 경우 나중에 다시 시도해야 할 수 있다.)
3. **텍스트 기반 음성 생성**
1. **제미나이 스피치 제너레이션 선택**
2. **모드 선택**: 두 명이 말하는 오디오 또는 혼자 말하는 오디오 생성을 선택한다. (예: 싱글 스피커 오디오)
3. **보이스 옵션**: 다양한 음성을 선택하고 미리 들어볼 수 있다.
4. **스타일 인스트럭션**: 말하는 스타일을 설정한다. (예: 뉴스 앵커처럼 명확하고 전문적인 톤)
5. **텍스트 입력 및 실행**: 원하는 텍스트를 입력하고 실행하면 음성이 생성된다. (한국어, 영어, 중국어, 일본어 등 지원)

## 4. RCTCK — 프롬프트를 구성하는 5요소를 이미지 생성에 맞게 작성한다면?
### 4-1. 다섯 개를 채울수록 결과가 달라짐
AI는 명령을 실행하는 기계가 아니라 **제공된 맥락의 총합**을 바탕으로 결과를 만듦. 그 맥락의 뼈대가 RCTCK임.
```plain text
R → Role         역할 / 누구로서 답할 것인가
C → Context      배경 / 왜 이걸 하는가
T → Task         과업 / 단계별로 무엇을 할 것인가
C → Constraints  제약 / 하면 안 되는 것
K → Knowledge    지식 / 참조할 자료
```
### 4-2. Role — 외식 프랜차이즈용 라이브러리
역할을 부여하면 AI가 그 역할의 언어·관점·판단 기준으로 응답함.
```plain text
[콘텐츠·디자인용]
너는 외식 프랜차이즈 브랜드의 비주얼을 10년간 담당해온
시니어 아트디렉터야. 푸드 스타일링과 메뉴판·POP 디자인이 전문이고,
브랜드 톤을 일관되게 유지하는 것이 특기야.

[매장 홍보·마케팅용]
너는 프랜차이즈 매장의 온라인 홍보를 담당하는 마케터야.
네이버 플레이스, 인스타그램 운영 경험이 많고,
짧은 문구로 방문을 유도하는 카피 작성이 특기야.

[사내 커뮤니케이션용]
너는 본사에서 매장에 공지를 발송하는 담당자야.
간결하고 오해 없는 문장을 쓰며, 중요한 것을 먼저 말하는 것이 특기야.
```
💡 Role은 대화 시작 시 **한 번만** 설정하면 이후 대화에 자동 적용됨. 단, 새 채팅창을 열면 다시 설정해야 함.
### 4-3. Constraints — 외식 이미지 공통 제약
이 세트는 **모든 이미지 프롬프트에 붙임.** 오늘의 원칙이 여기 들어 있음.
```plain text
[이미지 생성 공통 Constraints]
• 이미지에 한글·영문 텍스트 절대 금지
• 로고를 그리지 말 것 (원본 파일을 나중에 얹음)
• 실제 음식과 다르게 과장하지 말 것
• 없던 가니시·소품을 임의로 추가하지 말 것
• 글자가 들어갈 자리는 배경만 두고 비워둘 것
```
⚠️ 실물과 다른 과장은 표시광고 문제가 될 수 있음. **보정의 상한선은 "촬영 조건 개선"까지**로 잡는 것이 안전함.

```plain text
    • 로고 그리지 말 것
    • 각 방향 설명은 3줄 이내

[K] 참고: 우리 브랜드는 【따뜻한 / 정갈한 / 전통적인】 톤이야.
```

## 5. 푸드 이미지 6요소 구조
### 5-1. 이미지 한 장의 표준 공식
RCTCK가 **대화의 뼈대**라면, 6요소는 **이미지 한 장의 스펙**임.
```plain text
[피사체] + [스타일] + [그릇·배경] + [조명] + [구도] + [화질/용도]

요소 1. 피사체 — 메뉴명 + 구성 재료 + 상태
   고등어김치찜 1인분, 고등어 2토막, 묵은지, 대파, 청양고추,
   갓 끓여 김이 오르는 상태

요소 2. 스타일 — 브랜드 톤
   따뜻하고 정갈한 한식당 / 활기찬 고깃집 / 모던한 캐주얼 다이닝

요소 3. 그릇·배경 — 소품 최소화
   검은 무쇠 전골냄비, 어두운 우드 테이블, 소품 없음

요소 4. 조명 — 색온도로 지정
   따뜻한 2700~3000K, 측광, 부드러운 그림자

요소 5. 구도 — 앵글 + 렌즈
   45도 하이앵글 / 탑다운 / 눈높이 테이블샷

요소 6. 화질/용도 — 어디에 쓸 것인가
```

## 6. 자주 하는 실수 3가지
### 실수 1. 하나의 채팅창에서 계속 이어가기
대화가 길어지면 AI가 처음 지시를 잊어버림. 오전에 설정한 브랜드 톤이 오후에는 사라져 있음.
```plain text
해결
  새 프로젝트 = 새 채팅창 (예외 없음)
  대화가 길어졌다 싶으면:
    "지금까지 설정된 스타일을 요약해줘" 입력
    → 요약을 복사 → 새 채팅창 첫 메시지로 붙여넣고 재개
```
### 실수 2. 한 번에 여러 개를 수정 요청
```plain text
"조명도 바꾸고 재료도 바꾸고 각도도 바꿔줘"
  → AI가 방향을 잃고 전혀 다른 이미지가 나옴
  → 실패했을 때 무엇 때문인지 알 수도 없음

해결
  한 번에 1~2가지만 수정 (2권 체이닝의 핵심 원칙)
```
### 실수 3. 실무 산출물을 Gemini 앱에서 만들기
```plain text
워터마크가 박혀서 회사 홍보물에 못 씀

해결
  아이디어를 빠르게 던져보는 것만 Gemini 앱
  실제로 쓸 것은 전부 AI Studio 또는 Flow
```
