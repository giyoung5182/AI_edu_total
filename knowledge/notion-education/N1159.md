# 실습 2. 오케스트레이터 투입 — 같은 문서, 다시

정리일: 2026-10-08 · 교육 에셋 N1159

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
관리자 에이전트(오케스트레이터)를 투입해 같은 가이드를 다시 만들고, 실습 1의 실패 목록과 대조한다.
## 진행 단계
1. **프롬프트 입력** — 창②에 오케스트레이터 모드 추가 요구사항을 입력한다.
- 입력할 내용: "오케스트레이터 집필 시작" 버튼 추가, \[계획\] gemini-2.5-flash가 목차와 장별 JSON 지시서(용어집·문체 규칙·범위 경계·분량 600\~800자) 생성, \[집필\] 에이전트 5개가 지시서대로 작성, \[교차 검토\] 중복·용어·문체·혼선 점검 목록 표시, \[편집장 질문\] 사람 결정이 필요하면 질문 1개 표시, \[수정·완성\] 최종본 카드 표시, 단계별 로그 (이하 교안 참고)
2. **실행** — 서버를 재시작하고 /writing에서 "오케스트레이터 집필 시작"을 누른다.
3. **지시서 읽기** — 지시서 5개 중 하나를 골라 용어집·문체·범위·분량 네 항목이 있는지 확인한다.
4. **예측** — 실습 1에서 찾은 실패 중 지시서가 막아 줄 것과 못 막을 것을 나눠 적는다.
5. **로그 관찰** — 집필과 교차 검토 동안 창①의 로그를 본다.
6. **편집장 응답** — 오케스트레이터의 질문이 뜨면 답하고 결정 근거를 한 줄 메모한다.
7. **최종본 읽기·대조** — 최종본 카드 다섯 장을 읽고 실습 1의 실패 메모와 항목별로 대조한다. 내가 정한 용어가 다섯 장에 일관되게 반영됐는지 확인한다.
- 정상 결과: 실패 목록 중 일부가 해소되고, 그중 하나는 내 결정으로 고쳐짐
## 막히는 지점
- 편집장 질문이 안 뜸: 결정 필요 사안이 없다고 판단된 경우. 한 번 더 실행하거나 "용어 표기 선택은 항상 사람에게 묻게 해 주세요"라고 요청
- 수정 후에도 일부 문제 잔존: 교차 검토의 한계. "교차 검토 항목에 ○○ 점검을 추가해 주세요"라고 요청
- 단계 중간에 멈춤: 창①의 마지막 로그를 창②에 붙여넣어 해결 요청
- 429 에러: 호출이 몰린 것. 대기를 늘려 달라고 요청하고 재실행
