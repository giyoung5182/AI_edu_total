본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

> 이 자료는 1권 "데이터 연동" 챕터의 방식 ③(구글시트+GAS)을 **실제로 손코딩하는**<br>상세 실습입니다. 강사가 프로님 사본으로 관문을 확인한 뒤, 새 프로젝트+개인<br>Supabase로 처음부터 끝까지 완주한 과정을 그대로 담았습니다.<br>방식 ③이 필요한 수강생(프로님·프로님·프로님 휴무)의 개별 지원 시 사용합니다.
---
## 왜 개인 Supabase인가 (요약)
Lovable Cloud는 Supabase URL/key를 감춰둬서 **GAS 직접 연동이 안 됩니다.**<br>개인 Supabase는 URL/key가 노출되어 GAS가 바로 붙을 수 있습니다. 그래서 GAS<br>연동을 쓸 앱은 개인 Supabase(길3)로 갑니다. (자세한 배경은 1권 데이터 연동 챕터 참고)
전체 흐름:
```plain text
구글시트 → GAS(코드) → 개인 Supabase 테이블 → (앱이 읽음)
```

## STEP 1 — 개인 Supabase 프로젝트 만들기
```plain text
1. supabase.com 로그인 (GitHub 계정으로도 가능)
2. New organization
   · Name: 아무거나 (예: jjdd-test)
   · Type: Personal / Plan: Free
3. New project
   · Project name: 알아보기 쉽게 (예: jjdd-gas-test)
[개별 인증정보 제외 — 본인 계정으로 준비하세요.]
   · Region: Northeast Asia (Seoul) ← 한국이라 빠름
   · Plan: Free
4. 생성 직후 Status가 잠깐 "Unhealthy"일 수 있음
   → 1~2분 후 F5 → "Healthy"로 바뀌면 정상
```
> 💡 이 화면에서 이미 **Project URL이 그대로 노출**됩니다<br>(`[개별 링크 제외]). Lovable Cloud엔 없던 것으로, 개인 Supabase가<br>GAS에 유리한 이유의 실물 증거입니다.

## STEP 2 — 연결 정보(URL + key) 확보 ★ 핵심 함정
```plain text
⚙️ Settings → API Keys 로 이동

⚠️ 2026년 Supabase는 key 체계가 2가지입니다:

  [Publishable and secret API keys] 탭 (새 방식)
    · sb_publishable_...  (공개용)
    · sb_secret_...       (서버용)
    ★ 이 sb_secret_ key를 GAS에 쓰면 401 거부됩니다!
      오류: "Forbidden use of secret API key in browser..."

  [Legacy anon, service_role API keys] 탭 (예전 방식)
    · anon         (공개용)
    · service_role (서버용, eyJ로 시작하는 긴 JWT)
    ★ GAS에는 이 service_role key를 써야 작동합니다.
```
**할 일:**
```plain text
1. [Legacy anon, service_role API keys] 탭 클릭
2. service_role 줄의 [Reveal] → key 표시 → 복사 (eyJ로 시작)
3. Project URL도 메모 ([개별 링크 제외])
```
> ⚠️ service_role key는 RLS를 무시하는 마스터 키입니다. GAS(서버)에서만 쓰고,<br>절대 앱·브라우저 코드나 공개된 곳에 넣지 마세요. 유출되면 즉시 재발급하세요.

## STEP 3 — 데이터 받을 테이블 만들기
> 데이터를 넣으려면 "받을 표(테이블)"가 먼저 있어야 합니다.
```plain text
Table Editor → New table
  · Name: leaves  (예: 휴무 데이터용)
  · Columns:
      id          int8       (자동)
      created_at  timestamp  (자동)
      name        text       ← 추가
      date        text       ← 추가
      category    text       ← 추가
  · RLS: 켜둬도 됨 (service_role key가 RLS를 우회하므로 서버 요청은 통과)
  · Save
```
> ⚠️ **컬럼 이름은 구글시트 열과 정확히 일치**시켜야 합니다. (예: data ≠ date<br>오타 주의 — 한 글자만 달라도 데이터가 안 들어갑니다.)<br>⚠️ 날짜도 리허설에선 **text**로 통일하는 게 안전합니다(date 타입은 형식이<br>안 맞으면 오류). 나중에 코드에서 형식을 다듬습니다(아래).
---
## STEP 4 — 구글시트 준비 + GAS 코드 작성
```plain text
1. 구글시트에 데이터 준비 (예: 1행 헤더 이름/날짜/카테고리, 2행부터 데이터)
2. 구글시트 상단 메뉴 → 확장 프로그램 → Apps Script
3. 기본 코드(function myFunction) 지우고 아래 코드 붙여넣기
4. 맨 위 URL·KEY 두 줄을 본인 것으로 교체 → 저장(Ctrl+S)
```
```javascript
// ===== 여기 두 줄만 본인 것으로 =====
const SUPABASE_URL = '[개별 링크 제외]
const SUPABASE_KEY = 'eyJ...(Legacy service_role key)';
// ===================================

function syncToSupabase() {
  // 1) 구글시트에서 데이터 읽기
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('시트1');
  const rows = sheet.getDataRange().getValues();

  // 2) 첫 줄(헤더) 빼고 { name, date, category } 로 변환
  const records = [];
  for (let i = 1; i < rows.length; i++) {
    const row = rows[i];
    if (!row[0]) continue;                 // 이름 비면 건너뜀
    records.push({
      name: String(row[0]).trim(),         // trim: 앞뒤 공백 제거
      date: formatDate(row[1]),            // 날짜 형식 변환(아래 함수)
      category: String(row[2]).trim()
    });
  }
  Logger.log('보낼 데이터 ' + records.length + '건: ' + JSON.stringify(records));

  // 3) Supabase 테이블로 전송(INSERT)
  const response = UrlFetchApp.fetch(SUPABASE_URL + '/rest/v1/leaves', {
    method: 'post',
    contentType: 'application/json',
    headers: {
      'apikey': SUPABASE_KEY,
      'Authorization': 'Bearer ' + SUPABASE_KEY
    },
    payload: JSON.stringify(records),
    muteHttpExceptions: true
  });

  // 4) 결과 확인
  Logger.log('응답 코드: ' + response.getResponseCode());
  Logger.log('응답 내용: ' + response.getContentText());
}

// 시트 날짜칸은 Date 객체로 읽혀 긴 형식이 되므로 YYYY-MM-DD로 변환
function formatDate(value) {
  if (value instanceof Date) {
    return Utilities.formatDate(value, 'Asia/Seoul', 'yyyy-MM-dd');
  }
  return String(value).trim();
}
```
**코드가 하는 일 (한 줄씩):**
```plain text
getSheetByName('시트1')       → "시트1" 탭 지목
getDataRange().getValues()    → 시트 전체를 표(2차원 배열)로 읽음
for i=1부터                    → 0번(헤더) 건너뛰고, row[0]=이름/row[1]=날짜/row[2]=카테고리
.trim()                       → 공백 제거 (공백 때문에 깨지는 것 방지)
UrlFetchApp.fetch(...POST...) → Supabase에 "이 데이터 넣어줘" 요청
  URL 뒤 /rest/v1/leaves      → "leaves 테이블에"
  headers apikey/Authorization → service_role key로 인증 (★ 이게 되는 게 핵심)
응답 코드 201                 → 성공
```

## STEP 5 — 실행 + 권한 승인 (첫 실행만) ★ 수강생 놀람 포인트
```plain text
상단 [▶ 실행] 클릭 → 처음이면 권한 승인 절차가 뜸:

1. "승인 필요" 팝업 → [권한 검토]
2. 계정 선택 → 본인 구글 계정
3. ⚠️ "Google에서 확인하지 않은 앱" 경고 (무섭게 생겼지만 정상)
   → [고급] 클릭 → 아래 ["OOO(안전하지 않음)으로 이동"] 클릭
4. 권한 목록 → [허용]
   (스프레드시트 보기 + 외부 서비스 연결 권한)

→ 이 4단계는 처음 한 번만. 다음부터 바로 실행됨.
```
> ⚠️ 3번 "확인 안 된 앱" 경고에서 대부분 멈칫합니다. 본인이 만든 스크립트라<br>안전하며, \[고급\] → \[이동\]으로 넘어가면 됩니다.

## 날짜·중복 다듬기 (실무 완성도)
**① 날짜 형식** — 시트 날짜칸은 `Wed Jul 08 2026 00:00:00 GMT+0900...`처럼 길게<br>읽힙니다. 위 코드의 `formatDate` 함수가 이를 `2026-07-08`로 변환합니다<br>(`instanceof Date`로 날짜/글자를 판별해 처리).
**② 중복 방지** — GAS는 실행할 때마다 INSERT(새로 추가)라, 다시 실행하면<br>데이터가 쌓여 중복됩니다. 방지하려면 실행 전에 기존 데이터를 DELETE하는 방식<br>(= "스냅샷 덮어쓰기")을 씁니다. 프로님 휴무 기획서의 "스냅샷 덮어쓰기"가<br>바로 이것입니다.
```plain text
간단 리허설: Table Editor에서 기존 행 삭제 후 재실행
실무: 코드에 "INSERT 전 해당 범위 DELETE" 추가 (스냅샷)
```

## 자동 실행 (트리거)
버튼으로 매번 누르는 대신, GAS 트리거로 자동 실행할 수 있습니다.
```plain text
Apps Script → 왼쪽 [트리거(시계 아이콘)] → 트리거 추가
  · 실행할 함수: syncToSupabase
  · 이벤트 소스: 시간 기반
  · 예: 15분마다 (프로님 기획서의 "15분 주기 자동 동기화")
```

## 응용 — 드라이브 로우데이터까지 (프로님 사례)
위는 "구글시트 → Supabase"의 기본형입니다. 실무에서는 그 앞에 \*\*"드라이브에서<br>로우데이터를 불러와 GAS가 정리"\*\*하는 단계가 붙습니다. 프로님의 광고지표<br>자동화가 그 완성형이며, 별도 \[사례연구: 프로님 GAS 자동화\] 자료에서 다룹니다.
핵심만: `DriveApp`으로 드라이브 파일을 읽고, GAS가 정리한 뒤, 이 문서의<br>`UrlFetchApp.fetch(Supabase...)` 를 이어붙이면 "드라이브 → 정리 → Supabase → 앱"<br>전체 파이프라인이 완성됩니다.
> ⚠️ 단, "구글시트로 충분한지, 앱까지 필요한지"는 업무 판단입니다. 기술이<br>된다고 반드시 앱까지 갈 필요는 없습니다. (사례연구 자료 참고)
