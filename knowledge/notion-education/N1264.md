# 실습 1 — 기술 문서 요약

정리일: 2026-10-08 · 교육 에셋 N1264

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
기술 시방서를 RCTCK 다섯 칸으로 지시해, 거래처 구매담당자가 읽고 판단할 수 있는 1장짜리 소개 자료로 요약합니다.
## 진행 단계
1. **파일 업로드** — ChatGPT 입력창 왼쪽 **+** 버튼 → `03_DUOPOL_기술시방서.docx` 선택
2. **RCTCK 작성** — 워크시트 다섯 칸(R 역할 / C 맥락 / T 과업 / C 제약 / K 지식)을 먼저 채웁니다
3. **프롬프트 입력** — 채운 내용을 이어 붙여 한 번에 입력
- 입력할 내용(표준 답안):
```javascript
[역할]
너는 EPS 원료 제조사의 기술영업 담당자다.
건축자재 유통사를 상대해 왔고,
기술을 모르는 구매담당자에게 설명해야 하는 상황을 많이 겪었다.
자료에 없는 수치는 만들지 않고 "자료 확인 필요"로 표기한다.

[맥락]
이 자료를 받는 사람은 건축자재 유통사 구매담당자다.
EPS 제품을 처음 검토하는 상황이며,
이 1장으로 추가 미팅 여부를 판단한다.

[과업]
업로드한 시방서를 거래처 전달용 요약본으로 만들어라.

[제약]
- A4 반 장 이내
- 전문 용어는 괄호 안에 쉬운 설명 병기
- 경쟁 제품 대비 차별점이 드러나게
- 수치는 시방서에 있는 것만 사용
- 구성: 제품 개요 / 주요 규격 / 차별점 / 문의 안내

[지식]
업로드한 03_DUOPOL_기술시방서.docx
```
4. **결과 점검** — 체크리스트 3개 확인
- 정상 결과: 전문 용어가 그대로 남아 있지 않다 / 시방서에 없는 수치가 들어가지 않았다 / 거래처 구매담당자가 읽고 판단할 수 있다
5. **한 칸 보완** — 부족한 칸을 찾아 추가 후 재실행, "개선을 위해 추가한 칸" 기록
## 막히는 지점
- 시방서를 그대로 옮겨놓은 수준 → C(맥락)에 "제품을 처음 보는 사람" 명시
- 전문 용어가 그대로 → C(제약)에 "괄호 안에 쉬운 설명 병기"
- 없는 수치가 등장 → C(제약)에 "시방서에 있는 수치만 사용"
- 너무 김 → C(제약)에 "A4 반 장 이내"
