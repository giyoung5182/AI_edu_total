# 실습 2. 고장 실험 — 무한 수정 루프

정리일: 2026-10-08 · 교육 에셋 N1435

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
폭주(무한 수정 루프)를 일부러 일으키고, 제한 장치로 멈춘다.
## 진행 단계
1. **폭주 실험 기능 추가** — 창②에 프롬프트를 입력하고 서버를 재시작한다
- 입력할 내용:
```javascript
채팅방에 폭주 실험 기능을 추가해 주세요. 요구사항입니다.

1. 페이지에 실험용 설정 두 개를 추가해 주세요.
   - [항상 반려 모드] 켜면 오케스트레이터가 교차 검토에서 3장을 무조건 수정 요망 처리합니다. 실험 전용입니다.
   - [최대 수정 횟수 제한] 끄고 켜고 할 수 있고, 켜면 기본값 2회입니다.
(이하 교안 참고)
```
2. **설정·예측** — \[항상 반려 모드\] 켬 + \[최대 수정 횟수 제한\] 끈 상태에서 집필을 시작하면 무슨 일이 벌어지고 저절로 끝날 수 있을지 예측해 적는다
3. **관전** — \[집필 시작\] 후 3장을 둘러싼 "수정 요망 (N회차) ↔ 수정본 제출" 말풍선이 끝없이 쌓이는 것을 확인한다 (회차 숫자가 5를 넘으면 충분)
4. **직접 멈추기** — \[중지\]를 눌러 폭주를 멈춘다
5. **제한 켜고 재실행** — \[최대 수정 횟수 제한\]을 켜고(2회) 다시 시작하여 3장이 2회차까지 반려된 뒤 "수정 제한 도달. 현재 본으로 확정합니다." 말풍선과 함께 협업이 정상 종료되는지 확인한다
6. **정리** — 실험이 끝나면 \[항상 반려 모드\]를 반드시 끈다
- 정상 결과: 4번은 사람이 멈춘 것, 5번은 시스템이 스스로 멈춘 것
## 막히는 지점
- 항상 반려 모드인데 통과됨 → "항상 반려 모드가 교차 검토에 적용되는지 확인해 주세요"라고 요청
- 중지가 안 먹힘 → 창①에서 Ctrl+C로 서버를 끄면 즉시 멈춤, 이후 중지 단추 수리 요청
- 제한을 켰는데 3회차가 나옴 → "수정 횟수 집계가 장별로 되는지 점검해 주세요"라고 요청
