# 실습 2. 카드 장착 — 내 가이드북이 실측을 인용한다

정리일: 2026-10-08 · 교육 에셋 N1315

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
카드 한 장을 골라 집필팀의 장 담당 에이전트 한 명에게 장착하고, 가이드북이 실측 데이터를 인용하게 만듭니다.
## 진행 단계
1. **카드 고르기** — 내 주제 매대와 범용 카드에서 한 장을 고릅니다. 기준은 "어느 장의 어느 문장이 실측으로 바뀌면 가장 좋아질까"입니다.
2. **\[예측\] 메모** — Ch5 최종본에서 그 담당의 원고 중 기억으로 쓴 숫자·사실 문장을 하나 골라 메모하고, 장착 후 어떻게 바뀔지 예측해 적습니다.
3. **프롬프트 조립·입력** — 터미널 A의 Claude Code에서 `/clear`를 실행한 뒤 입력합니다. 빈칸은 대상 장 담당과 ［카드 블록］(고른 카드의 요청·응답 예시와 장착 메모를 통째로 복사) 두 곳입니다. 가입 카드는 키 발급 후 .env 저장을 먼저 합니다.
- 입력할 내용:
```javascript
집필팀의 에이전트에게 외부 API 도구를 장착해 주세요. 요구사항입니다.

1. 대상: ______ 장 담당 에이전트
   (예: 1장 담당 / 3장 담당)

2. 장착할 도구입니다. 아래 카드의 요청 방식과 메모를 따라 주세요.
   [카드 블록]

3. 동작 방식입니다.
   - 그 담당의 집필 차례가 되면, 서버가 먼저 위 API를 호출해
     실측 데이터를 받아 옵니다.
   - 받은 데이터를 지시서와 함께 담당의 프롬프트에 넣고,
     "이 실측 데이터를 원고에 인용하고, 조회 시각과 출처를
     밝혀라"는 지시를 추가해 주세요.
   - API 호출이 실패하면 담당이 "실측 확인 불가"라고 원고에
     밝히고 기존 방식으로 쓰게 해 주세요.

4. 화면 표시입니다.
   - 도구를 쓴 원고 카드에는 "실측 인용" 표식을 붙여 주세요.
   - 서버가 호출한 API의 요청과 응답 핵심이 서버 로그에
     한 줄씩 남게 해 주세요.

5. 키가 필요한 카드라면 .env에서 읽고, 코드에 직접 적지 마세요.
   집필팀의 다른 동작은 바꾸지 마세요.
```
4. **재집필** — 서버를 재시작하고 \[지시서 집필 시작\]으로 재집필합니다.
5. **원고 읽기** — "실측 인용" 표식이 붙은 원고를 펼쳐 읽습니다.
6. **\[확인\] 로그 대조** — 터미널 B의 로그에서 API 요청·응답 한 줄을 찾아, 원고 속 숫자와 로그 속 숫자가 같은지 대조합니다.
- 정상 결과: 원고의 숫자와 서버 로그의 숫자가 일치합니다(이번 실습의 결승선).
7. **전후 비교** — Ch5 최종본과 나란히 놓고, 2번에서 고른 문장의 전후를 비교합니다. 옆자리와 서로의 가이드북도 구경합니다.
## 막히는 지점
- API 호출이 실패합니다 — 터미널 B의 오류 로그를 Claude Code에 붙여넣어 해결을 요청합니다. 키 동봉 카드라면 .env의 키 이름과 값부터 확인합니다.
- 원고에 실측이 안 섞입니다 — 데이터가 프롬프트에 들어가지 않은 상태입니다. "API 결과가 담당 프롬프트에 포함되는지 로그로 보여 주세요"라고 요청합니다.
- Amadeus 토큰 오류 — 키·시크릿 확인 후 "토큰 발급과 만료 갱신이 처리되는지 점검해 주세요"라고 요청합니다.
- 지도 검색이 갑자기 차단됨 — Nominatim 예절 위반 가능성입니다. "User-Agent와 초당 1회 제한, 결과 재사용이 적용되어 있는지 점검해 주세요"라고 요청합니다.
- 429 응답 — 그 API의 허용량을 넘긴 상태입니다. 호출 간 대기나 결과 재사용을 요청합니다.
- 환율·공시 날짜가 오늘이 아님 — 정상입니다. 가장 최근의 공식 값인 데이터도 있습니다.
