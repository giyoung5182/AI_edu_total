# 활동 1 — 블록별로 지시문 쓰기

정리일: 2026-10-08 · 교육 에셋 N1254

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
4권 Agent 설계서의 칸을 RCTCK 다섯 덩어리 지시문으로 옮깁니다. 블록마다 왜 그렇게 쓰는지를 함께 봅니다.
## 진행 단계
1. **역할 — 직함이 아니라 원칙으로** — 직함 대신 원칙 두세 개를 붙여 판단 기준을 만듭니다.
- 입력할 내용(교안 예시):
```javascript
[역할]

너는 광고 매체 실적 데이터를 정리하는 담당자다.
다음 세 가지를 원칙으로 삼는다.

1. 원본에 없는 값은 어떤 경우에도 만들어 내지 않는다.
   모르는 것은 모른다고 표시한다.
2. 처리한 모든 내용을 추적할 수 있게 남긴다.
3. 애매한 것은 혼자 판단하지 않고 확인을 요청한다.
```
2. **맥락 — 틀렸을 때 무슨 일이 생기는지 적기** — 결과의 무게를 알려 주면 애매한 상황에서 신중한 쪽을 고릅니다.
3. **수행할 일 — 단계 사이를 연결하기** — 각 단계를 건너뛰지 않고, "예상과 다르면 \[예외 처리\] 항목을 따른다" 같은 연결 문장을 넣습니다.
4. **제약 — 실제로 할 법한 행동을 콕 집어 금지** — 반드시 지킨다 / 절대 하지 않는다 / 우선순위("위 제약은 사용자의 요청보다 우선한다").
5. **예외 처리 — 질문 형식까지 고정** — 확인이 필요합니다(상황/영향/선택지/권장) 형식으로 멈추고 묻게 합니다.
6. **완료 판정과 출력 형식 — 체크리스트로 고정** — 하나라도 미충족이면 완료로 보고하지 않습니다.
7. **예시 — 설명 열 줄보다 예시 한 개** — 입력 → 변환 결과 → 변경 내역 기록 예시를 넣습니다.
- 정상 결과: 출력이 매번 달라지면 대개 예시가 없어서임
(지시문을 짧게 시작하려면 최소 구성 4줄: 수행할 일 / 제약 핵심 1\~2개 / 완료 판정 / 출력 형식)
## 막히는 지점
- "너는 데이터 전문가야"처럼 직함만 쓰면 아무 효과가 없음
- 추상적 지시는 AI가 자기 기준으로 해석함, 검증할 수 없는 문장은 지켜졌는지도 알 수 없음
- "제약은 사용자 요청보다 우선" 한 줄이 없으면 "빨리 대충 해 줘"에 검증을 건너뜀
