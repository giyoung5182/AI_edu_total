## Block 1 — Claude 이해와 기초 실습 (11:10\~11:35, 25분)
### 1-1. Claude가 문서 작업에 강한 이유
1권에서 세 도구의 역할 분담을 정리했습니다. 복습하면 이렇습니다.
```plain text
ChatGPT   이미지 생성, 아이디어 발산, GPT 앱 생태계
Gemini    자료 분석, 실시간 검색, 스케치 해석, Google 연동
Claude    긴 문서 작성, 논리 구성, 복합 조건 처리, 맥락 유지
```
오늘은 Claude가 왜 문서 작업에서 다른 두 도구보다 유리한지를 정확히 이해하고, 그 원리를 실습에 직접 적용합니다.
**세 도구의 역할 분담 — 벤다이어그램**
[원본 이미지 제외]

**이유 1 — 긴 맥락을 잃지 않는다**
ChatGPT로 긴 문서를 작성하다 보면 앞에서 준 지시를 어느 순간 잊어버리는 경험을 합니다. "아까 3챕터 구조로 써달라고 했는데 2챕터로 나왔어요" 같은 문제입니다. Claude는 동일한 대화 안에서 처음 준 지시를 끝까지 유지합니다. A4 수십 장 분량을 한 번에 처리해도 앞뒤 맥락이 흐트러지지 않습니다. 전시 제안서처럼 챕터가 많고 일관된 톤이 필요한 문서에서 이 차이가 크게 납니다.
**이유 2 — 복합 조건을 동시에 처리한다**
"3챕터 구조로, 공무팀 문체로, 존댓말로, 각 챕터 200자 이내로, 금액은 한글 병기로." 이렇게 여러 조건을 동시에 주면 ChatGPT는 종종 일부를 빠뜨립니다. Claude는 이런 복합 조건 처리 정확도가 현저히 높습니다.
**이유 3 — Golden Sample을 학습한다**
이것이 오늘 Block 1의 핵심입니다. Claude는 K(Knowledge)에 기존 문서를 넣으면 그 문서의 문체, 구조, 톤, 어휘 선택 방식을 학습하여 새 내용을 동일한 스타일로 출력합니다. 단순히 내용을 참고하는 수준이 아니라, 텍스트 패턴을 분석해 같은 문장 리듬과 단어 수준으로 새 내용을 씁니다.
```plain text
K에 아무것도 넣지 않고 요청했을 때:
"전시 부스 제안서의 프롤로그는 전체 프레임을 설정하는 중요한 요소입니다.
 고객의 니즈를 파악하고 창의적인 솔루션을 제시하는 것이 핵심입니다."
→ 어디서나 볼 수 있는 평범한 문장

K에 기준 전시 프로젝트 제안서 PLANNING 챕터를 넣은 뒤:
"이미지는 '만드는 것'이 아니라 '쌓아 가는 것'이다.
 브랜드 이미지는 원하는 이미지를 정하고 만들어서 세상에 내보인다고 해서
 만들어지는 것이 아니다..."
→ 교육기관 고유의 문체와 철학적 깊이가 살아남
```

### Projects — 프로젝트별 대화 관리
**접근 경로:** 좌측 사이드바 → Projects 섹션 → "+ New project"
Projects는 연관된 대화를 하나의 프로젝트로 묶는 기능입니다. 프로젝트 안의 모든 대화가 같은 지침과 파일을 공유합니다. 여러 클라이언트 프로젝트를 동시에 진행할 때 대화가 뒤섞이는 문제를 방지합니다.
[원본 이미지 제외]

```plain text
일반 대화 vs Projects:

일반 대화
├ 대화마다 지침을 새로 입력해야 함
├ 파일을 매번 첨부해야 함
└ 대화가 쌓이면 이전 작업을 찾기 어려움

Projects
├ 프로젝트 지침을 한 번 설정 → 모든 대화에 자동 적용
├ 파일을 프로젝트에 올려두면 모든 대화에서 참조 가능
└ 프로젝트별로 대화가 분리되어 관리됨
```
**프로젝트 만드는 법:**
```plain text
1. 좌측 사이드바 하단 Projects 섹션에서 "+ New project" 클릭
2. 프로젝트 이름 입력 (예: "LG 테크 컨퍼런스 2026")
3. Project instructions(프로젝트 지침) 입력
4. Add content 버튼으로 관련 문서 업로드
5. 이 프로젝트 안에서 시작하는 모든 대화에 지침과 파일이 자동 공유
```
**Project instructions 작성 예시:**
```plain text
[LG 테크 컨퍼런스 2026 프로젝트]

클라이언트: 하이브 마케팅 컴퍼니 (담당: 프로님)
프로젝트명: LG 2026 Tech Conference 전시 부스 설치 공사
장소: ISC B1 + ISC 융합로 E1
계약 금액: 156,000,000원 (일억오천육백만 원정)

이 프로젝트의 모든 문서는 다음 기준을 따르세요.
- 문체: "~하였습니다" 공문 스타일
- 금액 표기: 숫자 + 한글 병기
- 클라이언트 담당자는 "프로님"으로 호칭
- 공사 항목 약어 정리: 목공 = 목공사 및 가구 제작, 전기 = 전기 공사
```
이렇게 설정해두면 "이번 클라이언트 담당자 이름이 뭐야?", "계약 금액 다시 알려줘"를 매번 설명 없이 바로 답할 수 있습니다.
**프로젝트에 파일 올리기:**
Add content 버튼을 클릭해 해당 프로젝트 관련 파일을 업로드합니다. 올려둔 파일은 프로젝트 안의 모든 새 대화에서 자동으로 참조됩니다.
```plain text
LG 테크 컨퍼런스 2026 프로젝트 파일 구성 예시:
├ 26_05_20_LG_Tech_Conference_견적서_교육기관.pdf   → 공사 항목·금액 참조
├ 도면_감리_프로세스_가이드.pdf                → 감리 절차 참조
└ 교육기관_제안서_Golden_Sample.txt                 → 문체 기준 참조
```

### 파일 업로드 — 개별 대화에서 문서 분석
Projects에 파일을 올리는 것 외에도, 개별 대화창에서 파일을 첨부해 그 내용을 즉시 분석할 수 있습니다.
**파일 첨부 방법:** 입력창 왼쪽 📎 아이콘 클릭 → 파일 선택, 또는 파일을 대화창으로 드래그
지원 형식: PDF, Word(.docx), Excel(.xlsx), 텍스트(.txt), 이미지(PNG·JPG)
```plain text
직군별 활용 예:

기획팀
├ 클라이언트 브리프 PDF 첨부   → "이 브리프 바탕으로 PLANNING 챕터 써줘"
├ 경쟁사 제안서 PDF 첨부       → "이 제안서의 전략 구조를 분석해줘"
└ RFP 문서 첨부               → "우리가 강조해야 할 포인트 3가지 뽑아줘"

디자인팀
├ 레퍼런스 이미지 첨부         → "이 공간의 소재·조명·색상을 텍스트로 설명해줘"
├ 스케치 사진 첨부             → "이 스케치에서 공간 컨셉 키워드 5개 추출해줘"
└ 기존 제안서 PDF 첨부         → "이 문서의 DESIGN 챕터 문체를 분석해줘"

공무팀
├ 견적서 PDF 첨부              → "이 항목들로 현장 완료 보고서를 써줘"
├ 현장 사진 첨부               → "완료된 공사 항목을 목록으로 정리해줘"
└ 카카오톡 대화 캡처 첨부      → "이 대화 내용을 공문 형식으로 변환해줘"
```
파일은 해당 대화에서만 사용됩니\`다. 같은 파일을 여러 대화에서 반복 참조하려면 Projects에 파일을 등록해두는 것이 효율적입니다.

### 두 가지 설정 방식의 역할 구분
Projects 지침과 RCTCK 프롬프트는 적용 범위가 다릅니다. 이 두 가지만 잘 써도 충분합니다.
```plain text
┌─────────────────────────────────────────────────────────────────┐
│  Projects 지침 (프로젝트별로 설정)                              │
│  적용 범위: 해당 프로젝트 안의 모든 대화                        │
│  담을 내용: 프로젝트 기간 내내 공통으로 쓰는 정보              │
│  예) 프로젝트명 / 클라이언트명 / Golden Sample / 특수 규칙     │
│                                                                 │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  RCTCK 프롬프트 (대화 1건)                                │  │
│  │  적용 범위: 지금 이 대화 1회만                            │  │
│  │  담을 내용: 이번 작업에만 필요한 구체적 지시              │  │
│  │  예) 이번 제안서 분량 / 이번 보고서 형식 / 이번 메일 수신자│  │
│  │  ★ 가장 구체적 · 가장 높은 우선순위                      │  │
│  └───────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
  Projects: 프로젝트 내 공통 정보를 한 번만 설정
  RCTCK:    지금 이 작업에만 필요한 것을 그때그때 입력
  충돌 시:  RCTCK가 우선 적용됩니다
```
실무 활용 원칙: Projects에는 "LG 테크 컨퍼런스 2026 동안 항상 쓸 것"을 넣고, RCTCK에는 "지금 이 보고서에만 필요한 것"을 넣습니다. 매 대화마다 같은 내용을 반복 입력하고 있다면 Projects 지침으로 올리는 것이 효율적입니다.
활용할 수 있습니다.

### Claude Code — 코딩 작업용 터미널 (참고)
Claude Code는 터미널 환경에서 동작하는 AI 코딩 에이전트입니다. <br>오늘 실습 범위는 아니지만, Excel 데이터 자동 처리나 반복적인 문서 변환 작업이 많은 경우 향후 검토할 수 있습니다. 코딩 경험이 없어도 한국어로 원하는 작업을 설명하면 Claude Code가 코드를 작성하고 실행합니다. 설치 방법과 활용 가이드는 claude.ai/code에서 확인할 수 있습니다.

### 1-3. RCTCK를 Claude에 적용하는 법
1회차에서 익힌 RCTCK 프레임워크를 Claude에 적용하는 방식은 구조적으로 동일합니다. 다만 Claude에서 특히 효과가 큰 요소가 있습니다.
**K(Knowledge)에 실제 문서를 통째로 넣는 것.**
ChatGPT나 Gemini도 K를 활용할 수 있지만, Claude는 K에 넣은 내용을 패턴으로 학습해 출력 스타일 전체를 변환합니다. 내용 참고를 넘어서, 문장 구조와 어휘 선택까지 따라갑니다.
**RCTCK 5요소 — 역할과 Claude에서의 작동 방식**
[원본 이미지 제외]

```plain text
RCTCK 템플릿 — Claude 전용

[R - Role]
당신은 전시 디자인 전문 회사 교육기관코리아의 [역할]입니다.

[C - Context]
회사 역량·실적: [공개 승인을 받은 가상 실적을 입력하세요.]
현재 [상황].

[T - Task]
[무엇을 만들어야 하는지 구체적으로]

[C - Constraint]
- [분량 또는 형식]
- [문체: 예) ~하였습니다 체 / 전문적이고 간결하게]
- [금지 사항: 예) 추상적 표현에만 그치지 않고 공간 요소와 연결]

[K - Knowledge]
[여기에 기존 제안서, 견적서, 클라이언트 브리프 등을 붙여넣기]
```
K 섹션에 넣는 자료의 분량은 A4 1\~3장 정도가 적당합니다. 전체 문서를 넣기보다 핵심 섹션을 발췌해 넣는 쪽이 학습 정밀도를 높입니다.

### 1-4. Golden Sample 기법
Golden Sample은 출력 품질의 기준이 될 실제 문서를 Claude에게 먼저 보여주는 방식입니다. "이렇게 써줘"를 말 대신 문서로 보여주는 것입니다.
**말로 설명 vs Golden Sample — 결과 비교**
[원본 이미지 제외]
**Golden Sample 선택 기준:**
```plain text
 ✅ 써도 되는 것                     ❌ 피해야 할 것
 ────────────────────────────────    ──────────────────────────────
 클라이언트 반응이 좋았던 제안서     여러 사람이 각기 쓴 문서
 우리 회사 스타일이 잘 드러난 문서   미완성이거나 수정이 많은 문서
 구조가 명확한 문서 (챕터·소제목)    스타일이 일관되지 않은 문서
 A4 1~3장 분량으로 발췌한 것        문서 전체를 통째로 넣은 것
```
**적용 순서:**
```plain text
 STEP 1          STEP 2              STEP 3         STEP 4
 ─────────       ──────────────      ──────────     ──────────────
 기존 제안서  →  K 섹션에       →   T 섹션에   →  "이 문체로
 핵심 섹션       "[참고 문서]"       새 프로젝트    써줘" 지시
 텍스트 복사     라벨 달고           정보 입력      → 결과 확인
                 붙여넣기                           → 체이닝 수정
```

### 실습 1-1. Golden Sample로 제안서 초안 만들기 (15분)
**목표:** 기준 전시 프로젝트 제안서의 문체·구조를 Golden Sample로 삼아, 새 클라이언트 제안서의 PLANNING 섹션 초안을 Claude로 생성한다. 체이닝 1\~2회를 통해 결과가 어떻게 개선되는지 직접 확인한다.
**준비:** claude.ai 접속 → 좌측 상단 "New conversation" 클릭
---
**Step 1 — 아래 프롬프트를 Claude 입력창에 붙여넣기**
아래 프롬프트를 그대로 복사해서 입력창에 붙여넣습니다. `[클라이언트 브리프]` 부분만 교체하면 됩니다. 오늘은 하단의 연습용 브리프를 그대로 사용합니다.
```plain text
[R - Role]
당신은 전시 디자인 전문 회사 교육기관코리아의 수석 기획자입니다.

[C - Context]
회사 역량·실적: [공개 승인을 받은 가상 실적을 입력하세요.]
전 과정 담당하는 전시 디자인 전문 회사입니다.
클라이언트 RFP를 받았으며, 제안서 PLANNING 챕터 초안을 작성해야 합니다.

[T - Task]
[클라이언트 브리프]를 바탕으로 아래 구성으로 PLANNING 챕터를 작성해 주세요.

구성:
1. PROLOGUE — 이 전시의 철학적 출발점 (역설적 선언 형식, 4~5문장)
2. INSIGHT — 클라이언트·시장 분석에서 도출한 인사이트 3가지 (소제목 + 설명 각 3문장)
3. STRATEGY — 공간 브랜딩 전략 방향 4개 (전략명(영문) + 설명 각 3문장)
4. SOLUTION — 전략 구현의 핵심 제안 3가지 (영문 키워드 + 설명 각 2문장)

[C - Constraint]
- 문체: 아래 [Golden Sample]과 동일한 톤 앤 매너
- PROLOGUE는 반드시 "X는 Y가 아니라 Z다" 형식의 역설적 선언으로 시작
- STRATEGY의 각 전략명은 영어 2~3단어로
- 추상적 개념을 쓸 때는 반드시 전시 공간의 구체적 요소(동선·소재·조명·헤더 구조 등)와 연결
- 금지 표현: "혁신적인", "최고의", "압도적인", "최첨단" 남발 금지

[K - Knowledge]
[Golden Sample — 기준 전시 프로젝트 교육기관 PLANNING 챕터 발췌]

PROLOGUE:
이미지는 '만드는 것'이 아니라 '쌓아 가는 것'이다.
브랜드 이미지는 원하는 이미지를 정하고 만들어서 세상에 내보인다고 해서
만들어지는 것이 아니다. 다양한 경험들이 쌓이고 그것들이 어떤 하나의
맥락으로 이어지면서 만들어져 간다. 브랜딩은 끝이 없다. 계속 진행 중인 상태다.

INSIGHT:
- LG Identity: 지속적으로 변화해온 LG다움의 새로운 디자인 적용을 통한
  LG Identity가 반영된 전시 디자인 제안
- Management: 디자인 제안 이후의 빠르고 정확한 실무 진행이 가능한
  종합 계획안 제안
- R&R: 업무 범위 및 내용의 변화에 대응하기 위한 효율적이고 효과적인
  조직 및 업무 분장 시스템 구축

STRATEGY:
- 선도성(ATTRACTOR & HERO): 이미지를 선점해 파급력을 높인다.
  첫 만남의 위치와 연출 상징성을 통해 모든 메시지를 함축적으로 표현하는 공간.
- 단순성(STRUCTURE): 쉽고 명쾌한 메시지를 전달한다.
  단순화된 전체 이미지를 통해 명확한 주제를 나타내고,
  디테일에서는 체험적 다양성을 품는 공간.
- 의외성(EXPERIENCE): 기대를 넘어 놀라움을 주다.
  자극을 줄 수 있는 감동과 경험의 몰입이 연출되어
  쾌감과 행복감을 가져갈 수 있는 공간.
- 화제성(FLOOR ZONING): 스토리를 담아낸다.
  공간의 연결고리가 만들어지면서 비즈니스 가치관과
  고객 가치관이 만나고 연관되는 공간.

SOLUTION:
- Focused Products: 본질을 경험하는 제품 중심의 경험 / 프리미엄 제품을 강조한 제품라인
- Flexible Space: 트렌드를 반영하는 부스구조 디자인 / 다양성과 독창성을 담아내는 컬러 적용
- LG다움: LG브랜드 지향점을 반영한 통일성과 정체성 / 젊고 따뜻하며 혁신적인 즐거운 경험 제공

[클라이언트 브리프]
클라이언트: 국내 중견 건설사 A사
전시명: 2026 대한민국 건축·인테리어 박람회
컨셉 키워드: 지속가능한 주거, 공간의 질, 기술과 자연의 공존
타겟: 30~50대 주택 구매자 및 인테리어 관심층
부스 규모: 약 300㎡
강조 포인트: 브랜드 리뉴얼 첫 공개 / 친환경 신소재 라인업 출시
```

**Step 2 — 결과 확인 (3분)**
결과가 나오면 다음 세 가지를 확인합니다.
첫째, PROLOGUE가 역설적 선언("X는 Y가 아니라 Z다" 형식)으로 시작하는가.<br>둘째, STRATEGY 전략명이 영어 2\~3단어로 붙었는가.<br>셋째, 추상적 개념이 공간 요소와 연결됐는가. ("단순성"이라고만 적은 게 아니라, 헤더 구조나 동선 설계 같은 구체적 실행 방식이 언급됐는가.)
세 가지 중 하나라도 미흡하면 Step 3에서 체이닝으로 수정합니다.
---
**Step 3 — 체이닝으로 개선 (7분)**
같은 대화창에서 아래 중 하나를 입력합니다. 처음 결과가 70% 수준이면 충분합니다. 나머지 30%는 체이닝으로 채웁니다.
**Prologue 감성이 약할 때:**
```plain text
PROLOGUE 섹션을 더 철학적인 문체로 다시 써줘.
"공간은 X가 아니라 Y다"로 시작하고, 건설사의 주거 공간 철학이
기준 전시 프로젝트 Golden Sample처럼 깊이 있게 담기도록 해줘.
```
**Strategy가 너무 추상적일 때:**
```plain text
STRATEGY 섹션의 각 전략을 전시 공간의 구체적인 실행 요소와
연결해서 다시 써줘. 예: "선도성"이라면 입구 어트랙터 구조,
조명 연출, 첫 시야각까지 언급하는 방식으로.
```
**전체 문체가 Golden Sample과 다를 때:**
```plain text
K에 넣어준 기준 전시 프로젝트 제안서 문체를 더 가깝게 따라줘.
문장이 짧고 선언적인 리듬, 마지막 줄에서 핵심을 한 문장으로
정리하는 방식을 유지해줘.
```
---
**Step 4 — 실제 프로젝트로 적용 (나머지 시간)**
연습용 브리프 대신 현재 진행 중인 실제 프로젝트 정보를 넣어서 다시 해봅니다.
```plain text
[클라이언트 브리프] 자리에 아래를 채워 넣으세요.

클라이언트:
전시명:
컨셉 키워드:
타겟:
부스 규모:
강조 포인트:
```
프로젝트 정보가 실제일수록 결과가 즉시 활용 가능한 수준으로 나옵니다.
