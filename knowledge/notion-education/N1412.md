# 실습 1. 처방 선택 — 다시 자르고, 다시 적재한다

정리일: 2026-10-08 · 교육 에셋 N1412

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
문서 페이지에 청킹 전략 선택 기능을 추가하고, 내가 고른 전략으로 재적재합니다.
## 진행 단계
1. **초기화** — 작업 시작 전 터미널 A의 Claude Code에서 `/clear` 실행
2. **프롬프트 입력 후 서버 재시작**
- 입력할 내용:
```plain text
문서 처리 페이지의 청킹을 업그레이드해 주세요. 요구사항입니다.

1. 페이지에 청킹 전략 선택 메뉴를 추가해 주세요. 세 가지입니다.
   - 고정 길이: 500자 단위, 오버랩 50자 (기존 방식)
   - 구조 경계 우선: "제N조" 형태의 조항 표기나 제목 줄을
     경계로 삼아 자르고, 한 덩어리가 800자를 넘으면
     800자 상한으로 나눕니다. 겹침은 100자입니다.
   - 문단 경계: 빈 줄 기준의 문단을 최소 단위로 삼아
     문단 중간을 자르지 않습니다. 짧은 문단은 500자 내외까지
     묶고, 겹침은 100자입니다.

2. 전략을 고르고 문서를 업로드하면 그 전략으로 청킹해
   청크 카드 목록을 보여 줍니다. 카드에는 적용된 전략 이름도
   표시해 주세요.

3. [벡터DB에 적재] 버튼은 기존 적재 내용을 비우고
   새 청크로 다시 채우게 해 주세요. 적재 현황에는
   적용 전략 이름이 함께 보이면 됩니다.

4. 서버 로그에 선택된 전략과 청크 개수가 출력되게 해 주세요.
```
1. **처방 고르기** — Ch2에서 메모한 손상 조각의 자리와 원인을 보고 세 전략 중 하나를 고르고 이유를 한 줄로 적기
2. **\[예측\]** — 다시 자르면 손상 조각이 온전해질지, 청크 개수가 늘지 줄지, 그대로일 손상은 무엇일지 적기
3. **재업로드·재적재** — 고른 전략으로 문서를 다시 업로드하고 적재
- 정상 결과: 손상 조각이 있던 자리의 카드를 펼쳐 예측과 실제를 대조
4. **재검색** — Ch2의 준비 질문 A와 B를 /search에서 같은 K로 다시 검색, 1위 청크가 달라졌는지 확인
5. **비교** — 옆자리와 결과를 비교하며 무엇이 나아지고 무엇이 그대로인지 한 문장씩 말하기
## 막히는 지점
- 전략을 바꿔도 어떤 조각이 그대로 깨져 있음: 정상 관찰. 파싱 단계에서 무너진 내용(대표적으로 표)은 어떤 전략으로도 복구되지 않음
- 구조 경계 전략인데 조항 단위로 안 잘림: Claude Code에 "조항 경계 인식이 동작하는지 청크 몇 개를 예시로 점검해 주세요"라고 요청
- 재적재했는데 예전 청크가 나옴: "적재 전에 기존 데이터를 비우는지 확인해 주세요"라고 요청 후 다시 적재
- 청크 개수가 크게 줄어듦: 경계 단위가 커서 생기는 정상 변화. 카드 내용이 온전한지로 판단
