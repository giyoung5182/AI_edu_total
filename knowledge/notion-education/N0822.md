## 핵심 개념 — AI와 엑셀 수식
### 자연어 요청이 수식이 되는 원리
**기존 방식:** "매장별 추가발주 건수를 세고 싶다" <br>→ COUNTIFS 함수 문법 검색 → 인수 순서 파악 → 범위 지정 → 오류 수정
**AI 활용 방식: **"매장별 추가발주 건수 세는 수식 만들어줘" <br>→ Claude가 구글 시트 문법으로 수식 생성 → 복사·붙여넣기
AI가 이것을 할 수 있는 이유는 수식 작성법을 학습했기 때문이 아니라, <br>**수십억 개의 코드·문서 데이터를 학습하면서 "이런 요청에는 이런 수식이 대응된다"는 패턴을 파악**했기 때문입니다.

### 수식 요청 전 데이터 구조 파악이 왜 중요한가
틀린 수식이 나오는 가장 큰 원인은 데이터 구조를 AI에게 정확히 설명하지 않아서입니다. AI는 파일을 직접 볼 수 없습니다. 우리가 설명한 내용만으로 수식을 만듭니다.
```plain text
나쁜 요청:
"누락 건수 세는 수식 만들어줘"
→ AI가 임의로 열 위치 가정 → 잘못된 수식

좋은 요청:
"A열: 매장명, E열: 누락(●), 데이터 2행부터 200행까지.
E열에 ●이 있는 행 수를 세는 COUNTIF 수식 만들어줘"
→ 정확한 수식 생성
```
### AI가 만든 수식을 믿어도 되는가
AI가 만든 수식은 **정답이 아닌 초안**입니다. 대부분의 경우 맞지만, 다음 세 가지를 항상 검증해야 합니다.
1. **행 수 확인**: "분석에 사용된 행이 몇 개야?" → 데이터 범위가 맞는지
2. **샘플 검증**: 눈에 보이는 데이터 2\~3개를 손으로 직접 대조
3. **오류 시 원인 질문**: 오류 메시지를 그대로 Claude에 주면 수정해줌
이 검증 습관이 AI 수식을 안전하게 쓰는 방법입니다.

### 데이터 분석 사고법 — 숫자에서 인사이트를 뽑는 과정
AI가 수식을 만들어주더라도, "어떤 질문을 던져야 하는가"는 사람이 결정합니다. 이것이 데이터 분석 사고법입니다.
좋은 데이터 분석 질문의 3단계:
```plain text
1단계. 현황 파악 (What)
   "지금 어떤 상태인가?"
   예: "오늘 업무보고에서 추가발주가 총 몇 건인가?"

2단계. 원인 분석 (Why)
   "왜 그런 상태인가?"
   예: "어느 매장에서 추가발주가 가장 많은가?"

3단계. 의사결정 지원 (So What)
   "그래서 어떻게 할 것인가?"
   예: "추가발주 빈도가 높은 매장에 적정 발주량을 재검토해야 하는가?"
```
AI는 1단계(현황 파악)를 빠르게 처리해줍니다. 2\~3단계로 갈수록 사람의 판단이 필요합니다. 오늘 실습 4는 AI가 1단계를 처리하는 방법을 배우는 것입니다.
### 반복 정제(Iteration) — 첫 결과가 완벽하지 않아도 된다
수식이나 분석 결과가 첫 시도에 완벽하게 나오지 않는 경우가 많습니다. <br>이것은 실패가 아닙니다. AI 활용의 정상적인 과정입니다.
**반복 정제의 사이클:**
```plain text
① 프롬프트 작성 → 결과 확인
② 결과의 어떤 부분이 문제인지 파악
③ 그 부분만 구체적으로 수정 요청
④ 다시 확인 → 만족할 때까지 반복
```
**교육기관 실습 4 적용:**
```plain text
1차: "누락 건수 세는 수식 만들어줘"
     → 결과: =COUNTIF(E:E,"●") — 작동은 하지만 범위가 너무 넓음

2차: "2행부터 200행만 보는 수식으로 수정해줘"
     → 결과: =COUNTIF(E2:E200,"●") — 개선됨

3차: "결과가 0으로 나와. 왜 그런지 설명해줘"
     → 원인 파악 후 수정
```
처음부터 완벽한 프롬프트를 쓰려고 하지 마세요. 빠르게 초안을 받고, 구체적으로 수정하는 것이 더 효율적입니다.

## 수식 요청 전 — 데이터 구조 먼저 파악하기
수식을 잘못 요청하는 가장 큰 이유는 **데이터 구조를 AI에게 정확히 설명하지 않아서**입니다.<br>새 데이터를 받으면 수식 요청 전에 아래 프롬프트로 먼저 파악합니다.
```plain text
이 데이터의 구조를 파악해줘.
- 열 이름과 각 열에 어떤 데이터가 들어있는지
- 전체 행 수
- 결측값(빈칸)이 있는 열과 개수
- 날짜 형식이 있으면 범위도 알려줘
```
**교육기관 업무보고 데이터에 적용하면:**
```plain text
실습4_업무보고_연습.xlsx를 보고 있어.
- A열: 매장명 / B열: 품명 / C열: 수량 / D열: 추가(●) / E열: 누락(●)
- F열: 반품(●) / G열: 수정(●) / H열: 취소(●) / I열: 비고
- 데이터는 2행부터 시작, 약 12개 행

이 구조에서 E열(누락)에 ●이 있는 행 수를 세는 COUNTIF 수식을 만들어줘.
```
> **구조를 먼저 알려줄수록 수식이 정확합니다.**<br>열 이름 + 데이터 시작 행 + 범위 — 이 세 가지만 있으면 Claude가 바로 정확한 수식을 만들어줍니다.

## 실습 4-C-1. 수식 결과 검증 — 3가지 체크포인트
수식을 붙여넣고 결과가 나왔을 때, 아래 세 가지를 반드시 확인합니다.<br>이것은 ADA 전문 교육에서 강조하는 **데이터 검증 원칙**과 동일합니다.





검증 항목

확인 방법

왜 중요한가




**① 행 수 일치**

"분석에 사용된 행이 몇 개야?" Claude에 질문

결측값 처리 후 행이 줄었을 수 있음




**② 결측값 처리**

"빈칸을 어떻게 처리했어?" 질문

빈칸 포함 여부에 따라 결과가 달라짐




**③ 샘플 검증**

눈에 보이는 데이터 1\~2개 손으로 대조

수식이 의도대로 작동하는지 확인


**교육기관 업무보고 시트 검증 예시:**
```plain text
방금 만든 수식으로 누락 건수가 2개 나왔어.
실제로 E열을 눈으로 보니 도곡 무, 도곡 콩나물에 ● 2개가 맞아.
수식이 맞게 작동하는지 확인해줘.
```
**수식 결과가 이상할 때:**
```plain text
누락 건수가 0으로 나왔어. E열에 실제로 ●이 있는데 왜 그런지 설명하고 수정해줘.

[현재 수식] =COUNTIF(E2:E200,"●")
[실제 데이터] E9, E10에 ● 있음
```
## 실습 4-D. 오류 발생 시 수정 요청
오류가 나면 그대로 Claude에게 주세요.
### 케이스 1: 결과가 0으로 나올 때
```plain text
이 수식 넣었는데 0이 나왔어.
E열에 실제로 ●이 2개 있는데 왜 0인지 설명하고 수정해줘.

[넣은 수식]
=COUNTIF(E2:E200,"●")

[현재 상황]
E열 일부 셀에 ●이 있는 것 확인됨
```
### 케이스 2: #REF! 오류
```plain text
아래 수식에서 #REF! 오류가 났어.
원인 설명하고 수정해줘.

[수식]
=QUERY(A2:I200,"SELECT A, COUNT(A) WHERE D='●' GROUP BY A ORDER BY COUNT(A) DESC")

[오류] #REF!
```
### 케이스 3: 수식 검증 요청
```plain text
이 수식이 내가 원하는 대로 작동하는지 확인해줘.

[수식] =COUNTIFS(A2:A200,"압구정",D2:D200,"●")

[내가 원하는 것]
A열="압구정"이고 D열="●"인 행의 수

[테스트 데이터]
A7=압구정, D7=● → 포함 ✅
A8=압구정, D8=(빈칸) → 미포함 ❌
A9=발산, D9=● → 미포함 ❌

맞는지 확인하고 더 좋은 방법 있으면 알려줘.
```
> **오류를 만나는 것도 실습입니다:**<br>AI가 틀린 수식을 줄 수 있습니다.<br>오류 메시지를 그대로 주면 고쳐줍니다.<br>이것이 AI와 협업하는 실제 방식입니다.
