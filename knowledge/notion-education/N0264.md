# 도구의 경계를 확인하는 방법
일반 질문으로는 한계가 드러나지 않습니다.
「너 최신 정보 알아?」라고 물으면 「제 지식에는 한계가 있습니다」 정도의 원론적 답변만 나옵니다. 무엇을 모르는지 특정되지 않아 다음 판단으로 이어지지 않습니다.
**구체 사안을 넣고 추정을 금지**하면 30초 만에 갈립니다.
```plain text
다음 세 가지를 알려 주세요.

1. 당신이 학습한 정보는 언제까지의 것입니까?

2. 아래 사안에 대해 알고 있는 내용이 있습니까?
   - KSGA-025-15 분산에너지자원 계통 지원 기능 요구사항
   - SEL-3555-2 RTAC의 최신 펌웨어 버전
   - 2026년 개정 REC 가중치

3. 모르는 항목은 「모름」으로만 답하고,
   추정해서 설명하지 마세요.

답변 형식
| 항목 | 알고 있음 / 모름 | 근거 시점 |
```
**추정 금지 한 줄이 핵심입니다.** 이 줄이 없으면 모르는 것도 설명하려 듭니다.

## C · 맥락에는 네 가지를 적습니다
수신처 · 목적 · 환경 · 분량과 형식입니다.
```plain text
[C]
수신처는 제조사 기술담당자입니다.
목적은 연동 가능 여부를 판단하기 위함입니다.
현장에 A사·B사 PCS가 혼재돼 있습니다.
분량은 표 중심, A4 1장입니다.
```
## T · 단계로 쪼개서
번호를 매기고 **단계 사이에 의존관계**를 만듭니다.
```plain text
[T]
1. 문서에서 통신 방식을 찾아 적으세요.
2. 제어 관련 항목을 항목 / 값 / 단위 / 문서 위치 표로 정리하세요.
3. 2번 표에서 값이 범위로 적힌 항목만 따로 모으세요.
4. 문서에 없어 제조사에 문의해야 할 항목을 정리하세요.
```
3번이 2번 결과를 재료로 씁니다. 이렇게 하면 결과의 일관성이 올라갑니다.
## C · 제약이 가장 중요합니다

**이 다섯 줄은 모든 기술 프롬프트에 넣으시면 됩니다.**

```plain text
[C]
- 제가 제공한 문서에 없는 값은 절대 만들지 마세요.
- 문서에 없는 항목은 [확인 필요]로 표시하세요.
- 원문의 단위를 그대로 쓰고 변환하지 마세요.
- 일반적인 기술 지식으로 빈칸을 채우지 마세요.
- 정보가 부족하면 추측하지 말고 먼저 물어보세요.
```
**단위 고정이 개발 계열의 핵심입니다.** 응답시간 100ms가 100s로 바뀌면 설계 전체가 틀어집니다.
