### 2-1. Gamma의 내부 작동 구조 — 왜 "카드"로 이해해야 하는가
```plain text
일반적인 오해: "Gamma에 주제를 넣으면 통짜로 슬라이드가 나온다"

실제 구조: Gamma는 입력된 텍스트를 논리 단위로 쪼개서
'카드' 각각에 독립적으로 콘텐츠·이미지·레이아웃을 할당합니다.

이 구조를 알아야 하는 이유:
- 카드 하나에 정보가 몰리면 AI가 자동으로 축약하거나 생략함
- "한 카드 = 한 개념"이 되도록 원본 텍스트를 미리 구조화해야
  AI가 자의적으로 쪼개는 것을 막을 수 있음
```
[원본 이미지 제외]

**파워유저 원칙 — 입력 전에 카드 경계를 미리 설계하라**
```plain text
❌ 초보자 방식: 긴 텍스트를 통째로 붙여넣고 "슬라이드로 만들어줘"
   → AI가 임의로 잘라서 논리 흐름이 원본과 달라짐

✅ 숙련자 방식: 붙여넣기 전에 마크다운 헤딩(#, ##)으로
   카드 경계를 미리 표시 → 각 ## 헤딩이 카드 1장에 대응
   → "AI가 카드 분할을 결정" 옵션을 꺼도 원하는 카드 수·순서 유지

실전 예시:

  ## 조기 수렴 문제란
  ## R.O.P.E.+K를 이미지에 적용하기
  ## 체이닝 4단계
  → 이렇게 넣으면 정확히 3개 카드로 분리됨
```

### 2-3. 이미지 모델 선택 전략 — 목적별로 다르게
```plain text
Gamma는 Midjourney, Nano Banana(Gemini), DALL-E, Leonardo 등

  → 사실적이고 부드러운 인물 표현에 강점

  → 임팩트 있는 비주얼, 단 세밀한 텍스트 지시는 약함

→ 슬라이드 전체를 하나의 모델로 통일하지 말고
   목적에 따라 카드별로 모델을 다르게 선택하는 것이
   전문가 프레젠테이션과 초보자 프레젠테이션의 차이입니다.
```

### 2-4. "AI 티 나는 슬라이드"를 피하는 법
```plain text
AI가 만든 슬라이드 특유의 느낌이 있습니다.
이걸 인지하고 의도적으로 피해야 전문성이 느껴집니다.

AI 티가 나는 패턴:
- 모든 슬라이드가 정확히 같은 레이아웃 반복
- 지나치게 대칭적인 구도
- 과도하게 낙관적이고 일반적인 문구
  ("AI로 미래를 바꾸세요!" 같은 상투적 표현)

피하는 방법:
1. 테마 적용 후 반드시 2~3개 슬라이드는 레이아웃 수동 변경
2. Magic Write류 문구 생성 후 이사님 특유의 말투로 1회 수정
3. AI 편집 에이전트에게 "이 슬라이드는 다른 레이아웃으로
   변형해줘, 나머지와 톤은 유지하되 배치를 다르게"라고
   명시적으로 다양성을 요구
```

### 3-1. 기술적 한계부터 정확히 알기 — 실패 예방
```plain text
소스 제한:
- 소스는 최대 50개까지 업로드 가능
- 각 소스는 최대 약 50만 단어(영문 기준) 또는 200MB까지

흔히 발생하는 실패 패턴:
- 스캔 품질 낮은 PDF → 텍스트 인식 실패 (사전에 텍스트 PDF로
  변환하거나, 스캔본이라면 OCR 처리 후 업로드)
- 오디오 요약 생성 중 원본 오디오 품질이 나쁘면 가져오기 자체가
  실패할 수 있음
- 앱 버전과 웹 버전 간 기능 차이가 있어, 복잡한 작업은
  웹 버전(notebooklm.google.com)에서 하는 것이 안전

★ 파워유저 원칙: 소스를 넣기 전에 "이 자료가 기계가 읽기
  좋은 형태인가"를 먼저 확인하는 것이 결과 품질의 8할을 결정
```

### 3-2. 소스 아키텍처 — 뭘 넣느냐가 결과의 8할을 결정한다
**하이브리드 소스 구성 — 고밀도 자료 + 저밀도 자료를 섞기**


```plain text
초보자 실수: 모든 자료를 무차별적으로 업로드

숙련자 원칙: 소스를 두 층으로 구분해서 구성

① 고신호(High-signal) 소스 — 핵심 근거가 되는 자료
   예: 0~3회차 교안 원본, 검증된 통계, 공식 문서

② 저신호(Low-signal) 소스 — 맥락·배경 참고용
   예: 관련 뉴스 기사, 블로그 글, 참고용 유튜브 영상

→ 이렇게 구분해두고 질문할 때 "고신호 소스를 우선하고,
   저신호는 배경 설명에만 참고해줘"라고 지정하면
   답변의 정확도가 크게 올라갑니다.
```


[원본 이미지 제외]


**소스 품질 체크리스트 — 넣기 전에 확인**
```plain text
□ 텍스트가 선택·복사 가능한 형태인가 (이미지로만 된 PDF가 아닌가)
□ 이 문서가 최신 정보를 담고 있는가, 오래된 버전은 아닌가
□ 출처가 명확한가 (근거를 물었을 때 답할 수 있는 자료인가)
□ 서로 모순되는 내용을 담은 소스가 섞여 있지 않은가
  (섞여 있다면 어느 쪽이 우선인지 미리 프롬프트에 명시)
```
**잘못된 소스 패턴 — 흔한 실수 3가지**
```plain text
① "일단 다 넣기" — 관련성 낮은 자료까지 전부 업로드
   → 응답이 산만해지고, 엉뚱한 저신호 자료가 답변에 섞임

② 버전 관리 실패 — 같은 교안의 구버전과 신버전을 동시에 업로드
   → NotebookLM이 어느 쪽이 최신인지 모르고 혼합해서 답변

③ 단일 소스 의존 — 소스 1개만 넣고 "다각도로 분석해줘" 요청
   → 애초에 다각도로 볼 자료 자체가 없어서 불가능한 요청
```
**Note를 Source로 승격하기 — 숨겨진 고급 기능**
```plain text
NotebookLM에서 대화하다가 나온 좋은 답변이나
직접 작성한 메모(Note)는 "소스로 승격"할 수 있습니다.

활용법:
1. NotebookLM과 대화하며 강의 아이디어를 다듬음
2. 마음에 드는 정리 내용을 Note로 저장
3. 그 Note를 다시 Source로 승격
4. 이후 질문에서 그 Note도 근거 자료로 활용됨

→ "대화 → 정리 → 소스화"의 반복으로
   나만의 지식 베이스가 스스로 진화하는 구조를 만들 수 있습니다.
   이게 일반 사용자와 파워유저의 가장 큰 차이입니다.
```

### 3-3. 프롬프트 엔지니어링 심화 — NotebookLM 전용 프레임
**5대 프레임 — 맥락 중심 프롬프트 작성법**
```plain text
NotebookLM은 일반 AI와 달리 "내가 준 자료 안에서만" 답하므로
프롬프트에 반드시 아래 요소를 포함해야 정확도가 올라갑니다.

① 근거 요구: "각 문장 옆에 출처가 된 소스 이름을 표시해줘"
② 관점 지정: "너는 지금부터 AI 강사 교육 전문가야"
③ 대상 지정: "초보 강사가 이해할 수 있는 눈높이로"
④ 형식 지정: "표로 정리해줘" / "5문장 이내로"
⑤ 불확실성 처리: "소스에 없는 내용은 추측하지 말고
   '자료에 없음'이라고 표시해줘"
```
**체인 프롬프팅 — 한 번에 묻지 않고 단계적으로 심화**
```plain text
1턴: "이 노트북의 소스를 바탕으로 핵심 내용을 5문장으로 요약해줘.
      각 문장 옆에 근거 소스 이름을 표시해줘."
2턴: "방금 요약한 내용 중에서, 초보 강사가 가장 헷갈려할
      부분이 어디일지 짚어줘."
3턴: "그 헷갈리는 부분을 설명하는 좋은 비유를 3개 제안해줘.
      단, 소스에 이미 있는 비유가 있다면 그것도 함께 알려줘."

→ 이전 답변 위에 다음 질문을 쌓아가는 방식이
   한 번에 완벽한 답을 요구하는 것보다 훨씬 깊이 있는 결과를 만듭니다.
```
**메타 프롬프트 — NotebookLM에게 질문을 만들어달라고 하기**
```plain text
"이 자료를 제대로 이해하려면 내가 먼저 어떤 질문을
 스스로에게 던져봐야 할지, 좋은 질문 5개를 만들어줘."

→ 내가 뭘 물어야 할지 모를 때, AI에게 질문 설계를 맡기는 기법
→ 특히 방대한 자료(87장 PPT 등)를 처음 넣었을 때 유용
```
**Self-Critique 루프 — AI가 자기 답변을 스스로 검증**
```plain text
1턴: (질문에 대한 답변을 받은 후)
2턴: "방금 네 답변에서 소스 내용과 다르게 말했거나,
      확실하지 않은데 확정적으로 말한 부분이 있는지
      스스로 다시 검토해줘."

→ 환각 가능성을 낮추는 2단계 검증 습관
→ 특히 강의 자료로 쓸 내용은 이 검증을 반드시 거칠 것
```
**Few-Shot 패턴 심화 — 원하는 답변 형태를 예시로 고정**
```plain text
"아래 형식으로 답해줘.

예시:
질문: 할루시네이션이 뭔가요?
답변: [정의] AI가 사실이 아닌 걸 사실처럼 말하는 현상
      [원인] 다음 단어를 확률로 예측하기 때문
      [대응] 중요한 정보는 재확인 필요

이제 이 형식으로 답해줘: 컨텍스트 윈도우가 뭔가요?"

→ NotebookLM도 예시를 주면 그 구조를 그대로 따라갑니다.
   매번 형식을 설명하는 대신 예시 하나로 고정하는 것이 효율적.
```
**부정 프롬프트 — 하지 말아야 할 것을 명시**
```plain text
"답변할 때 다음은 하지 마:
 - 소스에 없는 통계 수치를 지어내지 마
 - '아마도', '것 같습니다' 같은 애매한 표현 대신
   확실한 것과 불확실한 것을 명확히 구분해서 말해"
```
**컨텍스트 위치와 응답 차이 — 어디에 넣느냐도 영향을 준다**
```plain text
같은 정보라도 소스 문서의 어느 위치에 있느냐에 따라
AI가 그 정보를 얼마나 중요하게 반영하는지 달라질 수 있습니다.

실전 팁: 정말 중요한 핵심 정보는 문서의 맨 앞이나
소제목으로 명확히 구분해서 배치하면 AI가 더 안정적으로 인식합니다.
문서 중간에 파묻힌 중요 정보는 가끔 응답에서 누락될 수 있습니다.
```
**프롬프트 자산 관리 — 잘 통한 질문은 저장해서 재사용**
```plain text
NotebookLM에서 좋은 결과를 낸 프롬프트는 별도로
프롬프트 라이브러리(2회차에서 만든 것)에 추가해서
다음 노트북에서도 그대로 재사용할 수 있게 관리하세요.

→ 매번 새로 프롬프트를 고민하지 않고, 검증된 프레임을
   반복 사용하는 것이 시간을 가장 크게 절약하는 방법
```

### 3-6. 타 AI 도구와의 역할 분담 — NotebookLM만으로 끝내지 않기
```plain text
NotebookLM: 정확성·근거 기반 정리 (Gemini 기반, RAG 구조)
Claude: 긴 글의 자연스러운 문체·정교한 논리 전개

Perplexity: 최신 실시간 정보 보완

파워유저 워크플로우:
NotebookLM(근거 정리) → Claude(글 다듬기) → Gamma(슬라이드화)

→ 한 도구로 모든 걸 끝내려 하지 않고,
   각 도구의 강점만 릴레이로 활용하는 것이 핵심입니다.
```

## PART 6. 콘텐츠 기획력 — OSMU 전략 (45분)
> 도구를 아무리 정교하게 다뤄도, 기획 없이 만들면 산만한 결과물이 나옵니다. 이 파트는 콘텐츠 산업에서 검증된 **OSMU(One Source Multi Use)** 전략을 강사 콘텐츠에 적용합니다.
---
### 6-1. OSMU란 무엇인가 — 왜 강사에게도 적용되는가
```plain text
OSMU(One Source Multi Use) = 하나의 원천 콘텐츠를
다양한 형태로 재가공해서 여러 채널에서 활용하는 전략

원래는 콘텐츠 산업(웹툰→애니메이션→영화→게임)에서
쓰이던 개념이지만, 핵심 원리는 그대로 강사 콘텐츠에 적용됩니다.

★ 핵심 원칙: 같은 콘텐츠를 복제해서 여기저기 뿌리는 게 아니라,
   원천의 핵심 메시지는 유지한 채 각 채널의 특성에 맞게
   다시 설계하는 것입니다.

❌ OSMU가 아닌 것: 같은 이미지·같은 문구를 모든 채널에 복붙
✅ OSMU: 같은 메시지를, 카카오톡용/인스타용/강의 자료용으로
        각각 그 채널에 맞는 형태로 다시 만드는 것
```

---
### 6-2. 하나의 강의 회차에서 몇 개의 콘텐츠가 나올 수 있는가
```plain text
원천 콘텐츠: 3회차 "이미지 제작법 심화" 강의 1회

OSMU 확장 예시:

① 강의 교안 원본 → NotebookLM 소스로 저장 (지식 자산화)
② 교안 핵심 요약 → Gamma 발표 슬라이드
③ 발표 슬라이드 핵심 1장 → Canva 인스타그램 카드뉴스
④ 카드뉴스 문구 → 카카오톡 공지용 짧은 텍스트 (Magic Switch)
⑤ 강의 중 나온 좋은 비유 3개 → 다음 강의 도입부 스토리텔링 소재
⑥ 강의 녹음 또는 교안 전체 → NotebookLM 오디오 오버뷰
   (수강생 복습용 팟캐스트)
⑦ 수강생 반응 좋았던 부분 → 다음 달 강의 소개 문구에 인용

→ 강의 1회 = 최소 5~7개의 파생 콘텐츠로 확장 가능
   이걸 매번 새로 기획하지 않고 "패턴화"하는 것이 핵심
```
---
### 6-3. 콘텐츠 기획의 출발점 — 목적 먼저, 도구는 나중

```plain text
2. 대상: 누가 볼 것인가?
3. 형식: 목적과 대상에 맞는 형식은?
```

### 6-4. 강사 개인 브랜드 — 콘텐츠 3층 구조
[원본 이미지 제외]
```plain text
① 신뢰층 (가장 자주) — "이 강사는 진짜다"
   현장 사진, 수강생 반응, 실제 강의 장면
   → 텍스트보다 사실 자체가 증거

② 전문성층 (중간 빈도) — "이 강사는 잘 안다"
   AI 개념 설명, 트렌드 해설, Before/After 시연

③ 초대층 (가장 드물게) — "이 강사에게 배우고 싶다"
   강의 모집, 후기 모음, 커리큘럼 소개
   → 앞의 두 층이 쌓인 뒤에 나와야 설득력이 생김

❌ 흔한 실수: 초대층만 반복해서 내보냄 → 피로감 → 신뢰 하락
✅ 올바른 비율: 신뢰층 5 : 전문성층 3 : 초대층 2
```

### 6-5. 콘텐츠 캘린더 — 꾸준함이 완벽함을 이긴다

```plain text
꾸준한 콘텐츠 여러 개를 내보내며 반응을 보고 조정하는 것이 낫습니다.

월간 콘텐츠 캘린더 예시:
주 1회 — 신뢰층: 강의 후기·현장 사진 (Canva 카드뉴스, 5분 제작)
월 2회 — 전문성층: AI 트렌드 해설 (NotebookLM 리서치 → Gamma)
월 1회 — 초대층: 신규 강의 모집 (Canva Bulk Create + Magic Switch)

→ 이 리듬이 3개월 이상 쌓이면 "이 강사는 항상 뭔가 하고 있다"는
   인상 자체가 신뢰가 됩니다.
```

**콘텐츠 기획 — OSMU**
```plain text

하나의 원천에서 5~7개 파생 콘텐츠로 확장하는 것이 기본값
```

**AI 트렌드 초심화**
```plain text
4단계 진화: 프롬프트 → 컨텍스트 → 하네스 → 루프 엔지니어링
좋은 루프의 조건: 검증 가능한 종료 조건 + 실제 도구 + 분리된 검증자
자기 검증의 함정: "만든 것과 검증하는 것을 분리하라"
가트너 하이프 사이클로 "거품인가 실체인가" 판별
신조어는 원문 확인 → 배경 파악 → 필요한 만큼만 소화
```
