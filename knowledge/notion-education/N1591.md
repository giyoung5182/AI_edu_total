지금 우리 손에는 완성된 부품 일곱 개가 있습니다.<br>챗봇, 적재기, 검색기, 채점기, 오케스트레이터,<br>팀 채팅방, 그리고 재난 대응 5인 팀.<br>전부 지시대로 만든 것들입니다.<br>이제 지시가 끝났습니다.

이번 세션에서 우리가 하는 일은 세 가지입니다.

3. 완성 기준 체크리스트로 진행 상황을 스스로 점검합니다.
> 💡 좋은 프로젝트의 기준은 크기가 아닙니다.<br>질문 하나가 들어가서, 팀이 협업하고, 근거 있는 결과가<br>나오는 한 사이클이 끝까지 도는 것.<br>작아도 완주하는 시스템이 크고 멈춘 시스템을 이깁니다.

### 미션 정의 워크시트 — 다섯 칸이 설계도다
만들 것을 정하는 데에도 절차가 있습니다.<br>아래 다섯 칸을 순서대로 채우면 설계가 끝납니다.
[원본 이미지 제외]
채우는 요령은 **데이터 → 도구 → 역할** 순서입니다.<br>②에서 데이터를 정하면, 데이터 성격이 도구를 정해 줍니다.<br>서술형 문서면 검색(부품 C), 표 형태면 조회와 계산,<br>최신 정보면 웹 검색입니다.<br>도구가 정해지면 ⑤의 팀 명단은 거의 자동으로 나옵니다.<br>도구 하나에 담당 하나, 종합할 라이터 하나,<br>검수할 채점 담당 하나입니다.
⑤의 역할 이름은 기능으로 짓습니다.<br>"검색 담당", "위치 담당"은 좋은 이름입니다.<br>"팀장", "대리", "기획자"는 하는 일이 안 보이는 이름입니다.

### 두 갈래 길 — 가이드 트랙과 자유 트랙
출발선은 두 개입니다. 어느 쪽이든 좋은 선택입니다.
**가이드 트랙** — 아래 두 예시 미션 중 하나를 그대로 만듭니다.<br>워크시트가 이미 채워져 있어 바로 구축에 들어갑니다.<br>예시대로 완주한 뒤 자기 변형을 얹는 것도 훌륭한 경로입니다.

\[예시 미션 1. 야외 행사 안전 브리핑 팀\]<br>① 해결할 일:   행사 장소와 날짜를 넣으면 안전 브리핑을 자동 생성<br>② 입력 자료:   재난·안전 문서(적재됨) + 대피소 CSV + 웹(기상 정보)<br>③ 원하는 출력: 행동요령 요약 + 근처 대피소 지도 + 당일 유의사항<br>체크리스트, 근거 표기 포함<br>④ 필요한 부품: A, C, F, G의 구성 재활용<br>⑤ 팀 명단:    오케스트레이터 / 검색 담당(문서) /<br>위치 담당(대피소·지도) / 웹 담당(기상) /<br>브리핑 라이터 / 채점 담당


\[예시 미션 2. 근거 있는 생존 가이드 출판 팀\]<br>① 해결할 일:   장마다 공식 문서 근거가 달린 생존 가이드 집필<br>② 입력 자료:   재난·안전 문서(적재됨)<br>③ 원하는 출력: 5개 장 가이드. 모든 수치·절차에 청크 근거 번호,<br>장별 채점 점수표 포함<br>④ 필요한 부품: C, D, E, F의 결합<br>⑤ 팀 명단:    오케스트레이터 / 검색 담당(장별 근거 수집) /<br>장 담당 집필 에이전트 5 / 채점 담당(장별 검수)

**자유 트랙** — 워크시트를 스스로 채운 사람이 갑니다.<br>소재가 필요하면 이런 질문이 도움이 됩니다.<br>"재난 말고, 내가 자주 찾아보는 문서가 있나?"<br>"우리 팀 채팅방에 담당을 하나 바꾼다면?"<br>인터넷에서 구한 소형 PDF(수십 페이지 이내)를 부품 B로 직접 적재해 재료로 쓰는 것도 허용됩니다.<br>소형 문서 적재는 몇 분이면 끝납니다.<br>단, 대용량 문서의 새 적재는 이번 시간 안에 끝나지 않으므로 계획에 넣지 않습니다.
🔐 자유 트랙에서 문서를 새로 구할 때의 규칙입니다.<br>공개된 문서만 사용합니다. 회사 자료, 개인정보가 담긴 문서는 쓰지 않습니다.<br>문서의 청크가 임베딩 과정에서 외부로 전송된다는 사실을 기억하면 판단이 쉽습니다.

### 기획서 프롬프트 — 워크시트를 지시로 바꾸기
워크시트가 채워졌으면 Claude Code에게 전달할 차례입니다.<br>다섯 칸을 그대로 옮겨 담는 틀이 있습니다.<br>빈칸을 채워 그대로 쓰면 됩니다.

새 프로젝트를 시작합니다. 기존 부품을 재조합해 주세요.
\[목표\] (①을 씁니다)<br>예: 행사 장소와 날짜를 입력하면 안전 브리핑을 자동 생성합니다.
\[입력 자료\] (②를 씁니다)<br>예: 적재된 벡터DB, data/shelters.csv, 웹 검색을 사용합니다.
\[결과물\] (③을 씁니다)<br>예: 행동요령 요약, 대피소 지도, 유의사항 체크리스트가<br>한 화면에 나오고 근거가 표기됩니다.
\[팀 구성\] (⑤를 씁니다)<br>예: 오케스트레이터(flash), 검색 담당(flash-lite), ...<br>협업 과정은 기존 팀 채팅방 방식으로 보여 주세요.
\[작업 방식\]<br>전체를 한 번에 만들지 말고, 다음 순서로 하나씩 만들어<br>각 단계가 동작하는 것을 저와 확인한 뒤 넘어가 주세요.<br>1단계: 입력 화면과 팀 뼈대<br>2단계: 담당 에이전트를 하나씩 합류<br>3단계: 최종 결과물 화면<br>무료 한도 보호용 호출 간 대기도 유지해 주세요.

\[작업 방식\] 부분이 완주의 비결입니다.<br>큰 지시 하나는 크게 실패하고, 작은 지시 여럿은 작게 실패합니다.<br>작은 실패는 로그 한 번 붙여넣으면 고쳐집니다.

### 막혔을 때의 기술
구축 중 막히는 것은 사고가 아니라 기본값입니다.<br>대처 순서를 정해 두면 막힘이 짧아집니다.
1. **로그부터 붙여넣기**: 창①의 오류 로그를 복사해<br>창②에 붙여넣고 "이 오류를 해결해 주세요"라고 요청합니다.<br>설명을 지어내는 것보다 로그 원문이 빠릅니다.
2. **대화가 꼬였으면 ****`/clear`**: 수정 요청이 서로 엉키기<br>시작하면 `/clear` 후 현재 상태와 목표를 새로 설명합니다.
3. **같은 오류가 세 번 반복되면 범위 축소**: 그 기능을 빼거나<br>단순한 형태로 바꿉니다. 예를 들어 지도가 계속 말썽이면<br>"지도 대신 대피소 목록을 글로 보여 주세요"로 바꿉니다.<br>기능을 빼는 결정은 후퇴가 아니라 설계입니다.
4. **10분 이상 혼자 막혀 있지 않기**: 손을 들어 강사를 부릅니다.

## 실습 안내
### 실습 1. 워크시트 작성과 트랙 선택
진행 순서

1. 미션 정의 워크시트 다섯 칸을 종이나 메모장에 적습니다.<br>① 해결할 일 → ② 입력 자료 → ③ 원하는 출력 →<br>④ 필요한 부품 → ⑤ 팀 명단 순서입니다.
2. 5분 안에 ①이 떠오르지 않으면 고민을 멈추고<br>가이드 트랙의 예시 미션 중 하나를 고릅니다.<br>빠른 선택이 좋은 선택입니다.
3. 작성한 워크시트를 강사에게 보여 확인을 받습니다.<br>확인 포인트는 두 가지입니다.
- ②의 자료가 지금 이 자리에서 확보 가능한가
- ③의 출력이 이번 시간 안에 나올 크기인가
4. 확인이 끝나면 구축을 시작합니다.

### 실습 2. 골격부터 구축
진행 순서

1. 창②(Claude Code)에서 /clear 를 실행합니다.
2. 기획서 프롬프트 틀에 워크시트 내용을 채워 입력합니다.
3. 1단계(입력 화면과 팀 뼈대)가 완성되면 반드시 실행해 봅니다.<br>동작을 확인한 뒤에만 2단계로 넘어갑니다.
4. 에이전트를 하나 합류시킬 때마다 채팅방에서<br>그 담당의 말풍선이 올라오는지 확인합니다.
5. 진행 중 막히면 "막혔을 때의 기술" 순서를 따릅니다.
6. 남은 시간의 절반이 지나면 기능 추가를 멈추고<br>지금까지 만든 것의 완주 확인으로 전환합니다.

⚠️ 시간 관리의 유일한 규칙: 남은 시간 절반 시점에<br>"더하기"를 멈추고 "다듬기"로 바꿉니다.<br>미완성 기능 셋보다 완주하는 기능 하나가 시연에서 강합니다.
---
### 실습 3. 완성 기준 점검과 시연 준비
진행 순서

1. 완성 기준 체크리스트를 점검합니다.<br>□ 입력 하나를 넣으면 개입 없이 결과까지 완주한다<br>□ 협업 과정이 채팅방(또는 화면)에 보인다<br>□ 결과물에 근거가 표기된다 (청크 번호, 데이터, 출처 중 해당하는 것)<br>□ 폭주 방지 장치(수정 횟수 제한 등)가 살아 있다
2. 세 항목 이상 통과하면 시연 리허설을 합니다.<br>질문 입력부터 결과까지 손을 떼고 한 번 돌려 봅니다.
3. 시연 대본을 세 문장으로 준비합니다.
- 우리 팀이 해결하는 일 (워크시트 ①)
- 팀 구성과 각자의 도구 (워크시트 ⑤)
- 지금 보여드릴 한 사이클
4. 통과하지 못한 항목이 있으면 그대로 둡니다.<br>시연에서 "여기까지 됐고, 이 부분이 남았습니다"라고<br>말하는 것도 완전한 발표입니다.

## 실습 확장 (선택)
일찍 완주한 팀을 위한 추가 조합입니다.
- **채점 리포트 붙이기**: 부품 D 방식으로 내 팀의 결과물을<br>자동 채점하는 화면을 추가합니다.
- **편집장 질문 추가**: 팀이 애매한 결정을 만나면<br>나에게 묻고 진행하게 만듭니다.
- **우회 경로 추가**: 재료가 없을 때 팀이 스스로<br>다른 경로로 전환하는 동작을 넣습니다.
- **두 번째 미션**: 예시 미션 중 안 만든 쪽에 도전합니다.
