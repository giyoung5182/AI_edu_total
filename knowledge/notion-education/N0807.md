## 이번 세션에서 할 일
나의 에이전트 팀까지 완성되었습니다.<br>그런데 이 모든 것이 담긴 노트북은 교육용 장비입니다.<br>반납하면 다음 교육의 다른 사람이 쓰게 됩니다.<br>만든 것은 가져가야 하고, 남긴 흔적은 지워야 합니다.
이번 세션은 그 두 가지를 정확하게 하는 시간입니다.<br>프로젝트를 다른 컴퓨터에서 되살릴 수 있는 형태로 백업하고,<br>이 노트북에서 계정과 키와 파일을 정리합니다.<br>마지막으로, 언젠가 이 서비스를 세상에 공개하고 싶어질 때를<br>위한 지도 한 장을 챙깁니다.
이번 세션에서 우리가 하는 일은 세 가지입니다.
1. 복원 안내서를 만들어 프로젝트를 백업하고, 개인 저장 공간으로 옮깁니다.
2. API 키 폐기, 로그아웃, 파일 삭제로 노트북을 정리합니다.
3. 배포가 무엇이고, 하려면 무엇이 필요한지 지도를 그려 둡니다.
> 💡 이번 세션의 핵심은 공용 장비를 떠나는 기술입니다.<br>백업 없이 지우면 결과물을 잃고, 지우지 않고 떠나면<br>내 키와 계정을 잃습니다. 순서가 전부입니다.<br>반드시 백업 → 검증 → 삭제의 순서로 갑니다.

### 무엇을 가져가고, 무엇을 버리는가
프로젝트 폴더 안의 파일은 세 부류로 나뉩니다.<br>부류마다 처분이 다릅니다.

\[가져간다\] ─ 다시 만들 수 없는 것<br>├── server.py, static/ 등 코드 전체   ← 우리가 지시해 만든 결과<br>├── CLAUDE.md                        ← 프로젝트 안내 파일<br>├── evals/                           ← 평가 질문 세트<br>└── (워크시트, 시연 대본 메모)
\[버린다\] ─ 언제든 다시 만들 수 있는 것<br>├── chroma_db/     ← 문서를 다시 적재하면 재생성됩니다<br>├── docs/          ← 공개 문서라 다시 내려받으면 됩니다<br>└── data/          ← 공공데이터라 다시 구하면 됩니다
\[가져가지 않고 파기한다\] ─ 비밀<br>└── .env           ← API 키. 백업에 넣지 않고, 키 자체를 폐기합니다

버리는 것들을 버려도 되는 이유는 재생성 가능성입니다.<br>벡터DB는 저장물이 아니라 가공물입니다.<br>원본 문서와 적재 코드가 있으면 언제든 다시 만들어집니다.<br>백업 용량도 크게 줄어듭니다.
.env를 백업에서 빼는 이유는 다릅니다.<br>비밀은 파일로 복사되어 다니는 순간부터 위험해집니다.<br>키는 가져가는 것이 아니라, 여기서 폐기하고<br>필요한 곳에서 새로 발급하는 것이 원칙입니다.
---
### 복원 가능성 — 백업의 진짜 기준
백업의 기준은 "파일을 챙겼다"가 아니라<br>"다른 컴퓨터에서 되살릴 수 있다"입니다.<br>코드만 달랑 있으면 석 달 뒤의 나는 이것을 못 살립니다.<br>무엇을 설치하고, 어떤 순서로 실행해야 하는지가 함께 있어야 합니다.
그 안내서를 쓰는 데 가장 적임인 작성자가 있습니다.<br>이 프로젝트를 처음부터 끝까지 만든 Claude Code입니다.<br>백업 전에 Claude Code에게 복원 안내서를 쓰게 합니다.<br>안내서에는 다음이 담깁니다.

RESTORE.md (복원 안내서)<br>├── 이 프로젝트가 무엇인지 한 문단 소개<br>├── 필요한 준비물 (WSL, Claude Code, 파이썬 패키지)<br>├── 새 API 키를 발급받아 .env를 만드는 방법<br>├── 문서를 내려받아 다시 적재하는 방법<br>└── 서버 실행 명령과 첫 확인 방법

이 파일이 백업에 들어가면, 새 컴퓨터에서 할 일은<br>압축을 풀고 안내서를 따라가는 것뿐입니다.<br>안내서의 내용이 막히면 그때도 방법이 있습니다.<br>새 컴퓨터의 Claude Code에게 안내서를 보여 주며 "이대로 복원해 주세요"라고 지시하면 됩니다.

### 흔적 정리 — 떠나기 전 세 가지
공용 장비를 떠날 때 남기면 안 되는 것은 세 가지입니다.
- **키**: 발급받은 API 키는 이 노트북의 .env에 있고, 발급 계정의 관리 화면에도 살아 있습니다.<br>파일 삭제만으로는 부족하고, 관리 화면에서 키 자체를 삭제(폐기)해야 완전합니다. 폐기된 키는 즉시 무효가 되어, 어딘가에 복사본이 남아 있어도 쓸 수 없습니다.
- **로그인**: Claude Code와 브라우저에 계정이 로그인되어 있습니다. 로그아웃하지 않으면 다음 사용자가<br>내 계정 권한을 그대로 쓸 수 있습니다.
- **파일**: 백업이 끝난 프로젝트 폴더는 통째로 지웁니다. 코드 자체에 비밀은 없지만, 남길 이유도 없습니다.
> 🔐 순서가 안전을 만듭니다.<br>백업을 만들고 → 열어서 검증하고 → 개인 공간으로 옮긴 것을<br>확인한 다음에만 → 폐기와 삭제를 시작합니다.<br>삭제 명령은 되돌릴 수 없습니다.

### 배포 — 언젠가 세상에 내놓고 싶다면
[원본 이미지 제외]
지금 우리 서비스는 localhost에서만 삽니다.<br>내 노트북에서만 열리고, 노트북을 끄면 죽습니다.<br>이 서비스를 인터넷 주소로 누구나 접속하게 만드는 일을<br>배포(Deployment)라고 부릅니다.
이 자리에서 배포까지 가지 않은 이유는 구조에 있습니다.<br>우리 서비스는 서버가 항상 켜져 있어야 하고,<br>벡터DB가 폴더째 노트북에 있으며, 키가 .env에 있습니다.<br>셋 다 "내 컴퓨터"에 묶여 있는 구조라,<br>배포하려면 셋 다 옮겨야 합니다.
[원본 이미지 제외]
언젠가 하게 된다면 순서는 이렇습니다.
1. 코드를 GitHub 같은 코드 보관 서비스에 올립니다.<br>저장소는 비공개(Private)가 기본값입니다.
2. 파이썬 서버(FastAPI)를 상시로 돌려 주는 호스팅 서비스에<br>저장소를 연결합니다. 무료 체험 등급을 둔 곳이 여럿 있습니다.
3. 벡터DB를 폴더형에서 클라우드형으로 바꿉니다.
4. API 키는 파일이 아니라 호스팅이 제공하는<br>환경 변수 저장소에 넣습니다.
5. 아무나 못 쓰게 접속 제한(로그인 등)을 붙입니다.
⚠️ 배포는 비용과 책임의 시작이기도 합니다.<br>사용자가 늘면 API 호출이 늘어 무료 한도를 넘고,<br>무료 등급의 약관(입력 데이터 학습 활용)이<br>서비스의 성격과 맞는지도 따져야 합니다.<br>회사 업무로 만든다면 이 검토는 담당 부서와 함께 합니다.

**Claude Code 프롬프트**
```plain text
프로젝트를 마무리하고 백업하려 합니다. 도와주세요.

1. RESTORE.md 파일을 만들어 주세요. 이 프로젝트를 처음 보는
   사람이 다른 컴퓨터에서 되살릴 수 있도록 다음을 담습니다.
   - 프로젝트 소개 한 문단과 주요 기능 목록
   - 필요한 준비물 (WSL, Claude Code, 파이썬 패키지 설치)
   - 새 API 키를 발급받아 .env를 만드는 방법
     (.env에 어떤 항목이 필요한지 이름만 적고, 값은 적지 마세요)
```

진행 순서

1. 창②에 위 프롬프트를 입력하고 진행합니다.
2. Claude Code가 보여 준 압축 파일 목록에서 두 가지를<br>확인합니다.
- RESTORE.md와 server.py가 들어 있다
- .env가 들어 있지 않다
3. 윈도우 파일 탐색기를 열고 주소창에 \\\\wsl\$ 를 입력합니다.<br>Ubuntu → home → 계정 폴더 → disaster-bot 순서로 들어가<br>backup-disaster-bot.zip 을 찾습니다.<br>\[스크린샷 자리: 탐색기에서 WSL 폴더 접근 / 확인일 2026-07-19\]
4. 압축 파일을 바탕화면으로 복사한 뒤, 한 번 열어서<br>RESTORE.md가 읽히는지 직접 확인합니다. 이것이 검증입니다.
5. 검증된 파일을 개인 소유의 공간으로 옮깁니다.<br>개인 이메일로 자신에게 보내기, 개인 클라우드, USB 중<br>편한 방법을 씁니다.
6. 옮긴 곳에서 파일이 열리는 것까지 확인해야 백업 완료입니다.

⚠️ 백업을 옮기는 곳은 반드시 개인 소유 공간이어야 합니다.<br>배부받은 교육용 계정의 드라이브는 안 됩니다.<br>그 계정은 반납 대상이라, 계정과 함께 백업도 잃게 됩니다.
**잘 안 될 때**
**Q. 탐색기에서 ****`\wsl$`**** 가 안 열림**
- **원인**: WSL 미실행
- **해결**: WSL 터미널을 하나 열어 둔 상태에서 다시 시도합니다
**Q. zip 명령이 없다는 오류**
- **원인**: 압축 도구 미설치
- **해결**: 창②에 오류를 붙여넣으면 설치부터 진행해 줍니다
**Q. 압축 파일이 너무 큼**
- **원인**: 제외 목록 미적용
- **해결**: 창②에 "chroma_db와 docs가 제외되었는지 확인해 주세요"라고 요청합니다
**Q. 개인 메일 첨부 용량 초과**
- **원인**: 파일 크기 제한
- **해결**: 개인 클라우드나 USB를 사용합니다

### 실습 2. 노트북 정리 — 폐기, 로그아웃, 삭제
백업의 이동과 검증이 끝났을 때만 시작합니다.
진행 순서

1. \[키 폐기\] 브라우저에서 Google AI Studio에 접속해<br>API 키 관리 화면을 엽니다. 발급했던 키를 삭제합니다.<br>\[스크린샷 자리: AI Studio 키 삭제 화면 / 확인일 2026-07-19\]<br>화면 구성은 바뀔 수 있습니다. "API Key" 메뉴에서<br>삭제(휴지통) 동작을 찾으면 됩니다.
2. \[키 폐기 확인\] 채팅 페이지에서 아무 질문이나 보내 봅니다.<br>답변이 실패하면(401/403 로그) 키가 죽은 것입니다.<br>이 실패는 이번만큼은 성공의 신호입니다.
3. \[Claude Code 로그아웃\] 창②에서 /logout 을 입력합니다.
4. \[브라우저 로그아웃\] 브라우저에서 배부받은 Google 계정을<br>로그아웃합니다. 브라우저에 저장된 비밀번호가 있는지<br>설정에서 확인하고, 있으면 삭제합니다.
5. \[서버 종료\] 창①에서 Ctrl+C 로 서버를 끕니다.
6. \[폴더 삭제\] 터미널에서 다음을 입력합니다.<br>cd \~ && rm -rf disaster-bot<br>이 명령은 프로젝트 폴더를 통째로, 복구 불가능하게<br>지웁니다. 백업 검증이 끝났을 때만 실행합니다.
7. \[최종 확인\] ls 를 입력해 disaster-bot 폴더가<br>사라졌는지 확인합니다.

🔐 정리 순서를 요약하면 이렇습니다.<br>키는 관리 화면에서 죽이고(파일 삭제만으로는 부족),<br>로그인은 도구와 브라우저 양쪽에서 끊고,<br>파일은 백업 검증 후에만 지웁니다.<br>회사의 공용 장비, PC방, 빌린 노트북 어디서든<br>이 세 가지는 같은 순서로 적용됩니다.
**잘 안 될 때**
**Q. 키를 지웠는데 챗봇이 계속 답함**
- **원인**: 다른 키 존재 또는 반영 지연
- **해결**: 키 관리 화면에 남은 키가 없는지 확인하고, 1\~2분 뒤 다시 시도합니다
**Q. ****`/logout`**** 이 목록에 없음**
- **원인**: 명령어 변경 가능성
- **해결**: `/help` 로 로그아웃 계열 명령을 찾습니다. 없으면 강사에게 알립니다
**Q. ****`rm`**** 명령이 무서움**
- **원인**: 정상적인 감각입니다
- **해결**: 백업 검증을 한 번 더 하고 실행합니다. 그래도 불안하면 강사와 함께 실행합니다

## 이번 실습 결과물
이번 세션을 마친 우리 손에는 다음이 있습니다.
- 복원 안내서(RESTORE.md)가 든 백업 파일, 개인 공간에 안착
- 키가 폐기되고 로그인이 끊기고 파일이 지워진 깨끗한 노트북
- 배포까지의 다섯 단계 지도
- 그리고 노트북 밖에 남는 것들 — 부품 일곱 개의 구조,<br>데이터에 맞는 도구를 고르는 눈, 실패를 설계하는 감각,<br>자연어로 시스템을 만들 수 있다는 확인
백업 파일 안의 구조입니다.
```plain text
backup-disaster-bot.zip
├── RESTORE.md          ← 복원 안내서 (다른 컴퓨터에서의 출발점)
├── CLAUDE.md
├── server.py
├── static/             ← 화면 전체
├── evals/              ← 평가 질문 세트
```
