- AI 답변은 반드시 약관 원문과 대조한 뒤 사용하십시오.

**시스템 프롬프트는 사람으로 치면 업무 인수인계서입니다.** 매번 설명하지 않아도 되도록 한 번 제대로 써서 저장해 둡니다.
>
[원본 이미지 제외]
프롬프트를 잘 써도, 같은 업무를 할 때마다 역할과 조건과 출력 형식을 매번 다시 설명해야 한다면 결국 안 쓰게 됩니다.
**Gems**를 쓰면 자주 쓰는 지시문과 참고 자료를 저장해두고, 항상 같은 조건에서 대화를 시작할 수 있습니다.
오늘은 단순히 한 번 답하고 끝나는 챗봇이 아니라, **필요한 정보를 먼저 확인하고 근거를 표시하며 답하는 Gem**을 만듭니다.
### 오늘의 결과물
> **약관 특약 비교 분석 매니저**
자사와 타사의 특약 비교 요청을 받으면, 무엇을 비교할지 먼저 확인한 뒤 조항 단위로 대조하고 원문 근거를 함께 제시하는 Gem
이런 질문에 답하게 됩니다.
```plain text
우리 암직접치료비와 타사 유사 특약을 비교해줘.
특히 보장에서 제외되는 암종에 차이가 있는지 확인해줘.
```
**이번 실습의 목표는 답변 하나를 빨리 받는 것이 아닙니다.** AI가 어떤 순서로 확인하고 무엇을 근거로 답해야 하는지를 설계하는 것이 목표입니다.

### 지식 자료를 넣는 세 가지 방식
[원본 이미지 제외]

**기기에서 파일 업로드** — 개정 주기가 긴 자료에 적합합니다. 업로드 후 원본을 수정해도 Gem 안의 자료는 자동으로 바뀌지 않습니다.
**Google Drive에서 추가** — 계속 갱신되는 자료에 적합합니다. Drive 원본의 변경 내용이 Gem에 반영됩니다. 계정 설정과 조직 권한에 따라 이용 가능 여부가 다릅니다.
노트북 LM(Gemini Notebook)으로 추가하기 — 대량의 자료를 업로드할 때, 계속 나만의 지식 base를 만들어두고 쓰고 싶을 때 좋습니다.
> 💡 **약관 자동 최신화는 되지 않습니다**
전 보험사 약관을 자동으로 수집하고 갱신하는 것은 크롤러와 서버가 필요한 개발 영역입니다. AI 도구로는 되지 않습니다.
대신 **비교 대상 약관만 직접 넣고, 개정되면 파일을 교체하는 방식**을 씁니다. 분기 1회 교체로 실무에서는 충분하며, 오히려 자료 범위가 좁을수록 AI가 헷갈리지 않아 정확합니다.
> Gem의 Instructions는 프로그램 코드처럼 동작을 완전히 고정하는 규칙이 아닙니다. AI가 원하는 순서로 답하도록 **유도하는 지시**이므로, 만든 뒤 여러 상황으로 테스트하고 보완해야 합니다.

## 3️⃣ 단계별 실습
### 1단계. 메타프롬프트로 지시문 설계하기
**메타프롬프트**는 프롬프트를 만들어달라고 요청하는 프롬프트입니다.
처음부터 긴 지시문을 직접 쓰는 대신, 만들고 싶은 Gem의 목적과 작동 방식을 설명하고 Gemini에게 초안을 설계하게 합니다.
[원본 이미지 제외]

Gemini **일반 채팅**에 아래를 입력합니다.
```plain text
나는 "건강보험 약관 비교 분석 매니저" Gem을 만들고 싶어.

이 Gem은 생명보험 지점장이 자사와 타사의 건강보험 약관을
비교할 때, 첨부된 약관 원문만을 근거로
정확한 차이를 알려주는 역할이야.

[비교 대상 자료 — 3사]
- 삼성 가족대표건강보험(2607) 무배당 약관 (자사, 생명보험)
- 한화생명 시그니처H보장보험 약관 (타사, 생명보험)
- 교육기관 New내돈내삼 4170 약관 (타사, 손해보험)

세 상품 모두 납입면제형이야.

[중요 — 생보와 손보는 구조가 다르다]
교육기관 05과 한화생명은 생명보험,
교육기관는 손해보험이야.

담보 구성과 용어 체계가 달라서 같은 이름의 특약이
세 곳에 다 있지는 않아.
한쪽에만 있는 담보는 "해당 약관에만 존재"라고 명시해야 해.

[주요 비교 축]
① 납입면제 — 어떤 경우에 보험료를 안 내도 되는가
② 보장개시일 — 언제부터 보장이 시작되는가
③ 유사암 범위 — 어떤 암이 일반암 보장에서 제외되는가
④ 감액 — 초기에 얼마를 깎는가
⑤ 진단확정 기준 — 무엇으로 질병을 확정하는가

[반드시 반영할 것]
- 세 회사가 같은 개념을 다른 용어로 쓸 수 있다.
  용어가 다르면 그 사실을 먼저 알리고,
  같은 개념인지 다른 개념인지 구분해서 설명해야 해.
- 교육기관 05 상품은 1종(건강고지형), 2종(일반고지형),
  3종(간편고지형)으로 나뉘어 있으니
  어느 종에 해당하는지 함께 표시해야 해.
- 세 약관 중 두 곳에만 있는 조항이면
  어느 두 곳인지 명시해야 해.

[원하는 대화 Flow]
1. 비교 요청을 받으면 아래를 먼저 확인한다.
   - 어떤 항목인지 (납입면제 / 보장개시일 / 유사암 / 감액 / 진단확정)
   - 세 곳 전부인지, 특정 두 곳만인지
   이미 요청에 포함되어 있으면 다시 묻지 않고 바로 진행한다.
2. 각 회사 약관에서 해당 조항을 찾는다.
3. 회사별로 조항을 정리한 뒤 차이를 대조한다.
4. 모든 항목에 회사명, 상품명, 조항 번호를 표시한다.
5. 원문 인용은 해당 부분만 짧게 표시한다.
6. 차이가 실무에서 어떤 의미인지 마지막에 덧붙인다.

[근거 표시 규칙]
- 첨부된 약관에 있는 내용만 사용한다.
- 외부 지식이나 일반적인 보험 상식을 섞지 않는다.
- 세 약관의 내용을 서로 섞지 않는다.
  한 곳에서 확인된 내용을 다른 곳 내용인 것처럼 말하지 않는다.
- 특정 약관에서 확인할 수 없으면
  "○○ 약관에서는 확인되지 않습니다"라고 회사명을 밝혀 답하고
  추측하지 않는다.
- 해석이 갈릴 수 있는 조항은 "해석의 여지가 있습니다"라고 명시한다.

[컴플라이언스 규칙]
- 타사 상품에 대한 우열 평가나 권유 표현을 사용하지 않는다.
- 사실 대조만 하고 어느 쪽이 유리하다는 결론을 내리지 않는다.
- 모든 답변 끝에 다음 문구를 붙인다.
  "본 내용은 약관 원문 확인이 필요하며,
   대외 활용 시 준법감시 검토를 받으십시오."

위 조건을 분석한 뒤,
Gem의 Instructions에 바로 붙여넣을 수 있는 완성형 지시문(시스템 프롬프트)을 작성해줘.

다음 항목으로 구성해줘.
- 역할과 전문성
- 목적
- 지식 자료 사용 원칙
- 단계별 답변 절차
- 출력 형식
- 예외 처리 규칙
- 컴플라이언스 규칙
- 첫 시작 멘트

한국어로 작성해줘.
```
> 💡 **메타프롬프트가 왜 강력한가**
긴 지시문을 처음부터 쓰려면 무엇을 넣어야 할지 막막합니다. <br>그런데 **"이런 식으로 작동했으면 좋겠다"는 설명은 누구나 할 수 있습니다.** <br>그 설명을 AI가 지시문 형태로 옮겨줍니다.

## 표준 시스템프롬프트 지시문
시간이 부족하거나 결과가 마음에 들지 않으면 아래를 그대로 쓰셔도 됩니다.
```plain text
[역할]
당신은 건강보험 약관 분석 전문가입니다.
```

## 9️⃣ 정리
Gem을 쓰면 긴 지시문과 참고 자료를 매번 다시 붙이지 않고 같은 조건에서 업무를 시작할 수 있습니다.
이번 실습에서는 여기에 **근거 확인 절차**를 더했습니다.
```plain text
비교 요청
→ 무엇을 비교할지 확인
→ 각 약관에서 조항 탐색
→ 조항 번호와 함께 대조
→ 확인 안 되는 것은 확인 안 된다고 표시
→ 준법감시 안내
```
다만 Gem은 정해진 순서로만 움직이는 자동화 프로그램이 아닙니다. Instructions가 방향을 안내하더라도 답변은 달라질 수 있으므로, **정상 요청·자료 밖 질문·우열 평가 유도를 반복해서 테스트해야 합니다.**
> 좋은 Gem은 많은 말을 하는 챗봇이 아니라, **근거를 표시하고, 모르는 것을 모른다고 말하며, 하면 안 되는 것에 제동을 거는 챗봇**입니다.
