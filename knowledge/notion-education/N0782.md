## 2. GitHub 가입

**단계별 따라하기**
- [github.com](http://github.com) 접속 → 우측 상단 **Sign up** 클릭
- 이메일 / 비밀번호 / 유저네임 입력
- ⚠️ 유저네임 주의 — 나중에 주소에 들어갈 수 있으니 신중히 (예: [github.com/내이름](http://github.com/내이름))
- 이메일 인증 링크 클릭 → 가입 완료

---
## 3. Vercel 가입

**단계별 따라하기**
- vercel.com 접속 → 우측 상단 **Sign Up**
- **"Continue with GitHub" 버튼 클릭**
- 회원가입 완료 및 로그인하기

로그인 후, 좌측 하단 **Connect with GitHub** 버튼 클릭
- GitHub 권한 승인 화면 → Authorize 클릭
- 이후, 좌측 하단의 같은 자리에 나타난 install 버튼 클릭하고 install 진행
- 두 서비스 자동 연결 완료


**GitHub 계정으로 가입하는 이유**
- 이메일로 따로 가입하면 — 나중에 GitHub과 연결하는 단계가 추가로 필요
- 처음부터 GitHub 계정으로 가입하면 — 두 서비스가 한 번에 자동 연결되어 더 깔끔

## 4. 사전 준비 체크리스트

**배포 전 아래 2가지만 준비되어 있으면 됩니다**

- [ ] Node.js 설치 — nodejs.org에서 LTS 버전 다운로드 후 설치 마법사
- [ ] 클로드 데스크톱 앱 'Code' 탭에서 내 프로젝트 폴더가 열려 있음

**GitHub CLI / Vercel CLI 설치는 직접 하지 않아도 됩니다**
- 키 포인트 — 수강생이 직접 해야 하는 것은 마지막 "로그인 창의 버튼 클릭"뿐
- Node.js만 미리 설치되어 있으면 — 나머지는 아래 배포 프롬프트 하나에 모두 포함
- 클로드 코드가 설치·로그인·배포를 순서대로 실행

---
## 5. 설치 및 로그인 — 4개 단계로 따라가기
### 5-1단계 — CLI 설치 (클로드 코드에 한 줄)

**클로드 코드 대화창(Code 탭 입력창)에 아래 한 줄 입력**

```plain text
깃허브 CLI랑 버셀 CLI 설치해줘.
```
- 클로드 코드가 `npm install -g vercel`, `gh` 설치 명령을 알아서 실행합니다
---
### 5-2단계 — 데스크톱 앱 완전히 종료 후 재실행 ⭐

**종료 후 재실행이 필요한 이유**
- 방금 새 명령어(`gh`, `vercel`)를 설치했지만, 지금 실행 중인 데스크톱 앱은 시작할 때 읽은 명령어 목록을 그대로 기억
- 그래서 `gh`를 입력해도 "그런 명령어 없음"이라는 답이 돌아옴 — 앱을 완전히 종료 후 재실행해야 새로 설치한 명령어 목록을 다시 읽음
- 한 줄 비유 — "프로그램 새로 깔고 컴퓨터 한 번 껐다 켜는 것과 같은 이유"

- 클로드 데스크톱 앱을 **완전히 종료하고 다시 실행**
- ⚠️ **재실행 후 아직 Code 탭 입력창에 지시하지 마세요.** 다음 단계는 Code 탭의 내장 터미널에서 직접 합니다.
---
### 5-3단계 — 설치 확인 (내장 터미널에서 직접) ⭐

**Code 탭 입력창 말고, 내장 터미널(Ctrl+\`)을 열어 직접 입력해서 확인합니다**
- 클로드 코드를 통해 확인하면 PATH 미인식이 가려져 실제 설치 상태를 볼 수 없음
- 그래서 이 단계는 사람이 직접 내장 터미널에 두 줄을 입력해 눈으로 확인

```plain text
gh --version
vercel --version
```
- ✅ 버전 숫자가 두 줄 다 뜨면 OK → 다음 단계로
- ❌ `command not found`가 뜨면 → 앱을 한 번 더 완전히 종료 후 재실행하고 다시 시도, 그래도 안 되면 5-1로 돌아가 재설치

**확인이 끝났으면 — Code 탭 입력창으로 복귀**
- 내장 터미널 확인을 마치고 Code 탭 입력창으로 돌아오기
- 5-4 단계로 진행

---
### 5-4단계 — 로그인 (클로드 코드에 부탁)

**클로드 코드 대화창(Code 탭 입력창)에 아래 한 줄 입력**

```plain text
gh auth login이랑 vercel login 실행해줘. 인증은 내가 브라우저에서 직접 할게.
```
- 브라우저 창이 뜨면 — 새 탭에서 Authorize 버튼 클릭
- Code 탭으로 돌아와 "Logged in" 같은 메시지가 보이면 완료
---
## 6. 배포하기 — 클로드 코드에 한 줄로 부탁

**첫 배포**

```plain text
이 프로젝트를 깃허브에 푸시하고 버셀로 배포해줘. 깃허브 푸시할땐 '프라이빗'으로 해줘.
```
- ‘프라이빗’으로 푸시하는 이유 :
- 혹시 모를 코드 내 민감정보 유출을 막을 수 있습니다.
- ‘항상 프라이빗으로 푸시하라는 내용을 `CLAUDE.md`에 등록해달라’고 하면 더 좋습니다.

**재배포 — 파일 수정 후 다시 올릴 때**

```plain text
수정한 거 깃허브 푸시하고 버셀로 재배포해줘
```

## 7. .gitignore — 깃허브에 올리지 말 파일 목록 (윈도우 기준)

**.gitignore 파일이란?**<br>깃허브에 올릴 때 "이 파일들은 절대 올리지 마"라고 적어두는 목록 파일입니다. 비유하자면 짐을 쌀 때 "지갑·신분증은 가방에 넣지 마" 메모를 짐 위에 붙여두는 것.


**이 내용을 마지막에 다루는 이유**<br>5\~6번에서 클로드 코드가 `git init`을 할 때 적절한 `.gitignore`를 자동으로 만들어주는 경우가 많습니다. 그래도 어떤 파일을 왜 빼야 하는지 한 번 짚어두면, 내 `.gitignore`가 제대로 만들어졌는지 직접 확인할 수 있습니다.

### 꼭 들어가야 하는 항목

[계정 정보가 포함된 표 제외]

### Claude Code에 시키는 법
```plain text
이 폴더에 .gitignore 파일 만들어줘.
API 키·비밀번호·node_modules·윈도우 시스템 파일(Thumbs.db, desktop.ini) 등의 민감정보가 깃허브에 안 올라가게 해줘.
```

**자주 헷갈리는 부분**
- 클로드 코드는 `git init` 직후 적절한 `.gitignore`를 자동으로 만드는 경우가 많지만, 명시적으로 한 번 더 시키는 게 안전합니다.
- 이미 `.env`가 깃허브에 올라간 뒤에 `.gitignore`에 넣어도 늦습니다. 처음부터 `.gitignore`에 넣고 시작하는 습관이 중요합니다.

<details>
<summary>macOS·리눅스 사용자라면</summary>
위 항목에 더해 `.DS_Store` (macOS가 자동으로 만드는 시스템 파일)도 `.gitignore`에 추가해주세요. 윈도우 PC끼리만 협업하는 본 강의에서는 신경 쓰지 않아도 되지만, 외부 협업자 중 맥 사용자가 있으면 같이 막아두는 게 좋습니다.
</details>

## 다음 단계 — 데이터 저장·로그인이 필요한 경우 : Supabase
- 이번 배포는 **정적 사이트**(데이터가 코드 안에 들어있는 사이트)를 올린 겁니다.
- 그런데 프로젝트가 조금만 커져도 아래 조건이 생기면 **데이터베이스**가 필요해집니다.
- 사용자 입력을 저장해야 할 때 (예: 민원 접수 폼, 설문 응답)
- 여러 사람이 같은 데이터를 공유해야 할 때 (예: 팀 시설점검 진행 현황을 여러 담당자가 업데이트)
- 로그인·권한 구분이 필요할 때 (예: 보고서는 본인·팀장만 볼 수 있게)

**Supabase** = 이런 조건에서 가장 많이 쓰는 **무료로 시작 가능한 클라우드 데이터베이스 + 로그인 서비스**. 다른 서비스도 많지만 Supabase가 설정이 가장 간단해서 처음 쓰기 좋습니다.<br><br>Claude Code에 "Supabase로 설문 응답 저장 기능 붙여줘" / "로그인 기능 추가해줘" 식으로 시키면, **Supabase 계정 생성·프로젝트 만들기·키 발급·코드 연결**까지를 동료와 상의하듯 대화로 같이 설정해 갑니다. 키 보관은 `.env` 파일 방식 그대로.<br><br>이 강의 범위는 아니라 상세 수업은 생략하지만, 메인 프로젝트가 커지면 자연스럽게 만나게 되는 단계니 이름만 알아두세요.
