### 🔥 활동 2 — 더미 테스트 데이터 만들기
실제 데이터를 쓰기 전에 **테스트용 가짜 데이터**로 먼저 검증합니다. <br>보안 문제도 없고, 예외 상황을 일부러 넣을 수 있습니다.
```plain text
앞에서 만든 데이터 사전에 맞는
현실적인 테스트 데이터 20행을 만들어줘.

조건:
- 광고 매체 실적 데이터로, 실제 업무에서 나올 법한 내용
- 정상 케이스 70%, 이상·예외 케이스 30% 포함
- 이상 케이스에 반드시 포함할 것
  · 컬럼명이 기준표와 다른 파일 1개
  · 날짜 형식이 다른 행
  · 단위가 문자로 표기된 값 (1.2M 등)
  · 결측값
  · 동일 매체·동일 일자 중복 행
  · 전주 대비 비정상적으로 큰 값

표 형식으로 출력하고,
마지막에 "이 데이터셋에 포함된 이상 케이스 목록"을 정리해줘.
```
> **이상 케이스를 20\~30% 넣는 것이 핵심입니다.** 정상 데이터만으로 테스트하면 실전에서 반드시 터집니다. **자동화의 진가는 예외 상황에서 갈립니다.**

### 📖 개념: RAG — 검색이 먼저, 생성이 나중
회사 문서를 근거로 답하게 만드는 방식을 RAG라고 부릅니다. 우리말로는 「회사 문서 기반 답변」입니다.
```plain text
일반적인 질문     질문 → 바로 생성

RAG              질문 → 관련 문서 찾기 → 찾은 내용을 근거로 생성
```
**사이에 한 단계가 들어갔을 뿐입니다.** 이름은 어렵지만 이게 전부입니다.
> **비유하면** 규정을 물었을 때 **기억으로 답하는 직원**과 **규정집을 펼쳐 해당 페이지를 짚으며 답하는 직원**의 차이입니다. 후자는 느리지만 틀리지 않고, 틀렸을 때 어디를 보고 틀렸는지 추적할 수 있습니다.

> **AI가 답변에 출처를 표기할 때 파일명을 씁니다.** 파일명이 "최종본_v3"이면 근거 표기가 무의미해집니다. 그리고 **100페이지 통합본 하나보다 20페이지 다섯 개가 정확합니다.** 사람이 찾는 방식과 같게 나누면 됩니다.
**2단계 · 답변 규칙 걸기**
NotebookLM은 업로드한 문서 안에서 답하지만, **근거가 없을 때 어떻게 행동할지는 별도로 지시해야 합니다.**
```plain text
[답변 규칙]

1  업로드된 문서에 근거가 있는 내용만 답한다.

2  답변 끝에 근거를 표기한다.
   근거: [문서명] — [항목]

3  문서에 근거가 없으면 추측하지 않고 다음 문장만 출력한다.
   "해당 내용은 업로드된 문서에서 확인되지 않습니다.
    담당 부서에 확인하시기 바랍니다."

4  문서 내용과 일반 상식이 다르면 문서를 따른다.
```
> **3번이 핵심입니다.** "모르면 모른다고 하세요"라는 지시는 잘 안 지켜집니다. **출력할 문장을 통째로 정해 주면 지켜집니다.** 행동을 지시하는 것보다 결과물을 고정하는 편이 확실합니다. 이 원리는 5권 시스템 프롬프트 전체에 적용됩니다.

### 📌 3권 핵심 정리
① AI의 결과 품질은 **입력 데이터의 품질**로 결정된다. 한 행에 하나의 기록이 원칙이다.
② 정제한 데이터에는 **데이터 사전**이 따라와야 한다. 이것이 지시문의 절반이다.
③ 테스트 데이터에는 **이상 케이스를 20\~30%** 넣어야 실전에서 오류가 없다.
④ 데이터(숫자)와 지식(기준)은 다르다. **지식은 RAG로 연결하고, 근거 없을 때의 출력 문장을 고정한다.**
> **다음 단계 예고** — 4권에서는 지금까지 준비한 **과제 정의서 · 데이터 사전 · 지식 문서**를 하나로 묶어 **Agent 설계서**를 완성합니다. Agent의 다섯 가지 구성 요소와 승인 지점 설계를 다룹니다.
