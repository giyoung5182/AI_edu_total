## 이 시간이 답하는 질문
> **"이 앱이 앞으로 사내에서 실제로 쓰이는 도구가 되려면 무엇이 필요한가?"**
```plain text
지금까지 물었던 것    "내가 쓰기에 편한가"
이제 물을 것         "남이 쓸 수 있는가"
```
**앱은 이미 돌아갑니다.** 데이터도 들어가고 배포도 됐습니다. 남은 것은 **내 도구를 부서 도구로 옮기는 일**이고, 그건 기능이 아니라 **쓰는 사람 관점의 문제**입니다.
```plain text
1권에서 본 구분

  PoC 단계     "이 방향이 되는지" 확인하는 단계   ← 지금 여기
  운영 시스템   매일 여러 사람이 쓰는 단계        ← 오늘 향하는 곳

  차이는 기능의 개수가 아니라
  데이터·사용자·안정성 세 가지입니다.
```
이 시간에는 그중 **사용자**를 봅니다. 데이터는 대체로 붙었고, 안정성은 2주 실행 기간에 확인하게 됩니다.

**없앨 수 없음** — 잇는 방법 필요


### 왜 이것부터 보는가
```plain text
앱을 쓰는데 기존 방식도 계속 한다면
→ 앱은 일을 줄인 것이 아니라 하나 늘린 것입니다
→ 이 상태로는 남에게 권할 수 없습니다
```
**"왜 병행하는가"에 적은 이유가 곧 개선 항목이 됩니다.**
```plain text
"부서장이 엑셀로 봐서"        → 엑셀 내보내기를 붙이면 해결
"앱에 등록해도 알림이 안 감"   → 자동 알림을 붙이면 해결
"규정상 결재는 그룹웨어로"     → 없앨 수 없음. 이어야 함
```

# 점검 2. 사용자 관점 네 렌즈 (12분)
---
**워크시트 시트 2**를 채웁니다. **오늘 가장 중요한 작업입니다.**
---
## 렌즈 ① 진입 — 처음 쓰는 사람이 들어올 수 있는가
```plain text
시트 2 ①번  앞으로 이 앱을 실제로 쓸 사람은 누구인가

  구체적으로 적으세요.
  "총무팀"이 아니라 "총무팀 결제 담당 김○○ 대리"
  → 이름이 나와야 오후 실행계획을 세울 수 있습니다
```
**확인해볼 것**
```plain text
□ 그 사람이 계정을 어떻게 받나
□ 주소를 어떻게 아나
□ 처음 열었을 때 무엇을 해야 할지 아는가
```
**직접 해보는 방법** — 브라우저 시크릿 창에서 앱 주소를 열어보세요. 로그인 안 된 상태에서 어떻게 보이는지가 **새로 들어오는 사람이 보는 화면**입니다.
---
## 렌즈 ② 이해 — 설명 없이 쓸 수 있는가
```plain text
시트 2 ②번  그 사람들이 지금 이 앱을 쓴다면 어디서 막힐 것 같은가
```
**확인해볼 것**
```plain text
□ 버튼 이름만 보고 무엇을 하는지 아는가
□ 어디에 뭘 입력해야 하는지 보이는가
□ 실수했을 때 되돌릴 수 있는가
□ 용어가 나만 아는 말은 아닌가
```
> **가장 확실한 확인법은 옆 사람에게 시켜보는 것입니다.** 30초만 주고 "이 앱으로 결제 요청 하나 등록해보세요"라고 해보세요. 어디서 멈추는지가 바로 보입니다. 시간이 되면 지금 해보세요.
---
## 렌즈 ③ 연결 — 기존 업무와 이어지는가
**이번 회차에서 가장 많이 나올 항목입니다.**
```plain text
시트 2 ③번  그 사람들이 지금 쓰는 방식은 무엇인가
시트 2 ④번  앞으로도 병행해야 하는 과정은 무엇인가 (없앨 수 없는 것)
시트 2 ⑤번  그 병행을 어떻게 이을 것인가
```
### 병행을 두 종류로 나누세요





종류

무엇인가

목표




**없앨 수 있는 병행**

습관·불편 때문에 남아 있는 것

**없애기**




**없앨 수 없는 병행**

규정·결재·외부 시스템

**잇기**


```plain text
없앨 수 없는 병행의 예

  · 결재는 그룹웨어로 해야 한다 (규정)
  · 원본 서류는 종이로 보관해야 한다 (법적 의무)
  · 본사 시스템에 최종 등록해야 한다 (외부 시스템)
```
**없앨 수 없다면 없애려 하지 말고, 이중 입력이 안 생기게 이으세요.**
> **1권의 Klarna 사례가 같은 교훈입니다.** 사람을 전부 빼려다 되돌렸고, 결국 **단순한 것은 AI가, 복잡한 것은 사람이** 맡는 구조로 정리됐습니다.
우리도 같습니다. **앱이 모든 단계를 흡수할 필요가 없습니다.** 규정·결재처럼 사람이 해야 하는 단계는 남겨두고, 그 앞뒤를 잇는 것이 현실적인 설계입니다.
```plain text
잇는 방법 예시

  앱에서 결재 양식을 그대로 내보내기      → 복사해서 그룹웨어에 붙여넣기
  앱에서 등록번호를 부여                  → 종이에 그 번호만 적기
  본사 시스템 양식에 맞춰 엑셀 내보내기    → 그대로 업로드
```
> **④번을 안 적으면 2주 뒤에 발견합니다.** "다 만들었는데 규정상 못 쓴다"가 되면 시간이 사라집니다. **지금 확인하세요.** 모르면 '확인 필요'로 적고 이번 주에 알아보면 됩니다.
---
## 렌즈 ④ 지속 — 내가 없어도 굴러가는가
```plain text
시트 2 ⑥번  내가 없어도 이 앱이 돌아가려면 무엇이 필요한가
```
**세 가지가 있어야 합니다**
```plain text
① 나 말고 쓰는 사람이 있다
② 그 사람이 볼 사용법이 있다
③ 문제가 생겼을 때 어떻게 하는지 정해져 있다
```
**셋 중 하나라도 없으면 아직 내 도구입니다.** 오후 2주 계획에 이 셋을 넣습니다.
**확인해볼 것**
```plain text
□ 사용법이 문서로 있나 (없으면 2주 안에 만들어야 합니다)
□ 계정이 개인 것에 묶여 있지 않나
□ 오류가 나면 누가 대응하나
□ 내가 휴가를 가면 어떻게 되나
```
> **1권에서 본 JPMorgan 사례가 이 지점입니다.** 20만 명이 쓰게 된 결정적 이유는 좋은 기능이 아니라 **누구나 접근할 수 있는 환경**이었습니다. 확산은 지시로 일어나지 않았고, 쓸 수 있으니까 퍼졌습니다.
반대로 우리 앱은 지금 **접근 자체가 막혀 있는 상태**일 가능성이 높습니다. 계정이 하나뿐이거나, 주소를 아는 사람이 나뿐이거나.

# 점검 3. 개선 후보 나열 (5분)
---
**워크시트 시트 3**에 후보를 전부 적습니다. **지금은 고르지 말고 나열만 합니다.**
## 어디서 나오나
```plain text
시트 1의 "왜 병행하나"      → 대부분 여기서 나옵니다
시트 2 ②번 (막힐 것 같은 곳)
시트 2 ⑤번 (병행을 잇는 방법)
시트 2 ⑥번 (없어도 돌아가려면)
```
**각 후보마다 "어느 시트에서 나왔나"를 적어두세요.** 나중에 왜 그것을 골랐는지 설명할 때 씁니다.
## 나올 만한 후보들
```plain text
연결  (전달이 비어 있는 곳 — 대부분 여기서 나옵니다)
  · 등록 시 관련자에게 자동 알림
  · 엑셀 내보내기 (기존 양식과 열 순서까지 맞추기)
  · 다른 시스템에 올릴 양식 형태로 출력
  · 정해진 시각에 현황을 자동 발송

진입·이해
  · 계정을 사람별로 분리
  · 첫 화면에 무엇을 하는 곳인지 안내
  · 자주 쓰는 기능을 첫 화면으로
  · 입력 항목 줄이기 (드롭다운·기본값)

지속
  · 사용법 문서 만들기
  · 오류 시 대응 방법 정하기
  · 개인 계정을 공용으로 전환
  · 결과에 근거·생성시각 표시 (검산 없이 믿을 수 있게)
```
> **연결 항목이 2주 프로젝트에 가장 적합합니다.** 효과가 크고, 앱 코드를 크게 건드리지 않으며, Cursor 크레딧도 거의 쓰지 않습니다.

## 고를 때 함께 볼 것
