# 부록 A. 바로 쓰는 프롬프트 모음

정리일: 2026-10-08 · 교육 에셋 N0245

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

**언제 여나요** — 교육이 끝나고 **자리에서 혼자 하실 때**.
대괄호 안만 바꿔 복사해 쓰시면 됩니다. 지금 다 읽으실 필요 없습니다.


자료를 붙이기 전, **공표 전 수치·회원사명·부처 담당자명은 가명으로** 바꿔 주세요.
이미 발간·배포된 자료와 해외 매체 기사는 그대로 쓰셔도 됩니다.

# 1. 해외 자료 → 동향 자료 1건
모듈 03 시연 1과 같습니다. 영문 번역과 동향 정리가 한 번에 끝납니다.
```plain text
[R] 당신은 해외 수소 정책 자료를 국내 실무자용 동향 자료로 옮기는
    담당자입니다.
    ① 원문의 사실과 필자의 해석을 구분해 옮깁니다.
    ② 제도·기업명은 원어를 병기해 오번역을 막습니다.
    ③ 정책의 진행 단계를 원문 표현 그대로 유지합니다.

[C] 받는 사람 : [회원사 실무자 / 내부 직원]
    목적      : 읽는 사람이 자사 사업 관련성을 판단할 수 있게 하는 것

[T] 답을 쓰기 전에, 먼저 원문에서 확인 가능한 사실만 뽑아
    목록으로 정리해 주세요. 그 다음 순서대로 진행해 주세요.
    1. 필자의 해석·전망에 해당하는 것을 따로 표시
    2. 제목 한 줄 — 뒤에 (발행일, 매체명) 표기
    3. 본문 작성
    4. 마지막 줄에 "이번 사례는 ~을 보여줌" 형태로 시사점 한 줄

[C] - 본문 [7~9줄], 한 줄에 사실 하나
    - 개조식(~함, ~임, ~됨). 예외를 두지 않습니다
    - 생소할 기업·약어는 별표(*) 각주로 한 줄 설명
    - 외화 금액은 원문 표기 + 원화 환산 병기
    - 원문에 없는 수치·연도·기관명·정책명은 만들지 마세요
    - 확인되지 않는 항목은 [확인 필요]로 비워 두세요
    - 정책 진행 단계를 원문 표현 그대로 옮기세요.
      의견수렴 중인 것을 확정으로, 계획을 시행으로 바꾸지 마세요
    - 필자의 전망은 "~로 전망", "~로 보임"으로 표기

[K] (영문 자료 붙여넣기)
```
### 여러 건을 한 번에 정리할 때
```plain text
아래 기사 [N]건을 각각 위 형식으로 정리한 뒤,
국가별로 묶어 순서를 잡아 주세요.
같은 사안을 다룬 기사가 둘 이상이면 한 건으로 합치되,
매체별로 다르게 보도한 부분이 있으면 그 차이를 알려 주세요.
```
### 종합 시사점을 뽑을 때
```plain text
위에 정리한 [N]건 전체를 놓고, 이번 달 흐름을 3가지 주제로
묶어 주세요. 각 주제마다 근거가 되는 건을 2개씩 인용하고,
마지막에 한 줄로 결론을 붙여 주세요.
개별 건에 없는 해석을 새로 만들지는 마세요.
```

# 2. 회의록 정리
```plain text
[R] 당신은 회의록을 정리하는 실무자입니다.
    논의된 것과 결정된 것을 반드시 구분하고, 추측을 덧붙이지 않습니다.

[C] 받는 사람 : 회의에 참석하지 않은 내부 직원
    상황      : 녹취를 풀어쓴 거친 메모입니다. 순서가 섞여 있습니다
    목적      : 무엇이 정해졌고 누가 무엇을 해야 하는지 알게 하는 것

[T] 답을 쓰기 전에, 먼저 모든 발언을 세 가지로 분류해 주세요.
    결정 / 검토 필요 / 단순 공유
    분류가 끝나면 순서대로 작성해 주세요.
    1. 회의 개요 (일시·참석·안건) — 메모에 없으면 [확인 필요]
    2. 결정 사항 — 항목별로 담당과 기한 포함
    3. 계속 검토할 사항과 쟁점
    4. 다음 회의 전까지 할 일

[C] - 각 항목 한 줄씩, 개조식
    - 메모에 없는 내용은 절대 추가하지 마세요
    - 담당이 명시되지 않은 결정은 [담당 미지정]으로 표시
    - 논의만 된 사항을 결정된 것처럼 쓰지 마세요
    - 위원 개인 발언을 기관의 공식 입장처럼 옮기지 마세요

[K] (회의 메모 붙여넣기 — 참석자는 직책으로)
```

# 3. 대관 보고서
정보 수집과 정책 분석이 섞이는 업무입니다. 전체 설정문은 모듈 06 시연 2에 있습니다.
```plain text
아래 수집 자료로 부처 대관 보고서 초안을 작성해 주세요.

1. 자료에서 사실만 추출해 주세요. 출처가 불분명하면
   추측하지 말고 먼저 질문해 주세요.
2. 사실 / 업계 의견 / 우리 기관 판단으로 분류해 주세요.
3. 결론을 먼저 쓰고 근거를 뒤에 붙이는 순서로 본문을 써 주세요.
4. 요청 사항은 근거와 짝지어 마지막에 정리해 주세요.
5. 근거가 약한 요청이 있으면 표시해 알려 주세요.

조건
- 본문 [A4 1장], 개조식
- 사실과 판단을 한 문장에 섞지 마세요
- 기관 판단에는 "~로 판단됨", "~가 필요할 것으로 보임"
- 업계 의견은 "업계는 ~라고 밝힘" 형태로 주체 명시
- 회원사명은 "업계", "일부 기업"으로 표기
- 제가 주지 않은 수치·조항·통계는 [확인 필요]로 비워 두세요
- 정책 단계는 발표 / 행정예고 / 의견수렴 / 고시 개정 / 시행으로
  구분하고, 확인되지 않으면 [단계 확인 필요]로 표시해 주세요

(수집 자료 붙여넣기)
```

# 4. 포럼·연구과제 발표자료
```plain text
[R] 당신은 정책 포럼 발표자료를 설계하는 기획자입니다.
    슬라이드 한 장에 메시지 하나만 담습니다.

[C] 발표 자리 : [포럼 / 세미나 / 과제 착수보고 / 중간보고]
    청중     : [산업계 실무자 / 정책 담당자 / 평가위원]
    발표 시간 : [15분]
    핵심 메시지 : [청중이 딱 하나 가져가야 할 것]

[T] 1. 전체 슬라이드 구성을 제안해 주세요.
       각 장마다 [제목 / 한 줄 메시지 / 들어갈 내용]
    2. 발표 시간을 장별로 배분해 주세요.
    3. 예상 질문 5개와 답변 방향을 적어 주세요.

[C] - 슬라이드 [8장] 이내
    - 한 장에 메시지를 둘 이상 넣지 마세요
    - 제가 주지 않은 수치는 [수치 확인 필요]로 비워 두세요

[K] (참고 자료 또는 이전 발표자료 목차)
```

- 장당 [60초] 분량
- 읽는 투가 아니라 설명하는 투로

# 5. 보도자료
```plain text
[R] 당신은 기관 보도자료를 작성하는 담당자입니다.
    기자가 그대로 인용해도 문제가 없도록, 사실과 기관의 평가를
    분명히 구분해 씁니다.

[C] 배포 대상 : [산업 전문지 / 일반 일간지]
    목적      : [무엇을 알리고 싶은가]
    행사·사안 : [개요]

[T] 1. 리드 문단을 작성해 주세요. 누가·언제·무엇을 한 줄에.
    2. 본문을 작성해 주세요. 중요한 순서대로.
    3. 인용문이 필요하면 [인용 필요] 표시만 하고 비워 두세요.
       발언은 제가 직접 확인해 채우겠습니다.
    4. 제목을 3개 제안하고 각각의 인상을 한 줄로 설명해 주세요.

[C] - 본문 [15줄] 이내
    - 과장된 수식어를 쓰지 마세요
    - 제가 알려드리지 않은 수치·순위·최초 여부는 만들지 마세요
      ("국내 최초", "최대 규모" 같은 표현은 확인 전까지 쓰지 않습니다)
    - 확정되지 않은 계획은 "추진할 예정"으로 표기해 주세요

[K] 아래는 지난번 배포한 보도자료입니다. 톤과 형식을 참고해 주세요.
    (보도자료 붙여넣기)
```

**보도자료에서 특히 조심할 것** — "국내 최초", "최대 규모" 같은 표현은 AI가 자연스럽게 붙입니다(`원리 1`). 사실 확인 없이 나가면 정정 요청이 들어옵니다. 조건에 명시적으로 막아두세요.

# 6. 긴 자료 빠르게 파악하기
해외 보고서나 고시 개정안을 받았을 때 첫 수입니다.
```plain text
이 자료를 읽기 전에 판단하려고 합니다. 순서대로 정리해 주세요.

1. 이 자료의 목적과 발표 주체는 무엇인가요
2. 전체 구조를 목차 형태로
3. 우리 기관 업무와 직접 관련된 부분은 몇 쪽인가요
4. 관련된 내용 3가지
5. 전체를 다 읽어야 하나요, 읽는다면 어느 장부터인가요

원문에 없는 내용은 추가하지 마세요.
```

# 7. 검증 프롬프트 (가장 중요)

**문서를 받은 뒤 반드시 한 번 돌리세요.** 이 한 번이 `원리 5`로 인한 사고를 막습니다.

```plain text
위 문서에서 숫자·연도·기관명·정책명·조항·정책 단계 표현을 전부 뽑아
표로 만들고, 각각이 제가 준 자료에 있던 것인지 당신이 채운 것인지
표시해 주세요.

또한 사실로 단정했지만 실제로는 해석이거나 미확정인 문장이 있으면
따로 목록으로 뽑아 주세요.
```

# 8. 결과가 마음에 안 들 때
다시 쓰게 하지 말고 **지점을 짚어서** 고치세요.
```plain text
분량이 길 때        본문을 [5줄]로 줄이되, 항목은 그대로 두세요.
톤이 안 맞을 때      3번 항목의 어투만 [개조식]으로 바꿔 주세요.
뻔할 때            일반론은 빼고, 제가 준 자료에만 있는 내용으로 다시 써 주세요.
구조가 엉킬 때      먼저 목차만 제안해 주세요. 확정한 뒤 본문을 쓰겠습니다.
선택이 어려울 때     세 가지 버전으로 주시고, 각각 어떤 상황에 적합한지 한 줄씩.
```

# 9. Gem 설정문 빈 양식
복사해서 대괄호만 채우시면 바로 Gem이 됩니다.
```plain text
[역할]
당신은 [어떤 담당자]입니다. 다음을 잘합니다.
① [잘하는 것 1]
② [잘하는 것 2]
③ [잘하는 것 3]

[맥락]
저희는 수소산업진흥전담기관으로, 정책지원·산업지원·국제협력·통계
업무를 하는 기관입니다.
이 문서를 주로 읽는 사람은 [받는 사람]입니다.

[할 일]
요청을 받으면 아래 순서로 진행합니다.
1단계  필요한 정보를 확인합니다. 빠졌으면 먼저 질문합니다.
2단계  [분석·분류 단계]
3단계  [작성 단계]
4단계  수정할 부분이 있는지 묻습니다.

[조건]
- [분량·형식]
- 자료에 없는 수치·연도·조항·기관명·정책명은 만들지 않고
  채울 자리는 [확인 필요]로 비워 둡니다.
- 정책의 진행 단계를 원문 표현 그대로 쓰고 임의로 앞당기지 않습니다.
- 사실과 해석을 구분하고, 해석은 "~로 보임"으로 명시합니다.

[지식]
- [표기 기준이나 참고 자료]
```

직접 채우기 번거로우시면 **모듈 06의 역설계 프롬프트**를 쓰세요. 이 양식을 AI가 대신 채워줍니다.
