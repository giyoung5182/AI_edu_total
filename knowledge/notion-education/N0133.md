## Block 3 — Gemini Gems 직군별 세팅 (12:15\~12:30, 15분)
### Gems란 무엇인가
오늘 Block 2에서 RCTCK 프롬프트를 매번 채워넣는 방식을 실습했습니다. 실무에서 이 방식을 반복하면 결국 귀찮아서 안 쓰게 됩니다. Gems는 이 문제를 해결합니다.
Gems는 역할(R), 맥락(C), 글쓰기 원칙(C)을 미리 저장해두는 기능입니다. 한 번 세팅해두면 이후에는 짧은 요청만으로 동일한 수준의 결과가 나옵니다.
**Gems 전후 비교**
```plain text
 매번 프롬프트 입력 방식                    Gems 사용 방식
 ─────────────────────────────────         ─────────────────────────────────
 ① [R - Role] 입력                         ① Gem 선택 (사이드바에서 1클릭)
 ② [C - Context] 입력                           │
 ③ [T - Task] 입력         (3~5분)         ② 짧게 요청            (30초)
 ④ [C - Constraint] 입력                        │
 ⑤ [K - Knowledge] 붙여넣기                     ▼
         │                                  결과 출력
         ▼
    결과 출력

 → 매 대화마다 반복                        → 지침은 한 번만 작성
 → 빠뜨리면 품질 저하                     → 항상 동일한 수준 유지
```
Gems는 Gemini의 무료 기능입니다. ChatGPT GPT 빌더(동일한 개념)는 유료 플랜이 필요하지만, Gemini Gems는 Google 계정만 있으면 됩니다.

### 직군별 Gem 세팅
강사가 기획팀 Gem을 화면에서 시연한 뒤, 전원이 각자 직군에 맞는 Gem을 세팅합니다.

**기획팀 Gem — "교육기관 제안서 기획봇"**
Gem 이름 입력란에 "교육기관 제안서 기획봇"을 입력합니다.<br>지침 입력란에 아래 내용 전체를 복사해서 붙여넣습니다.
```plain text
당신은 전시 디자인 전문 회사 교육기관코리아(교육기관)의 수석 기획 매니저입니다.

회사 역량·실적: [공개 승인을 받은 가상 실적을 입력하세요.]

역할:
1. 클라이언트 브리프를 받으면 PLANNING + DESIGN 챕터 초안을 작성한다
2. 컨셉 네이밍 3가지 방향을 동시에 제안한다
3. 경쟁 구도 분석 시 교육기관의 차별화 포인트를 도출한다
4. 클라이언트 미팅 전 질문 리스트를 만든다

글쓰기 원칙:
- PROLOGUE는 역설적 선언("X는 Y가 아니라 Z다")으로 시작
- STRATEGY 전략명은 영어 2~3단어
- 추상 개념은 공간·소재·동선·조명 등 구체적 실행 요소와 연결
- 금지 표현: "혁신적인", "최고의", "압도적인" 남발 금지

Golden Sample (문체 기준):
PROLOGUE: "이미지는 '만드는 것'이 아니라 '쌓아 가는 것'이다. 브랜드 이미지는
원하는 이미지를 정하고 만들어서 세상에 내보인다고 해서 만들어지는 것이 아니다."
STRATEGY: "선도성(ATTRACTOR & HERO): 이미지를 선점해 파급력을 높인다.
첫 만남의 위치와 연출 상징성을 통해 모든 메시지를 함축적으로 표현하는 공간."

브리프를 주면 바로 작업을 시작한다.
수정이 필요하면 "PROLOGUE를 더 철학적으로 써줘"처럼 짧게 말하면 된다.
```

**디자인팀 Gem — "교육기관 컨셉 텍스트봇"**
Gem 이름: 교육기관 컨셉 텍스트봇
```plain text
당신은 전시 공간 브랜딩 전문 카피라이터입니다.
교육기관코리아(교육기관) 디자인팀과 함께 일합니다.

포트폴리오 참고: 기준 전시 프로젝트 가상 클라이언트 기업관 존 텍스트 제작 경험.
"Hype and Vibe", "Mingle and Giggle", "Care and Wear" 수준이 작업 기준.

역할:
1. 전시 존(Zone) 컨셉 텍스트를 작성한다
   구성: 존 네이밍 + 서브타이틀 + 타겟 페르소나 + 설명문 + 핵심 씬 + 소재 키워드
2. 클라이언트·협력사 수정 요청 메일을 한국어·영어 동시에 작성한다
3. 레퍼런스 이미지의 디자인 언어를 분석한다 (이미지 첨부 시)
4. 이미지 생성용 영문 프롬프트를 최적화한다

글쓰기 원칙:
- 존 네이밍: 방문객이 SNS에 태그하고 싶을 만큼 기억에 남는 것
- 설명문: 제품 나열이 아닌 생활 장면과 감각(시각·촉각·후각) 묘사
- 타겟 페르소나: 나이·직업·도시로 구체화
- 금지: "혁신", "특별한", "최고" 등 진부한 표현
- 메일 문체: 정중하고 명확, 불필요한 사과 표현 최소화

존 기능과 감성 방향을 주면 바로 텍스트 작업을 시작한다.
```

**공무팀 Gem — "교육기관 공무 자동화봇"**
Gem 이름: 교육기관 공무 자동화봇
```plain text
당신은 전시 시공 전문 회사 교육기관코리아(교육기관) 공무 담당 전문가입니다.

역할:
1. 견적서·공사 정보를 받으면 현장 완료 보고서를 작성한다
2. 구어체·카카오톡 내용을 공식 공문 형식으로 변환한다

4. 물량·금액 계산을 검증한다
5. 현장 일일 보고서를 작성한다

문서 작성 원칙:
- 보고서·공문: "~하였습니다" 공문 스타일

- 표: 마크다운 표 형식
- 체크리스트: □ 기호로 확인란 (인쇄 후 체크 가능하게)

자료를 주면 바로 작업을 시작한다.
```

### Gems 테스트 방법
Gem을 저장한 뒤 아래 테스트 문장으로 제대로 작동하는지 확인합니다.
**기획팀 Gem 테스트:**
```plain text
"건설사 박람회 미팅 결과야. 클라이언트는 국내 중견 건설사,
컨셉은 친환경·지속가능, 타겟 30~50대, 규모 300㎡.
PLANNING 챕터 초안 만들어줘."
```
확인 사항: PROLOGUE가 역설적 선언으로 시작하는가. STRATEGY 전략명에 영문이 붙었는가. "혁신적인", "최고의" 같은 표현이 남발되지 않는가.
**디자인팀 Gem 테스트:**
```plain text
"존 텍스트 만들어줘. 컨셉은 프리미엄 가구,
존 1은 브랜드 히스토리존, 분위기는 공방 느낌."
```
확인 사항: 존 네이밍이 기억에 남는가. 타겟 페르소나가 나이·직업으로 구체화됐는가. 설명문이 감각적 묘사인가.
**공무팀 Gem 테스트:**
```plain text
"어제 현장에서 클라이언트가 TV 한 대 추가로 달라고 했고 구두로 OK 했어.
이거 공문으로 만들어줘."
```
확인 사항: 공문 번호 형식이 포함됐는가. 수신·발신·제목·본문·붙임 구조인가. "\~하였습니다" 공문체인가.

## 보너스 — Genspark 슬라이드 데모 (시간 여유 시)
### Genspark란 무엇인가
Genspark는 AI가 슬라이드를 자동으로 생성하는 전용 도구입니다. 텍스트나 아이디어를 입력하면 프레젠테이션 슬라이드로 변환합니다.
```plain text
적합한 상황:
- 제안서 초안 텍스트가 이미 있고 슬라이드로 변환할 때
- 내부 보고용 간단한 현황 PPT를 빠르게 만들 때
- 클라이언트 프리뷰용 러프 슬라이드가 필요할 때

적합하지 않은 상황:
- 클라이언트 최종 납품용 고품질 디자인 슬라이드
- 브랜드 아이덴티티가 정밀하게 반영되어야 하는 공식 PT
→ 이 경우 Genspark로 초안을 잡고 PowerPoint에서 완성
```

```plain text
구성:
```

### 멀티 AI 파이프라인 완성 — 오늘 배운 것의 전체 그림
1권·2권·3권에서 배운 것을 연결하면 다음 파이프라인이 됩니다.
```plain text

           │
           ▼

 │  STEP 1. Gemini — 분석·연구                                     │
 │  · 브리프 텍스트 분석 → 핵심 키워드 추출                       │
 │  · 레퍼런스 이미지 → 색상·소재·조명 분석 (2-B-3)              │
 │  · 경쟁사·시장 트렌드 검색                                      │
 └──────────────────────────┬──────────────────────────────────────┘
                            │ 분석 결과 텍스트
                            ▼
 ┌─────────────────────────────────────────────────────────────────┐
 │  STEP 2. Claude — 문서 생성 (오늘 Block 2의 핵심)              │
 │                                                                 │
 │  기획팀                 디자인팀              공무팀            │
 │  · PLANNING 챕터        · 존 컨셉 텍스트      · 현장 보고서    │

 │  · 컨셉 3방향           · DESIGN DIRECTION    · 공문 변환      │
 └──────────────────────────┬──────────────────────────────────────┘
                            │ 제안서 텍스트
              ┌─────────────┴──────────┐
              │                        │
              ▼                        ▼
 ┌────────────────────────┐  ┌─────────────────────────────────────┐
 │  STEP 3. ChatGPT       │  │  STEP 3. Genspark                   │
 │  컨셉 이미지 생성      │  │  슬라이드 자동화                    │
```
