## 1. 결과물 공유
### 1-1. 왜 공유하는가
각자 다른 트랙을 했지만 **도구와 원리는 전부 같음.** 다른 사람의 방법이 내 업무에 그대로 쓰이는 경우가 많음.





그 사람이 만든 것

내 업무에 이렇게 쓰임




카드뉴스 5컷 톤 맞추기

소식탭 시리즈 게시물, 매장 발송 공지




메뉴판 텍스트 레이어 분리

가격표·POP·안내판 전부 동일




쇼츠 카메라 무브

완성한 포스터를 영상으로 재활용




인테리어 레퍼런스 분석

브랜드 톤을 언어로 정리하는 모든 작업




프롬프트 생성 Gem

업무별로 하나씩 만들면 됨


⚠️ **오늘 공유의 목적은 자랑이 아님.** 다음 주에 쓸 방법을 하나 이상 가져가는 것임.
### 1-2. 공유 방식 — 1인 4분
```plain text
[1분] 무엇을 만들었나
      결과물을 화면에 띄우고 용도를 한 줄로

[1분] 어떻게 만들었나
      쓴 도구와 순서
      ⚠️ 예쁜 결과보다 '순서'를 말할 것

[1분] 어디서 막혔나
      ⚠️ 이게 가장 중요함
      실패한 것, 잘 안 된 것, 포기한 것

[1분] 질문·의견
```
💡 **"어디서 막혔나"에 시간을 쓸 것.** 잘된 것은 혼자 알아도 되지만, 막힌 지점은 다른 사람도 반드시 만남.
⚠️ **여러 사람이 같은 곳에서 막혔다면 그건 개인 실력 문제가 아님.** 하네스에 구멍이 있다는 뜻이므로, 그 부분을 문서로 남겨야 함.

## 2. 자동화 설계 (30분)
### 2-1. 자동화는 3단계로 감
⚠️ **오늘 한 것은 이미 2단계임.** 3단계로 바로 뛰지 않음.
```plain text
[1단계] 수동
  매번 처음부터 만듦
  프롬프트도 매번 새로 씀
  → 결과가 매번 다름

        ↓ 오늘 여기까지 옴

[2단계] 표준화 (템플릿·자산화)
  고정(스타일 블록·템플릿)과 변수(문구·배경)를 분리
  프롬프트 생성 Gem이 초안을 써줌
  → 시간이 크게 줄고, 누가 해도 같은 결과가 나옴

        ↓ 다음 단계

[3단계] 자동화
  반복되는 트리거를 GAS·Make.com으로 연결
  → 사람은 검토와 판단만
```
> **⚠️ 자동화의 전제는 표준화임.표준화되지 않은 것을 자동화하면, 잘못된 것이 빠르게 반복됨.**
💡 오늘 2단계를 끝냈기 때문에 이제 3단계를 설계할 수 있음. **순서를 건너뛰면 안 되는 이유가 이것임.**
### 2-2. 자동화되는 것과 안 되는 것





자동화 가능

사람이 해야 함




정해진 시각에 발송

무엇을 만들지 결정




시트의 값을 읽어 문구 생성

방향 선택 (A·B·C 중 무엇)




완성물을 폴더에 저장

**할루시네이션 검수**




담당자에게 알림

**가격·날짜·메뉴명 최종 확인**




같은 템플릿에 문구만 교체

톤이 브랜드에 맞는지 판단


⚠️ **검수는 절대 자동화하지 않음.** AI가 잘못 만든 이미지가 자동으로 매장에 발송되면, 실수가 100배 빠르게 퍼짐.
> **자동화는 "만드는 시간"을 줄이는 것이지, "확인하는 시간"을 줄이는 것이 아님.**
### 2-3. 이미 배운 도구로 연결됨
4·5회차에서 배운 것이 여기서 다시 등장함.
```plain text
GAS (4회차)
  구글시트에서 값을 읽고, 조건에 따라 처리하고, 메일을 보냄

Make.com (5회차)
  시트·메일·텔레그램·드라이브를 조건에 따라 연결
  정해진 시각에 자동 실행
```
**연결 예시 — 동기부여 문자 이미지**
```plain text
[현재]
매일  임원이 주제 지정 → ChatGPT 초안 → 피드백 → 최종 → 발송
      = 매일 반복

[2단계 — 오늘 만든 것 적용]
주 1회  Claude로 문구 10개 → AI Studio 배경 10장 (같은 스타일 블록)
        → 미리캔버스 템플릿 10개 복제 → 완성
        → 구글드라이브에 저장 + 구글시트에 발송일 지정
      = 주 1회 30분

[3단계 — 자동화]
Make.com  매일 정해진 시각에 시트를 확인
          → 오늘 날짜의 이미지·문구를 찾아 발송
      = 사람이 하는 일: 주 1회 만들고 검수하는 것뿐
```
⚠️ **네이버 플레이스 소식탭은 자동 게시가 어려움.** (공개 API가 없음) 이런 경우는 \*\*"게시 직전까지 자동화"\*\*하고 마지막 업로드만 사람이 함.
⚠️ **확인 필요:** 위 연결의 실제 구현 가능 여부는 도구별 지원 범위에 따라 달라짐. 10\~12회차 프로젝트에서 실제로 붙여봄.

## 3. 하네스 최종 점검
1권 1-5에서 하네스 다섯 가지를 말했음. 오늘 다섯 가지가 다 채워졌는지 확인함.





요소

오늘 만든 것

확인




① 자료

브랜드 에셋 폴더 + 레퍼런스 세트

✅




② 지침

스타일 블록 (마스터 프롬프트)

✅




③ 도구

프롬프트 생성 Gem + 미리캔버스 템플릿

✅




④ 절차

발산→수렴, 체이닝, 4단계 파이프라인

✅




⑤ 검토

할루시네이션 검수 체크리스트

✅


### 3-1. 점검 질문 하나
> **"내가 내일 휴가를 가고 다른 사람이 이 일을 대신한다면, 같은 톤의 결과물이 나오는가?"**
```plain text
□ 다른 사람이 브랜드 이미지를 어디서 찾을지 아는가        (① 자료)
□ 브랜드 톤이 문서로 적혀 있는가                          (② 지침)
□ 그 사람이 프롬프트를 처음부터 쓰지 않아도 되는가        (③ 도구)
□ 어떤 순서로 작업할지 적혀 있는가                        (④ 절차)
□ 결과물이 잘못됐는지 판단할 기준이 있는가                (⑤ 검토)
```
⚠️ 하나라도 비어 있으면 그 지점에서 결과물이 사람마다 달라짐.
### 3-2. 뼈대와 도구를 구분함
⚠️ **오늘 배운 도구는 6개월 뒤에 바뀔 수 있음.** 그래도 뼈대는 남음.
```plain text
바뀌지 않는 것 (뼈대)
  - AI는 배경까지, 텍스트는 레이어로
  - 고정(스타일)과 변수(콘텐츠)를 분리
  - 유지할 것을 바꿀 것보다 길게
  - 발산으로 방향 잡고 수렴으로 완성
  - 최종 검토는 사람이
  - 자동화의 전제는 표준화

바뀌는 것 (도구·수치)
  - 어떤 모델이 가장 좋은가
  - 무료 한도가 얼마인가
  - 워터마크가 붙는가
  - 클릭 경로가 어디인가
```
💡 **뼈대는 저장하고, 도구는 갈아끼움.** 새 모델이 나와도 처음부터 다시 배우지 않아도 되는 이유임.

## 4. 오늘 반드시 손에 남아야 하는 것
```plain text
□ 스타일 블록 1개          → 프롬프트 라이브러리
□ 프롬프트 생성 Gem 1개    → Gemini
□ 템플릿 또는 양식 1개     → 미리캔버스 / 노션
□ 완성물 1건               → 드라이브 99_완성물_아카이브
□ 자동화 설계 워크시트     → 10~12회차 프로젝트의 출발점
```
⚠️ **완성물을 저장할 때 프롬프트를 함께 저장할 것.** 이미지만 남기면 "이거 어떻게 만들었더라"가 반복됨.

## 7. 체크 — 8회차를 마치며
✅ 다른 사람의 방법 1개 이상을 내 업무에 가져왔음
✅ 여러 사람이 공통으로 막힌 지점을 기록했음
✅ 자동화가 3단계로 간다는 것을 이해했음 (수동 → 표준화 → 자동화)
✅ **자동화의 전제가 표준화라는 것을 안다**
✅ 검수는 자동화하지 않는다는 원칙을 안다
✅ 자동화 설계 워크시트를 작성했음
✅ 월 절감 시간을 숫자로 적었음
✅ 하네스 5요소가 다 채워졌는지 점검했음
✅ 오늘 만든 자산 5개를 전부 저장했음
