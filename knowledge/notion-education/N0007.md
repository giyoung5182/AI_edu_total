### 🔧 AI 프롬프트 엔지니어링 진화의 3단계
> 💡 이 개념을 알면 오늘 교육의 RCTCK·멀티AI 협업 구조가 왜 나왔는지 이해됩니다.
AI를 잘 쓰는 방법론은 지금까지 세 단계로 진화해 왔습니다.

<br>          AI 활용 방법론의 진화: 3세대<br><br>1세대: 프롬프트 엔지니어링 (Prompt Engineering)<br>       핵심 질문: "무엇을 시킬 것인가?"<br>       방법: AI에게 명령을 어떻게 쓸지 설계<br>       한계: 좋은 명령만으로는 복잡한 작업 불가능<br><br>                      ↓<br><br>2세대: 콘텍스트 엔지니어링 (Context Engineering)<br>       핵심 질문: "무엇을 보여줄 것인가?"<br>       방법: AI가 판단할 맥락(배경정보·자료)을 설계<br>       = 오늘 배우는 RCTCK의 K(Knowledge) 개념<br>       한계: 맥락이 좋아도 실행 환경이 없으면 한계<br><br>                      ↓<br><br>3세대: 하네스 엔지니어링 (Harness Engineering)<br>       핵심 질문: "AI가 실제로 일할 수 있는 환경을 어떻게 만들 것인가?"<br>       방법: AI를 둘러싼 도구·구조·작업흐름 전체를 설계<br>       = 오늘 배우는 멀티AI 협업 파이프라인의 개념

### 하네스 엔지니어링이란 구체적으로 무엇일까?
AI에게 "전시 부스 제안서 만들어줘"라고 시켰다고 상상해보세요.
❌ 프롬프트만 잘 쓰면 되는가? → 아닙니다<br><br>AI가 실제로 잘 작동하려면 다음이 모두 필요합니다:<br>- 어떤 도구를 쓸 수 있는지 (Gemini? ChatGPT? 둘 다?)<br>- 어떤 자료를 먼저 참조해야 하는지 (클라이언트 브리프)<br>- 중간에 막히면 어떻게 다시 시도할지 (체이닝 전략)<br>- 결과물을 누가 어떻게 검토할지 (사람이 최종 확인)<br>- 각 단계에서 어떤 AI가 무엇을 담당할지 (역할 분담)<br><br>→ 이 전체 구조를 설계하는 것이 하네스 엔지니어링입니다.
OpenAI와 Anthropic 모두 이렇게 말합니다:
"좋은 모델만 있다고 좋은 결과가 나오는 것이 아니다.<br> 모델이 일할 수 있는 환경과 구조가 함께 있어야 한다."<br><br>"Humans steer. Agents execute."<br> 사람은 방향을 정하고, AI는 실행을 맡는다.<br><br>→ AI 모델이 똑똑한 신입사원이라면,<br>   하네스는 그 사원이 일할 수 있게 마련된 회사의 업무 환경입니다.<br>   업무 매뉴얼, 자료 정리, 사용 도구, 검토 기준이 모두 갖춰져야<br>   신입사원도 제 실력을 발휘할 수 있습니다.
**오늘 교육에서 배우는 것들이 곧 하네스입니다:**
RCTCK 프레임워크    → AI에게 줄 맥락과 역할 구조 설계<br>멀티AI 파이프라인   → 각 AI가 잘하는 단계에 배치하는 워크플로우<br>체이닝 전략         → 결과가 막혔을 때 다시 시도하는 방법<br>황금 프롬프트 3종   → 도구별 최적화된 작업 구조<br><br>→ 이 모든 것을 갖추면, 여러분이 AI의 하네스를 잘 설계한 것입니다.
> 💡 **하네스 엔지니어링의 핵심 교훈:**<br>더 똑똑한 AI를 찾는 게 아니라, AI가 제대로 일할 수 있는 환경을 만드는 것이 중요합니다.<br>그리고 AI 모델이 발전할수록 하네스도 함께 진화해야 합니다.

## 🔬 3. Part 0. 왜 지금까지 AI가 답답했는가? — 연구가 밝힌 진짜 이유

> Exploration vs. Fixation: Scaffolding Divergent and Convergent Thinking for Human-AI Co-Creation with Generative Models -
### 3-1. "조기 수렴(Early Convergence)" — AI가 창의성을 막는 구조적 문제
막스플랑크 소프트웨어 시스템 연구소가 2026년 발표한 연구 결과입니다. 24명의 실제 사용자를 대상으로 ChatGPT 단독 사용과 HAICo 방식 사용을 비교했을 때, 결정적인 문제가 발견됐습니다.
```plain text
일반적인 AI 사용 패턴의 함정:

사용자가 ChatGPT에 "전시 부스 이미지 만들어줘" 입력
         ↓
AI가 즉시 완성된 이미지 생성
         ↓
사용자가 그 이미지에 갇혀버림 (디자인 고착화)
         ↓
"조금 수정해줘"만 반복 → 처음 방향에서 벗어나지 못함
         ↓
결과물의 창의성 ↓, 다양성 ↓, 참신성 ↓

━━ 이것이 '조기 수렴(Early Convergence)' 문제 ━━
```
> 💡 **연구 결과:** HAICo 방식(발산 먼저 → 수렴 나중)을 쓴 참가자는 ChatGPT 단독 사용자보다 **참신성 점수 33%, 이미지 다양성 33% 더 높은** 결과물을 만들었습니다.
---
### 3-2. "구상 간의 간극(Vision Gap)" — 머릿속 그림이 안 나오는 진짜 이유
```plain text
머릿속에 있는 것:     "고급스럽고 미래적인 느낌의 자동차 전시 부스"
                              ↓
AI에게 전달하는 것:   "세련된 자동차 전시 부스 이미지 만들어줘"
                              ↓
AI가 생성하는 것:     (평범한 흰 바탕의 자동차 전시 이미지)
                              ↓
사용자 반응:          "이게 아닌데… 근데 뭐가 문제인지 모르겠어요"
```
이 간극을 메우는 방법이 바로 **4요소 파라미터**와 **프롬프트 체이닝**입니다. 오늘 이걸 정확히 배웁니다.
---
### 3-3. 오늘 교육의 해결 전략 — HAICo 워크플로우를 참고해보자!
```plain text
❌ 기존 방식: 입력 → 결과 → 약간 수정 → 결과 (반복)
              ↑ 이 구조에서 벗어나지 못하면 항상 60% 수준

✅ HAICo 방식:
  [발산] 먼저 다양한 방향을 넓게 탐색
         → 컨셉 A · B · C 동시에 생성
         → 가장 유망한 방향 선택
  [수렴] 선택된 방향을 단계적으로 정교화
         → 재질 정교화 → 조명 정교화 → 분위기 완성
         → 90%+ 품질 달성
```

### 4-2. ChatGPT 완전 기초 — 모델 구조와 작동 원리
#### 🤖 ChatGPT란 무엇인가?

**\[A형\] GPT 탐색 — "광고" 키워드로 기존 전문 GPT 찾기**

## 🚀 5. Part 2. 프롬프트 중급 — AI를 제대로 다루는 법

### 5-1. 프롬프트란 무엇인가? — 기초부터 중급까지
#### **프롬프트의 정의**
프롬프트(Prompt)는 AI에게 보내는 **지시문**입니다. AI는 여러분이 입력한 텍스트를 분석하여 그에 맞는 결과를 생성합니다. **프롬프트의 품질이 결과의 품질을 100% 결정합니다.**
```plain text
나쁜 프롬프트의 특징:          좋은 프롬프트의 특징:
━━━━━━━━━━━━━━━━━━━━━         ━━━━━━━━━━━━━━━━━━━━━━━
• 모호하고 추상적              • 구체적이고 명확함
• 맥락 정보 없음               • 배경 맥락 제공
• 원하는 형식 미지정           • 출력 형식 명시
• 한 문장으로 모든 것 요구     • 단계별로 나눠서 요청
• 수식어만 나열                • 파라미터 구조로 정리

예시:
❌ "멋진 전시 부스 이미지 만들어줘"
✅ "자동차 브랜드 전시 부스 이미지 만들어줘.
   스타일: 럭셔리 미니멀.
   재질: 흰 대리석 바닥, 무광 알루미늄 벽면.
   조명: 따뜻한 3000K 스포트라이트, 간접 LED.
   구도: 눈높이 와이드샷, 24mm 렌즈.
   화질: 4K 포토리얼리스틱."
```
#### **5-1-A. 🧩 RCTCK 프레임워크 — AI가 생각하고 행동하는 방식을 결정하는 5가지 핵심 요소**
> 💡 이 섹션이 오늘 교육에서 가장 중요한 개념입니다. 이 5가지를 이해하면 어떤 AI 도구를 쓰든, 어떤 업무에서든 원하는 결과를 끌어낼 수 있습니다.
AI에게 요청을 보낼 때, 많은 분들이 "그냥 부탁하면 되는 거 아닌가요?"라고 생각합니다. 하지만 AI는 단순히 명령을 실행하는 기계가 아닙니다. AI는 **여러분이 제공하는 맥락의 총합**을 바탕으로 결과를 만들어냅니다. 그 맥락을 구성하는 핵심 요소가 바로 **RCTCK 5요소**입니다.
```plain text
┌─────────────────────────────────────────────────────────────┐
│           AI 출력 품질을 결정하는 RCTCK 5요소                 │
│                                                             │
│   R  →  Role        역할 / 페르소나                          │
│   C  →  Context     배경 / 맥락                             │
│   T  →  Task        과업 / 할 일                            │
│   C  →  Constraints 제약 조건 / 규칙                         │
│   K  →  Knowledge   지식 / 참조 자료                         │
│                                                             │
│   이 5개를 모두 채울수록 AI의 결과물 품질이 극적으로 향상됩니다  │
└─────────────────────────────────────────────────────────────┘
```
#### 🎭 요소 1. Role — AI에게 부여하는 전문가의 가면
AI는 역할을 부여받으면 그 역할에 맞는 **전문적인 언어, 관점, 판단 기준**으로 응답합니다. 역할 없이 묻는 것과 역할을 준 후 묻는 것은 결과물의 깊이가 완전히 달라집니다.
```plain text
역할 부여의 효과:

❌ 역할 없이:
"전시 부스 컨셉을 제안해줘"
→ AI가 일반적이고 교과서적인 답변을 생성
→ 우리 회사의 맥락, 업계 깊이 없음

✅ 역할 부여 후:
"너는 국내외 100개 이상의 전시 프로젝트를 총괄한
 20년 경력의 전시 디자인 크리에이티브 디렉터야.
 럭셔리 브랜드와 테크 기업의 전시 공간을 전문으로 하며,
 클라이언트 설득력 있는 컨셉 개발이 특기야."
→ AI가 전문가 시각으로 깊이 있는 제안 생성
→ 업계 용어, 실무 경험에서 나오는 조언 포함
```
**전시 디자인 회사용 Role 라이브러리 — 복사해서 바로 사용**
```plain text
[기획·전략팀용]
너는 국내외 브랜드 전시 공간 기획을 전문으로 하는
시니어 전략 기획자야. 클라이언트 브리핑 → 컨셉 개발 →
제안서 완성까지 전 과정을 담당하며, 클라이언트 설득을 위한
시각 자료와 스토리텔링 구성이 특기야.

[디자인팀용]
너는 3D 공간 디자인과 렌더링을 전문으로 하는
시니어 공간 디자이너야. V-Ray, Unreal Engine 수준의
렌더링 감각을 갖고 있으며, 재질의 질감·조명의 물리적 특성·
공간 스케일감을 언어로 정밀하게 기술하는 능력이 뛰어나.

[공무·시공팀용]
너는 전시·인테리어 시공 현장 관리를 전문으로 하는
시니어 공무 PM이야. 현장 점검, 공정 관리, 하자 식별,
고객사 커뮤니케이션 문서 작성에 20년 이상의 경험이 있어.
한국 전시 업계의 공정 표준과 업무 프로세스를 완벽히 이해해.
```
> 💡 **실무 팁:** Role은 대화 시작 시 딱 1번만 설정하면 됩니다. 이후 모든 대화에 자동으로 적용됩니다. 단, 새 채팅창을 열면 다시 설정해야 합니다.

#### 🌍 요소 2. Context — AI에게 전달하는 배경과 맥락
Context는 AI가 **현재 상황을 이해하고 적절한 판단을 내리기 위해 필요한 모든 배경 정보**입니다. "왜 이걸 해야 하는가", "어떤 상황에서 쓰이는가"를 알려주는 것입니다.
```plain text
Context가 없을 때 vs 있을 때:

❌ Context 없이:
"전시 부스 이미지 만들어줘"
→ AI가 임의로 일반적인 전시 부스 생성

✅ Context 포함:
"우리는 국내 전시 디자인 전문 회사야.
이번 달 말에 독일 자동차 브랜드의 서울 모터쇼
제안 PT가 있어. 클라이언트는 '미래적이고 정밀한,
그러나 한국 감성이 가미된' 공간을 원하고 있어.
예산은 중상급, 부스 규모는 약 200sqm야.
이 맥락에서 제안서 첫 페이지에 들어갈
무드보드 이미지를 만들어줘."
→ 클라이언트 특성, 예산, 규모, 용도에 맞는 정확한 결과 생성
```
**Context 작성 체크리스트**
```plain text
Context를 쓸 때 아래 항목을 채워보세요:

□ 우리 회사/팀이 어떤 일을 하는 곳인가?
□ 이 작업의 최종 목적은 무엇인가?
□ 결과물을 누가 보는가? (클라이언트? 내부 팀? 상급자?)
□ 어떤 상황에서 사용되는가? (PT? 제안서? 현장 보고?)
□ 관련 제약 사항이 있는가? (예산, 규모, 납기 등)
□ 클라이언트나 대상의 특성은? (업종, 톤앤매너, 선호 스타일)
```

#### 📋 요소 3. Task — AI가 수행해야 할 구체적이고 단계적인 과업
Task는 **AI에게 정확히 무엇을 해야 하는지 단계별로 지시**하는 것입니다. 막연한 요청 대신, 번호를 붙여 순서대로 지시하면 AI가 누락 없이 완수합니다.
```plain text
Task 작성의 핵심: 번호를 붙여 단계별로 분해하기 / COT 적으로 사고해 (LET'S THINK STEP BY STEP)

❌ 막연한 Task:
"전시 제안서에 쓸 내용 만들어줘"

✅ 단계별 Task:
"다음 순서로 작업해줘:
1단계. 클라이언트 브리프(아래 첨부)에서 핵심 키워드 3개 추출
2단계. 추출된 키워드를 바탕으로 공간 컨셉 방향 A·B·C안 제안
3단계. 각 안에 대해 DALL-E 이미지 생성용 영문 프롬프트 작성
4단계. 각 안의 클라이언트 설득 포인트 2줄씩 한국어로 작성
5단계. 작업 완료 후 최우선 추천 안과 이유 1줄 제시"
```

#### 🚧 요소 4. Constraints — AI 출력을 통제하는 제약 조건과 규칙
Constraints는 **AI에게 해도 되는 것과 하면 안 되는 것을 명확히 정의**하는 것입니다. 이것이 없으면 AI가 예상 밖의 방향으로 흘러갑니다.
```plain text
Constraints의 3가지 유형:

① 형식 제약 (Format Constraints)
   "답변은 반드시 표 형식으로"
   "각 항목은 3줄 이내로"
   "영문 프롬프트와 한국어 설명을 함께 제공할 것"
   "불릿 포인트를 사용하지 말고 번호로 구분할 것"

② 내용 제약 (Content Constraints)
   "이미지에 한글 텍스트를 절대 넣지 말 것"
   "실존하는 브랜드 로고나 상표는 언급하지 말 것"
   "클라이언트 예산 정보는 외부 표현 없이 내부용으로만"
   "미확인 공정 사항에 대해서는 추정임을 명시할 것"

③ 톤·매너 제약 (Tone Constraints)
   "전문적이고 격식 있는 어조로"
   "클라이언트에게 직접 보낼 수 있는 공문체로"
   "팀 내부 공유용 캐주얼한 어조로"
   "초보자도 이해할 수 있는 쉬운 표현으로"
```
**전시 디자인 업무용 Constraints 표준 세트**
```plain text
[이미지 생성 공통 Constraints]
• 이미지에 한글·중국어 텍스트 절대 금지
• 실존 브랜드 로고, CI, 상표 재현 금지
• 실존 인물 얼굴 생성 금지 (실루엣/뒷모습으로 대체)
• 브랜드 시그니처 자리는 빈 패널로 남길 것

[제안서 텍스트 Constraints]
• 클라이언트명 노출 시 익명 처리 (A사, B브랜드 등)
• 확정되지 않은 내용은 "(검토 필요)" 표시
• 전문 용어 사용 시 괄호 안에 한국어 설명 병기
• 분량: 항목당 200자 이내, 전체 1페이지 분량

[현장 보고서 Constraints]
• 현장 기밀 정보(계약금액, 클라이언트 내부 정보) 미포함
• 이슈 분류는 반드시 HIGH/MED/LOW 3단계로만
• 작성자 이름은 항상 끝에 명시
• 날짜 형식: YYYY년 MM월 DD일로 통일
```

### 5-3. Gemini 중급 프롬프트 전략 — 분석·자동화 특화
#### 🎯 전략 1: 구조화된 분석 요청 — 정확한 출력 형식 지정
Gemini에게는 원하는 출력 형식을 명확히 지정할수록 좋습니다.
```plain text

[항목 1]: [설명]

[출력 형식]: [표/목록/보고서 등]"

━━ 공간 이미지 분석 최적 프롬프트 ━━

아래 항목을 순서대로 정리해서 답변해줘:

① 전체 디자인 컨셉 (한 문장, 20자 이내)
② 주요 재질 3가지 (한글 + 영문 병기, 각각 특성 1줄)
③ 색상 팔레트 (HEX 코드 + 색상명)
④ 조명 특성 (색온도 추정, 방향, 그림자 특성)

⑥ DALL-E 재현용 영문 프롬프트 키워드 (10개, 쉼표로 구분)
⑦ 이 스타일의 강점과 약점 (각 2줄)
```

① 공간 유형과 추정 규모
