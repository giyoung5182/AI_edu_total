## 7-2. 그런데 AI에게는 이 순서를 생략합니다
같은 분이 AI에게 같은 일을 시킬 때는 이렇게 합니다.
```plain text
"수업 계획 정리해줘"
```
이 한 문장으로 끝냅니다. 누가 볼 건지 안 알려주고, 얼마나 상세해야 하는지 안 정하고, 몇 차시분인지 범위도 안 정합니다.
> 💡 처음 온 실습생에게 "수업 계획 정리해놔" 한 마디만 던지고 완벽한 결과를 기대하는 것과 비슷합니다.
차이가 하나 있다면, **사람은 되물어보기라도 한다**는 겁니다.<br>"어떤 형식으로 드릴까요?" "지난번 양식대로 할까요?"
**AI는 안 물어봅니다.** 바로 만들기 시작하고, 빈 곳을 자기 판단으로 채웁니다.

### 수정을 시작하면 더 꼬입니다
"이 부분은 빼고, 이건 위로 올리고, 이 표는 따로 분리해줘."

```plain text

```

결국 여러 번 고치다가 "그냥 내가 처음부터 쓰는 게 낫겠다"는 결론에 이릅니다. 이 경험, 한 번쯤 있으실 겁니다.

## 7-5. 실행 단계의 원칙
가장 자주 어기게 되는 것이 실행 단계입니다.
> **한 단계씩 요청하고, 결과를 확인한 뒤에 다음으로 넘어갑니다.**
그리고 1교시에서 본 세 요소를 다시 떠올려주세요.
```plain text
① 무엇을 할지
② 지금 단계에서 할 것
③ 하지 말아야 할 것    ← 이게 핵심
```
**"하지 말아야 할 것"이 없으면** AI는 계획과 실행을 한 번에 해버립니다. 그러면 확인할 기회가 사라지고, 나중에 되돌리기 어려워집니다.
## 7-6. 한 걸음 더 — AI가 스스로 검사하게 하기
여기까지가 "내가 확인하고 다시 시키는" 방식입니다. 그런데 그 확인 자체를 **AI에게 넘기는 방법**도 있습니다.
### Loop 이란
한 번 답을 받고 끝내는 게 아니라, **스스로 검사하고 고치게** 만드는 구조입니다.
```plain text
실행  →  기준으로 검사  →  부족한 곳 수정  →  다시 실행
```







그냥 시키기

Loop




흐름

요청 → 결과 → 끝

실행 → 검사 → 수정 → 재실행




사람의 역할

결과를 보고 **내가 고침**

**기준을 주고** AI가 고치게 함




좋은 상황

간단한 요청

결과물이 중요할 때


### 필요한 것 세 가지
```plain text
① 무엇을 만들지
② 좋은 결과인지 판단할 기준
③ 언제 멈출지
```
②번이 핵심입니다. **기준이 없으면 AI가 뭘 고쳐야 할지 모릅니다.**
### 오후에 쓸 형태
오늘 오후 제작 시간에 이렇게 쓰실 수 있습니다.
```plain text
한 번에 끝내지 말고 아래 순서로 해줘.

1. 먼저 초안을 만들어줘.
2. 아래 기준으로 스스로 검사해줘.
   - 초등 3학년이 읽을 수 있는 낱말인가
   - 글자가 충분히 큰가
   - 휴대폰에서 봐도 잘리지 않는가
3. 부족한 부분을 찾아서 알려줘.
4. 그 부분만 고쳐줘.
```
> 💡 **언제 쓰면 좋은가**<br>아래 중 두 개 이상이면 Loop이 유리합니다.
```plain text
□ 결과물이 중요하다 (학생에게 보여줄 것이다)
□ 내가 매번 같은 부분을 고치고 있다
□ 좋고 나쁨을 판단할 기준이 있다
□ 초안보다 검토와 수정이 더 오래 걸린다
```

## 7-7. 검토 단계 — 흔들리는 부분을 적어둡니다
결과가 완벽하게 나오는 경우는 거의 없습니다. 검토하면서 발견한 것을 메모해둡니다.
**막연한 메모 vs 쓸모 있는 메모**





❌ 막연함

✅ 구체적

"3학년이 뒷자리에서 못 읽는다"




"화면이 이상하다"

"항목이 다섯 개 넘으면 아래로 밀린다"




"말이 어렵다"

"'실행'이라는 낱말을 3학년이 모른다"


오른쪽처럼 적어두면 다음 요청이 훨씬 쉬워집니다. **그대로 옮겨 쓰면 되니까요.**

- 휴대폰에서도 손가락으로 끌 수 있다
