## 2-1. 프롬프트란 무엇인가?
```plain text
프롬프트 = AI에게 보내는 지시문

같은 AI + 같은 데이터 + 다른 프롬프트 = 완전히 다른 결과

AI 성능 차이 < 프롬프트 품질 차이

오늘 이 사실이 가장 중요한 배경 지식입니다.
```
### 나쁜 프롬프트 → 좋은 프롬프트 비교 4단계
```plain text
레벨 1 (최악):
"보고서 써줘"
→ AI가 모든 것을 임의로 결정 → 원하는 결과 확률 10%

레벨 2 (부족):
"충북 기업 현황 보고서 써줘"
→ 어떤 기업? 어떤 형식? 누가 볼 건지? AI가 모름

레벨 3 (보통):
"교육기관 33 월간 기업 현황 보고서를 공문서 형식으로 써줘"
→ 어느 정도 방향은 잡혔지만 출처·제약·형식 미지정

레벨 4 (좋음 — RCTC 적용):
"너는 충북 지역 경제 분석 전문가야.
 교육기관 33 기업지원부 담당자가 원장님께 보고할
 5월 기업 동향 요약 자료야.
 업로드한 통계 PDF를 분석해서 사업체 수, 시군별 현황,
 특이사항을 공문서 스타일 A4 1장으로 작성해줘.
 업로드된 자료에 없는 내용은 추측하지 말고
 '자료 없음'으로 표시해줘. 각 수치는 출처를 표시해줘."
→ AI가 역할·맥락·과업·제약 모두 이해 → 원하는 결과 확률 80%+
```

### 🎭 R (Role) 심화 — "역할"을 넘어 "페르소나"를 설계하라
> **핵심 인사이트**: R은 단순히 직함을 붙이는 것이 아닙니다.<br>AI에게 **경력, 전문 분야, 주요 프로젝트 경험, 말투, 태도**까지 구체적으로 설정할수록<br>결과물의 깊이와 정확도가 급격히 올라갑니다.
### Role 레벨별 비교 — 같은 요청, 다른 결과
```plain text
레벨 1 | 직함만 지정 (약함):
  "너는 분석가야."
  → AI: 매우 일반적인 내용 생성, 차별점 없음

레벨 2 | 전문 분야 지정 (보통):
  "너는 공공기관 데이터 분석 전문가야."
  → AI: 공공기관 맥락 반영, 어느 정도 전문적

레벨 3 | 경력 + 경험 지정 (좋음):
  "너는 공공기관 데이터 분석 경력 10년의 전문가야.
   지방 중소기업 지원 정책 성과 분석 프로젝트를 다수 수행했어."
  → AI: 지방 공기업 특성과 중소기업 지원 맥락 반영한 깊은 분석

레벨 4 | 경력 + 경험 + 말투 + 태도까지 (최강):
  "너는 공공기관 성과 분석 경력 15년의 수석 컨설턴트야.
   충청권 지방 공기업의 기업 지원 사업 성과 평가 프로젝트를
   10건 이상 수행했고, 원장·부원장급 보고 경험이 풍부해.
   결과물은 항상 수치 근거를 먼저 제시하고,
   간결하고 자신감 있는 어조로 작성해.
   불확실한 내용은 절대 포함하지 않아."
  → AI: 고위직 보고서 스타일, 근거 중심 서술,
         충청권 공기업 특성 깊이 반영
```
### Role 설계 5가지 요소
```plain text
요소 1 | 경력 연수 (숫자로 구체적으로)
  ❌ "전문가"
  ✅ "10년 이상 경력의 전문가"
  ✅ "공공기관 성과 분석만 15년 해온 수석 컨설턴트"

요소 2 | 전문 도메인 (좁을수록 좋음)
  ❌ "데이터 전문가"
  ✅ "지방 중소기업 지원 정책 성과 평가 전문가"
  ✅ "충청권 공공기관 예산 집행 분석 전문가"

요소 3 | 프로젝트 경험 (유사 맥락일수록 효과적)
  ❌ 없음
  ✅ "지방 공기업 기업지원사업 KPI 분석 보고서를 다수 작성했어"
  ✅ "원장님께 월간 경영 현황 보고서를 5년 이상 작성해온 경험이 있어"

요소 4 | 말투·어조 (결과물 스타일 결정)
  → 간결하고 자신감 있는 어조
  → 데이터 근거를 먼저 제시한 후 해석
  → 전문 용어는 쓰되 이해하기 쉽게 설명
  → 공문서 스타일, 3인칭 문어체

요소 5 | 태도·원칙 (신뢰도에 직접 연결)
  → "불확실한 내용은 절대 포함하지 않아"
  → "수치 없는 주장은 하지 않아"
  → "항상 데이터를 먼저 보고 결론을 내려"
  → "틀린 내용을 자신있게 말하느니 모르겠다고 해"
```

### Role이 결과물에 미치는 실제 차이
```plain text
같은 요청: "이 기업 지원 실적 데이터를 분석해줘"

Role 없을 때 AI 응답 (예시):
  "전체 지원 건수는 573건이며, 청주시가 가장 많습니다.
   달성률은 평균 91.5%입니다."
  → 수치 나열에 그침, 인사이트 없음

교육기관 맞춤 Role 적용 후 AI 응답 (예시):
  "상반기 전체 실적을 검토한 결과, 청주 편중 구조가
   핵심 리스크로 확인됩니다. 청주시 신청 비중이 56%로,
   이는 설정된 '지역 균형 지원' 목표와 상충합니다.
   특히 영동·보은·단양 3개 군의 달성률이 75% 미만으로,
   농촌 소규모 기업의 접근성 문제가 구조적으로 작용하고 있습니다.
   하반기에는 찾아가는 상담 강화와 목표치 재조정을 검토하시기 바랍니다."
  → 문제 진단, 원인 분석, 개선 방향까지 포함한 인사이트
```
#### 📋 C (Context) 심화 — "맥락"이 없으면 AI는 엉뚱한 상황을 상상한다
> **핵심 인사이트**: AI는 Context가 없으면 자기가 상황을 임의로 설정합니다.<br>내가 공공기관 담당자인지, 스타트업 마케터인지, 학생인지를 모르면<br>가장 일반적인 상황을 가정해서 일반적인 답변을 냅니다.<br>Context는 AI가 나의 상황에 맞게 답하도록 좌표를 찍어주는 역할입니다.
### Context 레벨별 비교
```plain text
레벨 1 | 없음 (최악):
  "보고서 써줘."
  → AI: 어떤 기관인지, 어떤 내용인지, 누가 볼 건지 모름
  → 완전히 일반적인 형식의 결과물 생성

레벨 2 | 기관명만 있음 (부족):
  "교육기관 33 보고서 써줘."
  → AI: 어떤 부서인지, 어떤 상황인지, 보고 대상이 누구인지 모름
  → 기관 이름만 들어간 일반적 보고서

레벨 3 | 상황 + 목적 있음 (좋음):
  "교육기관 33 기업지원부 담당자야.
   상반기 실적 점검 보고서를 원장님께 보고해야 해."
  → AI: 공공기관, 내부 보고 목적, 경영진 대상임을 이해
  → 공문서 스타일, 간결한 보고서 생성

레벨 4 | 상황 + 목적 + 독자 + 활용처까지 (최강):
  "교육기관 33 기업지원부 담당자야.
   상반기 실적 점검 보고서를 다음 주 월요일 원장님께 보고해야 해.
   원장님은 수치보다 '우리 기관이 잘 하고 있는가,
   뭘 바꿔야 하는가'에 관심이 많으셔.
   작년 같은 시기 대비 비교가 꼭 들어가야 하고,
   이 보고서는 이후 이사회 자료로도 활용될 예정이야."
  → AI: 독자의 관심사, 비교 기준, 후속 활용까지 파악
  → 경영진 눈높이에 맞는 인사이트 중심 보고서 생성
```
### Context에 담아야 할 5가지 요소
```plain text
요소 1 | 나는 누구인가 (소속·역할)
  ❌ 없음
  ✅ "교육기관 33 기업지원부 담당자야"
  ✅ "교육기관에서 청년 창업 지원 사업을 3년째 맡고 있어"

요소 2 | 지금 어떤 상황인가 (배경)
  ❌ 없음
  ✅ "이번 달 안으로 상반기 실적 보고서를 제출해야 해"
  ✅ "5개 팀에서 각기 다른 형식으로 데이터가 들어와서 정리가 안 된 상태야"

요소 3 | 결과물을 누가 보는가 (독자)
  ❌ 없음
  ✅ "원장님께 보고하는 내부 자료야"
  ✅ "충북 지역 중소기업 담당자들에게 보내는 공문이야"
  ✅ "이사회 보고 자료로 활용될 예정이야"

요소 4 | 이미 알고 있는 정보는 무엇인가 (사전 정보)
  ❌ 없음
  ✅ "청주 편중이 심하다는 건 이미 알고 있어. 이 부분에 집중해줘."
  ✅ "달성률 80% 미만인 사업이 3개라는 건 확인됐어."

요소 5 | 이 결과물이 어디에 쓰이는가 (활용처)
  ❌ 없음
  ✅ "내부 검토용이라 다듬어지지 않은 초안이어도 돼"
  ✅ "외부 공개 자료라 공식적인 표현이 필요해"
```

```plain text
📋 기업 지원 공문:
  "교육기관 33에서 충북 지역 중소기업에 보내는 안내 공문이야.
   수신 기업 담당자들은 AI나 지원 제도에 익숙하지 않은 분들이 많아.
   신청 절차가 복잡하면 포기하는 분들이 있어서
   가능한 한 쉽고 단계별로 설명하는 게 중요해."

🔍 설문 데이터 분석:
  "교육기관 33이 진행한 기업 지원 만족도 조사 결과야.
   응답자는 충북 지역 중소기업 대표·담당자 총 47명이야.
   이 분석 결과는 내년 사업 기획에 활용되고,
   예산 심의 자료에도 첨부될 예정이야."
```
#### 🎯 T (Task) 심화 — "과업"이 구체적일수록 원하는 결과가 처음부터 나온다
> **핵심 인사이트**: Task는 AI에게 주는 업무 지시서입니다.<br>지시가 모호하면 AI는 가장 무난한 결과를 냅니다.<br>번호 목록으로 구체적으로 쪼개면, 원하는 항목을 빠뜨리지 않고 순서대로 처리합니다.
### Task 레벨별 비교
```plain text
레벨 1 | 동사 하나 (최악):
  "분석해줘."
  → AI: 무엇을, 어떤 방식으로, 어떤 형식으로 분석할지 임의 결정
  → 예측 불가한 결과

레벨 2 | 목적어 있음 (부족):
  "이 데이터 분석해줘."
  → AI: 어떤 항목을, 어떤 형식으로 출력할지 임의 결정

레벨 3 | 항목 나열 (좋음):
  "시군별 지원 기업 수를 집계하고,
   달성률 순으로 정렬해서 표로 만들어줘."
  → AI: 요청한 항목과 형식은 맞추지만
       추가로 필요한 것들은 판단해서 넣음

레벨 4 | 번호 목록 + 형식 지정 + 출력 기준 (최강):
  "다음을 순서대로 작성해줘:
   1. 시군별 지원 기업 수 집계
      (형식: 표 / 컬럼: 순위·시군명·기업수·달성률)
   2. 달성률 90% 미만 사업 목록
      (형식: 번호 목록 / 미달 원인 1줄씩 포함)
   3. 전체 요약 3줄
      (문체: 공문서 스타일 / 수치 근거 포함)"
  → AI: 빠뜨리는 항목 없이, 지정한 형식 그대로 출력
```
### Task를 구체화하는 4가지 방법
```plain text
방법 1 | 번호 목록으로 쪼개기
  ❌ "정리하고 분석하고 요약해줘"
  ✅ "1. 데이터 정리 (날짜 형식 통일)
      2. 시군별 집계 (표 형식)
      3. 핵심 인사이트 3줄 요약"

방법 2 | 출력 형식 명시하기
  ❌ "지원 실적을 정리해줘"
  ✅ "지원 실적을 표로 정리해줘.

방법 3 | 분량·길이 지정하기
  ❌ "보고서 써줘"
  ✅ "A4 1장 이내 / 3줄 요약 / 항목당 2문장 이내"
  ✅ "원장님께 구두 보고할 1분 스크립트로 써줘"

방법 4 | 우선순위 지정하기
  ❌ "분석해줘"
  ✅ "가장 중요한 인사이트를 맨 위에 배치해줘"
  ✅ "달성률이 낮은 항목을 먼저 다루고, 잘 된 것은 뒤에 배치해줘"
```

<summary>💡 Task를 하나씩 쪼개기 힘들 때 — CoT(Chain of Thought) 기법</summary>
---
> **상황**: 요청해야 할 내용이 복잡하고 많은데,<br>하나씩 번호 목록으로 다 쪼개서 쓰기가 너무 번거로울 때가 있습니다.<br>이럴 때 쓰는 것이 **CoT(Chain of Thought, 생각의 사슬)** 기법입니다.
---
### CoT란 무엇인가
```plain text
일반 프롬프트 방식:
  사람이 모든 단계를 미리 쪼개서 지시
  → AI가 지시받은 순서대로만 실행
  → 단계를 빠뜨리면 결과도 빠짐

CoT 방식:
  AI에게 "스스로 단계를 나눠서 생각하면서 일해"라고 지시
  → AI가 스스로 필요한 단계를 설계하고 순서대로 실행
  → 복잡한 작업일수록 정확도와 완성도가 높아짐
```
CoT는 AI가 답을 바로 내놓는 것이 아니라, **생각하는 과정을 거치면서** 결과를 도출하게 만드는 방식입니다. 사람도 복잡한 문제를 풀 때 순서를 먼저 정리하고 하나씩 해결하는 것처럼, AI도 같은 방식으로 작동하게 유도합니다.
---
### 마법의 문장 — 이 문구 하나로 CoT가 작동합니다
```plain text
"단계별로 차근차근 생각하면서 작업해줘."

또는 영어 원문 그대로:
"Let's think step by step."
```
> 이 문장 하나를 프롬프트 끝에 붙이는 것만으로<br>AI의 답변 정확도와 논리 일관성이 크게 향상됩니다.<br>연구에 따르면 복잡한 추론 문제에서 정답률이 평균 40% 이상 향상되는 것으로 알려져 있습니다.
---
### 기본 CoT 적용 방법
```plain text
기존 방식 (단계를 내가 다 쪼개야 함):
  "1. 데이터 구조 파악
   2. 시군별 집계
   3. 달성률 계산
   4. 미흡 항목 원인 분석
   5. 보고서 초안 작성"
  → 내가 단계를 빠뜨리면 AI도 빠뜨림

CoT 방식 (AI가 스스로 단계를 설계):
  "이 데이터를 분석해서 원장님 보고용 요약 보고서를 만들어줘.
   단계별로 차근차근 생각하면서 작업해줘.
   각 단계를 시작하기 전에 '지금 [N단계]: [무엇을 할 것인지]'를
   먼저 밝히고 진행해줘."
   결과물을 항상 나에게 검토 받고, 내가 OK 하면 그 때 넘어가.
  → AI가 스스로 필요한 단계를 설계하고 하나씩 실행
```

### CoT 프롬프트 3가지 패턴
**패턴 1 \| 기본형 — 한 줄 추가만으로 효과**
```plain text
R: 너는 공공기관 성과 분석 전문가야.

C: 교육기관 33 기업지원부 담당자야.
   이번 상반기 기업 지원 실적 데이터야.

T: 이 데이터를 분석해서 원장님 보고용 요약 보고서를 만들어줘.

C: 업로드된 자료 안에서만 분석하고, 수치마다 출처를 표시해줘.

→ 단계별로 차근차근 생각하면서 작업해줘.
```
> 마지막 줄 하나만 추가했는데,<br>AI가 스스로 "1단계: 데이터 파악 → 2단계: 항목별 집계 → 3단계: 인사이트 도출 → 4단계: 보고서 작성" 순서를 설계해서 진행합니다.
---
**패턴 2 \| 단계 공개형 — AI가 각 단계를 밝히면서 진행**
> 복잡한 분석일 때, AI가 어떤 단계를 거치는지 눈으로 확인하고 싶을 때 사용합니다.<br>중간에 잘못된 방향으로 가면 바로 잡을 수 있어서 신뢰도가 높아집니다.
```plain text
R: 너는 공공기관 데이터 분석 전문가야.

C: 교육기관 33 만족도 조사 결과 데이터야.
   이 분석을 차년도 사업 기획에 활용할 예정이야.

T: 아래 데이터를 분석해서 개선 권고안을 포함한 보고서를 만들어줘.

C: 데이터에 있는 내용만 사용하고, 추측은 '(추정)' 표시.

→ 단계별로 차근차근 생각하면서 작업해줘.
   각 단계를 시작하기 전에 먼저 어떤 작업을 할 건지 한 줄로 밝히고 진행해줘.
   (예: "1단계: 전체 응답자 수와 문항 구성 파악")
```
---
**패턴 3 \| 검토 포함형 — 단계마다 스스로 검토하게 만들기**
> 수치 계산이 포함된 분석에서 오류를 최소화하고 싶을 때 사용합니다.<br>AI가 각 단계 결과를 스스로 한 번 더 확인하게 유도합니다.
```plain text
R: 너는 공공기관 성과 분석 경력 10년의 전문가야.

C: 교육기관 33 상반기 실적 데이터야.
   이 수치는 이사회 보고 자료에 활용되므로 정확도가 매우 중요해.

T: 사업별 달성률을 분석하고, 미흡 사업의 원인과 대응 방안을 포함한
   보고서 초안을 작성해줘.

C: 데이터에 있는 수치만 사용하고, 계산 방법을 함께 보여줘.

→ 단계별로 차근차근 생각하면서 작업해줘.
   각 단계가 끝나면 결과가 올바른지 스스로 한 번 검토한 뒤 다음 단계로 넘어가줘.
   검토 결과도 짧게 밝혀줘. (예: "검토 완료: 합계 573건, 원본 데이터와 일치")
```

### CoT vs 직접 쪼개기 — 언제 무엇을 쓸까





상황

추천 방식

이유




요청 내용이 단순하고 명확할 때

직접 번호 목록

빠르고 정확함




복잡한 분석인데 단계가 잘 안 떠오를 때

CoT 기본형

AI가 알아서 단계 설계




분석 과정을 눈으로 확인하고 싶을 때

CoT 단계 공개형

수치 계산이 많고 정확도가 중요할 때

CoT + 직접 쪼개기 병행

### 실전 팁 — CoT를 더 잘 쓰는 방법
```plain text
팁 1: 마지막에 붙여라
  CoT 문구는 프롬프트 맨 마지막에 붙일 때 효과가 가장 좋습니다.
  RCTC를 다 쓴 뒤 → 마지막 줄에 추가

팁 2: 중간에 멈추고 수정할 수 있다
  AI가 1단계 결과를 보여주면 거기서 "잠깐, 2단계는 이렇게 바꿔줘"
  라고 중간 개입이 가능합니다.
  한 번에 끝까지 달리게 두는 것보다 단계마다 확인하는 것이 안전합니다.

팁 3: "왜 그렇게 생각했는지"도 물어볼 수 있다
  AI가 결론을 냈을 때 "방금 그 결론에 도달한 이유를 단계별로 설명해줘"
  라고 추가 질문하면 근거를 확인할 수 있습니다.

팁 4: 결과가 이상하면 단계를 역추적한다
  "3단계 결과가 이상해. 3단계로 돌아가서 다시 분석해줘."
  처럼 특정 단계로 되돌아가서 재작업을 요청할 수 있습니다.
```

### 🔒 C (Constraint) 심화 — "제약"이 신뢰도를 결정한다
> **핵심 인사이트**: Constraint는 RCTC에서 가장 중요한 요소입니다.<br>특히 공공기관 업무에서는 틀린 수치가 보고서에 들어가는 순간<br>담당자의 신뢰도에 직접 영향을 미칩니다.<br>Constraint는 AI가 "하면 안 되는 것"을 명확히 선 긋는 역할입니다.<br>없으면 AI는 빈칸을 창의적으로 채웁니다.
### Constraint 레벨별 비교
```plain text
레벨 1 | 없음 (위험):
  "이 데이터로 충북 기업 현황 보고서 써줘."
  → AI: 데이터에 없는 내용도 일반 지식으로 채움
  → 출처 없는 수치, 추측성 내용이 섞여 들어올 수 있음

레벨 2 | 기본 제약만 있음 (보통):
  "...업로드된 자료에 있는 내용만 써줘."
  → AI: 소스 범위는 지키지만
       계산 오류나 불확실한 내용 표시는 안 함

레벨 3 | 소스 범위 + 불확실성 처리 (좋음):
  "...업로드된 자료에 있는 내용만 써줘.
   자료에 없는 내용은 '자료 없음'으로 표시해줘."
  → AI: 소스 범위 지키고 없는 내용은 표시함
       그러나 계산 방법, 출처 명시는 여전히 없음

레벨 4 | 소스 범위 + 불확실성 처리 + 출처 표시
         + 계산 근거 + 수정 금지 (최강):
  "...반드시 업로드된 자료 안에서만 답해줘.
   각 수치 옆에 (출처: 자료명) 표시 필수.
   자료에 없는 내용은 절대 추측하지 말고
```

차트 유형

언제 쓰는가

교육기관 활용 예

AI 요청 핵심 키워드




**꺾은선 (Line)**

시간 흐름에 따른 변화

월별 지원 신청 건수 추이, 연도별 달성률 변화

"추이", "변화", "트렌드"




**세로 막대 (Column)**

항목 간 크기 비교

사업유형별 지원 기업 수 비교, 월별 지원금액

"비교", "현황", "집계"




**가로 막대 (Bar)**

항목 수가 많을 때 비교

시군별 지원 기업 수 (11개 시군)

"순위", "랭킹", "시군별"




**파이 (Pie)**

전체 중 비율 시각화

지원유형별 비율, 시군별 신청 비중

"비율", "구성", "비중"




**혼합 (Combo)**

두 가지 다른 지표 동시 표현

신청 건수(막대) + 달성률(꺾은선)

"두 지표 동시에", "이중 축"




**산점도 (Scatter)**

두 변수 간 관계 파악

지원금액과 고용증가율 상관관계

"상관관계", "관계 분석"


### 좋은 차트의 4가지 조건
```plain text
조건 1: 제목이 결론을 말한다
  ❌ "시군별 기업 수"
  ✅ "청주 집중 현상: 청주시 지원 기업이 전체의 35% 차지"

조건 2: 색상이 의미를 가진다
  달성률 차트: 우수(파랑) / 양호(초록) / 미흡(주황/빨강)
  비교 차트: 강조할 항목은 진한 색, 나머지는 연한 색

조건 3: 레이블이 읽기 쉽다
  막대 위에 수치 표시 / 파이에 % 레이블 / 축 이름 명확히

조건 4: 불필요한 요소를 제거한다
  3D 차트 사용 금지 (왜곡 발생)
  너무 많은 색상 금지 (7개 이상)
  격자선은 연하게
```

# 📚 부록 D \| 예상 Q&A 30문항
### 🔴 신뢰도·보안
**Q1. AI가 틀린 정보를 말하는 건 어쩔 수 없는 건가요?**<br>구조적으로 줄일 수 있습니다. NotebookLM처럼 내 자료 안에서만 답하는 도구 사용, RCTC 프롬프트의 제약 조건 설정, 3단계 검증 루틴을 조합하면 신뢰도를 크게 높일 수 있습니다. 0%로 만들 수는 없지만 실무 활용 가능 수준으로 낮출 수 있습니다.
**Q2. 기관 보안 정책상 AI를 쓰면 안 되지 않나요?**<br>데이터 성격에 따라 다릅니다. 공개 통계·뉴스·공식 발표 자료는 사용 가능합니다. 직원 개인정보, 미공개 예산안, 내부 의사결정 문서는 절대 입력하면 안 됩니다. 오늘 실습은 모두 공개 데이터 또는 가상 더미 데이터입니다.
**Q3. ChatGPT에 입력한 내용이 AI 학습에 쓰이나요?**<br>기본 설정에서는 그렇습니다. 설정 → 데이터 컨트롤 → "모델 개선" OFF를 반드시 하세요. 또는 임시 채팅을 사용하면 대화 기록이 서버에 저장되지 않습니다.
**Q4. AI 생성 보고서를 상사에게 보고해도 되나요?**<br>AI는 초안 생성 도구입니다. 담당자가 검토·수정·서명한 최종본을 보고하세요. 필요시 "AI 도구로 초안을 작성하고 검증했습니다"라고 투명하게 설명하는 것이 좋습니다.
**Q5. 젠스파크에서 AI가 엑셀을 직접 수정하는 게 위험하지 않나요?**<br>중요 파일은 반드시 백업 후 작업하세요. 젠스파크는 AI 에이전트가 작업하는 과정을 화면으로 보면서 확인할 수 있습니다. 각 단계 완료 후 원본 데이터와 대조하는 습관이 중요합니다.
---
### 🔵 도구 사용법
**Q6. 스마트폰만 있어도 실습이 가능한가요?**<br>네, 오늘 메인 실습(NotebookLM)은 스마트폰 Chrome 브라우저에서 완전히 가능합니다. ChatGPT, Claude, Gemini도 모바일에서 정상 작동합니다.
**Q7. 한글(HWP) 파일을 AI에서 직접 쓸 수 없나요?**<br>현재 대부분의 AI는 HWP 파일을 직접 읽지 못합니다. HWP 내용을 복사해서 붙여넣거나 PDF로 변환 후 업로드하세요.
**Q8. Claude in Excel은 무료인가요?**<br>Claude 추가 기능은 Claude Pro 이상 구독자(\$20/월)에게 제공됩니다. 코파일럿 내 Claude는 M365 구독자에게 제공됩니다. 오늘 실습은 무료 도구만 사용합니다.
**Q9. NotebookLM이 답을 못 하면 어떻게 하나요?**<br>업로드된 소스에 해당 정보가 없기 때문입니다. 관련 자료를 추가로 업로드하거나, 딥 리서치 기능으로 인터넷에서 관련 자료를 수집해서 소스로 추가하면 됩니다.
**Q10. 젠스파크 무료 100 크레딧은 어떻게 아껴쓰나요?**<br>채팅에 2\~30 크레딧, 이미지 생성에 80+ 크레딧 소모됩니다. NotebookLM으로 사전 분석 자료를 만들어서 젠스파크에 붙여넣으면 분석 과정 크레딧을 크게 줄일 수 있습니다. 슬라이드 제작 전 채팅으로 먼저 분석하는 것도 효과적입니다.

### 🟡 프롬프트
**Q11. RCTC를 매번 다 쓰기엔 너무 길지 않나요?**<br>처음에는 익숙해지기 위해 전체를 쓰는 것을 권장합니다. 익숙해지면 자주 쓰는 프롬프트를 메모장에 저장해두고 복사·붙여넣기로 재사용하세요. 오늘 제공된 템플릿 8\~12종도 그대로 복사해서 쓸 수 있습니다.
**Q12. AI가 원하는 형식으로 답하지 않을 때는?**<br>"결과를 \| 항목 \| 수치 \| 달성률 \| 비고 \| 형식의 표로 다시 작성해줘"처럼 원하는 형식을 직접 보여주면 됩니다. 예시를 보여주는 것이 가장 효과적입니다.
**Q13. 프롬프트에 데이터가 너무 많으면 잘릴 수 있나요?**<br>네, AI마다 처리 가능한 입력 크기(컨텍스트 윈도우)가 있습니다. 데이터가 매우 많으면 샘플만 붙여넣고 "이 구조로 되어 있어"라고 설명하거나, 파일로 업로드하는 방식을 사용하세요.
**Q14. 영어로 질문하면 더 좋은 답변이 나오나요?**<br>한국어 특화 업무(공문서, 한국 통계 등)는 한국어로 질문하는 것이 더 맥락에 맞는 답변이 나옵니다. ChatGPT, Claude, NotebookLM 모두 한국어 성능이 충분합니다.

### 🟢 데이터 분석·시각화
**Q15. 엑셀에서 차트 만드는 법을 모르는데 AI가 대신 만들어줄 수 있나요?**<br>네, 두 가지 방법이 있습니다. ① Gemini AI Studio로 화면을 공유하면 AI가 현재 내 화면을 보면서 단계별로 안내해줍니다. ② ChatGPT Plus에 파일을 업로드하면 직접 차트를 생성해서 이미지로 줍니다.
**Q16. AI가 만든 차트를 한글 문서에 넣을 수 있나요?**<br>ChatGPT Plus가 생성한 차트 이미지를 다운로드해서 한글 문서에 삽입하면 됩니다. 또는 엑셀에서 AI의 도움으로 차트를 만든 후 복사해서 한글에 붙여넣기 할 수 있습니다.
**Q17. 피벗테이블 없이 AI로 집계할 수 있나요?**<br>네, ChatGPT Plus에 파일을 업로드하고 "시군별로 지원 기업 수를 집계해서 표로 만들어줘"라고 하면 됩니다. 결과가 맞는지 엑셀로 재확인하는 것을 잊지 마세요.
**Q18. VBA 코드를 ChatGPT로 만들었는데 오류가 나면?**<br>오류 메시지를 그대로 복사해서 "이 오류가 났어. 원인 찾아서 수정해줘"라고 ChatGPT에 붙여넣으면 됩니다. Windows + Shift + S로 오류 화면 캡처 후 이미지로 보내도 됩니다.
