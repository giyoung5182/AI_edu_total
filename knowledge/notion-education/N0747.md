# 3️⃣ 아이디어를 바로 서비스로

정리일: 2026-10-08 · 교육 에셋 N0747

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

**학습목표:** 문제 정의 → PRD 작성 → Genspark MVP 제작까지 전 과정을 직접 경험하고, 자신의 업무 아이디어를 작동하는 프로토타입으로 구현할 수 있다.

## 3️⃣ "아이디어를 바로 서비스로" — 바이브코딩 실습 (Genspark)
---

### 코딩을 배우는 게 아닙니다
"아이디어가 떠오르면 IT부서에 의뢰 → 2주 후 미팅 → 1달 후 프로토타입 → 수정 요청..."
이 과정이 익숙하실 겁니다.
2026년에는 이렇게 바뀝니다:
**아이디어 → 자연어로 설명 → 30분 후 작동하는 서비스**
이것이 "바이브코딩"입니다. 코딩을 배우는 게 아닙니다.
**아이디어를 직접 검증하는 힘**을 얻는 것입니다.


**바이브코딩이란:** 자연어로 "이런 서비스 만들어줘"라고 말하면 AI가 코드를 생성하여 작동하는 서비스를 만들어주는 방식입니다. 코딩 지식이 전혀 필요 없습니다.

---
# 0️⃣ 워밍업: 먼저 게임부터 만들어봅니다

본 실습에 들어가기 전, **"정말 코드 없이 되네"**를 먼저 체감해봅니다. 가장 빠르게 결과가 나오는 게 바로 **게임**입니다. 이 워밍업은 **ChatGPT**로 진행합니다.

### 따라하기 — ChatGPT에 그대로 입력
아래 프롬프트를 **그대로 복사**해 ChatGPT에 붙여넣으세요. (앞에서 배운 *역할·입력·제약조건·출력* 구조가 그대로 적용된 프롬프트입니다)
```markdown
### 역할
당신은 블리자드에서 10년동안 슈팅게임을 개발한 개발자 입니다.

### 입력
총알피하기 게임을 만들어 주세요.

### 제약조건
1. 목숨은 3개 입니다.
2. 탄막 슈팅 스타일로 만들어 주세요.
3. 디자인은 아주 힙하게 만들어 주세요.
4. 유명 슈팅게임을 모티브로 해주세요.
5. 앞,뒤, 좌, 우로 방향키를 사용하여 총알을 피할수 있게 해주세요.

### 출력
단일 html 코드로 작성합니다.
```

**이 워밍업의 포인트**
- 1\~2분이면 실제로 움직이는 게임이 나옵니다 → "이게 된다고?"를 먼저 경험
- 앞 모듈에서 배운 **역할·입력·제약조건·출력** 구조를 그대로 쓴 프롬프트입니다 → 제약조건 한 줄만 바꿔도 결과가 달라집니다
- 이어서 자연어로 바꿔보세요: "보스 몹을 추가해줘", "배경에 별을 떨어뜨려줘", "난이도를 올려줘"
- 핵심은 게임 자체가 아니라, **"말로 설명하면 만들어지고, 말로 고치면 바뀐다"**는 감각을 잡는 것입니다
→ 이 감각 그대로 다음 단계에서는 **Genspark**로 업무용 대시보드를 만듭니다

```markdown

### Step 2. PRD(Product Requirements Document) 작성
ChatGPT에 아래 프롬프트를 입력하면 PRD가 자동 생성됩니다:

너는 IT 프로덕트 매니저 10년차야.

## 지시
아래 아이디어를 Genspark(바이브코딩 플랫폼)에서 구현하기 위한
PRD(제품 요구사항 문서)를 작성해줘.

## 아이디어
- 서비스명: 현장 안전 리스크 검토 AI
- 대상 사용자: 건설 현장소장, 안전관리자
- 핵심 기능:
  1. 현장 조건 입력 (공종, 층수, 계절, 특이사항)
  2. 맞춤형 안전 점검 체크리스트 자동 생성
  3. 위험등급(상/중/하) 자동 분류
  4. PDF 다운로드

## 출력양식
- 형식: PRD 문서 (기능 목록, 화면 구성, 데이터 흐름)
- 분량: A4 2페이지 이내
- md 파일로 저장
```
### Step 3\~4. Genspark에서 MVP 제작 → 테스트
1. PRD를 Genspark에 붙여넣기
2. AI가 서비스를 자동 생성 (1\~3분 소요)
3. 미리보기에서 테스트
4. 수정 요청: "입력 필드를 드롭다운으로 바꿔줘", "색상을 교육기관 CI로 맞춰줘"
5. 2\~3번 반복하면 공유 가능한 수준으로 완성

**리더에게 이것이 중요한 이유:**
"됩니다 / 안 됩니다"를 **코드 없이 30분 안에** 확인할 수 있습니다.
IT부서 의뢰 전 PoC(개념검증)를 리더가 직접 수행할 수 있습니다.

**\[예시 A\] 완성 결과물을 먼저 확인하세요**
이 대시보드는 **완성된 예시 결과물**입니다. 강사가 결과물을 보여드리고, 어떤 PRD로 만들어졌는지 함께 확인합니다. 직접 만드는 실습은 뒤의 **개인 주제 실습**에 집중합니다.
→ 완성 HTML 파일을 다운로드해 직접 열어볼 수 있습니다. "이런 걸 코드 없이 만들 수 있다"를 눈으로 확인하는 것이 목적입니다.

**이 결과물을 만든 PRD 프롬프트** — 어떻게 지시하면 이런 결과가 나오는지 참고하세요

```javascript
## 역할
너는 IT 프로덕트 매니저 10년차야.

## 지시
아래 아이디어를 Genspark(바이브코딩 플랫폼)에서 구현하기 위한
PRD(제품 요구사항 문서)를 작성해줘.

## 아이디어
- 서비스명: 교육기관 프로젝트 현황 대시보드
- 대상 사용자: 교육기관 리더
- 핵심 기능:
  1. 현장별 공정률 입력 폼 (현장명, 계획 공정률, 실적 공정률)
  2. 전체 현황 대시보드 (바 차트 + 요약 수치)
  3. 지연 현장 자동 표시 (빨간색 강조 + 원인/대책 입력)
  4. 데이터 추가/수정/삭제 기능
  5. 디자인: 다크 모드, 깔끔한 리더 보고용 UI

## 출력양식
- 형식: PRD 문서 (기능 목록, 화면 구성, 데이터 흐름)
- 분량: A4 2페이지 이내
- md 파일로 저장
```

**이 PRD를 Genspark에 넣으면** 위 예시 대시보드 같은 결과물이 나옵니다. 이후는 자연어로 모양을 다듬습니다:
- "지연 현장을 빨간색으로 표시해줘"
- "상단에 전체 평균 공정률 수치를 크게 보여줘"
- "다크모드, 색상을 교육기관 CI(주황색)로 맞춰줘"
직접 만들어 보고 싶은 분은 따라 해보셔도 좋지만, 이 세션은 **"이런 걸 만들 수 있다"를 확인**하는 데 초점이 있습니다.

핵심 데이터를 입력하면 리더 보고용 주간 보고서가 자동 생성되는 **완성 예시 웹앱**입니다. 결과물을 다운로드해 직접 값을 넣어보면 보고서가 즉시 바뀝니다.

**이 결과물을 만든 PRD 프롬프트** — 입력폼 → 보고서 자동생성 구조는 이렇게 지시했습니다

```javascript
## 역할
너는 IT 프로덕트 매니저 10년차야.

## 지시
아래 아이디어를 Genspark(바이브코딩 플랫폼)에서 구현하기 위한
PRD(제품 요구사항 문서)를 작성해줘.

## 아이디어
- 서비스명: 경영진 주간 보고 웹앱
- 대상 사용자: 교육기관 리더
- 핵심 기능:
  1. 주간 핵심 데이터 입력 폼 (주요 이슈 3개, 공정률, 안전지표, 예산집행률)
  2. 입력된 데이터로 리더 보고용 주간 보고서 자동 생성
  3. 보고서 형식: 핵심이슈 요약 → KPI 현황 표 → 지연/리스크 항목 → 다음 주 계획
  4. 보고서 복사/다운로드 기능
  5. 디자인: 깨끗한 보고서 포맷, 교육기관 CI 반영

## 출력양식
- 형식: PRD 문서 (기능 목록, 화면 구성, 데이터 흐름)
- 분량: A4 2페이지 이내
- md 파일로 저장
```

**이 PRD를 Genspark에 넣으면** 위 예시 웹앱 같은 결과가 나옵니다. 다운로드한 예시 결과물에 아래 샘플 값을 직접 넣어보면 보고서가 어떻게 완성되는지 확인할 수 있습니다:
- 주요 이슈 1: "강남 오피스 민원 확대 — 인근 학교 학부모 민원 추가 접수" / 영향도: 상
- 주요 이슈 2: "철근 단가 인상 요청 — ○○철강 8% 인상 통보" / 영향도: 중
- 주요 이슈 3: "평택 클린룸 설계변경 — 발주처 공조용량 상향 요청" / 영향도: 중

# 4️⃣ 실습 시나리오 C: 팀별 주간보고 취합 대시보드
여러 팀의 주간보고를 **한 화면에 취합**해, 의사결정자가 조직 전체를 한눈에 보는 대시보드를 만듭니다. 개인 업무가 아닌 **조직 단위**의 활용 예시입니다.

**완성 이미지:**
- 여러 팀의 주간보고를 한 화면에 한눈에
- 지연·리스크·예산 관련 이슈는 **자동으로 상단에 하이라이팅**
- 그동안 논의되지 않은 **신규 주제는 별도 구분** 표시
- 정상 진행 팀은 아래에 차분히 정리


**\[예시 C\] 조직 단위 활용 결과물**
여러 팀의 보고를 한 화면에 취합해 의사결정자가 조직 전체를 한눈에 보는 **완성 예시 대시보드**입니다. 지연·리스크 이슈는 자동으로 상단에 올라오고, 신규 주제는 따로 구분됩니다. 결과물을 다운로드해 확인하고, 아래 PRD로 어떻게 만들었는지 보세요.



[첨부 원본 제외: 파일 권리·개인정보 확인 전입니다.]


```javascript
## 역할
너는 IT 프로덕트 매니저 10년차야.

## 지시
아래 아이디어를 Genspark(바이브코딩 플랫폼)에서 구현하기 위한
PRD(제품 요구사항 문서)를 작성해줘.

## 아이디어
- 서비스명: 팀별 주간 업무보고 취합 대시보드
- 대상 사용자: 교육기관 본부장·임원 (여러 팀의 보고를 취합해 판단하는 의사결정자)
- 핵심 기능:
  1. 팀별 주간보고 입력 폼 (팀명, 주요 진행사항, 이슈, 일정)
  2. 여러 팀의 보고를 한 화면에 취합해 조직 전체 현황을 대시보드로 표시
  3. 지연·리스크·예산 관련 이슈를 자동으로 상단에 하이라이팅
  4. 그동안 논의되지 않은 신규 주제는 별도 카테고리로 구분 표시
  5. 디자인: 깔끔한 의사결정자 보고용 UI, 교육기관 CI(주황색) 반영

## 출력양식
- 형식: PRD 문서 (기능 목록, 화면 구성, 데이터 흐름)
- 분량: A4 2페이지 이내
- md 파일로 저장
```

**세 가지 예시의 흐름:** A(현장 현황) → B(주간 보고서) → C(팀 취합 현황판)로 갈수록 **개인 → 조직 단위**로 넓어집니다. 의사결정자 시각에서는 C가 가장 체감이 큽니다. 세 결과물 모두 다운로드해 직접 열어볼 수 있습니다.
