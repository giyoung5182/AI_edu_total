이 문서는 Claude Cowork와 Claude Code의 고급 기능을 한곳에 정리한 레퍼런스예요. 개발자가 바로 활용할 기능과, 다른 팀이 "Cowork가 뭐냐", "Code랑 뭐가 다르냐"고 물어올 때 답해줄 기준을 함께 담았어요. 앞의 'IT 운영 4대 주제' 트랙이 '무엇을 만들까'였다면, 이 문서는 '도구를 어디까지 다룰 수 있나'예요.

**전제 — 같은 엔진, 다른 표면**
Claude Cowork와 Claude Code는 같은 에이전트 엔진(계획 수립·자율 실행·서브에이전트 병렬)을 공유해요. 차이는 표면이에요 — Cowork는 비개발자·실무자를 위한 데스크톱 GUI, Code는 개발자를 위한 터미널 CLI. 선택 기준은 Part 3에 표로 정리해 뒀어요.

**서브에이전트가 핵심**
Cowork와 Code가 공유하는 가장 강력한 능력이 서브에이전트예요. N개 작업을 순차로 도는 게 아니라 병렬로 쪼개고, 각 에이전트가 격리된 컨텍스트에서 일한 뒤 최종 결과만 합칩니다. 그래서 '20개 파일 분석' 같은 작업이 가장 긴 한 건의 시간으로 끝나고, 컨텍스트 분리로 정확도도 올라가요.

## ② 복합 스킬(파이프라인) + 스케줄
단순 스킬이 단일 작업이라면, 복합 스킬은 여러 단계를 하나로 묶은 파이프라인이에요. "데이터 정리 → 분석 리포트 → PPT"를 한 번에 도는 식이죠. 핵심은 **각 Step의 중간 산출물 파일명을 명시**하는 것 — 그래야 Claude가 중간 결과를 저장하며 다음 단계로 넘어가 에러가 줄어요.
```plain text
[스킬: monthly-report-pipeline]

이 폴더에 데이터가 있어. 아래 순서로 처리해줘:

[Step 1: 데이터 정리]
- xlsx를 읽고 품질 점검(결측·이상치)
- "정리완료.xlsx"로 저장

[Step 2: 분석 리포트]
- 핵심 지표 집계, 전월 대비 증감 원인
- "분석_YYYY-MM.docx"로 저장

[Step 3: 경영진 PPT]
- 리포트 기반 6장 PPT
- "보고_YYYY-MM.pptx"로 저장

[조건]
- 결과물은 '결과물' 폴더에, 금액은 원화(₩)·천 단위 콤마
```
복합 스킬을 스케줄에 연결하면, 데이터만 폴더에 넣어두면 정리·분석·보고서·PPT가 정기적으로 자동 생성돼요. "복합 스킬 + 스케줄 = 정기 자동 보고"가 가장 강력한 조합이에요. 호출은 슬래시 커맨드(`/monthly-report-pipeline`)로 합니다.

## ④ 메모리·컨텍스트 원리 — CLAUDE.md · 오토 메모리 · 컨텍스트 관리
Claude Code의 '기억'은 두 층이에요. **CLAUDE.md**(명시적 메모리)는 내가 적어두는 규칙·아키텍처·금지사항이고 세션 시작 때 자동 로드돼요. **오토 메모리**(MEMORY.md)는 Claude가 작업하며 스스로 축적하는 학습으로(빌드 명령·코드 패턴·선호), 세션 시작 시 앞부분(처음 200줄/25KB 한도)이 로드돼요. 전자는 사람이, 후자는 에이전트가 쓰는 메모리예요.
진짜 심화 포인트는 **컨텍스트 관리**예요. 세션이 길어지면 컨텍스트 창이 차고, Claude는 오래된 도구 출력부터 비운 뒤 그다음 대화를 요약(compaction)해요. 이때 초반에 줬던 지시가 유실될 수 있어서 — '계속 지켜져야 하는 규칙'은 대화가 아니라 CLAUDE.md에 둬야 살아남습니다. `/context`로 무엇이 컨텍스트를 차지하는지 보고, `/compact focus on ...`으로 요약 시 보존할 초점을 줄 수 있어요.

**서브에이전트, 직접 구성하고 직접 시키기.** Claude가 알아서 하위 작업을 나누기도 하지만, 직접 통제하면 결과가 더 안정적이에요. 두 갈래예요.
- **직접 구성** — `/agents` 또는 `.claude/agents/`로 커스텀 서브에이전트를 정의해요. 각 서브에이전트에 전용 시스템 프롬프트·허용 도구·역할(예: 'DB 영향도 분석 전담', '보안 리뷰 전담')을 지정해 두면, Git으로 팀이 같은 전문가 세트를 공유할 수 있어요.
- **직접 지시** — 프롬프트에서 분담을 명시해요. 예: "이 레포를 세 서브에이전트로 나눠 각각 (a) 인증, (b) 결제, (c) 알림 모듈의 의존성·리스크를 분석하고 요약만 모아줘." 막연히 맡기는 것보다 범위·관점을 직접 끊어 주면 병렬 효율과 정확도가 올라가요.

**checkpoints의 경계**
rewind는 현재 세션의 직접 편집만 추적해요 — Git 같은 영구 히스토리가 아니라 세션이 끝나면 사라집니다. 세션 외부 변경(수동 편집·다른 도구)은 추적 못 해요. 진짜 버전 관리는 Git이 하고, checkpoints는 '한 세션 안에서의 실험 안전망'으로 보세요.

## ⑦ 목표 달성까지 — 에이전트가 끝까지 도는 원리
'에이전트를 굴린다'는 건 결국 **목표에 도달할 때까지 스스로 도는 것**이에요. 그 동작 원리를 두 층으로 보면 됩니다 — 기본 엔진인 **에이전틱 루프**, 그리고 '완전히 끝날 때까지'를 못 박는 **/goal**.
**에이전틱 루프(동작 원리).** 명령 하나를 주면 Claude는 '맥락 수집 → 실행 → 검증'을 한 턴으로 돌고, 그 턴에서 얻은 정보로 다음 행동을 정해 또 돌아요. 이 사이클을 더 할 일이 없을 때까지 반복하는 게 핵심이에요. "테스트 고쳐줘" 한 마디에 \[테스트 실행 → 에러 읽기 → 소스 수정 → 재실행 → 통과 확인\]이 자동으로 이어지죠. 모델이 추론하고(판단), 도구가 행동하고(파일·명령·검색), 각 도구 결과가 다시 루프로 들어가 다음 판단을 만들어요. 사용자는 언제든 끼어들어 방향을 틀 수 있고요.
```plain text
프롬프트
  → [맥락 수집] 파일·로그·검색으로 현재 상태 파악
  → [실행] 편집·명령·도구 호출
  → [검증] 테스트·결과 확인
  → (목표 미달이면) 다시 맥락 수집으로 …
  → (목표 달성/할 일 없음) 종료
```
**기본 루프의 한계와 /goal.** 기본 루프는 'Claude가 됐다고 판단하면' 멈춰요. 그런데 "정말 끝까지" — 예컨대 모든 테스트가 통과할 때까지 — 보장하려면 종료 기준을 사람이 못 박아야 해요. 그게 `/goal`이에요. 완료 조건을 걸면 매 턴이 끝날 때마다 별도의 빠른 모델이 조건 충족을 검사하고, 안 됐으면 다음 턴을 자동으로 시작해요. 충족되면 자동 종료. (내부적으로는 매 턴 후 평가하는 prompt 기반 Stop hook이에요.)
```plain text
/goal test/auth의 모든 테스트가 통과하고 lint가 깨끗할 때까지.
실제로 테스트를 돌려 통과를 확인할 것. 다른 테스트 파일은 수정 금지.
또는 20턴 후 중단.
```
좋은 조건은 **측정 가능한 최종 상태 + 검증 방법 + 지켜야 할 제약**으로 써요(예: "테스트 전부 통과", "변경 없음 상태", "TODO 0개"). 평가자는 Claude가 대화에 드러낸 것만 보고 판단하니(평가자가 직접 명령을 실행하지는 않음), "Claude가 실제로 돌려서 결과가 대화에 남는" 형태로 조건을 적어야 해요. 진행 상황은 `/goal`(인자 없이)로 보고, `/goal clear`로 취소, `claude -p "/goal ..."`로 헤드리스 1회 완주도 가능합니다.
**더 무인으로 — auto mode와 함께.** `/goal`이 '턴을 계속 잇는' 거라면, auto mode는 '한 턴 안의 도구 승인을 자동화'예요. 둘을 같이 쓰면 매 턴이 사람 개입 없이 끝까지 돌아요. 그만큼 가드(아래)가 먼저예요.

**자율 실행 가드레일**
리스크는 무한 반복·비용 폭주·잘못된 방향 고착이에요. (1) 조건에 "또는 N턴 후 중단" 같은 상한을 넣고, (2) 처음엔 작은 범위로 검증한 뒤 확대하고, (3) auto mode와 함께 쓸 땐 Hooks·스테이징·읽기 전용 권한 같은 가드를 먼저 깔고, (4) 어긋나면 Ctrl+C. `/goal`은 trust 승인된 워크스페이스에서만 동작하고, 관리자 정책으로 hooks를 끄면(disableAllHooks) 쓸 수 없어요.

## ⑧ 안전장치 & 자동화 — Hooks · headless · MCP
자동화에서 '자율성'은 양날의 검이에요. 그래서 반드시 지켜야 할 것은 AI 재량이 아니라 결정론적 가드로 강제합니다.
**Hooks — 도구 실행 수명주기에 거는 셸 로직.** `PreToolUse`는 실행 전 차단(운영계 명령·보호 파일), `PostToolUse`는 실행 후 후처리(포맷·린트·테스트), `SessionStart`/`SessionEnd`도 있어요. 운영 DB 직접 수정 차단, 모든 위험 변경 감사 로깅 같은 '안전벨트'를 코드로 박을 수 있어요. (참고로 ⑦의 `/goal`이 바로 prompt 기반 Stop hook 위에 만들어진 기능이에요.)
```plain text
# PreToolUse 예: 운영 DB 직접 수정 차단
matcher: { toolName: bash, inputPattern: 'psql.*prod.*(UPDATE|DELETE)' }
handler: 차단(exit 1) + 알림
```
**headless — 비대화형 실행.** `claude -p "<지시>" --output-format json --allowed-tools "Read,Edit,Bash"`로 cron·CI에서 무인 실행하고, GitHub Actions 공식 액션(`anthropics/claude-code-action@v1`)으로 PR마다 자동 리뷰·정기 감시를 돌립니다. JSON 출력에 비용도 실려 와 추적이 쉬워요.
**MCP — 도구 통합.** Jira·DB·모니터링·Slack을 한 컨텍스트에 붙여, 코드 작업과 사내 툴 작업이 끊기지 않게 해요. (앞 IT 운영 트랙 '주제 2'에서 stdio/HTTP·scope·Cloud/Data Center 분기를 자세히 다뤘어요.)
## ⑨ Skills 팀 자산화 — SKILL.md
개인의 프롬프트는 흩어지지만, 팀의 스킬은 쌓여요. Claude Code의 Skill은 `SKILL.md` 하나가 진입점인 디렉토리고, Agent Skills 개방 표준(agentskills.io)을 따라 Cowork·Gemini CLI와도 호환돼요.
```plain text
skill-name/
├── SKILL.md          # 필수: frontmatter(메타) + 지침
├── scripts/          # 선택: 실행 코드(본문엔 안 들어감)
├── references/       # 선택: 필요할 때만 읽는 상세
└── assets/           # 선택: 템플릿
```
동작은 **progressive disclosure** — 평소엔 description(약 100토큰)만 보다가, 관련 작업이 오면 본문을, 필요할 때만 번들 리소스를 읽어요. 그래서 긴 레퍼런스를 넣어도 쓰기 전엔 비용이 거의 안 들어요.

**API를 MCP 대신 Skill로 감싸 토큰 줄이기.** 연결된 MCP 서버는 도구 정의(스키마)를 컨텍스트에 올려요. 그래서 그 도구를 안 쓰는 전혀 무관한 대화를 해도 baseline 토큰이 깔리고, 서버·도구가 많을수록 커져요. 반면 Skill은 progressive disclosure라 평소엔 description(약 100토큰)만 떠 있고 본문·스크립트는 실제 트리거될 때만 로드돼요. 그래서 자주 안 쓰는 API는 'MCP로 상시 연결'하는 대신 **호출 스크립트를 담은 Skill로 만들고 description을 잘 적어두면**, 안 쓸 때 컨텍스트 비용이 거의 0이에요. (단, Claude Code는 MCP tool search로 도구 정의를 지연 로드해 이 비용을 완화하기도 해요. `/context`·`/mcp`로 실제 baseline을 확인하세요.)

**실측 참고 — tool search가 켜져 있으면 MCP baseline은 생각보다 작아요**
서버를 여러 개 연결해도 컨텍스트에 실제 올라온 도구 정의는 그세션에서 호출한 몇 개뿐이고, 나머지는 'Available' 상태로 대기하다 쓸 때만 로드돼요. 예를 들어 Atlassian·Gmail·Calendar·Drive·Notion·DB를 다 연결해도 `/context`의 'MCP tools' 항목은 1k 토큰 안판에 그치는 경우가 많아요(실제 로드된 도구만 계산됨). 그래서 토큰이 정말 문제라면 MCP/Skill 구성보다 **대화 길이(****`/compact`****)**부터 보는 게 맞아요 — 실제로 컨텍스트를 가장 많이 먹는 건 대개 쌌인 대화 자체예요.
