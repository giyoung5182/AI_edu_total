### 🔥 활동 1 — 승인 지점 설계하기
1권의 질문을 다시 씁니다.
```plain text
이 단계에서 틀렸는데 아무도 확인하지 않으면 무슨 일이 일어나는가
```
**지시문에 쓰는 방법**
```plain text
[승인이 필요한 상황]

아래 상황에서는 진행을 멈추고 사용자에게 확인을 요청한다.
확인을 받기 전까지 다음 단계로 넘어가지 않는다.

1  기준표에 없는 컬럼명이 발견된 경우
   → 어떤 컬럼으로 매핑할지 질문한다

2  결측값이 전체의 5%를 넘는 경우
   → 처리 방식을 질문한다

3  전주 대비 수치가 2배 이상 차이 나는 경우
   → 데이터 오류 가능성을 알리고 확인을 요청한다

4  입력 파일 수가 예상과 다른 경우
   → 누락 파일 목록을 제시하고 진행 여부를 질문한다

[질문 형식]

  확인이 필요합니다
  상황: (무엇이 발생했는지)
  영향: (그대로 진행하면 어떻게 되는지)
  선택지: (가능한 처리 방법 2~3개)
  권장: (권장안과 그 이유)
```
> **참고** — **질문 형식까지 정해 주는 이유** — 형식을 안 정하면 "어떻게 할까요?"라는 막연한 질문이 옵니다. 그러면 사람이 상황을 파악하는 데 시간이 더 걸려서 **자동화의 의미가 줄어듭니다.<br><br>**
[원본 이미지 제외]
**내 승인 지점 빈칸**
```plain text
승인이 필요한 상황 1 : ________________________________
  틀리면 생기는 일   : ________________________________

승인이 필요한 상황 2 : ________________________________
  틀리면 생기는 일   : ________________________________

승인이 필요한 상황 3 : ________________________________
  틀리면 생기는 일   : ________________________________
```
**✅ 승인 지점이 제대로 잡혔는지 3초 체크**
- [ ] 되돌릴 수 없는 행동 앞에 승인이 있습니까
- [ ] 승인 지점이 5개 이하입니까 (너무 많으면 자동화 효과가 사라집니다)
- [ ] 각 승인마다 무엇을 물을지 정해져 있습니까

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[1] 이름          매체 실적 통합 도우미
[2] 사용자        매체 담당자
[3] 사용 시점     매주 월요일 오전

───────────────────────────────────────
[4] 목표
───────────────────────────────────────
  매체사별 실적 파일을 하나의 통합 표로 만들고,
  처리 과정에서 발견된 문제를 함께 보고한다.

  이 Agent가 하지 않는 일
  - 성과 해석과 코멘트 작성
  - 보고서 대외 발송
  - 원본 파일 수정

───────────────────────────────────────
[5] 도구
───────────────────────────────────────
  파일 읽기        엑셀·CSV
  표 생성          통합 표 출력
  문서 생성        변경 내역 보고서

───────────────────────────────────────
[6] 지식
───────────────────────────────────────
  컬럼 기준표          매체사별 컬럼명 → 표준 컬럼명 매핑
  데이터 사전          컬럼 정의, 허용값, 처리 규칙
  매체별 예외 사항     특정 매체의 보고 형식 특수성

───────────────────────────────────────
[7] 기억
───────────────────────────────────────
  전주 처리 시 확인받은 매핑 규칙
  신규 매체 추가 이력
  반복 발생 오류 유형

───────────────────────────────────────
[8] 규칙
───────────────────────────────────────
  반드시 한다
  - 변경한 모든 항목을 내역으로 남긴다
  - 결측·중복을 별도 목록으로 보고한다
  - 판단이 애매하면 확인을 요청한다

  절대 하지 않는다
  - 값을 추정하거나 보간하지 않는다
  - 기준표에 없는 컬럼을 임의로 매핑하지 않는다
  - 원본 파일을 수정하지 않는다
  - 확인 요청 없이 예외 상황을 넘어가지 않는다

───────────────────────────────────────
[9] 처리 흐름
───────────────────────────────────────
  1  입력 파일 확인       파일 수·형식 점검
  2  유형 판별            매체사별 구분
  3  컬럼 매핑            기준표 대조        ← 예외 시 승인

  7  검증                 완료조건 점검

───────────────────────────────────────
[10] 완료조건
───────────────────────────────────────
  [ ] 입력 파일 전부 처리

  [ ] 결측·중복 목록 생성
  [ ] 변경 내역 보고서 생성
  [ ] 확인 필요 항목이 있으면 별도 표시

[11] 예외 상황

### 📌 4권 핵심 정리
① Agent는 **목표·도구·지식·기억·규칙** 다섯 덩어리다. 하나라도 비면 그 자리에서 문제가 생긴다.
② 워크플로와의 차이는 **판단의 유무**다. 예외가 있는 업무에 Agent가 필요하다.
③ 권한은 **되돌릴 수 있는 범위까지만** 준다. 완료조건은 **체크리스트로** 쓴다.
④ **지시하지 않은 행동은 일어나지 않고, 금지하지 않은 행동은 일어난다.** 설계의 절반은 금지 목록이다.
⑤ Skills가 막힌 환경에서 **CLAUDE.md가 반복 절차를 저장하는 대체 경로**다.
