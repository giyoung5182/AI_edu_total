---

# 빠른 진단 — 막혔을 때 이 순서로
1. **화면에 뜬 문구를 그대로 읽습니다.** 아래에서 그 문구를 찾습니다.
2. **없으면 그 문구를 통째로 복사해 AI에게 물어봅니다.** "아래 오류가 났어. 원인이 뭐고 어떻게 고쳐?"
3. **그래도 안 되면 두 번까지만 시도합니다.** 세 번째부터는 방식을 바꾸거나 도움을 요청하세요.

**같은 요청을 반복하는 것이 시간을 가장 많이 잡아먹습니다.** 두 번 해서 안 되면 다른 방법을 찾으세요.

# 1. 설치와 환경
## npm.ps1 파일을 로드할 수 없습니다
**원인** — Windows가 외부 스크립트 실행을 기본으로 막아둡니다.
**해결** — PowerShell에 아래를 입력하고 Enter를 누릅니다.
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
**확인** — "변경하시겠습니까?"가 나오면 Y를 입력합니다. 아무 반응 없이 넘어가도 정상입니다. 이미 풀려 있었다는 뜻입니다.
**주의** — 컴퓨터당 한 번만 하면 됩니다.
## claude 용어가 인식되지 않습니다 / npm이 인식되지 않습니다
**원인** — 설치 후 새 창을 열지 않았습니다. 90%가 이것입니다.
**해결** — 지금 창을 완전히 닫고, PowerShell을 새로 열고, 다시 입력합니다.
**그래도 안 되면** — `claude doctor` 를 입력합니다. 설치 상태를 점검해 문제와 해결법을 알려줍니다.
## package.json이 없습니다
**원인** — 프로젝트 폴더 밖에서 명령을 실행했습니다.
**확인** — 터미널 맨 앞 경로를 봅니다. 프로젝트 이름까지 나와야 정상입니다. 사용자 이름에서 끝나면 폴더 밖입니다.
**해결** — `cd` 명령으로 프로젝트 폴더로 이동합니다.
## 설치가 중간에 끊기거나 액세스가 거부되었습니다
**원인** — 회사 보안 프로그램 차단입니다.
**해결** — 전산 담당 부서에 문의하거나 개인 노트북에서 진행합니다.
## npm 업데이트 안내가 나옵니다
"npm notice New major version available" 같은 메시지입니다.
**따르지 마세요. 광고입니다.** 수업 중 버전을 바꾸면 방금 설치한 부품과 어긋날 수 있습니다.

# 2. 앱 만들기 (Lovable)
## 데이터가 새로고침하면 사라집니다
**원인** — 브라우저 메모리에만 저장되고 데이터베이스에 안 들어갑니다.
**확인** — 데이터 1건을 입력하고 F5를 눌러 남아있는지 봅니다. 그다음 스마트폰에서 열어 보이는지 확인합니다.
**해결** — Lovable 채팅에 아래처럼 요청합니다.
이 앱에 데이터베이스를 연결해줘.
\[저장할 항목들\]을 저장하는 테이블을 만들어서,
입력한 데이터가 새로고침해도 유지되게 해줘.
임시 데이터가 아니라 실제로 저장되어야 해.
## 데이터베이스 사이트에 테이블이 없다고 나옵니다
**원인** — Lovable Cloud를 쓰고 있어서입니다. 개인 계정과는 별개입니다.
**해결** — Lovable에서 구름 아이콘(Cloud)을 누르고 Database로 들어갑니다. 여기서 테이블과 행이 보입니다.
**주의** — 외부 사이트에서 찾으면 계속 안 보입니다. 가지 마세요.
## GitHub 연동 메뉴를 못 찾겠습니다
**원인** — Connectors 메뉴가 아닙니다.
**위치** — 화면 하단 입력창 왼쪽의 더하기 버튼을 누르면 GitHub가 있습니다. 또는 Settings에서 왼쪽 메뉴의 Git 항목으로 들어갑니다.
**주의** — Connectors에 있는 GitHub 관련 항목은 다른 기능입니다.
## 삭제 버튼을 눌렀는데 오히려 생성됩니다
**원인** — 삭제 이벤트와 등록 이벤트가 섞여 있습니다.
**해결** — 아래처럼 요청합니다.
삭제 버튼을 누르면 항목이 삭제되지 않고
오히려 새 항목이 생성됩니다.
삭제 버튼의 클릭 이벤트가 등록 폼의 제출 이벤트와
분리되어, 삭제만 수행하도록 고쳐주세요.
실제 데이터베이스에서 해당 행을 지우는지도 확인해주세요.
## 크레딧이 빨리 소모됩니다
**아끼는 법**
- 텍스트, 색상, 여백은 Edit 모드로 (크레딧 소모 없음)
- 관련 있는 수정끼리만 묶어서 요청
- 서로 무관한 영역을 한 번에 요청하지 않기
- 세밀한 수정은 Cursor에서 (크레딧 별개)
**주의** — "여러 개 묶기"가 아니라 "관련 있는 것끼리만 묶기"입니다.
## 목록에 샘플 몇 개만 들어 있습니다
**원인** — 설계서에 전체 목록을 안 줘서 AI가 예시로 만든 것입니다.
**해결** — 실제 목록을 프롬프트에 붙여넣어 요청합니다. "지점 목록을 아래 전체로 바꿔줘" 하고 목록을 붙이면 됩니다.

# 3. 코드 수정과 배포
## Cursor를 켰는데 예전과 화면이 다릅니다
**원인** — 에이전트 창이 기본으로 열렸습니다.
**확인** — 상단 메뉴가 4개(File, Edit, View, Help)면 에이전트 창입니다.
**해결** — 오른쪽 맨 위 IDE 버튼을 클릭합니다. 상단 메뉴가 8개로 늘고 Terminal 메뉴가 생기면 성공입니다.
## 커밋이 안 되고 user.name 오류가 납니다
**원인** — Git에 사용자 정보가 등록되지 않았습니다. 처음 커밋할 때 한 번 반드시 납니다.
**해결** — 터미널을 새로 열고 두 줄을 입력합니다.
git config --global user.name "본인이름"
git config --global user.email "본인이메일"
아무 반응 없이 넘어가면 성공입니다. Source Control로 돌아가 다시 Commit을 누릅니다.
**주의** — 개발 서버가 돌고 있는 터미널은 명령을 받지 않습니다. Terminal 메뉴에서 New Terminal로 새로 여세요.
## 커밋했는데 GitHub에 안 올라갑니다
**원인** — 커밋만 하고 푸시를 안 했습니다. 가장 흔한 실수입니다.
**비유** — 상자에 담기가 커밋, 택배 접수가 푸시입니다. 접수를 안 하면 안 갑니다.
**해결** — Sync Changes 버튼을 클릭합니다. 왼쪽 아래 브랜치 이름 옆의 별표가 사라지면 완료입니다.
## 로컬 주소가 안 열립니다
**원인** — 서버가 꺼져 있습니다. 터미널을 닫으면 꺼집니다.
**해결** — Cursor에서 프로젝트 폴더를 열고, 새 터미널을 열고, 경로를 확인한 뒤 개발 서버 실행 명령을 입력합니다.
**주의** — 부품 설치는 다시 안 해도 됩니다. node_modules 폴더가 있으면 이미 설치된 것입니다.
## 포트 번호가 예상과 다릅니다
Lovable로 만든 앱은 보통 8080입니다. 다른 프로그램이 쓰고 있으면 8081 등으로 바뀝니다.
**화면에 실제로 나온 숫자를 쓰세요.**
## 배포했는데 데이터가 안 나옵니다
**확인 순서**
첫째, 로컬에서는 데이터가 나오는지 봅니다. 안 나오면 앱 자체 문제이니 먼저 그것부터 해결합니다.
둘째, 로컬에서 나온다면 환경변수 문제일 수 있습니다. Vercel의 Settings에서 Environment Variables로 들어가 설정 파일의 내용을 하나씩 추가한 뒤, Deployments에서 재배포합니다.
**참고** — Lovable로 만든 앱은 대개 설정 파일이 함께 올라가 별도 설정 없이 동작합니다.
## 수정했는데 배포된 앱에 반영이 안 됩니다
**원인 1** — 푸시를 안 했습니다. GitHub 저장소에서 커밋이 보이는지 확인하세요.
**원인 2** — 긴 주소를 보고 있습니다. 짧은 주소로 접속하세요.
**주의** — 동료에게 공유할 때는 반드시 짧은 주소를 주세요. 긴 주소는 그때 배포한 것에 고정됩니다.
## 고치다가 앱이 깨졌습니다
**복구 방법 세 가지**
1. Cursor에서 실행 취소를 누르거나 "방금 요청 취소하고 이전 상태로 돌아가줘"라고 요청합니다
2. Vercel의 Deployments에서 이전 배포를 골라 즉시 되돌립니다
3. 마지막으로 잘 되던 코드를 메모장에 복사해뒀다면 그것으로 되돌립니다

# 4. 자동화 (GAS와 Make)
## 첫 실행에서 확인 안 된 앱 경고가 나옵니다
**정상입니다.** 내가 만든 스크립트라서 그렇습니다. 고급 항목을 누르고 이동한 뒤 허용을 선택합니다.
## 트리거가 안 돌아갑니다
**확인할 것**
- Apps Script 왼쪽 트리거 메뉴에 등록되어 있는가
- 실행 로그에 오류가 있는가
- 스크립트를 수동으로 실행하면 되는가
수동으로는 되는데 자동이 안 되면 트리거 설정 문제입니다. 수동으로도 안 되면 코드 문제입니다.
## 시트 값을 코드가 못 읽습니다
**원인** — 열 이름, 순서, 형식이 코드가 기대하는 것과 다릅니다. 사람이 시트를 직접 고치면 자주 발생합니다.
**해결** — 아래처럼 요청합니다.
구글시트에서 값을 읽는 부분을 확인해줘.
시트의 실제 열 이름과 코드에서 참조하는 이름이
일치하는지 확인하고, 앞뒤 공백이나 대소문자 차이도
확인해서 정리 처리를 추가해줘.
**예방** — 시트에 드롭다운(데이터 확인)을 걸어 입력값을 고정합니다.
## Make 시나리오가 처음만 되고 끊깁니다
**확인 순서**
- 시나리오가 활성 상태인가
- 실행 기록에 실패한 실행이 있는가
- 실패 사유가 무엇인가
- 연결된 서비스의 인증이 만료되지 않았는가
**근본 대책** — "멈춘 것을 알아채는 방법"을 만들어두세요. GAS로 발송 건수를 따로 받거나, 0건이어도 결과가 오게 설계하면 됩니다.

# 5. Claude Code 에이전트
## Agent type not found
**원인 1** — 에이전트를 만든 뒤 재시작을 안 했습니다. 대부분 이것입니다.
**해결** — `/exit` 후 다시 실행합니다.
**원인 2** — 에이전트 이름을 한글로 지었습니다.
**해결** — 이름은 영어 소문자와 하이픈으로만 만듭니다. 사람이 부를 때만 한글로 부르면 됩니다.
## 에이전트를 안 부르고 메인이 직접 처리합니다
**원인** — 요청에 에이전트 이름이 없거나 약합니다.
**해결 1** — 이름을 정확히 불러서 요청합니다. "○○ 에이전트한테 맡겨줘" 형태입니다.
**해결 2** — 골뱅이 기호를 눌러 에이전트를 태그합니다. 그 에이전트 실행이 보장됩니다.
**해결 3** — 에이전트 파일의 호출 조건(description)에 호출 문구를 여러 개 넣습니다.
## 파일을 못 찾는다고 합니다
**원인** — 작업 폴더가 다릅니다.
**확인** — 화면 상단의 작업 폴더 경로를 봅니다. 실습 폴더 이름이 있어야 합니다.
**해결** — 폴더에서 오른쪽 클릭해 터미널을 열고 다시 실행합니다.
## 백그라운드 에이전트 대기 상태로 멈춰 있습니다
**원인** — 에이전트가 자기 자신을 계속 호출하고 있습니다.
**해결**
1. Ctrl과 C를 두 번 눌러 중단합니다
2. 에이전트 폴더의 해당 파일을 메모장으로 엽니다
3. 맨 위 구분선 사이에 `disallowedTools: [Agent]` 한 줄을 추가합니다 (Agent의 A는 반드시 대문자)
4. 저장 후 종료하고 다시 실행합니다
**예방** — 만들 때 프롬프트에 미리 넣어두세요. "disallowedTools에 Agent를 추가해줘" 한 줄이면 됩니다.
## 판정이 전부 한쪽으로 쏠립니다
**원인** — 판단 기준이 느슨합니다.
**해결** — 예시를 주며 기준을 조정합니다. "이 건은 이렇게 판정되어야 해. 기준을 그렇게 고쳐줘" 하고 요청한 뒤 재시작합니다.
## 자료에 없는 내용을 지어냅니다
**해결** — 에이전트를 수정합니다. "자료에 없는 내용은 추측하지 말고 확인 필요로 표시하도록 에이전트를 수정해줘" 라고 요청하세요.
**예방** — 만들 때부터 이 규칙을 넣으세요.
## 에이전트 폴더가 안 보입니다
**원인** — 점으로 시작하는 폴더는 숨김 처리됩니다.
**해결** — 파일 탐색기에서 보기 메뉴로 들어가 숨긴 항목을 체크합니다.

## 만든 앱을 동료에게 알려줘도 되나요
링크를 주는 것 자체는 문제없습니다. 다만 아래를 먼저 확인하세요.
- 로그인이 걸려 있는가 (아무나 못 들어오게)
- 민감한 데이터가 들어 있지 않은가
- 설명서가 있는가
- 문제가 생기면 누가 대응하는지 정해져 있는가
## 담당자가 바뀌면 어떻게 하나요
이것 때문에 12회차에 인수인계 문서를 만들었습니다. 넘길 때 아래를 함께 전하세요.
- 인수인계 문서
- 계정 정보 (비밀번호는 별도 경로로)
- 에이전트 파일 폴더
- 관련 구글시트 소유권
## AI가 만든 결과를 그대로 써도 되나요

## 새 도구가 나오면 다시 배워야 하나요
화면과 메뉴는 바뀝니다. 하지만 아래는 안 바뀝니다.
- 업무를 단계로 쪼개서 보는 법
- 판단, 규칙, 전달, 기록으로 나누는 법
- 한 번에 하나씩 요청하고 확인하는 습관
- 검증 없이 쓰지 않는 원칙
**이것을 알고 있으면 새 도구는 하루면 익힙니다.**
