# AI와 함께 데이터 정의서 오류 찾고 안전하게 UPDATE하기

정리일: 2026-10-08 · 교육 에셋 N1483

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
맥락 제공 → AI에게 SQL 초안 요청 → DBeaver에서 실행 → 사람이 결과 검증 → 안전한 UPDATE만 실행 → 수정 결과 확인의 흐름을 한 번 완주합니다.
## 진행 단계
1. **문제 1. 맥락 제공 후 오류 탐지 SQL 받기** — GPT에게 맥락을 주고 data dictionary 오류를 찾는 SELECT 쿼리를 요청합니다(UPDATE 쿼리는 아직 작성하지 않게 함).
- 입력할 내용: MySQL 데이터 품질관리 튜터 역할, SELECT/WHERE/JOIN/UPDATE 정도의 문법만 사용, data dictionary 전체 확인 SELECT, building_energy_records 실제값 예시 SELECT, 설명·단위가 이상한 컬럼 후보와 근거, 바로 Update 가능한 정의서 오류와 원천 확인 필요한 데이터 오류 구분 (이하 교안 참고)
2. **문제 2. DBeaver에서 실행** — 쿼리를 실행하고 표를 채웁니다(쿼리 오류 여부, 존재하지 않는 컬럼명 사용 여부, 설명이 잘못된 컬럼, 단위가 잘못된 컬럼).
3. **문제 3. UPDATE 쿼리 초안 요청** — UPDATE 전에 SELECT로 수정 대상을 먼저 확인하는 쿼리도 함께 요청합니다.
4. **문제 4. 사람이 검증** — UPDATE 전에 SELECT가 있는지, WHERE 조건이 있는지, 수정 대상 컬럼명이 실제로 존재하는지, 데이터 정의서만 수정하는지, 원천 확인이 필요한 값을 임의로 바꾸지 않는지 체크 후 안전한 UPDATE만 실행합니다.
5. **추가문제** — 실제 데이터 오류 후보를 '찾아줘, 분류해줘'로 요청하고, building_type 표기 표준화(Nonresidential → NonResidential, 앞뒤 공백 제거)만 UPDATE합니다. 정상 결과: UPDATE 전후 SELECT로 확인.
## 막히는 지점
- 실제 데이터 값은 함부로 수정하면 안 됩니다. AI에게 '고쳐줘'가 아니라 '찾아줘, 분류해줘'라고 요청합니다.
- 면적 0 이하, year_built가 reporting_year보다 큼, 에너지 사용량 음수는 원천 확인이 필요해 바로 UPDATE할 수 없습니다.
- AI가 존재하지 않는 컬럼명을 쓰지 않았는지 확인해야 합니다.
