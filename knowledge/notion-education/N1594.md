# 1️⃣ 예외 상황까지 정의하기
## 왜 예외 상황을 먼저 보나요?
겉으로는 작동하는 앱도 실제로 써보면 빈 입력, 잘못된 형식, 너무 긴 결과, 복사할 내용 없음 같은 상황에서 쉽게 무너집니다.
디버깅과 고도화의 출발점은 기능을 더 붙이는 것이 아니라, 사용자가 자주 만날 수 있는 예외 상황을 먼저 확인하는 것입니다.
## 꼭 확인할 예외 상황
1. 입력값이 비어 있을 때
2. 숫자가 아닌 값이 들어왔을 때
3. 날짜 형식이 이상할 때
4. 결과가 너무 길 때
5. 복사 버튼을 눌렀는데 결과가 없을 때

## 예시
1. `입력이 비어 있으면 경고 문구를 보여준다.`
2. `숫자가 아닌 값은 계산에서 제외하고 안내 문구를 보여준다.`
3. `결과는 한 화면에 읽기 좋게 카드 단위로 나눈다.`
4. `복사할 결과가 없으면 복사 버튼을 비활성화하거나 안내 문구를 보여준다.`
> TIP: 예외 상황을 먼저 잡으면 이후 디자인이나 기능을 추가해도 앱이 덜 흔들립니다.

# 2️⃣ 오류 대응: 작동이 안 될 때
## 문제는 정상입니다
바이브 코딩에서는 오류가 나는 것이 이상한 일이 아닙니다.
오히려 어떤 점이 이상한지 빠르게 설명하고 수정하는 능력이 중요합니다.

## 문제 설명
문제를 AI에게 말할 때는 아래 네 가지를 포함합니다.
1. 무엇을 했는가
2. 기대한 결과는 무엇인가
3. 실제로 어떤 일이 일어났는가
4. 어떻게 바꾸고 싶은가
## 예시
### 나쁜 설명
`이거 안 돼.`
### 좋은 설명
`요약하기 버튼을 눌렀는데 결과 카드가 비어 있어. 주간 보고를 입력했을 때 완료/진행중/이슈가 각각 한 줄씩 보이길 원해. 빈 결과가 아니라 분류된 카드가 나오도록 수정해줘.`
> TIP: 에러 문구가 보이면 그대로 복사해서 붙여넣는 것이 가장 빠릅니다.

### 오류 수정 프롬프트 예시
```plain text
현재 기능은 유지한 채 아래 문제를 수정해줘.
1. [여기에 실제 문제 입력]
2. 기대한 동작은 [여기에 기대 결과 입력]
3. 수정 후에는 브라우저에서 바로 실행 가능한 HTML 단일 파일 상태를 유지해줘.
4. 실제 회사 데이터 입력을 유도하지 말고, 테스트는 더미 데이터 기준으로 안내해줘.
```

# 3️⃣ 기능 추가: 에러는 없지만 더 좋아지지 않을 때
## 이런 경우를 찾습니다
지금 동작은 하지만 아래 같은 아쉬움이 남아 있을 수 있습니다.
1. 입력이 번거롭다.
2. 결과를 다시 활용하기 어렵다.
3. 반복해서 쓰기엔 편의 기능이 부족하다.
4. 화면이 읽히긴 하지만 한눈에 들어오지 않는다.
## 기능 추가를 보는 네 가지 관점
1. 입력 편의성 개선
2. 결과 활용성 개선
3. 반복 사용을 위한 보조 기능 추가
4. 카드, 표, 색상, 강조 같은 표현 개선
## 먼저 추가하면 좋은 기능
1. 예시 데이터 자동 입력 버튼
2. 결과 복사 버튼 또는 다운로드 버튼
3. 필터 또는 정렬 기능
4. 카드/표 전환 기능
5. 핵심 결과 강조 표시
> TIP: 고도화는 새로운 앱을 다시 만드는 작업이 아니라, 이미 만든 초안을 더 쓸 만하게 다듬는 작업입니다.

### 기능 추가 프롬프트 예시
```plain text
현재 기능은 유지한 채 아래 기능 중 하나만 추가해줘.
선택 기능: [카드/표 전환, 필터 또는 정렬, 결과 다운로드, 디자인 정돈 중 하나]

추가 조건
1. 기존 입력, 실행, 결과, 복사 기능은 유지해줘.
2. 더미 데이터 버튼은 유지해줘.
3. 실제 회사 데이터 입력을 유도하는 문구는 넣지 말아줘.
4. 브라우저에서 바로 실행 가능한 HTML 단일 파일 상태를 유지해줘.
```

# 4️⃣ 기능 추가는 순서가 중요합니다
## 추천 순서
1. 예외 상황 확인
2. 오류 수정
3. 기능적 보완
4. 결과 표현 개선
5. 디자인 고도화
6. 마지막 저장 및 실행 테스트
### 고도화 순서 한눈에 보기
```plain text
[예외 상황 확인]
   ↓
[오류 수정]
   ↓
[기능 보완]
   ↓
[표현 개선]
   ↓
[디자인 정돈]
   ↓
[최종 실행 테스트]
```
## 디자인은 마지막에 다듬습니다
디자인을 너무 일찍 건드리면 기능 수정 때 다시 무너질 수 있습니다.
기능부터 안정화한 뒤, 마지막에 화면을 정리하는 편이 훨씬 효율적입니다.

## 디자인 고도화 요청 예시
```plain text
기존 기능은 유지한 채 디자인만 더 정돈해줘.
1. 밝은 회색 배경
2. 진한 남색 계열 포인트 컬러
3. 버튼은 둥글고 또렷하게
4. 결과 카드는 읽기 쉽게 여백을 충분히
5. 전체적으로 깔끔한 비즈니스 도구처럼 보이게 해줘
6. 실제 회사 데이터 대신 더미 데이터로 테스트한다는 안내를 유지해줘
```
