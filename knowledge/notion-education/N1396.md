# Step 3 — 데이터 정제: 오류 수정과 롤백 전략

정리일: 2026-10-08 · 교육 에셋 N1396

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
정제 전 백업 테이블을 만든 뒤 오류를 UPDATE·DELETE로 정제합니다.
## 진행 단계
1. **백업 테이블 생성**
```sql
CREATE TABLE inspection_log_backup_20260614 AS SELECT * FROM inspection_log;
SELECT COUNT(*) AS 백업건수 FROM inspection_log_backup_20260614;
```
- 정상 결과: 백업건수 7.
2. **정제 1 — 코드값 표준화** — `UPDATE inspection_log SET result = '정상' WHERE result = '이상없음';` L001이 정상으로 바뀜.
3. **정제 2 — 날짜 형식 표준화**
```sql
UPDATE inspection_log
SET inspect_date = DATE_FORMAT(STR_TO_DATE(inspect_date, '%Y.%m.%d'), '%Y-%m-%d')
WHERE inspect_date LIKE '____.__.__';
```
- 정상 결과: L[차량번호 비공개]-04-30.
4. **정제 3 — 중복 삭제(MIN log_id만 남김)** — `DELETE FROM inspection_log WHERE log_id NOT IN (SELECT min_id FROM (SELECT MIN(log_id) AS min_id FROM inspection_log GROUP BY facility_id, inspect_date) AS t);`
- 정상 결과: 중복 확인 쿼리에 행 없음.
5. **정제 4 — 참조무결성 위반 삭제** — facilities에 없는 facility_id 행 삭제.
- 정상 결과: 남은건수 5.
6. **정제 5 — 확인 필요 항목 메모** — 미래 날짜(L003)와 날짜 논리 오류(L007)는 note에 CONCAT(IFNULL(note,''), ' \[미래날짜 검토 필요\]') 등으로 메모하고 담당자 확인 대기.
## 막히는 지점
- MySQL에서는 DELETE ... WHERE IN (SELECT ... FROM 같은 테이블) 구문이 오류를 발생시킵니다. 서브쿼리를 한 번 더 감싸는 FROM (...) AS t 패턴으로 우회합니다.
- 롤백 쿼리(TRUNCATE 후 백업에서 INSERT)는 실습에서 실행하지 않습니다.
