# (강사 시연) 예시를 넣으면 이렇게 달라진다

정리일: 2026-10-08 · 교육 에셋 N1080

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
고객사 처리 결과 안내 문구를 한 줄로만 요청할 때와 잘 쓴 예시 2개를 먼저 보여 줄 때의 결과를 비교한다.
## 진행 단계
1. **시연 ①** — 상담이력 첨부 → 한 줄 요청
```javascript
첨부한 상담이력으로 고객사에 보낼 처리 결과 안내 문구를 건별로 써줘.
```
- 볼 것: 건마다 길이·구성·말투가 다른지, 귀책이 '확인 중'·'미기재'인 건도 원인을 단정하는지, 내부 메모가 고객 문구에 섞이는지
2. **시연 ②** — 같은 채팅에서 \[예시 1\]［예시 2］(서로 다른 사건)와 ［규칙］(순서: 인사·건 이름 → 확인 결과 → 처리 결과 → 마무리 1문장 / 귀책이 확인 중이거나 비면 '확인 중' / 내부 메모 제외)을 넣고 5건을 재요청
- 볼 것: 5건이 예시와 같은 순서·길이·말투인지, 확인 중인 건을 '확인 중'으로 남기는지, 예시 속 사실이 다른 건에 섞이지 않는지
3. **정리** — 규칙을 길게 설명하는 것보다 잘 쓴 결과 2개를 보여 주는 쪽이 형식·말투를 빨리 맞춤
## 막히는 지점
- 시연 ①에서 자주 보이는 것: 귀책 미기재 건의 원인을 추측해 채움, 내부 메모(원인 분석 보고서 작성 필요 등)가 고객 문구에 들어감
