## Step 01 :: 매번 말하던 규칙을 CLAUDE.md 파일로 만듭니다.
### `.md` 파일이 무엇인가
지금부터 만들 것은 전부 `.md`로 끝나는 파일입니다. 설치할 것 없이 글자만 들어 있는 파일이고, 메모장으로 열립니다. `md`는 Markdown의 줄임말로, 기호 몇 개로 제목과 목록을 표시하는 방식입니다(`#` 제목, `-` 목록, `**굵게**`). 직접 쓰실 일은 거의 없습니다 - AI가 만들어줍니다.

**왜 워드가 아니라 이걸 쓰나** - 워드는 글자와 서식 정보가 함께 들어 있어 AI가 읽을 때 서식을 해석해야 하고, 복사해서 옮기면 깨지기도 합니다. 마크다운은 글자만 있어서 그대로 읽히고, 그대로 옮겨집니다. AI에게 주는 글은 파일로 저장했다가 다른 대화에 붙여넣고 동료에게 보내는 식으로 계속 옮겨 다니기 때문에 이 방식이 표준이 됐습니다.

### 오늘 몇 번 말씀하셨나요?
```javascript
"금액은 천 단위 쉼표"
"숫자는 오른쪽 정렬"
"좁은 화면에서도 보이게"
"클라이언트명은 코드로"
"빈 값은 0으로 채우지 마"
"다른 기능은 그대로 두고"
```

**세 번 이상 말한 게 있으면 그건 규칙입니다.** `coding` 폴더 바로 안(하위 폴더 아님)에 `CLAUDE.md` 파일 하나를 두면 매 요청마다 자동으로 읽힙니다. 팀 스타일 가이드와 같습니다 - 신입이 올 때마다 같은 설명을 반복하지 않으시죠.

### 만듭니다.
`[ ]` 부분만 본인 업무에 맞게 바꾸시면 됩니다.
```javascript
coding 폴더에 CLAUDE.md 파일을 만들어줘. 내용은 아래 그대로.

# 작업 규칙

## 용도
- 광고 실무에서 쓰는 도구입니다.
- 업무 중에 보는 화면이라 읽기 편한 것이 우선입니다.

## 표기
- 금액은 천 단위 쉼표를 넣습니다.
- 날짜는 YYYY-MM-DD 형식입니다.
- 숫자는 오른쪽 정렬합니다.

## 화면
- 표가 좁은 화면에서 잘리지 않게 합니다.
- 강조색은 한 화면에 한 종류만 씁니다.

## 데이터 처리
- 값이 비어 있으면 0으로 채우지 않고 「미입력」으로 둡니다.
- 계산에 쓴 건수와 제외한 건수를 함께 표시합니다.

## 금지
- 클라이언트 실명을 화면에 넣지 않습니다.
- 계약 금액이나 수수료율을 표시하지 않습니다.
- 요청하지 않은 기능을 추가하지 않습니다.

## 작업 방식
- 산출물은 항상 coding 폴더 안에만 만듭니다.
- 수정할 때는 지정한 부분만 고치고 나머지는 그대로 둡니다.

## 자주 틀리는 것
(여기에 한 줄씩 추가해 나갈 것)
```

**오늘 배운 것이 전부 여기 들어갔습니다.** 세 개의 벽에 대한 대응이 그대로 규칙이 됐습니다. 이 파일 하나가 오늘 하루를 기억합니다. 맨 아래 "자주 틀리는 것"은 지금 비워두고, 같은 실수를 만날 때마다 한 줄씩 채웁니다.


**길수록 나빠집니다.** 이 파일은 매번 다시 읽힙니다 - 컨텍스트 붕괴와 같은 원리로, 분량이 늘면 중요한 것이 묻힙니다. 20\~30줄로 시작하고, 판단 기준은 하나입니다: "이건 AI가 알아낼 수 있나?" 알아낼 수 있으면 지우고, 절대 알 수 없는 것(클라이언트 실명 금지 등)만 남깁니다.

## Step 02 :: 규칙이 실제로 적용되는지 확인합니다.
파일 탐색기에서 `coding` 폴더 안에 `CLAUDE.md`가 있는지 확인합니다(하위 폴더 안이면 안 됩니다, 이름은 전부 대문자여야 합니다).
`/context`를 입력창에 치면 지금 무엇이 읽혀 있는지 보여줍니다. 목록에 `CLAUDE.md`나 Memory가 보이면 읽히고 있는 것입니다.

**같은 대화에서 시험하면 의미가 없습니다.** 방금 말한 내용이 대화에 남아 있어서 파일 덕분인지 대화 덕분인지 구분이 안 됩니다. `/clear`로 대화를 비운 뒤, 규칙에 있는 것을 말하지 않고 요청해봅니다.

```javascript
아래쪽에 합계 행을 추가해줘.
```
천 단위 쉼표나 오른쪽 정렬을 말하지 않았는데도 적용되면 성공입니다. 안 먹히면 위치(하위 폴더에 있는가)·이름(정확히 CLAUDE.md인가)·대화 길이(새 대화에서 다시 해보기)를 순서대로 확인합니다.

## Step 03 :: 반복 작업을 Skill로 묶습니다.

**Skill을 먼저 만들려고 하면 잘 안 됩니다.** 성공한 경험이 있어야 뽑을 게 생깁니다. 오늘 앞에서 만들고 지금 뽑는 것이 정석 순서입니다.

Skill은 폴더 하나에 파일 하나입니다.
```javascript
coding/

    └ skills/
       └ dashboard-maker/        ← 폴더 하나
          └ SKILL.md             ← 그 안에 파일 하나
```

본문

실제 작업 방법

이 작업이라고 판단됐을 때만



**Claude는 평소에 description만 보고 있습니다.** 요청이 이 설명과 맞으면 그때 본문을 펼쳐 그대로 따릅니다. 설명이 부실하면 본문이 아무리 좋아도 안 꺼냅니다 - 서가에 책은 있는데 책등에 제목이 없는 것과 같습니다. 그래서 Skill을 여러 개 가지고 있어도 부담이 없습니다.

`skill-creator`를 써서 만듭니다 - Claude가 이미 가지고 있는, Skill을 만들어주는 Skill입니다. 폴더 구조·파일 이름·형식을 알아서 맞춰줍니다.
```javascript
skill-creator를 써서, 오늘 진행한 작업을
앞으로 반복해서 쓸 수 있는 Skill로 만들어줘.

- 그걸 보기 좋은 화면으로 만들어야 합니다

작업 순서와 확인할 점도 같이 넣어줘.
반드시 포함할 것이야.
```

**이름 규칙** - 파일 이름은 정확히 `SKILL.md`(대소문자까지), 폴더 이름은 영문 소문자와 붙임표만(예: `dashboard-maker`, 공백·대문자·밑줄·한글 금지). **작업 규칙(****CLAUDE.md****)과 Skill의 차이** - "매번 지켜야 하나"면 작업 규칙, "부를 때만 하나"면 Skill입니다.

`SKILL.md`에도 "자주 틀리는 것" 항목을 하나 만들어두세요. 본문을 잘 쓰는 것보다 이 목록 한 줄이 실수를 더 잘 막습니다.
확인은 이렇게 합니다: `방금 만든 Skill, 언제 쓰는 거야?`라고 물어봅니다.

만들어보셨으니 무엇이 좋은 Skill인지 정리해둡니다. 회사에서 두 번째, 세 번째를 만드실 때 쓰입니다.

**② 「자주 틀리는 것」 목록을 두세요.** 본문을 잘 쓰는 것보다 이 목록 한 줄이 실수를 더 잘 막습니다.
```javascript
## 자주 틀리는 것
- 금액에 쉼표를 안 넣음. 반드시 명시할 것
- 표를 만들면 좁은 화면에서 잘림. 카드 배치로 유도
- 빈 값을 0으로 계산함. 「미입력」으로 두라고 못박을 것
```
**③ 실제로는 이렇게 자랍니다.** 오늘은 「업무 화면 만드는 방법」이 전부, 2주 뒤에 주의 한 줄 추가, 두 달 뒤에 주의 항목이 여섯 개로 늘면 그때부터는 거의 실수하지 않습니다. **처음부터 완벽하게 만들려고 하지 마세요.**
**④ 너무 가두지 마세요.** ❌ 「반드시 A → B → C 순서로 하고 결과를 D 형식으로 저장하라」 → ✅ 「이런 것들이 있고 각각 이럴 때 쓴다. 상황에 맞게 조합하라」. 순서를 못 박으면 상황이 조금만 달라져도 이상해집니다.
**⑤ 길어지면 나누세요.** 본문에는 핵심만 두고 상세한 것은 별도 파일로 뺜니다.
**⑥ 성공한 뒤에 뽑으세요.** 먼저 만들려고 하면 뽑을 게 없습니다. 오늘 앞에서 만들고 지금 뽑는 것이 정석 순서입니다.

## Step 04 :: 다음에 이어받을 수 있게 인수인계 문서를 만듭니다.

오늘 작업한 대화는 다음에 새 창을 열면 없습니다. 그리고 오늘 쓴 것은 교육용 계정이라, 회사에 돌아가 회사 계정에서 다시 만드셔야 합니다. 손에 파일이 없으면 오늘 하루 다듬은 것을 기억에 의존해 다시 쓰게 됩니다.

```javascript
오늘 만든 것을 다음에 새 대화에서 그대로 이어받을 수 있게 정리해줘.

coding 폴더에 06_인수인계.md 로 저장해줘.

들어갈 내용이야.
- 무엇을 왜 만들었는지
- 누가 언제 쓰는 것인지
- 현재 어떤 기능이 구현돼 있는지
- 저장 방식과 현재 저장된 데이터 구조
- 아직 안 한 것과 다음에 할 것
- 오늘 막혔던 지점과 어떻게 풀었는지
```

**"오늘 막혔던 지점" 항목을 꼭 넣으세요.** 다음에 같은 곳에서 또 막힙니다. 적어두면 그때 바로 넘어갑니다.

폴더에 이것들이 다 있는지 확인합니다.
```javascript
coding/
  ├── 02_명세서.md
  ├── 03_데이터.csv
  ├── 04_결과물.html
  ├── 05_백업.html
  ├── 06_인수인계.md
  ├── CLAUDE.md
```
