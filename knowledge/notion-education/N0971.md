# 1부 · 프롬프트와 시스템 프롬프트는 다른 물건입니다

## 둘을 섞을 때 생기는 일
현장에서 가장 흔한 패턴입니다.
```plain text
월요일  "개조식으로, 수치 지어내지 말고, 빈칸은 [확인 필요]로…" (20줄 입력)
화요일  "개조식으로, 수치 지어내지 말고, 빈칸은 [확인 필요]로…" (또 20줄)
수요일  귀찮아서 몇 줄 빼먹음 → 결과물 형식이 틀어짐
목요일  "AI가 어제랑 다르네요" → 사실은 지시문이 달라진 것
```

반복되는 것을 지시문에 계속 쓰고 있다면, 그건 **시스템 프롬프트로 가야 할 내용**입니다.
세 번 이상 반복해서 입력한 문장은 전부 후보입니다. `원리 4`

능력을 적으면 AI가 **그 능력을 쓰려고 합니다.** 직함만 주면 직함처럼 말만 합니다.

**실무자만 아는 지점 — 목적을 두 겹으로 쓰세요**
맥락에 "왜 시키는지"를 적을 때 **1차 이유와 진짜 목적**을 나눠 쓰면 결과가 달라집니다.
```plain text
1차 이유  — 발주처에 내일 아침까지 점검일지를 내야 합니다.
진짜 목적 — 다만 이번 건은 CHP-2 진동이 7주째 방치된 상태라,
            이 항목이 조치 대상으로 명확히 드러나게 하는 것이 실제 목적입니다.
```
진짜 목적을 적으면 AI가 **그 항목을 묻히지 않게 배치**합니다. 안 적으면 그냥 한 줄로 끝납니다.


**실무자만 아는 지점 — 범위의 경계를 그으세요**
앞으로 할 일 전체를 알려 주고, 이번에 할 것만 지정하면 AI가 선을 넘지 않습니다.
```plain text
1단계 오늘 — 점검일지 초안 작성 (지금 시키는 것)
2단계 내일 — 조치 항목별 견적 정리
3단계 이번 주 — 발주처 보고용 요약본
2·3단계는 지금 하지 말고, 1단계 결과가 그 다음에 쓰일 것만 감안해 주세요.
```
이걸 안 적으면 AI가 묻지도 않은 견적과 요약본까지 만들어 놓습니다.

## T · 과제
한 번에 여러 가지를 시키면 AI는 가장 쉬운 것만 처리하거나 뭉뚱그려 답합니다. <br>번호로 나누면 순서대로 처리합니다. → 단계별로 시키는 연습. → 귀찮음. (Cot 기법)
```plain text
1) 메모에서 점검 시각별로 항목을 분리하세요.
2) 각 항목을 기계 / 전기 / 소방 / 방재 / 기타로 분류하세요.
3) 분류한 항목 중 관리기준을 벗어났거나 조치가 필요한 것만 골라내세요.
4) 골라낸 항목을 조치 시급도 순으로 정렬하세요.
5) 정렬 결과를 발주처 제출용 보고서 형식으로 작성하세요.
```





나쁜 구성

좋은 구성




각 단계가 서로 무관함

앞 결과가 뒤의 입력이 됨




1) 정리 2) 요약 3) 제목 달기

1) 분류 2) 그중 기준 초과 선별 3) 선별한 것을 시급도 정렬


**앞 단계 결과가 뒤 단계 재료가 되도록** 쓰세요. 3번을 하려면 2번 결과가 있어야 하므로 AI가 중간을 건너뛰지 못합니다.
마법의 문장: `단계별로 생각해서 답해 주세요`

**실무자만 아는 지점 — 빠진 걸 물어보게 하세요**
마지막 단계에 이 한 줄을 붙이면 결과가 달라집니다.
```plain text
6) 위 작업을 하기 전에, 내가 놓친 항목이나 추가로 넣으면 좋을 내용이 있으면
   먼저 알려 주세요. 내가 확인한 뒤에 진행하겠습니다.
```
AI가 **작업 계획을 먼저 보고**합니다. 방향이 틀렸으면 여기서 잡을 수 있습니다.
단계는 3\~5개가 적당합니다. 여섯을 넘으면 뒤쪽이 부실해집니다.

종류

예시




**원자료**

이번에 처리할 대상

야간순회 메모, 민원 대장, 근무일지




**골든 샘플**

결과물이 따라야 할 형식

지난달 운영보고서, 기존 공문 양식


대부분의 사람이 원자료만 넣습니다. 그래서 내용은 맞는데 **형식이 우리 것이 아닌** 문서가 나옵니다.
```plain text
아래는 8월 14일 야간순회 메모 원문입니다.
여기 적힌 사실만 사용하세요. 여기 없는 내용은 추가하지 마세요.
```
"여기 적힌 사실만 사용하세요"라는 한 줄이 중요합니다. 자료를 주기만 하고 이 문장을 안 쓰면 AI가 자료 밖의 내용을 섞습니다.

**실무자만 아는 지점 — 나쁜 예시도 함께 주세요**
좋은 예시만 주면 AI가 "어느 선까지가 안 되는지"를 모릅니다.
```plain text
이런 문장은 피해 주세요 —
"향후 지속적인 관리를 통해 만전을 기하겠음"
```
**좋은 예 1개 + 나쁜 예 1개**가 좋은 예 3개보다 정확합니다.

**실습 · 내 업무 지시문 만들기 (15분)**
1. 내가 매달 또는 매주 반복해서 만드는 문서를 하나 고르세요 (2분)
2. 아래 워크시트를 채우세요 (8분)
3. ChatGPT에 넣고 결과를 확인하세요 (3분)
4. 진단표를 보고 빠진 블록을 하나 찾아 보완하세요 (2분)

```plain text
[R] 당신은 ____________________________________________ 입니다.
    능력 1) ______________________________________________
    능력 2) ______________________________________________

[C] 현장 / 부서 : ______________________________________
    수신처       : ______________________________________
    문서 종류    : ______________________________________
    제출 시점    : ______________________________________
    진짜 목적    : ______________________________________

[T] 1) ______________________________________________
    2) ______________________________________________
    3) ______________________________________________
    4) 작업 전에 내가 놓친 항목이 있으면 먼저 알려 주세요.

[C] 형식 : ____________________________________________
    금지 : 제가 제공하지 않은 수치·판정은 절대 만들지 마세요.
           자료에 없는 항목은 [확인 필요]로 표시하세요.
           확실하지 않으면 아는 척하지 말고 질문해 주세요.

[K] 원자료     : ______________________________________
    골든 샘플  : ______________________________________
```

**완료 기준**
- [ ] R에 직함뿐 아니라 능력이 번호로 들어갔다
- [ ] C에 수신처가 명시되었다
- [ ] C에 진짜 목적이 적혔다
- [ ] T가 3단계 이상이고 앞뒤가 연결된다
- [ ] C에 지어내기 금지와 \[확인 필요\] 표기가 들어갔다
- [ ] K에 원자료와 골든 샘플이 구분되어 있다
- [ ] 지시문을 따로 저장했다


**오늘의 진짜 산출물은 결과물이 아니라 이 지시문입니다.**
결과물은 이번 주에 쓰고 끝나지만, 지시문은 다음 달에도 그대로 씁니다.
그리고 이 지시문이 모듈 06에서 GPTs 지침의 재료가 됩니다.
