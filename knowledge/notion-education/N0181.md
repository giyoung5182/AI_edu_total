# 11장 · CLAUDE.md — 항상 켜져 있는 규칙

## 11-1. 아까 몇 번이나 말씀하셨나요
지난 교시에 웹 페이지를 만드시면서 이런 말들을 하셨을 겁니다.
```plain text
"글자 더 크게"
"초등학생이 볼 거야"
"쉬운 말로 써줘"
"한국어로 해줘"
```
**몇 번이나 하셨나요?** 세 번? 다섯 번?
그리고 지금 **새 세션을 열면 또 처음부터 말해야 합니다.** Claude는 이전 대화를 기억하지 못하기 때문입니다.
## 11-2. 그래서 파일에 적어둡니다
`CLAUDE.md`는 **프로젝트 폴더에 두는 규칙 파일**입니다.
이 파일이 폴더에 있으면, 그 폴더에서 작업을 시작할 때마다 Claude가 **자동으로 읽습니다.** 매번 말할 필요가 없어집니다.
```plain text
sw2026/
  ├── CLAUDE.md      ← 세션 시작할 때마다 자동으로 읽힘
  ├── index.html
  └── 기획서.md
```
> 💡 학기 초에 학급 규칙을 정해서 게시판에 붙여두는 것과 비슷합니다.<br>매 시간 "떠들지 마세요"를 반복하는 대신, 한 번 붙여두고 "규칙 3번"이라고 하면 되는 것처럼요.
### 정확히 어떻게 작동하나요
CLAUDE.md 파일은 누적됩니다. 여러 위치의 파일이 동시에 Claude의 맥락에 들어갑니다. 작업 폴더와 그 상위 폴더의 파일은 시작할 때 로드되고, 하위 폴더의 파일은 그 폴더에서 작업할 때 로드됩니다. 지시가 서로 충돌하면 Claude가 판단해서 조정하는데, 대체로 더 구체적인 지시가 우선합니다.
**우리에게 중요한 건 이겁니다.**
```plain text
파일을 폴더 최상위에 둔다  →  그 폴더 작업은 항상 규칙이 적용된다
```

# 12장 · Skill — 필요할 때만 꺼내는 작업서
> ⏱️ 15:20 \~ 15:50 (30분)
## 12-1. 카페의 제조법
카페에서 "딸기 요거트 스무디 주세요"라고 주문한다고 해봅시다.
손님이 매번 이렇게 설명하지는 않습니다.
```plain text
딸기를 넣고,
요거트 파우더를 넣고,
우유를 넣고,
얼음을 넣고,
믹서기로 갈아주세요.
```
**가게 안에 이미 제조법이 있기 때문**입니다. 직원은 그 제조법을 보고 만듭니다.
그리고 중요한 건 — **아메리카노를 주문했을 때는 스무디 제조법을 꺼내보지 않습니다.** 필요할 때만 꺼냅니다.
> 💡 **Skill은 AI에게 주는 제조법입니다.**<br>"이런 걸 만들 때는 이런 순서로, 이런 기준으로 해줘"를 미리 적어두는 것입니다.<br>그리고 **그 작업을 할 때만** 꺼내 읽습니다.

### 왜 이 차이가 중요한가
CLAUDE.md는 **항상 읽히기 때문에 길면 안 됩니다.** 그런데 작업 절차는 원래 깁니다. "이 파일을 받아서, 이렇게 확인하고, 이런 형식으로 만들고, 다 되면 이걸 점검한다" — 이걸 다 CLAUDE.md에 넣으면 파일이 터집니다.
**그래서 나눠 둡니다.**
```plain text
항상 필요한 것   →  CLAUDE.md    (짧게)
가끔 필요한 것   →  Skill        (길어도 됨)
```
### 작동 방식 — 이름표만 보고 있다가 펼칩니다
이게 Skill의 핵심 원리입니다. 공식 문서에서는 이걸 **점진적 공개**라고 부르고, **3단계**로 설명합니다.





단계

무엇이

언제 읽히나




**1단계**

이름 + 설명

**항상** — 다만 아주 짧음




**2단계**

SKILL.md 본문

이 작업과 관련 있다고 판단될 때




**3단계**

딸린 참고 파일들

본문을 읽다가 필요해질 때


```plain text
평소            "학습 안내 페이지 만들기" 라는 이름표만 보고 있음
                                ↓
내가 요청       "학습 안내 페이지 만들어줘"
                                ↓
2단계           이름표가 맞으니까 → 본문을 펼쳐서 읽음
                                ↓
3단계           본문에 "자세한 건 학년별표현.md 참고" → 그것도 읽음
```
> 💡 도서관 서가에 책등만 보이는 것과 같습니다. 필요한 책만 뽑아서 펼치고, 그 책이 다른 책을 가리키면 그때 또 뽑습니다.<br>**그래서 Skill은 10개, 20개를 갖고 있어도 부담이 없습니다.**
## 12-3. Skill은 파일이 아니라 폴더입니다
가장 흔한 오해입니다. "SKILL.md 파일 하나 아닌가요?"
**아닙니다. 폴더입니다.**
```plain text
class-page-maker/
  ├── SKILL.md              ← 핵심 지침 (필수)
  ├── references/           ← 필요할 때 읽는 참고 문서 (선택)
  │     └── grade-words.md
  ├── assets/               ← 결과물에 쓰는 템플릿·서식 (선택)
  │     └── base.html
  └── scripts/              ← 실행할 코드 (선택)
```
이렇게 하면 **SKILL.md는 짧게 유지하면서**, 상세 내용은 필요할 때만 추가로 읽게 할 수 있습니다.
### ⚠️ 이름 규칙 — 안 지키면 아예 안 올라갑니다
공식 문서에 정해진 규칙이 있습니다. 잘못 지으면 오류가 납니다.
**파일 이름**
```plain text
✅ SKILL.md        ← 정확히 이것만. 대소문자까지 같아야 합니다
❌ Skill.md  ❌ skill.md  ❌ SKILL.MD
```
**폴더 이름** — 영문 소문자와 붙임표(-)만 씁니다.
```plain text
✅ class-page-maker
❌ Class Page Maker      (공백·대문자 금지)
❌ class_page_maker      (밑줄 금지)
❌ 학습페이지-만들기       (한글은 피하세요)
```
> 💡 폴더 안의 내용은 한국어로 쓰셔도 됩니다. **폴더 이름과 SKILL.md 안의 ****`name`**** 값만** 영문 소문자로 지으시면 됩니다.
**그 외 규칙 두 개**
```plain text
· Skill 폴더 안에 README.md 를 넣지 마세요
  → 설명은 SKILL.md 나 references/ 에 넣습니다

· 이름에 claude 나 anthropic 을 넣지 마세요 (예약어)
```
> 💡 오늘 실습에서는 Claude가 알아서 규칙에 맞게 만들어줍니다. **다만 나중에 직접 손볼 때** 이 규칙을 알고 계셔야 합니다.

## 실습 · Skill 만들고 써보기 (22분)
### STEP 1 · Skill 만들기 (8분)
방금 하신 작업을 그대로 Skill로 정리시킵니다.
> 💡 **지금 이 순서가 공식이 권장하는 방식입니다.**<br>Anthropic 가이드에는 이렇게 적혀 있습니다.<br>**"하나의 어려운 작업에서 성공할 때까지 반복한 다음, 그 성공한 방식을 Skill로 추출하라."**
우리가 4교시에 먼저 만들고 지금 Skill로 뽑는 게 바로 이것입니다.<br>**먼저 Skill부터 만들려고 하면 잘 안 됩니다.** 성공한 경험이 있어야 뽑을 게 생깁니다.
Claude에는 **Skill 만드는 걸 도와주는 기능이 이미 들어 있습니다.** 따로 설치하실 게 없습니다.
```plain text
skill-creator를 써서, 방금 진행한 작업을
앞으로 반복해서 쓸 수 있는 Skill로 만들어줘.

이 Skill은 이런 상황에서 씁니다.
- 수업에 쓸 안내 자료 내용이 있습니다
- 그걸 학생들이 볼 수 있는 웹 페이지로 만들어야 합니다
- index.html 파일 하나로 만듭니다
- 초등학생이 보기 쉬워야 합니다

작업 순서와 확인할 점도 같이 넣어줘.
폴더 이름은 영문 소문자로 지어줘.
```
> 💡 마지막 줄을 넣는 이유는 12-3의 이름 규칙 때문입니다.
### 화면에서 일어나는 일
```plain text
1. Claude가 Skill 폴더와 SKILL.md를 만들겠다고 합니다
2. 승인 화면에 만들 내용이 표시됩니다
3. [수락]
4. 폴더에 Skill 폴더가 하나 생깁니다
```
> ✅ **체크포인트**: Skill이 만들어졌다는 응답이 나오면 OK.
### STEP 2 · 내용 확인 (4분)
**그냥 쓰지 마시고 한 번 읽어보세요.** Claude가 만든 것도 검토가 필요합니다.
```plain text
방금 만든 Skill 내용을 보여줘.
```
### 확인할 다섯 가지
```plain text
□ 언제 쓰는 Skill인지 설명이 적혀 있는가   ← 제일 중요
□ 어떤 자료를 받는지 적혀 있는가
□ index.html 파일 하나로 만든다고 되어 있는가
□ 글자 크기·쉬운 말 기준이 들어 있는가
□ 작업 후 확인할 것이 적혀 있는가
```
### ⚠️ 첫 번째 항목이 가장 중요합니다
Skill 맨 위에는 **"이건 이럴 때 쓰는 겁니다"** 라는 설명이 들어갑니다.
Claude는 평소에 **이 설명만 보고 있습니다.** 여기가 부실하면, 아무리 안쪽 내용이 좋아도 **꺼내 쓰질 않습니다.**
```plain text
❌ "웹 페이지를 만드는 스킬"
   → 너무 막연해서 언제 써야 할지 모름

✅ "수업 자료 내용을 학생용 안내 웹 페이지로 만들 때 사용.
    차시 안내, 활동 순서, 준비물 안내 등."
   → 언제 꺼낼지 분명함
```
부족하면 바로 보완합니다.
```plain text
설명 부분을 더 구체적으로 고쳐줘.
'차시 안내, 활동 순서, 준비물 안내를 만들 때 쓴다'는 걸
분명하게 적어줘.
```
### ⭐ 제대로 꺼내지는지 확인하는 법
공식 문서에 나오는 **가장 쉬운 진단 방법**입니다. 그냥 물어보면 됩니다.
```plain text
방금 만든 Skill, 언제 쓰는 거야?
```
Claude가 **설명에 적힌 내용을 그대로 읊어줍니다.** 그 대답을 들어보면 뭐가 빠졌는지 바로 보입니다.
```plain text
❌ "웹 페이지를 만들 때 씁니다"
   → 너무 막연함. 이러면 안 꺼내집니다

✅ "수업 자료를 학생용 안내 페이지로 만들 때 씁니다.
    차시 안내, 활동 순서, 준비물 안내 같은 것들이요"
   → 이 정도면 잘 꺼내집니다
```
### 반대로, 아무 때나 꺼내질 때
나중에 Skill이 여러 개가 되면 **엉뚱한 데서 튀어나오는** 문제가 생깁니다. 그럴 땐 **하지 말아야 할 상황을 적어줍니다.**
```plain text
설명에 이런 내용도 넣어줘.
'단순히 글을 정리하거나 문서를 만들 때는 쓰지 않는다'
```
> 💡 **"\~할 때는 쓰지 마세요"** 한 줄이 의외로 효과가 큽니다.
### STEP 3 · 두 번째 결과물 만들기 (10분) ★
**여기가 오늘의 핵심입니다.**
이번엔 **다른 주제**로 하나 더 만듭니다. 아까처럼 길게 설명하지 않습니다.
```plain text
새로 class2 폴더를 만들고,
방금 만든 Skill을 써서 [다른 주제]로 하나 더 만들어줘.
```
`[다른 주제]` 자리에는 이런 걸 넣으시면 됩니다.
```plain text
· 다음 차시 준비물 안내 페이지
· 모둠 활동 순서 안내
· 안전 수칙 확인 페이지
· 학기말 정리 안내
```
### 완성되면 시간을 재보세요
```plain text
아까 처음 만들 때  →  43분
지금 두 번째       →  ?분
```
**같은 일을 훨씬 짧게 끝냈습니다.** 이게 Skill입니다.
> 💡 처음 한 번은 오래 걸립니다. 하지만 그 과정을 Skill로 정리해두면, 다음부터는 계속 짧아집니다.
학기마다, 차시마다 반복하는 일이라면 **첫 번째에 들인 시간이 계속 돌아옵니다.**
> ✅ **체크포인트**: `class2` 폴더에 새 `index.html`이 생겼고, 브라우저에서 열리면 OK.

## 12-4. 앞으로 Skill을 늘려가는 방법
오늘 하나 만들어보셨습니다. 집에 가서 이렇게 늘려가시면 됩니다.
```plain text

        ↓

        ↓
④ 계속 좋아짐
```
