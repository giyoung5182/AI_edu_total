# Part 4. 발표자료 설계서 쓰는 법 (35분)
## 4-1. 오늘 배우는 것은 도구가 아닙니다
**핵심**
발표자료를 만들어 주는 AI 도구는 지금도 여러 개고 앞으로 더 늘어납니다. 무료 크레딧 정책도 수시로 바뀝니다. 어떤 도구는 반년 뒤 서비스를 종료합니다.
그런데 어떤 도구를 쓰든 바뀌지 않는 것이 하나 있습니다. **결과 품질은 입력 품질이 결정합니다.**
```plain text
도구 사용법을 배운 사람   →  그 도구가 바뀌면 처음부터 다시
설계서를 쓸 줄 아는 사람  →  도구가 무엇이든 같은 품질
```
오늘 배우는 설계서는 발표자료 자동 생성 도구에 넣어도, 파워포인트 코파일럿에 넣어도, Claude나 Gemini에 넣어도 동일하게 작동합니다. 심지어 AI를 쓰지 않고 직접 만들 때도 그대로 쓸 수 있습니다. 설계서 자체가 이미 발표자료의 뼈대이기 때문입니다.

## 4-3. 설계서 4블록 구조
**핵심**

AI가 청중과 목적을 모르면 일반론을 씁니다. 다음 항목을 채우세요.

```plain text

   - 발표자:
   - 사용 도구:

2) 유의사항
   - (청중 특성상 반드시 고려할 점)
   - (오해하기 쉬운 지점)
   - (강조해야 할 점)

3) 최종 목적
   - 컨셉:
   - 이 발표가 끝났을 때 청중이 하게 될 행동:

4) 전체 흐름 (시간 배분 포함)
   - 도입 (○분):
   - 본론 1 (○분):
   - 본론 2 (○분):
   - 마무리 (○분):
```
### 유의사항 항목이 특히 중요합니다
여기가 자료의 성격을 결정합니다. 예를 들어 같은 사업 설명회라도 이렇게 달라집니다.
```plain text

"신청 경험이 없는 기업이 대부분임. 용어를 풀어 쓰고,
 서류 준비 단계에서 막히는 지점을 미리 짚을 것."

대상이 재신청 기업일 때
"작년 신청 경험이 있는 기업임. 기본 설명은 생략하고
 올해 바뀐 부분만 명확히 대비시켜 보여줄 것."
```

## 4-6. 블록 3 — 디자인 규격
AI에게 "깔끔하게"라고 하면 평균이 나옵니다. `원리 셋` 색상 코드까지 지정하세요.
```plain text
[블록 3. 디자인 규격]

- 배경색: #FFFFFF (기본) / #F4F5F7 (섹션 구분용)
- 주색상: #(기관 표준색)
- 강조색: #(포인트 색 하나만)
- 글꼴: 프리텐다드 또는 본고딕(Noto Sans KR)
- 글자 크기: 제목 40pt 이상, 본문 28pt 이상
- 비율: 16:9 고정
- 레이아웃 규칙:
  · 하단에 빈 공간이 남지 않도록 화면 전체를 채울 것
  · 요소 간 겹침과 잘림이 없도록 배치할 것
  · 큰 도표와 그래픽을 적극 사용할 것
- 이미지: 미니멀 벡터 아이콘과 평면 그래픽만 사용.
  고해상도 사진이나 3D 렌더는 사용하지 말 것
- □ → ❍ → - → ※ / ▸ 4단 기호 체계를 항상 지킬 것.
```
### 색상 코드를 쓰는 이유
"남색"이라고 쓰면 AI가 남색의 평균을 씁니다. `#1A3C34`라고 쓰면 정확히 그 색이 나옵니다. 기관 표준 색상이 있다면 코드로 확인해서 넣으세요.
**실전 노하우**
색은 세 개까지만 쓰세요. 배경색, 주색상, 강조색. 네 개를 넘으면 공공 문서로서의 격식이 흐트러집니다.<br>색은 세 개까지 지정해주는 게 귀찮다면, 메인색 하나를 설정해주시고 “어울리는 색깔 2개를 알아서 골라서 사용해줘”라고 해도 됩니다.
### 레이아웃 규칙에 검수 조건을 함께 넣으세요
```plain text
"컴포넌트 요소가 깨지거나 겹치지 않도록
 작업 후 다섯 번 이상 확인할 것."
```
이 한 문장이 실제로 결과를 개선합니다. AI가 생성 후 자체 점검 과정을 거치도록 유도하는 지시입니다.

## 4-7. 블록 4 — 산출 규칙
여기가 **AI 티를 없애는 블록**입니다.
```plain text
[블록 4. 산출 규칙]

1) 말투
   - 구어체 사용 금지
   - 종결어미를 최소화하고 개조식으로 작성할 것
   - 예: "디자인씽킹 기법은 ~~~하는 것입니다" (X)
         "디자인씽킹 기법: ~~~" (O)

2) 사실 관계
   - 내가 제공하지 않은 수치나 사실은 절대 추가하지 말 것
   - 자료에 없는데 필요한 항목은 [확인 필요]로 표시할 것
   - 추정·예상·전망은 근거가 제공된 경우에만 서술할 것

3) 구성
   - 한 장에 두 가지 이상의 주제를 섞지 말 것
   - 한 장에 내용이 넘치면 억지로 넣지 말고 장을 분리할 것
   - 장을 분리했을 경우 작업 후 어느 부분을 추가·수정했는지 보고할 것

4) 재량
   - 설계도는 가이드이며, 전체 맥락상 필요한 내용이 있으면 추가해도 됨
   - 지시대로만 따르지 말고 빠진 부분이 있으면 보완할 것
```
### 네 항목의 의미
**1) 말투**
개조식 지정이 AI 티를 없애는 가장 강력한 장치입니다. AI는 기본적으로 설명형 구어체를 씁니다. 공공기관 발표자료에는 맞지 않습니다.
**2) 사실 관계**
`원리 여덟`의 실행입니다. `[확인 필요]` 표시 강제가 핵심입니다. 빈칸을 창작으로 메우는 것을 구조적으로 막습니다.
**3) 구성**
`원리 일곱`의 실행입니다. 마지막 문장 — 변경 사항 보고 요청 — 이 실무에서 매우 유용합니다. 무엇이 바뀌었는지 알아야 검토할 수 있습니다.
**4) 재량**
이 항목이 없으면 AI는 설계도에 없는 것을 절대 넣지 않습니다. 설계도에 구멍이 있을 때 그대로 구멍이 뚫린 자료가 나옵니다. 재량을 허용하되 보고하게 하는 것이 균형점입니다.

## 4-9. 설계서를 AI에게 대신 쓰게 하기
`원리 다섯`
설계서를 매번 처음부터 쓰는 것은 부담입니다. **초안을 AI에게 맡기고 사람이 검토하는 방식**이 현실적입니다.
```plain text
아래 자료를 읽고, 발표자료 설계서 초안을 작성해 줘.
아직 슬라이드는 만들지 말고 설계서 텍스트만 줘.
```
