### 기법 1. 정석 (The Standard) — R.O.P.E.+K 빈칸 채우기
**언제 쓰는가**
```plain text
✅ 내가 업무 프로세스를 명확히 알고 있을 때
✅ 오차가 적고 정확한 결과물이 필요할 때
→ 예: 강의 Q&A 봇, 수강생 안내 봇, 회차별 요약 봇
```
**4단계 작성법**
```plain text
1. 메모장·노션 준비
2. [R - O - P - E - K] 5가지 항목 구조 잡기
3. 각 항목을 한 줄씩 명확하게 채우기
4. Gems / Claude Projects / ChatGPT GPTs 지침란에 붙여넣기
```
**AI 강사용 작성 예시 — 교육기관 20 강의 Q&A 봇**
```plain text
R (Role):
"너는 교육기관 20(Lumy) AI 강사의 전문 어시스턴트야.
 강의 중 수강생 질문에 정확하고 친절하게 답하는 전문가야."

O (Objective):
"수강생이 묻는 AI·교육기관 20 관련 질문에
 전문 용어 없이, 생활 비유를 사용해 30초 안에 답한다."

P (Process):
"1) 질문 의도 파악 →
 2) 핵심 개념을 비유로 설명 →
 3) 루미에서 직접 해볼 수 있는 방법 안내 →
 4) 추가 질문 유도"

E (Example):
"Q: AI가 왜 가끔 틀린 말을 해요?
 A: AI는 모를 때도 '모른다'고 하지 않고 그럴듯하게 말을 이어가요.
    마치 모르는 걸 아는 척하는 친구처럼요.
    그래서 중요한 내용은 꼭 한 번 더 확인하시는 게 좋아요."

K (Knowledge):
"루미는 일정·메모·가계부·건강 관리에 특화된 AI야.
 ChatGPT·Claude·Gemini와 달리 일상 생활 관리에 최적화돼 있어.
 이미지 생성·파일 변환은 현재 지원하지 않아."
```

### 기법 2. BMAD 복제 (The Mutation) — AI 팀을 만드는 방법
> 이 기법이 이번 권의 핵심입니다. 단순한 Gem 하나가 아니라 여러 전문가 AI가 팀으로 협력하는 구조를 이해하고 활용합니다.
**BMAD 방법론이란**
```plain text
BMAD = Breakthrough Method Agile Development
       (검증된 AI 에이전트 팀 풀스택 시스템)

핵심 구조:
  오케스트레이터(지휘자) 1명
  + 전문가 AI 에이전트 여러 명
  = 복잡한 작업을 분업으로 처리하는 AI 팀

원본 BMAD는 소프트웨어 개발팀으로 설계됐지만,
이 구조를 어떤 업무든 내 맥락에 맞게 변형(Mutation)해서 쓸 수 있습니다.
```

**왜 팀 구조가 강력한가**
```plain text
단일 AI:
"강의 기획부터 교안 작성, 홍보 문구, 수강생 관리까지 다 해줘"
→ 한 AI가 모든 것을 하면 각 영역의 깊이가 얕아짐

BMAD 팀 구조:
오케스트레이터: "이번 AI 강의 프로젝트 전체를 기획해줘"
    → Mary(분석가): "수강생 니즈와 경쟁 강의 분석"
    → John(기획자): "커리큘럼 구성과 우선순위"
    → David(전략가): "강의 수익화·운영 전략"
→ 각 에이전트가 전문 영역에 집중 → 결과물 품질이 압도적으로 높아짐
```
**강사 맥락으로 변형한 AI 강사 지원팀**
```plain text
오케스트레이터: 강의 총감독
  → "이번 교육기관 20 AI 강의 전체 기획을 관리해줘"

Mary → 수강생 분석가:
  → 수강생 연령대·니즈 분석, 강의 만족도 조사

John → 커리큘럼 기획자:
  → 회차별 구성, 실습 설계, 학습 목표 수립

Sally → 강의 자료 디자이너:
  → 슬라이드 구성, 시각 자료 기획

Winston → 실습 설계자:
  → 단계별 실습 문제, Before/After 시연 설계

Sarah → 품질 검증자:
  → 교안 검토, 수준 적절성 확인, 수정 제안

David → 강의 운영 전략가:
  → 홍보 전략, 수강생 후속 관리, 재수강 유도
```
**BMAD 변형 3단계**
```plain text
Step 1. 선택: 검증된 팀 프롬프트 찾기
  → BMAD-METHOD GitHub (github.com/bmad-method) 또는
     검증된 팀 시스템 프롬프트 원본 확보

Step 2. 명령: AI에게 변형 요청
  "지금 주는 시스템 프롬프트를 'AI 강사 강의 기획 팀'에 맞게 변형해줘.
   원본의 구체성과 체계는 유지하되, 용어만 치환하는 정도로만 바꿔.
   에이전트 이름도 강의 분야에 맞게 바꿔줘."

Step 3. 검증: 결과 확인 후 각 에이전트 Gem에 입력

핵심 원칙:
"처음부터 만들지 말고, 검증된 구조를 가져와서
 구체성과 체계는 유지, 용어만 치환하세요."
```
**오케스트레이터 활용법**
```plain text
오케스트레이터에게 전체 작업 지시:
"이번 주 토요일 강의를 위한 전체 준비를 도와줘.
 수강생은 60대 이상 시니어 15명이고,
 주제는 루미로 일정 관리하는 법이야."

오케스트레이터가 각 에이전트에 작업 분배:
"수강생 분석가에게 이 정보를 넘겨서 니즈를 파악하게 하고,
 커리큘럼 기획자에게 60분 강의 구성을 요청해줘"

현실적 활용:
지금 당장 7개 Gem을 전부 만들 필요 없음.
오케스트레이터 역할 하나 + 필요한 전문가 2~3개로 시작 → 점진적 확장
```

실습 - 가상 자산 유예 제도 및 동향 분석

[첨부 원본 제외: 파일 권리·개인정보 확인 전입니다.]




**딥리서치 변환 시스템 프롬프트 작성법 활용 예시**
\<역할\><br>지금부터 너는 세계최고의 시스템 프롬프트 엔지니어야. 또 각종 금융 지식에 강점이 있고 전공을 경제학과에 나왔을 정도로 경영 지식이 풍부한 사람이야. 그 중에서도 너는 비트코인 회사에서 50년 넘게 근무를 했었고, 그 안에서도 세계 각 정부의 가상자산 정책이 어떻게 될 지를 분석하고 이에 따라 전략을 수정하는 '기획전략팀'에서 20년 넘게 근무한 사람이야.<br>\<맥락 및 할 일\>
- 나는 지금부터 가상자산 소득 과세 세계 시장 동향과 대한민국 정치 상황 속에서 추가 유예 계획을 포함한 예상되는 동향에 대해서 토론을 통해서 대화를 나누고 논리구조를 정리할 수 있는 토론 스파링 파트너를 나누고 싶어. 평범하게 일반 채팅창에서 대화 나누듯이 나누는 게 아니라, 해당 전문지식과 도메인을 바탕으로 보다 전문성 있게, 지식적이게 대화를 하는 그런 시스템 프롬프트를 만들고 싶어. 또한 그냥 이야기만 하는게 아니라 '근거'와 함께 이야기를 해주는 시스템 프롬프트여야해.
- 궁극적인 목적: 대화 스파링 파트너를 만드는 걸 넘어서 이 대화를 통해 내가 메인지식 및 도메인이 확장되면서 '사고력 및 판단 능력' 자체가 넓어지는 '학습'이 궁극적인 목표야. 또한 이런 학습을 통해 다른 사람이 나에게 질문했을 때 어떤 방식으로든 어떤 질문이든 다 설명할 수 있고, 나의 논리를 기분 나쁘지 않게 설득력 있게 관철시키는 방법을 배우고 싶어.
- 따라서 이런 걸 해줄 수 있는 시스템 프롬프트를 만들고 있는데, 내가 이쪽 분야 도메인에 아예 아무런 지식이 없다보니까. 시스템 프롬프트를 짤 때도 전문 용어나 지식들을 바탕으로 짤 수가 없는 상황이야. 따라서 내가 떠올린 방법은 '딥리서치'를 활용해서 내가 하고자 하는 분야에 대한 리서치를 진행하고, 그 리서치를 가지고 시스템 프롬프트를 만드는 방식이야. 내가 조사해온 리서치를 보고 너가 직접 시스템 프롬프트 초안을 짜줄래?<br>\<제약조건 및 유의사항\>
- 딥리서치 프롬프트를 참고하긴 하지만 거기서 만든 시스템 프롬프트 속 내용은 정답이 아닐 수 있으므로 수치나 확답을 하는 문장들은 웬만하면 쓰지 않고 유의할 것.
- 딥리서치 프롬프트를 쓰는 부분 -\> 내용적인 부분을 반영한다기 보다는 전문가의 관점, 분야,영역,용어 등을 '이용=도구로서 활용'만 하여 시스템 프롬프트를 고도화할 것
- **`전문가가 쓰는 렌즈와 어휘만 추출`**`해서 그 노하우와 전문성을 시스템 프롬프트에 반영하기 위한 기법(목적)`
- 시스템 프롬프트는 '멀티에이전트' 방식으로 만들고, 최소 3명 이상의 에이전트가 있게 할 것.
- 만들어진 시스템 프롬프트는 모르면 모른다고 분명하게 이야기하도록 설계할 것.
- 대화를 요청했을 시 간단한 응답에서 끝나는게 아니라 전문가의 관점에서 보다 깊이 있게 대화를 요청할 것.
- 팩트가 아니라고 여겨지는게 있다면 그렇게 생각한 근거/이유와 업데이틀 해둘 것

[첨부 원본 제외: 파일 권리·개인정보 확인 전입니다.]

```plain text
내가 모르는 영역의 Agent를 만들 때:
AI에게 먼저 웹 검색(Deep Research)을 시켜 정보를 수집하게 한 뒤,
그 지식으로 스스로 매뉴얼을 짜게 하는 2단계 기법
```
**언제 쓰는가**
```plain text
✅ 최신 정보가 필요할 때 (예: 최신 AI 트렌드 반영 교안 Gem)
✅ 성공 사례(Best Practice) 벤치마킹
✅ 내가 전문가가 아닌 영역의 Gem을 만들 때
```
**AI 강사 실전 2단계**
```plain text
Step 1: 딥리서치 지시
"최근 2년간 시니어 대상 디지털 리터러시 교육의
 성공 사례와 실패 사례를 심층 분석하고 싶어.
 목적은 교육기관 20 AI 강의를 위한 교수법 Gem을 만들기 위해서야."

Step 2: Gem 생성 요청
"방금 리서치한 내용을 바탕으로,
 시니어 AI 강의에서 가장 효과적인 교수법을
 R.O.P.E.+K 형식의 Gem 시스템 프롬프트로 짜줘."

강사 교훈:
"내가 공부하지 않아도 AI가 먼저 공부한 내용으로
 더 전문적인 Gem을 만들 수 있습니다."
```

### 기법 4. 역설계 ★추천 (Reverse Engineering) — 황금알에서 거꾸로
**핵심 원리**
```plain text
완벽한 결과물(황금알)을 AI에게 던져주고,
"이거랑 똑같이 쓰는 기계를 만들어줘"라고 명령하는
가장 쉽고 강력한 방법
```
**언제 쓰는가**
```plain text
✅ 지금까지 가장 잘 됐다는 칭찬을 받은 강의 교안이 있을 때
✅ 나만의 강의 말투·스타일을 복제하고 싶을 때
✅ 프롬프트 짜는 것조차 귀찮을 때
```
**마법의 주문 — 강사 버전**
```plain text
"이건 내가 진행한 최고의 AI 강의 교안이야.
[교안 붙여넣기]

이 교안을 분석해서
1) 강의 톤앤매너 (수강생을 대하는 방식),
2) 설명 구조 (개념→비유→실습 순서),
3) 문장 호흡과 길이
를 추출해줘.

그리고, 앞으로 내가 어떤 주제를 던지든 무조건
이 교안이랑 똑같은 스타일로 새 강의 내용을 써주는
시스템 프롬프트를 네가 직접 짜줘."
```
**역설계 4단계 프로세스**
```plain text
Step 1. Golden Sample 준비
  → 지금까지 수강생 반응이 가장 좋았던 강의 내용 1개
  → 또는 직접 쓴 강의 소개문 중 가장 잘 됐다고 느낀 것

Step 2. AI에게 분석 요청 (위의 마법의 주문 입력)

Step 3. AI가 생성한 System Prompt 확인
  → Gem 지침란에 붙여넣기

Step 4. 다른 상황에 테스트
  → "다음 주 프롬프트 강의 교안을 이 스타일로 써줘"
  → 톤앤매너 일치 여부 점검 → 미세 조정

핵심:
"이렇게 해"가 아니라 "이걸 보고 배워"라고 말하는 것
→ 감성적 톤·독특한 스타일 복제에 압도적으로 효과적
```
**확장 활용**
```plain text
수강생 안내 문자 스타일 복제:
→ 가장 반응 좋았던 안내 문자 1개 → 역설계 → Gem 생성
→ 이후 모든 안내 문자를 이 스타일로 자동 생성

→ 가장 잘 쓴 후기 답글 1개 → 역설계
→ "어떤 후기가 들어와도 이 말투로 답글 써줘" Gem 완성
```

### 3-1. Agentic Loop — AI가 스스로 반복하며 일하는 구조
**단순 챗봇 vs AI 에이전트**
```plain text
단순 챗봇:
사용자 입력 → AI 답변 → 끝 (매번 사람이 다음 질문을 해야 함)

AI 에이전트 (Agentic Loop):
목표 설정 → 계획 → 도구 실행 → 결과 관찰 → 재계획 → 반복 → 목표 달성
(사람 개입 없이 여러 단계를 스스로 수행)
```
**Agentic Loop 4단계 구조**
```plain text
[1단계] Perception (인식)
  현재 상황·목표·사용 가능한 도구를 파악
  예: "강의 자료를 분석해야 한다. 파일 읽기 도구가 있다."

[2단계] Reasoning (추론)
  목표 달성을 위한 계획 수립
  예: "파일 읽기 → 핵심 내용 추출 → 요약 → 퀴즈 생성 순서로 진행"

[3단계] Action (행동)
  도구를 실제로 호출·실행
  예: 파일 읽기 → 내용 추출 → 요약 생성

[4단계] Observation (관찰)
  행동의 결과를 확인하고 다음 단계 결정
  예: "요약이 너무 길다. 다시 줄여야 한다" → 2단계로 돌아감

이 4단계가 목표 달성까지 반복 = Agentic Loop
```
**강의 자료 리뉴얼 에이전트 예시**
```plain text
목표: "기존 자료를 시니어 친화적으로 업그레이드"

Loop 1: 자료 읽기 → 어려운 용어 파악 → 개선안 작성
Loop 2: 개선안 검토 → 부족한 부분 발견 → 추가 수정
Loop 3: 최종 결과 검토 → 완료 판단 → 출력

→ 사람이 매 단계 지시하지 않아도 자동으로 진행
```

### 3-2. Tool Use / Function Calling
**Tool Use란**
```plain text
AI가 자신의 학습 데이터 안에서만 답하는 것이 아니라,
외부 도구(API·데이터베이스·검색엔진 등)를 직접 호출해서
실시간 정보를 가져오거나 실제 행동을 수행하는 기술

Function Calling = Tool Use의 기술적 구현 방식
(OpenAI 2023년 도입, 현재 업계 표준)
```
**AI가 호출할 수 있는 도구 종류**
```plain text
정보 검색: 웹 검색, 날씨 API, 주가 조회
파일 처리: 문서 읽기·쓰기, 이미지 분석
외부 서비스: 캘린더 추가, 이메일 전송, 슬랙 메시지
계산 도구: 수식 계산, 데이터 분석, 차트 생성
```
**루미와 Tool Use의 연결**
```plain text
"내일 오후 3시 치과 예약 추가해줘"

AI 내부:
1. 캘린더 추가 도구 선택
2. 파라미터 구성: {date: "2026-07-02", time: "15:00", title: "치과 예약"}
3. calendar.add_event 호출
4. "등록 완료" 수신
5. 사용자에게 답변

→ 루미의 일정 관리 기능이 바로 Tool Use의 실제 구현

강사 멘트:
"루미가 '내일 오후 3시 치과 예약 추가해줘'라고 하면
 실제로 캘린더에 들어가는 게 바로 Tool Use예요.
 AI가 말로만 답하는 게 아니라 실제로 '한다'는 거죠."
```

### 3-3. Memory 3종 — AI가 기억하는 방법
**① 단기 기억 (Short-term / Working Memory)**
```plain text

특징:
  현재 대화 내용이 저장됨
  처리 속도 빠름

한계:
  컨텍스트 윈도우 한도 초과 시 오래된 내용부터 삭제

실용 예:
  루미와 대화할 때 "아까 말한 일정이 뭐였어?"

```
**② 장기 기억 (Long-term Memory)**
```plain text
= 세션을 넘어 영구적으로 저장되는 메모리

구현 방식:
  벡터 데이터베이스: 의미 기반 검색 가능한 외부 저장소
  관계형 데이터베이스: 구조화된 사실 정보 저장

실제 예시:
  Claude Projects: 프로젝트 내 문서·지시사항이 장기 기억으로 유지
  ChatGPT Memory 기능: 사용자 선호·이름·업무 맥락 저장
  교육기관 20 "나만의 교육기관 20": 내 이름·선호도 저장

강사 비유:
"단기 기억은 오늘 강의에서 나눈 대화,
 장기 기억은 수강생 관리 노트처럼 계속 쌓이는 기록이에요."
```
**③ 외부 기억 (External / Episodic Memory)**
```plain text

특징:
  에피소드 메모리: "언제, 무슨 일이 있었는지" 기록
  세션 간 연속성 유지 가능

현실 구현:
  Google NotebookLM: 내가 올린 문서를 AI의 외부 기억으로 활용

  기업용 RAG 시스템: 회사 문서 전체를 AI 외부 기억으로

강사 포인트:
```

### 3-4. Multi-Agent Framework
**단일 에이전트 vs 멀티 에이전트**
```plain text
단일 에이전트:
  하나의 AI가 모든 작업을 순차적으로 처리
  장점: 구조 단순, 맥락 유지 쉬움
  단점: 복잡한 작업에서 각 영역의 전문성 부족

멀티 에이전트:
  여러 전문화된 AI가 분업하여 동시에 또는 순차적으로 처리
  장점: 각 영역 전문성, 병렬 처리로 속도 향상
  단점: 에이전트 간 통신 오버헤드, 설계 복잡성
```
**단일 에이전트를 멀티 에이전트로 바꾸기**

\<역할\>
지금부터 너는 세계최고의 멀티 에이전트 시스템 프롬프트 엔지니어야.
\<과업\>
아래 시스템 프롬프트 초안을 보고 이걸 멀티 에이전트 방식으로 작동할 수 있는 시스템 프롬프트로 바꿔줘
작업순서는 다음과 같아.
1. 먼저 어떤 에이전트를 만들지에 대한 기획을 초안으로 작성할거야. 단, 작업을 할 때는 아래 내가 생각한 멀티에이전트 시스템 역할 분배를 참고해서 만들어줬으면 좋겠어. 단, 이 외에도 더 필요한 에이전트가 있거나 반대로 필요 없다고 생각되는 에이전트가 있으면 얘기해줘. 피드백을 주고 나의 컨펌이 완료되면 다음 단계로 넘어갈거야.
- 시간대별로 인사말을 작성해주는 사람
- 질문이 올라오면 초보자용 프롬프트를 작성해주는 사람
- 프롬프트 고도화 제안에 대한 피드백을 주는 사람 + 부연설명을 해주는 사람
- 최종 버전의 메세지를 보낼 수 있게 작성본을 완성해주는 사람.
- 마무리 인사 및 기타 cs 대응
1. 1번 과정이 끝나고 나면 해당 에이전트들이 무슨 역할을 하는지를 조금 더 구체화 할거야. 역할, 이름, 정체성, 업무 태도, 주요 스킬, 업무 시 유의사항 등의 내용에 맞게 자세하게 정리해. 이 내용을 내가 컨펌 완료하면 3번으로 넘어갈거야.
2. 이 내용을 바탕으로 시스템 프롬프트 초안을 짜주고, 초안에 대한 나의 수정 피드백을 받아
3. 수정 피드백을 바탕으로 그걸 수정해서 최종본을 짜줘
\<제약조건\>
- 멀티 에이전트 시스템으로 만들 때에는 각 에이전트들 간의 역할 배분이 겹치지 않게 업무 분장을 잘 할 것.
- 멀티 에이전트를 만들 때 각 과업별로 호출 명령어(단축키)를 최소 5개 이상 설계할 것.
- 멀티 에이전트 시스템이 병렬적인 과정으로 이어지되, 병렬 작업 뿐만 아니라 단일 작업도 가능할 수 있게 (호출 시에 별도 작업만 따로 할 수 있게) 할 것.
- 작업 중간 중간에 전체 작업 과정 중 어느 단계를 거치고 있는지 단계를 확인할 수 있게 할 것.

**2026년 주요 멀티에이전트 프레임워크**
```plain text
LangGraph (LangChain):
  그래프 기반 에이전트 설계. 결정론적 흐름 제어에 강함

  AutoGen + Semantic Kernel 통합 (2025년 10월 통합 출시)
  기업용 멀티에이전트 표준

CrewAI:
  역할 기반 에이전트 팀 구성. 비즈니스 업무에 최적화
  BMAD와 유사한 철학

Google Cloud ADK (Agent Development Kit):
  계층적 에이전트 트리 구조. A2A 프로토콜 지원
```

**강사 실전 — 간이 멀티에이전트 워크플로우**
```plain text
Gems 여러 개를 순서대로 활용하면 멀티에이전트 효과:

Gem 1 (분석가): "다음 주 강의 수강생 피드백을 분석해줘"
    ↓
Gem 2 (기획자): "(분석 결과) 이 피드백을 바탕으로 강의 구성을 수정해줘"
    ↓
Gem 3 (작성자): "(수정 방향) 이 방향으로 교안 초안을 써줘"
    ↓
Gem 4 (검토자): "(초안) 이 내용에서 60대가 어려워할 부분을 찾아 수정해줘"
```

### 3-5. Orchestration vs Choreography
**Orchestration (오케스트레이션) — 지휘자 방식**
```plain text
구조: 중앙 오케스트레이터가 모든 에이전트를 지휘

특징:
  흐름 제어가 명확하고 예측 가능
  오케스트레이터가 전체 상태를 추적
  오류 발생 시 재시도 결정

비유: 오케스트라 지휘자 — 각 연주자는 지휘자 신호에 따라 연주
     BMAD 오케스트레이터 = 이 역할

적합한 상황:
  순서가 중요한 작업 (A가 끝나야 B 시작)
  오류 처리가 중요한 고신뢰 업무
  → 강사의 Gems 활용에는 이 방식 추천
```
**Choreography (코레오그래피) — 자율 분산 방식**
```plain text
구조: 중앙 지휘자 없이 각 에이전트가 스스로 판단

특징:
  중앙 병목 없이 병렬 처리 가능
  시스템 전체 흐름이 창발적으로 결정됨

비유: 재즈 즉흥 연주 — 지휘자 없이 연주자들이 서로 맞춰감

적합한 상황:
  대규모 병렬 처리
  각 에이전트가 독립적으로 완결된 작업을 할 때
  → 현재 Gems 수준에서는 개념 이해 수준으로 충분
```

## PART 4. 통합 실습 — 나만의 Agent 팀 설계 (15분)
### 오늘 만들 Gem 선택
```plain text
A. 교육기관 20 강의 Q&A 봇
   → 수강생 질문에 전문 용어 없이 답하는 Gem
   → 추천 기법: 정석 (R.O.P.E.+K)

B. 강의 교안 작성 어시스턴트
   → 내 강의 스타일로 새 교안을 써주는 Gem
   → 추천 기법: 역설계 ★

C. 강의 준비 팀 에이전트 (오케스트레이터 + 분석가 + 기획자)
   → 추천 기법: BMAD 변형

D. 수강생 안내 문자 봇
   → 공지·일정 안내를 내 말투로 써주는 Gem
   → 추천 기법: 역설계 or 메타 프롬프트
```
**실습 순서**
```plain text
Step 1: A~D 중 하나 선택 (2분)
Step 2: 선택한 기법으로 Gem 시스템 프롬프트 작성 (8분)
Step 3: Claude Projects 또는 ChatGPT GPTs에 입력 후 테스트 (5분)
         테스트 질문: "안녕! 너는 어떤 걸 도와줄 수 있어?"
```

## 핵심 요약
**Agent 디자인 5가지 기법**
```plain text
기법 1. 정석      → 내가 업무를 잘 알 때. R.O.P.E.+K 순서대로 채우기
기법 2. BMAD 복제 → 복잡한 프로젝트에 AI 팀 만들기. 오케스트레이터가 지휘
기법 3. 딥리서치  → 모르는 분야는 AI가 먼저 공부하게 하기
기법 4. 역설계 ★  → 잘 된 결과물로 거꾸로 Gem 만들기. 가장 쉽고 강력
기법 5. 메타 프롬프트 → AI에게 프롬프트 설계 맡기기

최강 콤보:
역설계(톤앤매너) + 정석(구조) + CoT(추론) = 고품질 전문가 AI
```
