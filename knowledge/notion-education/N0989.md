# 1. 데이터 정리와 분석 (1\~3회차)
## 데이터 정리시키기
```javascript
아래 데이터를 정리해줘.
[데이터 붙여넣기 또는 파일 첨부]

- 중복된 행을 찾아 표시해줘
- 빈 칸이 있는 행을 따로 알려줘
- 항목의 표기가 통일되어 있는지 확인해줘
  (예: 강남점 / 강남 / 강남지점이 섞여 있는지)
- 원본은 그대로 두고 정리 결과만 새로 만들어줘
```
## 집계와 비교 요청
```javascript
이 데이터를 기준별로 집계해줘.
- 건수와 합계를 함께 보여줘
- 금액이 큰 순으로 정렬해줘
- 전월과 비교해 증감을 표시해줘
- 계산에 포함한 건수를 함께 표시해줘
```
## 이상값 찾기
```javascript
아래 데이터에서 이상해 보이는 것을 찾아줘.
- 다른 값들과 크게 차이 나는 것
- 형식이 다른 것 (날짜 형식, 단위 등)
- 논리적으로 맞지 않는 것 (음수 수량, 미래 날짜 등)
왜 이상한지 이유도 함께 적어줘.
```
## 보고서 작성 — 세 가지 유형
**요약형** — "지금 상황이 어떤가"
```javascript
역할: [직무] 담당자
상황: [이슈 두세 줄]
요청: 위 내용을 [받는 사람]에게 보고할 요약 보고서로 써줘.
      5줄 이내, 핵심만.
```
**분석형** — "왜 이런 결과인가"
```javascript
역할: [직무] 담당자
상황: [반복되는 패턴이나 수치]
요청: 원인 분석과 개선 방향을 담은 보고서를 써줘.
      원인, 영향, 개선 방안 순으로.
      자료에 없는 원인은 추측하지 말고 '확인 필요'로 표시해줘.
```
**설득형** — "어떻게 해야 하나"
```javascript
역할: [직무] 담당자
목적: [제안하고 싶은 것]
근거: [현재 비용과 손실, 기대 효과]
요청: 의사결정자를 설득할 제안서를 써줘.
      문제, 영향, 해결안, 기대효과 구조로.
```
## 결과를 고칠 때
```javascript
방금 만든 것에서
1. 이 항목을 더 구체적인 숫자로 바꿔줘
2. 전체 톤을 더 공식적으로 바꿔줘
3. 결론을 3줄로 줄여줘
```

# 2. GAS 자동화 (4회차)
## 코드 요청 기본형
```javascript
나는 코드를 모르는 비개발자야.
구글 앱스크립트 코드를 만들어줘.

하고 싶은 것: [원하는 자동화]
시트 이름: [시트명]
열 구성: A열 날짜, B열 업체명, C열 금액

코드를 만든 뒤 어디에 붙여넣어야 하는지도 알려줘.
```
## 정기 실행과 알림
```javascript
구글 앱스크립트 코드를 만들어줘.
지정한 시트에서 조건에 해당하는 행을 골라
매주 지정한 요일 오전에 받는 사람에게 요약 메일을 보내줘.

메일에 포함할 것
- 해당 건수
- 건별 목록 (표 형태)
- 생성 시각
- 해당 건이 0건이어도 0건이라고 메일을 보내줘
```

**마지막 줄이 중요합니다.** 0건이어도 메일이 와야 안 오는 것으로 고장을 알 수 있습니다.

## 시트 통합
```javascript
지정한 세 시트의 데이터를
통합이라는 새 시트에 하나로 합치는 스크립트를 만들어줘.
헤더는 한 번만 남기고, 마지막 열에 출처 시트 이름을 표시해줘.
```
## 두 표 대조
```javascript
대상 시트의 A열을 기준으로 참조 시트에서 값을 찾아
채워 넣는 스크립트를 만들어줘.
찾는 값이 없으면 확인 필요로 표시하고 눈에 띄게 해줘.
처리 후 몇 행을 처리했는지 알려줘.
```
## 오류가 났을 때
```javascript
아래 오류가 났어. 원인이 뭐고 어떻게 고쳐야 해?
[오류 메시지 전체 복사]

내가 하려던 것: [무엇을 하려 했는지]
```

# 3. Make 자동화 (5회차)
## 시나리오 설계 요청
```javascript
Make로 자동화를 만들려고 해.
하고 싶은 것: 구글시트에 새 행이 추가되면 메일 발송

어떤 모듈을 어떤 순서로 연결해야 하는지 알려줘.
각 모듈에서 설정해야 할 항목도 함께 알려줘.
```
## 연결이 끊겼을 때
```javascript
Make 시나리오가 처음에는 작동했는데 지금은 실행이 안 돼.
확인해야 할 것을 순서대로 알려줘.
```
**직접 확인할 순서**
- 시나리오가 활성 상태인가
- 실행 기록에 실패한 실행이 있는가
- 실패 사유가 무엇인가
- 연결된 서비스의 인증이 만료되지 않았는가

# 4. 앱 만들기 (6\~7회차)
## 설계서 만들기
```javascript
나는 [부서]에서 [업무]를 담당하고 있어.

- 지금 어떻게 하고 있는지
- 무엇이 불편한지

- 무엇을 입력하고 무엇을 보고 싶은지
- 누가 쓸 것인지

이 내용으로 앱 제작을 위한 설계서를 만들어줘.
화면 구성, 각 화면의 기능, 데이터 항목을 포함해줘.
```

```javascript
[설계서 붙여넣기]
```

## 데이터가 안 남을 때

```javascript
아니면 브라우저 메모리에만 저장되는 부분이 남아있는지 확인해줘.
```

```javascript
- 한글이 깨지지 않게 UTF-8로 읽어줘
- 금액은 콤마를 제거하고 숫자로 변환해줘
- 저장 후 몇 건 저장되었는지 메시지를 보여줘
- 실패하면 몇 번째 줄에서 실패했는지 알려줘
```

# 5. 배포와 코드 수정 (9회차)
## Cursor에 수정 요청 — 파일 지정
골뱅이 기호로 파일을 지정하고 요청합니다.
```javascript
@파일명 에서 [무엇]을 [어떻게] 고쳐줘.
```

**파일을 지정하면** AI가 프로젝트 전체를 읽지 않아 훨씬 빠르고, 사용량도 적게 듭니다.

## 버그 수정
```javascript

원래는 [어떻게] 되어야 합니다.
원인을 찾아서 고쳐줘.
```
**증상을 말하고 해결책은 지시하지 마세요**







예시

왜




나쁨

"상태 관리를 다시 해줘"

해결책을 지시함




좋음

"답을 골라도 반응이 없어"

증상을 설명함

```javascript

이 에이전트는 [역할]을 담당한다.

정보 범위
작업 폴더 안의 [파일 또는 폴더명] 자료를 읽고 참고한다.

출력 형식
결과는 [형식]으로 작성한다.
표로 만들 경우 열은 [열 구성]으로 한다.

페르소나 및 판단 기준
- [페르소나]
- 자료에 없는 내용은 추측하지 말고 '확인 필요'로 표시한다
- 최종 결정을 확정하지 않고 검토 의견으로 제시한다
- 근거가 되는 파일명을 함께 밝힌다

호출 문구 세 개와 같거나 비슷한 요청이 오면
반드시 이 에이전트가 쓰이도록 호출 조건을 작성해줘.
에이전트 이름은 영어 소문자와 하이픈으로 만들어줘.
도구와 모델은 현재 실습 환경에 맞게 적절히 설정해줘.
disallowedTools에 Agent를 추가해줘.
```

```javascript
- 맨 위에 생성 시각을 표시해줘
- 결과는 대시보드 파일로 저장해줘

원본 자료는 수정하지 말고 새 결과물 파일만 만들어줘.
자료에 없는 내용은 임의로 만들지 말고 '확인 필요'로 표시해줘.
```

# 8. 자료 정리와 문서화 (12회차)
## 인수인계 문서 생성
```javascript
이 폴더의 자료를 읽고 인수인계 문서를 만들어줘.
아래 여덟 항목으로 구성해줘.

1. 기본 정보 — 도구 이름, 만든 사람, 접속 주소, 현재 상태
2. 무엇을 하는 도구인가 — 해결하려는 문제, 하는 일, 쓰는 사람
3. 쓰는 법 — 가장 자주 하는 작업 3가지의 클릭 순서
4. 접근 권한 — 로그인 방식, 계정 소유자, 연결된 서비스
5. 데이터 — 어디에 저장되나, 어떻게 들어가나, 주의할 점
6. 자동으로 도는 것 — 무엇이 자동인가, 멈췄는지 아는 법
7. 알아둘 것 — 자주 나는 오류, 하면 안 되는 것, 아직 안 된 것
8. 이어받는 사람에게 — 자유 메모, 문의처

조건
- 자료에 없는 내용은 '확인 필요'로 표시할 것
- 비밀번호와 접근 키는 절대 적지 말 것
- 전문 용어에는 괄호로 쉬운 설명 붙이기
```
## 오류 모음 만들기
```javascript

- 원인이 무엇이었나
- 어떻게 해결했나
- 해결됐는지 여부

자료에 적힌 것만 쓰고, 원인을 모르면 '원인 미상'으로 표시해줘.
```
## 발표 자료 초안
```javascript
첨부한 워크시트를 바탕으로 발표 내용을 정리해줘.
아래 여덟 항목으로 만들어줘.

1. 어떤 프로젝트를 했나
2. 어떤 비효율이 있었나
3. 어떻게 개선했나 (개선 전후, 없어진 일)
4. 기술적으로 무엇을 활용했나
5. 실제 시연에서 보여줄 순서
6. 어려웠던 점
7. MVP 테스트 결과
8. 더 수정하고 고도화할 부분

조건
- 각 항목은 슬라이드 한 장 분량으로
- 전문 용어 없이
- 워크시트에 없는 내용은 지어내지 말고 '확인 필요'로 표시
- 숫자가 있으면 반드시 넣어줘
```

# 자주 쓰는 조건문 모음

## 정확성
```javascript
자료에 없는 내용은 추측하지 말고 '확인 필요'로 표시해줘.
계산에 포함한 건수를 함께 표시해서 검산할 수 있게 해줘.
근거가 되는 파일명이나 항목을 함께 밝혀줘.
확실하지 않은 것은 확실하지 않다고 말해줘.
```
## 안전
```javascript
원본 자료는 수정하지 말고 새 파일로 만들어줘.
최종 결정은 확정하지 말고 검토 의견으로 제시해줘.
비밀번호나 개인정보는 결과물에 넣지 말아줘.
```

```javascript
업무를 모르는 사람이 읽어도 이해되게 써줘.

표로 만들고 정해진 기준 순으로 정렬해줘.
맨 위에 생성 시각을 표시해줘.
```
