# 다섯 가지 요소
```plain text
R — Role          역할     어떤 담당자처럼 답할지
C — Context       맥락     상황, 받는 사람, 목적
T — Task          할 일    무엇을 만들지, 몇 단계로
C — Constraints   조건     분량, 형식, 금지사항
K — Knowledge     지식     참고할 자료, 예시
```
각 칸이 원리 하나씩과 짝을 이룹니다. 빠뜨리면 그 원리가 그대로 문제로 나타납니다.

## R · 역할은 직함이 아니라 능력으로
`원리 3`을 그대로 씁니다. 업무별 역할 문장은 모듈 01의 표에 정리해 두었으니 복사해 쓰시면 됩니다.
## C · 맥락은 네 가지면 충분합니다
```plain text
받는 사람 : 누구에게 가는 문서인가
상황      : 왜 이 문서를 쓰게 되었나
목적      : 상대가 읽고 무엇을 하길 바라나
분위기    : 공식 문서인가, 내부 공유용인가
```

**네 가지 중 효과가 가장 큰 것은 받는 사람입니다.**
같은 해외 정책 내용이라도 **회원사 배포용**과 **부처 대관용**은 구조가 다릅니다. 회원사용은 "우리 사업에 무슨 영향이 있나"까지 가야 하고, 대관용은 "그래서 무엇을 건의하나"로 끝나야 합니다.

정리 잘 해 줘

1. 원문에서 확인 가능한 사실만 추출해 목록으로 정리해 주세요. 2. 사실과 필자의 해석을 구분해 표시해 주세요. 3. 정리한 목록으로 본문을 작성해 주세요. 4. 마지막 줄에 시사점을 한 줄로 붙여 주세요.


핵심은 **1번을 "사실 추출"로 두는 것**입니다. 바로 본문을 쓰게 하면 AI가 기사를 훑고 아는 것으로 채웁니다. 추출 → 구분 → 작성 순서를 밟게 하면 누락과 지어내기가 동시에 줄어듭니다. 이것을 **CoT(생각의 사슬)** 라고 합니다.

지난 호 자료, 표기 기준, 담아야 할 항목을 함께 붙입니다. **잘 쓴 지난 문서 하나만 넣어도 문체가 우리 기관 문서처럼 바뀝니다.**

# 시연 1 · 영문 기사를 동향 자료 1건으로

**보실 것** — 먼저 "이 기사 요약해줘"를 돌리고, 그다음 아래 지시문을 돌려 둘을 나란히 비교합니다.
**영문 번역과 동향 정리가 한 번에 끝나는** 형태입니다.

```plain text
[R] 당신은 해외 수소 정책 자료를 국내 실무자용 동향 자료로 옮기는
    담당자입니다. 다음을 잘합니다.
    ① 원문의 사실과 필자의 해석을 구분해 옮깁니다.
    ② 제도·기업명은 원어를 병기해 오번역을 막습니다.
    ③ 정책의 진행 단계를 원문 표현 그대로 유지합니다.

[C] 받는 사람 : 국내 회원사 실무자와 내부 직원 (업계 배경 지식 있음)
    상황      : 매월 발간하는 해외 동향 자료의 개별 건입니다
    목적      : 읽는 사람이 자사 사업 관련성을 판단할 수 있게 하는 것
    분위기    : 사무적으로. 홍보성 표현은 쓰지 않습니다

[T] 답을 쓰기 전에, 먼저 원문에서 확인 가능한 사실만 뽑아
    목록으로 정리해 주세요. 그 다음 순서대로 진행해 주세요.
    1. 정리한 사실 중 필자의 해석·전망에 해당하는 것을 따로 표시
    2. 제목 한 줄 작성 — 뒤에 (발행일, 매체명) 표기
    3. 본문 작성
    4. 마지막 줄에 시사점을 "이번 사례는 ~을 보여줌" 형태로 한 줄

[C] - 본문은 7~9줄, 한 줄에 사실 하나만 담습니다.
    - 개조식(~함, ~임, ~됨)으로 씁니다. 예외를 두지 않습니다.
    - 국내 독자에게 생소할 기업·약어는 별표(*) 각주로 한 줄 설명합니다.
    - 외화 금액은 원문 표기를 쓰고, 원화 환산을 괄호로 병기합니다.
    - 원문에 없는 수치·연도·기관명·정책명은 만들지 마세요.
    - 원문에서 확인되지 않는 항목은 [확인 필요]로 비워 두세요.
    - 정책 진행 단계를 원문 표현 그대로 옮기세요.
      의견수렴 중인 것을 확정된 것으로, 계획을 시행으로 바꾸지 마세요.
    - 필자의 전망은 "~로 전망", "~로 보임"으로 표기해 사실과 구분하세요.

[K] 아래는 원문입니다. 이 범위 안에서만 작성해 주세요.
    (영문 기사 붙여넣기)
```

**시연에서 볼 지점 넷**
1. 첫 결과에 비해 **형식이 잡혔는가** — 개조식, 날짜·매체 표기, 각주
2. 원문에 없는 수치를 **지어냈는가, 비워 두었는가**
3. **단계 표현이 그대로 유지되는가** — 가장 중요한 지점
4. 마지막 줄이 **시사점 형태로 마무리되는가**


**조건 중 두 줄이 이 업무의 핵심입니다.**
`외화 금액은 원문 표기를 쓰고, 원화 환산을 괄호로 병기합니다`
`생소할 기업·약어는 별표 각주로 한 줄 설명합니다`
해외 자료를 그대로 옮기면 읽는 사람이 규모를 가늠하지 못하고, 처음 보는 기업명 앞에서 멈춥니다. 이 두 줄이 **읽는 사람의 부담을 덜어주는 장치**이고, 매번 손으로 챙기기 번거로운 부분이라 조건으로 박아두면 효과가 큽니다.

# 시연 2 · 회의록을 정리된 문서로
위원회, 간담회, 포럼 등 회의가 잦은 기관에서 가장 시간이 많이 줄어드는 작업입니다. 핵심은 **논의된 것과 결정된 것을 AI가 섞지 않게 하는 것**입니다.
```plain text
[R] 당신은 회의록을 정리하는 실무자입니다.
    논의된 것과 결정된 것을 반드시 구분하고, 추측을 덧붙이지 않습니다.

[C] 받는 사람 : 회의에 참석하지 않은 내부 직원과 관련 부서
    상황      : 녹취를 풀어쓴 거친 메모입니다. 순서가 섞여 있습니다
    목적      : 무엇이 정해졌고 누가 무엇을 해야 하는지 알게 하는 것

[T] 답을 쓰기 전에, 먼저 메모의 모든 발언을 아래 세 가지로
    분류해 주세요. 결정 / 검토 필요 / 단순 공유
    분류가 끝나면 순서대로 작성해 주세요.
    1. 회의 개요 (일시·참석·안건) — 메모에 없으면 [확인 필요]
    2. 결정 사항 — 항목별로, 각각 담당과 기한을 붙여서
    3. 계속 검토할 사항과 쟁점
    4. 다음 회의 전까지 해야 할 일

[C] - 각 항목은 한 줄씩, 개조식으로 씁니다.
    - 메모에 없는 내용은 절대 추가하지 마세요.
    - 담당자가 명시되지 않은 결정은 [담당 미지정]으로 표시해 주세요.
    - 논의만 된 사항을 결정된 것처럼 쓰지 마세요.
    - 위원 개인 발언을 기관의 공식 입장처럼 옮기지 마세요.

[K] (회의 메모 붙여넣기 — 참석자 실명은 직책으로 바꿔서)
```

**마지막 두 줄이 이 지시문의 핵심입니다.**
AI는 문장을 깔끔하게 만들려는 성질이 있어서 "검토하기로 했다"를 "확정했다"로 바꿉니다. `원리 5`가 회의록에서 나타나는 형태이고, 여기서 나온 오류는 되돌리기가 어렵습니다.
특히 **외부 위원 의견이 기관 입장으로 둔갑하는 것**은 운영위원회처럼 회원사 임원이 참여하는 회의체에서 반드시 막아야 합니다.
