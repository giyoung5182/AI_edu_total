# 1부 — 자동화 설계의 기본 원리
---
## 자동화란 무엇인가 — 정확한 정의부터
많은 사람이 자동화를 "AI가 다 해주는 것"으로 생각합니다. 그렇지 않습니다.
**자동화의 정확한 정의:**
> 사람이 매번 직접 하던 **규칙 기반의 반복 동작**을<br>컴퓨터가 대신 실행하도록 만드는 것
핵심은 두 단어입니다. **규칙 기반** + **반복**.
규칙이 없거나, 반복이 없으면 자동화의 효과가 없습니다.
---
## 자동화가 가능한 동작 vs 불가능한 동작
모든 업무 동작은 두 가지로 나뉩니다.
### 판단(Judgment)이 필요한 동작
```plain text
정의: 상황에 따라 다르게 처리해야 하는 것
     경험, 맥락, 감각이 필요한 것

예시:
- 발주 수량 결정 (재고 상황, 행사 여부, 날씨 고려)
- 보고서 문장 작성 (상사의 취향, 상황의 긴급도 고려)
- 이상값의 원인 파악 (현장 상황 고려)
- 거래처와 협상 (관계, 맥락 고려)

→ 사람이 해야 합니다. 자동화 불가.
```
### 규칙(Rule)에 따른 동작
```plain text
정의: 항상 같은 방식으로 처리되는 것
     "이 상황이면 항상 이렇게 한다"고 말할 수 있는 것

예시:
- 입력한 데이터를 특정 형식으로 옮기기
- A 시트 데이터를 B 시트에 저장하기
- 금액 합산해서 집계표 만들기
- 특정 조건이 되면 이메일 보내기
- 매일 같은 시간에 같은 작업 실행하기

→ 자동화 가능합니다.
```
---
## 자동화의 3가지 구성 요소
모든 자동화는 이 세 가지로 이루어져 있습니다.
### 구성 요소 1: 트리거 (언제 실행되는가)
```plain text
버튼 클릭:      내가 원할 때 버튼을 누르면 실행
시간 기반:      매일 오전 9시, 매주 월요일 등 정해진 시간에 자동 실행
조건 기반:      특정 조건이 충족되면 자동 실행
                예: 잔액이 50만원 이하가 되면
                예: 파일에 새 데이터가 추가되면
```
### 구성 요소 2: 처리 (무엇을 하는가)
```plain text
읽기:    특정 셀·시트에서 데이터를 가져옴
변환:    형식을 바꾸거나, 계산하거나, 분류함
쓰기:    결과를 특정 셀·시트에 저장함
발송:    이메일, 메시지 등 외부로 전달
```
### 구성 요소 3: 데이터 흐름 (어디서 어디로)
```plain text
[입력 폼]  →  [처리]  →  [저장/보고서]
사람이 씀       GAS        자동 생성
```
---
## 자동화 설계의 핵심 사고 틀 — WHAT·WHERE·WHEN
자동화를 설계할 때 세 가지 질문에 답하면 됩니다.
```plain text
WHAT:  무엇을 자동화하는가?
       (어떤 반복·규칙 동작인가)

WHERE: 어디서 어디로 흐르는가?
       (어떤 파일, 어떤 시트, 어떤 셀)

WHEN:  언제 실행되는가?
       (버튼 클릭, 시간, 조건)
```
이 세 가지가 명확하면 Claude에게 정확한 코드를 받을 수 있습니다.
---
## 왜 설계를 먼저 해야 하는가
```plain text
설계 없이 바로 요청하면:
"GAS로 업무보고 자동화해줘"
→ Claude가 추측으로 코드를 짬
→ 실제 파일과 맞지 않음
→ 오류 발생 → 수정 반복

설계 후 요청하면:
"발주입력 시트 A열(매장명), B열(품목), C열(수량)을 읽어서
 발주이력 시트에 한 줄씩 저장하고
 [제출] 버튼 클릭 시 실행되게 해줘"
→ 첫 번째 코드가 바로 맞음
→ 한 번에 완성
```
설계에 10분을 쓰면 수정에 드는 1시간을 절약합니다.

# 2부 — 워크시트 작성법
---
## 작성 순서 안내
워크시트를 처음 보면 어디서 시작해야 할지 막막합니다. 아래 순서대로 작성하면 됩니다.
```plain text
① 현재 업무 흐름 적기 (가장 중요, 가장 먼저)
② 각 동작에 판단/규칙 표시
③ 자동화 대상 선택
④ 파일 구조 설계
⑤ 트리거 결정
```
---
## 각 항목 작성법
---
### 항목 1. 현재 업무 흐름 적기
**작성 방법:**<br>지금 이 업무를 어떤 순서로 하고 있는지 **동사 중심으로** 씁니다. 최대한 작게 쪼갭니다.
```plain text
좋은 예 (동사 중심, 세분화):
① 광고주센터에 접속한다
② 날짜를 어제로 설정한다
③ 매장별로 지표를 확인한다
④ 수치를 드래그해서 복사한다
⑤ 엑셀 파일을 열고 해당 매장 탭으로 이동한다
⑥ 날짜에 맞는 셀을 찾는다
⑦ 붙여넣는다
⑧ 다음 매장으로 이동해서 ④~⑦ 반복

나쁜 예 (너무 뭉쳐 있음):
① 광고 성과를 엑셀에 정리한다  ← 이렇게 쓰면 자동화 포인트가 안 보임
```
**포인트:** 귀찮거나 실수가 생기는 부분일수록 더 세분화해서 씁니다.
---
### 항목 2. 판단 vs 규칙 표시
각 동작 옆에 아래 기호를 답니다.
```plain text
[판단] 내가 생각해서 결정해야 함 → 자동화 불가
[규칙] 항상 같은 방식으로 처리 → 자동화 가능
[반복] 같은 동작을 여러 번 반복 → 자동화 가능 (특히 효과적)
```
**판단인지 규칙인지 헷갈릴 때 이 질문을 해보세요:**
> "이 동작을 새로 입사한 직원에게 설명할 수 있는가?<br>설명서를 만들 수 있는가?"
설명서로 만들 수 있다 → 규칙 → 자동화 가능<br>설명서로 만들 수 없다 → 판단 → 자동화 불가
---
### 항목 3. 자동화 대상 선택
\[규칙\]과 \[반복\]이 붙은 것 중 아래 기준으로 우선순위를 정합니다.
```plain text
우선순위 높음:
✅ 매일 반복되는 것
✅ 실수가 자주 나는 것
✅ 여러 파일·시트를 오가야 하는 것
✅ 시간이 오래 걸리는 것

우선순위 낮음:
⬜ 가끔 하는 것
⬜ 금방 끝나는 것
⬜ 이미 잘 되고 있는 것
```
---
### 항목 4. 파일 구조 설계
자동화에 필요한 시트를 설계합니다. 모든 GAS 자동화는 아래 구조를 기본으로 합니다.
```plain text
[입력 시트]     사람이 데이터를 입력하는 폼
                여기에만 사람 손이 닿음

[이력 시트]     GAS가 자동으로 누적 저장하는 DB
                삭제하지 않고 계속 쌓임

[보고서 시트]   GAS가 이력 시트를 읽어서 만드는 결과물
                버튼 클릭 또는 자동으로 갱신
```
세 가지가 다 필요하지 않을 수 있습니다. 업무에 따라 두 가지만 쓰거나, 한 가지만 쓰기도 합니다.
**각 시트에 어떤 열(컬럼)이 필요한지도 적어둡니다.**
```plain text
입력 시트 열 구성:
A열: 날짜 / B열: 매장명 / C열: 품목 / D열: 수량 / E열: 유형

이력 시트 열 구성:
A열: 제출일시 / B열: 날짜 / C열: 매장명 / D열: 품목 / E열: 수량 / F열: 유형
```
---
### 항목 5. 트리거 결정
```plain text
버튼 클릭이 맞는 경우:
  → 내가 원할 때만 실행하고 싶음
  → 실행 전 확인이 필요함
  예: 지출결의서 제출, 업무보고 생성

시간 기반이 맞는 경우:
  → 매일 같은 시간에 자동으로 실행해야 함
  → 내가 잊어버릴 수 있음
  예: 비즈머니 잔액 확인, 일일 리포트 발송

조건 기반이 맞는 경우:
  → 특정 상황이 됐을 때만 실행
  → 매일 확인하기 번거로움
  예: 재고가 10개 이하일 때 알림
```
