# Cursor 개인별 심화 실습 (참고용)
## 오후 실습 목표
오전에 Cursor로 텍스트·색상 같은 간단한 수정을 해봤다면, 오후에는 각자 7회차 전 과제에 직접 작성한 "어려웠던 점"과 "추가하고 싶은 기능"을 실제로 Cursor에서 해결·구현합니다.
```plain text
오후 목표:
  본인이 제출한 문제·요청사항을 다시 확인
  → Cursor Agent에게 요청 → [KEEP] → 브라우저에서 확인 → 반복
```
---
## Cursor 실습 핵심 원칙 5가지
**원칙 1: 한 번에 하나씩 요청한다**
```plain text
❌ "정렬 기능 추가하고, 색상 조건도 넣고, 팝업도 만들고,
    자동 계산도 해줘"
  → AI가 우선순위를 잘못 잡거나 일부를 놓칠 수 있음

✅ 1단계: "정렬 기능 추가해줘" → KEEP → 브라우저 확인
   2단계: "조건부 색상 넣어줘" → KEEP → 확인

💡 Cursor는 Lovable과 달리 요청 횟수에 따른 크레딧 부담이
   훨씬 적으므로(무료 월 50회), 나눠서 요청하는 것이
   오히려 정확하고 빠릅니다.
```
**원칙 2: **KEEP** 전에 어떤 파일이 바뀌는지 훑어본다**
```plain text
Cursor Agent는 수정할 파일과 내용을 먼저 보여줍니다.
→ 파일 이름이 내가 의도한 화면과 관련 있어 보이는지만
  가볍게 확인하고 [KEEP]
→ 전혀 무관해 보이는 파일이 대량으로 바뀐다면
  KEEP 전에 "왜 이 파일을 수정하는 거야?"라고 물어보세요.
```
**원칙 3: 결과를 반드시 확인하고 다음으로 넘어간다**
```plain text
수정 요청 → KEEP → 브라우저(localhost:8080)에서 확인
→ 원하는 대로 됐으면 다음 기능 / 안 됐으면 추가 요청
```
**원칙 4: 오류 메시지는 그대로 AI에게 보여준다**
```plain text
브라우저 F12 → Console 탭 → 빨간 오류 텍스트 복사
→ Cursor AI 패널에 붙여넣기
→ "이 오류가 났어. 원인이 뭐고 어떻게 고쳐?"
```
**원칙 5: 같은 문제로 3번 이상 막히면 전략을 바꾼다**
```plain text
같은 요청을 3번 이상 반복하고 있다면 잠깐 멈추고:

방법 A — Claude.ai에게 프롬프트를 다듬어달라고 요청 (크레딧 소비 없음):
  "Cursor에서 [겪고 있는 문제]를 계속 시도했는데 안 돼.
   Cursor가 한 번에 알아들을 수 있는 프롬프트를 만들어줘."
  → 받은 프롬프트를 Cursor에 입력

방법 B — 강사 호출

→ 무한 반복은 크레딧과 시간만 소모합니다.
```

## 1-2. 요청하는 방법 — 기본 5원칙
### 원칙 1. 한 번에 하나씩
```plain text
❌ "제목 바꾸고, 색깔도 바꾸고, 아이콘도 넣어줘"
   → AI가 일부를 놓치거나 엉뚱한 곳을 건드립니다

✅ "제목을 바꿔줘"  →  확인  →  "이제 색깔을 바꿔줘"  →  확인
```
> 💡 Cursor는 Lovable과 달리 요청 횟수 부담이 적습니다(무료 월 50회). 나눠서 요청하는 편이 오히려 정확하고 빠릅니다.
### 원칙 2. 어디를 고칠지 구체적으로 말한다
```plain text
❌ "버튼 색 바꿔줘"
   → 화면에 버튼이 여러 개면 AI가 어느 것인지 모릅니다

✅ "화면 오른쪽 위에 있는 '저장' 버튼의 배경색을 바꿔줘"
```
### 원칙 3. \[Keep\]을 눌러 확정한다
```plain text
AI가 고치면 위쪽에 버튼 3개가 뜹니다.

  [Undo]  되돌리기
  [Keep]  ← 이것을 눌러 확정
  [Review] 자세히 보기

→ Keep을 누르면 초록·빨강 표시가 사라지고
  버튼에서 Undo와 Keep이 없어집니다. 그게 완료 신호입니다.
```
> ⚠️ **Keep을 안 누르면** 다음 요청과 뒤섞여서 뭐가 뭔지 알 수 없게 되고, 나중에 실수로 \[Undo\]를 누르면 작업이 통째로 날아갑니다.
### 원칙 4. 브라우저에서 확인하고 다음으로
```plain text
수정 → Keep → 브라우저(localhost:8080)에서 눈으로 확인 → 다음 요청
```
> ⚠️ **화면이 안 바뀌면 F5를 누르세요.** 자동 갱신이 안 되는 경우가 있습니다. 실패가 아닙니다.
### 원칙 5. 오류가 나면 그대로 복사해서 보여준다
```plain text
브라우저 화면이 빨간 오류로 바뀌었을 때:

① F12 키 → Console 탭 클릭
② 빨간 글씨 전체를 복사
③ Cursor AI 패널에 붙여넣고:
   "이 오류가 났어. 원인이 뭐고 어떻게 고쳐?"
```

## 1-3. 뭘 고칠지 어떻게 정하나
막상 "고쳐보세요"라고 하면 막막합니다. 아래 순서로 앱을 훑으면 고칠 것이 저절로 나옵니다.
```plain text
① 내 앱을 브라우저에 띄워놓고 위에서 아래로 훑어봅니다

② 이 세 가지를 찾습니다
   □ 영어로 남아있는 글자가 있나?        → 실습 ①
   □ 제목이나 이름이 어색한가?           → 실습 ②
   □ 색이 눈에 안 들어오거나 촌스러운가?  → 실습 ③

③ 찾은 것 중 2~3개만 메모하고 시작합니다
```
> 💡 **완벽하게 만들려 하지 마세요.** 오늘 목표는 "고치는 방법을 익히는 것"이지 "앱을 완성하는 것"이 아닙니다. 배포까지 끝내면 그 뒤로는 언제든 혼자 고칠 수 있습니다.

## 1-4. 실습 — 아래에서 2\~3개만 골라 해보세요
각 항목의 프롬프트를 **그대로 복사해서** Cursor AI 패널(Ctrl+L)에 붙여넣고, 대괄호 안만 본인 앱에 맞게 바꾸면 됩니다.
---
### 실습 ① 텍스트 바꾸기 (가장 쉬움)
```plain text
"'[기존 문구]' 라고 되어 있는 부분을
 '[새 문구]' 로 바꿔줘."
```
**예시**
```plain text
"'Submit' 이라고 되어 있는 버튼을 '저장하기'로 바꿔줘."

"'No data' 라고 뜨는 안내 문구를
 '아직 등록된 내역이 없습니다'로 바꿔줘."
```
> 💡 영어로 남아있는 문구를 한글로 바꾸면 실제 업무에서 훨씬 쓰기 좋아집니다. Lovable이 만들 때 영어가 섞여 들어간 곳이 대부분 있습니다.
---
### 실습 ② 제목 바꾸기
```plain text
"화면 맨 위 제목을 '[새 제목]'으로 바꿔줘."
```
**예시**
```plain text
"화면 맨 위 제목을 '구매정육부 휴무 관리'로 바꿔줘."

"브라우저 탭에 표시되는 이름도 같이 바꿔줘."
```
> 💡 **브라우저 탭 이름**은 따로 지정되어 있어서 화면 제목만 바꾸면 안 바뀝니다. 위 두 번째 문장을 함께 요청하세요.
---
### 실습 ③ 색상 바꾸기
```plain text
"[어느 부분]의 색을 [색깔]로 바꿔줘."
```
**예시**
```plain text
"저장 버튼의 배경색을 짙은 초록색(#1B4332)으로 바꿔줘."

"화면 맨 위 헤더 배경을 짙은 남색(#1a365d)으로 바꾸고,
 글씨는 흰색으로 해줘."
```
> 💡 **색상 코드를 몰라도 됩니다.** "차분한 남색", "밝은 하늘색", "회사 로고 같은 빨간색"처럼 말로 해도 알아듣습니다. 다만 정확한 색을 원하면 `#` 뒤 6자리 코드를 쓰는 것이 확실합니다.
> 💡 **색상 코드 찾는 법:** 검색창에 "컬러 피커"라고 치면 색을 골라 코드를 얻을 수 있는 사이트가 나옵니다.
---
### 실습 ④ 아이콘 넣기
```plain text
"[어느 버튼] 옆에 [무슨] 아이콘을 넣어줘."
```
**예시**
```plain text
"저장 버튼 왼쪽에 저장(디스켓) 아이콘을 작게 넣어줘."

"목록의 각 항목 오른쪽에 삭제(휴지통) 아이콘을 넣고,
 누르면 그 항목이 지워지게 해줘."
```
> 💡 **아이콘 그림 파일을 준비할 필요가 없습니다.** Lovable이 만든 앱에는 아이콘 모음(lucide-react)이 이미 들어있어서, AI에게 말만 하면 알아서 가져다 씁니다.
---
### 실습 ⑤ 링크 버튼 만들기
```plain text
"[어디]에 '[버튼 이름]' 버튼을 추가하고,
 누르면 [주소]로 새 탭에서 열리게 해줘."
```
**예시**
```plain text
"화면 오른쪽 위에 '사내 게시판' 버튼을 추가하고,
 누르면 [개별 링크 제외] 으로 새 탭에서 열리게 해줘."

"화면 맨 아래에 '문의: 총무팀 내선 1234' 라는
 안내 문구를 작은 회색 글씨로 추가해줘."
```
> 💡 실무에서 의외로 유용합니다. 자주 쓰는 사내 시스템이나 구글시트 주소를 버튼으로 걸어두면 오가는 시간이 줄어듭니다.

## 2-4. STEP 2 — 무엇이 바뀌었는지 확인
```plain text
왼쪽에 이런 목록이 나옵니다:

  Changes
    src/routes/__root.tsx      M
    package-lock.json          U
```
**옆에 붙은 알파벳의 뜻**
```plain text
M  = Modified (수정됨)
     원래 있던 파일을 고쳤다는 뜻

U  = Untracked (추적 안 됨)
     새로 생긴 파일이라 Git이 아직 모른다는 뜻

```
> 💡 **package-lock.json은 왜 올리나요?** "어떤 부품을 어떤 버전으로 설치했는지" 기록한 파일입니다. Vercel이 배포할 때 같은 환경을 그대로 재현하려면 필요합니다.

### ⚠️ 여기서 오류가 나면 — Git 사용자 정보 미설정
```plain text
이런 메시지가 뜹니다:

  Make sure you configure your "user.name" and "user.email" in git.
```
**왜 나나요?**
Git은 커밋을 만들 때 **"누가·언제·무엇을 바꿨는지"를 반드시 함께 기록**합니다. 송장에 보내는 사람 이름이 없으면 접수가 안 되는 것과 같습니다.
**해결 — 터미널에서 두 줄 입력 후 다시 Commit**
```plain text
git config --global user.name "본인이름"
git config --global user.email "본인이메일@example.com"
```
> ⚠️ **터미널이 잠겨 있으면** `npm run dev`가 돌고 있는 터미널은 명령을 받지 않습니다. 상단 메뉴 → Terminal → **New Terminal**로 새로 하나 열어 입력하세요. (서버는 계속 켜둬야 하므로 기존 터미널을 끄지 마세요)
> 💡 1권에서 미리 설정하셨다면 이 오류는 나지 않습니다.

## 3-1. 먼저 이해하기 — 지금 뭐가 문제인가
### localhost는 "이 컴퓨터"라는 뜻입니다
```plain text
지금 우리 앱 주소:  localhost:8080

  localhost  =  이 컴퓨터
  8080       =  8080번 창구

즉 "내 컴퓨터 안 8080번 창구"라는 뜻입니다.
```
**이 주소의 한계 세 가지**
```plain text
① 남에게 알려줘도 안 열립니다
   옆자리 동료에게 localhost:8080을 보내면,
   그 사람 컴퓨터의 8080번 창구를 열려고 해서 아무것도 안 나옵니다.

② 터미널을 끄면 즉시 죽습니다
   npm run dev를 멈추는 순간 앱도 멈춥니다.

③ 컴퓨터를 끄면 당연히 죽습니다
```
즉 지금 앱은 **나만, 내 컴퓨터가 켜져 있을 때만** 볼 수 있습니다.

## 3-2. Vercel이 뭔가요
**내가 만든 웹앱을 인터넷에 공개해주는 서비스**입니다.
```plain text
동작 방식:

  GitHub에 올린 코드를
    ↓ Vercel이 가져가서
  자기네 서버에서 24시간 돌려주고
    ↓
  앱이름.vercel.app 같은 주소를 줍니다

→ 내 컴퓨터를 꺼도 살아 있습니다
```
**왜 하필 Vercel인가**
```plain text
· 무료입니다 (개인 사용 Hobby 플랜)
· GitHub만 연결하면 알아서 빌드해줍니다
· 코드를 Push할 때마다 자동으로 다시 배포됩니다
· 주소(https 보안 인증서 포함)를 자동으로 줍니다
```

## 3-3. ★ "웹호스팅에 올리면 안 되나요?" — 자주 나오는 질문
가비아 같은 웹호스팅을 써보신 분이라면 당연히 드는 의문입니다. 답은 "이 앱은 그 방식으로는 안 됩니다"이고, 이유가 세 가지입니다.
### 이유 1 — 올릴 파일 자체가 없습니다
```plain text
일반 웹호스팅은 완성된 파일을 FTP로 올리는 방식입니다.
예전 홈페이지처럼 index.html, style.css를 올리면 그대로 보여줍니다.

그런데 우리 프로젝트 폴더를 보면
  · index.html 이 없습니다
  · .tsx, .ts 같은 파일뿐입니다

브라우저는 이런 파일을 읽지 못합니다. 사람이 쓰기 편한 언어라서요.
```
**브라우저가 읽을 수 있는 형태로 바꾸는 과정**을 \*\*빌드(build)\*\*라고 합니다. 지금 `npm run dev`가 실시간으로 해주고 있는 일이 바로 그것입니다.
즉 웹호스팅에 올릴 **완성품이 애초에 없습니다.**
### 이유 2 — 이 앱은 "서버가 돌아야" 하는 앱입니다
```plain text
앞에서 터미널에 이런 줄이 떴던 것 기억하시나요?

  [vite] (ssr) connected

SSR = Server Side Rendering
     서버에서 화면을 미리 만들어 보내주는 방식
```
즉 이 앱은 **파일만 올려두면 끝나는 게 아니라**, 누가 접속할 때마다 서버 프로그램이 돌면서 화면을 만들어줘야 합니다. 일반 웹호스팅 상품은 이걸 지원하지 않습니다.
### 이유 3 — 수정할 때마다 지옥이 됩니다
```plain text
웹호스팅 방식 — 글자 하나 바꿀 때마다:
  코드 수정 → 빌드 명령 실행 → 생성된 파일 찾기
  → FTP 프로그램 켜기 → 접속 → 업로드 → 확인

Vercel 방식:
  코드 수정 → Push. 끝.
```
Vercel이 GitHub를 지켜보고 있다가, 새 코드가 올라오면 **알아서 빌드하고 알아서 교체**합니다.
### 한 줄 정리
> **웹호스팅은 완성된 집을 옮겨놓는 이삿짐센터입니다.<br>Vercel은 설계도를 주면 집을 지어서 땅까지 마련해주는 시공사입니다.우리에겐 아직 설계도밖에 없습니다.**

## 3-11. STEP 8 — 자동 재배포 확인 (오늘의 마무리)
앞으로 앱을 수정하는 방식이 어떻게 되는지 직접 확인합니다.
```plain text
① Cursor로 돌아가서 아주 작은 수정 하나
     예: AI 패널에 "화면 맨 아래에 '테스트' 라는 글자를 추가해줘"

② [Keep] 눌러 확정

③ Source Control → [+] → 메시지 입력 → [Commit] → [Sync Changes]

④ Vercel 대시보드 → 왼쪽 [Deployments] 탭

⑤ 맨 위에 새 배포가 자동으로 생기는지 확인
     아무 버튼도 안 눌렀는데 "Building"(빌드 중)이 뜹니다
     → Vercel이 GitHub를 지켜보다가 스스로 시작한 것입니다

⑥ 1~2분 후 "Ready"로 바뀌면 앱 주소를 새로고침
     → 수정한 내용이 반영되어 있습니다
```
> 💡 **이 흐름이 앞으로의 작업 방식입니다.**
```plain text
Cursor에서 수정 → Keep → Commit → Push → 끝
                                       ↓
                         Vercel이 알아서 배포
```
파일을 올리거나 서버를 만지는 과정이 전혀 없습니다. 실제 개발팀도 똑같이 일합니다.

> 💡 이 사전 미션이 곧 11\~12회차 프로젝트의 출발점입니다. 미리 찾아둘수록 남은 회차가 훨씬 알차집니다.
> 💡 오늘 배운 흐름(Cursor 수정 → Push → Vercel 자동 배포)을 다음 회차까지 **스스로 한 번이라도 돌려보세요.** 컨설팅 시간이 훨씬 알차집니다.
# 부록 - 회사 도메인 연결하기 (선택)
> 오늘 실습 범위는 아닙니다. 나중에 필요할 때 보시라고 정리한 참고 자료입니다.

## 1. 먼저 — 도메인은 안 사도 됩니다
```plain text
지금 받은 주소:  앱이름.vercel.app

이건 Vercel이 공짜로 준 주소입니다.
도메인을 산 게 아니라, Vercel이 자기 도메인(vercel.app)의
앞자리를 하나 떼어준 것입니다.
```
> 💡 **비유하자면** `vercel.app`이라는 아파트 단지에 101호를 무료로 배정받은 것입니다. 땅을 산 게 아니라 방을 하나 얻은 것이죠.
**이 주소로 영구히 쓸 수 있습니다.** 기간 제한도, 갱신도, 요금도 없습니다.
---
## 2. 그럼 도메인은 왜 사나
이유가 세 가지인데, **전부 "필수"가 아니라 "취향·신뢰도" 문제**입니다.
```plain text
① 보기 좋음
   jeongdang.co.kr   vs   pay-buddy-cloud-a7x2.vercel.app

② 신뢰도
   고객사나 외부에 링크를 보낼 때 .vercel.app은
   "임시로 만든 것" 같은 느낌을 줍니다.
   사내용이면 전혀 상관없습니다.

③ 소유권
   Vercel을 떠나 다른 서비스로 옮겨도 주소를 유지할 수 있습니다.
   .vercel.app 주소는 Vercel을 떠나면 사라집니다.
```

## 4. 역할 분담 — 도메인을 사면 이렇게 됩니다.
```plain text
가비아   =  주소(이름표)만 판매
Vercel   =  실제 서버 운영

  가비아에서 산 jeongdang.co.kr
        ↓ (설정으로 연결)
  Vercel의 앱이 열림
```
**도메인을 사도 호스팅은 여전히 Vercel이 합니다.** 가비아에서는 이름표만 사는 것입니다.
---
## 5. DNS가 뭔가 — 개념부터
```plain text
도메인을 사면 "이름표"만 생깁니다.
그 이름표가 어느 서버를 가리킬지는 따로 정해줘야 합니다.

그 연결 정보를 적어두는 장부가 DNS입니다.
전화번호부라고 생각하시면 됩니다.

  jeongdang.co.kr 이라는 이름  →  실제로는 여기로 가세요
```
가비아는 도메인을 팔면서 이 장부(DNS 관리 화면)를 함께 제공합니다. 여기에 **"Vercel로 가라"고 적어주는 것**이 연결 작업의 전부입니다.
---
## 6. 전체 순서
```plain text
1. 가비아에서 도메인 구매          (연 1~2만 원)
2. Vercel에 "이 도메인 쓸게요" 등록
3. Vercel이 알려주는 값을 가비아 DNS에 입력
4. 10분~24시간 기다리면 연결 완료
5. https 인증서는 Vercel이 자동 발급
```

## 7. 단계별 상세
### ① 가비아에서 도메인 구매
```plain text
가비아 → 도메인 → 원하는 이름 검색 → 구매

  .com    연 1.5만 원대
  .co.kr  연 2만 원대
```
> ⚠️ **반드시 "도메인" 메뉴에서 사세요.** 웹호스팅 상품과 헷갈리지 마세요.
---
### ② Vercel에 도메인 등록
```plain text
① Vercel 프로젝트 → 왼쪽 메뉴 [Domains]
② [Add] 버튼 클릭
③ 산 도메인 입력 (예: jeongdang.co.kr)
④ [Add] 클릭
```
그러면 화면에 빨간 글씨로 **`Invalid Configuration`**(설정 안 됨) 경고가 뜨면서, **입력해야 할 값이 표시**됩니다.
> 💡 **이건 오류가 아닙니다.** "아직 가비아 쪽에 연결 설정을 안 했다"는 뜻입니다. 다음 단계를 하면 초록색으로 바뀝니다.
> ★ **이 화면을 캡처해두세요.** 다음 단계에서 이 값을 그대로 옮겨 적습니다.
---
### ③ Vercel이 요구하는 값 — 두 종류

값




`jeongdang.co.kr` (앞에 아무것도 없음)

`www.jeongdang.co.kr`

Vercel이 알려주는 주소 문자열


> 💡 **왜 두 종류로 나뉘나요?**<br>맨 앞자리 주소(`jeongdang.co.kr`)에는 이메일 설정 같은 다른 정보도 함께 붙어야 합니다. 그런데 CNAME은 규칙상 다른 정보와 함께 쓸 수 없습니다. 그래서 맨 앞자리는 IP를 직접 적는 A 레코드를 씁니다.
---
### ★★ 인터넷에서 찾은 IP를 쓰지 마세요
```plain text
검색하면 76.76.21.21, cname.vercel-dns.com 같은 값이
정답처럼 돌아다닙니다. 지금은 다릅니다.
```
Vercel은 프로젝트마다·플랜마다 **다른 주소를 배정**합니다. CNAME 값도 `XYZ.vercel-dns-016.com` 같은 형태로 프로젝트별로 달라졌습니다.
> ⚠️ **반드시 내 Vercel 화면에 표시된 값을 복사해서 붙여넣으세요.** 검색으로 나온 값을 쓰면 연결이 안 되거나, 되더라도 나중에 문제가 생길 수 있습니다.
---

### ⑤ 기다리기
```plain text
DNS 설정은 즉시 반영되지 않습니다.

  최대    24 ~ 48시간
```
Vercel의 Domains 화면에서 \*\*`Invalid Configuration`(빨강) → `Valid Configuration`(초록)\*\*으로 바뀌면 완료입니다.
---
### ⑥ https 보안 인증서 — 자동입니다
DNS 확인이 끝나면 **Vercel이 SSL 인증서를 자동으로 발급**합니다. 별도 구매나 설치가 없습니다.
> ⚠️ **가비아에서 SSL 인증서를 따로 사면 돈 낭비입니다.** Vercel이 무료로 자동 발급합니다.

## 9. 수업 멘트용 요약
> **주소도 서버도 공짜로 다 나옵니다.도메인은 "명함에 적을 주소가 좀 더 그럴듯했으면 좋겠다" 싶을 때만 사면 됩니다.그때도 호스팅은 Vercel 그대로이고, 가비아에서는 도메인만 사면 됩니다.보안 인증서(https)도 Vercel이 공짜로 자동 발급합니다.**
---
> **강사용 노트 — 부록**
**① "도메인 안 사도 되나요?"는 반드시 나오는 질문입니다.**`.vercel.app` 주소를 보면 "임시 주소 아닌가?" 하고 불안해합니다. **영구 무료**라는 점을 먼저 못 박으세요.
**② 웹호스팅 오구매를 막으세요.**<br>가비아를 써본 분은 "호스팅도 사야 하는 것 아닌가" 생각합니다. **주소만 사면 된다**는 구분이 실무자에게 가장 값진 정보입니다.
**③ IP 값을 교재에 박아두지 마세요.**<br>Vercel이 프로젝트별로 다른 값을 배정하도록 바뀌었습니다. "화면에 뜬 값을 그대로 옮겨 적으세요"가 정답입니다.
