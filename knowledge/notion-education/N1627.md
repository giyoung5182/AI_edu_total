## 이번 세션에서 할 일
지금 우리에게는 지시서 협업으로 완성한 세 장짜리 가이드북이 있습니다.<br>용어가 통일되고 문체가 맞춰진, 제법 책 같은 결과물입니다.<br>그런데 내용을 다시 읽어 보면 근거가 전부 한곳에서 나옵니다.<br>모델의 기억입니다.<br>여행 가이드의 환율과 항공권 시세, 재테크 가이드의 금리와 주가,<br>생존 가이드의 날씨와 지진 소식. 전부 학습 시점의 기억이라<br>그럴듯하지만, 지금 이 순간의 사실은 하나도 없습니다.
이번 세션에서는 가이드북에 실측을 답니다.<br>바깥세상의 데이터를 실시간으로 가져오는 API를 메뉴판으로 놓고,<br>내 주제에 맞는 카드를 골라 장 담당 에이전트에게 장착합니다.<br>장착 전과 후의 가이드북을 나란히 놓고 비교하는 것이<br>이번 세션의 확인 장치입니다.<br>그리고 그 전에, API라는 것 자체를 손으로 만져 봅니다.
이번 세션에서 우리가 하는 일은 세 가지입니다.

1. API를 읽는 법을 익히고, 브라우저 주소창만으로<br>직접 호출해 봅니다.
2. 메뉴판에서 내 주제에 맞는 카드를 골라 장 담당에게<br>장착하고, 가이드북이 실측을 인용하게 만듭니다.
3. 오늘 익힌 조립법을 내 업무에 대 보는<br>업무 지도 카드를 작성합니다.


> 💡 이번 세션의 핵심은 조립법입니다.<br>데이터를 고르고, 담당을 정하고, 인용 지시를 붙인다.<br>이 세 칸은 오늘의 카드 열 장 어디에나 똑같이 적용되고,<br>세상의 다른 어떤 API를 만나도 똑같이 적용됩니다.<br>카드는 소모품이지만 조립법은 남습니다.

## API — 주소 한 줄로 데이터를 주문한다
API는 프로그램끼리 데이터를 주고받는 창구입니다.<br>거창해 보이지만, 실체는 주소 한 줄로 하는 주문입니다.<br>주문서 한 장을 해부해 봅니다.
```plain text
[개별 링크 제외]

① 가게 주소: [개별 링크 제외]
② 메뉴: v1/forecast
③ 주문 옵션: ?latitude=37.40&longitude=127.10¤t_weather=true
```
- **① 가게 주소(도메인)**: 어느 서비스에 요청하는가
- **② 메뉴(경로)**: 그 서비스의 어떤 기능인가 — 예보(forecast)
- **③ 주문 옵션(파라미터)**: `?` 뒤에 `이름=값`을 `&`로 이어 붙입니다.<br>어디의(위도·경도), 무엇을(현재 날씨) 달라는 세부 주문입니다.
주문에 대한 답은 JSON이라는 형식으로 옵니다.<br>중괄호와 따옴표로 짜인 데이터 꾸러미입니다.
```json
{
  "latitude": 37.4,
  "current_weather": {
    "temperature": 29.4,
    "windspeed": 8.2
  }
}
```
읽는 법은 바깥에서 안으로, 경로를 따라가는 것입니다.<br>"현재 기온"은 `current_weather` 안의 `temperature`에 있습니다.<br>우리 서버의 코드가 하는 일도 정확히 이 경로 따라가기입니다.
**인증은 세 형태가 있습니다.**
- **무키**: 아무나 바로 호출합니다. 오늘 카드 대부분이 이 형태입니다.
- **키 동봉**: 파라미터나 헤더에 발급받은 키를 함께 보냅니다.<br>Tavily, OpenDART, Finnhub가 이 형태입니다.
- **키+시크릿 → 토큰**: 키 한 쌍으로 임시 통행증(토큰)을 먼저<br>발급받고, 이후 요청에 토큰을 씁니다. Amadeus가 이 형태입니다.<br>절차가 한 단계 길지만, 그 단계도 Claude Code가 코드로 처리합니다.
**사용량 예절도 있습니다.**<br>어느 API든 초당·일당 허용량이 있습니다.<br>허용량을 넘으면 429 응답(요청 과다)이 돌아옵니다.<br>각 카드에 적힌 허용량 안에서 쓰고, 같은 결과는 저장해 재사용하는 것이<br>모든 API에 통하는 기본 예절입니다.

### 실습 1. 브라우저로 API 맛보기
프로그램 없이, 브라우저 주소창만으로 API를 호출해 봅니다.<br>무키 주문은 주소창이 곧 주문서이기 때문입니다.
진행 순서

1. 브라우저 새 탭의 주소창에 아래를 붙여넣고 엽니다.<br>[개별 링크 제외]
2. 화면에 뜬 JSON에서 경로를 따라가 현재 기온을 찾습니다.<br>지금 판교의 실제 기온입니다.
3. 주소의 latitude, longitude 값을 다른 도시 좌표로 바꿔<br>다시 엽니다. (예: 제주 33.50, 126.53)
4. 두 번째 주문입니다. 새 탭에 붙여넣습니다.<br>[개별 링크 제외]
5. JSON에서 trade_price를 찾습니다.<br>지금 이 순간 비트코인의 원화 가격입니다.
6. 옆자리와 화면을 비교합니다. 몇 초 차이로 열었을 뿐인데<br>숫자가 다를 수 있습니다. 살아 있는 데이터라는 뜻입니다.


> 💡 방금 우리는 코드 한 줄 없이 API 두 개를 호출했습니다.<br>이제부터 하는 모든 일은, 이 주소창의 일을 서버가 대신 하고<br>그 결과를 에이전트에게 건네주는 것뿐입니다.
**FAQ**
- **Q. 글자가 한 줄로 빽빽하게 나옵니다**
- 정상입니다. JSON 원문 그대로입니다. 브라우저에 따라 보기 좋게 접어서 보여 주기도 합니다.
- **Q. 페이지가 안 열립니다**
- 주소를 복사하다 일부가 잘렸을 가능성이 큽니다. 한 줄 전체를 다시 복사해 붙입니다.

## 도구 장착 — 조립법은 세 칸이다
에이전트가 도구를 쓴다는 말의 실체는 단순합니다.<br>**에이전트가 집필하기 전에, 서버가 API를 먼저 호출하고,<br>그 결과를 프롬프트에 넣어 주는 것**입니다.
```plain text
[도구 없는 집필]
지시서  ─────────────────────────▶  장 담당  ──▶  원고 (기억 기반)

[도구 장착 집필]
서버가 API 호출 ──▶ 실측 데이터 ─┐
지시서 ──────────────────────────┴▶  장 담당  ──▶  원고 (실측 인용)
```
에이전트 자신이 인터넷에 접속하는 것이 아닙니다.<br>서버가 데이터를 떠먹여 주고, 에이전트는 그것을 근거로 씁니다.<br>그래서 장착의 조립법은 언제나 세 칸입니다.
```plain text
① 데이터   어떤 API에서 무엇을 받아 올 것인가
② 담당     그 데이터를 누구의 프롬프트에 넣을 것인가
③ 지시     "이 실측을 인용하고 출처를 밝혀라"
```
이 세 칸에 무엇을 채우느냐만 다를 뿐,<br>오늘 메뉴판의 어느 카드도, 앞으로 만날 어떤 API도<br>장착 방법은 이 세 칸을 벗어나지 않습니다.

## API 메뉴판
메뉴판은 2부입니다. 1부는 어느 주제에나 쓰는 범용 카드,<br>2부는 주제별 매대입니다. 내 주제 매대부터 읽고,<br>범용 카드를 곁들이는 순서를 권합니다.
### 1부. 범용 카드
**카드 1. Open-Meteo — 날씨 (무키)**
```php
GET [개별 링크 제외]
    ?latitude=37.40&longitude=127.10¤t_weather=true
→ { "current_weather": { "temperature": 29.4, "windspeed": 8.2 } }
```
- 붙는 자리: 여행 2장(현지 날씨), 생존 전 장(기상 상황)
- 장착 메모: 비상업 일 1만 호출 무료. daily 파라미터로 7일 예보 확장 가능.
**카드 2. Frankfurter — 환율 (무키)**
```php
GET [개별 링크 제외]
→ { "date": "2026-07-21", "rates": { "KRW": 1389.5, "EUR": 0.92 } }
```
- 붙는 자리: 여행 1장(경비 환산), 재테크 전 장
- 장착 메모: 유럽중앙은행 고시라 영업일 단위 갱신. 어제 날짜여도 정상.
**카드 3. 지도 — Nominatim + Leaflet (무키)**
```php
GET [개별 링크 제외]
→ [ { "lat": "37.3947", "lon": "127.1112", "display_name": "판교역, ..." } ]
```
- 붙는 자리: 여행 2장(장소 지도), 생존 1장(대피 장소 지도)
- 장착 메모: 장소 이름→좌표는 Nominatim, 좌표→지도 그림은 Leaflet.<br>공용 서버 예절 세 가지를 프롬프트에 그대로 적습니다 —<br>초당 1회 이하, 프로그램을 밝히는 User-Agent 지정, 같은 결과는 저장해 재사용.
**카드 4. Tavily — 웹 검색 (배부 키)**
```php
POST [개별 링크 제외]
     { "query": "검색어", "api_key": "YOUR_API_KEY" }
→ { "results": [ { "title": "...", "url": "...", "content": "..." } ] }
```
- 붙는 자리: 모든 주제의 "최신 동향·제도 변경" 대목
[개별 인증정보 제외 — 본인 계정으로 준비하세요.]
### 2부. 주제 매대

매대의 일부 카드는 무료 회원가입이 필요합니다(3\~5분, 신용카드 불요).<br>가입 카드를 고른 분만 실습 중에 가입합니다.<br>발급받은 키는 전부 `.env`에 한 줄씩 저장하고,<br>코드와 대화창에 실값을 적지 않습니다.


**\[여행 매대\]**
**카드 5. Amadeus — 실제 항공권 검색 (가입 필요, 토큰 방식)**
```php
1) 토큰 발급:
POST [개별 링크 제외]
     (발급받은 키와 시크릿 전송) → { "access_token": "..." }
2) 항공권 검색:
GET [개별 링크 제외]
    ?originLocationCode=ICN&destinationLocationCode=CDG
    &departureDate=2026-08-20&adults=1&max=3   (토큰 동봉)
→ { "data": [ { "price": { "total": "845.30", "currency": "EUR" }, ... } ] }
```
- 붙는 자리: 여행 1장 — "인천→파리 지금 최저가"가 원고에 박힙니다.
- 장착 메모: developers.amadeus.com 가입 → 앱 생성 → 키·시크릿 발급.<br>둘 다 `.env`에 저장. 테스트 환경은 월 무료 쿼터(항공권 검색 기준<br>월 2,000회) 안에서 무료이며 일부 데이터는 캐시 기반입니다.<br>토큰 발급·갱신 코드는 Claude Code가 작성합니다.
**카드 6. Wikipedia — 명소 요약 (무키)**
```php
GET [개별 링크 제외]
→ { "title": "에펠탑", "extract": "에펠탑은 프랑스 파리의 ..." }
```
- 붙는 자리: 여행 2장 — 도시·명소 소개 문단에 출처 있는 요약 공급
- 장착 메모: 문서 제목을 경로에 그대로 씁니다. 한국어 문서가 없으면<br>en.wikipedia.org로 바꿔 시도합니다.
**카드 7. Travel-Advisory — 국가별 여행 위험 지수 (무키)**
```php
GET [개별 링크 제외]
→ { "data": { "FR": { "advisory": { "score": 2.8, "message": "..." } } } }
```
- 붙는 자리: 여행 3장(안전), 생존 주제에도 겸용
- 장착 메모: 0\~5 점수. 숫자 하나가 그 나라의 현재 위험도입니다.
**\[재테크 매대\]**
**카드 8. OpenDART — 우리 회사 공시·재무 (가입 필요)**
```php
GET [개별 링크 제외]
    ?crtfc_key=YOUR_API_KEY&corp_code=회사고유번호&bgn_de=20260101
→ { "list": [ { "report_nm": "분기보고서 (2026.03)",
                "rcept_dt": "20260515", ... } ] }
```
- 붙는 자리: 재테크 3장(첫 투자) — 공시 읽는 법을 실데이터로.<br>회사 고유번호에 교육기관 계열 상장사를 넣으면 우리 회사의 실제 공시<br>목록이 원고에 들어옵니다.
- 장착 메모: opendart.fss.or.kr 가입 → 인증키 발급(일 2만 건 무료).<br>회사명→고유번호 변환은 API가 제공하는 목록 파일로 하며,<br>그 처리도 Claude Code가 작성합니다.
**카드 9. Finnhub — 미국 주식 실시간 시세 (가입 필요)**
```php
GET [개별 링크 제외]
→ { "c": 612.4, "d": -3.1, "dp": -0.5 }
```
- 붙는 자리: 재테크 3장 — 관심 종목의 지금 가격.<br>LMT(록히드마틴) 같은 해외 방산주 시세도 됩니다.
- 장착 메모: finnhub.io 가입 즉시 키 발급, 무료 분당 60회.<br>응답의 c가 현재가, d가 전일 대비, dp가 등락률(%)입니다.
**카드 10. Upbit — 비트코인 원화 시세 (무키)**
```php
GET [개별 링크 제외]
→ [ { "trade_price": 165230000, "signed_change_rate": 0.012 } ]
```
- 붙는 자리: 재테크 2·3장 — 실습 1에서 이미 손으로 호출해 본 그 주문입니다.
- 장착 메모: 시세 조회는 키 없이 초당 10회까지. markets에<br>KRW-ETH처럼 다른 종목을 이어 붙일 수 있습니다.
**\[생존 매대\]**
**카드 11. USGS — 전 세계 실시간 지진 (무키)**
```php
GET [개별 링크 제외]
    ?format=geojson&minmagnitude=4.5&limit=3&orderby=time
→ { "features": [ { "properties":
     { "mag": 5.1, "place": "27 km SW of ..." } } ] }
```
- 붙는 자리: 생존 1장(지진) — "지난 24시간 규모 4.5 이상" 실황 목록.<br>카드 3(지도)과 결합하면 발생 지점을 지도에 찍을 수 있습니다.
- 장착 메모: 미국 지질조사국 공개 API. starttime, minmagnitude로<br>기간·규모를 조절합니다.
**카드 12. Open-Meteo 대기질 — 미세먼지 (무키)**
```php
GET [개별 링크 제외]
    ?latitude=37.40&longitude=127.10¤t=pm2_5,pm10
→ { "current": { "pm2_5": 18.3, "pm10": 41.7 } }
```
- 붙는 자리: 생존 2·3장 — 실외 활동·대피 판단 대목에 지금 공기질
- 장착 메모: 카드 1과 같은 집안의 자매 주소입니다. 가입도 키도 같은 값(불요)입니다.

### 실습 2. 카드 장착 — 내 가이드북이 실측을 인용한다
카드 한 장을 골라 집필팀의 장 담당 한 명에게 장착합니다.<br>프롬프트를 조립합니다. 빈칸은 두 개입니다.<br>어느 장 담당에게, 어떤 카드를.<br>\[카드 블록\] 자리에는 고른 카드의 **요청·응답 예시와 장착 메모를<br>통째로 복사해** 붙입니다. 카드가 곧 사양서입니다.
작업 시작 전에 터미널 A의 Claude Code에서 `/clear`를 실행합니다.<br>가입 카드를 골랐다면 지금 가입하고 키를 `.env`에 저장한 뒤 시작합니다.
**Claude Code 프롬프트**
```plain text
집필팀의 에이전트에게 외부 API 도구를 장착해 주세요. 요구사항입니다.

1. 대상: ______ 장 담당 에이전트
   (예: 1장 담당 / 3장 담당)

2. 장착할 도구입니다. 아래 카드의 요청 방식과 메모를 따라 주세요.
   [카드 블록]

3. 동작 방식입니다.
   - 그 담당의 집필 차례가 되면, 서버가 먼저 위 API를 호출해
     실측 데이터를 받아 옵니다.
   - 받은 데이터를 지시서와 함께 담당의 프롬프트에 넣고,
     "이 실측 데이터를 원고에 인용하고, 조회 시각과 출처를
     밝혀라"는 지시를 추가해 주세요.
   - API 호출이 실패하면 담당이 "실측 확인 불가"라고 원고에
     밝히고 기존 방식으로 쓰게 해 주세요.

4. 화면 표시입니다.
   - 도구를 쓴 원고 카드에는 "실측 인용" 표식을 붙여 주세요.
   - 서버가 호출한 API의 요청과 응답 핵심이 서버 로그에
     한 줄씩 남게 해 주세요.

5. 키가 필요한 카드라면 .env에서 읽고, 코드에 직접 적지 마세요.
   집필팀의 다른 동작은 바꾸지 마세요.
```
진행 순서

1. 내 주제 매대와 범용 카드에서 한 장을 고릅니다.<br>기준은 하나입니다. "어느 장의 어느 문장이 실측으로<br>바뀌면 가장 좋아질까."
2. \[예측\] Ch5 최종본에서 그 담당의 원고 중 기억으로 쓴<br>숫자·사실 문장을 하나 골라 메모합니다.<br>장착 후 그 자리가 어떻게 바뀔지 예측해 적습니다.
3. 프롬프트를 조립해 입력하고, 진행합니다.<br>(가입 카드는 키 발급과 .env 저장을 먼저 합니다.)
4. 서버를 재시작하고 \[지시서 집필 시작\]으로 재집필합니다.
5. "실측 인용" 표식이 붙은 원고를 펼쳐 읽습니다.
6. \[확인\] 터미널 B의 로그에서 API 요청·응답 한 줄을 찾아,<br>원고 속 숫자와 로그 속 숫자가 같은지 대조합니다.<br>화면의 문장이 실제 데이터에서 왔다는 증거입니다.
7. Ch5 최종본과 나란히 놓고, 2번에서 고른 문장의 전후를<br>비교합니다.
8. 옆자리와 서로의 가이드북을 구경합니다. 주제·담당·카드<br>조합이 달라 전부 다른 업그레이드가 되어 있습니다.

> 💡 6번의 대조가 이번 실습의 결승선입니다.<br>원고의 숫자와 서버 로그의 숫자가 일치하는 것을 눈으로 본 순간,<br>"AI가 도구를 쓴다"는 말이 정확히 무엇인지 알게 된 것입니다.
**FAQ**
- **Q. API 호출이 실패합니다**
- 터미널 B의 오류 로그를 Claude Code에 붙여넣어 해결을 요청합니다. 키 동봉 카드라면 `.env`의 키 이름과 값부터 확인합니다.
- **Q. 원고에 실측이 안 섞입니다**
- 데이터가 프롬프트에 들어가지 않은 상태입니다. Claude Code에 "API 결과가 담당 프롬프트에 포함되는지 로그로 보여 주세요"라고 요청합니다.
- **Q. Amadeus 토큰 오류가 납니다**
- 키·시크릿 확인 후, Claude Code에 "토큰 발급과 만료 갱신이 처리되는지 점검해 주세요"라고 요청합니다.
- **Q. 지도 검색이 갑자기 차단되었습니다**
- Nominatim 예절 위반 가능성입니다. Claude Code에 "User-Agent와 초당 1회 제한, 결과 재사용이 적용되어 있는지 점검해 주세요"라고 요청합니다.
- **Q. 429 응답이 옵니다**
- 그 API의 허용량을 넘긴 상태입니다. 카드의 허용량을 확인하고, 호출 간 대기나 결과 재사용을 요청합니다.
- **Q. 환율·공시 날짜가 오늘이 아닙니다**
- 정상입니다. 환율은 영업일 고시, 공시는 제출일 기준입니다. 실시간이 아니라 "가장 최근의 공식 값"인 데이터도 있습니다.

### 실습 3. 한 장 더 (선택)
시간이 남는 분만 진행합니다.<br>다른 카드 한 장을 다른 장 담당에게 장착합니다. 방법은 같습니다.<br>두 도구가 한 번의 집필 안에서 함께 동작하면,<br>장마다 근거의 출처가 다른 가이드북이 완성됩니다.<br>조합의 예입니다. 여행이면 항공권(1장)+지도(2장),<br>재테크면 공시(3장)+비트코인(2장), 생존이면 지진(1장)+대기질(2장).

## 문서 근거 담당을 초대하고 싶다면
외부 데이터만 도구가 되는 것은 아닙니다.<br>우리에게는 이미 벡터DB에 적재된 문서와 하이브리드 검색기가 있습니다.<br>검색기를 도구로 쥔 담당을 집필팀에 초대하면, 원고에 청크 번호가 달립니다.<br>원하는 분을 위해 요청 프롬프트만 남겨 둡니다.
```plain text
집필팀에 "문서 근거 담당"을 추가해 주세요.
- 각 장의 집필 전에, 서버가 그 장의 주제로 하이브리드 검색을
  실행해 상위 3개 청크를 가져옵니다.
- 장 담당은 청크 내용을 근거로 쓸 수 있는 대목에서 인용하고,
  청크 번호와 출처 문서명을 함께 밝힙니다.
- 검색 결과가 빈약하면 "적재 문서에서 근거를 찾지 못했습니다"
  라고 원고에 밝히게 해 주세요.
```

### 실습 4. 업무 지도 카드 — 조립법을 내 일에 댄다
마지막 10분은 화면을 잠시 접고, 종이 또는 메모장에<br>세 칸짜리 카드를 작성합니다.<br>오늘의 조립법(데이터 → 담당 → 지시)을 그대로 내 일에 대 보는 정리입니다.

① 내가 회사나 일상에서 반복하는 \[결정\] 또는<br>\[찾아보는 정보\] 하나:<br>(예: 주간 회의 안건 정리 / 규정 조항 확인 /<br>환율 걸린 견적 검토 / 출장 준비)
② 그 일은 어느 부품의 일에 가까운가: (동그라미)<br>문서에 근거해 답하기 (A·B·C) /<br>입장을 다투고 결정하기 (D) /<br>나눠 쓰고 합치기 (E) /<br>두 가지 이상의 조합
③ 그 일에 실측을 붙인다면 — 메뉴판에서 빌려올 카드,<br>또는 "이런 데이터를 주는 API가 있다면" 하는 희망 사항:<br>(없으면 "없음"도 답입니다)

작성한 카드는 버리지 말고 지참합니다.<br>5분 안에 ①이 떠오르지 않으면 위 예시 중 하나에<br>동그라미를 치는 것으로 충분합니다.

## 실습 확장 (선택)
- **예보 넓히기**: 날씨 카드를 썼다면 "7일 예보도 함께 인용하게<br>해 주세요"라고 요청합니다.
- **지진 지도**: USGS를 썼다면 카드 3을 겹쳐 "지진 발생 지점을<br>지도에 표시해 주세요"라고 요청합니다.
- **검색어 훔쳐보기**: 웹 검색 카드를 썼다면 서버 로그에서 서버가<br>만든 검색어를 찾아보고, "검색어를 담당이 직접 정하게 해<br>주세요"라고 바꿔 차이를 관찰합니다.
- **새 카드 발굴**: 메뉴판에 없는 API를 하나 찾아<br>이번 조립법으로 장착을 시도합니다. 무키인지, 허용량이<br>넉넉한지, 응답이 JSON인지 — 오늘 배운 눈으로 직접 판별합니다.
- **코드 열어 보기**: "API를 호출해 프롬프트에 넣는 함수를<br>보여 주고, 한 줄씩 설명해 주세요"라고 요청합니다.

## 이번 실습 결과물
이번 세션을 마친 우리 손에는 다음이 있습니다.
- 브라우저 주소창으로 API를 직접 호출해 본 경험,<br>그리고 주문서(요청)와 꾸러미(JSON)를 읽는 눈
- 실측 데이터를 조회 시각·출처와 함께 인용하는 내 가이드북
- 원고의 숫자와 서버 로그의 숫자를 짝지어 본 경험
- 어떤 API에도 통하는 세 칸 조립법과, 그것을 내 일에 대 본<br>업무 지도 카드
지금 프로젝트 폴더의 구조입니다.
```plain text
~/my-chat/
├── CLAUDE.md
├── .env                    ← Gemini·Tavily 등 키 보관 (외부 공유 금지)
├── server.py               ← 채팅(RAG) + 문서 + 검색 + 회의 + 집필 + 도구
├── static/
│   ├── index.html          ← 채팅 화면
│   ├── documents.html      ← 문서 처리 화면
│   ├── search.html         ← 검색 비교 화면
│   └── meeting.html        ← 회의방 (회의/집필 모드, 실측 인용 표식)
├── docs/                   ← 배부받은 문서 3종
├── chroma_db/              ← 벡터DB
└── requirements.txt
```
파일 이름과 구조는 Claude Code의 작업에 따라 조금 다를 수 있습니다.<br>장착한 도구의 실측 인용이 동작하면 문제없습니다.
**지금 우리가 가진 부품**
```plain text
부품 A. 나만의 AI 채팅방 (문서 근거 답변 모드 장착)
부품 B. 문서 적재기 (파싱 → 청킹 전략 3종 → 임베딩 → 적재)
부품 C. 하이브리드 검색기 (BM25 + 벡터, RRF 결합)
부품 D. 회의방 (에이전트 격돌 + 본부장 진행 + 결정권자 개입)
부품 E. 집필팀 (지시서 협업 + 실측 인용 업그레이드)
부품 F. 도구 연결기 (세 칸 조립법: 데이터 → 담당 → 지시)
```
여섯 부품은 서로 끼워 쓸 수 있게 만들어져 있습니다.<br>어떤 문서든 B·C로 검색 대상이 되고, 어떤 논쟁이든 D의 방식으로<br>결론에 닿고, 어떤 결과물이든 E의 방식으로 나눠 만들 수 있으며,<br>어떤 담당에게든 F의 조립법으로 세상의 데이터를 붙일 수 있습니다.
