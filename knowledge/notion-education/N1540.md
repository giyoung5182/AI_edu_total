## 01. 내 프로젝트 시작
1교시까지는 강사가 정해 준 D-day 계산기를 다 같이 만들었습니다. 같은 지시를 따라 치면서 말로 시켜 화면을 만들고 고치는 리듬에 익숙해지는 시간이었습니다. 이제부터는 그 익숙해진 방식을 내 일에 가져옵니다. 오늘 2교시에 정한 주제 하나를 0교시 게임에서 4교시 완성품까지 한 줄기로 끌고 갈 겁니다. 그러니 여기서 무엇을 만들지를 또렷하게 정해 두는 일이 뒤 세 시간을 좌우합니다.
오늘 할 일은 한 문장으로 정리됩니다. 내가 풀 문제를 정하고, 만들 화면을 이미지로 그려 Padlet에 올립니다.
[원본 이미지 제외]
평소 일하다 보면 '이건 매번 번거롭다' 싶은 일이 한두 개씩 있습니다. 같은 값을 매번 계산기로 따로 옮겨 적는 일, 양식을 매번 새로 채우는 일, 점검 항목을 종이에 적어 가며 확인하는 일. 그런 일 하나를 오늘 가져옵니다. 그걸 웹앱으로 어떻게 간단히 풀지 Gemini와 함께 궁리해 보면, 무엇을 만들지가 또렷해지고 그다음 작업이 한결 수월해집니다.
## 02. Gemini와 아이디어 잡기
막상 '뭘 만들지' 떠올리려고 하면 머리가 하얘질 수 있습니다. 그럴 때 혼자 끙끙댈 필요가 없습니다. Gemini에게 지금 상황을 그대로 말로 풀어 놓고 같이 정리하면 됩니다. 거창하게 정리해서 물어볼 것도 없습니다. 평소에 동료에게 푸념하듯 적어 보세요.
예를 들어 이렇게 물어봅니다.
```plain text
요즘 이런 일이 번거로운데, 단일 html로 간단히 풀 방법이 있을까?
[여기에 번거로운 일을 한두 줄로 적습니다]
```
엔터를 누르면 Gemini가 "이렇게 만들면 어떨까요" 하고 방향을 몇 가지 잡아 줍니다. 입력칸은 무엇을 두면 좋을지, 어떤 값을 자동으로 계산해 줄 수 있을지, 결과를 어떤 모습으로 보여 줄지를 같이 짚어 줍니다. 내가 생각하지 못한 쪽을 제안하기도 하니, 마음에 드는 방향이 나올 때까지 "그건 좀 복잡한데 더 단순하게 해줘", "그 기능은 빼고 가자"처럼 편하게 주고받아 보세요.

**실제 회사 정보는 빼고 묻습니다**
Gemini에 적은 내용은 외부 서버로 넘어갑니다. 번거로운 일을 설명할 때 실제 계약명, 사람 이름, 금액은 빼거나 가짜로 바꿔서 적습니다. '○○사 견적' 대신 '거래처 견적'처럼만 적어도 방향을 잡는 데는 충분합니다.

## 03. PRD 만들기
Gemini와 이야기하다 보면 '아, 이런 걸 만들면 되겠다' 하는 그림이 잡힙니다. 그 내용을 한곳에 모아 두는 문서가 PRD입니다. 이름이 어렵게 들리지만, PRD는 '만들 것을 적은 설명서'입니다. 신입에게 일을 맡길 때 "이거 넣고, 이렇게 처리하고, 이렇게 보여 주세요"라고 적어 건네는 메모와 같습니다.
PRD에 담을 건 세 가지면 충분합니다. 무엇을 입력으로 넣을지, 그 값을 어떻게 처리할지, 결과로 무엇을 보여 줄지. 이 정도만 정해지면 AI가 화면을 만드는 데 필요한 재료는 다 갖춘 셈입니다. 두꺼운 양식을 빈칸 없이 채울 필요는 없습니다. 우리한테 필요한 건 만들 것을 또렷하게 적은 한 장입니다.
[원본 이미지 제외]
직접 형식을 고민할 것도 없습니다. 방금까지 나눈 대화를 그대로 살려 Gemini에게 정리를 맡기면 됩니다.
```plain text
지금까지 이야기한 내용을 PRD로 정리해줘. 무엇을 입력하고, 어떻게 처리하고, 무엇을 보여줄지가 들어가게.
```
엔터를 누르면 우리가 나눈 대화가 입력·처리·결과로 깔끔하게 묶인 설명서 한 장으로 정리되어 나옵니다. 읽어 보고 빠진 게 있으면 "여기에 이런 항목도 넣어줘", 너무 많으면 "이건 빼자"라고 한 번 더 다듬어 보세요. 이 PRD가 오늘 만들 것의 뼈대입니다.
## 04. 문서·툴 방향 정하기
PRD까지 나왔으면 이제 방향을 한 가지 정합니다. 만드는 건 문서여도 좋고 툴이어도 좋습니다. 둘은 쓰임이 다릅니다. 공유할 자료를 깔끔하게 정리해 두고 동료에게 그대로 건네고 싶으면 문서로 만듭니다. 값을 입력하면 결과를 계산해 내주는 게 필요하면 툴로 만듭니다. 같은 견적이라도 '이번 분기 견적 안내'처럼 읽고 공유할 거라면 문서, '숫자를 넣으면 견적이 바로 나오는' 게 필요하면 툴입니다.
[원본 이미지 제외]
우리는 이걸 'HTML로 만든다'고 했습니다. HTML로 만든다는 건 프로그래밍 언어로 만든다는 뜻입니다. 그런데 그 이상은 몰라도 됩니다. HTML이 어떻게 생겼는지, 어떻게 돌아가는지 알 필요가 없습니다. 우리는 무엇을 만들지 정하는 데까지만 하면 되고, 그걸 코드로 바꾸는 일은 AI가 합니다.

**문서일까, 툴일까**
결과물을 '읽기만 하면 되는가' 아니면 '값을 넣고 결과를 받아야 하는가'로 갈라 보면 쉽습니다. 읽으면 끝이면 문서, 눌러야 결과가 나오면 툴입니다.

## 05. 순수 HTML의 한계
우리가 오늘 만드는 건 HTML 파일 하나입니다. 편하고 빠르지만, 파일 하나로 못 하는 일도 있습니다. 이런 기능이 필요하면 외부 서비스를 따로 연결해야 합니다.

**HTML 파일 하나로는 안 되는 일**
- **함께 보기·수정**: 여러 사람이 같은 데이터를 함께 보고 고치기
- **영구 보관**: 입력한 값은 내 브라우저에만 임시로 남아서, 기록을 지우거나 다른 PC에서 열면 사라집니다
- **로그인·권한 관리**: 누가 들어왔는지 구분하고 권한 나누기
- **자동 발송·기록**: 메일·메신저 자동 발송, 사내 시트에 자동 기록
- **실시간 외부 정보**: 환율·날씨·공공데이터 불러오기

## 06. 외부 서비스 연결
방금 본 한계는 외부 서비스를 붙이면 넘을 수 있습니다. 무엇을 만들지 정할 때, 당장 안 되는 기능도 나중에 이런 걸 붙이면 된다는 그림을 알아 두면 좋습니다.





연결 대상

붙이면 할 수 있는 것

주의·난이도




**데이터 저장·공유** (Supabase / Firebase)

여러 사람이 같은 데이터 보기, 영구 저장, Gmail 로그인, 실시간 동기화

난이도 중 · 회사 데이터를 저장하면 보안 검토 필수




**사내 시트·문서** (Google Sheets / Apps Script)

입력값을 시트에 자동 누적, Docs·PDF 자동 생성

난이도 중 · Apps Script 과정에서 다룸




**알림·메시지** (이메일 / 사내 메신저)

제출·이상 발생 시 자동 메일·알림 발송

중계 서버(Apps Script·n8n) 필요




**외부 공개 데이터** (공공데이터포털 / 환율 / 날씨 / 지도)

실시간 정보를 화면에 불러오기

CORS 제약 있음 · 프록시 필요




**업무 자동화** (n8n / Zapier / Make)

여러 앱을 흐름으로 자동 연결 (입력 → 기록 → 알림 → 보고)

난이도 중 · N8N 과정에서 다룸




**결제·정산** (PG사)

실제 결제·정산 처리

난이도 상 · 서버 간 통신 필요(고급)



**오늘 실습은 순수 HTML까지만**
외부 서비스를 연결하려면 계정과 키를 설정하고 보안 검토도 거쳐야 해서 시간이 제법 걸립니다. 그래서 이번 과정에서는 순수 HTML까지만 만듭니다. 위 표는 '이런 게 가능하다'는 지도일 뿐, 오늘 직접 붙이지는 않습니다. 생성형 AI 연동은 회사 보안 정책상 제외합니다.

## 07. 화면 이미지 그리기
주제가 정해졌으면 그 화면이 어떻게 생겼을지 그림으로 한 장 받아 봅니다. 말로만 '입력칸 하나에 버튼 하나'라고 하면 머릿속 그림이 사람마다 다릅니다. 눈에 보이는 그림이 한 장 있으면 무엇이 어디에 놓일지가 분명해지고, 3교시에서 이 그림을 실제 화면으로 바꿀 때 흔들림이 줄어듭니다.
[원본 이미지 제외]
방금 만든 PRD를 그대로 활용합니다.
```plain text
이 PRD대로 만들 화면을 이미지로 그려줘.
```
엔터를 누르면 입력칸과 버튼, 결과가 화면 어디에 배치될지가 한눈에 보이는 그림 한 장이 나옵니다. 받아 보고 '결과를 위로 올렸으면', '입력칸이 너무 많다' 싶으면 그대로 말해 다시 그리게 합니다.
```plain text
결과를 화면 위쪽에 크게 보여주고, 입력칸은 아래로 모아줘.
```
또, 다른 사람들에게 해당 문제 공유와 이해를 위해 4컷 만화도 한번 만들어볼게요
```json
PRD 기준으로 문제 상황과 해결 방안을 4컷 만화로 그려줘
```
이렇게 마음에 들 때까지 한두 번 다시 그립니다. 여기서 픽셀 단위까지 완벽하게 맞출 필요는 없습니다. 무엇이 어디에 있는지, 큰 배치가 마음에 드는지까지만 잡으면 충분합니다. 세밀하게 다듬는 일은 3교시에서 Stitch로 합니다.
## 08. Padlet에 공유하기
마음에 드는 그림이 나왔으면 그 이미지를 Padlet에 올립니다. Padlet은 우리가 만든 결과물을 한곳에 모아 두는 게시판입니다. 오늘 그린 화면 이미지를 여기에 올려 두면, 3교시에서 다시 꺼내 Stitch에 넣어 실제 화면으로 바꾸게 됩니다.

**Padlet 링크**
화면 이미지를 아래 Padlet에 올립니다.


Padlet에 게시한 이미지를 기반으로 본인의 아이디어를 1분간 소개하는 시간을 가져봅시다.

**이 이미지는 아직 코드가 아닙니다**
오늘 그린 건 '이렇게 생긴 화면을 만들 것이다'를 보여 주는 밑그림입니다. 이걸 실제로 동작하는 코드로 바꾸는 일은 3교시(Stitch)부터입니다. 지금은 무엇을 만들지와 어떻게 생겼는지까지만 정해 두면 됩니다.
