# 실습 · 부서 전용 Gems 지침 작성

정리일: 2026-10-08 · 교육 에셋 N1188

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
검토 절차를 Gems에 저장해 다음번에도 같은 품질로 나오게 하는 부서 전용 Gem의 지침을 R.O.P.E.+K 구조로 작성함. 오늘은 지침까지 만들고 자료는 회사에서 붙임.
## 진행 단계
1. **새 Gem 만들기 (5분)** — 브라우저에서 Gemini → 왼쪽 메뉴 Gems → 새로 만들기. 이름은 모듈 01에서 고른 업무명 그대로 사용.
2. **R·O·P 채우기 (15분)** — 먼저 세 칸만 작성.
- 입력할 내용:
```javascript
[R] 역할
당신은 (어느 분야)를 (몇 년간) 담당하며
(어떤 산출물)을 직접 작성해 온 (직책)입니다.

[O] 목표 — 한 문장으로
사용자가 (무엇을) 넣으면 (무엇을) 만듭니다.

[P] 절차 — 번호로
1.
2.
3.
4.
```
- 주의: O는 반드시 한 문장. 두 문장이 되면 Gem을 둘로 나누는 편이 나음.
3. **E와 K 채우기 (10분)** — 품질을 가르는 칸. 원하는 출력 형태를 짧게라도 직접 그려 넣고(예: \| 항목 \| 값 \| 단위 \| 문서 위치 \|), K에는 약어·단위 규칙·쓰지 말 표현을 넣음.
4. **제약 붙이기 (2분)** — 아래를 복사해 맨 끝에 붙임.
- 입력할 내용:
```javascript
[제약]
- 제가 제공한 문서에 없는 값은 절대 만들지 마세요.
- 문서에 없는 항목은 [확인 필요]로 표시하세요.
- 원문의 단위를 그대로 쓰고 변환하지 마세요.
- 일반적인 기술 지식으로 빈칸을 채우지 마세요.
- 정보가 부족하면 추측하지 말고 먼저 물어보세요.

[자주 틀리는 것]
(비워 둡니다)
```
5. **돌려보기 (8분)** — 배포된 자료 아무거나 넣어 두 번 실행. 내용이 업무와 안 맞아도 지침이 작동하는지만 확인.
- 정상 결과: 두 번의 형식이 같음 / 절차 순서대로 동작 / 없는 값을 지어내지 않음 / 약어를 제대로 씀. 어긋난 것은 \[자주 틀리는 것\] 칸에 한 줄씩 기록.
## 막히는 지점
- O가 두 문장이 됨 — 과업이 두 개라는 뜻이므로 Gem을 둘로 나눔.
- 절차를 글로 적기 어려움 — 너무 익숙해서 의식하지 않기 때문. AI에게 "한 번에 하나씩 질문해 5개 정도 물은 뒤 \[P\] 절차를 번호로 정리"하도록 인터뷰시킴.
- 형식이 다름 → E에 출력 예시를 더 구체적으로 / 순서 안 지킴 → P 번호를 더 잘게 / 값을 지어냄 → 제약 문장을 맨 끝에 한 번 더 / 약어 오류 → K에 약어 추가.
