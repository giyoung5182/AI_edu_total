# 2. ROPE + K — Gem 지시문 작성 공식
## 2-1. 왜 Gem은 RCTCK가 아닌 ROPE+K인가
```plain text
RCTCK:
  1회성 요청에 최적화된 프롬프트 공식
  "이번 한 번만 이 업무를 해줘"

ROPE+K:
  반복 자동화에 최적화된 Gem 지시문 공식
  "앞으로 이 업무를 맡아서 항상 처리해줘"

차이:
  RCTCK → 그때그때 지시
  ROPE+K → 역할을 부여하고 역할을 수행하게 함
```
---
## 2-2. ROPE + K 각 요소 설명
```plain text
╔══════════════════════════════════════════════════════════╗
║                                                          ║
║  R  Role — 역할·페르소나·전문성                           ║
║     단순한 직함이 아니라,                                 ║
║     어떤 경험과 원칙을 가진 전문가인지까지 설정           ║
║                                                          ║
║  O  Objective — 이 Gem의 존재 목적                        ║
║     어떤 반복 업무를 처리하는가                           ║
║     어떤 상황에서 호출되는가                              ║
║                                                          ║
║  P  Process — 처리 방식·출력 순서·형식                    ║
║     결과를 어떤 순서로 어떤 형식으로 내는가               ║
║     표·목록·단락 등 출력 형식 지정                        ║
║                                                          ║
║  E  Example — 이상적인 출력 예시                          ║
║     좋은 결과물의 예시 1건                                ║
║     예시가 있으면 품질이 크게 향상됨                      ║
║     (없어도 되지만, 있으면 훨씬 좋음)                     ║
║                                                          ║
║  K  Knowledge — 기관 정보·문서·금지 사항                  ║
║     우리 기관 기본 정보                                   ║
║     Golden Sample (문체 기준 문서)                        ║
║     절대 하면 안 되는 것                                  ║
║                                                          ║
╚══════════════════════════════════════════════════════════╝
```

## 2-3. ROPE+K 각 요소 심화 — 교육기관 기준
### R \| Role — 역할을 구체적으로 설정할수록 품질이 달라진다
```plain text
레벨 1 (약함):
  "너는 공문 작성 전문가야."
  → AI: "공문 전문가"의 기준이 모호

레벨 2 (보통):
  "너는 교육기관 기업지원부 담당자야."
  → AI: 기관명은 알지만 경험·원칙 모름

레벨 3 (강함):
  "너는 교육기관 33 기업지원부에서
   기업 지원사업 안내 공문을 10년 이상 작성한 담당자야.
   충청북도 공공기관 표준 공문 양식을 완벽히 숙지하고 있으며,
   항상 기업이 이해하기 쉬운 어조를 유지해.
   수치와 날짜는 반드시 확인된 것만 사용하고,
   불확실한 내용은 절대 임의로 작성하지 않아."
  → AI: 경험·원칙·말투·제약까지 모두 파악
```
### O \| Objective — 어떤 반복 업무를 맡기는가
```plain text
구체적일수록 좋습니다.

약한 O:
  "공문 작성을 도와줘."

강한 O:
  "내가 사업명, 지원 내용, 신청 기간, 대상을 알려주면,
   즉시 충청북도 공공기관 표준 형식의 공문 초안을 생성해.
   기업 대표 수신용과 실무 담당자 수신용
   두 가지 버전을 항상 함께 제공해."
```
### P \| Process — 출력 순서와 형식을 고정한다
```plain text
P에서 정해두면:
  매번 요청할 때마다 항상 같은 형식으로 출력됨
  팀원이 사용해도 동일한 결과물

예시:
  "결과물은 항상 이 순서로:
   1. 기업 대표 수신용 공문 (전문)
   2. 실무 담당자 수신용 공문 (전문)
   3. 검증 체크리스트 (미기재 항목, 수정 필요 사항)"
```
### E \| Example — 예시 1건의 위력
```plain text
Example이 없을 때:
  AI가 임의로 예시 형식을 만들어냄

Example이 있을 때:
  → AI가 그 예시의 구조·어조·분량을 기준으로 생성
  → 처음부터 원하는 결과에 훨씬 가까워짐

예시 작성 팁:
  실제로 잘 만들어진 공문 1건의 첫 단락만 넣어도 충분
  전문 다 넣으면 더 좋지만, K에 Golden Sample로 넣을 것이므로
  E에는 짧은 예시로 충분
```
### K \| Knowledge — Gem이 영구 기억하는 기관 정보
```plain text
K에 넣어야 할 것들:

기관 기본 정보:
  기관명: 교육기관 33
  주소: 충북 청주시 흥덕구 풍산로 50, 1~3층
  대표번호: [연락처 비공개]
  영문명: Chungbuk Business Agency

부서 구성:
  경영기획부, 기업지원부, 일자리지원부,
  청년지원부, 소상공인지원센터, 농식품유통본부

주요 사업 목록:
  중소기업육성자금, 글로벌강소기업 육성사업,
  기업경영안정화 자금, 가족친화인증기업 바우처,
  한국경제인협회 경영자문상담회, 영세기업 위기극복 컨설팅,
  기업애로 SOS 자문단, 판로개척지원, 수출기업 육성 등

Golden Sample:
  [우리 기관이 잘 작성한 문서 1건 삽입]

절대 금지 사항:
  확인되지 않은 수치나 날짜 임의 작성 금지
  내가 입력하지 않은 항목은 [미기재 - 담당자 입력 필요]로 표시
  기밀 정보나 타 기업 정보 절대 포함 금지
```

# 3. Gem 만드는 법 — 4가지 방법
## 3-1. 정석 방법 — ROPE+K로 직접 작성
```plain text
언제: 새로운 업무를 처음 자동화할 때

방법:
  ① ROPE+K 각 요소를 채워서 지시문 초안 작성
  ② Gemini → Gem 만들기 → 지시문 붙여넣기 → 저장
  ③ 테스트 → 결과 확인 → 지시문 수정
  ④ 확정 후 팀 공유

적합한 상황:
  완전히 새로운 업무 유형을 자동화할 때
  특정 형식이 중요한 공식 문서 작업
```
---
## 3-2. 역설계 방법 — 잘 된 결과물에서 Gem 추출
```plain text
언제: 이미 잘 만들어진 공문·보고서가 있을 때

방법:
  ① 잘 된 기존 문서 1건을 AI에게 보여줌
  ② AI에게 "이 문서를 자동으로 생성할 Gem 지시문을 만들어줘"
  ③ 생성된 지시문 검토·수정 → Gem에 붙여넣기

프롬프트:
  "아래는 내가 실제로 작성한 공문이야.
   이 문서를 분석해서, 앞으로 비슷한 공문을
   자동으로 생성할 수 있는 Gem 지시문을 만들어줘.
   ROPE + K 형식으로 작성해줘.

   [기존 문서 전문 붙여넣기]"

장점:
  ROPE+K 작성 방법을 몰라도 바로 시작 가능
  이미 검증된 결과물 기반이라 품질 보장
```

## 3-3. 메타프롬프트 방법 — AI가 Gem을 설계하게 하기
```plain text
언제: 업무는 알고 있는데 어떻게 자동화할지 막막할 때

방법:
  AI에게 "내 업무 상황"을 설명하면
  AI가 Gem 지시문 전체를 설계해줌

프롬프트:
  "나는 교육기관 33 기업지원부 담당자야.
   매달 여러 종류의 기업 지원사업 안내 공문을 작성해야 해.

   아래 정보를 참고해서,
   이 반복 업무를 자동화할 Gem 지시문을 만들어줘.
   ROPE + K 형식으로 작성해줘.

   기관명: 교육기관 33
   대표번호: [연락처 비공개]
   주요 사업: 중소기업육성자금, 글로벌강소기업 육성,
              기업경영안정자금, 판로개척 지원 등
   자주 쓰는 공문 유형: 참가기업 모집, 선정 통보,
                        사업 안내, 결과 보고"

장점:
  완전 초보도 바로 시작 가능
  AI가 놓친 부분은 이후 수정하면 됨
```

## 3-4. 딥리서치 방법 — AI가 외부 정보까지 수집해서 Gem 강화
```plain text
언제: Gem에 넣을 배경 지식이 부족할 때

방법:
  NotebookLM이나 ChatGPT에 공개 자료를 넣고
  AI가 그 자료를 학습한 후 Gem 지시문 작성

예시 (교육기관 기업지원 Gem 강화):
  ① 교육기관 33 홈페이지 사업 안내 페이지 URL을
     NotebookLM에 소스로 등록
  ② "이 자료를 바탕으로 기업지원 업무 자동화 Gem 지시문을
     ROPE+K 형식으로 작성해줘"
  ③ 생성된 지시문 → Gemini Gem에 붙여넣기

장점:
  최신 사업 정보가 반영된 Gem 생성 가능
  공개된 기관 자료 기반이라 정확도 높음
```

# 4. Gemini에서 Gem 만들기 — 단계별 가이드
## 4-1. Gem 만들기 전 준비물
```plain text
필요한 것:
  ① Google 계정 (무료)
  ② 만들 Gem의 ROPE+K 지시문 (직접 작성 또는 AI 생성)
  ③ Golden Sample 문서 1건 (K에 넣을 기존 문서)
  ④ 기관 기본 정보 (기관명·주소·연락처·주요 사업)
```
## 4-2. Gem 만들기 단계별 클릭 가이드
```plain text
STEP 1: Gemini 접속
  → gemini.google.com 접속
  → 구글 계정으로 로그인

STEP 2: Gem 탐색 진입
  → 왼쪽 사이드바에서 [Gem 탐색] 클릭
  → 오른쪽 상단 [+ 새 Gem] 클릭

STEP 3: 기본 정보 입력
  → 이름 입력: "기업지원부 공문 작성 비서"
  → 설명 입력 (선택): "교육기관 기업지원부 공문 자동 작성"

STEP 4: 지시문 입력
  → [지시문] 텍스트 박스에 ROPE+K 내용 전체 붙여넣기
  → 여기에 Golden Sample, 기관 정보 모두 포함

STEP 5: 저장 및 테스트
  → 우측 상단 [저장] 클릭
  → 채팅창에 테스트 내용 입력 → 결과 확인

STEP 6: 팀 공유
  → Gem 화면 우측 상단 [공유] 클릭
  → 링크 복사 → 팀 단톡방에 공유
```

# 6. 실습 — 나만의 Gem 처음부터 직접 만들기 (25분)
> **실습 방식 안내**
완성된 지시문을 복붙하는 것이 아닙니다.<br>내 업무를 분석하고, ROPE+K 각 요소를 직접 채우고,<br>지시문을 완성한 뒤 Gemini에 등록해서 실제로 돌려보는<br>**처음부터 끝까지 직접 만드는** 실습입니다.
완성된 Gem은 오늘부터 실무에 바로 쓸 수 있습니다.
---
## STEP 1 \| 내 업무 발굴 — 무엇을 자동화할 것인가 (5분)
> Gem을 만들기 전에 먼저 "무엇을 만들지"를 결정해야 합니다.<br>아래 3가지 질문에 답하면서 자동화할 업무 1개를 고르세요.
---
### 질문 1 \| 내가 가장 자주 반복하는 문서 업무는?
> 아래 예시 목록을 보면서 내 업무와 가장 가까운 것에 체크하세요.<br>없으면 직접 쓰세요.
```plain text
공문·안내문 유형:
  □ 기업 지원사업 참가기업 모집 공문

  □ 월간·분기 KPI 실적 보고서

기타 반복 업무:
  □ 이메일·카카오 공지문 초안
  □ 만족도 조사 결과 요약
  □ 사업 기획서 초안
  □ 기타: ___________________________

  ____________________________________
```

## STEP 2 \| ROPE+K 워크시트 — 직접 채우기 (10분)
> STEP 1에서 고른 업무를 기준으로 아래 5개 칸을 채웁니다.<br>각 칸마다 **가이드라인**을 읽고 채우세요.<br>처음엔 어색해도 괜찮습니다. 완벽하지 않아도 됩니다.
---
### R \| Role — 이 Gem이 맡을 역할과 원칙
> **가이드라인**<br>"전문가야"처럼 막연하게 쓰면 효과가 없습니다.<br>아래 3가지를 모두 포함해야 합니다:<br>① 우리 기관 어느 부서의 어떤 담당자인지<br>② 그 업무를 얼마나, 어떤 방식으로 해왔는지<br>③ 결과물을 쓸 때 반드시 지키는 원칙이 무엇인지
```plain text
작성 전 체크:
  □ 기관명·부서명이 들어갔는가?
  □ 경력이나 전문성을 구체적으로 표현했는가?
  □ 어조·말투 기준을 넣었는가?
  □ "확인 안 된 내용은 작성 안 한다"는 원칙을 넣었는가?

나의 R 작성:
  너는 교육기관 33 ________ 에서
  __________________ 을(를) 수백 건 이상 작성해온
  __________________ 야.
  항상 __________________ 어조를 유지하고,
  __________________ 은(는) 절대 하지 않아.

작성 예시 (참고용):
  "너는 교육기관 33 기업지원부에서
   기업 지원사업 안내 공문과 모집 공고를 10년 이상
   작성해온 행정 전문 담당자야.
   충청북도 공공기관 표준 공문 양식을 완벽히 숙지하고 있으며,
   수치와 날짜는 반드시 내가 제공한 것만 사용하고,
   확인되지 않은 내용은 절대 임의로 작성하지 않아."
```
---
### O \| Objective — 이 Gem이 처리할 반복 업무
> **가이드라인**<br>"도와줘"처럼 막연한 목적은 안 됩니다.<br>"내가 ___를 주면, Gem이 ___를 출력한다"<br>이 문장 구조로 작성하세요.<br>출력물이 항상 몇 가지 버전인지도 정해두면 좋습니다.
```plain text
작성 전 체크:
  □ "내가 __를 주면" → 입력이 무엇인지 명시했는가?
  □ "Gem이 __를 출력한다" → 출력이 무엇인지 명시했는가?
  □ 버전 수(1개? 2개?)를 정했는가?

나의 O 작성:
  내가 __________________ 을(를) 알려주면
  즉시 __________________ 을(를) 생성해.
  매번 __________________ 와 __________________ 를 함께 제공해.

작성 예시 (참고용):
  "내가 사업명, 지원 내용, 신청 기간, 지원 대상, 문의처를
   알려주면 즉시 완성형 공문 초안을 생성해.
   매번 기업 대표 수신용과 실무 담당자 수신용
   두 가지 버전을 함께 제공해."
```
---
### P \| Process — 출력 순서와 형식을 고정한다
> **가이드라인**<br>P가 없으면 AI가 매번 다른 형식으로 출력합니다.<br>"결과물은 항상 이 순서로:" 라고 시작해서<br>번호 목록으로 출력 항목을 고정하세요.<br>표·목록·단락 등 형식도 지정해야 일관됩니다.
```plain text
작성 전 체크:
  □ "항상 이 순서로"라는 선언이 들어갔는가?
  □ 각 출력 항목을 번호로 나열했는가?
  □ 표·목록 등 형식을 지정했는가?
  □ 각 버전의 분량(A4 몇 장)을 정했는가?

나의 P 작성:
  결과물은 항상 다음 순서로 제공해:
  1. [__________________ ] (형식: __________, 분량: __________)
  2. [__________________ ] (형식: __________, 분량: __________)
  3. [__________________ ] (있는 경우만)

작성 예시 (참고용):
  "결과물은 항상 다음 순서로 제공해:
   1. [버전 1 - 기업 대표 수신용] (격식체, A4 1장)
      - 공고번호, 수신, 제목, 발신 기본 형식
      - 사업의 기대 효과 강조
   2. [버전 2 - 실무 담당자 수신용] (실용적, A4 1장)
      - 신청 절차를 번호 목록으로
   3. [검증 체크리스트]
      - [미기재] 항목 목록"
```
---
### E \| Example — 좋은 출력의 예시 1건
> **가이드라인**<br>예시가 있으면 없을 때보다 결과 품질이 크게 좋아집니다.<br>전부 쓸 필요는 없습니다.<br>첫 문단만, 또는 표 구조만 보여줘도 충분합니다.<br>"이 느낌으로 써줘"라는 기준점 역할입니다.
```plain text
작성 전 체크:
  □ 내가 실제로 만족했던 결과물 1건이 있는가?
  □ 없다면: 이상적인 결과의 첫 2~3줄이라도 직접 써볼 수 있는가?
  □ 분량이 너무 길면 K(Golden Sample)와 겹치므로 짧게 유지

나의 E 작성:
  좋은 __________________ 의 예시 (이 형식으로):
  ____________________________________
  ____________________________________

작성 예시 (참고용):
  "좋은 공문의 예시 (이 어조와 형식으로):
   충청북도 공고 제○○호
   2026년 글로벌강소기업 육성사업 참가기업 모집 공고
   교육기관 33장은 충북 소재 중소기업의 글로벌 역량
   강화를 위하여 다음과 같이 참가기업을 모집합니다."

  예시가 없어도 됩니다. 이 칸을 비워도 Gem은 작동합니다.
  단, 있으면 훨씬 더 정확한 결과가 나옵니다.
```
---
### K \| Knowledge — Gem이 영구 기억할 기관 정보
> **가이드라인**<br>K는 세 가지로 나뉩니다:<br>① 기관 기본 정보 (항상 포함)<br>② Golden Sample (문체 기준 문서, 있으면 포함)<br>③ 절대 금지 사항 (반드시 포함)
Golden Sample은 1부에서 배운 것과 동일합니다.<br>내 Gem이 맡을 업무와 같은 유형의 잘 쓴 문서 1건을<br>이 칸에 넣으세요.
```plain text
작성 전 체크:
  □ 기관명·주소·전화번호를 넣었는가?
  □ 내 부서에서 자주 다루는 사업 목록을 넣었는가?
  □ Golden Sample 문서를 넣었거나 표시했는가?
  □ "절대 금지 사항" 항목을 넣었는가?

나의 K 작성:

  [기관 기본 정보]
  기관명: 교육기관 33
  주소: 충북 청주시 흥덕구 풍산로 50, 1~3층
  대표번호: [연락처 비공개]
  내 부서: __________
  내 부서 주요 사업:
    ____________________
    ____________________
    ____________________

  [Golden Sample]
  아래 문서의 문체와 구성을 기준으로 출력해:
  → 오늘 강사가 단톡방에 공유한 충청북도 공고문 붙여넣기
    또는 내가 가진 기존 문서 1건 붙여넣기

  [절대 금지 사항]
  - 확인되지 않은 수치·날짜 임의 작성 금지
  - 내가 입력하지 않은 항목은 [미기재 - 담당자 입력 필요]로 표시
  - __________________________________________
```

```plain text
P: (STEP 2에서 작성한 P 내용)

E: (STEP 2에서 작성한 E 내용 — 없으면 이 줄 삭제)

K: (STEP 2에서 작성한 K 내용)
```

### 지시문 자가 점검 체크리스트
> Gemini에 붙여넣기 전, 아래를 확인하세요.
```plain text
□ R에 기관명·부서명·경력·원칙이 모두 들어갔는가?
□ O에 "내가 __를 주면 Gem이 __를 출력" 구조가 명확한가?
□ P에 출력 순서와 형식이 번호로 고정되어 있는가?
□ K에 기관 기본 정보와 절대 금지 사항이 들어갔는가?
□ Golden Sample을 K에 붙여넣었는가?
□ 지시문 어디에도 기밀 정보·개인정보가 없는가?

하나라도 빠졌다면 → 해당 칸으로 돌아가서 추가 후 진행
```

## STEP 4 \| Gemini에 Gem 등록하기 (3분)
```plain text
① gemini.google.com 접속 → 구글 계정 로그인
② 왼쪽 사이드바 → [Gem 탐색] 클릭
③ 우측 상단 [+ 새 Gem 만들기] 클릭
④ 이름 입력: STEP 1에서 정한 Gem 이름 그대로
⑤ 지시문 입력창에 STEP 3에서 완성한 지시문 전체 붙여넣기
⑥ [저장] 클릭
⑦ 왼쪽 사이드바 → 내 Gem 목록에서 방금 만든 Gem 확인
```

## STEP 5 \| 첫 테스트 — 실제 업무 내용으로 돌려보기 (4분)
> Gem을 클릭한 뒤, 오늘 실제로 처리해야 할 업무 내용을<br>아래 형식으로 입력해보세요.<br>(없으면 아래 제공된 테스트 케이스 중 하나를 사용하세요)
---
### 내 업무로 테스트하기
```plain text
[입력 형식 예시 — 내 업무에 맞게 수정해서 입력]

공문 비서 Gem 테스트:
  "사업명: [내 사업명]
   신청 기간: [기간]
   지원 대상: [대상]
   지원 내용: [내용]
   문의처: [연락처]
   위 내용으로 참가기업 모집 공문 만들어줘."

보고서 비서 Gem 테스트:
  "[1부 더미데이터 붙여넣기]
   위 데이터로 상반기 실적 보고서 만들어줘."

회의록 비서 Gem 테스트:
  "[Clova 녹취록 샘플 전문 붙여넣기]
   위 녹취록으로 회의록과 액션아이템 표 만들어줘."
```
---
### 테스트 결과 점검 — 결과가 나오면 이것을 확인하세요
```plain text
출력 형식 확인:
  □ P에서 정한 순서대로 출력됐는가?
  □ 정해둔 형식(표·목록 등)이 지켜졌는가?
  □ 분량이 P에서 정한 범위 안인가?

내용 정확성 확인:
  □ 내가 입력하지 않은 수치나 날짜를 만들어내지 않았는가?
  □ [미기재] 항목이 제대로 표시됐는가?
  □ K(Golden Sample)의 문체와 느낌이 비슷한가?

개선 필요 확인:
  □ 어색하거나 고치고 싶은 부분이 있는가?
     → 있으면 지시문으로 돌아가서 해당 칸 수정 → 저장 → 재테스트
```
---
### 지시문 개선 요령 — 결과가 마음에 안 들 때
```plain text
결과가 너무 길다
  → P에 분량 제한 추가
  예: "각 버전은 A4 1장을 넘지 않는다"

문체가 여전히 어색하다
  → K의 Golden Sample을 더 구체적인 문서로 교체
  예: 공고문 → 내가 직접 작성한 기존 공문 1건으로 교체

빠진 항목이 생긴다
  → P의 출력 항목 목록에 해당 항목 추가

AI가 임의로 수치를 만든다
  → C에 "확인되지 않은 수치는 절대 작성 금지" 추가
  → K의 절대 금지 사항에도 동일하게 추가
```

## 6-3. 결과 공유 & 피드백 (7분)
```plain text
2~3명 자원자가 화면을 공유하며 결과를 발표합니다.

공유할 것:
  1. 어떤 업무를 자동화하는 Gem을 만들었는지
  2. ROPE+K 중 가장 어려웠던 칸은 어디였는지
  3. 테스트 결과가 기대와 어떻게 달랐는지
  4. 개선하고 싶은 부분이 있다면

강사 피드백 포인트:
  □ R이 막연하지 않고 충분히 구체적인가?
  □ O의 입력-출력 구조가 명확한가?
  □ P에 출력 형식이 번호로 고정돼 있는가?
  □ K에 기관 정보와 금지 사항이 모두 들어갔는가?
  □ Golden Sample이 같은 문서 유형으로 선택됐는가?
```
