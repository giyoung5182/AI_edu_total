# 12분 실습 | 내 Gem 설정문 고도화하기

정리일: 2026-10-08 · 교육 에셋 N1081

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
모듈 05에서 만든 내 Gem 설정문을 가져와 CoT 자가진단 프롬프트로 약점을 찾고 개선판으로 고도화합니다.
## 진행 단계
1. **새 대화창을 열고 내 설정문을 붙여넣는다** — 05에서 못 만들었으면 부록 C 자료 3(약점을 일부러 넣어둔 설정문 초안)을 씁니다.
2. **자가진단 프롬프트를 붙여넣고 평가를 받는다**
- 입력할 내용:
```javascript
방금 만든 설정문의 약점을 스스로 찾아 주세요.
아래 기준으로 단계별로 평가해 주세요.

1단계  다섯 항목이 충분히 구체적인가?
        모호한 표현이 있으면 집어주세요.
2단계  이 설정문만 보고 매번 일관된 결과를 낼 수 있는가?
3단계  없는 정보를 지어낼 위험이 있는 부분은 어디인가?
        특히 금액·날짜·조항 번호 관련으로.
4단계  빠진 제약 조건이 있을 것 같은 부분은?
5단계  금융사 문서로서 분쟁 소지가 있는 표현을 허용하고 있지 않은가?

평가가 끝나면 개선된 버전을 보여주세요.
```
3. **개선판을 받아 원본과 비교한다**
- 규칙이 과하게 늘었으면: `핵심만 남기고 규칙을 다섯 줄 이내로 줄여줘`
4. **가상 상황을 줘보고 작동을 확인한다**
- 입력할 내용:
```javascript
완성된 설정문을 기준으로,
아래 상황이 들어왔다고 가정하고 실제로 작동해봐 주세요.

[상황: A딜러사 서류 미접수, 기한 안내 필요]
```
5. **Gem 편집으로 들어가 개선판으로 교체한다**
6. **최종본을 메모장에 다시 복사한다**
- 확인할 것: 메타 프롬프팅 설명 가능 / 자가진단으로 약점을 받아봄 / 개선판과 원본의 차이 설명 가능 / 개선판을 Gem에 반영하고 메모장에 복사함
## 막히는 지점
- 개선판을 무조건 받아들이지 마세요. AI가 규칙을 과하게 늘려놓는 경우가 있고, 규칙이 열 줄이 넘으면 중요한 게 묻힙니다.
