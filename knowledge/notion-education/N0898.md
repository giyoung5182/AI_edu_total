## 1. 체이닝 — 60%를 90%로
### 1-1. 왜 한 번에 안 되는가
1권 실습 3에서 나온 이미지는 60% 수준이었을 것임. 프롬프트를 못 써서가 아님.
머릿속 이미지와 실제로 쓸 수 있는 프롬프트 사이에는 간극이 있음. 이 간극은 프롬프트를 더 길게 써서 메울 수 없음. **여러 번에 나눠서 좁혀 들어가야 함.** 이것을 체이닝(Chaining)이라 함.
```plain text
1차 프롬프트 → 60%  (방향성 확인)
2차 프롬프트 → 75%  (재료·플레이팅 정교화)
3차 프롬프트 → 85%  (조명 정교화)
4차 프롬프트 → 90%+ (분위기 완성)
```
⚠️ **한 번에 너무 많이 바꾸면 AI가 방향을 잃음.** 한 번에 1\~2가지만 고침.
### 1-2. STYLE LOCK — 바꾸지 말 것을 먼저 못 박음
체이닝이 실패하는 가장 흔한 이유는 **고쳐달라고 한 것 말고 다른 것까지 바뀌기 때문**임.
AI는 이미지를 부분적으로 수정하는 것이 아니라 **원본을 참고해서 새로 그림.** 지키라고 말하지 않은 것은 지켜지지 않음.
> **원칙: 바꿀 것보다 "바꾸지 말 것"을 더 길게 씀.**
**STYLE LOCK 템플릿 — 모든 체이닝 프롬프트 맨 앞에 붙임**
```plain text
STYLE LOCK — 아래는 그대로 유지할 것:
- 구도와 앵글
- 그릇의 모양·색·위치
- 재료의 개수와 배치
- 배경, 테이블, 조명
- 이미지 전체의 크롭

내가 명시적으로 요청한 것만 바꿀 것. 나머지는 전부 동일하게.
```

### 1-5. 체이닝의 함정 — 실제로 써본 사람만 아는 것
**함정 1. 5회를 넘기면 오히려 나빠짐**
체이닝은 매번 이미지를 **다시 그리는** 작업임. 반복할수록 원본에서 조금씩 멀어지고, 질감이 뭉개지거나 디테일이 뭉툭해짐.
```plain text
대응
  마음에 드는 단계가 나오면 그 자리에서 저장할 것.
  "조금만 더"를 반복하다 이전 단계보다 나빠지는 경우가 자주 있음.
  AI에는 되돌리기(Undo)가 없음. 저장하지 않으면 사라짐.
```
⚠️ **매 단계마다 저장함.** 1차·2차·3차·4차를 전부 남김. 나중에 "3차가 더 나았다"는 판단이 자주 나옴.
**함정 2. 부정문은 잘 안 먹힘**
`"청양고추를 넣지 마"`라고 썼는데 오히려 고추가 나오는 경우가 있음. 이미지 생성 AI는 부정문 처리가 약함.
```plain text
권장
  ❶ 원하는 것을 긍정문으로 기술:
     "고명은 대파만 올릴 것" (고추 얘기를 아예 안 함)

  ❷ 반드시 빼야 하는 것은 [금지] 블록으로 분리:
     [금지] 청양고추, 깨, 참기름

  → 본문에 부정문을 섞지 말고, 금지 항목은 따로 모아둘 것


  고등어 김치찜에 고등어 조각 '2조각'으로 내주세요.
  [음식 조각 수] 고등어 김치찜 안에 있는 고등어 조각의 수: 2조각.
```
<br>

**함정 3. 새 채팅창을 열면 이미지 맥락이 사라짐**
같은 채팅창에서 이어가야 AI가 이전 이미지를 기억함. 새 창을 열면 이미지를 다시 업로드해야 하고, 그러면 미묘하게 톤이 달라짐.
```plain text
대응
  하나의 이미지 작업은 하나의 채팅창에서 끝낼 것.
  다음 이미지는 새 채팅창에서 시작 + 스타일 블록 재입력.
```
**함정 4. "왜 이렇게 나왔는지" AI에게 물어볼 수 있음**
방향이 잡히지 않을 때, AI에게 **자기 결과를 스스로 진단하게** 하면 막힌 지점이 풀리는 경우가 있음.
```plain text
내가 요청한 것과 결과 이미지 사이에 어떤 차이가 있어?
내 프롬프트에서 모호했던 부분을 3가지만 짚어주고,
어떻게 고치면 좋을지 수정된 프롬프트를 제안해줘.
```

### 실습 1. 체이닝으로 90%까지 (20분)
**목표:** 1권 실습 3에서 만든 이미지를 체이닝 3회로 완성함.
```plain text
[STEP 1] 같은 채팅창에서 이어감 (2분)
  ⚠️ 새 채팅창을 열지 말 것

[STEP 2] 2차 — 재료 정교화 (6분)
  1-3의 [2차] 템플릿을 본인 메뉴에 맞게 고쳐 입력
  ⚠️ 한 번에 1~2가지만
  ⚠️ 결과를 반드시 저장할 것

[STEP 3] 3차 — 조명 정교화 (6분)  → 저장

[STEP 4] 4차 — 분위기 완성 (6분)  → 저장

[STEP 5] 1차와 4차를 나란히 놓고 비교
```
💡 **STYLE LOCK을 빼고 한 번 해보는 것도 좋음.** <br>요청하지 않은 것까지 바뀌는 것을 직접 봐야 이 원칙이 와닿을 수 있어요.
**성공 기준:** 체이닝 3회로 결과가 확실히 달라졌음. 4단계를 전부 저장했음.

## 2. 마스터 프롬프트 — 매번 같은 톤이 나오게
### 2-1. 고정과 변수를 분리함
매번 결과가 달라지는 이유는 매번 프롬프트를 새로 쓰기 때문임.
```plain text
[스타일 블록]  고정. 한 번 만들면 계속 재사용
  브랜드 톤, 조명, 앵글, 색감, 배경, 질감, 금지 사항

[콘텐츠 블록]  변수. 이번에 만들 것만 바꿈
  메뉴명, 구성 재료, 개수, 상태
```
**스타일 블록 예시**
```plain text
[스타일 블록 — 고정]
브랜드: 돌담 제주흑돼지
분위기: 따뜻한 조명, 전통적이면서 정갈한 한식당
촬영: 45도 하이앵글, 얕은 심도, 자연광 느낌
배경: 어두운 우드 테이블, 소품 최소화
색감: 붉은 톤 강조, 채도는 과하지 않게
질감: 음식의 윤기와 김이 살아있게
금지: 텍스트 넣지 말 것. 로고 그리지 말 것.
      상단 1/3은 비워둘 것. 실물보다 과장하지 말 것.
```
**콘텐츠 블록 예시**
```plain text
[콘텐츠 블록 — 변수]
피사체: 고등어김치찜 1인분
구성: 고등어 2토막, 묵은지, 대파, 청양고추
그릇: 검은 무쇠 전골냄비
상태: 갓 끓여 김이 오르는 상태
```
### 2-2. 레퍼런스 세트 — 글보다 그림이 빠름
프롬프트를 아무리 잘 써도 글만으로는 톤이 흔들림. **참고 이미지를 함께 넣으면 일관성이 크게 올라감.**

```plain text
구글 드라이브
  └ 교육기관_브랜드에셋
      ├ 00_로고_서체        ← 로고 원본. AI가 그린 것 금지
      ├ 01_[브랜드명]
      │    ├ 음식컷 / 공간컷 / 판형컷
      ├ 02_[브랜드명]
      └ 99_완성물_아카이브   ← 오늘 만든 것을 여기 저장
```
💡 **99번 폴더가 다음번의 레퍼런스가 됨.** 완성물을 저장할 때 **프롬프트를 함께 저장할 것.** 이미지만 남기면 "이거 어떻게 만들었더라"가 반복됨.
⚠️ **확인 필요:** 브랜드별 로고 원본 파일(png/ai)과 지정 서체가 확보되어 있는지 확인 필요함.
### 2-3. 고급 기법 — 역방향 프롬프트 추출
마음에 드는 이미지가 있는데 그걸 말로 설명할 수 없을 때 쓰는 방법임. **이미지를 주고 프롬프트를 뽑아냄.**
```plain text
[gemini에 이미지 첨부 후]

이 음식 사진을 다른 AI로 재현하려고 해.
아래 항목으로 정확하게 분석해줘:

① 전체 컨셉 (한 문장)
② 조명: 색온도 추정(K), 방향, 그림자 특성
③ 구도: 앵글, 추정 렌즈, 심도
④ 색감: 주요 색상 3개 (HEX 코드)
⑤ 그릇·배경의 재질과 질감
⑥ 이 이미지를 재현할 수 있는 프롬프트 (6요소 구조로)

⚠️ 추정한 항목은 [추정]이라고 표시하고,
   확실하지 않은 것은 지어내지 말 것.
```
이렇게 뽑아낸 것이 **스타일 블록의 초안**이 됨. 기존에 잘 나온 우리 사진 3장을 이렇게 분석하면, 우리 브랜드의 톤이 무엇이었는지 언어로 정리됨.
💡 프로님이 이미 하고 있는 \*\*"레퍼런스 찾기"\*\*를 AI로 대체하는 것이 아니라, **찾은 레퍼런스를 언어로 번역하는** 단계임. 이게 있어야 다른 사람도 같은 톤으로 만들 수 있음.

AI가 숫자를 그림으로 그림 → 오타·왜곡 위험

텍스트는 빼고 미리캔버스에서 얹음




로고 지정이 없음

AI가 로고를 흉내 냄 → **최종 단계에서 로고 원본을 다시 덧입혀야 했음**

"로고 그리지 말 것" 명시


**실제 진행된 작업 흐름**
```plain text
1. 프롬프트 입력 → 주류 이미지 생성
2. 기네스·블랑은 적합 → 디테일 작업 진행
3. 테라는 무드 부적합 → 적합한 이미지를 다시 찾음
4. 테라 컨셉 사진 + 호프 맥주잔 결합 → 최종 테라 이미지
5. 최종 이미지에 로고 원본 추가 → 완성
```
💡 3\~5번이 전부 **AI가 한 번에 못 해서 사람이 메꾼 단계**임. 스타일 블록이 있었다면 3번이 없었고, 로고를 금지했다면 5번이 필요 없었음.

```plain text
[STEP 1] 역방향 추출로 초안 잡기 (5분)
```

```plain text
[STEP 3] 검증 (5분)

  ⚠️ 검증 기준은 "예쁜가"가 아니라 "두 장의 톤이 일치하는가"
  일치하지 않으면 스타일 블록에 빠진 항목이 있다는 뜻임
```
**성공 기준:** 서로 다른 메뉴 2장의 톤이 일치했음.

## 3. 프롬프트를 만들어주는 AI 만들기 (Gems)
### 3-1. 왜 이게 필요한가
스타일 블록을 매번 복사해서 붙여넣는 작업은 3주면 안 하게 됨. 6요소를 매번 손으로 채우는 것도 마찬가지임.
> **그래서 프롬프트를 대신 써주는 AI를 하나 만들어둠.**<br>우리가 하는 일은 **"김치찜, 소식탭"** 두 단어를 넣는 것뿐임.
⚠️ **이 Gem은 이미지를 만들지 않음. 오직 프롬프트 텍스트만 출력함.** 이미지 생성은 AI Studio에서 함. (Gemini 앱은 워터마크가 붙기 때문)
### 3-2. Gems란
Gemini에서 만들 수 있는 **나만의 전용 AI**임. 역할·지침·참고 자료를 미리 설정해두면, 그 설정이 매번 자동으로 적용됨.
```plain text
접속 경로
  gemini.google.com → 왼쪽 사이드바 → [Gem] 또는 [새 Gem]
```
⚠️ **확인 필요:** Gemini 화면 구성이 자주 바뀜. 메뉴 이름과 위치는 교육 당일 실제 화면으로 확인 후 진행함.

### 실습 3. 프롬프트 생성 Gem 만들기 (20분)
**목표:** 두 단어만 넣으면 완성된 프롬프트가 나오는 도구를 손에 넣음.
```plain text
[STEP 1] 새 Gem 생성 (2분)

이름: 교육기관 프롬프트 메이커
설명: 외식 이미지 프롬프트를 대신 써주는 AI
```
```plain text
[STEP 2] 지침 붙여넣기 (5분)
```
아래를 **지침(Instructions)** 칸에 그대로 붙여넣음.
```plain text
너는 외식 프랜차이즈의 이미지 프롬프트를 설계하는 전문가야.

■ 절대 규칙
- 너는 이미지를 만들지 않는다. 오직 프롬프트 '텍스트'만 출력한다.
- 확실하지 않은 정보를 지어내지 않는다.
  모르는 것은 [확인 필요]로 표시한다.
- 네가 임의로 추정한 항목은 [추정]이라고 표시한다.

■ 사용자가 주는 것
① 브랜드명  ② 메뉴명  ③ 용도 (소식탭 / 메뉴판 / POP / 인스타)
※ 이 세 가지만 받는다. 더 묻지 않는다.

■ 네가 할 일
1. 부족한 정보(구성 재료·개수·그릇·상태)를 상식적으로 추정해 채운다.
   추정한 항목에는 [추정] 표시를 붙인다.
2. 아래 형식으로 프롬프트를 출력한다.
3. 이어서 체이닝 2차·3차·4차 프롬프트도 함께 출력한다.
4. 모든 프롬프트는 복사하기 쉽게 코드블록으로 감싼다.

■ 출력 형식

[스타일 블록 — 고정]
브랜드 / 분위기 / 촬영(앵글·심도) / 배경 / 색감 / 질감

[콘텐츠 블록 — 변수]
피사체(메뉴명 + 1인분) / 구성 재료 / 개수 / 그릇 / 상태

[금지]  ← 아래 4개는 예외 없이 항상 포함한다
- 절대 니가 직접적으로 '이미지'를 자동 생성해주지 않는다. (원하는 분들은 추가하셔도 됩니다)
- 이미지에 텍스트를 넣지 말 것
- 로고를 그리지 말 것
- 실물보다 과장하지 말 것
- 글자가 들어갈 상단 1/3을 비워둘 것

[체이닝 2차] 재료·플레이팅 정교화 (STYLE LOCK 포함)
[체이닝 3차] 조명 정교화 (STYLE LOCK 포함)
[체이닝 4차] 분위기 완성 (STYLE LOCK 포함)

■ 필수 준수 사항
- 재료의 개수를 반드시 숫자로 명시한다 (예: 고등어 2토막)
- 조명은 색온도(K)로 지정한다
- 구도는 앵글과 렌즈(mm)로 지정한다
- 체이닝 프롬프트는 반드시 STYLE LOCK 문장으로 시작한다
- 용도에 따라 규격을 함께 제안한다
  (소식탭/인스타 = 정사각, 메뉴판/POP = A4 세로)
```
```plain text
[STEP 3] 지식 자료 업로드 (3분)
  브랜드 레퍼런스 이미지 3~5장 업로드
  ⚠️ 이 단계를 하면 톤 일관성이 크게 올라감
```
```plain text
[STEP 4] 테스트 (7분)
  Gem을 열고 딱 이렇게만 입력:

      돌담, 고등어김치찜, 소식탭

  → 완성된 프롬프트 + 체이닝 2·3·4차가 한 번에 나오는가?
  → [추정] 표시가 제대로 붙어 있는가?
```
```plain text
[STEP 5] 실전 확인 (3분)
  나온 프롬프트를 복사 → AI Studio에 붙여넣기 → 이미지 생성
  ⚠️ 실습 2에서 직접 만든 것과 품질을 비교해볼 것
```
**성공 기준:** 세 단어를 넣어 완성된 프롬프트가 나왔음. 그 프롬프트로 이미지가 생성됐음.
💡 이 Gem이 오늘 만드는 것 중 **가장 오래 쓰이는 자산**임. 교육이 끝나도 계속 씀. 팀원과 공유하면 팀 전체가 같은 톤으로 만들 수 있음.
⚠️ **Gem이 지어낸 정보를 그대로 믿지 말 것.** \[추정\] 표시가 붙은 항목은 반드시 실제 메뉴 구성과 대조함. 다음 4장에서 다룸.

## 4-4. Gem 만드는 4가지 방법
[원본 이미지 제외]

### 방법 1. 정석 — ROPE+K 빈칸 채우기
가장 기초적이고 탄탄한 방법입니다. ROPE+K 5가지 항목을 직접 논리적으로 채웁니다.
```plain text
언제 쓰는가:
- 내가 업무 프로세스를 명확히 알고 있을 때
- 정확한 결과물이 반복적으로 필요할 때
→ 예시: 홍보글 Gem, 리뷰 답변 Gem
```
### 방법 2. 역설계 — 황금알에서 거꾸로 (강력 추천)
잘 된 결과물을 AI에게 던져주고 "이거랑 똑같이 쓰는 기계를 만들어줘"라고 명령하는 가장 쉽고 강력한 방법입니다.
**마법의 주문:**
```plain text
이건 내가 쓴 최고의 [홍보글 / 리뷰 답변 / 공지문]이야.
[글 내용 붙여넣기]

이 글을 분석해서
1) 톤앤매너,
2) 글의 구조,
3) 문장 호흡을 추출해줘.

그리고, 앞으로 내가 어떤 상황을 던지든 무조건
이 글이랑 똑같은 스타일로 새 글을 작성해주는
시스템 프롬프트를 ROPE+K 형식으로 네가 직접 짜줘.
```
**역설계 실전 순서:**
```plain text
Step 1. 지금까지 쓴 글 중 가장 마음에 드는 것 1개 선택
         (홍보글, 리뷰 답변, 공지문 등)

Step 2. 마법의 주문 입력 + 글 붙여넣기

Step 3. AI가 생성한 시스템 프롬프트 확인
         → Gem "요청사항" 칸에 붙여넣기

Step 4. 다른 상황에 테스트 → 스타일 일치 여부 점검 → 미세 조정
```
### 방법 3. 메타 프롬프트 — AI가 AI를 만드는 방식
내가 어떤 업무를 하는지 설명하면 AI가 최적의 시스템 프롬프트를 스스로 짜주는 방식입니다.
```plain text
나는 은평구에서 순대국집을 운영하는 사장님이야.
주로 SNS 홍보글, 단골 감사 문자, 리뷰 답변을 자주 써야 해.
내 가게 특징은 30년 전통 육수이고, 주요 고객은 40~60대 동네 단골이야.

이 업무를 자동화할 수 있는 Gem을 만들고 싶어.
최적의 시스템 프롬프트를 ROPE+K 형식으로 직접 짜줘.
```
### 방법 4. 딥리서치 변환 — AI에게 먼저 공부시키기
내가 모르는 영역의 Gem을 만들 때 유용합니다. AI에게 먼저 검색을 시켜 정보를 수집하게 한 뒤, 그 지식으로 스스로 시스템 프롬프트를 짜게 하는 2단계 기법입니다.
```plain text
Step 1:
"소상공인이 SNS를 효과적으로 운영하는 방법과
 고객 응대 시 주의해야 할 점을 심층 분석해줘."

Step 2:
"딥리서치 내용을 바탕으로 소상공인 SNS 홍보 전문 Gem의
 시스템 프롬프트를 ROPE+K 형식으로 짜줘."
```

## 4. 할루시네이션 검수 — AI가 만들어낸 거짓말 잡아내기
### 4-1. 이미지에도 할루시네이션이 있음
텍스트 AI가 없는 사실을 지어내듯, 이미지 AI도 **없는 것을 그려냄.** 그런데 이미지는 그럴듯해 보여서 그냥 넘어가기 쉬움.
**실제로 자주 발생하는 것**





유형

예시




재료를 임의로 추가

우리 메뉴에 없는 깻잎·통깨·고추를 얹음




개수를 늘리거나 줄임

고등어 2토막이라고 했는데 4토막

### 4-2. 검수 체크리스트 — 내보내기 전에 반드시
```plain text
[실물 대조]

□ 젓가락·수저의 개수와 방향이 정상인가
□ 이미지 어딘가에 글자가 있는가 (있으면 실패 — 다시 생성)
□ 로고를 흉내 낸 것이 있는가 (있으면 지우고 원본을 얹음)

□ 인쇄용이라면 해상도가 충분한가
```
💡 **확대해서 볼 것.** 축소된 썸네일에서는 오류가 안 보임. 특히 손·젓가락·배경 글자는 100%로 확대해야 보임.
### 4-3. 이미지 검수도 AI에게 시킬 수 있음

```plain text
① 물리적으로 이상한 부분이 있는가 (손가락, 젓가락, 그림자, 반사)
② 이미지 안에 글자나 로고 비슷한 것이 있는가
③ 아래 실제 메뉴 구성과 다른 점이 있는가

[실제 메뉴 구성]

확실하지 않은 것은 "확인 필요"라고 답하고, 지어내지 말 것.
```
⚠️ **AI의 검수도 100% 신뢰하지 말 것.** 최종 판단은 사람이 함. AI는 1차 필터임.

## 5-2. (참고) 수정 유형 4가지
**유형 A — 메뉴 통째 교체**
```plain text
[수정 요청]
이 사진의 음식을 '고등어김치찜'으로 바꿀 것.
- 시래기를 묵은지로 교체
- 국물 색을 김치찜 특유의 붉은 톤으로

[유지 — 절대 바꾸지 말 것]
- 냄비, 테이블, 배경, 조명, 앵글
- 고등어 토막의 개수(2토막)와 위치
- 김이 오르는 상태
```
⚠️ 개수를 말하지 않으면 AI가 임의로 늘림. **메뉴판에 2토막인데 이미지가 4토막이면 매장에서 클레임이 들어옴.**
**유형 B — 재료 하나만 추가·교체**
가장 자주 발생하고, 가장 잘 실패하는 유형임. 요청은 작은데 결과물은 통째로 달라져서 옴.
```plain text
[수정 요청]
이 사진에 고사리 나물을 추가할 것.
등갈비 사이 빈 공간에 자연스럽게 얹을 것.

[유지 — 절대 바꾸지 말 것]
- 냄비의 모양, 색, 위치
- 등갈비의 개수와 배치
- 묵은지의 양과 위치
- 배경, 테이블, 조명, 색감
- 촬영 앵글과 구도
- 이미지 전체의 크롭
```
⚠️ **바꿀 것이 하나라면 유지할 것은 스무 개를 적어도 과하지 않음.**
**유형 C — 다른 이미지와 합성**
```plain text
[첨부 1] 미나리전 사진   ← 기준 이미지
[첨부 2] 호프 맥주잔 사진 ← 합성할 대상

[요청]
첨부 1의 우측 상단 빈 공간에 첨부 2의 맥주잔을 배치할 것.
- 첨부 2 맥주잔의 형태를 그대로 유지할 것
- 첨부 1의 조명 방향과 그림자에 맞출 것

[유지] 첨부 1의 미나리전, 접시, 배경, 앵글 전부
```
⚠️ **로고가 들어간 대상은 AI가 다시 그리면 반드시 망가짐.** 합성 결과의 로고가 어긋나면 AI로 더 시도하지 말고, 미리캔버스에서 로고 원본 파일을 얹을 것.
**유형 D — 폰 사진을 스튜디오 촬영컷으로**
```plain text
[요청]
이 사진을 전문 스튜디오에서 촬영한 푸드 사진처럼 만들 것.
- 조명: 부드러운 측광, 자연스러운 그림자
- 심도: 배경을 얕게 흐리게
- 화이트밸런스 보정, 노이즈 제거

[유지 — 절대 바꾸지 말 것]
- 음식의 종류, 개수, 크기, 배치
- 접시·그릇의 모양과 색
- 튀김옷의 질감과 소스의 양

[금지]
- 음식을 다시 그리지 말 것. 촬영 조건만 개선할 것
- 없던 가니시나 소품을 추가하지 말 것
```
💡 \*\*"음식을 다시 그리지 말 것"\*\*이 이 프롬프트의 핵심 문장임. 없으면 AI가 "더 맛있어 보이는 다른 치킨"을 그려버림.
### 5-3. 계절 변경 — 반복 업무 자동화
```plain text
[요청]
이 매장 외관 사진의 계절감을 '여름'으로 바꿀 것.
- 하늘을 맑고 푸르게
- 나무와 식재의 잎을 짙은 초록으로
- 햇빛을 밝고 강하게, 그림자를 선명하게

[유지 — 절대 바꾸지 말 것]
- 건물의 형태, 색, 창문 위치
- 간판의 위치와 글자 (간판은 손대지 말 것)
- 촬영 앵글과 구도
- 주변 건물과 도로
```
⚠️ **간판은 반드시 "손대지 말 것"으로 지정함.** AI가 간판을 다시 그리면 한글이 깨지거나 상호가 바뀜.
💡 계절 프롬프트 4개를 한 번 만들어 라이브러리에 저장 → 계속 재사용.
### 5-4. 실패 사례 — 한우 어슷썰기
한우 어슷썰기 사진을 AI로 작업했을 때, AI가 단면을 **사각형으로 인식**하거나 **어슷썰기 형태가 무너졌음.**
⚠️ **원인은 가설임.** 고기 슬라이스 사진의 대다수는 직각 단면이므로, AI가 고기를 다시 그릴 때 익숙한 직각 형태로 되돌아갈 가능성이 있음.
**핵심은 원인이 아니라 대응임.**
```plain text
[1차] 형태 유지를 명시적으로 걸어봄
    "고기의 썰린 각도와 단면 형태를 절대 바꾸지 말 것.
     비스듬한(사선) 단면을 그대로 유지할 것."

[2차] 요청을 분리함
    형태를 건드리는 작업을 포기하고 화질·조명만 개선
    → 고기를 다시 그리지 않으므로 형태가 유지됨

[3차] 부분만 처리함
    고기는 원본 그대로, 배경·접시만 AI로 개선 후 미리캔버스에서 합성

[4차] 포기함
    촬영을 요청하거나 다른 컷을 쓰는 것이 빠름
```
⚠️ **당일 재검증:** 위 사례는 2025년 작업임. 2026년 7월 현재 모델은 형태 유지 능력이 개선되었을 수 있음. 교육 당일 동일 사진으로 재시도함. **되면 되는 대로, 안 되면 안 되는 대로 사실 그대로 안내함.**

### 6-1. 하네스가 있는지 확인하는 방법
거창한 점검이 필요 없음. **질문 하나면 됨.**
> **"내가 내일 휴가를 가고, 다른 사람이 이 일을 대신한다면 같은 톤의 결과물이 나오는가?"**
```plain text
나온다  → 하네스가 있음
안 나온다 → 아직 개인의 감(感)에 의존하고 있음
```
**항목별로 점검함**
```plain text
□ 다른 사람이 브랜드 이미지를 어디서 찾을지 아는가        (① 자료)
□ 브랜드 톤이 문서로 적혀 있는가                          (② 지침)
□ 그 사람이 프롬프트를 처음부터 쓰지 않아도 되는가        (③ 도구)
□ 어떤 순서로 작업할지 적혀 있는가                        (④ 절차)
□ 결과물이 잘못됐는지 판단할 기준이 있는가                (⑤ 검토)
```
⚠️ 하나라도 비어 있으면 그 지점에서 **결과물이 사람마다 달라짐.** 지금까지 "매번 딴판"이었던 이유가 여기 있음.
### 6-2. 하네스는 계속 진화해야 함

### (참고)6-4. 하네스 다음 — 계속 돌리고 관리함
하네스를 갖추는 것은 **한 번 만드는 일**임. 그런데 진짜 어려운 것은 그다음임. **만들어둔 것을 계속 돌리고, 낡으면 고치는 것.**
**작업 자산은 쓸수록 낡음 (드리프트)**
오늘 만든 스타일 블록·Gem·템플릿을 **작업 자산**이라 부름. 한 번 쓰고 버리는 프롬프트와 달리, 판단 기준을 담아 계속 재사용되는 것들임.
⚠️ **문제는 이 자산이 시간이 지나면서 서서히 낡는다는 것임.** 이 현상을 드리프트(drift)라 함.
\`\`\`<br>드리프트의 예
- Gem 지침에 지난 시즌 메뉴가 그대로 남아 있음<br>→ 여름인데 겨울 메뉴 톤이 섞여 나옴
- 스타일 블록에 예전 로고 위치가 적혀 있음<br>→ 리뉴얼 후에도 옛날 배치로 만들어짐
- 체크리스트가 너무 길어져서 일부 항목을 아무도 안 봄<br>→ 검수가 형식만 남음
- 완성물 폴더에 실패작과 완성작이 섞여 있음<br>→ 다음 레퍼런스로 실패작을 집어옴<br>\`\`\`
⚠️ **드리프트가 생기면 "매번 딴판" 문제가 다시 돌아옴.** 이때 원인은 모델이 아니라 **관리되지 않은 자산**임. 새 모델을 찾을 게 아니라, 낡은 자산을 손봐야 함.
**그래서 자산도 주기적으로 점검함**
` [월 1회 자산 점검] <br>□ Gem 지침에 지난 시즌·옛 정보가 남아 있지 않은가 <br>□ 스타일 블록이 현재 브랜드와 맞는가 (로고·컬러·톤) <br>□ 체크리스트가 너무 길어지지 않았는가 (안 보는 항목은 지움) <br>□ 완성물 폴더에서 실패작을 걸러냈는가`
💡 **자산은 한 번 만들고 끝이 아니라, 화분처럼 계속 돌봐야 함.** 이 점검을 빠뜨리면 하네스가 서서히 무너짐.
**언제 멈출지 미리 정해둠 (종료 조건)**
체이닝이든 자동화든, **"언제 멈출 것인가"를 정하지 않으면 잘못된 작업을 빠르고 비싸게 반복함.**
AI 작업이 실패하는 이유는 모델 성능보다 **출구가 없어서**인 경우가 많음. 시작할 때 아래를 미리 정함.
\`\`\`<br>\[종료 조건 — 시작 전에 정함\]
성공하면 멈춤:  결과가 검수 체크리스트를 통과하면 끝<br>실패하면 멈춤:  같은 시도를 3번 했는데 나아지지 않으면 중단<br>→ 3-4 어슷썰기의 "20분 넘으면 손 뗀다"가 이것임<br>사람에게 넘김:  개수·가격·톤 판단이 애매하면 AI를 붙들지 말고<br>사람이 직접 결정<br>비용 한도:      무료 크레딧이 얼마 안 남았으면 아껴 씀<br>(특히 Flow 영상 — 4권)<br>\`\`\`
⚠️ **종료 조건이 없는 작업에는 큰 권한을 주지 않음.** 특히 자동화(4권)에서, "언제 멈추고 사람에게 넘길지"가 없는 흐름은 위험함. 잘못된 결과물이 자동으로 매장에 나갈 수 있기 때문임.
> **결국 AI를 가장 잘 쓰는 사람은,어떤 일을 반복 가능한 흐름으로 만들지,어떤 자산으로 그 흐름을 이끌지,그리고 어떤 판단을 끝까지 사람의 몫으로 남길지를 아는 사람!!!**
