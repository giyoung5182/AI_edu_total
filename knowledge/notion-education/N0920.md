# 9회차 리허설 가이드북 (강사용)
> **목적:** 9회차 수업 전, 강사가 0→1→2권 전 과정을 실제로 완주하며<br>막히는 지점·소요시간·오류를 미리 확보한다.<br>**결과물:** 이 문서의 기록란을 채우면 그대로 9회차 실행 플랜의 원재료가 된다.<br>**기준:** 2026년 7월
---
## 이 리허설을 하는 이유
```plain text
9회차는 5시간 안에 설치→연동→GitHub→Cursor→배포를 전부 넣습니다.
수강생 6명 전원이 GitHub·Cursor·Vercel을 처음 씁니다.

리허설 없이 들어가면:
  · 각 단계가 실제로 몇 분 걸리는지 모름 → 타임테이블이 추측이 됨
  · 어디서 막힐지 모름 → 현장에서 강사도 같이 헤맴
  · UI가 교재와 다를 때 즉시 대응 불가

리허설을 하면:
  · 실제 소요시간 확보 → 타임테이블 확정
  · 막힘 지점 사전 파악 → 교재에 미리 반영
  · 강사가 화면을 외우고 있으므로 순회 속도가 빨라짐
```
---
## 리허설 구성 — 2단계
```plain text
[1단계] B안 — 새 테스트 앱으로 전 과정 완주   ← 먼저 이것부터
  · 데이터 미연동 상태에서 시작 (프로님 상황과 동일)
  · 연동 → GitHub → Cursor → 배포까지 깨끗하게 한 바퀴
  · 예상 소요: 90~150분

[2단계] A안 — 프로님 Remix 사본으로 검증   ← 시간 되면
  · 22화면짜리 복잡한 앱에서도 같은 절차가 통하는지 확인
  · 이미 Lovable Cloud가 붙어있는 상태에서의 배포 검증
  · 예상 소요: 40~60분
```
> 💡 1단계를 먼저 하는 이유: 9회차 최대 난관이 "데이터 미연동 상태에서 연동 붙이기"인데, 프로님 사본은 이미 연동돼 있어 그 경험을 못 합니다. 프로님이 정확히 이 상태이므로 1단계가 더 중요합니다.
---
## 기록 원칙 (중요)
각 단계마다 아래 3가지를 반드시 적으세요. 이게 실행 플랜의 재료가 됩니다.
```plain text
① 실제 소요시간   — 시작·종료 시각을 적고 분 단위로
② 막힌 지점       — 헤맨 곳, 예상과 다른 UI, 오류 메시지
③ 수강생 예상 난이도 — 상/중/하 + 이유
```
> ⚠️ **교재와 화면이 다르면 그 자리에서 캡처하거나 메모하세요.** 도구 UI는 자주 바뀝니다. 리허설의 가장 큰 수확은 "교재를 최신 화면에 맞추는 것"입니다.

## 2-1. Lovable에서 테스트 앱 생성
**아래 프롬프트를 Lovable에 그대로 붙여넣으세요.**
