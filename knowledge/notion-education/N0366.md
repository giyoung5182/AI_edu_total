# 실습 1. 검색 비교 페이지 만들기

정리일: 2026-10-08 · 교육 에셋 N0366

본문 수집·공개 편집. 도구 실행·최신 기능 재검증은 미실시. 고객·참여자 정보와 개별 접근 링크, 원본 첨부는 제외했습니다.

---

## 이 실습으로 하는 것
키워드·의미·하이브리드 검색을 나란히 실행해 각 검색이 실패하는 질문을 직접 확인합니다.
## 진행 단계
1. **작업 시작 전** — 창②(Claude Code)에서 `/clear`를 실행합니다.
2. **Claude Code 프롬프트 입력** — 창②에 프롬프트를 입력하고 진행한 뒤 패키지를 설치합니다.
- 입력할 내용:
```javascript
지금 프로젝트에 검색 페이지를 추가해 주세요. 요구사항입니다.
1. /search 경로에 새 페이지를 만들고 상단 메뉴에 추가해 주세요.
2. 질문을 입력하면 세 가지 검색을 모두 실행합니다.
   - 키워드 검색: BM25. 형태소 분석기 kiwipiepy로 토큰화. 대상은 벡터DB에 적재된 청크 원문 전체.
   - 의미 검색: 벡터DB(ChromaDB) 유사도 검색.
   - 하이브리드 검색: 두 결과를 RRF 방식으로 결합.
3. 결과 화면은 [키워드 검색] [의미 검색] [하이브리드] 세 열로 나란히. 각 열에 상위 K개 청크 카드(순위, 점수, 청크 번호, 출처 문서명, 원문 미리보기).
4. K값은 입력칸에서 바꿀 수 있게. 기본값 3.
5. 서버 로그에 검색 한 건마다 세 검색의 1위 청크 번호가 한 줄로 출력되게.
6. 필요한 패키지 설치 명령을 알려 주세요.
(이하 교안 참고)
```
3. **서버 재시작** — 창①에서 서버를 재시작하고 /search 페이지를 엽니다.
4. **질문 A** — "AED 사용 순서 알려줘" 입력. \[예측\] 세 열 중 어느 검색이 1위에 가장 정확한 청크를 올릴지 적습니다.
5. **확인** — 세 열의 1위 카드를 펼쳐 원문을 읽고 비교합니다.
6. **질문 B** — "옆 사람이 목에 뭐가 걸려서 숨을 못 쉬어요" 입력. \[예측\] 어느 검색이 이길지 적고, 키워드 열과 의미 열의 순위를 비교합니다.
7. **하이브리드 확인** — 두 질문 모두에서 하이브리드 열이 정확한 청크를 상위에 올렸는지 확인합니다.
8. **자유 질문** — 두세 개 던져 보고 세 열의 차이를 관찰합니다.
## 막히는 지점
- 검색 결과가 세 열 모두 비어 있음: 벡터DB가 비어 있음. 문서 처리 페이지의 적재 현황 확인, 0개면 다시 적재.
- 키워드 검색 열만 결과 이상: 형태소 분석기 미적용. 창②에 "BM25 토큰화에 kiwipiepy가 쓰이고 있는지 확인해 주세요"라고 요청.
- 형태소 분석기 설치 실패: 창②에 오류 로그를 붙여넣고 해결 요청. 늦어지면 강사에게 알림.
- 점수가 열마다 자릿수가 다름: 정상. BM25 점수와 유사도 점수는 범위가 달라 열 안의 순위만 비교.
