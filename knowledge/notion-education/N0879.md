## 4.0 마지막 주 — "배운 사람"에서 "가르칠 수 있는 사람"으로
1주차에 AI를 처음 이해했고, 2주차에 프롬프트와 에이전트를 만들었고, 3주차에 콘텐츠를 완성했습니다. 오늘은 그 모든 것을 "남에게 가르치는 능력"으로 전환하는 날입니다.
배우는 것과 가르치는 것은 완전히 다른 능력입니다.
```plain text
배운 사람:    AI를 쓸 줄 안다
가르치는 사람: AI를 모르는 사람의 눈으로 세상을 볼 수 있다
```
오늘 세 가지를 가져갑니다.
1. **피드백** — 내 5분 시연이 어땠는지, 무엇을 더 다듬을지
2. **심화 교수법** — 3주차에서 다룬 7원칙 위에 더 얹는 것들
3. **강의자료 제작법 + 꿀팁** — 현장에서 바로 쓸 수 있는 것들
### 오늘의 약속
> 오늘 끝나고 나면 각자 완성된 "강사 키트" 하나를 갖게 됩니다.<br>교안 · 시연 대본 · PPT · 프롬프트 라이브러리 · 현장 체크리스트.<br>이 다섯 가지가 갖춰지면, 언제든 강의장에 설 수 있습니다.

### 발표자에게 — 시연 전 마음가짐
발표 전 긴장을 느끼는 게 정상입니다. 오히려 긴장이 없다면 준비가 부족한 것일 수 있어요. 다만 한 가지만 기억하세요.
> **오늘 발표의 목적은 "완벽하게"가 아니라 "끝까지 해보는" 것입니다.**
60점짜리 발표를 끝까지 한 사람이, 80점짜리를 준비하다 못 한 사람보다 훨씬 빠르게 성장합니다. 체이닝처럼, 강의도 반복하면서 올라갑니다.
### 청중(동료 강사)에게 — 듣는 법
발표를 들을 때 아래 두 가지 관점으로 봐주세요.
```plain text
① 내가 수강생이라면: 이 강의를 듣고 AI를 써보고 싶어졌나?
② 내가 강사라면:     나라면 어떻게 다르게 했을까?
```
이 두 관점을 가지고 들으면, 피드백이 훨씬 구체적으로 나옵니다.

## 4.2 피드백 구조 — 칭찬 하나, 제안 하나, 질문 하나
좋은 피드백은 "잘했어요 / 못했어요"가 아닙니다. **더 나아지게 돕는 구체적인 말**입니다.
### 피드백 3단 구조 (동료 피드백용)
모든 피드백을 이 순서로 합니다.
```plain text
① 칭찬 하나 — 구체적으로. "전달력이 좋았어요"가 아니라
   "AI를 신입 직원에 비유한 게 바로 이해됐어요."

② 제안 하나 — 부드럽게. "이건 틀렸어요"가 아니라
   "Before/After 비교를 화면에 보여줬으면 더 강했을 것 같아요."

③ 질문 하나 — 발표자가 스스로 생각하게.
   "청중이 직접 입력해볼 시간을 주셨는데,
    그 순간 청중 반응은 어떨 것 같으셨어요?"
```

## 4.3 자주 나오는 발표 패턴과 처방
실제 발표에서 반복적으로 나오는 패턴입니다. 강사는 이를 알고 있어야 그 자리에서 바로 도울 수 있습니다.
### 패턴 1 — "잘 아는데 못 가르치는" 함정
가장 흔한 패턴. AI를 잘 아는 사람일수록 수강생 입장을 잊습니다.
```plain text
증상: 용어를 자연스럽게 쓴다. "LLM이", "컨텍스트가", "토큰이"...
      본인은 자연스럽지만 청중은 첫 문장부터 막힌다.

처방: 5분 강의를 녹화하고 "나는 AI를 전혀 모르는 사람"으로
      다시 들어본다. 이해 안 되는 단어가 나오면 전부 바꾼다.
```
### 패턴 2 — "설명만 하고 보여주지 않는" 강의
```plain text
증상: 말로 15분을 설명했는데, 화면에선 아무것도 일어나지 않았다.
처방: "이걸 설명할 때 화면에서 무언가를 보여줄 수 있는가?"
      항상 이 질문을 던진다. AI 강의에서 시연 없는 설명은 반쪽짜리.
```
### 패턴 3 — 시연이 막혔을 때 패닉
```plain text
증상: AI가 예상과 다른 답을 냈을 때 당황해서 말이 막힌다.
처방: 이 문장 하나를 외운다.
      "오, 이렇게 나왔네요. 이게 바로 환각입니다.
       이럴 때 강사는 이렇게 대응합니다."
      → 실패가 가장 생생한 교육 자료가 된다는 것을 기억.
```
### 패턴 4 — "시간을 못 지키는" 강의
```plain text
증상: 5분 시연인데 10분이 지났다. 중요한 내용만 하려다 다 했다.
처방: 리허설을 타이머 켜고 반드시 한다.
      "이 내용 없어도 청중이 하나를 가져갈 수 있는가?"로
      매 슬라이드를 걸러낸다. 5분은 슬라이드 최대 5장.
```
### 패턴 5 — "결론이 없는" 강의
```plain text
증상: 내용은 다 맞는데 끝나고 나서 "그래서 내가 뭘 해야 하지?"가 남는다.
처방: 마지막 슬라이드를 "오늘 집에서 딱 하나만"으로 고정한다.
      구체적인 행동 하나가 없으면 강의는 기억에서 사라진다.
```

## (복습) 3.10 AI 교수법 — 비전공 청중을 가르치는 기술
> 이 섹션이 3주차의 진짜 핵심입니다. 도구를 아는 것과, 모르는 사람에게 가르치는 것은 완전히 다른 능력입니다. 강사는 그 두 번째를 갖춰야 합니다.
### AI 교육이 일반 강의와 다른 이유
일반 강의는 "모르는 것을 알게" 합니다. AI 교육은 여기에 두 가지가 더 붙습니다.
```plain text
일반 강의: 모름 → 앎
AI 교육:   두려움 → 안심
           불신   → 신뢰
           앎     → 직접 해봄
```
청중은 AI를 배우러 오지만, 실제로는 **세 가지 감정** 중 하나를 품고 옵니다.





감정

유형

표현 방식




두려움

"AI가 내 일자리를 뺏지 않을까?"

질문을 안 하고 팔짱을 낀다




불신

"AI가 틀린 말도 한다던데, 믿을 수 있나?"

날카로운 반박 질문




과한 기대

"AI가 다 해주겠지?"

나중에 실망하고 떠남


이 세 가지를 다루지 않으면, 아무리 좋은 기능을 가르쳐도 수강생이 집에 가서 쓰지 않습니다.
### 세 가지 감정을 다루는 법
**① 두려움 → "AI는 대체제가 아니라 도구"**
```plain text
❌ 하면 안 되는 말:
"AI가 이 정도를 할 수 있게 됐으니, 앞으로 많은 일이 자동화됩니다."
→ 두려움이 커짐.

✅ 이렇게 말하세요:
"AI가 반복 작업의 80%를 가져가면, 여러분은 나머지 20%의
 판단·창의·책임에 더 집중하게 됩니다. 그게 AI를 잘 쓰는 사람과
 못 쓰는 사람의 차이입니다."
```
**② 불신 → "한계를 먼저 솔직하게"**
```plain text
❌ 하면 안 되는 말:
"AI는 정말 놀라운 기술이에요! 못 하는 게 없어요."
→ 나중에 틀린 답이 나오면 강사 신뢰가 무너짐.

✅ 이렇게 말하세요:
"AI는 가끔 틀린 내용을 자신 있게 말합니다. 환각이라고 해요.
 그래서 사람이 마지막에 꼭 확인해야 합니다. AI는 초안 작성자,
 사람은 최종 판단자 — 이 역할 분담이 AI를 안전하게 쓰는 법입니다."
→ 한계를 먼저 말하면 오히려 신뢰가 올라갑니다.
```
**③ 과한 기대 → "Quick Win으로 현실 조율"**
```plain text
❌ 하면 안 되는 말:
"AI 쓰면 업무가 다 자동화됩니다."
→ 기대치가 너무 높아짐. 나중에 "생각보다 별로네"로 이탈.

✅ 이렇게 말하세요:
"오늘 끝나면 이 하나만 가져가세요 — 지금 30분 걸리는 이 작업,
 3분으로 줄이는 것. 그것 하나면 충분합니다."
→ 작은 성공(Quick Win)이 습관을 만들고, 습관이 AI 활용 문화를 만듭니다.
```

## 3.11 교수법 원칙 7가지 — 강사 필수 암기
### 원칙 1 · 용어를 일상어로 바꾼다





AI 용어

강의에서 쓸 말




프롬프트

"AI에게 하는 말", "부탁하는 방법"




환각(Hallucination)

"AI가 가끔 지어내는 것"




토큰

"AI가 읽는 글자 단위" (숫자 외우게 하지 말 것)




컨텍스트 윈도우

"AI의 작업 기억 한계"




에이전트

"맞춤 전용 비서"




RCTC+K

약자를 외우게 하지 말고 "5가지로 구체적으로"로




시스템 프롬프트

"비서한테 미리 교육해두는 것"




메타 프롬프팅

"AI한테 AI 지시문을 만들어달라고 하는 것"


> 규칙: **용어는 강사가 알고, 청중에게는 비유를 준다.**
### 원칙 2 · 비유를 먼저, 개념을 나중에
설명 순서가 거꾸로 되면 청중이 닫힙니다.
```plain text
❌ 잘못된 순서:
"LLM은 대규모 언어 모델로, 확률 기반 토큰 예측을 통해..."
→ 첫 문장에서 청중의 절반이 포기.

✅ 올바른 순서:
"AI는 세상의 책을 엄청 많이 읽은 사람이, 다음에 올 말을 잘 맞히게
 된 거예요. 정답을 외운 게 아니라 패턴을 익힌 거죠."
→ 비유로 직관을 준 뒤 개념을 설명.
```
### 원칙 3 · 개념 → 시연 → 체험의 3단 구조
강의의 모든 파트를 이 순서로 진행합니다.
```plain text
① 개념 (5분): 왜 이게 중요한지, 비유로
② 시연 (5분): 강사가 화면에서 직접 보여주기
③ 체험 (10분): 수강생이 손으로 직접 해보기

→ ③이 없으면 기억에 남지 않습니다.
   "들었다"와 "해봤다"는 전혀 다른 기억입니다.
```
### 원칙 4 · "왜"를 먼저, "어떻게"는 나중에
청중이 "왜 이걸 배우지?"를 느끼면 집중이 끊깁니다.
```plain text
❌ "오늘은 RCTC+K를 배우겠습니다."
→ "그게 뭔데?"

✅ "AI한테 뭔가 시켰는데 결과가 별로였던 적 있으시죠?
   그 이유가 오늘 3분 안에 풀립니다."
→ 이유가 생기면 집중이 생깁니다.
```
### 원칙 5 · 라이브 시연은 "실패"도 교육이다
시연 중 AI가 엉뚱한 답을 내는 경우가 반드시 생깁니다. 이걸 두려워하지 마세요.
```plain text
❌ 실패했을 때 당황하거나 서두르면
→ 청중이 "강사도 모르는 거 아닌가?" 불신

✅ 실패했을 때 이렇게 말하면
"오, 이렇게 나왔네요. 이게 바로 환각입니다.
 실제 강의에서도 이런 일이 생기고, 이럴 때 이렇게 대응하면 됩니다."
→ 실패가 가장 생생한 교육 자료가 됩니다.
```
### 원칙 6 · 청중이 직접 입력하게 만든다
듣기만 하면 3일 뒤 잊습니다. 손이 기억해야 합니다.
```plain text
"자 이제 여러분도 해보세요. 지금 ChatGPT(또는 교육기관 20) 열고,
 아까 제가 보여드린 프롬프트에서 【 】 부분만 본인 상황으로 바꿔서
 넣어보세요. 3분 드릴게요."
```
> 손 한 번 움직인 경험이, 1시간 강의보다 강합니다.
### 원칙 7 · 마무리는 항상 "다음 한 걸음"으로
강의 끝에 "오늘 배운 걸 정리하면..." 대신, 집에 가서 바로 할 수 있는 것 하나를 줍니다.
```plain text
❌ "오늘 RCTC+K, 에이전트, 이미지 생성, 워크플로우를 배웠습니다."
→ 많이 배웠는데 정작 뭘 해야 할지 모름.

✅ "오늘 집 가시면 딱 이것 하나만 해보세요.
   지금 제일 귀찮은 반복 업무 하나에 RCTC+K 써서 AI에게 시켜보기.
   15분이면 됩니다."
→ 구체적인 다음 행동이 습관의 씨앗이 됩니다.
```

## 3.13 결과물 검수 & 저작권
**검수 3원칙**
- 정보(수치·사실)는 원본과 대조 — 특히 건강·법·가격 정보
- 맞춤법·브랜드 톤·금지 표현 최종 확인
- AI = 초안, 사람 = 최종 판단
**저작권 핵심 (강의에서 반드시 짚을 것)**
- AI 생성 이미지의 상업 사용 조건은 도구마다 다름 → 약관 확인 필수
- 가장 안전: Adobe Firefly (Adobe가 상업 면책 보장)
- 실존 인물·로고·저작물을 따라 만든 이미지는 위험
- **"이 내용이 외부에 노출되어도 괜찮은가?"** — AI에 뭔가를 넣기 전 이 질문 한 번
---

3주차에서 교수법 7원칙을 배웠습니다. 이번엔 강의 전체를 설계하는 더 큰 원리를 다룹니다.
### 조기 수렴(Early Convergence) — AI 강의가 실패하는 구조적 이유
막스플랑크 연구소(2026)가 밝혀낸 AI 활용의 결정적 함정입니다. AI를 처음 쓰는 사람들은 대부분 이렇게 합니다.
```plain text
질문 입력 → AI가 답 줌 → "오 됐다" → 그대로 씀

→ 이것이 조기 수렴(Early Convergence).
  첫 번째 AI 출력에 갇혀버리는 것.
  탐색을 멈추고 너무 일찍 수렴한다.
```
이 연구에서 AI와 대화하며 **발산(탐색) → 수렴(정제)** 방식을 쓴 사람은, AI를 단순히 쓴 사람보다 결과물의 참신성과 다양성이 33% 더 높았습니다.
### 강의 설계에 적용하기 — 발산·수렴 2단계
```plain text
[발산 단계] — 먼저 넓게 탐색한다
  "AI로 어떤 게 가능할지 일단 다 보여드릴게요."
  여러 방향, 여러 결과를 경험시킨다.
  청중이 스스로 "나한테는 이게 맞겠다"를 발견하게.

[수렴 단계] — 선택한 방향을 깊게 정교화한다
  "고르셨으면, 이제 그걸 90%로 올려봅시다."
  체이닝, 메타 프롬프팅, 피드백 반복.
  하나를 완성까지 가져가는 경험.
```
> 강사 포인트: 강의 전체를 이 구조로 짜면 청중이 "많이 배웠다"가 아니라 "진짜 내 것이 생겼다"를 느낍니다. 그리고 그 경험이 다음에 스스로 써보게 만드는 동력이 됩니다.
### 90분 강의 발산·수렴 설계 템플릿
```plain text
[0–15분]  도입·공감 (발산 준비)
  → 청중의 페인포인트 꺼내기
  → "오늘 이 하나가 해결됩니다" 약속

[15–45분] 발산 — 가능성을 넓게 보여주기
  → AI로 할 수 있는 것들 빠르게 시연
  → 청중이 "오!" 하는 순간들을 만들기
  → 직접 따라 해보는 짧은 체험

[45–75분] 수렴 — 하나를 완성까지
  → 청중이 고른 하나를 함께 정교화
  → 프롬프트 고치기, 체이닝, 에이전트화
  → 완성품이 손에 남게

[75–90분] 마무리
  → 오늘 만든 것 정리
  → "집에서 할 것 하나"
  → Q&A
```

## 4.5 청중 타입별 강의 전략
같은 주제도 청중이 누구냐에 따라 강의 설계가 달라집니다.
### 타입 1 — AI 처음 접하는 분 (완전 입문)
```plain text
목표: 두려움 없애기. 딱 하나 직접 해보게 하기.
전략:
  - 전문용어 0개. 비유만.
  - 첫 5분 안에 손이 움직이게.
  - "못 해도 괜찮아요" 반복.
  - 완성보다 시작 경험이 목표.
피해야 할 것: 많은 기능 보여주기. 청중 압도됨.
```
### 타입 2 — AI 써봤지만 결과가 별로 (중간)
```plain text
목표: "AI가 별로인 게 아니라 제대로 안 시킨 것"을 깨닫게.
전략:
  - Before/After 비교가 핵심.
  - RCTC+K로 같은 질문을 두 번.
  - "왜 차이가 났는지"를 청중이 스스로 말하게.
피해야 할 것: 처음부터 "이렇게 해야 해요" 정답 제시. 탐색 기회를 빼앗음.
```
### 타입 3 — AI 잘 쓰는데 더 잘 쓰고 싶다 (심화)
```plain text
목표: 에이전트·워크플로우·메타 프롬프팅으로 업그레이드.
전략:
  - 이론 짧게, 실습 길게.
  - 강사가 배우는 자세로 함께 탐색.
  - "이 경우는 어떻게 해야 할까요?" 질문을 청중에게 되돌리기.
피해야 할 것: 기초 반복. 이미 아는 것을 가르치면 바로 집중 끊김.
```
### 혼합 청중일 때 — 가장 흔한 현장 상황
```plain text
실제 현장은 타입 1~3이 한 교실에 섞여 있습니다.
이때 쓰는 전략:

① 자가 진단으로 시작: "AI 얼마나 써보셨어요?"로 현재 위치 파악
② 공통분모로 진행: 모두가 "오!" 할 수 있는 Before/After 시연
③ 심화는 선택으로: "더 해보고 싶은 분은 이걸 해보세요"로 분기
④ 마무리는 같이: 누구나 가져갈 수 있는 "다음 한 걸음 하나"
```

## 4.6 돌발 상황 대응 — 현장에서 생기는 일들
어떤 강의도 계획대로만 되지 않습니다. 아래를 미리 알고 가면 당황하지 않습니다.
### 상황 1 — AI가 엉뚱한 답을 냈을 때
```plain text
당황하지 말고 이렇게:
"오, 이렇게 나왔네요. 이게 바로 환각입니다.
 AI는 모를 때 '모른다'고 안 하고 그럴듯하게 지어내요.
 그래서 사람이 꼭 검수해야 한다는 거 오늘 직접 보셨죠?"
→ 실패가 가장 생생한 교육 자료.
```
### 상황 2 — "그거 ChatGPT로도 되지 않나요?"
```plain text
이 질문은 적대가 아니라 관심의 표현입니다.
"맞아요. ChatGPT로도 됩니다. 도구마다 강점이 달라서,
 오늘 배우는 원리(RCTC+K, 체이닝)는 어떤 도구에서도 똑같이 써요.
 도구가 바뀌어도 원리는 남습니다."
→ 질문자를 적군이 아니라 앰배서더로 만드는 순간.
```
### 상황 3 — 인터넷이 끊겼을 때
```plain text
라이브 시연 불가. 이때:
① 미리 준비한 스크린샷/영상으로 대체
② "이럴 때 강사는 이렇게 합니다" 하고 상황 자체를 교육으로
③ 오프라인 활동으로 전환: "옆 분과 5분 동안 어떤 업무에 AI를 쓸지 얘기해보세요"
→ 백업 스크린샷 5장 + 짧은 영상 클립은 항상 준비해두세요.
```
### 상황 4 — "AI가 내 일자리를 뺏지 않을까요?"
```plain text
이 질문은 절반의 청중이 속으로 품고 있는 것입니다.
직접 나왔을 때가 오히려 기회입니다.

"정말 중요한 질문이에요. 솔직하게 말씀드리면,
 일부 반복 업무는 줄어들 겁니다. 하지만 그 빈 시간에
 더 가치 있는 일을 할 수 있는 사람과, 그냥 불안해하는 사람의
 차이가 생길 거예요. 오늘 여기 계신 분들은 전자를 선택하신 거고요."
→ 회피하지 않고 정직하게 답하는 것이 신뢰를 만듭니다.
```
### 상황 5 — 질문이 너무 어렵거나 모를 때
```plain text
모르는 것을 아는 척하지 마세요. 신뢰가 한 번에 무너집니다.

"좋은 질문이에요. 솔직히 저도 확실하지 않아서
 강의 후에 찾아보고 알려드릴게요. 이런 게 궁금하다는 게
 AI를 제대로 보고 계신다는 거예요."
→ "모릅니다"를 자연스럽게 말하는 것 자체가 강의 신뢰를 높입니다.
   (1주차에서 배운 정직성 원칙 — 강사에게도 적용됩니다.)
```

## 4.7 시간 관리 — 5분·30분·90분 각각의 법칙
### 5분 강의 (오늘 시연)
```plain text
구조: 도입(30초) → 핵심 1가지(3분) → 마무리(1분 30초)
원칙: 내용은 1가지만. 하나를 확실히.
흔한 실수: 3가지를 넣으려다 아무것도 못 함.
```
### 30분 강의 (짧은 특강)
```plain text
구조: 공감(5분) → 시연(15분) → 체험(5분) → 마무리(5분)
원칙: 시연에 절반을 쓴다. 설명은 최소.
흔한 실수: 설명에 25분 쓰고 체험 5분으로 압축.
```
### 90분 강의 (정규 강의)
```plain text
구조: 발산(45분) → 수렴(30분) → 마무리(15분)
원칙: 중간에 반드시 손 움직이는 시간 2회 이상.
흔한 실수: 한 방향으로만 달려가다 청중이 지침.
팁: 45분마다 "5분 휴식 + 옆 사람과 지금까지 한 것 공유"
```

## 4.8 AI 교육 강의자료 만드는 법
이제 강의 내용을 가르쳤다면, 그 내용을 담을 자료를 어떻게 만드는지입니다. AI를 쓰면 자료 제작 시간이 80% 줄어듭니다.
### PPT 설계 원칙 — 슬라이드를 만들기 전에
좋은 PPT를 만들려면 먼저 "교안(강의 흐름)"이 있어야 합니다. 교안 없이 슬라이드부터 만들면 구조가 무너집니다.
```plain text
순서:
1단계: 강의 흐름(교안) 먼저 — 무엇을 어떤 순서로
2단계: 각 단계별 핵심 메시지 1개씩
3단계: 그 메시지를 시각화하는 슬라이드
```
### 슬라이드 1장 = 메시지 1개
가장 많이 무너지는 원칙. 슬라이드에 3가지를 넣으면 청중은 0가지를 기억합니다.
```plain text
❌ 슬라이드 하나에:
  - AI란 무엇인가
  - 왜 지금 AI인가
  - AI의 종류
  → 청중이 어디를 봐야 할지 모름.

✅ 슬라이드 하나에:
  "AI는 많이 읽은 사람이 다음 말을 잘 맞히는 것"
  → 이 한 줄이 슬라이드 전체. 나머지는 강사의 입.
```
### AI로 강의자료 만들기 — 단계별
**1단계: 교안(강의 흐름) 초안**
```plain text
나는 【대상】에게 【주제】를 가르치는 【시간】 강의를 준비 중이야.
아래 조건으로 강의 흐름(교안)을 만들어줘.

조건:
- 발산(가능성 탐색) 50% + 수렴(하나 완성) 30% + 마무리 20%
- 각 단계별 핵심 메시지 1개
- 청중이 직접 손 움직이는 시간 2회 이상 포함
- 전문용어 없이
```
**2단계: 슬라이드 문구 생성**
```plain text
위 교안 【N】번째 단계를 슬라이드 1장으로 만들려고 해.
조건:
- 헤드라인: 청중이 "오!" 할 수 있는 1줄 (15자 이내)
- 서브: 헤드라인을 뒷받침하는 2줄
- 강사 멘트: 이 슬라이드에서 강사가 할 말 3문장
- 전문용어 금지
```
**3단계: Before/After 비교 시연 스크립트**
```plain text
아래 AI 활용 상황을 Before/After로 비교하는 시연 스크립트를 써줘.

Before: 【청중이 지금 하는 방식】
After: 【AI로 바꿨을 때】

조건:
- 강사가 말하는 멘트 포함
- 화면에서 어떻게 보여줄지 포함
- 3분 이내
```
**4단계: Q&A 예상 질문·답변집**
```plain text
【주제】 강의에서 청중이 자주 하는 질문 10개와
강사 답변(2~3문장)을 만들어줘.
어렵거나 답하기 곤란한 질문도 포함해줘.
```

## 4.9 프롬프트 라이브러리 구축 — 강사의 영구 자산
강의를 반복할수록 "잘 통하는 프롬프트"가 쌓입니다. 이걸 정리해두면 강의 준비 시간이 점점 줄어듭니다.
### 라이브러리 구조
```plain text
강사 프롬프트 라이브러리
│
├─ 교안 제작
│   ├─ 기본 교안 생성 프롬프트
│   ├─ 슬라이드 문구 생성 프롬프트
│   └─ Q&A 예상 질문 생성 프롬프트
│
├─ 시연 자료
│   ├─ Before/After 비교 스크립트
│   ├─ 직군별 시연 예시 모음
│   └─ 연령별 화법 가이드
│
├─ 청중 반응 대응
│   ├─ 돌발 질문 답변 템플릿
│   ├─ 시연 실패 시 멘트
│   └─ 감정 타입별 접근 멘트
│
└─ 이미지·콘텐츠 제작
    ├─ 슬라이드 배경 이미지 프롬프트
    ├─ 강의 썸네일 생성 프롬프트
    └─ 카드뉴스 제작 프롬프트
```
### 라이브러리 관리 방법
- **저장 위치**: 노션 또는 구글 문서 (검색 가능하게)
- **명명 규칙**: "분야_용도_버전" (예: "일반인강의_교안생성_v3")
- **업데이트 규칙**: 강의 후 "잘 통한 것"과 "안 통한 것"을 바로 메모
- **공유**: 강사끼리 좋은 프롬프트를 공유하면 전체 수준이 올라감

## 4.10 강의 전날·당일 체크리스트
현장에서 가장 많이 무너지는 건 "실력"이 아니라 "준비 부족"입니다.
### 강의 전날
- [ ] PPT 최종 검토 (오타·링크·이미지 깨짐)
- [ ] 시연 도구 계정 로그인 상태 확인
- [ ] 인터넷 연결 방법 확인 (현장 와이파이 + 모바일 핫스팟 백업)
- [ ] 스크린샷 백업 5장 준비 (인터넷 끊겼을 때)
- [ ] 리허설 1회 (타이머 켜고)
- [ ] Q&A 예상 질문 10개 읽어보기
### 강의 당일
- [ ] 30분 일찍 도착 (장소·장비 세팅)
- [ ] 빔프로젝터·화면 연결 확인
- [ ] 시연 도구 실제 작동 테스트 (현장 환경에서)
- [ ] 청중 사전 파악 (인원, 직군, AI 경험 수준)
- [ ] 물 한 잔 준비 (목)
### 강의 중
- [ ] 첫 5분 — 청중이 긴장 풀게 가볍게 시작
- [ ] 시연 전 — "지금부터 화면을 봐주세요"로 주의 집중
- [ ] 체험 시간 — "지금 해보세요, 3분 드릴게요"로 명확하게
- [ ] 시간 체크 — 매 15분마다 흐름 확인
### 강의 후
- [ ] 수강생 피드백 수집 (간단한 설문 또는 구두)
- [ ] "잘 통한 것" 메모 (당일 저장)
- [ ] "안 통한 것" 메모 → 다음 강의 개선 포인트
- [ ] 프롬프트 라이브러리 업데이트

## 4.11 현장 꿀팁 20가지
3\~4주 동안 배운 것, 그리고 현장에서 직접 쓰는 것들을 압축했습니다.
### 강의 설계 꿀팁
**① 첫 3분이 전부다**<br>청중이 "이 강사, 들을 만하다"를 결정하는 시간. 자기소개보다 청중의 페인포인트로 시작하세요. "이런 경험 있으시죠?" 한 문장이 30분 설명보다 강합니다.
**② Before/After를 반드시 화면에서 보여라**<br>말로 "이렇게 하면 좋아져요"는 기억에 안 남습니다. 화면에서 같은 질문을 두 번 입력하고 결과를 나란히 보여주는 순간, 청중이 "오..." 합니다. 이 3초가 30분 설명보다 강합니다.
**③ "얼마나 줄어드는지"를 숫자로 줘라**<br>"시간이 절약돼요"보다 "주 8시간이 돌아옵니다"가 100배 강합니다. 청중이 자기 일에 대입하게 만드는 숫자 하나를 준비하세요.
**④ 슬라이드는 강사를 대신하지 않는다**<br>PPT는 시각 보조 자료입니다. 강사의 말을 대체하는 게 아니에요. 슬라이드에 문장이 가득하면 청중은 강사를 안 봅니다.
**⑤ 체험 시간을 시작하면 걸어다녀라**<br>"지금 해보세요"를 외치고 앞에 서 있으면 청중이 어색합니다. 돌아다니면서 "잘 되고 계세요?", "이 부분 막히셨어요?" 하면 현장 온도가 올라갑니다.
### 프롬프트·AI 활용 꿀팁
**⑥ "단계별로 생각해줘"는 만능 문장이다**<br>복잡한 작업에서 답이 애매하게 나오면 이 문장 하나로 품질이 올라갑니다.
**⑦ 나쁜 예시를 먼저 만들어라**<br>Before/After 시연에서 Before를 강렬하게 만들면 After의 임팩트가 배가 됩니다. "이렇게 하면 이런 결과가 나와요 — 보기 안 좋죠?" 하고 직접 보여주세요.
**⑧ AI한테 "더 나쁜 버전도 보여줘"라고 해봐라**<br>교육용 Before 예시를 AI한테 만들어달라고 할 수 있습니다. "이 프롬프트의 나쁜 버전을 만들어줘"라고 하면 바로 나옵니다.
**⑨ 실습 프롬프트는 반드시 복붙 가능하게 준비해라**<br>슬라이드에 프롬프트를 띄워놓고 "따라 치세요"는 시간 낭비입니다. 카카오톡이나 단체 채팅방으로 텍스트를 미리 보내두고, 복붙만 하게 하세요.
**⑩ 세 가지 AI 도구 중 하나는 항상 무료여야 한다**<br>청중 중 "저는 유료 결제 못 해요"가 반드시 있습니다. Gemini(무료), 뤼튼(무료) 같은 무료 옵션을 항상 준비해두세요.
### 청중 관리 꿀팁
**⑪ 첫 발언자를 미리 섭외해라**<br>"질문 있는 분?" 하면 아무도 안 합니다. 강의 전에 한 명에게 미리 "강의 중에 이 질문 해주실 수 있어요?"라고 부탁해두면 분위기가 열립니다.
**⑫ "틀려도 괜찮아요"를 자주 말해라**<br>특히 체험 시간. AI 교육에서 청중이 가장 두려워하는 건 "내가 잘못 입력하면 어떡하지"입니다. "AI는 지우개가 있어요, 틀려도 새로 쓰면 됩니다"로 안심시키세요.
**⑬ 50대 이상에게는 성공 경험을 먼저 줘라**<br>이론 5분보다 "지금 바로 이거 해보세요"로 작은 성공을 먼저 경험시키는 게 효과적입니다. "저도 됐어요!"가 나오면 그다음은 쉬워집니다.
**⑭ "AI가 틀릴 수 있다"를 강의 초반에 말해라**<br>나중에 시연 중 실패했을 때보다, 초반에 미리 말해두면 훨씬 자연스럽습니다. "AI는 가끔 지어냅니다. 오늘 강의 중에도 그런 순간이 올 수 있고, 그게 바로 살아있는 교육 자료가 됩니다."
**⑮ 질문은 "예/아니요"로 끊지 마라**<br>"AI 써보신 분 있으세요?" → 손 들기. 그 다음 "어떤 용도로요?"로 이어가면 대화가 열립니다.
### 현장 운영 꿀팁
**⑯ 시연은 실제 계정으로, 실제 데이터로**<br>"예시 데이터"로 시연하면 청중이 "나한텐 어떻게 적용하지?"를 생각합니다. 실제 업무 상황(물론 민감정보는 제외)으로 하면 몰입도가 다릅니다.
**⑰ 시연 중 화면 폰트 크게**<br>발표자는 가까이서 보지만 청중은 멀리서 봅니다. 브라우저 확대(Ctrl + +)로 120\~130%로 키우세요.
**⑱ 강의 후 자료를 바로 공유하라**<br>"나중에 드릴게요"는 대부분 안 됩니다. 강의 끝나기 5분 전에 QR코드 또는 링크로 바로 줘야 합니다.
**⑲ 강의 하나가 끝나면 당일 피드백 메모**<br>기억이 생생할 때 적어야 합니다. "오늘 잘 통한 것 3가지, 안 통한 것 3가지" 메모가 다음 강의를 만드는 자산입니다.
**⑳ 첫 강의는 무조건 작게 시작하라**<br>처음부터 100명 앞에서 하려 하지 마세요. 5명·10명 앞에서 먼저. 피드백이 빠르고, 실수해도 회복이 쉽습니다. 작은 성공이 자신감을 만들고, 자신감이 더 큰 강의로 이어집니다.

## 4.12 수료 — 강사 키트 최종 점검
### 수료 후 강사 성장 로드맵
강의는 이 과정이 끝났다고 완성되지 않습니다. 현장을 반복하면서 완성됩니다.
```plain text
[1단계 · 현장 적응기 — 수료 직후 1개월]
목표: 완성한 강의를 실제 현장에서 3회 진행
포인트: 매번 "잘 통한 것 / 안 통한 것" 메모

[2단계 · 숙련기 — 1~3개월]
목표: 청중·직군에 따라 강의를 자유롭게 변형
포인트: 시연 레퍼토리 3개 이상, 프롬프트 라이브러리 50개 이상

[3단계 · 전문가기 — 3개월 이후]
목표: 나만의 강의 브랜드 형성, 후배 강사 양성
포인트: AI 트렌드 업데이트 주기화, 자료 고도화 지속
```
### 마지막으로 — 이 과정을 통해 당신이 갖게 된 것
```plain text
1주차: AI를 설명할 수 있는 사람
2주차: AI에게 제대로 시킬 수 있는 사람
3주차: AI로 결과물을 만들어낼 수 있는 사람
4주차: 그 모든 것을 남에게 가르칠 수 있는 사람
```
> "좋은 AI 강사는 AI를 파는 사람이 아니라,<br>사람들이 AI를 믿고 계속 쓰게 만드는 사람입니다."

## 부록 A — 복사해서 바로 쓰는 자산
### A-1. 교안 초안 생성 프롬프트
```plain text
나는 【대상】에게 【주제】를 가르치는 【시간】 강의를 준비 중이야.
아래 구조로 강의 교안을 만들어줘.

구조:
- 발산(가능성 탐색): 전체 시간의 50%
- 수렴(하나 완성): 30%
- 마무리: 20%

조건:
- 각 단계 핵심 메시지 1개씩
- 청중이 직접 손 움직이는 시간 2회 이상
- 전문용어 없이. 비유 최소 2개 포함
- 마무리는 "오늘 집에서 할 것 하나"로 끝내기
```
### A-2. 슬라이드 문구 생성 프롬프트
```plain text
【강의 주제】 강의의 【N】번째 슬라이드 문구를 만들어줘.
이 슬라이드의 핵심 메시지: 【내용】

조건:
- 헤드라인: 청중이 "오!" 할 1줄 (15자 이내)
- 서브: 헤드라인을 뒷받침하는 2줄
- 강사 멘트 힌트: 이 슬라이드에서 할 말 3문장
- 전문용어 금지
```
### A-3. Q&A 예상 질문·답변 생성 프롬프트
```plain text
【주제】 강의에서 나올 수 있는 청중 질문 10개와
강사 답변(2~3문장)을 만들어줘.

포함할 것:
- 어렵거나 답하기 곤란한 질문 (일자리 관련, AI 한계 등)
- 모든 질문에 정직하고 과장 없는 답변
- 모르면 "확인 후 알려드릴게요" 형태도 포함
```
### A-4. 강의 피드백 분석 프롬프트
```plain text
오늘 강의 후 받은 수강생 피드백을 분석해줘.

[피드백 내용 붙여넣기]

분석 요청:
1. 긍정 반응 핵심 3가지
2. 개선 필요 핵심 3가지
3. 다음 강의에서 바꿔야 할 것 구체적으로 2가지
4. 다음 강의에서 유지할 것 구체적으로 2가지
```
### A-5. 강의에서 그대로 쓰는 멘트 최종 모음
```plain text
[강의 오프닝]
"오늘 목표는 하나입니다.
 끝나고 집에 가서 딱 하나를 직접 해보고 싶어지는 것.
 그것 하나면 오늘 충분합니다."

[체험 시작]
"자 이제 여러분 차례예요. 3분 드릴게요.
 완벽하지 않아도 됩니다. 틀려도 됩니다.
 일단 한 번 해보는 게 목표입니다."

[시연 실패 시]
"오, 이렇게 나왔네요. 이게 바로 환각입니다.
 이럴 때 우리는 이렇게 합니다."

[AI 일자리 질문]
"정말 중요한 질문이에요. 솔직히 말씀드리면,
 반복 업무는 줄어들 겁니다. 그 빈 시간에 더 가치 있는 일을 하는
 사람과 불안해하는 사람의 차이가 생길 거예요.
 오늘 여기 계신 분들은 이미 선택을 하신 겁니다."

[강의 마무리]
"오늘 집에 가시면 딱 이것 하나만.
 지금 제일 귀찮은 반복 업무 하나에 AI 시켜보기.
 15분이면 됩니다. 그게 시작입니다."
```

## Ch 4 핵심 요약 — 강사가 가져갈 7줄
1. **5분 시연 = 끝까지 완주가 목표** — 완벽보다 완주가 먼저
2. **피드백 3단**: 칭찬 하나 · 제안 하나 · 질문 하나 — 평가가 아니라 성장
3. **발산 → 수렴** — 좋은 강의는 넓게 탐색하고 하나를 완성까지
4. **돌발은 준비할 수 있다** — 5가지 상황과 대응 문장을 미리 외운다
5. **강의자료도 AI로** — 교안·슬라이드·Q&A 전부 AI가 초안을 만든다
6. **프롬프트 라이브러리 = 강사의 영구 자산** — 쌓일수록 강의가 빨라진다
7. **꿀팁 ①번**: 첫 3분이 전부다 — 청중의 페인포인트로 시작하라
> 이 과정을 마친 당신은 AI를 설명하고 · 시키고 · 만들고 · 가르칠 수 있는 강사입니다.<br>다음은 현장입니다. 현장이 진짜 선생님입니다.
