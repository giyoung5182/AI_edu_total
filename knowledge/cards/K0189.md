# Claude Code 확인창 반복은 권한 모드 문제 — Shift+Tab 전환, 전면 우회(bypass)는 격리 환경 전용

> 역사 자료. 확인 수준과 확인일은 원본 기록을 보존한 값입니다. 공개 편집일의 최신 기능·가격·법률 확인을 의미하지 않습니다.

## 정리된 지식

- 권한 모드는 Manual(설정값 default)·acceptEdits·plan·auto·dontAsk·bypassPermissions로 구분되며 CLI에서는 Shift+Tab, VS Code는 모드 표시기, 데스크톱은 모드 선택기로 전환
- auto 모드는 분류기(두 번째 모델)가 사용자 대신 작업을 검토하는 방식이며 v2.1.283 이상에서는 터미널·VS Code 대화형 세션의 기본 시작 모드
- bypassPermissions는 공식 표에서 '격리된 컨테이너와 VM 전용'으로 분류, --dangerously-skip-permissions 무인 실행은 컨테이너·VM·샌드박스가 필요하다고 명시
- 기본 모드는 settings 파일의 permissions.defaultMode로 지정(.claude.json 아님), 프로젝트 .claude/settings.json의 auto·bypassPermissions 값은 적용되지 않음
- deny 규칙과 중요 경로 rm 등 일부 동작은 어떤 모드에서도 자동 승인되지 않음
- Claude Code 권한 모드 문서: bypassPermissions(--dangerously-skip-permissions와 동일)는 권한 확인과 안전 점검을 끄고 보호 경로 쓰기까지 즉시 실행, '인터넷 접근 없는 컨테이너·VM·dev container 같은 격리 환경에서만 사용'하라고 명시
- 모드: default(읽기만 무확인), acceptEdits(파일 편집·일반 파일 명령), plan, auto(별도 분류 모델이 사용자 대신 행동 검토), CLI는 Shift+Tab으로 전환, deny 규칙은 모든 모드에서 차단
- Bash 샌드박스 문서: 기본적으로 작업 디렉터리·하위 폴더, --add-dir로 추가한 폴더, 사용자 임시 폴더에만 쓰기 허용하고 그 밖의 수정은 OS 수준에서 차단(macOS·Linux·WSL2 지원, 네이티브 Windows 미지원), /sandbox로 설정

## 교육과 업무에 활용

- 확인창 피로는 모드 선택 문제로 설명, '무조건 bypass'가 아니라 auto 모드 우선 안내
- bypass·skip-permissions는 개인 PC가 아닌 컨테이너·VM에서만 쓰도록 교육
- 기본 모드는 settings.json의 defaultMode로 고정하는 방법까지 실습
