# 서브에이전트는 독립 컨텍스트에서 실행되고 model 필드로 Claude 모델을 지정 — 타사 모델 조합·다계정 인계는 커뮤니티 운용 방식

## 정리된 지식

- Claude Code 공식 문서: 서브에이전트는 YAML 머리말이 있는 마크다운 파일(.claude/agents/ 또는 ~/.claude/agents/)로 정의하며, 각자 독립된 컨텍스트 창·시스템 프롬프트·도구 권한으로 실행되고 메인 대화 기록은 받지 않음
- model 필드에는 sonnet·opus·haiku·fable 별칭, 전체 모델 ID(예: claude-opus-5-5), inherit를 지정 가능. 우선순위는 호출 시 지정 > 에이전트 정의 > CLAUDE_CODE_SUBAGENT_MODEL > 메인 모델
- 서브에이전트 요청도 메인 대화와 같은 사용 한도에서 차감됨
- Anthropic 프롬프팅 가이드: 최신 모델은 서브에이전트 오케스트레이션을 기본 수행하며, 병렬 작업·격리된 컨텍스트·독립 작업에 쓰고 단순·순차·단일 파일 작업은 직접 처리 권장 → '자동 할당되어 신경 안 썼다'는 경험과 부합
- GPT 계열을 서브에이전트로 섞는 방식, 계정 간 자동 인계는 공식 문서화된 기능이 아니며, 다계정 운용의 약관 적합성은 확인하지 못함
- [추가 2026-09-09] 공식 문서 확인: 서브에이전트는 자체 컨텍스트 창에서 실행되고 메인 대화와 같은 로직으로 자동 컴팩션을 지원. memory 필드를 쓰면 user·project·local 범위의 영구 메모리 디렉터리가 생겨 세션 간 지식이 누적됨. 따라서 'compact가 안 돼 토큰이 쌓인다'는 우려는 문서와 다름.
- [추가 2026-10-01] 커뮤니티 운용 사례: Orca CLI로 Claude CLI가 Antigravity(agy) CLI를 워커로 부리게 해 OCR·단순 잡일만 Gemini Flash에, Claude 한도 부족 시 agy의 Opus 4.8 한도를 워커로 활용(실측 필요, 공식 기능 아님)

## 교육과 업무에 활용

- 멀티모델 오케스트레이션은 '공식 기능(서브에이전트·model 필드)'과 '커뮤니티 자작 구성'을 구분해 소개
- 서브에이전트도 한도를 소모하므로 단순 작업은 직접 처리하는 기준 제시

## 정정과 한계

'서브에이전트는 compact가 안 돼 토큰이 쌓인다'는 우려는 공식 문서와 다름 — 서브에이전트도 메인과 같은 로직으로 자동 컴팩션, memory 필드로 영구 메모리 지정 가능.
