## 정리된 지식

- Google Stitch: Google Labs의 AI UI 디자인 도구(공식 블로그 발표)
- Pencil: 공식 사이트 표기상 'pen.dev (formerly pencil.dev)' — pen.dev로 이름이 바뀐 에이전트 기반 디자인 캔버스
- '결과가 뻔하다', '포스터는 아스트라가 낫다'는 공식 비교 자료가 없는 사용 체감
- 무료 3D 생성 사이트와 weweb의 기능·가격은 원본 정리 시 확인 범위에서 공식 자료로 확인하지 못함
- [추가 2026-07-08] 커뮤니티 추가 노하우: 색 팔레트·서체·폰트 크기는 기본, 간격·모서리 각도·선 굵기·사용 시점까지 지정, 참고 사이트에서 '어떤 부분'을 가져올지 구체화, getdesign.md의 design-md로 틀을 잡고 방향에 맞는 사이트를 AI에 서칭시키기, Fable은 레퍼런스를 주면 잘 따라한다는 평(모두 체감)
- [추가 2026-08-27] 8월 디자인 논의: DESIGN.md로 디자인 규칙을 문서화(Google Labs가 2026-04-21 Stitch 블로그에서 DESIGN.md 초안 사양을 오픈소스 공개), Claude Design은 코드베이스·디자인 파일·문서·로고 등으로 디자인 시스템을 만들어 이후 프로젝트에 일관 적용(공식 도움말은 '스펙보다 실제 완성 페이지 예시를 넣으라' 권고), Stitch MCP로 IA 설계 후 UI 생성, grill-me 스킬(계획·디자인을 역질문으로 다듬는 스킬)로 요구사항 정리. 그라데이션·파스텔 과용 금지, 여백·버튼·폰트 기준 자료 제공. 개발자에게 디자인을 맡기지 말라는 조언
- [추가 2026-09-21] 9/21 커뮤니티: 레퍼런스를 찾아 컨셉을 맞춘 뒤 조금씩 화면 제작, Astra에 먼저 시키고 고친다, 비전공자는 결국 자료(레퍼런스) 차이라는 결론.
- [추가 2026-06-26] 커뮤니티 팁: design.md로 디자인 규칙 명시, lazyweb 스킬(무거움), 검수자 안목이 결과를 좌우, Google Stitch·Claude Design 병행
- [추가 2026-09-30] 실무 팁: Codex 등에게 UI를 바로 구현시키지 말고 이미지 생성으로 UI 시안을 먼저 뽑은 뒤 그것을 충실히 구현하게 하면 결과가 좋아짐. 이미지가 빨리 만들어져 반복 수정이 편하기 때문이며(공장장), 코드를 고려하는 모델에게 바로 디자인시키면 인터랙티브한 결과가 나오기 어렵다는 의견(커뮤니티 경험)
- [추가 2026-10-02] - 멋진 랜딩 페이지는 특별한 프롬프트 없이도 나온다는 체감(Sol xhigh 25분·medium 15분, Opus 5.5 xhigh 50분·medium 25분, Opus가 더 폭넓게 구현)
- 원하는 콘셉트의 웹페이지를 캡처해 레퍼런스로 주는 방식이 효과적
- 'AI 디자인 티' 탈피 도구로 Open Design 추천: 공식 사이트 기준 Apache-2.0 오픈소스 디자인 에이전트 작업공간, Claude Code·Codex·Cursor 등 21개+ 에이전트와 연결, 150+ 디자인 시스템, HTML·PDF·PNG(슬라이드는 PowerPoint) 내보내기, 무료 데스크톱+유료 클라우드 요금제

- 디자인 실습에서는 도구 선택보다 '참고 이미지·색상·폰트 규칙을 먼저 정해 주는' 지시 방식을 강조
