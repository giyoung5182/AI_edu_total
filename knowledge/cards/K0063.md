## 정리된 지식

- Andrej Karpathy가 공개한 LLM Wiki 패턴(gist): ① 바뀌지 않는 원본 자료, ② LLM이 유지하는 서로 연결된 마크다운 위키, ③ 작성 규칙을 정한 스키마 문서의 3층 구조
- 질문할 때마다 원문에서 다시 찾는 RAG와 달리, 자료를 넣을 때 LLM이 한 번 종합해 항목 페이지 갱신·모순 표시·연결 강화를 수행해 지식이 누적됨
- 사람이 위키를 포기하는 이유(유지 부담)를 LLM이 대신 진다는 것이 핵심 논리
- 커뮤니티가 언급한 Tencent DB·Agent Memory 프로젝트는 원본 정리 시 확인에서 공식 저장소를 특정하지 못함
- [추가 2026-07-12] 커뮤니티 운용 사례 추가: 사용자는 Inbox에 던지고 분류·태그·MOC는 AI가 하는 원칙을 CLAUDE.md에 명시, 회의록·메일·통화 STT를 볼트에 쌓아 초안 작성에 활용, Drive 동기화+GitHub 버전관리, 운용 언어는 영어·md 직접 작성 비율을 높여야 번역체로 언어 체계가 무너지지 않는다는 조언, index 파일 하나에서 링크를 타고 찾는 구조, 깊게 하려면 임베딩→적재→색인 분리 학습 제안(모두 커뮤니티 경험)
