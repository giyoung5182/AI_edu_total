## 정리된 지식

- Codex 공식 문서: 승인 정책 on-request·never·untrusted·granular, 샌드박스 read-only·workspace-write·danger-full-access. config.toml의 approval_policy·sandbox_mode로 설정, /permissions로 전환
- '--dangerously-bypass-approvals-and-sandbox'(별칭 --yolo)는 '고위험(Elevated Risk)'으로 샌드박스·승인 모두 없음. 네이티브 Windows는 [windows] sandbox = 'unelevated' 또는 'elevated'로 설정
- Claude Code 공식 문서: auto mode에서는 분류기(두 번째 모델)가 사람 대신 행동을 검토하며, git reset --hard 등 커밋 안 된 변경을 버리는 명령을 기본 차단
- 분류기가 연속 3회 또는 세션 누적 20회 차단하면 auto mode가 멈추고 다시 사용자에게 묻는 방식으로 돌아감(설정 불가)
- bypassPermissions는 '격리된 컨테이너·VM 전용' 권장 모드이며, deny 규칙은 bypass에서도 적용

## 교육과 업무에 활용

- '승인 끄기'는 컨테이너·VM 같은 격리 환경에서만 권장한다고 교육
- auto mode에서 반복 확인창이 뜨면 차단 누적으로 인한 정상 동작일 수 있음을 안내
- 파괴적 명령(git reset --hard, rm 등)은 deny 규칙으로 별도 차단
