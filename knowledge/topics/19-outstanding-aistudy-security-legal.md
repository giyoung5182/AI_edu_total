## 실제 학습 내용

### AI 채용 판단은 편향 통제가 어렵고, 인공지능기본법은 채용 판단·평가를 고영향 인공지능 영역으로 분류

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

- 「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」 제2조의 고영향 인공지능 정의에 '채용, 대출 심사 등 개인의 권리·의무 관계에 중대한 영향을 미치는 판단 또는 평가'에 쓰이는 AI가 포함됨(국가법령정보센터 원문은 이번에 직접 열람하지 못하고 검색 결과로 확인)
- 아마존 AI 채용도구 폐기(여성 지원자 불리 편향)는 2018년 로이터 보도로 알려진 사례(언론 보도 기준)

**활용할 때 확인할 점**

- HR 대상 교육에서 채용·평가 AI는 '보조 도구+사람 최종 결정' 원칙과 법적 고영향 분류를 함께 안내
- 대리변수(출신·경력 공백 등) 편향 예시로 설명

### 앱 코드 난독화(R8)는 공식 문서상 용량 최적화 기능 — 보안의 핵심은 비밀키를 앱에 넣지 않는 것

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- Android R8: 코드 축소·최적화·난독화(클래스·메서드 이름 단축)를 수행하며 release 빌드에서 활성화(AGP 9.3 이상은 optimization { enable = true }, 이전 버전은 isMinifyEnabled = true)
- 공식 문서는 난독화를 DEX 파일 크기 축소 목적으로 설명하며 보안 수단으로 제시하지 않음
- Android 보안 문서: 앱에 하드코딩한 비밀값은 리버스 엔지니어링 도구로 매우 쉽게 추출 가능, Android Keystore·KeyChain 사용 권장
- 'AI가 스크린샷으로 복제한다'는 관점은 커뮤니티 의견

**활용할 때 확인할 점**

- 바이브코딩 앱 배포 교육에서 API 키·비밀값은 서버 측에 두는 원칙을 먼저 강조
- 난독화는 부가 조치로 설명하고, 기능 복제 방어는 코드가 아니라 데이터·운영·고객으로 해야 한다는 점 연결

### 내 클라우드 VM에서 내 Claude 구독으로 Claude Code를 돌리는 것은 본인 사용 범위 — 남을 위한 봇·서비스는 API 키 필수

원본 상태: 공식확인 · 원본 확인일: 2026-10-06

- Claude Code 공식 법률·준수 문서: Free·Pro·Max 사용자는 Consumer Terms 적용, Pro·Max 광고 사용량은 '평범한 개인 사용'을 전제
- OAuth(구독 로그인)는 구독 구매자 본인의 Claude Code·Anthropic 네이티브 앱 사용을 위한 것
- 제품·서비스를 만드는 개발자(Agent SDK 포함)는 Console API 키나 지원 클라우드 사업자 인증을 써야 하며, 사용자를 대신해 Free·Pro·Max 자격증명으로 요청을 중계하거나 Claude 로그인 토큰을 수집·보관하는 것은 금지
- 호스팅 플랫폼에서도 최종 사용자가 수정되지 않은 Claude Code에 본인 구독으로 로그인하는 것은 허용, Anthropic은 사전 통지 없이 제한 조치 가능

**활용할 때 확인할 점**

- 판단 기준은 '어디서 돌리나'가 아니라 '누구의 사용인가·누구에게 제공하나'
- 팀·고객용 봇은 처음부터 API 키 과금 구조로 설계
- 24시간 대량 자동화는 '평범한 개인 사용' 범위를 넘을 수 있음

### Anthropic 분석(2026-09-29): 오픈웨이트 GLM-5.3이 제한 공개 모델급 익스플로잇 능력 도달 — 고급 사이버 능력의 '확산'

원본 상태: 공식확인 · 원본 확인일: 2026-10-06

- Anthropic 연구 글(2026-09-29): GLM-5.3은 ExploitBench(Chrome V8 취약점)에서 12% 성공, Claude Mythos Preview 14%와 비슷한 수준. 이전 모델(Claude Opus 4.6, GLM-5.2)은 거의 0%
- 내부 바이너리 익스플로잇 벤치마크에서 4% 시도로 완전한 제어 흐름 탈취
- 안전장치 우회율: 직접 요청 0%, 기만적 설정 64%, 추론 토큰 프리필 92%, 안전장치 제거 버전 100%
- NIST AI 표준·혁신센터 평가 인용: 지금까지 공개된 오픈웨이트 모델 중 사이버 능력 최고, 미국 프런티어 대비 약 4개월 격차
- 권고: 정부의 독립 안전성 시험, 오픈웨이트 능력 보호, 검증된 방어자에게 방어 도구 접근 확대

**활용할 때 확인할 점**

- 오픈웨이트 모델은 안전장치가 쉽게 제거된다는 전제로 보안 정책 설계
- 사내 코드·인프라 접근 권한을 가진 에이전트는 최소 권한·감사 로그 필수
- 경쟁사 발표 자료는 독립 평가(NIST 등)와 교차 확인

### 비개발자 바이브코딩의 벽은 코딩보다 운영·보안 — 위험을 모르면 '보안 점검해줘'조차 요청하지 못함

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-10-06

- 커뮤니티 실무 경험 정리이며 사고 빈도·배상 규모에 대한 공식 통계는 확인하지 않음
- 공통 조언: 관리자 경로 접근 통제, 저장소 공개 범위·비밀키 관리, 출시 전 별도 세션·도구로 보안 검토

**활용할 때 확인할 점**

- 바이브코딩 교육에 '배포 전 보안 체크리스트(인증·권한·비밀키·공개 범위)'를 필수 단계로 포함
- 수익화는 기술보다 수익 구조·기존 본업 연계부터 설계
- '모르는 위험'을 AI에 묻도록 질문 목록을 제공
