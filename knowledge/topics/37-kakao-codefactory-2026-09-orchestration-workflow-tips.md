## 실제 학습 내용

### GPT-6 Astra는 Plus에도 포함되지만 5시간당 추정 5~45회 수준, 높은 추론 effort일수록 한도 소모 증가

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

- OpenAI 도움말: Astra는 Work/Codex에서 Plus·Pro 및 Business Standard/Premium 좌석에 포함. 5시간당 추정 로컬 메시지 수는 Plus 5-45, Pro 5x 25-225, Pro 20x 100-900이며 고정 한도가 아니고 주간 한도도 함께 적용. 높은 effort는 허용량을 더 쓰며 항상 더 나은 결과를 주지는 않으므로 낮은 effort부터 시작, 일상 작업은 Luna·Terra 선택, fast 모드 회피를 권장.
- [추가 2026-09-23] 공식 도움말: Plus 기준 5시간당 5~45개 메시지 추정(표상 모델 중 가장 적은 수치, 높은 effort는 허용량을 더 소모), Plus는 Work·Codex에서 Astra 사용 가능(Chat에서는 불가). 커뮤니티 체감: 같은 추론 깊이 기준 Sol의 2~3배 소모, Plus는 20~30분이면 소진, Pro도 5.6 대비 2~3배.

**활용할 때 확인할 점**

Astra는 '기본값 high'가 아니라 '낮은 effort부터 올려가기' 원칙으로 안내. 다른 모델로 지시를 정리해 넘기는 절감 효과는 체감 사례로만 소개.

### Claude effort 기본값은 모델·환경마다 다름 — Opus 5.5는 medium, Sonnet 5.5도 xhigh 지원

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- Anthropic effort 문서: 레벨은 low·medium·high·xhigh·max. xhigh는 '장시간(30분 이상) 에이전트·코딩 작업용', low는 서브에이전트 같은 단순 작업용. xhigh·max 지원 모델에 Fable 5.1, Opus 5.5, Sonnet 5.5 등이 포함됨. API 기본값은 Opus 5.5만 medium, 나머지(Fable 5.1, Sonnet 5.5 등)는 high. Claude Code에서는 Opus 5.5와 Sonnet 5.5 모두 기본 medium이며 /effort 또는 --effort로 변경. 공식 권장은 '기본값으로 시작 → 역량이 중요한 작업은 xhigh/max로 올리고, 평가로 품질 유지가 확인되면 medium/low로 내림'.
- [추가 2026-09-26] 9/26 Claude 앱 effort 표시(medium 기본)와 CLI의 effort 이름이 달라 헷갈린다는 반응 — 기존 카드대로 Opus 5.5 기본값은 medium.

**활용할 때 확인할 점**

effort는 '높을수록 좋음'이 아니라 작업 길이·난이도에 맞추는 설정이라는 점을 공식 표로 설명. API와 Claude Code의 기본값이 다를 수 있다는 점도 함께 안내.

- 채팅 앱은 작업 중 대기열 입력이 안 되는 불편이 언급됨

### Codex에서 Claude Code auto mode에 해당하는 기능은 auto-review — approvals_reviewer = "auto_review"(기본값은 user)

### Jev를 에이전트 라우터로 쓰는 법과 한계 — 세션 시작·서브에이전트 분기에서만 라우팅, 한국어는 사전 테스트 필수

원본 상태: 부분확인 · 원본 확인일: 2026-10-06

- 논문 'Control the Harness, Control the Cost'(arXiv 2609.28919, 2026-09-24 제출): Jev로 요청을 분류해 가격대가 다른 모델에 배정하는 라우터 제안. 모의 1만 석 기업에서 모델 지출의 14~21% 절감 추정(Anthropic 2026년 9월 가격 기준). 대화 중 모델 전환은 프롬프트 캐시 재구축 비용이 커서 세션 시작·병렬 작업 레인·서브에이전트 실행 시점에서만 전환. 긴 도구 사용 세션에서는 비싼 모델이 오히려 싸게 먹힐 수 있다고 분석. 저자 소속(하버드 여부)은 원본 정리 시 확인에서 미확인
- TypeSafe 공식 문서: Jev는 영어가 주 학습 언어이며 CJK 등 다른 언어는 '처리하지만 동등하게 잘하지는 않으므로 비영어 작업은 자체 테스트 후 사용'하라고 명시. 입력은 텍스트만, 요청당 64k 토큰
- 경쟁 모델 CLM-8B(스탠퍼드·엔비디아, Apache 2.0): 보도 기준 Jev보다 최대 9배 빠르나 BFCL v4 도구 호출 정확도 95.2%(Jev 99.2%)
- [추가 2026-10-02] Jev 한국어 성능 질문은 답변 없음. 대안으로 Laya 다국어 체크포인트(mmBERT-base, 100+ 언어)가 있으나 한국어 정확도는 자체 테스트 필요 — 신규 카드 K0369 참조

**활용할 때 확인할 점**

- 라우터 도입 전 상시 로드 토큰·캐시 만료·모델 전환 시점 같은 하네스 기본기 점검이 우선
- 모델 전환은 캐시를 깨므로 '대화 중간'이 아닌 '작업 분기점'에서만
- 한국어 업무에 Jev 적용 시 자사 데이터로 정확도 검증 또는 영문 병행 설계

### 에이전트 비용 측정과 통제 — OpenRouter는 응답마다 cost 자동 포함, 지시는 이중부정 대신 긍정문으로

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- OpenRouter 공식 문서: 모든 응답의 usage에 전체 사용 내역이 자동 포함되며 cost(청구 금액)와 cost_details.upstream_inference_cost 필드 제공. 과거 usage: {include: true} 파라미터는 더 이상 효과 없음(chat completions 포함)
- LangSmith Claude Code 플러그인(langchain-ai): 대화·도구 호출·서브에이전트 실행·컨텍스트 압축을 추적하고 LLM 실행별 토큰 사용량 기록. Node.js 18 이상 필요, 서브에이전트는 완료 시점에만 추적되어 실행 중 중단하면 기록되지 않음
- Claude Code 자체에도 --max-budget-usd(출력 모드 -p 전용)로 API 지출 상한을 두는 공식 플래그가 있음
- Anthropic 공식 프롬프트 가이드: '하지 말 것' 대신 '할 것'을 말하라(Tell Claude what to do instead of what not to do)

**활용할 때 확인할 점**

- 비용 통제는 프롬프트 금지문보다 측정(usage·cost 필드, 추적 도구)과 하드 상한(플래그·hook)으로
- 원치 않는 행동이 반복되면 부정·이중부정 지시를 긍정형 목표 서술로 바꿔보기
- 캐시 적용 여부에 따라 실제 비용이 달라지므로 측정값 기준으로 판단
