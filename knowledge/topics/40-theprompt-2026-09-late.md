### 최신 모델 한국어 문체의 특징 — 축약·전문용어 과다, 콤마 남용, 외국 문자 혼입과 감수 요령

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-10-06

- 커뮤니티 체감 정리이며 공식 문서로 확인된 내용이 아님

- 체감은 사용자·언어(영어 위주 vs 한국어 위주)에 따라 정반대로 갈림
- 실무 감수 기준 예: 2~4어절마다 용언·문장부호 배치, 절당 성분 4개 이하
- [추가 2026-10-02] '의도한 이유로 실패했다'(테스트를 일부러 실패시켜 원인 확인) 같은 번역투·개발 용어 직역이 비개발자 이해를 막는 사례. 대응: 실패 이유를 쉬운 말로 다시 설명해 달라고 요청, '어려운 말은 쉬운 말 주석·임의 용어 금지'를 지침에 고정

**활용할 때 확인할 점**

- AI 한국어 초안은 '읽기 쉬움' 기준(용언 간격·절당 성분 수)으로 따로 감수
- 콤마·전문용어·외국 문자 혼입을 체크리스트 항목으로 운영
- 긴 세션에서 영어로 바뀌면 출력 언어를 다시 명시하거나 새 세션으로 분리

### 증류(distillation) 자체는 정상 학습 기법, 타사 모델을 부정 계정으로 대량 추출하는 것은 약관 위반 공격

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

- Anthropic 공식 글(2026-02-23)은 증류를 '약한 모델을 강한 모델의 출력으로 학습시키는 널리 쓰이는 정당한 학습 방법'으로 정의하고, 프런티어 연구소가 자사 모델을 증류해 작은 모델을 만드는 것은 일상적이라고 설명
- 문제는 타사 모델을 서비스 약관·지역 접근 제한을 어기고 부정 계정으로 대량 추출하는 경우로, 해당 글은 DeepSeek(약 15만 건)·Moonshot(약 340만 건)·MiniMax(약 1,300만 건), 부정 계정 약 2만 4천 개를 제시
- 2026년 9월 위협 인텔리전스 보고서(9/10 공개)는 '불법 증류(illicit distillation)'를 7개 위해 영역 중 하나로 다룸. 알리바바 1억 5,100만 건·3,500개 계정(2026년 5~7월) 수치는 TechCrunch 보도 기준이며, 원본 정리 시 확인에서 보고서 원문 해당 페이지까지는 열람하지 못함

**활용할 때 확인할 점**

- '증류=불법'이 아니라 '타사 약관을 어긴 무단 추출'이 문제라는 구분을 교육에서 명확히
- 기업 AI 보안 교육에서 모델 출력이 공격 대상이 되는 사례로 활용
- 수치 인용 시 공식 보고서와 언론 보도 출처를 구분해 표기

### Claude Opus 5.5 프롬프팅 — 기본 effort medium·사고 상시 켜짐, 시간 예산 표기와 진행 상황 표시 설정

원본 상태: 정정 · 원본 확인일: 2026-09-29

- 공식 가이드: Opus 5.5는 사고(thinking)가 항상 켜져 있고 기본 effort가 medium(Opus 5는 high). 'medium부터 명시적으로 설정해 여러 단계를 자체 평가로 테스트'하라고 권장
- medium 설정에서도 코딩·지식 작업 평가에서 Opus 5 high와 같거나 높고, 출력 토큰 생성이 30% 빠름
- 사고 토큰도 max_tokens에 포함되므로 긴 에이전트 턴은 128,000 수준으로 넉넉히
- 소요 시간을 추정할 수 있으면 하네스가 매 메시지 끝에 'elapsed 340s / 1200s' 형식으로 경과 시간을 붙이는 방식 권장
- 진행 상황 업데이트는 text가 아닌 thinking 블록으로 오며, 기본 display: "omitted"에서는 비어 있음. display: "updates"(베타 헤더 필요)로 요약을 받을 수 있음
- 조기 종료 방지: 남은 할 일 목록을 담은 계속 진행 메시지 전송

**활용할 때 확인할 점**

- 모델 교체 시 effort를 명시적으로 지정하고 자체 평가로 비교
- 에이전트 하네스에 경과 시간/예산 표기를 넣는 실습 과제로 활용
- 진행 상황이 안 보이면 버그가 아니라 display 설정 문제일 수 있음

**정정과 한계**

'기존 프롬프트를 그대로 쓰면 결과가 나빠진다'는 일반화는 공식 문구와 다름. 공식 가이드는 '기존 Opus 5 프롬프트는 수정 없이도 잘 작동해야 한다'고 하며, 재점검 대상은 사고 비활성 시절에 추론을 대신 쓰게 하던 지시 등 특정 우회 지시임.

### Jev를 에이전트 라우터로 쓰는 법과 한계 — 세션 시작·서브에이전트 분기에서만 라우팅, 한국어는 사전 테스트 필수

원본 상태: 부분확인 · 원본 확인일: 2026-10-06

- 논문 'Control the Harness, Control the Cost'(arXiv 2609.28919, 2026-09-24 제출): Jev로 요청을 분류해 가격대가 다른 모델에 배정하는 라우터 제안. 모의 1만 석 기업에서 모델 지출의 14~21% 절감 추정(Anthropic 2026년 9월 가격 기준). 대화 중 모델 전환은 프롬프트 캐시 재구축 비용이 커서 세션 시작·병렬 작업 레인·서브에이전트 실행 시점에서만 전환. 긴 도구 사용 세션에서는 비싼 모델이 오히려 싸게 먹힐 수 있다고 분석. 저자 소속(하버드 여부)은 원본 정리 시 확인에서 미확인
- TypeSafe 공식 문서: Jev는 영어가 주 학습 언어이며 CJK 등 다른 언어는 '처리하지만 동등하게 잘하지는 않으므로 비영어 작업은 자체 테스트 후 사용'하라고 명시. 입력은 텍스트만, 요청당 64k 토큰
- 경쟁 모델 CLM-8B(스탠퍼드·엔비디아, Apache 2.0): 보도 기준 Jev보다 최대 9배 빠르나 BFCL v4 도구 호출 정확도 95.2%(Jev 99.2%)
- [추가 2026-10-02] Jev 한국어 성능 질문은 답변 없음. 대안으로 Laya 다국어 체크포인트(mmBERT-base, 100+ 언어)가 있으나 한국어 정확도는 자체 테스트 필요 — 신규 카드 K0369 참조

**활용할 때 확인할 점**

- 라우터 도입 전 상시 로드 토큰·캐시 만료·모델 전환 시점 같은 하네스 기본기 점검이 우선
- 모델 전환은 캐시를 깨므로 '대화 중간'이 아닌 '작업 분기점'에서만
- 한국어 업무에 Jev 적용 시 자사 데이터로 정확도 검증 또는 영문 병행 설계

### 에이전트 비용 측정과 통제 — OpenRouter는 응답마다 cost 자동 포함, 지시는 이중부정 대신 긍정문으로

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- OpenRouter 공식 문서: 모든 응답의 usage에 전체 사용 내역이 자동 포함되며 cost(청구 금액)와 cost_details.upstream_inference_cost 필드 제공. 과거 usage: {include: true} 파라미터는 더 이상 효과 없음(chat completions 포함)
- LangSmith Claude Code 플러그인(langchain-ai): 대화·도구 호출·서브에이전트 실행·컨텍스트 압축을 추적하고 LLM 실행별 토큰 사용량 기록. Node.js 18 이상 필요, 서브에이전트는 완료 시점에만 추적되어 실행 중 중단하면 기록되지 않음

### Claude Code 시스템 프롬프트 교체·추가 플래그 — 공식 --mode 플래그는 없고 claude-mode는 설정 전환 래퍼

원본 상태: 정정 · 원본 확인일: 2026-09-29

- Claude Code 공식 CLI 시스템 프롬프트 플래그: --system-prompt·--system-prompt-file(기본 프롬프트 전체 교체, 둘은 동시 사용 불가), --append-system-prompt·--append-system-prompt-file(기본 프롬프트 뒤에 추가, 교체 플래그와 병용 가능)
- 공식 문서는 기본 도구 안내·안전 지침을 유지하려면 추가(append) 플래그를, 정체성·권한 모델이 완전히 다를 때만 교체 플래그를 쓰라고 안내. 교체 시 기본 프롬프트의 도구 안내·안전 지침이 모두 빠짐
- --model은 sonnet·opus·haiku·fable 별칭 또는 전체 모델명을 받음
- 공식 CLI에 --mode 플래그는 없음. claude-mode(Mineru98)는 셸 함수 래퍼로 settings/settings.<name>.jsonc를 --settings로 넘겨 플러그인·스킬·MCP 구성만 세션별로 바꾸며 시스템 프롬프트는 바꾸지 않음(bash·zsh는 jq 필요)
- 한글 토큰 문제 해소는 개인 체감으로 공식 확인 없음

**활용할 때 확인할 점**

- 작업 유형별 시스템 프롬프트 파일을 만들어 append로 붙이는 방식은 버전 관리·재사용에 유리
- 교체(--system-prompt)는 안전·도구 지침까지 사라지므로 입문자에게는 append 권장
- 커뮤니티 명령어 예시는 공식 플래그인지 래퍼인지 구분해 안내

**정정과 한계**

'claude --mode=write'는 Claude Code 공식 플래그가 아니라 claude-mode 같은 셸 래퍼를 설치해야 동작하는 방식이며, 그 래퍼도 시스템 프롬프트가 아닌 설정·플러그인·스킬·MCP만 전환함. 시스템 프롬프트 추가는 공식 플래그 --append-system-prompt-file로 가능.
