## 실제 학습 내용

### Claude·Codex 전환·병행은 md 지침 이전과 역할 분담이 핵심, 완전 호환은 불가

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-10-06

- 커뮤니티 경험 정리: 지침 파일(CLAUDE.md↔AGENTS.md) 교체로 대부분 이전 가능, CLI별 기본 하네스·서브에이전트·hook 설정은 개별 재구성 필요
- 병행 시 '기획·검수=Codex, 생성·실행=Claude'처럼 역할을 md에 명시하는 방식이 반복 언급
- 체감 비교(Codex가 더 정밀·할루시네이션 적음 vs Claude 코드 정돈이 낫다)는 사람마다 갈림
- 장애 대비로 두 도구를 백업 관계로 유지하는 사례 다수
- [추가 2026-10-01] Codex→Claude 전환 시 MCP·computer use 등 주요 기능은 Claude에도 있다는 답. 두 도구 병행 시 스킬을 서로 가져오게 시키는 방식은 만족도가 낮다는 경험 다수

**활용할 때 확인할 점**

- 도구 교체 전 지침 파일·스케줄·hook 목록을 먼저 문서화
- 초보는 도구 전환보다 한 도구로 업무 흐름 정착이 우선
- 두 모델 교차 토론은 판정 기준을 정해두고 실행

### API 없는 카카오톡 채널 CS 자동화 사례 — 브라우저 에이전트+노션 매뉴얼+가드레일 구조

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-09-29

- 커뮤니티 사례: 프롬프트 하나가 아니라 '데이터 분석→유형 분류→응답·인계 흐름→가드레일→외부 매뉴얼' 시스템화가 성공 요인으로 제시
- 지침을 모델 내부가 아닌 노션 등 외부 문서에 두면 오류 시 수정·개선이 쉽다는 운영 노하우
- 브라우저 조작 방식은 공식 API 연동이 아니므로 안정성·약관 검토가 별도로 필요(공식 확인 안 됨)

**활용할 때 확인할 점**

- CS 자동화 교육 시 '사람 인계 기준'과 '금지 응답' 설계를 필수 단계로 포함
- 매뉴얼 외부화(노션·시트)로 비개발자도 봇 동작 수정 가능

### 개인 비서형 에이전트는 '요청 분류→컨펌 필요 여부 판단→실행' 프로토콜과 비서 R&R 정의로 개인화

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-09-29

- 커뮤니티 경험 기반 설계 요소: ① 반복 행위의 스킬화 ② 요청 분류·승인 게이트 ③ 역할(R&R) 문서화 ④ 스케줄 작업 ⑤ 외부 지식 저장소(옵시디언·노션)
- 기존 도구 불만(장기 작업을 백그라운드로 돌리지 않아 병렬 불가 등)을 목록화해 자체 개선한 사례
- 채팅 앱은 작업 중 대기열 입력이 안 되는 불편이 언급됨

**활용할 때 확인할 점**

- 에이전트 교육 시 '프롬프트'보다 '승인 게이트·역할 문서·스케줄' 설계를 먼저
- 실제 비서와의 격차를 전제로 기대치 설정

### 맥락 없는 요청은 '가장 흔한 답'으로 수렴 — 국가·도메인 맥락과 데이터를 넣는 컨텍스트 엔지니어링이 결과를 좌우

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-09-29

- 커뮤니티 실무 경험 정리이며 특정 연구로 검증하지 않음
- 반복 관찰: 프롬프트에 국가·업종·기준 목록을 명시하지 않으면 학습 데이터가 많은 영어권 사례가 기본값이 되고, 이후 다중 에이전트 단계에서도 누락이 이어짐
- 결과를 '아무튼 출력은 나온다'는 특성 때문에 오류가 드러나지 않아 검수(HITL) 설계가 필요

**활용할 때 확인할 점**

- 프롬프트 교육에 '반드시 포함할 대상·국가·기준' 체크리스트 단계 추가
- 평가·인사 등 고영향 문서는 무검수 붙여넣기 금지 규칙 명시
- 비전공자 설명은 '확률적으로 흔한 답을 먼저 낸다' 한 문장으로

### 스탠퍼드 CS336 과목 CLAUDE.md — AI 코딩 도구를 '정답 생성기'가 아닌 '조교'로 제한하는 수업용 에이전트 지침

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- 공식 과제 저장소의 'AI Agent Guidelines for CS336 at Stanford': ChatGPT·Claude Code·Copilot·Cursor 등 AI 코딩 도우미에 적용
- 해야 할 일: 개념 설명으로 방향 안내, 강의자료·공식 문서 안내, 작성한 코드 리뷰, 수정 대신 유도 질문으로 디버깅, 오류 메시지 설명
- 하지 말 것: 파이썬·의사코드 작성, 문제 해답 제공, TODO 채우기, 학생 저장소 코드 수정, bash 명령 실행 등
- 교수법: 무엇을 시도했는지 먼저 질문, 수정보다 테스트·불변식 제안

**활용할 때 확인할 점**

- 교육기관·사내 교육에서 '학습용 CLAUDE.md' 템플릿으로 활용 가능
- 지침 파일로 AI의 역할(조교 vs 대행)을 바꿀 수 있음을 시연하는 실습 소재

### 번역도 '역번역 반복'으로 완벽해지지 않음 — 번역 업무는 사람 경량 검수(HITL-Light)로 역할 이동

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-09-29

- 커뮤니티 실험·현장 전언으로 공식 통계 확인 없음
- 핵심: 역번역 일치는 품질 기준이 아니며, 번역 품질 검증은 용어집·스타일 기준과 사람 검수로 설계

**활용할 때 확인할 점**

- 번역 자동화 교육 시 '반복 루프'보다 용어집·검수 체크리스트 제시
- 'HITL 없는 원클릭'은 번역에서도 불가하다는 사례로 활용

### '하네스'는 AI가 작동하는 환경 전체 — 모델(연산 담당)과 그 모델을 돌리는 도구·지침·권한의 구분

원본 상태: 커뮤니티경험 · 원본 확인일: 2026-10-06

- 커뮤니티 정의: 하네스=모델을 둘러싼 실행 환경(도구, 지침 파일, 권한, 컨텍스트 관리 등). 같은 모델도 하네스에 따라 결과가 달라짐
- Cursor 안의 Grok 등은 하네스 안에서 연산을 맡는 '모델'에 해당
- 표준화된 공식 정의는 이번 구간에서 확인하지 않음

**활용할 때 확인할 점**

- 입문 교육에서 '모델 vs 하네스(도구)' 구분을 먼저 설명하면 도구 비교 혼란 감소
- 실행 위치(로컬/클라우드)에 따라 비용·데이터 위치가 달라진다는 점 함께 안내
