## 실제 학습 내용

### Claude Opus 4.8은 2026-05-28(미국) 출시, 입력 $5·출력 $25, Claude Code는 업데이트 후 [1m] 지정으로 1M 컨텍스트

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- Anthropic 공식 발표(2026-05-28): claude.ai와 API(claude-opus-4-8)에서 즉시 제공, 가격 입력 $5·출력 $25(백만 토큰당)
- fast mode는 입력 $10·출력 $50, 속도 2.5배
- 발표문에 '향후 수주 내 Mythos급 모델을 모든 고객에게 제공 예정' 언급
- Claude Code 모델 설정 문서: 모델 별칭·전체 이름 뒤에 [1m]을 붙여 1M 컨텍스트 요청(예: /model claude-opus-4-8[1m]); 현행 문서 기준 Anthropic API에서는 Opus 4.7 이상이 요금제와 무관하게 1M 창으로 실행되고 기본 자동 압축은 약 967K 토큰

**활용할 때 확인할 점**

- '너무 빨리 압축된다'면 먼저 현재 모델의 컨텍스트 창(200K/1M) 확인
- 새 모델이 CLI에 안 보이면 도구 업데이트부터

### GPT-5.6(Sol·Terra·Luna)은 2026-07-09 출시 — Sol 체감은 '더 정교하지만 느리고 한도 소모 큼'과 '일하는 척' 평가로 갈림

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

- OpenAI 발표: GPT-5.6은 2026-07-09 출시, Sol(플래그십)·Terra(균형·일상 업무)·Luna(최고 비용효율) 3단계
- API 가격(100만 토큰당): Sol 입력 $5/출력 $30, Terra $2.50/$15, Luna $1/$6
- ChatGPT Work·Codex: Free/Go는 Terra, Plus 이상은 Sol·Terra·Luna와 effort 선택 가능
- 환각 개선·체감 성능은 공식 수치가 아닌 커뮤니티 경험으로 평가가 갈림

**활용할 때 확인할 점**

- 신모델 도입 교육 시 '공식 사양'과 '사용자 체감'을 분리해 제시
- 높은 effort·빠른 속도 옵션은 한도 소모가 커진다는 점을 실습 전에 안내

### 수츠케버의 '스케일링 시대 종료' 발언은 2025-11 인터뷰 — 근거는 데이터 유한성과 일반화 한계, '연구의 시대'로 복귀

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

- 발언 출처: 2025-11-25 Dwarkesh Patel 팟캐스트 인터뷰 'We're moving from the age of scaling to the age of research'(공유 글의 '2026년 들어서면서'와 시점 다름)
- 수츠케버는 OpenAI 공동창업자·전 수석과학자로 현재 Safe Superintelligence(SSI) 소속
- 인터뷰상 근거: 데이터는 명백히 유한함, 컴퓨트가 매우 커져 다시 연구(아이디어)가 병목인 시대, 모델이 사람보다 일반화를 훨씬 못한다는 근본 문제
- '루프형 트랜스포머'·'학습비 1조 원' 설명은 인터뷰에 없는 커뮤니티 추측

**활용할 때 확인할 점**

- AI 트렌드 강의에서 인용 시 발언 시점(2025-11)과 원문 맥락(사전학습 스케일링 한계)을 정확히 표기
- '스케일링 종료=발전 정체'로 단순화하지 않도록 설명

### Qwen-Image-3.0(2026-07-21) — Qwen Chat에서 제공, 이전 버전과 달리 오픈 웨이트·벤치마크 미공개

- 공식 블로그 페이지는 열었으나 본문 확인 불가

**활용할 때 확인할 점**

- 오픈소스 이미지 모델로 소개할 때 버전별 공개 방식(웨이트 공개 여부) 확인 필수
- 제작사 선별 예시 이미지만으로 성능을 단정하지 않기

### GPT-6.1 Sol 체감 — 한도 소모는 매우 적지만 느림, effort는 high~xhigh 권장(max는 Astra만큼 느림)

원본 상태: 부분확인 · 원본 확인일: 2026-10-06

- 공식: Plus·Business(Standard) 5시간 창 추정 메시지 수는 GPT-6 Astra 5~45회, GPT-6.1 Sol 15~160회로 Sol이 훨씬 넉넉
- 공식: 같은 작업이라도 모델·입출력 크기·추론 수준에 따라 한도 소모가 다르며, 낮은 effort의 Astra가 높은 effort의 Sol을 앞설 수 있다고 안내
- 공식: fast 모드는 더 빠른 대신 포함 사용량을 더 많이 소모
- 속도·품질 비교(Opus 5.5·Sonnet 5.5 대비)는 커뮤니티 체감이며 공식 비교 아님

**활용할 때 확인할 점**

- 대량·장시간 작업은 Sol(high~xhigh), 정밀 판단은 상위 모델로 역할 분담
- effort를 최대로 올리면 속도가 급락하므로 작업 난이도별로 단계 선택
- 출시 직후 체감은 며칠 사용 후 재평가
