## 실제 학습 내용

### 모델 전환·effort 변경은 프롬프트 캐시를 깨뜨려 사용량을 추가 소모

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

Claude Code 공식 문서: 모델마다 캐시가 따로 있어 /model로 전환하면 다음 요청이 전체 대화를 캐시 없이 다시 처리함. 대부분 모델에서 effort 변경도 캐시를 무효화하나 Opus 5.5·Sonnet 5.5·Fable 5.1(API 키·구독)은 유지. fast mode 켜기, MCP 서버 추가, /compact도 캐시 재구축 유발. 긴 세션일수록 매 요청마다 전체 맥락을 캐시 단가로 다시 읽으므로 무관한 작업 사이에는 /clear, 구체적 지시가 권장됨. 검색 범위 축소 효과의 수치(10% 이하)는 공식 수치가 아님.

**활용할 때 확인할 점**

'모델·effort는 세션 시작 때 정하고 중간에 바꾸지 않기', '작업 단위로 /clear'를 비용 절감 기본 수칙으로 교육.

### '컨텍스트가 빨리 찬다' 체감에는 근거 있음 — 요청당 컨텍스트 2.6배 증가, Sonnet 5.5 공식 창은 1M

원본 상태: 정정 · 원본 확인일: 2026-09-29

Claude 블로그(2026-09-24): Claude Code에서 요청당 컨텍스트가 2.6배 증가, 입력:출력 토큰 비율이 189:1에서 324:1로 이동, 프롬프트당 작업 시간 3.3배·모델 호출 40% 이상 증가. /usage로 캐시 읽기 비중 확인 권장. Claude Code 문서: Sonnet 5.5·Sonnet 5는 API에서 항상 1M 컨텍스트로 동작하며 약 967K 토큰에서 자동 압축. '150k 정도 버틴다'는 품질 체감에 대한 개인 경험으로 공식 한도와 다름.

**활용할 때 확인할 점**

컨텍스트 소진은 모델이 아니라 작업 방식(도구·MCP·긴 세션) 변화에서도 온다는 점을 수치로 설명. 공식 한도와 '실사용 품질 한계'를 구분해 안내.

**정정과 한계**

Sonnet(5/5.5)의 공식 컨텍스트 한도는 1M 토큰이며 150k는 공식 한도가 아님(체감상 품질 저하 시점에 대한 개인 의견).

### 컴팩션은 이전 대화를 요약으로 치환, 원문 디테일은 컨텍스트에서 사라짐

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

Claude API 공식 문서: 컴팩션은 서버가 쓴 요약으로 대화의 오래된 턴을 대체하며, 임계값 컴팩션 시 요약 블록 이전 내용은 버려짐. 옵션에 따라 최근 몇 턴은 원문 그대로 유지 가능. Claude Code 문서: /compact는 대화를 구조화된 요약으로 대체하고, 호출했던 스킬 본문은 스킬당 최대 5,000토큰까지 다시 주입. Claude Code는 세션 기록을 로컬에 별도 보관(세션 관리 문서). 파일·메모리 등 대화 밖 산출물은 영향 없음.

**활용할 때 확인할 점**

'긴 대화는 요약되며 디테일이 준다, 중요한 것은 파일·메모리로 남겨라'는 실무 원칙으로 교육.

**정정과 한계**

'원문 전체를 버린다'는 설명은 대체로 맞지만, API 설정에 따라 최근 턴은 원문 유지 가능.

### 컨텍스트 사용량 확인은 Claude Code 상태줄로, 채팅 UI에는 공식 표시 없음

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

Claude Code 공식 문서: 상태줄은 사용자가 설정한 셸 스크립트를 실행해 화면 하단에 표시하며, 세션 JSON 데이터를 받아 컨텍스트 사용량·비용·git 상태 등을 보여줌(기본 자동 표시가 아닌 사용자 구성 기능). claude.ai 설정의 사용한도 게이지는 요금제 메시지 한도로 컨텍스트 토큰 사용량과 다른 지표. 세션 시스템 알림의 남은 토큰 수는 특정 환경 관찰값으로, 컴팩션 후 다시 커지며 공식 보장 지표 아님.

**활용할 때 확인할 점**

'사용한도 게이지 ≠ 컨텍스트 사용량' 구분 교육. 정확한 확인은 Claude Code 상태줄 권장.

### Claude 프롬프트 캐시 기본 수명 5분(1시간 옵션) — 캐시가 깨지면 전체 컨텍스트가 비싼 쓰기 비용으로 재청구

원본 상태: 부분확인 · 원본 확인일: 2026-09-29

- 공식 문서: 캐시 기본 수명은 5분, 추가 비용으로 1시간 수명 선택 가능
- 가격 배수: 5분 캐시 쓰기 1.25배, 1시간 캐시 쓰기 2배, 캐시 읽기 0.1배(기본 입력 단가 대비)
- 따라서 캐시 적중 시 대부분 0.1배로 처리되던 긴 컨텍스트가 캐시 미스 시 쓰기 단가로 다시 계산되어 한 턴 사용량이 크게 뛸 수 있음
- 질문자가 겪은 '더블링'이 캐시 미스인지 버그인지는 공식 확인 불가(개인 버그 리포트 단계)

**활용할 때 확인할 점**

- 긴 세션일수록 자리 비움·모델 전환이 비용을 키우는 원리를 캐시 개념으로 설명
- 사용량이 비정상적으로 빨리 닳으면 세션 로그 분석·버그 리포트 절차 안내

- Claude Code 공식 비용 문서는 무관한 작업으로 넘어갈 때 /clear로 새로 시작하고, /compact에 보존할 내용을 지정(예: '/compact Focus on code samples')하라고 안내
- /compact는 요약 대상 대화를 읽으므로 큰 컨텍스트 압축 자체가 큰 요청이며, 연속성이 필요 없으면 /clear는 비용이 없다고 명시
- 오래 열어 둔 세션은 매 요청마다 전체 대화를 다시 보내 사용량이 늘어날 수 있음
- 커뮤니티 공통 경험: 작업 단위 종료 시 '다음 세션에 필요한 기록'만 md로 남기고 새 세션에서 시작
- 공식 문서상 Claude Code는 매 세션 새 컨텍스트로 시작하며 프로젝트 CLAUDE.md는 매 세션·/compact 이후에도 다시 로드되므로, 계속 필요한 규칙은 CLAUDE.md에, 일회성 인계는 md 파일에 두는 구분이 가능
- 모델 성능 향상으로 관리가 불필요해졌다는 주장은 확인된 근거 없음(커뮤니티는 반대 의견 우세)
- [추가 2026-10-05] 10월 커뮤니티 운용 방식: 핸드오프 문서 작성 후 /clear, 작업 문서에 상시 기록하고 clear, 같은 폴더면 이전 세션 내용을 불러올 수 있어 새 세션으로 진행, 개요·세부 플랜·예시 프롬프트 md 3종을 매 세션 읽게 하는 방식 등. '요즘은 long context 효율이 좋아 /clear를 꼭 하지 않아도 되며, clear 후 병목은 정확한 첫 프롬프트'라는 의견.

원본 상태: 공식확인 · 원본 확인일: 2026-10-06

- Claude Code 공식 비용 문서: MCP 도구 정의는 기본적으로 지연 로드되어 도구 이름·서버 지시문만 먼저 컨텍스트에 들어가며, /context로 공간을 차지하는 항목 확인, /mcp로 안 쓰는 서버 비활성화 권장
- /usage의 플랜 사용량 분석에서 최근 사용량을 스킬·서브에이전트·플러그인·개별 MCP 서버별 비율로 확인 가능

- [추가 2026-09-30] Opus 토큰 효율 개선이 체감되지 않을 때 오래된 하네스·스킬부터 점검하고 컨텍스트 25만 토큰 전후에서 핸드오프·컴팩트를 자주 하라는 조언, 동시 프로젝트 수가 많으면 체감이 줄어든다는 사례(커뮤니티)

### Claude Code 세션은 계정이 아닌 PC·프로젝트 폴더 단위로 로컬 저장 — 채팅(claude.ai)은 계정 클라우드

원본 상태: 공식확인 · 원본 확인일: 2026-10-06

- Claude Code 공식 문서: 세션은 프로젝트 디렉터리에 묶인 저장 대화이며 작업 중 로컬에 저장
- 기본 저장 위치 ~/.claude/projects/<project>/<session-id>.jsonl, 기본 보관 30일(cleanupPeriodDays로 변경)
- 데스크톱 앱·claude.ai/code·VS Code 확장은 각자 세션 목록을 가짐
- 이어서 하기: claude --continue(최근 세션), claude --resume(선택기), /export로 텍스트 내보내기
- Codex 계정 전환 시 세션 표시 방식은 공식 문서로 확인하지 못함(커뮤니티 경험만)

**활용할 때 확인할 점**

- 공용 PC·계정 전환 환경에서는 로컬 세션 기록이 다른 계정 사용자에게 보일 수 있음 — 보안 교육 포인트
- 계정이 바뀌어도 작업 맥락을 이어야 하면 /export나 세션 파일 재개 활용
