### Jev(TypeSafe)는 문장 대신 분류·점수만 병렬로 내는 'System One' 모델로 2026-09-15 얼리 액세스 출시

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- TypeSafe 공식 발표: Jev는 첫 'System One 모델'. 토큰을 하나씩 생성하지 않고 모든 확률을 병렬로 출력해 분류·라우팅·점수화·추출·분기에 쓰는 타입 안전한 구조화 값과 보정된 확신도를 반환
- 출시일 2026-09-15, 얼리 액세스(대기자 명단 순차 승인), 오픈 웨이트·로컬 배포 언급 없음
- 가격(공식 발표 기준): 입력 100만 토큰당 $0.042, 출력 무료. 응답 시간 70ms~500ms
- 이미지 입력은 출시 시점 미지원('아직')으로 명시
- 사용 방식: 공식 문서는 Jev가 Claude Code·Cursor 등 에이전트의 LLM을 대체하지 않으며, 에이전트가 Jev를 '호출하는 코드'를 작성하도록 TypeSafe agent skill·Python SDK·Playground를 안내
- [추가 2026-09-23] 9/22 TypeSafe 공식 X 계정이 'Jev is now available to everyone. No waitlist' 공지(회사 SNS). 커뮤니티 활용: Yes/No 판단 용도, LLM 앞단 검출기, 추천엔진 제작, awesome-jev 목록 공유. 9/23 신규 가입이 막혔다는 이야기와 초대 메뉴가 안 보인다는 반응, 가입 정책 변동은 공식 확인 안 됨.

**활용할 때 확인할 점**

- 비용 절감 교육에서 '모든 요청을 비싼 LLM으로 처리하지 않는' 라우팅·필터링 계층 사례로 활용
- 얼리 액세스 단계이므로 실습 교재에는 대기 승인 필요 여부를 함께 표기

**정정과 한계**

기존 지식베이스(kakao-codefactory-2026-09-jev-classifier-model)는 가격을 '미검증'으로 두었으나 TypeSafe 공식 발표에서 입력 $0.042/MTok·출력 무료가 확인됨. 'n8n JSON 강제 출력과 같다'는 해석은 공식 설명(자기회귀 생성 없이 확률을 병렬 출력)과 다름.

### CLI '크레딧 부족'은 API 선불 크레딧 소진 — 구독 로그인(/login)으로 전환하면 구독 한도 사용, API는 서비스 연동용

- Claude Code 오류 문서: 'Credit balance is too low'는 Console 조직의 선불 크레딧 소진을 뜻함. 대응은 결제 설정에서 크레딧 추가·자동 충전, 또는 Pro·Max·Team·Enterprise 구독자는 /login으로 구독 인증 전환

- '크레딧 부족'과 '사용 한도 도달'은 다른 과금 체계의 메시지라는 점을 구분해 안내
- 수강생 PC에 남아 있는 ANTHROPIC_API_KEY 환경변수로 의도치 않은 API 과금이 생길 수 있음을 주의사항으로 포함

### Jev = TypeSafe AI의 판단 전용 모델, 입력 $0.042/백만·출력 무료

원본 상태: 정정 · 원본 확인일: 2026-09-29

TypeSafe AI 공식: 2026-09-15 첫 'System One 모델' Jev 발표·얼리 액세스. 비정형 입력을 받아 미리 정의된 타입의 확률적 결정(분류·라우팅·점수·추출, 선택지 최대 255개)과 보정된 신뢰도를 반환. 가격 입력 $0.042/백만 토큰, 출력 무료. 응답 70~500ms. GitHub의 TheoLeeCJ/openjev는 README에서 Jev의 인터페이스 패턴을 오픈 모델로 재현한 독립 연구 프로젝트이며 Jev의 모델·학습은 재현하지 않는다고 명시.

**활용할 때 확인할 점**

'모든 요청에 비싼 LLM을 쓰지 않는' 저비용 판단 계층 개념 소개 사례. 구체 체감 수치는 인용 금지.

**정정과 한계**

openjev는 Jev의 공식 오픈소스가 아니라 독립 재현 프로젝트. 한국어 성능·정확도·5천 건 0.4달러 등은 커뮤니티 체감으로 공식 확인 안 됨.

### Jev와 LLM 구조화 출력의 차이, 회사 발표 기준 별도 아키텍처 모델

원본 상태: 공식확인 · 원본 확인일: 2026-09-29

- TypeSafe AI 공식 발표: Jev는 별도 인프라와 새 아키텍처·학습법(RLCD, 보정된 결정을 위한 강화학습)으로 만든 별개 모델로, 순차 토큰 생성이 아닌 병렬 샘플링을 쓰며 사전 정의된 값만 내므로 타입 오류·환각이 없다고 주장. 즉 기존 LLM에 스키마만 강제한 방식과 다르다는 것이 회사 입장(독립 검증은 아님).
- [추가 2026-09-21] TypeSafe 공식 문서: Jev는 영어가 주 학습 언어이며 CJK 등 비영어는 정확도가 동등하지 않아 자체 테스트 후 사용 권장, 입력은 텍스트만·요청당 64k 토큰. 커뮤니티 평가는 '컨셉보다 속도가 강점, 한국어 이해 제한으로 프로덕션은 애매'. 9/21 Jev 기반 검색 서비스 Jev Search(jev.s1.dev, 검색할 곳을 고르고 결과를 순위화, 생성 답변 없음) 공유.

**활용할 때 확인할 점**

'출력 형식 강제'와 '판단 전용 모델'의 차이를 설명하는 개념 사례. 성능 주장은 회사 발표 기준임을 명시.

### Jev를 에이전트 라우터로 쓰는 법과 한계 — 세션 시작·서브에이전트 분기에서만 라우팅, 한국어는 사전 테스트 필수

원본 상태: 부분확인 · 원본 확인일: 2026-10-06

- 논문 'Control the Harness, Control the Cost'(arXiv 2609.28919, 2026-09-24 제출): Jev로 요청을 분류해 가격대가 다른 모델에 배정하는 라우터 제안. 모의 1만 석 기업에서 모델 지출의 14~21% 절감 추정(Anthropic 2026년 9월 가격 기준). 대화 중 모델 전환은 프롬프트 캐시 재구축 비용이 커서 세션 시작·병렬 작업 레인·서브에이전트 실행 시점에서만 전환. 긴 도구 사용 세션에서는 비싼 모델이 오히려 싸게 먹힐 수 있다고 분석. 저자 소속(하버드 여부)은 원본 정리 시 확인에서 미확인
- TypeSafe 공식 문서: Jev는 영어가 주 학습 언어이며 CJK 등 다른 언어는 '처리하지만 동등하게 잘하지는 않으므로 비영어 작업은 자체 테스트 후 사용'하라고 명시. 입력은 텍스트만, 요청당 64k 토큰
- 경쟁 모델 CLM-8B(스탠퍼드·엔비디아, Apache 2.0): 보도 기준 Jev보다 최대 9배 빠르나 BFCL v4 도구 호출 정확도 95.2%(Jev 99.2%)
- [추가 2026-10-02] Jev 한국어 성능 질문은 답변 없음. 대안으로 Laya 다국어 체크포인트(mmBERT-base, 100+ 언어)가 있으나 한국어 정확도는 자체 테스트 필요 — 신규 카드 K0369 참조

**활용할 때 확인할 점**

- 라우터 도입 전 상시 로드 토큰·캐시 만료·모델 전환 시점 같은 하네스 기본기 점검이 우선

- Cloudflare 공식 블로그(2026-10-01): 입력을 분류해 확률과 함께 정해진 타입의 답을 돌려주는 결정 모델 계열, Apache 2.0으로 Hugging Face 공개·Workers AI 호스팅
- Clef(Qwen 27B 기반)·Clef-flash(Qwen 9B 기반), 중앙값 지연 Clef-flash 38.8ms ~ Clef 209.3ms
- 텍스트·이미지 입력, 스키마 선택지를 병렬로 점수화하는 비생성형·결정적 방식, 64k 컨텍스트
- 블로그는 Jev와 비교해 비전 인코더 포함·컨텍스트 64k(Jev 32k)를 차별점으로 제시
