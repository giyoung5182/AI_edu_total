## 실제 학습 내용

### Claude in Slack은 Slack 관리자 앱 승인 후 사용자가 'Connect Account'로 Claude 계정을 직접 인증하는 공식 앱

원본 상태: 정정 · 원본 확인일: 2026-09-29

- Anthropic 공식 도움말: Claude 앱은 유료 Slack 요금제 사용자에게 제공
- Slack 관리자가 먼저 Slack App Marketplace에서 Claude 앱을 'Add to Slack'으로 조직에 승인해야 개별 사용자가 사용 가능
- 사용자는 앱에서 'Connect Account' → 조직 선택 → 'Authorize'로 자신의 Claude 계정 접근을 허용
- 즉 공식 Claude 앱은 API 키 없이 Claude 계정 연결로 동작하며, '구독이라 무조건 API 필요'는 공식 앱에는 해당하지 않음(자체 게이트웨이·서드파티 봇은 별개)

**활용할 때 확인할 점**

- '연결하라' 안내 반복 시 점검 순서: 관리자 앱 승인 → Slack 유료 요금제 → Connect Account 인증 완료
- 공식 앱과 자체 제작 봇(게이트웨이)의 인증 방식 구분

**정정과 한계**

공식 'Claude in Slack' 앱은 API 과금이 아니라 Claude 계정 연결(Connect Account) 방식. 연결 안내가 반복되면 관리자 승인 여부·Slack 유료 요금제·인증 완료 여부를 먼저 확인

### Windows(WSL)에서 Hermes 게이트웨이가 터미널 종료 시 멈추면 systemd 서비스+WSL VM 상시 유지로 해결

원본 상태: 정정 · 원본 확인일: 2026-09-29

- Hermes Agent 공식 WSL2 가이드: systemd를 켜두면 hermes gateway가 일반 리눅스처럼 동작하며, 설치 마법사가 WSL 시작 시 게이트웨이를 자동 실행하는 systemd 사용자 유닛 설치를 제안
- 터미널을 닫을 때 WSL VM이 내려가는 것을 막기 위해 Windows 작업 스케줄러로 로그인 시 백그라운드 프로세스(-d Ubuntu --exec /bin/sh -c "sleep infinity")를 띄워 VM을 유지하는 방법을 안내
- PC 자체는 켜져 있어야 한다는 점은 커뮤니티 답과 동일

**활용할 때 확인할 점**

- 상시 에이전트 운영은 '프로세스 서비스화'와 '호스트 상시 가동'을 구분해 설명
- 맥미니 구매 전 기존 PC의 WSL 서비스화부터 시도

**정정과 한계**

'터미널을 닫으면 멈추는 것'은 피할 수 없는 현상이 아니라 WSL VM 종료 때문. systemd 서비스 등록+VM 유지 설정으로 터미널 없이 상시 실행 가능(PC 전원은 유지 필요)
