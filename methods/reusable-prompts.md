# 입력부터 검수까지 연결하는 요청문

정리일: 2026-10-08. 교육 운영·교재 검토·실제 도구 분석에서 얻은 방법을 바탕으로 새로 작성한 범용 요청문입니다. 원래 대화나 교재 요청문을 복제한 것이 아닙니다. 대괄호를 자신의 자료로 채웁니다.

## 새 업무 도구 설계

> [반복 업무]를 위한 도구를 설계해줘. [준비한 파일]에서 직접 읽을 항목과 사람/AI가 먼저 정리할 항목을 나눠줘. 작업 순서마다 실제 행동과 필요한 요청을 넣고 [결과 형식]으로 출력해줘. 지원 형식과 실패 조건, 완료 기준을 먼저 정하고, 새 가상 입력으로 결과가 바뀌는지 확인해줘. 자동 AI 호출이 없으면 그 사실을 기능 설명에 반영해줘.

## 파일·라이브러리 선택

> [파일 형식·구조]를 읽어 [필드]를 추출하려고 해. 브라우저 단일 파일, 로컬 라이브러리, 서버 방식의 준비 조건과 처리 범위를 비교해줘. 파일 선택·텍스트 추출·계산·의미 분석을 구분해줘. 예제 하나의 성공을 모든 문서 지원으로 일반화하지 말고, 현재 확인한 수준과 남은 시험을 적어줘.

## 새 설문 반영

> 새 설문과 기존 문항표가 준비됐어. 원본을 보존하고 차수·종류·척도를 실제 헤더와 날짜로 대조해줘. 문항별 유효 응답·무응답·중복 처리 기준을 표시해줘. 비교 가능한 문항만 추세에 추가하고 정성 의견과 해석을 분리해줘. 독립 대조가 끝난 범위와 남은 불일치를 보고해줘.

## 최소 교재 수정

> [현재 기준본]과 [현재 승인 범위] 안에서 따라 하다가 막히는 부분만 고쳐줘. 찾을 제목·문구, 문제, 제한된 교체 문구, 근거, 앞뒤 단계 연결을 표로 써줘. 기존 예제·시간·순서를 유지하고 적용 후보와 실제 적용 여부를 구분해줘.

## 결과물 검수

> [입력]과 [결과물]을 대조해줘. 소개·코드·실행·공식 문서·설계 제안·미확인을 구분해줘. 새 입력, 오류, 데이터 교체, 저장·복원, 내보내기 후 재열기를 확인해줘. 실행하지 못한 부분은 이유를 기록하고 확인한 기능만 완료로 보고해줘.
