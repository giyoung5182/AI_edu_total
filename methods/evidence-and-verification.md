# 도구 설명에 근거 수준 붙이기

정리일: 2026-10-08. 소스 버전: 교육 운영 규칙 및 실행·코드 검토 기록의 2026-10-07~08 시점. 실제 결과물을 분석할 때의 방법론을 범용으로 편집했습니다.

화면이 완성됐다는 설명과 파일을 처리했다는 설명은 각각 근거가 필요합니다. 다음 표를 기능마다 채웁니다.

| 수준 | 확인할 근거 | 말할 수 있는 범위 |
| --- | --- | --- |
| 소개 확인 | 소개문·명세 | 제작자가 설명한 의도 |
| 코드 확인 | 함수·분기·의존성 | 구현된 처리와 조건; 실행 성공은 별도 |
| 공식 문서 확인 | 제품 문서·확인일 | 문서에 명시한 지원 조건; 계정에서 실행 여부는 별도 |
| 실제 실행 확인 | 입력·환경·기대값·실제값 | 해당 입력과 환경에서 관찰한 동작 |
| 출력 재열기 확인 | 저장 파일·재열기 결과 | 파일 생성과 재열기한 내용 |
| 설계 제안 | 대안·필요 의존성 | 앞으로 구현할 수 있는 방법 |
| 미확인 | 미수신·실패·미실행 사유 | 아직 주장할 수 없는 부분 |

파일 업로드 → 글자·셀 추출 → 규칙 계산 → 의미 해석 → 내보내기를 따로 검사합니다. OCR로 글자를 읽은 것이 문서의 의도를 이해한 것은 아닙니다. 브라우저 라이브러리로 계산한 것을 외부 AI 호출로 설명하지 않습니다.

새 테스트 자료가 준비됐다면 초기 샘플과 다른 값을 넣습니다. 숫자·행 수·빈칸·파일 형식을 하나씩 바꿔 결과가 바뀌는지 확인합니다. 입력이 거절되는 경우에도 사용자에게 실패 이유가 보이는지 검사합니다. 예시 체험을 끝낸 후 기존 자료가 유지되는지도 확인합니다.

내보내기 버튼을 누른 뒤 실제 저장 파일을 찾아 새 창이나 대응 앱에서 다시 엽니다. 저장 위치를 얻지 못했으면 다운로드·재열기 상태를 미확인으로 남깁니다. ZIP/XML 구조 검사는 문서 앱의 화면 검수와 구분합니다.

검증표에는 `기능 / 입력 / 환경 / 기대 결과 / 관찰 결과 / 파일 / 확인 수준 / 남은 한계`를 기록합니다. 코드 작성자와 다른 사람이 주요 경로를 확인하면 동일한 가정을 반복할 위험을 줄일 수 있습니다. 통과 횟수만 제시하지 말고 무엇을 시험했는지 적습니다.
