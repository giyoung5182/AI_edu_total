# AI 업무를 설계하는 다섯 질문

정리일: 2026-10-08. 소스 버전: 2026-10-07 업무 설계 다섯 관점 별첨. 외부 원문과 교재를 복제하지 않고 범용 설명으로 편집했습니다. 아래 내용은 설계 관점이며 AI 호출을 실행한 결과가 아닙니다.

| 관점 | 먼저 물을 질문 | 준비할 것 |
| --- | --- | --- |
| 요청문 | 무엇을 어떤 형태로 요청할까? | 목표·입력·출력·제약·완료 기준 |
| 맥락 | 지금 어떤 자료와 기준을 보여줄까? | 이번 건 자료, 지속해서 쓸 기준, 출처 버전 |
| 작업 환경 | 어디서 작업하고 확인하게 할까? | 파일·도구·권한·검증 방법·로그 |
| 반복 루프 | 어떤 결과를 보고 다시 하고 언제 끝낼까? | 오류 조건·수정 대상·횟수·종료 기준 |
| 작업 연결 | 결과에 따라 다음 작업을 어디로 보낼까? | 단계별 입출력·분기·사람 확인 지점 |

가상 번역 검토 업무라면 요청문에는 숫자·변수·의미 차이를 구분해 달라고 씁니다. 맥락에는 원문·번역표·용어집·화면 제약을 넣습니다. 환경에는 표 파서와 문구 미리보기, 비교 결과 파일을 준비합니다. 루프는 누락·숫자 차이·줄 넘침을 고친 뒤 재검사하고 종료 조건을 둡니다. 작업 연결은 규칙으로 통과한 행, 의미 확인이 필요한 행, 사람이 확정한 행을 다음 단계로 보냅니다.

견적 비교에도 같은 질문을 적용할 수 있습니다. 먼저 품목 ID·수량·단가를 추출하고, 규칙 계산으로 합계를 대조하고, 애매한 품목 매칭은 후보로 남깁니다. 의미 매칭이 필요한 부분에만 AI 또는 사람의 판단을 연결합니다. 최종 출력의 숫자는 원본과 다시 대조합니다.

반복을 설계할 때 오류를 없애려고 기준을 바꾸면 결과가 좋아 보일 수 있습니다. 기준 변경은 이유와 버전을 기록하고 기존 기준의 실패를 숨기지 않습니다. 현재 건의 정보와 계속 사용할 규칙을 분리해 임시 사례가 전체 운영 원칙이 되지 않게 합니다.

규칙 기반 체험에서 분기나 루프를 보여줬다면 '규칙 기반 시뮬레이션'이라고 표시합니다. 도구 실행 기록과 공식 문서를 확인하지 않은 상태에서 실제 AI 에이전트, 자율 운영 또는 최신 제품 기능으로 설명하지 않습니다.
