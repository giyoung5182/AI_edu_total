# 실제 업무 도구에서 재사용할 구현·검수 패턴

정리일: 2026-10-08. 소스 버전: 2026-10-07 실제 파일 6종 코드·명세 대조와 개념 가이드 추가 근거. 개인·회사·평가·원본 자산은 제외했습니다. 아래 흐름은 분석을 바탕으로 범용화한 설계이며 전체 동작 성공을 주장하지 않습니다.

| 업무 | 준비할 자료와 흐름 | 검수·한계 |
| --- | --- | --- |
| 영상 스토리보드 | 영상 → 컷 후보 → 사람 선택 → 나레이션 → PPT → 버전 이력 | 저해상도 캡처를 원본 품질이라고 쓰지 않음; 요청문 복사는 자동 AI 호출과 구분 |
| 공간 계획 | 도면 이미지 + 사람/AI가 구조화한 좌표 → 구역·순서·경로 → PPT | 격자 근사는 정확한 면적 계산과 다름; 직교 경로가 장애물 회피를 보장하지 않음 |
| 번역·화면 문구 | 원문·번역표 + 사전 의미 비교 → ID 대조 → 숫자·빈칸 → 영역 배치 → 글꼴 줄 넘침 → 사람 확정 | 의미 비교와 규칙 검사는 별도; 제한된 XLSX 파서를 모든 엑셀 지원으로 설명하지 않음 |
| 설문 요약 | 여러 파일의 ID 대조 → 미확정 후보 → 사람 확정 → 재판정 → 공유용 출력 | 대표 의견 선택 근거와 개인정보 제거를 각각 검사 |
| 준수 점검 | 규칙·문서 → 일치/불일치 후보 → 근거 위치 → 사람 판단 → 출력 | 규칙으로 잡힌 후보를 최종 판단이라고 하지 않음 |
| KPI 화면 | 새 원본 → 파싱 → 계산 → 파일 생성 → 재열기 | HTML만 수신하고 서버 엔진이 없으면 시뮬레이션과 실제 처리 구분 |

데모에는 두 방식이 있습니다. 기존 데이터를 교체한다면 삭제·대체 범위를 먼저 알리고 사용자가 동의한 뒤 수행합니다. 별도 데모 저장소를 쓴다면 체험 종료 후 원래 기록이 복원되는지 검사합니다. 샘플을 다시 보여주는 버튼만으로 새로운 입력 시험을 완료했다고 하지 않습니다.

공유 화면에서 내부 메모를 숨겨도 HTML 내부 JSON에 원본 행·계정 ID가 남을 수 있습니다. 화면과 파일 내부를 모두 검수하고 공개용 필드 허용목록을 사용합니다.

새 제출물을 받을 때는 고득점만 보지 않습니다. 새로운 파일 형식, 좋은 UI, 실패 조건, 반복 업무의 구조가 학습 가치가 될 수 있습니다. 소개만 수신한 사례, 코드를 확보한 사례, 실행한 사례, 확장 제안을 구분합니다. 원본 코드·그림·사진의 재배포 권한은 별도로 확인해야 합니다.
